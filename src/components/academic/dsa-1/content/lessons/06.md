# Module 06: Master Theorem

## Learning objectives

- Recognise recurrences of the form T(n) = aT(n/b) + f(n).
- Apply the three cases, including the regularity condition.
- Know when the theorem does not apply and which method to use instead.

## Prerequisites

[Module 05](topic:correctness-and-recurrences): recurrences and recursion trees.

## Intuition

A divide-and-conquer algorithm splits a problem of size n into a subproblems of size n/b and spends f(n) outside the calls. The recursion tree has log_b n levels; the leaves number n^(log_b a). The theorem compares f(n) with n^(log_b a) to decide whether the leaves, every level equally, or the root dominates.

## Definitions and terminology

| Symbol | Meaning |
|---|---|
| a ≥ 1 | number of subproblems |
| b > 1 | factor by which the size shrinks |
| f(n) | work done outside the recursive calls (divide + combine) |
| n^(log_b a) | the *watershed* function: total cost of the leaves |

## The three cases

Let c* = log_b a.

| Case | Condition | Result |
|---|---|---|
| 1 | f(n) = O(n^(c* − ε)) for some ε > 0 (leaves dominate) | T(n) = Θ(n^c*) |
| 2 | f(n) = Θ(n^c* · log^k n), k ≥ 0 (balanced) | T(n) = Θ(n^c* · log^(k+1) n) |
| 3 | f(n) = Ω(n^(c* + ε)) and a·f(n/b) ≤ k·f(n) for some k < 1 (regularity; root dominates) | T(n) = Θ(f(n)) |

## Worked examples

| Recurrence | a, b, c* | f(n) | Case | Result |
|---|---|---|---|---|
| Binary search T(n) = T(n/2) + 1 | 1, 2, 0 | 1 = Θ(n⁰) | 2 (k = 0) | Θ(log n) |
| Merge sort T(n) = 2T(n/2) + n | 2, 2, 1 | n = Θ(n¹) | 2 | Θ(n log n) |
| T(n) = 8T(n/2) + n² | 8, 2, 3 | n² = O(n^(3−1)) | 1 | Θ(n³) |
| T(n) = 2T(n/2) + n² | 2, 2, 1 | n² = Ω(n^(1+1)); 2(n/2)² = n²/2 ≤ ½n² | 3 | Θ(n²) |
| T(n) = 2T(n/2) + n log n | 2, 2, 1 | Θ(n log¹ n) | 2 (k = 1) | Θ(n log² n) |

## When the theorem does not apply

- **Not of the form**: T(n) = T(n − 1) + n (subtracting, not dividing) → expansion gives Θ(n²).
- **Unequal splits**: T(n) = T(n/3) + T(2n/3) + n → recursion tree: each level costs ≤ n, depth log_{3/2} n → Θ(n log n).
- **a < 1 or non-constant a**: T(n) = 2^n T(n/2) + n^n is not covered.
- **f(n) between cases**: T(n) = 2T(n/2) + n / log n falls in the gap between cases 1 and 2 → use a recursion tree (result Θ(n log log n)).
- Floors and ceilings (T(⌊n/2⌋)) do not change the result.

## Correctness reasoning

Summing the recursion tree level by level gives Σ_{j=0}^{log_b n} a^j f(n/b^j). If these level costs grow geometrically, the last level (the leaves, Θ(n^c*)) dominates; if they are equal, multiply one level by log n; if they shrink geometrically (guaranteed by regularity), the root f(n) dominates. That is the whole theorem.

## Complexity analysis

Applying the theorem is O(1) once a, b and f are identified. Binary search Θ(log n), merge sort Θ(n log n), and Karatsuba multiplication T(n) = 3T(n/2) + n gives Θ(n^1.585).

## Implementation (C++17)

```cpp
#include <cmath>
#include <iostream>
using namespace std;

// Classify T(n) = a T(n/b) + n^d (polynomial f) with the Master Theorem.
int main() {
    double a, b, d;
    cin >> a >> b >> d;                       // e.g. 2 2 1 for merge sort
    double c = log(a) / log(b);               // watershed exponent log_b a
    if (fabs(d - c) < 1e-9) cout << "Case 2: Theta(n^" << d << " log n)\n";
    else if (d < c) cout << "Case 1: Theta(n^" << c << ")\n";
    else cout << "Case 3: Theta(n^" << d << ")\n";   // regularity holds for polynomial f
}
```

## Common mistakes and edge cases

- Forgetting the regularity condition in case 3 (it holds automatically for polynomial f).
- Applying the theorem to T(n) = T(n − 1) + n, which is not divide-and-conquer.
- Confusing log_b a with log_a b.

## Key takeaways

- Compare f(n) with n^(log_b a).
- Smaller → leaves win; equal (up to log^k) → multiply by log n; larger (with regularity) → f(n) wins.
- Use a recursion tree when the recurrence does not fit.
