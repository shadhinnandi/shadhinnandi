## Prerequisites

## Intuition

An array stores n elements of one type contiguously, so a[i] is found in O(1) by address = base + i·size. The price: inserting or deleting in the middle shifts all later elements.

## Definitions and terminology

| Term | Meaning |
|---|---|
| Static array | Fixed size known at compile time: `int a[100];`, `std::array` |
| Dynamic array | Grows at run time: `std::vector` doubles its capacity when full |
| 2D array (row-major) | `a[i][j]` at base + (i·C + j)·size |
| Prefix sum | P[i] = a[0] + … + a[i−1]; range sum (l..r) = P[r+1] − P[l] |
| Frequency array | cnt[v] = occurrences of v, for small value ranges |

## Operations

| Operation | Cost | Why |
|---|---|---|
| Access a[i] | O(1) | address arithmetic |
| Linear search | O(n) | check every element |
| Binary search (sorted) | O(log n) | halve the range |
| Insert/delete at position i | O(n − i) | shift later elements |
| Append to vector | O(1) amortised | doubling: total copies < 2n |

**Amortised append proof:** with doubling, n appends cause copies of 1 + 2 + 4 + … + n/2 < n elements in total, so the average cost per append is O(1).

## Matrix traversal

Row-by-row traversal of a C++ matrix reads memory sequentially (cache friendly); column-by-column jumps C elements each step.

## Common patterns

Two pointers, sliding window, prefix sums (O(1) range sums after O(n) preprocessing), frequency counting (O(n + range)), in-place reversal.

## Applications and comparison

Arrays back heaps, hash tables, matrices and dynamic programming tables. Compared with linked lists ([Module 08](topic:linked-lists)), arrays win on access and cache behaviour and lose on middle insertion.

## Complexity analysis

Access O(1); search O(n) or O(log n) if sorted; insert/delete O(n); append O(1) amortised; prefix sums O(n) build and O(1) query; space O(n).

## Implementation (C++17)

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, q;
    cin >> n >> q;
    vector<long long> prefix(n + 1, 0);            // prefix[i] = a[0] + ... + a[i-1]
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        prefix[i + 1] = prefix[i] + x;
    }
    while (q--) {
        int l, r;                                  // 0-based inclusive range
        cin >> l >> r;
        cout << prefix[r + 1] - prefix[l] << '\n'; // O(1) per query
    }
}
```

**Input:**

```text
5 2
3 1 4 1 5
0 4
1 3
```

**Output:**

```text
14
6
```

## Pseudocode

```text
PREFIX(A[0..n-1])
    P[0] ← 0
    for i ← 0 to n-1:  P[i+1] ← P[i] + A[i]
RANGE-SUM(l, r)  return P[r+1] - P[l]
```

## Dry run

A = [3, 1, 4, 1, 5] gives P = [0, 3, 4, 8, 9, 14]. Sum of A[1..3] = P[4] − P[1] = 9 − 3 = 6 = 1 + 4 + 1. ✓

## Applications

Image processing (2D arrays), lookup tables, frequency counting, prefix sums for range queries ([DSA07-E02](problem:DSA07-E02), [DSA07-M02](problem:DSA07-M02)), difference arrays for range updates ([DSA07-M03](problem:DSA07-M03)), sliding windows ([DSA07-H04](problem:DSA07-H04)).

## Comparison with related concepts

| | Static array | `std::vector` | Linked list |
|---|---|---|---|
| Size | fixed | grows (doubling) | grows node by node |
| Access a[i] | O(1) | O(1) | O(i) |
| Append | not possible | O(1) amortised | O(1) with tail |
| Middle insert | O(n) | O(n) | O(1) at a known node |

## Common mistakes and edge cases

- Off-by-one errors (`i <= n`).
- Large local arrays overflowing the stack; use vector.
- Iterating while erasing from a vector invalidates iterators.
- Prefix sums overflowing int.

## Key takeaways

- Contiguity gives O(1) access and good cache use.
- Middle insertion/deletion is O(n).
- vector append is O(1) amortised thanks to doubling.
- Prefix sums turn O(n) range queries into O(1).
