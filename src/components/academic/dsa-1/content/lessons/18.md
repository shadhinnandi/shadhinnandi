# Module 18: Integrated Revision and Job Preparation

## Learning objectives

- Choose the right data structure and algorithm from the operations and constraints of a problem.
- Compare the course's structures and algorithms side by side.
- Practise under time limits with mixed-topic sets drawn from the question bank.

## Prerequisites

All earlier modules.

## Choosing a data structure

| You need | Use | Cost |
|---|---|---|
| Index access, appends | `vector` | O(1), O(1) amortised |
| LIFO / undo / matching | stack | O(1) |
| FIFO / BFS | queue (circular / `deque`) | O(1) |
| Repeated max or min | heap / `priority_queue` | O(log n) |
| Membership, no order | `unordered_set` / `unordered_map` | O(1) expected |
| Membership with order, ranges | `set` / `map` (balanced BST) | O(log n) |
| Dynamic connectivity | DSU | O(α(n)) |
| Shortest hops in an unweighted graph | BFS | O(n + m) |

## Algorithm and complexity review

| Constraint n | Target | Typical tools |
|---|---|---|
| ≤ 20 | O(2^n) | brute force, backtracking |
| ≤ 5000 | O(n²) | nested loops, insertion sort |
| ≤ 2·10^5 | O(n log n) | sorting, heaps, binary search, BST |
| ≤ 10^6 | O(n) | prefix sums, two pointers, hashing, BFS/DFS |

## Complexity analysis

Revision is about estimating cost before coding: read the constraint, pick the target class, then the structure that achieves it.

## Common mistakes and edge cases

- Starting to code before choosing the complexity.
- Ignoring empty input, n = 1, duplicates, negative values and overflow.
- Using an ordinary BST and assuming O(log n).
