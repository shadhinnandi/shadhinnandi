## Intuition: testing shows bugs, proofs show their absence

A hundred passing tests show that an algorithm works on a hundred inputs. A proof shows it works on *every* valid input. You do not need heavy mathematics: most proofs in this course follow two patterns.

- For a **loop**, find a statement that is true before the loop, stays true after each iteration, and at the end says exactly what you want (a *loop invariant*).
- For **recursion**, assume the recursive calls on smaller inputs are correct (the *inductive hypothesis*) and show the current call is then correct.

For efficiency, recursive algorithms lead to **recurrences** such as T(n) = 2T(n/2) + n, which you solve to get a closed-form bound.

## Definitions and terminology

| Term | Meaning |
|---|---|
| **Precondition** | What the algorithm assumes about its input (e.g. "the array is sorted") |
| **Postcondition** | What it guarantees on exit (e.g. "returns an index with A[i] = x, or −1 if x is absent") |
| **Correctness** | Every input satisfying the precondition produces output satisfying the postcondition |
| **Partial correctness** | *If* the algorithm terminates, the output is correct |
| **Total correctness** | Partial correctness plus termination |
| **Loop invariant** | A statement about the variables that holds before every iteration and after the loop |
| **Variant (bound function)** | A non-negative integer that strictly decreases every iteration, proving termination |
| **Recurrence relation** | An equation that defines T(n) in terms of T on smaller inputs |

## Loop invariants

To prove a loop correct with invariant I:

1. **Initialisation:** I is true before the first iteration.
2. **Maintenance:** if I is true before an iteration, it is true after it.
3. **Termination:** the loop ends, and when it does, I together with the exit condition implies the postcondition.

### Example 1: linear search

```text
LINEAR-SEARCH(A[0..n-1], x)
    i ← 0
    while i < n and A[i] ≠ x
        i ← i + 1
    return (i < n) ? i : -1
```

**Invariant:** x does not occur in A[0..i−1].

- *Initialisation:* i = 0, so A[0..−1] is empty. ✓
- *Maintenance:* the loop body runs only if A[i] ≠ x; after i ← i + 1, x is still absent from A[0..i−1]. ✓
- *Termination:* the variant n − i decreases each iteration, so the loop stops. Either i = n (by the invariant, x is absent: return −1 is correct) or A[i] = x (return i is correct, and it is the first occurrence). ✓

### Example 2: insertion sort

```text
INSERTION-SORT(A[0..n-1])
    for j ← 1 to n - 1
        key ← A[j]
        i ← j - 1
        while i ≥ 0 and A[i] > key
            A[i+1] ← A[i]
            i ← i - 1
        A[i+1] ← key
```

**Invariant of the outer loop:** at the start of iteration j, A[0..j−1] holds the elements originally in A[0..j−1], in sorted order.

- *Initialisation:* j = 1: A[0..0] is a single element, trivially sorted. ✓
- *Maintenance:* the inner loop shifts every element of A[0..j−1] greater than key one place right and drops key into the gap; A[0..j] is now the original first j + 1 elements, sorted. ✓
- *Termination:* the loop ends with j = n, so A[0..n−1] is sorted. ✓

```cpp
#include <iostream>
#include <vector>
using namespace std;

void insertionSort(vector<int>& a) {
    for (size_t j = 1; j < a.size(); ++j) {      // invariant: a[0..j-1] is sorted
        int key = a[j];
        size_t i = j;
        while (i > 0 && a[i - 1] > key) {        // shift larger elements right
            a[i] = a[i - 1];
            --i;
        }
        a[i] = key;
        for (int x : a) cout << x << ' ';       // trace: the sorted prefix grows by one
        cout << '\n';
    }
}

int main() {
    vector<int> a = {5, 2, 4, 6, 1, 3};
    insertionSort(a);
}
```

**Output:**

```text
2 5 4 6 1 3 
2 4 5 6 1 3 
2 4 5 6 1 3 
1 2 4 5 6 3 
1 2 3 4 5 6 
```

### Example 3: binary search

Precondition: A is sorted. Postcondition: return an index i with A[i] = x, or −1.

```text
BINARY-SEARCH(A[0..n-1], x)
    lo ← 0, hi ← n - 1
    while lo ≤ hi
        mid ← lo + (hi - lo) / 2
        if A[mid] = x  return mid
        if A[mid] < x  lo ← mid + 1
        else           hi ← mid - 1
    return -1
```

**Invariant:** if x occurs in A, it occurs in A[lo..hi].

- *Initialisation:* lo..hi is the whole array. ✓
- *Maintenance:* if A[mid] < x then, because A is sorted, every A[k] with k ≤ mid is < x, so x can only be in A[mid+1..hi]. Symmetrically for A[mid] > x. ✓
- *Termination:* the variant hi − lo + 1 at least halves each iteration. On exit lo > hi, the range is empty, so by the invariant x is absent: return −1 is correct. ✓

## Mathematical induction for recursive algorithms

**Strong induction:** to prove P(n) for all n ≥ n₀, prove P(n₀) (or several base cases), then prove P(n) assuming P(k) for **all** n₀ ≤ k < n. This matches recursion, which may call itself on any smaller input.

**Example: recursive maximum.** `maxOf(A, lo, hi)` returns A[lo] if lo = hi; otherwise it returns the larger of `maxOf(A, lo, mid)` and `maxOf(A, mid+1, hi)`.

- *Base:* one element: it is the maximum. ✓
- *Step:* both halves are smaller, so by the inductive hypothesis the calls return their maxima; the maximum of the whole range is the larger of the two. ✓

## Proof by contradiction

Assume the statement is false and derive something impossible.

**Example: Euclid's algorithm terminates.** Suppose it ran forever. Then b would take infinitely many values, each a remainder a mod b < b, so b would strictly decrease forever. But b is a non-negative integer, and a strictly decreasing sequence of non-negative integers cannot be infinite. Contradiction.

**Example: comparison search needs Ω(log n) comparisons in the worst case.** Suppose some comparison-based search always used fewer than log₂ n comparisons. Each comparison has two outcomes, so fewer than log₂ n comparisons distinguish fewer than n outcomes, but there are n possible answers. Two different answers would get the same comparison results, so the algorithm would be wrong on one of them. Contradiction.

## Correctness of an elementary data structure

For the array stack of Module 02 (`data` vector, top at `data.back()`), the **representation invariant** is: *the vector holds the stack's elements from bottom to top.* The constructor makes an empty vector (empty stack ✓), `push` appends (new top ✓), `pop` removes the last element (previous top exposed ✓), `top` reads the last element ✓. Since every operation preserves the invariant, every sequence of operations does too: this is induction on the number of operations.

## Recurrence relations

A recursive algorithm's running time satisfies a recurrence: the cost on n equals the cost of the recursive calls plus the work done outside them.

| Algorithm | Recurrence | Solution |
|---|---|---|
| Recursive sum (reduce by 1) | T(n) = T(n − 1) + c | Θ(n) |
| Binary search | T(n) = T(n/2) + c | Θ(log n) |
| Selection-style recursion | T(n) = T(n − 1) + cn | Θ(n²) |
| Merge sort | T(n) = 2T(n/2) + cn | Θ(n log n) |
| Naive Fibonacci | T(n) = T(n − 1) + T(n − 2) + c | Θ(φ^n) |
| Tower of Hanoi | T(n) = 2T(n − 1) + c | Θ(2^n) |

### Method 1: expansion (iteration)

T(n) = T(n − 1) + cn:

T(n) = cn + T(n − 1) = cn + c(n − 1) + T(n − 2) = … = c(n + (n − 1) + … + 2) + T(1) = Θ(n²).

T(n) = T(n/2) + c (n a power of 2): T(n) = c + c + … + T(1) with log₂ n copies of c, so Θ(log n).

### Method 2: the recursion tree

Draw the calls as a tree, write each node's non-recursive cost, and sum level by level.

```text
T(n) = 2T(n/2) + cn

level 0:              cn                       cost cn
level 1:       cn/2        cn/2                cost cn
level 2:   cn/4  cn/4  cn/4  cn/4              cost cn
  ...                                            ...
level k:   2^k nodes of cost cn/2^k            cost cn
leaves (k = log₂ n): n nodes of cost c          cost cn

total: cn per level × (log₂ n + 1) levels = Θ(n log n)
```

If the level costs shrink geometrically (as in T(n) = 2T(n/2) + n²: costs n², n²/2, n²/4, …) the root dominates: Θ(n²). If they grow geometrically, the leaves dominate. The Master Theorem (Module 06) packages these three situations.

### Method 3: substitution (guess and prove by induction)

Guess T(n) = O(n log n) for T(n) = 2T(⌊n/2⌋) + n with T(1) = 1. Claim: T(n) ≤ c·n log₂ n for n ≥ 2, for a suitable c.

- *Step:* assume T(⌊n/2⌋) ≤ c⌊n/2⌋ log₂⌊n/2⌋. Then T(n) ≤ 2c(n/2) log₂(n/2) + n = cn log₂ n − cn + n ≤ cn log₂ n whenever c ≥ 1. ✓
- *Base:* T(2) = 2T(1) + 2 = 4 and T(3) = 2T(1) + 3 = 5; with c = 2, 2·2·1 = 4 ≥ 4 and 2·3·log₂3 ≈ 9.5 ≥ 5. ✓ (n = 1 is excluded because log₂ 1 = 0; that is why base cases start at 2.)

## Space complexity derivations

Recursion uses one stack frame per active call. Space = (frame size) × (maximum depth):

- Recursive binary search: depth log₂ n → Θ(log n) space (an iterative version uses Θ(1)).
- Merge sort: depth log₂ n, plus a Θ(n) buffer for merging → Θ(n).
- Recursion that reduces n by 1: depth n → Θ(n). For n = 10^6 this can overflow a typical 8 MB stack.

## Complexity analysis summary

| Technique | Use it when |
|---|---|
| Exact counting with sums | Loops with known bounds |
| Expansion | Recurrences that reduce n by a constant or a constant factor, with one call |
| Recursion tree | Several recursive calls; to *see* where the cost is |
| Substitution | To *prove* a guessed bound rigorously |
| Master Theorem | T(n) = aT(n/b) + f(n) (Module 06) |

## Implementation: checking a recurrence numerically

The program evaluates T(n) = 2T(⌊n/2⌋) + n, T(1) = 1 exactly and compares it with n log₂ n. The ratio approaches 1, consistent with Θ(n log n).

```cpp
#include <cmath>
#include <iomanip>
#include <iostream>
using namespace std;

long long T(long long n) {
    if (n <= 1) return 1;
    return 2 * T(n / 2) + n;           // depth log2 n; both calls have the same argument
}

int main() {
    for (long long n : {16LL, 1024LL, 1048576LL}) {
        long long t = T(n);
        double ratio = t / (n * log2(static_cast<double>(n)));
        cout << n << ' ' << t << ' ' << fixed << setprecision(3) << ratio << '\n';
    }
}
```

**Output:**

```text
16 80 1.250
1024 11264 1.100
1048576 22020096 1.050
```

For n = 2^k the exact solution is T(n) = n(k + 1) = n log₂ n + n, so the ratio is (k + 1)/k.

## Dry run

T(16) = 2T(8) + 16; T(8) = 2T(4) + 8; T(4) = 2T(2) + 4; T(2) = 2T(1) + 2 = 4; so T(4) = 12, T(8) = 32, T(16) = 80 = 16 · 5 = n(log₂ n + 1). ✓

## Common mistakes and edge cases

- **An invariant that is true but useless:** "i ≥ 0" holds, but does not imply the postcondition. The invariant must say *what has been achieved so far*.
- **Forgetting termination:** partial correctness is not enough; give a decreasing variant.
- **Assuming the claim in the induction step** for the same n, instead of smaller values.
- **The growing-constant fallacy:** "T(n) = 2T(n/2) + n ≤ 2c(n/2) + n = cn + n = O(n)" is wrong: the step must reproduce *exactly* c·n, not (c + 1)·n.
- **Ignoring floors and ceilings** in recurrences; they rarely change the Θ bound, but base cases must be checked.
- **Counting only time:** recursion depth is memory.

## Applications

- Invariants are how library code (sorting, binary search, hash tables) is verified, and they make good comments.
- Recurrences analyse every divide-and-conquer algorithm in the course: binary search, merge sort, quick sort, tree algorithms.
- Interviewers often ask "why does this work?" after you code a solution; an invariant is the best answer.

## Key takeaways

- Correct = postcondition holds for every input meeting the precondition, and the algorithm terminates.
- Loop invariant: initialisation, maintenance, termination (with a decreasing variant).
- Strong induction proves recursive algorithms; contradiction proves impossibility and termination.
- Write recurrences from code, then solve by expansion, recursion tree or substitution.
- In substitution proofs the constant must not grow; check the base cases.
