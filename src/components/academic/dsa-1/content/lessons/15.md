# Module 15: Binary Search Trees

## Learning objectives

- State the BST ordering property and use it to search, insert and delete.
- Handle the three deletion cases.
- Find minimum, maximum, predecessor and successor.
- Explain average versus worst-case cost and why balanced trees exist.

## Prerequisites

[Module 11](topic:trees).

## Intuition

A BST keeps every key in the left subtree smaller and every key in the right subtree larger than the node's key. Searching is then like binary search: each comparison discards one subtree.

## Operations

| Operation | Idea |
|---|---|
| search(k) | go left if k < node, right if k > node |
| insert(k) | search for k; attach a new leaf where the search ends |
| min / max | leftmost / rightmost node |
| successor | leftmost node of the right subtree, or the nearest ancestor reached from a left child |
| inorder traversal | visits keys in **sorted order** |

## Deletion cases

1. **Leaf:** remove it.
2. **One child:** replace the node by its child.
3. **Two children:** copy the inorder successor's key into the node, then delete the successor (which has at most one child).

## Cost: average versus worst case

All operations cost O(h), where h is the height. For random insertion orders h is O(log n) on average, but inserting sorted keys produces a **degenerate tree** (a linked list) with h = n − 1, so operations become O(n). **An ordinary BST does not guarantee O(log n).** Balanced BSTs (AVL, red-black; `std::set`/`std::map`) keep h = O(log n) by rebalancing (DSA II).

## Validation

A tree is a BST iff every node's key lies in the (low, high) range inherited from its ancestors; checking only each node against its children is a common error.

## Complexity analysis

search, insert, delete, min, max, successor: O(h); h = O(log n) on average for random inputs, O(n) in the worst case; inorder traversal O(n).

## Implementation (C++17)

```cpp
#include <iostream>
#include <memory>
using namespace std;

struct Node {
    int key;
    unique_ptr<Node> left, right;
    explicit Node(int k) : key(k) {}
};

void insert(unique_ptr<Node>& t, int k) {
    if (!t) { t = make_unique<Node>(k); return; }
    if (k < t->key) insert(t->left, k);
    else if (k > t->key) insert(t->right, k);         // duplicates ignored
}

void erase(unique_ptr<Node>& t, int k) {
    if (!t) return;
    if (k < t->key) { erase(t->left, k); return; }
    if (k > t->key) { erase(t->right, k); return; }
    if (!t->left) { t = std::move(t->right); return; }  // leaf or right child only
    if (!t->right) { t = std::move(t->left); return; }  // left child only
    Node* s = t->right.get();                          // two children: inorder successor
    while (s->left) s = s->left.get();
    t->key = s->key;
    erase(t->right, s->key);
}

void inorder(const Node* t) { if (!t) return; inorder(t->left.get()); cout << t->key << ' '; inorder(t->right.get()); }

int main() {
    unique_ptr<Node> root;
    for (int k : {50, 30, 70, 20, 40, 60, 80}) insert(root, k);
    erase(root, 30);                                   // two children
    erase(root, 20);                                   // leaf
    inorder(root.get());
    cout << '\n';
}
```

## Pseudocode

```text
SEARCH(t, k)
    while t ≠ null and t.key ≠ k:
        t ← (k < t.key) ? t.left : t.right
    return t
SUCCESSOR(t)                     // t has a right child
    t ← t.right; while t.left ≠ null: t ← t.left; return t
```

## Dry run

Insert 50, 30, 70, 20, 40, 60, 80. Search 60: 60 > 50 → right (70); 60 < 70 → left (60): found after 3 comparisons. Delete 30 (two children): successor 40 replaces it.

## Applications

Ordered sets and maps (`std::set`, `std::map`), range queries ([DSA15-E05](problem:DSA15-E05)), floor/ceiling lookups ([DSA15-H04](problem:DSA15-H04)), booking systems ([DSA-C23](problem:DSA-C23)), nearest-value search ([DSA-C17](problem:DSA-C17)), database indexes (B-trees generalise BSTs).

## Comparison with related concepts

| | Ordinary BST | Balanced BST | Hash table |
|---|---|---|---|
| search/insert/delete | O(h), worst O(n) | O(log n) guaranteed | O(1) expected |
| Ordered traversal, floor, range | yes | yes | no |
| Degenerates on sorted input | yes ([DSA15-E04](problem:DSA15-E04)) | no | no (needs good hashing) |

## Common mistakes and edge cases

- Claiming O(log n) for an unbalanced BST.
- Validating only parent-child pairs.
- Losing a subtree in the two-children deletion case.
- Recursion depth n on degenerate trees.

## Key takeaways

- Left < node < right; inorder gives sorted keys.
- Every operation is O(h).
- Deletion has three cases; use the successor for two children.
- Sorted insertions degenerate the tree; balanced trees fix this.
