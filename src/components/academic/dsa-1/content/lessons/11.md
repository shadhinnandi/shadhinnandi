# Module 11: Trees and Tree Traversals

## Learning objectives

- Use tree terminology precisely.
- Distinguish full, complete and perfect binary trees.
- Implement preorder, inorder, postorder (recursive and iterative) and level-order traversals.
- Reconstruct a tree from preorder + inorder, and compute height and size.

## Prerequisites

[Module 08](topic:linked-lists), [Module 09](topic:stacks), [Module 10](topic:queues).

## Intuition

A tree is a hierarchy: one root, and every other node has exactly one parent. File systems, organisation charts and expression trees are all trees.

## Terminology

| Term | Meaning |
|---|---|
| Root, parent, child, leaf | top node; node above; node below; node with no children |
| Depth of a node | edges from the root to it |
| Height of a tree | edges on the longest root-to-leaf path (−1 for an empty tree, 0 for one node) |
| Degree | number of children of a node |
| Subtree | a node together with all its descendants |

## Binary tree shapes

| Shape | Definition |
|---|---|
| Full | every node has 0 or 2 children |
| Complete | every level full except possibly the last, which is filled left to right |
| Perfect | all internal nodes have 2 children and all leaves are at the same depth (2^(h+1) − 1 nodes) |

Every perfect tree is full and complete; the converse fails.

## Representations

Linked nodes {value, left, right}; array (for complete trees: children of i at 2i+1 and 2i+2); first-child/next-sibling for general trees.

## Traversals

```text
        1
      /   \
     2     3
    / \
   4   5
preorder (root, left, right):  1 2 4 5 3
inorder  (left, root, right):  4 2 5 1 3
postorder (left, right, root): 4 5 2 3 1
level order (BFS):             1 2 3 4 5
```

Iterative versions use an explicit stack (pre/in/post) or a queue (level order).

## Reconstruction

Preorder + inorder (distinct keys) determine a binary tree: the first preorder element is the root; its position in inorder splits the left and right subtrees; recurse. Preorder + postorder alone do not determine it in general.

## Basic algorithms

height(t) = −1 if empty else 1 + max(height(left), height(right)); size(t) = 0 if empty else 1 + size(left) + size(right). Both visit each node once.

## Complexity analysis

Every traversal visits each node once: O(n) time; space O(h) for recursion/stack (h = height, up to n for a degenerate tree), O(width) for level order.

## Implementation (C++17)

```cpp
#include <iostream>
#include <memory>
#include <queue>
using namespace std;

struct Node {
    int value;
    unique_ptr<Node> left, right;
    explicit Node(int v) : value(v) {}
};

void preorder(const Node* t)  { if (!t) return; cout << t->value << ' '; preorder(t->left.get()); preorder(t->right.get()); }
void inorder(const Node* t)   { if (!t) return; inorder(t->left.get()); cout << t->value << ' '; inorder(t->right.get()); }
void postorder(const Node* t) { if (!t) return; postorder(t->left.get()); postorder(t->right.get()); cout << t->value << ' '; }
int height(const Node* t) { return t ? 1 + max(height(t->left.get()), height(t->right.get())) : -1; }

int main() {
    auto root = make_unique<Node>(1);
    root->left = make_unique<Node>(2);
    root->right = make_unique<Node>(3);
    root->left->left = make_unique<Node>(4);
    root->left->right = make_unique<Node>(5);
    preorder(root.get()); cout << '\n';
    inorder(root.get()); cout << '\n';
    postorder(root.get()); cout << '\n';
    queue<const Node*> q;                      // level order
    q.push(root.get());
    while (!q.empty()) {
        const Node* t = q.front(); q.pop();
        cout << t->value << ' ';
        if (t->left) q.push(t->left.get());
        if (t->right) q.push(t->right.get());
    }
    cout << "\nheight " << height(root.get()) << '\n';
}
```

## Pseudocode

```text
BUILD(pre, in)                   // distinct keys
    if in is empty: return null
    root ← first unused element of pre
    split in at root into L and R
    root.left ← BUILD(pre, L); root.right ← BUILD(pre, R)
    return root
```

## Applications

File systems and organisation charts (general trees, [DSA-C22](problem:DSA-C22)), expression trees ([DSA11-H04](problem:DSA11-H04)), heaps and BSTs (Modules 14 and 15), decision trees, HTML/XML documents.

## Comparison with related concepts

| Traversal | Order | Typical use |
|---|---|---|
| Preorder | root, left, right | copying a tree, prefix expressions |
| Inorder | left, root, right | sorted output of a BST |
| Postorder | left, right, root | deleting a tree, evaluating expressions |
| Level order | by depth | shortest depth, printing levels |

## Common mistakes and edge cases

- Mixing up height conventions (edges vs nodes).
- Calling a complete tree 'full' or vice versa.
- Recursion depth n on degenerate trees: use an explicit stack.
- Assuming preorder + postorder determine a binary tree.

## Key takeaways

- Know the terms: depth, height, degree, subtree.
- Full ≠ complete ≠ perfect.
- Four traversals, all O(n).
- Preorder + inorder reconstruct a binary tree with distinct keys.
