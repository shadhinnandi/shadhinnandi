# Module 16A: Heap Sort

## Learning objectives

- Sort in place with a max-heap.
- Dry-run build-heap and the extraction phase.
- State complexity and stability.

## Prerequisites

[Module 14](topic:heaps), [Module 04](topic:asymptotic-analysis) and [Module 05](topic:correctness-and-recurrences).

## Intuition

Build a max-heap, then repeatedly swap the maximum (root) to the end of the array and restore the heap on the shrinking prefix.

## Procedure

1. Build a max-heap in place (sift down from index n/2 − 1 to 0): O(n).
2. For end = n − 1 down to 1: swap a[0] and a[end]; sift down a[0] within a[0..end−1].

## Dry run: [4, 10, 3, 5, 1]

| Step | Array |

| swap 10, sift | [5, 4, 3, 1, \| 10] |
| swap 5, sift | [4, 1, 3, \| 5, 10] |
| swap 4, sift | [3, 1, \| 4, 5, 10] |
| swap 3 | [1, \| 3, 4, 5, 10] |

## Properties

- Time Θ(n log n) in **every** case (best, average, worst).
- In place: O(1) extra space.
- **Not stable**: the swaps move equal keys past each other.
- Poorer cache behaviour than quick sort in practice.

## Complexity analysis

Θ(n log n) time in all cases (O(n) build + n − 1 sift-downs of O(log n)); O(1) auxiliary space; not stable.

## Implementation (C++17)

```cpp
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

void siftDown(vector<int>& a, size_t i, size_t n) {   // heap is a[0..n-1]
    for (;;) {
        size_t largest = i, l = 2 * i + 1, r = l + 1;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) return;
        swap(a[i], a[largest]);
        i = largest;
    }
}

void heapSort(vector<int>& a) {
    size_t n = a.size();
    for (size_t i = n / 2; i-- > 0;) siftDown(a, i, n);   // build max-heap, O(n)
    for (size_t end = n; end-- > 1;) {
        swap(a[0], a[end]);                               // max goes to its final place
        siftDown(a, 0, end);
    }
}

int main() {
    vector<int> a = {4, 10, 3, 5, 1};
    heapSort(a);
    for (int x : a) cout << x << ' ';
    cout << '\n';
}
```

## Pseudocode

```text
HEAP-SORT(A[0..n-1])
    BUILD-MAX-HEAP(A)
    for end ← n-1 down to 1:
        swap A[0], A[end]
        SIFT-DOWN(A, 0, end)
```

## Correctness

Invariant: before each iteration, A[0..end] is a max-heap holding the end + 1 smallest elements, and A[end+1..n−1] holds the largest elements in sorted order. Swapping the root (the maximum of the heap) into position end extends the sorted suffix; sift-down restores the heap.

## Applications

Systems that need a guaranteed O(n log n) with O(1) extra memory (embedded code), the fallback inside introsort ([DSA16C-H04](problem:DSA16C-H04)), partial sorting of the k smallest ([DSA16A-M01](problem:DSA16A-M01)).

## Comparison with related concepts

Heap sort matches merge sort's worst-case Θ(n log n) without merge sort's Θ(n) buffer, but it is not stable ([DSA16A-E05](problem:DSA16A-E05)) and usually slower than quick sort because its memory accesses jump around the array.

## Common mistakes and edge cases

- Sifting down over the whole array instead of the shrinking heap.
- Building the heap from index 0 upwards.
- Claiming heap sort is stable.

## Key takeaways

- Build-heap O(n), then n − 1 extractions O(log n) each.
- Θ(n log n) worst case, in place, not stable.
