## Intuition

Comparison sorts only learn about keys by comparing pairs. If keys are small integers (or digits), we can use them directly as array indices and avoid comparisons altogether.

## The comparison lower bound

A comparison sort is a decision tree whose leaves are the n! possible orderings; a binary tree with n! leaves has height ≥ log₂(n!) = Θ(n log n). So **any comparison sort** needs Ω(n log n) comparisons in the worst case. Counting/radix/bucket sort do not compare keys; they assume something about the keys (bounded range, fixed digits, uniform distribution), so the bound does not apply to them.

## Algorithms

| Algorithm | Precondition | Time | Space | Stable |
|---|---|---|---|---|
| Counting sort | integer keys in [0, k] | Θ(n + k) | Θ(n + k) | Yes (with prefix sums, filled right to left) |
| Radix sort (LSD) | d-digit keys in base b | Θ(d(n + b)) | Θ(n + b) | Yes (each pass must be stable) |
| Bucket sort | keys roughly uniform in [0, 1) | Θ(n) expected, Θ(n²) worst | Θ(n) | Yes if buckets use a stable sort |

## Comparative table of the course's sorts

| Sort | Best | Average | Worst | Extra space | Stable | In place |
|---|---|---|---|---|---|---|
| Insertion | n | n² | n² | 1 | Yes | Yes |
| Heap | n log n | n log n | n log n | 1 | No | Yes |
| Merge | n log n | n log n | n log n | n | Yes | No |
| Quick (random) | n log n | n log n | n² | log n | No | Yes |
| Counting | n + k | n + k | n + k | n + k | Yes | No |
| Radix | d(n + b) | d(n + b) | d(n + b) | n + b | Yes | No |

**Use cases:** small or nearly sorted arrays → insertion; guaranteed bound, little memory → heap; stability or linked lists → merge; general-purpose speed → quick (introsort); small integer keys → counting/radix.

## Complexity analysis

Counting sort Θ(n + k); radix Θ(d(n + b)); bucket Θ(n) expected. Useful only when k (or d, b) is small relative to n; with k = 10^9 counting sort is impossible.

## Implementation (C++17)

```cpp
#include <iostream>
#include <vector>
using namespace std;

// Stable counting sort of values in [0, k].
vector<int> countingSort(const vector<int>& a, int k) {
    vector<int> count(k + 1, 0), out(a.size());
    for (int x : a) ++count[x];
    for (int v = 1; v <= k; ++v) count[v] += count[v - 1];   // count[v] = number of keys <= v
    for (size_t i = a.size(); i-- > 0;) out[--count[a[i]]] = a[i];   // right to left: stable
    return out;
}

int main() {
    vector<int> a = {4, 1, 3, 4, 3, 0, 2};
    for (int x : countingSort(a, 4)) cout << x << ' ';
    cout << '\n';
}
```

## Pseudocode

```text
COUNTING-SORT(A, k)              // stable, keys in [0, k]
    C[0..k] ← 0; for x in A: C[x] ← C[x] + 1
    for v ← 1 to k: C[v] ← C[v] + C[v-1]
    for i ← n-1 down to 0: C[A[i]] ← C[A[i]] - 1; B[C[A[i]]] ← A[i]
RADIX-SORT(A, d)  for digit ← least to most significant: stable COUNTING-SORT by that digit
```

## Common mistakes and edge cases

- Using counting sort when the key range is huge.
- Filling left to right after prefix sums (loses stability, breaks radix sort).
- Saying radix sort beats the lower bound in general (it relies on bounded digits).

## Key takeaways

- Comparison sorts need Ω(n log n); non-comparison sorts exploit key structure.
- Counting sort is stable Θ(n + k); radix sort repeats a stable pass per digit.
- Choose a sort by size, key type, stability and memory.
