# Module 14: Heaps

## Learning objectives

- Define min-heaps and max-heaps and store them in arrays.
- Implement sift-up, sift-down, insert, extract and peek.
- Build a heap in O(n) and explain why.
- Use heaps as priority queues for top-k and scheduling problems.

## Prerequisites

[Module 11](topic:trees) (complete binary trees) and [Module 07](topic:arrays).

## Intuition

A max-heap keeps the largest element at the root of a complete binary tree, with every parent ≥ its children. It is only partly sorted, which is exactly enough to always know the maximum and update it in O(log n).

## Array representation

For a node at index i (0-based): parent (i − 1)/2, left child 2i + 1, right child 2i + 2. The tree is complete, so there are no gaps and the height is ⌊log₂ n⌋.

**Heap property (max-heap):** a[parent(i)] ≥ a[i] for every i > 0. (Min-heap: ≤.) This is unrelated to the heap memory region (Module 01).

## Operations

| Operation | How | Cost |
|---|---|---|
| peek | a[0] | O(1) |
| insert | append, then **sift up** while larger than the parent | O(log n) |
| extract-max | move the last element to the root, then **sift down** (swap with the larger child) | O(log n) |
| build-heap | sift down every internal node from the last one up to the root | O(n) |

**Why build-heap is O(n):** about n/2^(h+1) nodes have height h, and sifting one down costs O(h), so the total is Σ h·n/2^(h+1) = n·Σ h/2^(h+1) = O(n) (the series converges to 1).

## Priority queues and applications

`std::priority_queue` is a max-heap (use `greater<>` for a min-heap). Top-k largest elements: keep a min-heap of size k (O(n log k)). Scheduling: always run the most urgent task. Heap sort ([Module 16A](topic:heap-sort)).

## Complexity analysis

peek O(1); insert and extract O(log n); build-heap O(n); space O(n) in a single array.

## Implementation (C++17)

```cpp
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

class MaxHeap {
    vector<int> a;
    void siftUp(size_t i) {
        while (i > 0 && a[(i - 1) / 2] < a[i]) { swap(a[(i - 1) / 2], a[i]); i = (i - 1) / 2; }
    }
    void siftDown(size_t i) {
        for (;;) {
            size_t largest = i, l = 2 * i + 1, r = 2 * i + 2;
            if (l < a.size() && a[l] > a[largest]) largest = l;
            if (r < a.size() && a[r] > a[largest]) largest = r;
            if (largest == i) return;
            swap(a[i], a[largest]);
            i = largest;
        }
    }
public:
    void push(int x) { a.push_back(x); siftUp(a.size() - 1); }
    int top() const { return a[0]; }                     // precondition: !empty()
    void pop() { a[0] = a.back(); a.pop_back(); if (!a.empty()) siftDown(0); }
    bool empty() const { return a.empty(); }
};

int main() {
    MaxHeap h;
    for (int x : {5, 1, 9, 3, 7}) h.push(x);
    while (!h.empty()) { cout << h.top() << ' '; h.pop(); }   // 9 7 5 3 1
    cout << '\n';
}
```

## Common mistakes and edge cases

- Swapping with the smaller child in a max-heap sift-down.
- Index formulas for 1-based vs 0-based arrays.
- Thinking a heap is sorted (only the root is known).
- Building a heap by n insertions (O(n log n)) when O(n) build-heap suffices.

## Key takeaways

- Complete tree in an array: children at 2i+1, 2i+2.
- Insert = sift up; extract = sift down; both O(log n).
- Build-heap is O(n).
- Heaps implement priority queues; use a size-k min-heap for top-k.
