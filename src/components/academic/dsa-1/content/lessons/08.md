# Module 08: Linked Lists

## Learning objectives

- Implement singly, doubly and circular linked lists.
- Insert, delete, search, reverse and merge lists by pointer manipulation.
- Use dummy/sentinel nodes to remove special cases.
- Compare linked lists with arrays.

## Prerequisites

[Module 01](topic:data-representation) (pointers, non-contiguous storage) and [Module 07](topic:arrays).

## Intuition

A linked list stores each element in its own node, with a pointer to the next node (and, in a doubly linked list, the previous one). Nodes can be anywhere in memory, so inserting is just relinking pointers, but reaching the i-th node means walking i links.

## Definitions and terminology

| Term | Meaning |
|---|---|
| Node | {data, next} (singly) or {data, prev, next} (doubly) |
| head / tail | first / last node |
| Circular list | the tail's next points back to the head |
| Dummy (sentinel) node | an extra node before the head so insertion/deletion at the front needs no special case |

```text
singly:   head -> [10|*] -> [20|*] -> [30|null]
doubly:   null <- [10] <-> [20] <-> [30] -> null
circular: [10] -> [20] -> [30] -+
           ^--------------------+
```

## Core operations

| Operation | Singly | Doubly |
|---|---|---|
| Insert at head | O(1) | O(1) |
| Insert at tail (with tail pointer) | O(1) | O(1) |
| Delete a given node | O(n) (need predecessor) | O(1) |
| Search / access i-th | O(n) | O(n) |
| Reverse | O(n), three pointers | O(n) |
| Merge two sorted lists | O(n + m) | O(n + m) |

**Reversal invariant:** `prev` is the reversed prefix, `cur` the rest; each step moves one node from `cur` to the front of `prev`.

## Memory overhead and pointer errors

Each node costs one or two extra pointers (8–16 bytes). Common errors: losing the rest of the list by overwriting `next` too early, dereferencing nullptr, dangling pointers after delete, memory leaks.

## Array versus linked list

| | Array | Linked list |
|---|---|---|
| Access by index | O(1) | O(n) |
| Insert/delete at known node | O(n) | O(1) |
| Memory per element | data only | data + pointers |
| Cache behaviour | excellent | poor |

## Complexity analysis

Traversal, search, reversal O(n); insertion/deletion at a known position O(1) (doubly) ; space O(n) plus pointer overhead.

## Implementation (C++17)

```cpp
#include <iostream>
using namespace std;

struct Node {
    int value;
    Node* next;
};

Node* reverse(Node* head) {               // invariant: prev = reversed prefix
    Node* prev = nullptr;
    while (head) {
        Node* nextNode = head->next;      // save the rest before relinking
        head->next = prev;
        prev = head;
        head = nextNode;
    }
    return prev;
}

int main() {
    Node* head = nullptr;
    for (int v = 5; v >= 1; --v) head = new Node{v, head};   // 1 2 3 4 5
    head = reverse(head);
    for (Node* p = head; p; p = p->next) cout << p->value << ' ';
    cout << '\n';
    while (head) { Node* nextNode = head->next; delete head; head = nextNode; }   // free every node
}
```

## Common mistakes and edge cases

- Losing the list by updating next before saving it.
- Forgetting to update tail or head on deletion.
- Not freeing nodes (leaks) or using them after delete.
- Infinite loops on circular lists without a stopping condition.

## Key takeaways

- Linked lists trade O(1) access for O(1) relinking.
- A dummy head removes front-of-list special cases.
- Reverse with three pointers; merge with a dummy head.
- Prefer arrays unless you need frequent middle insertion.
