# Module 00: Programming and Mathematical Prerequisites

## Learning objectives

By the end of this module you can:

- Write C++17 functions that take parameters **by value**, **by reference** and **by const reference**, and explain the difference in cost.
- Use arrays, `std::vector`, pointers and references without undefined behaviour.
- Trace a recursive function and identify its base case and recursive case.
- Use logarithms, arithmetic and geometric sums, sets and mathematical induction in algorithm analysis.
- Read input constraints, estimate whether an algorithm is fast enough, and avoid integer overflow.

This module is a **refresher**, not a first programming course. If any section feels new, practise it before Module 01, because every later module assumes it.

## Prerequisites

Basic programming in any C-family language: variables, `if`, loops and functions. No previous data structures course is needed.

## Intuition: why DSA needs these tools

A data structure is a way of **arranging data in memory** so that the operations you need are fast. An algorithm is a **precise procedure** that solves a problem. To study either, you need three kinds of tools:

| Tool | Why DSA needs it |
|---|---|
| **Programming** (functions, loops, arrays, pointers, recursion) | To build structures from scratch and implement algorithms correctly |
| **Mathematics** (logarithms, sums, induction) | To count steps, compare algorithms and prove that they work |
| **Constraint awareness** (input size, overflow, edge cases) | To choose an algorithm that is fast enough and gives the right answer on every valid input |

## Definitions and terminology

| Term | Meaning |
|---|---|
| **Variable** | A named piece of memory with a type, such as `int count = 0;` |
| **Pass by value** | The function receives a *copy*; changes do not affect the caller |
| **Pass by reference** (`T&`) | The function works on the caller's variable itself |
| **Const reference** (`const T&`) | No copy and no modification: the usual way to pass large objects |
| **Pointer** (`T*`) | A variable that stores a memory address; `*p` reads the value there |
| **Recursion** | A function that calls itself on a smaller input until a **base case** |
| **Constraint** | A limit on the input, such as `1 ≤ n ≤ 2·10^5`, that tells you how fast the solution must be |
| **Overflow** | A result too large for its type; for signed integers in C++ it is **undefined behaviour** |

## Programming refresher

### Functions and parameter passing

```cpp
#include <iostream>
#include <vector>
using namespace std;

void byValue(int x) {                      // x is a copy
    x = 100;
    cout << "inside byValue: " << x << '\n';
}
void byReference(int& x) { x = 100; }      // changes the caller's variable
long long total(const vector<int>& v) {    // no copy, read-only
    long long s = 0;
    for (int x : v) s += x;
    return s;
}

int main() {
    int a = 1, b = 1;
    byValue(a);
    byReference(b);
    vector<int> v = {4, 5, 6};
    cout << a << ' ' << b << ' ' << total(v) << '\n';
}
```

**Output:**

```text
inside byValue: 100
1 100 15
```

Passing a `vector` **by value** copies every element, which costs O(n) time and memory for each call. Inside a loop or a recursive function, that hidden copy can turn an O(n) algorithm into O(n²). Use `const vector<int>&` unless you really need a copy.

### Loops and arrays

An array stores elements **contiguously** (next to each other in memory), so `a[i]` is found in constant time by computing an address. `std::vector` is a resizable array; prefer it to raw arrays in C++.

```cpp nocompile
vector<int> a(n);            // n zeros
for (int i = 0; i < n; ++i)  // indices 0 .. n-1; a[n] is out of bounds
    cin >> a[i];
```

The most common array bug is an **off-by-one** error: looping to `i <= n`, or reading `a[i + 1]` when `i == n - 1`.

### Pointers and references

```cpp nocompile
int x = 7;
int* p = &x;      // p holds the address of x
*p = 9;           // x is now 9
int& r = x;       // r is another name for x
r = 11;           // x is now 11
int* q = nullptr; // a pointer to nothing; *q would be undefined behaviour
```

Pointers are essential for linked structures (linked lists, trees). Two rules prevent most pointer bugs: **never dereference `nullptr`**, and **never use a pointer to memory that has been freed**.

### Recursion

A recursive function needs:

1. A **base case** that is answered directly.
2. A **recursive case** that reduces the problem to a smaller instance.

```cpp nocompile
long long power(long long base, int exp) {     // exp >= 0
    if (exp == 0) return 1;                     // base case
    long long half = power(base, exp / 2);      // smaller instance
    return (exp % 2 == 0) ? half * half : half * half * base;
}
```

Each call is stored on the **call stack** until it returns. This function makes about log₂(exp) nested calls; a function that recurses once per element of a million-element input may overflow the stack (Module 09 covers the call stack in detail).

### Memory basics

| Region | What lives there | Lifetime |
|---|---|---|
| **Stack** | Local variables and function call frames | Until the function returns |
| **Heap** (free store) | Memory from `new` or inside containers such as `vector` | Until `delete`, or until the container is destroyed |

The heap *memory region* is unrelated to the heap *data structure* in Module 14. Module 01 explains memory layout in depth.

## Mathematics refresher

### Logarithms

log_b(n) is the power you raise b to in order to get n. In algorithm analysis, log means **log₂** unless stated otherwise.

| Fact | Why it matters |
|---|---|
| log₂(1024) = 10, log₂(10^6) ≈ 20, log₂(10^9) ≈ 30 | Halving a million items takes about 20 steps |
| log_b(n) = log₂(n) / log₂(b) | All logarithm bases differ by a constant factor, so O(log n) needs no base |
| log(xy) = log x + log y | Used when simplifying sums of logarithms |
| Repeatedly halving n reaches 1 after ⌊log₂ n⌋ steps | The source of every O(log n) loop |

### Summations

| Sum | Closed form | Appears in |
|---|---|---|
| 1 + 2 + … + n | n(n+1)/2 = Θ(n²) | Nested loops where the inner loop grows |
| 1² + 2² + … + n² | n(n+1)(2n+1)/6 = Θ(n³) | Triple loops |
| 1 + 2 + 4 + … + 2^k | 2^(k+1) − 1 | Doubling (dynamic arrays, recursion trees) |
| 1 + r + r² + … + r^k, r ≠ 1 | (r^(k+1) − 1)/(r − 1) | Geometric recursion trees |
| 1 + 1/2 + 1/3 + … + 1/n | ≈ ln n = Θ(log n) | Harmonic loops |

### Sets

A set is a collection of **distinct** elements. Union A ∪ B, intersection A ∩ B and difference A − B appear throughout the course (Module 17 implements them). |A| is the number of elements; a set of n elements has 2^n subsets, which is why trying every subset is only feasible for small n.

### Mathematical induction

To prove a statement P(n) for every n ≥ n₀:

1. **Base case:** prove P(n₀).
2. **Inductive step:** assume P(k) for an arbitrary k ≥ n₀ (the *inductive hypothesis*), and prove P(k + 1).

**Example.** Prove 1 + 2 + … + n = n(n+1)/2 for all n ≥ 1.

- Base: n = 1 gives 1 = 1·2/2. ✓
- Step: assume 1 + … + k = k(k+1)/2. Then 1 + … + k + (k+1) = k(k+1)/2 + (k+1) = (k+1)(k+2)/2, which is the formula for n = k + 1. ✓

Induction is how we prove recursive algorithms correct (Module 05) and how we verify recurrence solutions.

## Constraints, edge cases and overflow

### Reading constraints

A typical judge or lab machine performs roughly **10^8 simple operations per second**. Use the constraint to choose the complexity before writing code:

| Largest n | Comfortable complexity |
|---|---|
| n ≤ 10–12 | O(n!) |
| n ≤ 20–25 | O(2^n) or O(2^n · n) |
| n ≤ 500 | O(n³) |
| n ≤ 5000 | O(n²) |
| n ≤ 2·10^5 to 10^6 | O(n log n) or O(n) |
| n ≤ 10^18 | O(log n) or O(1): use a formula |

### Integer types and overflow

| Type | Range (typical) |
|---|---|
| `int` | about ±2.1 · 10^9 |
| `long long` | about ±9.2 · 10^18 |
| `unsigned long long` | 0 to about 1.8 · 10^19 |

Signed overflow is **undefined behaviour** in C++: the program may print a wrong answer, or behave unpredictably.

```cpp nocompile
int n = 100000;
long long bad = n * n;               // overflow: n * n is computed in int first
long long good = 1LL * n * n;        // 10000000000, computed in long long
```

Rules: sum many `int` values into a `long long`; cast **before** multiplying; when reducing modulo m, reduce after every operation.

### Edge cases to test every time

- The smallest input (n = 0 or n = 1, an empty string).
- The largest input (does it overflow? is it fast enough?).
- All elements equal; already sorted; sorted in reverse.
- Negative numbers and zero.
- Duplicates.

## Complexity analysis

The tools in this module have these costs, which later modules use constantly:

| Operation | Time |
|---|---|
| `a[i]` in an array or vector | O(1) |
| Passing a vector by value | O(n) copy |
| Passing by reference / const reference | O(1) |
| Recursion halving n each call (like `power`) | O(log n) time, O(log n) stack |
| Recursion reducing n by 1 each call | O(n) stack depth |

## Implementation: a complexity-aware program

The program below reads n numbers, prints their sum (safely in `long long`), the maximum, and how many halvings reduce n to 1 (that is, ⌊log₂ n⌋).

```cpp
#include <iostream>
#include <vector>
using namespace std;

int floorLog2(long long n) {      // number of halvings until n == 1, for n >= 1
    int steps = 0;
    while (n > 1) {
        n /= 2;
        ++steps;
    }
    return steps;
}

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;

    long long sum = 0, best = a[0];
    for (long long x : a) {
        sum += x;                      // long long: no overflow for 2e5 values up to 1e9
        if (x > best) best = x;
    }
    cout << "sum " << sum << '\n';
    cout << "max " << best << '\n';
    cout << "halvings " << floorLog2(n) << '\n';
}
```

**Input:**

```text
5
1000000000 1000000000 1000000000 7 -3
```

**Output:**

```text
sum 3000000004
max 1000000000
halvings 2
```

## Dry run

For the input above:

| Step | x | sum | best |
|---|---|---|---|
| start | | 0 | 1000000000 |
| 1 | 1000000000 | 1000000000 | 1000000000 |
| 2 | 1000000000 | 2000000000 | 1000000000 |
| 3 | 1000000000 | 3000000000 | 1000000000 |
| 4 | 7 | 3000000007 | 1000000000 |
| 5 | −3 | 3000000004 | 1000000000 |

`floorLog2(5)`: 5 → 2 → 1, so 2 halvings. With `int sum`, step 3 would already overflow (3 · 10^9 > 2.1 · 10^9).

## Common mistakes and edge cases

- **Multiplying two `int`s and storing in `long long`**: the multiplication overflows first. Write `1LL * a * b`.
- **Copying large containers** by passing them by value inside loops or recursion.
- **Missing base case** in recursion, or a recursive case that does not shrink the input: infinite recursion and a stack overflow.
- **Off-by-one loops**: `for (i = 0; i <= n; ++i)` reads one element too many.
- **Ignoring n = 1 or empty input**: `a[0]` on an empty vector is undefined behaviour.
- **Using floating point for exact integer answers**: `pow(10, 18)` returns a `double` that may not be exact; use integer loops or exact formulas.

## Applications

- Constraint reading decides the algorithm before any code is written, in labs, contests and interviews alike.
- Logarithms explain binary search, balanced trees, heaps and merge sort.
- Summations analyse nested loops; induction proves loops and recursion correct.
- Overflow awareness is essential in counting problems, prefix sums and hashing.

## Comparison with related concepts

| | Pass by value | Pass by reference | Pass by pointer |
|---|---|---|---|
| Copies the argument | Yes | No | No (copies the address) |
| Can modify the caller's data | No | Yes | Yes (through `*p`) |
| Can be "nothing" | No | No | Yes (`nullptr`) |
| Typical use | Small types (`int`, `char`) | Output parameters, large objects (`const&`) | Optional objects, linked structures |

## Key takeaways

- Pass large objects by `const&`; know when a copy happens.
- Every recursion needs a base case and a shrinking step; depth costs stack memory.
- log₂(10^6) ≈ 20: halving is extremely fast. Learn the five summation formulas.
- Induction = base case + inductive step; it is the proof tool for loops and recursion.
- Read the constraints first: they tell you the complexity you need and the integer type you need.
