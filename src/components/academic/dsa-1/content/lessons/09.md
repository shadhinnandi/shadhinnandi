# Module 09: Stacks

## Learning objectives

- Implement the Stack ADT with arrays and linked lists, handling overflow and underflow.

- Explain the call stack and recursion.
- Use a monotonic stack (extension).

## Prerequisites

[Module 02](topic:abstract-data-types), [Module 07](topic:arrays), [Module 08](topic:linked-lists).

## Intuition

A stack is last in, first out (LIFO): like a pile of plates, you only touch the top. That matches nested structure: the most recently opened bracket must close first, and the most recent function call returns first.

## Operations

| Operation | Meaning | Cost |
|---|---|---|
| push(x) | put x on top (overflow if a bounded stack is full) | O(1) |
| pop() | remove the top (underflow if empty) | O(1) |
| top()/peek() | read the top | O(1) |
| isEmpty() | size = 0? | O(1) |

Array stack: index `top`; linked stack: insert/delete at the head. Both O(1).

## Balanced parentheses

Push every opening bracket; on a closing bracket, the top must be the matching opener; at the end the stack must be empty.

## Infix, postfix and prefix

| Form | Example |
|---|---|
| Infix | (2 + 3) * 4 |
| Postfix (Reverse Polish) | 2 3 + 4 * |
| Prefix (Polish) | * + 2 3 4 |

- **Postfix evaluation:** push numbers; on an operator, pop b then a, push a op b.
- **Infix → postfix (shunting yard):** output operands; push operators, first popping operators of higher (or equal, for left-associative) precedence; '(' is pushed, ')' pops to the matching '('.
- **Prefix evaluation:** scan right to left like postfix.

## The call stack

Each function call pushes a frame (parameters, locals, return address); returning pops it. Deep recursion overflows the stack, which is why recursive algorithms can be rewritten with an explicit `std::stack`.

## Monotonic stack (extension)

Keeping the stack increasing (popping larger elements) finds the next smaller element for every position in O(n) total, since each element is pushed and popped once.

## Complexity analysis

All stack operations O(1); bracket check and postfix evaluation O(n); shunting yard O(n); space O(n).

## Implementation (C++17)

```cpp
#include <iostream>
#include <sstream>
#include <stack>
#include <string>
using namespace std;

int main() {                               // evaluates a postfix expression, e.g. "2 3 + 4 *"
    string line, token;
    getline(cin, line);
    istringstream in(line);
    stack<long long> st;
    while (in >> token) {
        if (token == "+" || token == "-" || token == "*" || token == "/") {
            if (st.size() < 2) { cout << "INVALID\n"; return 0; }   // underflow
            long long b = st.top(); st.pop();
            long long a = st.top(); st.pop();
            if (token == "/" && b == 0) { cout << "INVALID\n"; return 0; }
            st.push(token == "+" ? a + b : token == "-" ? a - b : token == "*" ? a * b : a / b);
        } else {
            st.push(stoll(token));
        }
    }
    if (st.size() == 1) cout << st.top() << '\n';
    else cout << "INVALID\n";
}
```

## Common mistakes and edge cases

- Calling pop/top on an empty stack (undefined in std::stack).
- Popping operands in the wrong order for - and /.
- Treating '-' associativity like '^' in conversions.
- Forgetting that the stack must be empty after a bracket check.

## Key takeaways

- LIFO matches nesting: brackets, expressions, recursion, undo.
- Postfix needs no parentheses and evaluates with one stack.
- Every recursive algorithm can use an explicit stack.
- Monotonic stacks answer next-greater/smaller queries in O(n).
