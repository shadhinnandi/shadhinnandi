# Module 12: Graphs and Graph Representations

## Learning objectives

- Use graph vocabulary: vertices, edges, paths, cycles, connectivity, components.
- Distinguish directed/undirected and weighted/unweighted graphs; know what a DAG is (extension).
- Build adjacency matrices, adjacency lists and edge lists from input, and compare their costs.

## Prerequisites

[Module 07](topic:arrays), [Module 11](topic:trees).

## Intuition

A graph models relationships: cities and roads, students and friendships, courses and prerequisites. Vertices are the things; edges are the relationships.

## Terminology

| Term | Meaning |
|---|---|
| G = (V, E) | vertices V (|V| = n) and edges E (|E| = m) |
| Directed / undirected | edges have / do not have a direction |
| Weighted | edges carry a number (distance, cost) |
| Path, cycle | sequence of edges; a path returning to its start |
| Connected, component | every pair joined by a path; maximal connected part |
| DAG (extension) | directed graph with no directed cycle (e.g. prerequisite graphs) |
| Sparse / dense | m close to n / m close to n² |

## Representations

| | Adjacency matrix | Adjacency list | Edge list |
|---|---|---|---|
| Space | Θ(n²) | Θ(n + m) | Θ(m) |
| Is (u, v) an edge? | O(1) | O(deg u) | O(m) |
| List neighbours of u | O(n) | O(deg u) | O(m) |
| Best for | dense graphs, small n | sparse graphs (most problems) | sorting edges (Kruskal) |

## Input parsing

The usual format is `n m` followed by m lines `u v` (or `u v w`). For an undirected graph add both directions; check whether vertices are 0- or 1-based.

## Modelling

Road maps (weighted undirected), web links (directed), social networks (undirected), task dependencies (DAG), grids (implicit graph: cell neighbours).

## Complexity analysis

Building an adjacency list: O(n + m) time and space; matrix: O(n²) space regardless of m. With n = 10^5 a matrix needs 10^10 cells, so lists are mandatory for large sparse graphs.

## Implementation (C++17)

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {                                   // input: n m, then m undirected edges u v (1-based)
    int n, m;
    cin >> n >> m;
    vector<vector<int>> adj(n + 1);
    for (int i = 0; i < m; ++i) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);                   // undirected: both directions
    }
    for (int u = 1; u <= n; ++u) {
        cout << u << ':';
        for (int v : adj[u]) cout << ' ' << v;
        cout << '\n';
    }
}
```

**Input:**

```text
4 3
1 2
2 3
1 4
```

**Output:**

```text
1: 2 4
2: 1 3
3: 2
4: 1
```

## Pseudocode

```text
READ-GRAPH(n, m)
    adj ← n empty lists
    repeat m times: read u v; append v to adj[u]; append u to adj[v]   // undirected
```

## Dry run

n = 4, edges (1,2), (2,3), (3,4), (1,3): adj[1] = [2, 3], adj[2] = [1, 3], adj[3] = [2, 4, 1], adj[4] = [3]. The degrees 2, 2, 3, 1 sum to 2m = 8.

## Applications

Road and transit networks, social networks ([DSA-C09](problem:DSA-C09)), the web, course prerequisites ([DSA12-H03](problem:DSA12-H03)), computer networks ([DSA-C08](problem:DSA-C08)), dependency resolution in build systems.

## Comparison with related concepts

| Need | Choose |
|---|---|
| Large sparse graph, traversals | adjacency list |
| Small dense graph, frequent edge tests | adjacency matrix |
| Process edges in sorted order (Kruskal) | edge list |
| Grid or rule-based neighbours | implicit graph (no structure) |

## Common mistakes and edge cases

- Adding only one direction for undirected graphs.
- Using an adjacency matrix for n = 10^5.
- Off-by-one between 0- and 1-based vertex numbers.
- Ignoring self-loops and parallel edges in the input.

## Key takeaways

- Graphs model relationships; n and m decide the representation.
- Adjacency lists: Θ(n + m), the default choice.
- Matrices: O(1) edge test, Θ(n²) space.
- Edge lists suit algorithms that process edges in order.
