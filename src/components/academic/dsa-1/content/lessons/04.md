## Intuition: how does the cost grow?

Timing a program in seconds depends on the machine, the compiler and the input. Instead we count **basic steps** (comparisons, assignments, arithmetic) as a function of the input size n, and ask how that count **grows** as n gets large. Doubling n doubles a linear algorithm's work, quadruples a quadratic one's and squares an exponential one's. For large inputs, the growth rate decides everything; constant factors and small terms only matter for small n.

::viz growth

## Definitions and terminology

| Term | Meaning |
|---|---|
| **Input size n** | The quantity the cost depends on: array length, number of vertices, number of digits |
| **Time complexity T(n)** | The number of basic steps as a function of n |
| **Auxiliary space** | Extra memory used beyond the input itself (the input is not counted) |
| **Worst case** | The maximum cost over all inputs of size n |
| **Best case** | The minimum cost over all inputs of size n |
| **Average case** | The expected cost over a stated distribution of inputs of size n |

### Best, average and worst case: linear search

Searching for x in an array of n elements by scanning from the left:

| Case | When | Comparisons |
|---|---|---|
| Best | x is at position 0 | 1 |
| Worst | x is absent (or last) | n |
| Average | x present, equally likely at each position | (1 + 2 + … + n)/n = (n + 1)/2 |

Worst-case bounds are the most common because they are **guarantees**. Average-case analysis needs an assumption about the inputs, which may not hold (a quick sort is fast on average for random inputs, but an adversary can force its worst case; Module 16C).

## Growth of functions

| Class | Name | n = 10 | n = 10^3 | n = 10^6 | Example |
|---|---|---|---|---|---|
| 1 | constant | 1 | 1 | 1 | array indexing |
| log n | logarithmic | 3.3 | 10 | 20 | binary search |
| n | linear | 10 | 10^3 | 10^6 | one scan |
| n log n | linearithmic | 33 | 10^4 | 2·10^7 | merge sort |
| n² | quadratic | 100 | 10^6 | 10^12 | all pairs |
| n³ | cubic | 10^3 | 10^9 | 10^18 | all triples |
| n^k | polynomial | | | | fixed k nested loops |
| 2^n | exponential | 1024 | ≈ 10^301 | (astronomical) | all subsets |
| n! | factorial | 3.6·10^6 | | | all permutations |

At about 10^8 basic steps per second, an n² algorithm handles n = 10^4 in a second, and n log n handles n = 10^6 to 10^7.

## Formal definitions

Let f and g be functions from positive integers to non-negative reals.

| Notation | Definition | Meaning |
|---|---|---|
| f(n) = **O**(g(n)) | ∃ c > 0, n₀ ≥ 1 such that f(n) ≤ c·g(n) for all n ≥ n₀ | f grows **at most** as fast as g (upper bound) |
| f(n) = **Ω**(g(n)) | ∃ c > 0, n₀ ≥ 1 such that f(n) ≥ c·g(n) for all n ≥ n₀ | f grows **at least** as fast as g (lower bound) |
| f(n) = **Θ**(g(n)) | f = O(g) and f = Ω(g) | f grows **exactly** as fast as g (tight bound) |

The constants c and n₀ are called **witnesses**. "=" here means "belongs to the class", so O(n) = O(n²) is true but O(n²) = O(n) is false.

**Important:** O, Ω and Θ are statements about functions, not about cases. "The worst case of insertion sort is Θ(n²)" and "the best case is Θ(n)" are both precise. "Insertion sort is O(n²)" is true but says nothing about the best case.

### Worked proof 1: 3n² + 5n + 2 = Θ(n²)

*Upper bound.* For n ≥ 1, 5n ≤ 5n² and 2 ≤ 2n², so 3n² + 5n + 2 ≤ 3n² + 5n² + 2n² = 10n². Witnesses: c = 10, n₀ = 1.

*Lower bound.* For n ≥ 1, 3n² + 5n + 2 ≥ 3n². Witnesses: c = 3, n₀ = 1.

Both hold, so 3n² + 5n + 2 = Θ(n²).

### Worked proof 2: n² is not O(n)

Suppose n² ≤ c·n for all n ≥ n₀. Dividing by n gives n ≤ c for all n ≥ n₀, which fails for n = max(n₀, ⌈c⌉ + 1). Contradiction, so no witnesses exist.

### Worked proof 3: log_a n = Θ(log_b n)

log_a n = log_b n / log_b a, and 1/log_b a is a positive constant for fixed a, b > 1. That is why O(log n) needs no base.

## Simplification rules

1. **Constant factors vanish:** 7n³ = Θ(n³).
2. **The dominant term wins:** n³ + 1000n² + 10^6 = Θ(n³), because lower-order terms are eventually smaller than any constant fraction of the highest term.
3. **Sum rule:** O(f) + O(g) = O(max(f, g)): sequential steps cost the larger of the two.
4. **Product rule:** O(f) · O(g) = O(f · g): a loop of f iterations doing O(g) work costs O(f · g).
5. **Hierarchy:** 1 < log n < √n < n < n log n < n² < n³ < 2^n < n! (each is o() of the next).

## Analysing code

### Single and sequential loops

```cpp nocompile
for (int i = 0; i < n; ++i) sum += a[i];      // n iterations: Θ(n)
for (int i = 0; i < n; ++i) cnt += a[i] > 0;  // another Θ(n)
// total Θ(n) + Θ(n) = Θ(n)
```

### Nested loops

```cpp nocompile
for (int i = 0; i < n; ++i)                   // n times
    for (int j = 0; j < n; ++j)               // n times each
        work();                               // Θ(n²) total

for (int i = 0; i < n; ++i)
    for (int j = i + 1; j < n; ++j)           // n-1-i times
        work();                               // Σ (n-1-i) = n(n-1)/2 = Θ(n²)
```

Triangular loops still cost Θ(n²): half of n² is still quadratic.

### Logarithmic loops

```cpp nocompile
for (long long i = 1; i < n; i *= 2) work();  // i = 1, 2, 4, …: ⌈log₂ n⌉ iterations, Θ(log n)
for (long long i = n; i > 0; i /= 2) work();  // halving: Θ(log n)
```

### Harmonic loops

```cpp nocompile
for (int i = 1; i <= n; ++i)
    for (int j = i; j <= n; j += i)           // n/i iterations
        work();
```

Total: n/1 + n/2 + … + n/n = n(1 + 1/2 + … + 1/n) ≈ n ln n = Θ(n log n). (This is the cost of the sieve of Eratosthenes style loops.)

### Mixed expressions

```cpp nocompile
for (int i = 0; i < n; ++i)                   // n times
    for (long long j = 1; j < n; j *= 2)      // log n times
        work();                               // Θ(n log n)
sort(a.begin(), a.end());                     // Θ(n log n)
for (int i = 0; i < n; ++i) work();           // Θ(n)
// total Θ(n log n)
```

### Simple recursion

```cpp nocompile
int sumTo(int n) { return n == 0 ? 0 : n + sumTo(n - 1); }
```

T(n) = T(n − 1) + c with T(0) = c, so T(n) = c(n + 1) = Θ(n). Space: n + 1 stack frames, Θ(n). Recurrences in general (and the Master Theorem for divide and conquer) are the subject of Modules 05 and 06.

## Comparing algorithms under realistic constraints

- **Read the constraints first** (Module 00): they tell you the largest acceptable growth rate.
- **Constants matter for small n.** An algorithm doing 100·n log n steps is slower than 2n² until 2n² > 100 n log n, roughly n > 400. Library sorts switch to insertion sort for tiny subarrays for exactly this reason.
- **Memory is a constraint too.** An O(n²) table for n = 10^5 needs 10^10 cells: impossible regardless of time.
- **Asymptotics hide cache effects.** A linked-list traversal and an array scan are both Θ(n), but the array is often several times faster because it is contiguous (Module 01).

## Complexity of the patterns in this module

| Pattern | Time |
|---|---|
| Single loop to n | Θ(n) |
| Two nested loops to n (square or triangular) | Θ(n²) |
| Loop multiplying or dividing by 2 | Θ(log n) |
| Harmonic double loop | Θ(n log n) |
| n iterations × halving inner loop | Θ(n log n) |
| Recursion reducing n by 1 with O(1) work | Θ(n) |

## Correctness of the analysis

An analysis is a claim, so justify it: count iterations exactly where possible (as sums), then simplify with the rules above. To claim Θ, show both an upper and a lower bound. The program below counts the iterations of four loop patterns, so you can compare the counts with the formulas.

## Implementation: counting steps

```cpp
#include <iostream>
using namespace std;

int main() {
    long long n = 1000;
    long long single = 0, triangular = 0, halving = 0, harmonic = 0;
    for (long long i = 0; i < n; ++i) ++single;
    for (long long i = 0; i < n; ++i)
        for (long long j = i + 1; j < n; ++j) ++triangular;
    for (long long i = n; i > 0; i /= 2) ++halving;
    for (long long i = 1; i <= n; ++i)
        for (long long j = i; j <= n; j += i) ++harmonic;
    cout << "single " << single << '\n';             // n
    cout << "triangular " << triangular << '\n';     // n(n-1)/2
    cout << "halving " << halving << '\n';           // floor(log2 n) + 1
    cout << "harmonic " << harmonic << '\n';         // about n ln n
}
```

**Output:**

```text
single 1000
triangular 499500
halving 10
harmonic 7069
```

n ln n = 1000 · 6.91 ≈ 6908, close to the exact harmonic count 7069 (the difference is the lower-order Θ(n) term).

## Dry run

Halving loop with n = 1000: i takes 1000, 500, 250, 125, 62, 31, 15, 7, 3, 1: ten values, then 0 stops it. ⌊log₂ 1000⌋ + 1 = 9 + 1 = 10. ✓

## Common mistakes and edge cases

- **Counting only the outer loop** of nested loops.
- **Saying O when you mean Θ.** O(n³) is a true but useless bound for a linear scan.
- **Ignoring hidden costs:** passing a vector by value (O(n)), `string` concatenation in a loop, `vector::erase` from the front (O(n)) inside a loop.
- **Calling a loop "log n" because it halves something other than its counter.** Analyse what actually changes each iteration.
- **Mixing up cases and bounds:** "the worst case is O(n²)" is an upper bound on the worst case; to say it is achieved, give Θ or Ω.
- **Forgetting space:** recursion depth is memory.

## Applications

- Choosing an algorithm in a lab, contest or interview starts with "what n can this handle?".
- Big-O vocabulary is how engineers communicate scalability ("this endpoint is linear in the number of users").
- Lower bounds (Ω) tell you when to stop optimising: comparison sorting is Ω(n log n) (Module 16D).

## Comparison with related concepts

| | Big O | Big Ω | Big Θ |
|---|---|---|---|
| Bound | Upper | Lower | Tight (both) |
| Analogy | ≤ | ≥ | = |
| Typical use | Guarantees ("never worse than") | Impossibility results ("no algorithm can beat") | Exact growth of a specific algorithm |

## Key takeaways

- Count steps as a function of n; care about growth, not seconds.
- Worst case gives guarantees; average case needs input assumptions.
- O = upper bound, Ω = lower bound, Θ = both; prove them with witnesses c and n₀.
- Drop constants and lower-order terms; sequential costs add, nested costs multiply.
- Halving gives log n, a harmonic double loop gives n log n, triangular loops are still n².
