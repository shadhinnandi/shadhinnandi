# Module 16C: Quick Sort

## Learning objectives

- Partition with the Lomuto and Hoare schemes.
- Analyse average Θ(n log n) and worst Θ(n²) cases.
- Use randomized pivots to avoid adversarial worst cases.

## Prerequisites

[Module 16B](topic:merge-sort), [Module 04](topic:asymptotic-analysis) and [Module 05](topic:correctness-and-recurrences).

## Intuition

Pick a pivot, rearrange so smaller elements come before it and larger after (partition), then sort the two sides recursively. All the work is in the partition; there is no merge.

## Partition schemes

- **Lomuto:** pivot = a[hi]; i marks the end of the "< pivot" region; scan j, swapping smaller elements forward; finally put the pivot at i. Simple, more swaps.
- **Hoare:** two indices move inwards from both ends and swap out-of-place pairs; fewer swaps, returns a split point (pivot not necessarily in final position).

## Analysis

| Case | When | Recurrence | Time |
|---|---|---|---|
| Best/average | pivot splits roughly in half | T(n) = 2T(n/2) + n | Θ(n log n) |
| Worst | pivot is always the min or max (e.g. sorted input with last-element pivot) | T(n) = T(n − 1) + n | Θ(n²) |

**Randomized pivot:** choosing the pivot uniformly at random makes the *expected* time Θ(n log n) for every input. Recursing on the smaller side first (or looping on the larger) keeps the stack O(log n).

## Properties

In place (O(log n) stack), **not stable**, very fast in practice (cache friendly). `std::sort` uses introsort: quick sort that switches to heap sort if recursion gets too deep.

## Complexity analysis

Average Θ(n log n), worst Θ(n²) (avoided in expectation by random pivots); O(log n) expected stack; not stable.

## Implementation (C++17)

```cpp
#include <iostream>
#include <random>
#include <utility>
#include <vector>
using namespace std;

mt19937 rng(12345);

int lomutoPartition(vector<int>& a, int lo, int hi) {   // a[lo..hi], returns pivot index
    uniform_int_distribution<int> pick(lo, hi);
    swap(a[pick(rng)], a[hi]);                            // random pivot moved to the end
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; ++j)
        if (a[j] < pivot) swap(a[i++], a[j]);             // a[lo..i-1] < pivot
    swap(a[i], a[hi]);
    return i;
}

void quickSort(vector<int>& a, int lo, int hi) {
    while (lo < hi) {
        int p = lomutoPartition(a, lo, hi);
        if (p - lo < hi - p) { quickSort(a, lo, p - 1); lo = p + 1; }   // recurse on the smaller side
        else { quickSort(a, p + 1, hi); hi = p - 1; }
    }
}

int main() {
    vector<int> a = {9, 4, 7, 1, 8, 2, 2, 6};
    quickSort(a, 0, static_cast<int>(a.size()) - 1);
    for (int x : a) cout << x << ' ';
    cout << '\n';
}
```

## Pseudocode

```text
QUICK-SORT(A, lo, hi)
    if lo ≥ hi: return
    p ← PARTITION(A, lo, hi)          // pivot ends at p
    QUICK-SORT(A, lo, p - 1); QUICK-SORT(A, p + 1, hi)
LOMUTO(A, lo, hi)
    pivot ← A[hi]; i ← lo
    for j ← lo to hi - 1: if A[j] < pivot: swap A[i], A[j]; i ← i + 1
    swap A[i], A[hi]; return i
```

## Dry run

Lomuto on [3, 8, 2, 5, 1, 4, 7, 6] with pivot 6: elements < 6 (3, 2, 5, 1, 4) move to the front, giving [3, 2, 5, 1, 4, 6, 7, 8] with the pivot at index 5 ([DSA16C-E02](problem:DSA16C-E02)).

## Correctness

Lomuto's invariant: A[lo..i−1] < pivot ≤ A[i..j−1]. After the loop the pivot is swapped between the two regions, so it is in its final sorted position; the two sides are sorted recursively (induction on size).

## Applications

General-purpose in-memory sorting (`std::sort` is introsort), selection with quickselect ([DSA16C-E05](problem:DSA16C-E05)), median finding ([DSA16C-H05](problem:DSA16C-H05)), partition-based problems such as nuts and bolts ([DSA16C-M05](problem:DSA16C-M05)).

## Comparison with related concepts

| Pivot rule | Sorted input | Duplicates | Guarantee |
|---|---|---|---|
| Last/first element | Θ(n²) | Θ(n²) with Lomuto | none |
| Median of three | good | Θ(n²) | none |
| Random + three-way | expected Θ(n log n) | good | in expectation |
| Introsort | Θ(n log n) | good | worst case |

## Common mistakes and edge cases

- Always picking the first/last element on sorted input (Θ(n²)).
- Infinite recursion when the partition does not shrink the range.
- Claiming quick sort is stable.

## Key takeaways

- Partition is the core; no merge step.
- Average Θ(n log n), worst Θ(n²); randomize the pivot.
- In place and fast, but not stable.
