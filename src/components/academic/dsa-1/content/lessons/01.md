## Intuition: everything is bits at an address

Memory is one long row of numbered **bytes**. Each byte holds 8 **bits**. Every variable, array and object is a pattern of bits stored at some **address**. A data structure is a decision about *where* those patterns go:

- Put the elements **next to each other** (an array): any element is found by arithmetic in one step, but inserting in the middle means shifting everything after it.
- Put each element **anywhere** and connect them with addresses (a linked list): inserting is cheap once you are at the right place, but finding the i-th element means following i links.

Every trade-off in this course starts from that picture.

## Definitions and terminology

| Term | Meaning |
|---|---|
| **Bit** | A single binary digit, 0 or 1 |
| **Byte** | 8 bits; the smallest addressable unit of memory |
| **Word** | The natural unit a CPU handles at once (64 bits on most modern machines) |
| **Address** | The number of a byte in memory; a pointer stores one |
| **Primitive type** | A built-in type such as `char`, `int`, `double`, `bool` |
| **Contiguous storage** | Elements in consecutive addresses (arrays, `vector`) |
| **Non-contiguous storage** | Elements scattered in memory, linked by addresses (linked lists, trees) |
| **Static memory** | Size fixed at compile time (global arrays, `int a[100]`) |
| **Dynamic memory** | Size decided at run time, obtained from the heap region (`new`, `vector`) |
| **Alignment** | The rule that a type of size s usually starts at an address divisible by s |

## Number representation

### Binary and hexadecimal

A binary number's digits are powers of two: 1011₂ = 8 + 0 + 2 + 1 = 11. Hexadecimal groups 4 bits per digit (0–9, A–F), which is why addresses are printed in hex: 0x1F = 0001 1111₂ = 31.

| Decimal | Binary | Hex |
|---|---|---|
| 5 | 0101 | 0x5 |
| 10 | 1010 | 0xA |
| 255 | 1111 1111 | 0xFF |
| 256 | 1 0000 0000 | 0x100 |

To convert decimal to binary, repeatedly divide by 2 and read the remainders from last to first.

### Two's complement

C++ integers store negative numbers in **two's complement**: with k bits, the top bit has weight −2^(k−1).

```text
8-bit two's complement
 0000 0101 =  5
 1111 1011 = -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5
 1000 0000 = -128          (the smallest 8-bit value)
 0111 1111 =  127          (the largest)
```

To negate: invert every bit and add 1. The range of a k-bit signed integer is −2^(k−1) to 2^(k−1) − 1, which is why `int` (32 bits) stops at 2147483647.

### Floating point (IEEE 754)

A `float` stores **sign** (1 bit), **exponent** (8 bits, biased by 127) and **mantissa** (23 bits): value = (−1)^s · 1.m · 2^(e−127). Consequences that matter in DSA:

- Most decimal fractions are not exact (`0.1 + 0.2 != 0.3`).
- Large integers lose precision: a `double` represents every integer exactly only up to 2^53.
- Never compare floating values with `==`; never use them for exact counting.

## Primitive types and storage size

Sizes are **implementation-defined**. The C++ standard only guarantees minimums (`int` at least 16 bits, `long long` at least 64). On the common 64-bit platforms (Linux, macOS, Windows with GCC, Clang or MSVC):

| Type | Typical size | Typical range |
|---|---|---|
| `bool`, `char` | 1 byte | `char`: −128 to 127 (or 0 to 255) |
| `short` | 2 bytes | ±32767 |
| `int` | 4 bytes | ±2.1·10^9 |
| `long long` | 8 bytes | ±9.2·10^18 |
| `float` | 4 bytes | about 7 decimal digits |
| `double` | 8 bytes | about 15–16 decimal digits |
| any pointer | 8 bytes | an address |

Check them on your machine with `sizeof`:

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "char " << sizeof(char) << '\n';
    cout << "int " << sizeof(int) << '\n';
    cout << "long long " << sizeof(long long) << '\n';
    cout << "double " << sizeof(double) << '\n';
    cout << "pointer " << sizeof(int*) << '\n';
}
```

**Output:**

```text
char 1
int 4
long long 8
double 8
pointer 8
```

(This is the output on a 64-bit machine; on a 32-bit system the pointer is 4 bytes.)

## Memory addresses and layout

### Arrays are contiguous

For an array whose first element is at address **base**, with elements of size **s** bytes:

> address(a[i]) = base + i · s

```text
int a[5];  base = 0x1000, s = 4

address  0x1000  0x1004  0x1008  0x100C  0x1010
         +-------+-------+-------+-------+-------+
 a[i]    |  a[0] |  a[1] |  a[2] |  a[3] |  a[4] |
         +-------+-------+-------+-------+-------+
```

This formula is why array access is O(1): no matter how large i is, one multiplication and one addition find the element.

### Two-dimensional arrays

C++ stores `int m[R][C]` in **row-major** order: row 0, then row 1, and so on.

> address(m[i][j]) = base + (i · C + j) · s

Some languages (Fortran, MATLAB) use **column-major** order: address = base + (j · R + i) · s. Traversing a C++ matrix row by row visits memory sequentially, which is much faster than column by column because of the CPU cache.

### Structs, alignment and padding

Each field is placed at an offset that is a multiple of its alignment, and the whole struct's size is rounded up to a multiple of its largest alignment.

```text
struct A { char c; int x; short s; };   // 1 + 3 padding + 4 + 2 + 2 padding = 12 bytes
struct B { int x; short s; char c; };   // 4 + 2 + 1 + 1 padding           =  8 bytes
```

Ordering fields from largest to smallest alignment usually minimises padding. Exact layouts are implementation-defined, but these rules hold on mainstream compilers.

## Static and dynamic memory

| | Static | Dynamic |
|---|---|---|
| Size known | At compile time | At run time |
| Example | `int a[100];` | `vector<int> v(n);`, `new int[n]` |
| Where | Global/static area, or stack if local | Heap region |
| Freed | Automatically | By `delete[]`, or automatically by `vector` (RAII) |

```cpp nocompile
int* raw = new int[n];   // dynamic: you must delete[] it exactly once
delete[] raw;
vector<int> v(n);        // dynamic, but the vector frees its memory itself (preferred)
```

### Stack memory versus heap memory

```text
 high addresses
 +------------------+
 |      stack       |  local variables, function call frames
 |        |         |  grows and shrinks with calls; small (often 1–8 MB)
 |        v         |
 |                  |
 |        ^         |
 |        |         |
 |       heap       |  new / vector storage; large; manual or RAII lifetime
 +------------------+
 |  globals, code   |
 +------------------+
 low addresses
```

- A local `int big[10000000];` inside a function overflows the stack. Use a `vector` (its elements are on the heap) or a global array.
- **The heap memory region has nothing to do with the heap data structure** (Module 14), which is a tree stored in an array. The shared name is a historical accident.

## Contiguous versus non-contiguous storage

```text
Contiguous (array)                 Non-contiguous (linked list)
+----+----+----+----+              +----+------+     +----+------+     +----+------+
| 10 | 20 | 30 | 40 |              | 10 | 0x9A |---->| 20 | 0x3C |---->| 30 | null |
+----+----+----+----+              +----+------+     +----+------+     +----+------+
0x100 0x104 0x108 0x10C            at 0x500          at 0x9A0          at 0x3C0
```

Each linked node carries its data **plus** the address of the next node. That pointer costs 8 extra bytes per node, but it lets the list grow without moving existing elements.

## References, pointers and object relationships

In C++, a **pointer** is a value (an address) that can be null and can be re-pointed; a **reference** is a permanent alias that must be bound to an object.

```cpp nocompile
struct Node {
    int value;
    Node* next;          // relationship: "points to the next node" (may be nullptr)
};
Node c{30, nullptr};
Node b{20, &c};          // b -> c
Node a{10, &b};          // a -> b -> c
int sum = a.value + a.next->value + a.next->next->value;   // 60
```

Linked lists, trees and graphs are all objects related by pointers (or by indices into an array, which is the same idea).

## How representation affects performance

| Operation | Contiguous (array / vector) | Non-contiguous (linked list) |
|---|---|---|
| Access i-th element | **O(1)** (address arithmetic) | O(i) (follow links) |
| Insert/delete at a known position | O(n) (shift elements) | **O(1)** (relink) |
| Insert at the end | O(1) amortised (`vector`) | O(1) with a tail pointer |
| Extra memory per element | none | one or two pointers |
| Cache behaviour | excellent (sequential) | poor (scattered) |

## Complexity analysis

- Address computation `base + i·s` is O(1); so is the 2D formula.
- Converting a number n to binary takes O(log n) steps (one per bit).
- Counting set bits by testing each bit is O(number of bits); `n & (n − 1)` clears the lowest set bit, giving O(number of set bits).
- A dynamic array that doubles its capacity copies at most 2n elements over n insertions: O(1) amortised per insertion (proved in Module 07).

## Implementation: inspecting a representation

The program prints the 8-bit two's complement pattern of a value, the row-major address of a matrix element, and the size of two structs with different field orders.

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Unordered { char c; int x; short s; };
struct Ordered { int x; short s; char c; };

string bits8(int value) {              // two's complement pattern of an 8-bit value
    unsigned pattern = static_cast<unsigned>(value) & 0xFFu;
    string out;
    for (int b = 7; b >= 0; --b) out += ((pattern >> b) & 1u) ? '1' : '0';
    return out;
}

int main() {
    cout << "5 -> " << bits8(5) << '\n';
    cout << "-5 -> " << bits8(-5) << '\n';
    long long base = 0x2000, cols = 4, size = 4, i = 2, j = 1;   // a 3 x 4 int matrix
    cout << "m[2][1] at 0x" << hex << base + (i * cols + j) * size << dec << '\n';
    cout << "sizeof(Unordered) = " << sizeof(Unordered) << '\n';
    cout << "sizeof(Ordered) = " << sizeof(Ordered) << '\n';
}
```

**Output:**

```text
5 -> 00000101
-5 -> 11111011
m[2][1] at 0x2024
sizeof(Unordered) = 12
sizeof(Ordered) = 8
```

## Dry run

`bits8(-5)`: `static_cast<unsigned>(-5)` is 2^32 − 5; masking with 0xFF keeps the low byte 1111 1011. The loop reads bits 7 down to 0, producing "11111011".

Address of `m[2][1]`: (2 · 4 + 1) · 4 = 36 = 0x24, so 0x2000 + 0x24 = 0x2024.

## Common mistakes and edge cases

- **Assuming `int` is always 4 bytes** in a portable program. Use `int32_t` / `int64_t` from `<cstdint>` when the exact size matters.
- **Right-shifting negative numbers** or shifting by ≥ the bit width (undefined or implementation-defined). Do bit manipulation on unsigned types.
- **`1 << 40`**: the literal 1 is an `int`, so this overflows. Write `1LL << 40`.
- **Large local arrays** overflowing the stack.
- **Memory leaks** (`new` without `delete`) and **dangling pointers** (using memory after `delete`). Prefer `vector` and smart pointers.
- **Confusing the heap region with the heap data structure.**

## Applications

- Bit manipulation powers sets of flags, bitsets, hashing and compact data structures.
- Address arithmetic explains why arrays, heaps (stored in arrays) and matrices are fast.
- Understanding padding and contiguity helps you fit large inputs in memory limits.
- Allocators, garbage collectors and databases manage contiguous blocks of memory.

| Managed by | The compiler (automatic) | The program (`new`/`delete`, RAII) | Your code, usually inside an array |
| Typical size | Small (MB) | Large (most of RAM) | As many elements as you store |
| Module | 00, 09 | 01 | 14 |

## Key takeaways

- Memory is numbered bytes; a data structure decides where the bits go.
- Two's complement: the top bit has negative weight; negate by inverting and adding 1.
- Array element address = base + i · size, which is why indexing is O(1).
- Contiguous storage gives fast access; non-contiguous storage gives cheap insertion.
- Stack and heap are memory regions; the heap data structure is unrelated.
