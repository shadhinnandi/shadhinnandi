## DSA00-E01 · Safe Total
**Difficulty:** Easy · **Subtopic:** Integer overflow · **Tags:** overflow, long long, input · **Source:** Original

### Statement
A canteen records the takings of each till in a day. Print the total. Some tills record refunds as negative values.

### Input
The first line contains n. The second line contains n integers a₁ … aₙ.

### Output
Print the sum of all values.

### Constraints
- 1 ≤ n ≤ 2·10^5
- −10^9 ≤ aᵢ ≤ 10^9

### Sample Input
```text
4
1000000000 1000000000 1000000000 -5
```

### Sample Output
```text
2999999995
```

### Sample Explanation
3 · 10^9 − 5 = 2999999995, which is larger than the largest `int` (about 2.1 · 10^9).

### Target
O(n) time, O(1) extra space.

### Hints
1. What is the largest possible total? Compare it with the range of `int`.
2. Accumulate in a `long long`, not an `int`.

### Approach
Read each value and add it to a `long long` accumulator. The total is at most 2·10^5 · 10^9 = 2·10^14 in absolute value, far inside the `long long` range.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long total = 0;          // up to 2e14 in absolute value
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        total += x;
    }
    cout << total << '\n';
}
```

### Explanation
The only real decision is the accumulator type. With `int total`, the third addition in the sample already overflows, which is undefined behaviour in C++. Reading each value into a `long long` also avoids any intermediate `int` arithmetic.

### Edge Cases
- n = 1 (the loop runs once).
- All values negative.
- The maximum total, 2·10^14, still fits in `long long`.

### Tests
#### Single negative value
```text
1
-1000000000
```
```text
-1000000000
```

#### Mixed signs cancel
```text
3
5 -5 0
```
```text
0
```

## DSA00-E02 · Digits and Halvings
**Difficulty:** Easy · **Subtopic:** Logarithms · **Tags:** logarithm, loops, integer arithmetic · **Source:** Original

### Statement
For each query number n, print how many decimal digits it has and how many times it can be halved (integer division by 2) before it becomes 1. The second value is ⌊log₂ n⌋. Use integer arithmetic only: floating-point `log` can be off by one for values near powers of two.

### Input
The first line contains T. Each of the next T lines contains one integer n.

### Output
For each query, print the number of digits and ⌊log₂ n⌋, separated by a space.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ n ≤ 10^18

### Sample Input
```text
3
1
1000
1000000000000000000
```

### Sample Output
```text
1 0
4 9
19 59
```

### Sample Explanation
1000 has 4 digits; 2^9 = 512 ≤ 1000 < 1024 = 2^10, so ⌊log₂ 1000⌋ = 9. For 10^18, 2^59 ≈ 5.76·10^17 ≤ 10^18 < 2^60.

### Target
O(log n) per query, O(1) space.

### Hints
1. Dividing by 10 removes one digit; dividing by 2 is one halving.
2. Count how many divisions it takes until the number reaches 0 (digits) or 1 (halvings).

### Approach
Loop `while (x > 0) { x /= 10; ++digits; }` and `while (x > 1) { x /= 2; ++halvings; }`. Each loop runs at most 19 or 59 times.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n;
        cin >> n;
        int digits = 0;
        for (long long x = n; x > 0; x /= 10) ++digits;
        int halvings = 0;
        for (long long x = n; x > 1; x /= 2) ++halvings;
        cout << digits << ' ' << halvings << '\n';
    }
}
```

### Explanation
Each division removes one decimal digit or one binary digit, so the loop counts are exactly the digit count and ⌊log₂ n⌋. This is the same reasoning used to show that halving loops run O(log n) times.

### Edge Cases
- n = 1: one digit, zero halvings.
- Exact powers of two such as 1024 (⌊log₂⌋ = 10).
- n = 10^18, the largest value, still fits in `long long`.

### Tests
#### Powers of two
```text
2
1024
1023
```
```text
4 10
4 9
```

## DSA00-E03 · Minimum, Maximum and Mean
**Difficulty:** Easy · **Subtopic:** Loops and arrays · **Tags:** arrays, loops, formatting · **Source:** Original

### Statement
A lab records the running times of n test programs in milliseconds. Print the smallest time, the largest time and the mean rounded to exactly two decimal places.

### Input
The first line contains n. The second line contains n integers.

### Output
Print the minimum, the maximum and the mean (two decimal places), separated by spaces.

### Constraints
- 1 ≤ n ≤ 10^5
- −10^9 ≤ each value ≤ 10^9

### Sample Input
```text
3
4 -2 9
```

### Sample Output
```text
-2 9 3.67
```

### Sample Explanation
The sum is 11, so the mean is 11/3 = 3.666…, printed as 3.67.

### Target
O(n) time, O(1) extra space.

### Hints
1. Start the minimum and maximum at the first value, not at 0.
2. The sum can reach 10^14: use `long long`, and divide as floating point only at the end.

### Approach
One pass keeps the running minimum, maximum and `long long` sum. Print the mean with `fixed` and `setprecision(2)`.

### Solution
```cpp
#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long first;
    cin >> first;
    long long lo = first, hi = first, sum = first;
    for (int i = 1; i < n; ++i) {
        long long x;
        cin >> x;
        if (x < lo) lo = x;
        if (x > hi) hi = x;
        sum += x;
    }
    double mean = static_cast<double>(sum) / n;
    cout << lo << ' ' << hi << ' ' << fixed << setprecision(2) << mean << '\n';
}
```

### Explanation
Initialising `lo` and `hi` to the first value works for all-negative inputs, where starting `hi` at 0 would be wrong. The sum stays exact in `long long`; only the final division uses floating point.

### Edge Cases
- n = 1: minimum, maximum and mean are all the same value.
- All values negative.
- A large sum (n = 10^5 values of 10^9).

## DSA00-E04 · Recursive Digit Sum
**Difficulty:** Easy · **Subtopic:** Recursion · **Tags:** recursion, base case, digits · **Source:** Original

### Statement
Write a recursive function that returns the sum of the decimal digits of n. Then print the **digital root** of n: repeatedly replace n by its digit sum until a single digit remains.

### Input
One integer n.

### Output
Print the digit sum of n and the digital root of n, separated by a space.

### Constraints
- 0 ≤ n ≤ 10^18

### Sample Input
```text
98765
```

### Sample Output
```text
35 8
```

### Sample Explanation
9 + 8 + 7 + 6 + 5 = 35, and 3 + 5 = 8.

### Target
O(log n) time; recursion depth is the number of digits (at most 19).

### Hints
1. Base case: a single digit (n < 10) is its own digit sum.
2. Recursive case: the last digit is n % 10, and the rest of the number is n / 10.

### Approach
`digitSum(n) = n < 10 ? n : n % 10 + digitSum(n / 10)`. For the digital root, apply `digitSum` while the value has two or more digits.

### Solution
```cpp
#include <iostream>
using namespace std;

long long digitSum(long long n) {
    if (n < 10) return n;                  // base case: one digit
    return n % 10 + digitSum(n / 10);      // last digit + the rest
}

int main() {
    long long n;
    cin >> n;
    long long s = digitSum(n);
    long long root = s;
    while (root >= 10) root = digitSum(root);
    cout << s << ' ' << root << '\n';
}
```

### Explanation
Each recursive call removes one digit, so the input shrinks and the base case is always reached. The depth equals the number of digits, at most 19, so there is no risk of stack overflow.

### Edge Cases
- n = 0: digit sum 0, root 0.
- A single digit: both outputs equal n.
- n = 10^18: digit sum 1.

#### Zero

```text

```

#### Largest value


## DSA00-E05 · Gauss Range Sums
**Difficulty:** Easy · **Subtopic:** Summations · **Tags:** summation, formula, overflow · **Source:** Original

### Statement
For each query l r, print l + (l+1) + … + r. With r up to 10^9, a loop is too slow for 10^5 queries: use the closed form.

### Input
The first line contains T. Each of the next T lines contains l and r.

### Output
For each query, print the sum.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ l ≤ r ≤ 10^9

### Sample Input
```text
3
1 100
5 5
1 1000000000
```

### Sample Output
```text
5050
5
500000000500000000
```

### Sample Explanation
1 + … + 100 = 100 · 101 / 2 = 5050. The last sum is 10^9 · (10^9 + 1) / 2.

### Target
O(1) per query.

### Hints
1. 1 + 2 + … + k = k(k + 1)/2.
2. l + … + r = S(r) − S(l − 1). Compute k(k + 1) in `long long`.

### Approach
Define S(k) = k(k+1)/2 in `long long` (at most about 5·10^17) and print S(r) − S(l − 1).

### Solution
```cpp
#include <iostream>
using namespace std;

long long prefixSum(long long k) {   // 1 + 2 + ... + k, k >= 0
    return k * (k + 1) / 2;          // k(k+1) <= 1e18 + 1e9: fits in long long
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long l, r;
        cin >> l >> r;
        cout << prefixSum(r) - prefixSum(l - 1) << '\n';
    }
}
```

### Explanation
The formula turns an O(r − l) loop into O(1). Because l and r are read as `long long`, k(k + 1) is computed in 64 bits; one of k and k + 1 is even, so the division is exact.

### Edge Cases
- l = r: a single term.
- l = 1: S(0) = 0.
- r = 10^9: the product 10^9 · (10^9 + 1) needs `long long`.

## DSA00-M01 · Will It Run in Time?
**Difficulty:** Medium · **Subtopic:** Constraint analysis · **Tags:** complexity, constraints, overflow · **Source:** Original

### Statement
A judge allows 10^8 basic operations. For an input size n, decide which of six algorithms finish in time. Let L = ⌊log₂ n⌋ + 1 (the number of bits of n). The algorithms perform exactly L, n, n·L, n², n³ and 2^n operations. Print YES for each one that performs at most 10^8 operations and NO otherwise.

Compute the counts without overflow: n³ and 2^n are astronomically large for big n.

### Input
The first line contains T. Each of the next T lines contains n.

### Output
For each query, print six words (YES or NO) for L, n, n·L, n², n³ and 2^n, in that order.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ n ≤ 10^18

### Sample Input
```text
3
100000
20
1000000000000000000
```

### Sample Output
```text
YES YES YES NO NO NO
YES YES YES YES YES YES
YES NO NO NO NO NO
```

### Sample Explanation
For n = 10^5, L = 17, n·L = 1.7·10^6 fits, but n² = 10^10 does not. For n = 20, 2^20 = 1048576 fits. For n = 10^18 only the L = 60 algorithm fits.

### Target
O(log n) per query, no overflow.

### Hints
1. Never compute n³ directly. Multiply step by step and stop as soon as the product exceeds the limit.
2. A safe test for x · y ≤ LIMIT with positive x, y is x ≤ LIMIT / y.
3. 2^n ≤ 10^8 only for n ≤ 26.

### Approach
Write a helper that multiplies factors one at a time and returns "too big" as soon as the running product would exceed 10^8, using the division test before each multiplication. Apply it to the factor lists [L], [n], [n, L], [n, n], [n, n, n], and 2 repeated n times (stop early).

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

const long long LIMIT = 100000000;  // 1e8 operations

// Does the product of the factors stay within LIMIT? Stops before overflowing.
bool fits(const vector<long long>& factors) {
    long long product = 1;
    for (long long f : factors) {
        if (f > LIMIT / product) return false;   // product * f would exceed LIMIT
        product *= f;
    }
    return true;
}

bool powerOfTwoFits(long long n) {   // 2^n <= LIMIT ?
    long long p = 1;
    for (long long i = 0; i < n; ++i) {
        p *= 2;
        if (p > LIMIT) return false;
    }
    return true;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n;
        cin >> n;
        long long bits = 0;
        for (long long x = n; x > 0; x /= 2) ++bits;   // L = floor(log2 n) + 1
        bool ok[6] = {fits({bits}), fits({n}), fits({n, bits}), fits({n, n}), fits({n, n, n}), powerOfTwoFits(n)};
        for (int i = 0; i < 6; ++i) cout << (ok[i] ? "YES" : "NO") << (i < 5 ? ' ' : '\n');
    }
}
```

### Explanation
`fits` checks `f > LIMIT / product` before each multiplication. Since `product ≤ LIMIT` at every step, `product * f` is only computed when it stays within the limit, so no overflow can occur even for n = 10^18. `powerOfTwoFits` stops after at most 27 doublings. This is exactly the reasoning you do when reading constraints: compare the operation count with about 10^8.

### Edge Cases
- n = 1: every algorithm fits (L = 1, 2^1 = 2).
- Boundaries: n³ fits for n = 464 but not 465; 2^n fits for n = 26 but not 27; n² fits for n = 10^4.
- n = 10^18: products must not overflow.

### Tests
#### Cubic and exponential boundaries
```text

464
465
26
27
```
```text
YES YES YES YES YES NO
YES YES YES YES NO NO
YES YES YES YES YES YES
YES YES YES YES YES NO
```

#### Smallest input
```text
1
1
```

## DSA00-M02 · Tower of Hanoi
**Difficulty:** Medium · **Subtopic:** Recursion · **Tags:** recursion, induction, exponential growth · **Source:** Original

### Statement
n discs of different sizes sit on peg A, largest at the bottom. Move them all to peg C using peg B, one disc at a time, never placing a larger disc on a smaller one. Print the minimum number of moves, then every move.

### Input
One integer n.

### Output
First the number of moves, then one move per line as two peg letters, from and to.

### Constraints
- 1 ≤ n ≤ 15

### Sample Input
```text
2
```

### Sample Output
```text
3
A B
A C
B C
```

### Sample Explanation
Move the small disc to B, the large disc to C, then the small disc onto C.

### Target
O(2^n) moves (optimal), recursion depth n.

### Hints
1. To move n discs from A to C, the largest disc must move from A to C exactly once. Where must the other n − 1 discs be at that moment?
2. Move n − 1 discs A → B, move the largest A → C, then move n − 1 discs B → C.
3. The move count satisfies M(n) = 2M(n − 1) + 1 with M(1) = 1, so M(n) = 2^n − 1.

### Approach
`hanoi(n, from, to, via)`: if n = 0 return; `hanoi(n−1, from, via, to)`; print the move; `hanoi(n−1, via, to, from)`. Print 2^n − 1 first.

### Solution
```cpp
#include <iostream>
using namespace std;

void hanoi(int n, char from, char to, char via) {
    if (n == 0) return;              // nothing to move
    hanoi(n - 1, from, via, to);     // clear the top n-1 discs onto the spare peg
    cout << from << ' ' << to << '\n';
    hanoi(n - 1, via, to, from);     // put them back on top of the largest disc
}

int main() {
    int n;
    cin >> n;
    cout << (1 << n) - 1 << '\n';   // 2^n - 1 moves
    hanoi(n, 'A', 'C', 'B');
}
```

### Explanation
By induction, `hanoi(k, …)` correctly moves k discs for every k: true for k = 0; for k + 1 it moves the top k discs out of the way (inductive hypothesis), moves the largest, then moves the k discs back on top. Any solution must move the largest disc at least once, with all other discs on the spare peg, giving the lower bound M(n) ≥ 2M(n−1) + 1, so 2^n − 1 is optimal.

### Edge Cases
- n = 1: a single move A C.
- n = 15: 32767 moves; the output is large but fine.

### Tests

```text

A C
```

#### Three discs
```text
3
```

```text
A C
A B
C B
A C
B A
```

## DSA00-M03 · Set Algebra
**Difficulty:** Medium · **Subtopic:** Sets · **Tags:** sets, sorting, union, intersection · **Source:** Original

### Statement
Two clubs keep membership lists of student numbers. A list may contain duplicates (a student signed up twice). Print the union, the intersection and the difference A − B, each as a sorted list of distinct numbers.

### Input
n, then n integers (list A); m, then m integers (list B).

### Output
Three lines: the union, the intersection and A − B. Each line starts with the number of elements, followed by the elements in increasing order.

### Constraints
- 1 ≤ n, m ≤ 2·10^5
- −10^9 ≤ each number ≤ 10^9

### Sample Input
```text
5
3 1 4 1 5
4
4 5 9 2
```

### Sample Output
```text
6 1 2 3 4 5 9
2 4 5
2 1 3
```

### Sample Explanation
A = {1, 3, 4, 5}, B = {2, 4, 5, 9}. The union has six elements, the intersection is {4, 5}, and A − B = {1, 3}.

### Target
O((n + m) log(n + m)) time.

### Hints
1. Sort each list and remove duplicates first; then both are sorted sets.
2. With two sorted sets, all three operations are a single merge-like walk with two indices (or `std::set_union` and friends).

### Approach
Sort and deduplicate A and B (`sort` + `unique` + `erase`). Then `set_union`, `set_intersection` and `set_difference` from `<algorithm>` produce sorted results in linear time.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <iterator>
#include <vector>
using namespace std;

vector<long long> readSet() {
    int k;
    cin >> k;
    vector<long long> v(k);
    for (auto& x : v) cin >> x;
    sort(v.begin(), v.end());
    v.erase(unique(v.begin(), v.end()), v.end());   // distinct, sorted
    return v;
}

void print(const vector<long long>& v) {
    cout << v.size();
    for (long long x : v) cout << ' ' << x;
    cout << '\n';
}

int main() {
    vector<long long> a = readSet(), b = readSet();
    vector<long long> uni, inter, diff;
    set_union(a.begin(), a.end(), b.begin(), b.end(), back_inserter(uni));
    set_intersection(a.begin(), a.end(), b.begin(), b.end(), back_inserter(inter));
    set_difference(a.begin(), a.end(), b.begin(), b.end(), back_inserter(diff));
    print(uni);
    print(inter);
    print(diff);
}
```

### Explanation
After sorting and deduplicating, each list is a set in increasing order. The three standard algorithms walk both sequences once, so each operation is O(n + m); sorting dominates. Module 17 builds these operations by hand and compares them with hash sets.

### Edge Cases
- Disjoint sets: the intersection line is just `0`.
- Identical sets: the difference line is `0`.
- Duplicates inside one list must not appear twice.

### Tests


```text
0

```

#### Same list with duplicates

## DSA00-M04 · Sum of Squares Modulo a Prime
**Difficulty:** Medium · **Subtopic:** Summations and modular arithmetic · **Tags:** summation, modular arithmetic, overflow · **Source:** Original

### Statement
For each n, print (1² + 2² + … + n²) mod 1 000 000 007. The value n can be as large as 10^18, so neither a loop nor a direct product n(n+1)(2n+1) in 64 bits will work.

### Input
The first line contains T. Each of the next T lines contains n.

### Output
For each query, print the sum modulo 10^9 + 7.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ n ≤ 10^18

### Sample Input
```text
3
1
10
1000000000000000000
```

### Sample Output
```text
1
385
40425
```

### Sample Explanation
1² + … + 10² = 10 · 11 · 21 / 6 = 385. The last value is n(n+1)(2n+1)/6 reduced modulo 10^9 + 7.

### Target
O(1) per query, no overflow and no floating point.

### Hints
1. Use the formula n(n+1)(2n+1)/6, but the product of three 10^18-sized numbers overflows.
2. Division and the modulus do not mix: (x mod p)/6 is wrong. Divide **before** reducing.
3. Exactly one of n, n+1 is even, and exactly one of n, n+1, 2n+1 is divisible by 3. Divide those factors first.

### Approach
Let a = n, b = n + 1, c = 2n + 1 (all fit in `long long`, c ≤ 2·10^18 + 1). Divide whichever of a, b is even by 2, and whichever of a, b, c is divisible by 3 by 3. Now the product of the three factors is the exact sum. Reduce each factor mod p, multiply two at a time, reducing after each multiplication (each product is below 10^18).

### Solution
```cpp
#include <iostream>
using namespace std;

const long long MOD = 1000000007;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n;
        cin >> n;
        long long a = n, b = n + 1, c = 2 * n + 1;   // c <= 2e18 + 1 fits in long long
        if (a % 2 == 0) a /= 2; else b /= 2;         // one of n, n+1 is even
        if (a % 3 == 0) a /= 3;                       // exactly one of them is divisible by 3
        else if (b % 3 == 0) b /= 3;
        else c /= 3;
        long long result = (a % MOD) * (b % MOD) % MOD;   // < 1e18 before the second %
        result = result * (c % MOD) % MOD;
        cout << result << '\n';
    }
}
```

### Explanation
The divisions are exact, so a · b · c equals the true sum. After reducing each factor below p ≈ 10^9, every product is below 10^18 and fits in `long long`. Note that 2n + 1 is odd, so the factor 2 always comes from n or n + 1; and n, n+1, 2n+1 cover all three residues mod 3.

### Edge Cases
- n = 1, 2, 3 (small values hit each divisibility branch).
- n = 10^18: 2n + 1 is about 2·10^18, still inside `long long`.
- Reducing before dividing gives wrong answers.

### Tests
#### Small values
```text

2
3
4
```

## DSA00-M05 · Overflow Guard
**Difficulty:** Medium · **Subtopic:** Integer overflow · **Tags:** overflow, undefined behaviour, long long · **Source:** Original

### Statement
A calculator works on 64-bit signed integers. For each operation, print the exact result if it fits in `long long`, otherwise print `OVERFLOW`. You must detect overflow **without** performing an overflowing operation, because signed overflow is undefined behaviour in C++.

### Input
The first line contains T. Each line has an operator (`+` or `*`) and two integers a and b.

### Output
For each line, print the result or `OVERFLOW`.

### Constraints
- 1 ≤ T ≤ 10^5
- a and b fit in `long long` (−9223372036854775808 to 9223372036854775807)

### Sample Input
```text
4
+ 9000000000000000000 300000000000000000
* 3037000499 3037000499
* -4611686018427387904 2
+ -5 3
```

### Sample Output
```text
OVERFLOW
9223372030926249001
-9223372036854775808
-2
```

### Sample Explanation
9.3·10^18 exceeds LLONG_MAX ≈ 9.22·10^18. 3037000499² = 9223372030926249001 just fits. −2^62 · 2 = −2^63 = LLONG_MIN, which fits exactly.

### Target
O(1) per operation.

### Hints
1. For addition with b > 0, overflow happens exactly when a > LLONG_MAX − b. That subtraction itself cannot overflow.
2. For multiplication, split by the signs of a and b and compare against LLONG_MAX / b or LLONG_MIN / b.
3. Be careful: LLONG_MIN / −1 itself overflows. Choose comparisons that never divide LLONG_MIN by −1.

### Approach
Addition: if b > 0 check a > MAX − b; if b < 0 check a < MIN − b. Multiplication (the CERT rule): if a > 0 and b > 0, overflow iff a > MAX / b; if a > 0 and b ≤ 0, iff b < MIN / a; if a ≤ 0 and b > 0, iff a < MIN / b; if both ≤ 0, iff a ≠ 0 and b < MAX / a.

### Solution
```cpp
#include <climits>
#include <iostream>
using namespace std;

bool addOverflows(long long a, long long b) {
    if (b > 0) return a > LLONG_MAX - b;
    if (b < 0) return a < LLONG_MIN - b;
    return false;
}

bool mulOverflows(long long a, long long b) {
    if (a > 0) {
        if (b > 0) return a > LLONG_MAX / b;
        return b < LLONG_MIN / a;                 // a > 0, b <= 0
    }
    if (b > 0) return a < LLONG_MIN / b;          // a <= 0, b > 0
    return a != 0 && b < LLONG_MAX / a;           // a < 0, b <= 0: result >= 0
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        char op;
        long long a, b;
        cin >> op >> a >> b;
        bool over = (op == '+') ? addOverflows(a, b) : mulOverflows(a, b);
        if (over) cout << "OVERFLOW\n";
        else cout << (op == '+' ? a + b : a * b) << '\n';
    }
}
```

### Explanation
Every comparison uses only operations that cannot overflow: subtracting a positive b from LLONG_MAX, and dividing by a non-zero value whose quotient is in range (MAX / a with a negative never divides LLONG_MIN). Only after the check passes is the real operation performed. This pattern protects counting problems, prefix sums and products in later modules.

### Edge Cases
- Results exactly equal to LLONG_MAX or LLONG_MIN fit.
- Multiplying by 0 or by ±1.
- LLONG_MIN · (−1) overflows.

## DSA00-H01 · Modular Exponentiation
**Difficulty:** Hard · **Subtopic:** Recursion and fast power · **Tags:** recursion, divide and conquer, modular arithmetic, overflow · **Source:** Original

### Statement
For each query, print a^e mod m. Both e and m can be up to 10^18, so a loop of e multiplications is far too slow, and even multiplying two residues below m overflows 64 bits. Use only standard C++ (no 128-bit integers).

### Input
The first line contains T. Each of the next T lines contains a, e and m.

### Output
For each query, print a^e mod m.

### Constraints
- 1 ≤ T ≤ 1000
- 0 ≤ a ≤ 10^18, 0 ≤ e ≤ 10^18, 1 ≤ m ≤ 10^18

### Sample Input
```text
3
2 10 1000
3 0 7
123456789012345678 987654321098765432 1000000000000000003
```

### Sample Output
```text
24
1
741324316488551443
```

### Sample Explanation
2^10 = 1024, and 1024 mod 1000 = 24. Any a^0 = 1 (and 1 mod 7 = 1).

### Target
O(log e · log m) per query.

### Hints
1. a^e = (a^(e/2))² when e is even, and a · (a^(e/2))² when e is odd: O(log e) multiplications.
2. To multiply x · y mod m without overflow, add x to an accumulator for each set bit of y while doubling x, reducing mod m each time. Since x, y < m ≤ 10^18, x + x < 2·10^18 fits in 64 bits.
3. Remember that a^0 mod 1 is 0.

### Approach
`mulmod(x, y, m)`: binary multiplication (double-and-add) with every intermediate below 2m. `power(a, e, m)`: iterative square-and-multiply on the bits of e, starting from `1 % m`.

### Solution
```cpp
#include <iostream>
using namespace std;
using u64 = unsigned long long;

// x * y mod m without overflow, for x, y < m <= 1e18 (sums stay below 2e18).
u64 mulmod(u64 x, u64 y, u64 m) {
    u64 result = 0;
    while (y > 0) {
        if (y & 1) result = (result + x) % m;
        x = (x + x) % m;
        y >>= 1;
    }
    return result;
}

u64 power(u64 a, u64 e, u64 m) {
    u64 result = 1 % m;      // handles m == 1
    a %= m;
    while (e > 0) {          // square-and-multiply over the bits of e
        if (e & 1) result = mulmod(result, a, m);
        a = mulmod(a, a, m);
        e >>= 1;
    }
    return result;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        u64 a, e, m;
        cin >> a >> e >> m;
        cout << power(a, e, m) << '\n';
    }
}
```

### Explanation
The loop invariant of `power` is: result · a^e (with the current a and e) equals the original a^e mod m. Each iteration halves e, so there are at most 60 iterations, each calling `mulmod` with at most 60 steps. `mulmod` keeps every value below m, so `result + x` and `x + x` are below 2·10^18, which fits in an unsigned 64-bit integer.

### Edge Cases
- m = 1: every answer is 0, including a^0.
- e = 0: answer 1 % m.
- a ≥ m or a = 0.

### Tests
#### Modulus one and zero base
```text
3
5 0 1
0 0 10
0 5 10
```
```text
0
1
0
```

## DSA00-H02 · Geometric Sum Without Division
**Difficulty:** Hard · **Subtopic:** Summations and divide and conquer · **Tags:** divide and conquer, summation, recursion, modular arithmetic · **Source:** Original

### Statement
For each query, print (1 + r + r² + … + r^n) mod m. The closed form (r^(n+1) − 1)/(r − 1) needs a division, which is not possible modulo an arbitrary m (and fails for r = 1). Find a method that uses only addition and multiplication.

### Input
The first line contains T. Each of the next T lines contains r, n and m.

### Output
For each query, print the sum modulo m.

### Constraints
- 1 ≤ T ≤ 1000
- 0 ≤ r ≤ 10^18, 0 ≤ n ≤ 10^18, 1 ≤ m ≤ 10^18

### Sample Input
```text
3
2 3 1000
10 2 7
1 1000000000000000000 1000000007
```

### Sample Output
```text
15
6
50
```

### Sample Explanation
1 + 2 + 4 + 8 = 15. 1 + 10 + 100 = 111 and 111 mod 7 = 6. With r = 1 the sum is n + 1 = 10^18 + 1, which is 50 modulo 10^9 + 7.

### Target
O(log n · log m) per query.

### Hints
1. Let G(k) = 1 + r + … + r^(k−1) (k terms) and P(k) = r^k. Then G(2k) = G(k) + r^k · G(k).
2. And G(2k + 1) = G(2k) + r^(2k). Compute the pair (G, P) recursively on the bits of k.
3. The answer is G(n + 1). Reuse a safe `mulmod` from DSA00-H01.

### Approach
Recursive function `sumPow(k)` returns (G(k), P(k)): G(0) = 0, P(0) = 1 mod m. For k > 0 compute (g, p) = sumPow(k / 2); then (g + p·g, p·p) are the values for 2·(k/2); if k is odd, add one more term: G ← G + P, P ← P · r. Recursion depth is about 60.

### Solution
```cpp
#include <iostream>
#include <utility>
using namespace std;
using u64 = unsigned long long;

u64 mulmod(u64 x, u64 y, u64 m) {     // x, y < m <= 1e18
    u64 result = 0;
    while (y > 0) {
        if (y & 1) result = (result + x) % m;
        x = (x + x) % m;
        y >>= 1;
    }
    return result;
}

u64 r, m;

// Returns { 1 + r + ... + r^(k-1), r^k } modulo m.
pair<u64, u64> sumPow(u64 k) {
    if (k == 0) return {0, 1 % m};
    auto [g, p] = sumPow(k / 2);                  // values for k/2 terms
    u64 g2 = (g + mulmod(p, g, m)) % m;           // G(2h) = G(h) + r^h * G(h)
    u64 p2 = mulmod(p, p, m);                     // r^(2h)
    if (k % 2 == 1) {                             // one more term: r^(2h)
        g2 = (g2 + p2) % m;
        p2 = mulmod(p2, r % m, m);
    }
    return {g2, p2};
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        u64 n;
        cin >> r >> n >> m;
        cout << sumPow(n + 1).first << '\n';      // n + 1 terms
    }
}
```

### Explanation
The recurrence splits k terms into two halves: the second half is the first half multiplied by r^h. Correctness follows by induction on k. Each level halves k, giving about 60 levels, each with a constant number of `mulmod` calls. No division is used, so the method works for every m and for r = 0 or r = 1. n + 1 ≤ 10^18 + 1 fits in an unsigned 64-bit integer.

### Edge Cases
- n = 0: the sum is 1 % m.
- r = 0: the sum is 1 (only r^0).
- r = 1: the sum is n + 1, where the closed form would divide by zero.
- m = 1: every answer is 0.


## DSA00-H03 · Counting Subsets with a Target Sum
**Difficulty:** Hard · **Subtopic:** Complexity-aware search (extension: meet in the middle) · **Tags:** subsets, sorting, binary search, exponential growth · **Source:** Original

### Statement
Given n positive integers and a target S, count the subsets whose elements sum to exactly S (the empty subset has sum 0). With n up to 40, trying all 2^40 ≈ 10^12 subsets is too slow, but 2^20 ≈ 10^6 is fine.

*Meet in the middle is an extension beyond the official syllabus; it is included because it is the classic example of letting the constraint choose the algorithm.*

### Input
n and S, then n integers.

### Output
Print the number of subsets with sum S.

### Constraints
- 1 ≤ n ≤ 40
- 1 ≤ aᵢ ≤ 10^9
- 0 ≤ S ≤ 4·10^10

### Sample Input
```text
4 5
1 2 3 4
```

### Sample Output
```text
2
```

### Sample Explanation
{1, 4} and {2, 3} both sum to 5.

### Target
O(2^(n/2) · n) time, O(2^(n/2)) memory.

### Hints
1. Split the array into two halves of at most 20 elements and list every subset sum of each half (about 10^6 each).
2. A subset of the whole array is a subset of the left half plus a subset of the right half. For each left sum x you need right sums equal to S − x.
3. Sort the right sums and count S − x with binary search (`equal_range`).

### Approach
Enumerate subset sums of each half with bitmasks (or recursion). Sort the right list. For each left sum x ≤ S, add the number of right sums equal to S − x using `equal_range`. Sums fit in `long long`.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

// All 2^k subset sums of v[from, from + k).
vector<long long> subsetSums(const vector<long long>& v, int from, int k) {
    vector<long long> sums(1LL << k, 0);
    for (long long mask = 1; mask < (1LL << k); ++mask) {
        int low = __builtin_ctzll(static_cast<unsigned long long>(mask));   // lowest set bit
        sums[mask] = sums[mask & (mask - 1)] + v[from + low];               // reuse a smaller subset
    }
    return sums;
}

int main() {
    int n;
    long long target;
    cin >> n >> target;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    int half = n / 2;
    vector<long long> left = subsetSums(a, 0, half);
    vector<long long> right = subsetSums(a, half, n - half);
    sort(right.begin(), right.end());
    long long count = 0;
    for (long long x : left) {
        if (x > target) continue;
        auto range = equal_range(right.begin(), right.end(), target - x);
        count += range.second - range.first;
    }
    cout << count << '\n';
}
```

### Explanation
Every subset is uniquely a pair (left subset, right subset), so counting pairs with sums x + y = S counts subsets exactly once. Each half has at most 2^20 subsets; building each sum from a smaller subset makes enumeration O(1) per subset. Sorting costs O(2^20 log 2^20) and each of the 2^20 lookups is O(log 2^20). `__builtin_ctzll` is a GCC/Clang built-in that returns the index of the lowest set bit; a loop over the bits works too.

### Edge Cases
- S = 0: only the empty subset (all values are positive), so the answer is 1.
- n = 1: the halves have 0 and 1 elements.
- Many equal values: counts can be large (up to C(40, 20) ≈ 1.4·10^11, needs `long long`).

### Tests
#### Empty subset only
```text
3 0
5 6 7
```
```text
1
```

#### Identical values
```text
4 2
1 1 1 1
```

## DSA00-H04 · Josephus Survivor
**Difficulty:** Hard · **Subtopic:** Recurrences and induction · **Tags:** recurrence, induction, recursion, iteration · **Source:** Original

### Statement
n people numbered 1 to n stand in a circle. Starting from person 1, count k people around the circle; the k-th person leaves. Counting restarts from the next person. Print the number of the last person remaining. Simulating with a list is O(n·k), too slow for n = 10^6 and k = 10^9.

### Input
Two integers n and k.

### Output
Print the survivor's number.

### Constraints
- 1 ≤ n ≤ 10^6
- 1 ≤ k ≤ 10^9

### Sample Input
```text
7 3
```

### Sample Output
```text
4
```

### Sample Explanation
People leave in the order 3, 6, 2, 7, 5, 1, and person 4 remains.

### Target
O(n) time, O(1) space.

### Hints
1. Number the people 0 to n − 1. After the first person (number (k − 1) mod n) leaves, the remaining n − 1 people form the same problem, shifted.
2. If J(n) is the 0-based survivor among n people, then J(1) = 0 and J(n) = (J(n − 1) + k) mod n.
3. Compute J iteratively from 1 up to n to avoid deep recursion, then add 1.

### Approach
Iterate i from 2 to n with `j = (j + k) % i`, starting from j = 0. Print j + 1. Use `long long` for j + k.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    long long n, k;
    cin >> n >> k;
    long long survivor = 0;               // J(1) = 0 (0-based)
    for (long long i = 2; i <= n; ++i)
        survivor = (survivor + k) % i;    // J(i) = (J(i-1) + k) mod i
    cout << survivor + 1 << '\n';
}
```

### Explanation
After removing person (k − 1) mod i, renumber the remaining i − 1 people so that the person just after the removed one is 0. A person with new number x had old number (x + k) mod i. By induction, if J(i − 1) is the survivor in the new numbering, (J(i − 1) + k) mod i is the survivor in the old numbering. The loop is O(n); a recursive version would need a million stack frames, which is why the iterative form is used.

### Edge Cases
- n = 1: the only person survives.
- k = 1: people leave in order, so n survives.
- k much larger than n: the modulus handles it.

```text

```

#### k equals one
```text
5 1
```
```text

```

#### Large input
```text

```

## DSA00-H05 · Prime Power in a Factorial
**Difficulty:** Hard · **Subtopic:** Logarithmic loops and overflow · **Tags:** logarithm, overflow, number theory, loops · **Source:** Original

### Statement
For each query n and prime p, print the largest e such that p^e divides n!. The classic formula is e = ⌊n/p⌋ + ⌊n/p²⌋ + ⌊n/p³⌋ + …, but computing p², p³, … directly overflows when p is large.

### Input
The first line contains T. Each of the next T lines contains n and a prime p.

### Output
For each query, print the exponent e.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ n ≤ 10^18
- 2 ≤ p ≤ 10^18, p is prime

### Sample Input
```text
3
10 2
100 5
1000000000000000000 1000000007
```

### Sample Output
```text
8
24
999999993
```

### Sample Explanation
10! = 3628800 = 2^8 · 14175, and ⌊10/2⌋ + ⌊10/4⌋ + ⌊10/8⌋ = 5 + 2 + 1 = 8. For 100! and p = 5: 20 + 4 = 24 (this is also the number of trailing zeros of 100!).

### Target
O(log_p n) per query, no overflow.

### Hints
1. ⌊n/p²⌋ = ⌊⌊n/p⌋/p⌋. You never need p² itself.
2. Repeatedly divide n by p and add each quotient until it reaches 0.

### Approach
`e = 0; while (n > 0) { n /= p; e += n; }`. Each step is a division, so nothing can overflow, and the loop runs log_p(n) times.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n, p;
        cin >> n >> p;
        long long exponent = 0;
        while (n > 0) {
            n /= p;              // floor(n / p^i) from floor(n / p^(i-1))
            exponent += n;
        }
        cout << exponent << '\n';
    }
}
```

### Explanation
Each multiple of p up to n contributes one factor p, each multiple of p² one more, and so on (Legendre's formula). Using nested floors ⌊⌊n/p⌋/p⌋ = ⌊n/p²⌋ avoids computing p^i, which would overflow for large p. The total is at most n, so it fits in `long long`.

### Edge Cases
- p > n: the answer is 0.
- p = 2 and n = 10^18: about 60 iterations.
- n = 1: 1! has no prime factors.

### Tests
#### Prime larger than n
```text
2
5 7
1 2
```
```text
0
0
```
