# Heap Sort: Practice Problems

Heap sort itself, its properties (in place, Θ(n log n), not stable), and heap-based greedy problems that use the same machinery.

## DSA16A-E01 · Heap Sort Ascending
**Difficulty:** Easy · **Subtopic:** Heap sort · **Tags:** heap sort, in-place, sorting · **Source:** Original

### Statement
Sort the array in ascending order with your own in-place heap sort.

### Input
n, then n integers.

### Output
The sorted array.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
5
4 10 3 5 1
```

### Sample Output
```text
1 3 4 5 10
```

### Sample Explanation
Build a max-heap, then move the maximum to the end repeatedly.

### Target
O(n log n), O(1) extra.

### Hints
1. Build-heap with sift-down from n/2 − 1 to 0.
2. Swap a[0] with a[end] and sift down within a[0..end−1].

### Approach
Classic heap sort.

### Solution
```cpp
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

void siftDown(vector<long long>& a, size_t i, size_t n) {
    for (;;) {
        size_t b = i, l = 2 * i + 1, r = l + 1;
        if (l < n && a[l] > a[b]) b = l;
        if (r < n && a[r] > a[b]) b = r;
        if (b == i) return;
        swap(a[i], a[b]);
        i = b;
    }
}

int main() {
    size_t n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    for (size_t i = n / 2; i-- > 0;) siftDown(a, i, n);
    for (size_t end = n; end-- > 1;) { swap(a[0], a[end]); siftDown(a, 0, end); }
    for (size_t i = 0; i < n; ++i) cout << a[i] << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
After each extraction the sorted suffix grows by one; the heap shrinks to the prefix.

### Edge Cases
- n = 1; duplicates.

### Tests
#### Duplicates
```text
4
2 1 2 1
```
```text
1 1 2 2
```

### Output
The labels in sorted order.

- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
2 a
1 b
2 c
1 d
```

### Sample Output
```text

```

### Sample Explanation
a came before c in the input, but c comes first in the output: equal keys changed order.

### Target
O(n log n).

### Hints
1. Use the same heap sort, comparing only the key.
2. A stable sort would print b d a c.

### Approach
Heap sort on pairs with a key comparator.

### Solution

```cpp
#include <string>
#include <utility>
#include <vector>
using namespace std;

        if (r < n && a[r].first > a[b].first) b = r;
        if (b == i) return;
        swap(a[i], a[b]);
        i = b;
    }
}

int main() {

    vector<Rec> a(n);
    for (auto& [k, s] : a) cin >> k >> s;
    for (size_t i = n / 2; i-- > 0;) siftDown(a, i, n);

    for (size_t i = 0; i < n; ++i) cout << a[i].second << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation

## DSA16A-M01 · The k Smallest, Sorted
**Difficulty:** Medium · **Subtopic:** Partial heap sort · **Tags:** heap, partial sort · **Source:** Original

### Statement
Print the k smallest values in ascending order without fully sorting.

### Input
n and k, then n integers.

### Output
k values.

### Constraints
- 1 ≤ k ≤ n ≤ 2·10^5

### Sample Input
```text
6 3
7 2 9 4 1 8
```

### Sample Output
```text
1 2 4
```

### Sample Explanation
The three smallest.

### Target
O(n + k log n).

### Hints
1. Build a min-heap of all elements in O(n).
2. Extract k times.

### Approach
`make_heap` with `greater`, then k `pop_heap` calls.

### Solution
```cpp
#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    make_heap(a.begin(), a.end(), greater<long long>());           // O(n)
    for (int i = 0; i < k; ++i) {
        pop_heap(a.begin(), a.end() - i, greater<long long>());     // min moves to the back
        cout << a[n - 1 - i] << (i + 1 < k ? ' ' : '\n');
    }
}
```

### Explanation
Stopping heap sort early costs only k extractions, which is how `std::partial_sort` works.

### Edge Cases
- k = n is a full sort.

### Tests
#### All of them
```text
3 3
3 1 2
```
```text
1 2 3
```

## DSA16A-M02 · Nearly Sorted Array
**Difficulty:** Medium · **Subtopic:** Small heap window · **Tags:** heap, sorting, k-sorted · **Source:** Original

### Statement
Every element is at most k positions away from its sorted position. Sort in O(n log k).

### Input
n and k, then n integers.

### Output
The sorted array.

### Constraints
- 1 ≤ n ≤ 2·10^5, 0 ≤ k < n

### Sample Input
```text
7 3
6 5 3 2 8 10 9
```

### Sample Output
```text
2 3 5 6 8 9 10
```

### Sample Explanation
Each element is within 3 places of its final position.

### Target
O(n log k).

### Hints
1. The smallest remaining element is always among the next k + 1 elements.
2. Keep a min-heap of size k + 1.

### Approach
Sliding min-heap.

### Solution
```cpp
#include <functional>
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<long long> a(n), out;
    for (auto& x : a) cin >> x;
    priority_queue<long long, vector<long long>, greater<long long>> window;
    for (int i = 0; i < n; ++i) {
        window.push(a[i]);
        if (static_cast<int>(window.size()) > k) { out.push_back(window.top()); window.pop(); }
    }
    while (!window.empty()) { out.push_back(window.top()); window.pop(); }
    for (int i = 0; i < n; ++i) cout << out[i] << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
A heap of size k + 1 suffices, so each step is O(log k) instead of O(log n).

### Edge Cases
- k = 0: already sorted.

### Tests
#### Already sorted
```text
3 0
1 2 3
```
```text
1 2 3
```

## DSA16A-H01 · d-ary Heap Sort
**Difficulty:** Hard · **Subtopic:** Generalised heaps · **Tags:** heap sort, d-ary heap, analysis · **Source:** Original

### Statement
Sort with a d-ary max-heap (children of i are d·i + 1 … d·i + d).

### Input
n and d, then n integers.

### Output
The sorted array.

### Constraints
- 1 ≤ n ≤ 2·10^5, 2 ≤ d ≤ 10

### Sample Input
```text
6 3
5 2 8 1 9 3
```

### Sample Output
```text
1 2 3 5 8 9
```

### Sample Explanation
Same result as binary heap sort.

### Target
O(n·d·log_d n).

### Hints
1. Parent of i is (i − 1)/d.
2. Sift-down compares up to d children.

### Approach
Heap sort with generalised indices.

### Solution
```cpp
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

size_t d;

void siftDown(vector<long long>& a, size_t i, size_t n) {
    for (;;) {
        size_t b = i;
        for (size_t c = d * i + 1; c <= d * i + d && c < n; ++c)
            if (a[c] > a[b]) b = c;
        if (b == i) return;
        swap(a[i], a[b]);
        i = b;
    }
}

int main() {
    size_t n;
    cin >> n >> d;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    for (size_t i = n; i-- > 0;) siftDown(a, i, n);     // leaves return immediately
    for (size_t end = n; end-- > 1;) { swap(a[0], a[end]); siftDown(a, 0, end); }
    for (size_t i = 0; i < n; ++i) cout << a[i] << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
A wider heap is shallower (log_d n levels) but each sift-down step compares d children: a trade-off that favours larger d when insertions dominate.

### Edge Cases
- d larger than n.

### Tests
#### Binary
```text
3 2
3 1 2
```
```text
1 2 3
```

## DSA16A-H02 · Halve the Largest
**Difficulty:** Hard · **Subtopic:** Greedy with a max-heap · **Tags:** heap, greedy, simulation · **Source:** Original

### Statement
k times, take the largest value and replace it with ⌈value/2⌉. Print the minimum possible final sum.

### Input
n and k, then n integers.

### Output
The final sum.

### Constraints
- 1 ≤ n ≤ 2·10^5, 1 ≤ k ≤ 2·10^5, 1 ≤ values ≤ 10^9

### Sample Input
```text
3 2
5 4 9
```

### Sample Output
```text
12
```

### Sample Explanation
9 → 5, then 5 (either) → 3: 3 + 4 + 5 = 12.

### Target
O((n + k) log n).

### Hints
1. Halving the largest value removes the most.
2. A max-heap gives the largest in O(log n).

### Approach
k heap operations.

### Solution
```cpp
#include <iostream>
#include <queue>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    priority_queue<long long> pq;
    long long sum = 0;
    for (int i = 0; i < n; ++i) { long long x; cin >> x; pq.push(x); sum += x; }
    while (k--) {
        long long top = pq.top();
        pq.pop();
        long long half = (top + 1) / 2;
        sum -= top - half;
        pq.push(half);
    }
    cout << sum << '\n';
}
```

### Explanation
Greedy is optimal because the reduction ⌊x/2⌋ is non-decreasing in x, so the largest element always gives the biggest reduction.

### Edge Cases
- Values of 1 stay 1.

### Tests
#### Ones
```text
2 5
1 1
```
```text
2
```

```cpp
using namespace std;

int main() {
    string s;
    cin >> s;
    int count[26] = {};
    for (char c : s) ++count[c - 'a'];
    priority_queue<pair<int, int>> pq;                // (count, -letter)
    for (int c = 0; c < 26; ++c) if (count[c]) pq.push({count[c], -c});
    string out;
    pair<int, int> held = {0, 0};
    while (!pq.empty()) {
        auto [cnt, negc] = pq.top();
        pq.pop();
        out += static_cast<char>('a' - negc);
        if (held.first > 0) pq.push(held);
        held = {cnt - 1, negc};
    }
    cout << (out.size() == s.size() ? out : "IMPOSSIBLE") << '\n';
}
```

### Explanation
If the heap empties while a letter is still held back, no different letter is available: impossible.

### Edge Cases
- "aaab": impossible.

## DSA16A-H04 · k-th Smallest in a Sorted Matrix
**Difficulty:** Hard · **Subtopic:** Heap over rows · **Tags:** heap, matrix, k-way merge · **Source:** Original

### Statement
Every row and every column of an n × n matrix is sorted ascending. Print the k-th smallest element.

### Input
n and k, then the matrix.

### Output
The value.

### Constraints
- 1 ≤ n ≤ 1000, 1 ≤ k ≤ n²

### Sample Input
```text
3 8
1 5 9
10 11 13
12 13 15
```

### Sample Output
```text
13
```

### Sample Explanation
Sorted: 1 5 9 10 11 12 13 13 15.

### Target
O(k log n).

### Hints
1. Each row is a sorted list: merge them with a min-heap of row heads.
2. Pop k − 1 times.

### Approach
k-way merge stopped at k.

### Solution
```cpp
#include <functional>
#include <iostream>
#include <queue>
#include <tuple>
#include <vector>
using namespace std;

int main() {
    int n;
    long long k;
    cin >> n >> k;
    vector<vector<long long>> a(n, vector<long long>(n));
    for (auto& row : a) for (auto& x : row) cin >> x;
    using T = tuple<long long, int, int>;
    priority_queue<T, vector<T>, greater<T>> heap;
    for (int i = 0; i < n; ++i) heap.emplace(a[i][0], i, 0);
    for (long long step = 1; step < k; ++step) {
        auto [v, i, j] = heap.top();
        heap.pop();
        if (j + 1 < n) heap.emplace(a[i][j + 1], i, j + 1);
    }
    cout << get<0>(heap.top()) << '\n';
}
```

### Explanation
The heap holds at most n heads, so each step is O(log n).

### Edge Cases
- k = 1; k = n².

### Tests
#### Largest
```text

1 2
3 4
```


## DSA16A-H05 · Bricks and Ladders
**Difficulty:** Hard · **Subtopic:** Min-heap of choices · **Tags:** heap, greedy · **Source:** Original

### Statement
You walk along buildings of given heights. Climbing from a lower to a higher building needs either one ladder or (difference) bricks. With B bricks and L ladders, print the furthest building index (0-based) you can reach.

### Input
n, B, L, then n heights.

### Output
The furthest index.

### Constraints
- 1 ≤ n ≤ 2·10^5, 0 ≤ B ≤ 10^9, 0 ≤ L ≤ n

### Sample Input
```text
7 5 1
4 2 7 6 9 14 12
```

### Sample Output
```text
4
```

### Sample Explanation
Use the ladder for 2→7 and 3 bricks for 6→9; then 9→14 needs 5 bricks but only 2 remain.

### Target
O(n log L).

### Hints
1. Use ladders on the largest climbs.
2. Keep the climbs assigned to ladders in a min-heap; when there are more than L, pay the smallest with bricks.

### Approach
Min-heap of the L largest climbs so far.

### Solution
```cpp
#include <functional>
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    int n;
    long long bricks;
    size_t ladders;
    cin >> n >> bricks >> ladders;
    vector<long long> h(n);
    for (auto& x : h) cin >> x;
    priority_queue<long long, vector<long long>, greater<long long>> laddered;
    int i = 0;
    for (; i + 1 < n; ++i) {
        long long climb = h[i + 1] - h[i];
        if (climb <= 0) continue;
        laddered.push(climb);
        if (laddered.size() > ladders) {
            bricks -= laddered.top();               // cheapest climb paid with bricks
            laddered.pop();
            if (bricks < 0) break;
        }
    }
    cout << i << '\n';
}
```

### Explanation
Exchange argument: swapping a ladder from a smaller climb to a larger one never costs more bricks, so ladders belong to the largest climbs seen.

### Edge Cases
- No climbs at all: the last index.

### Tests
#### Flat
```text
3 0 0
5 5 4
```
```text
2
```
