# Internal Data Representation: Practice Problems

Bits, bytes, addresses and memory layout. Unless a problem says otherwise, assume a typical 64-bit platform: `char` 1 byte, `int` 4 bytes, `long long`, `double` and pointers 8 bytes.

## DSA01-E01 · Binary Representation
**Difficulty:** Easy · **Subtopic:** Binary numbers · **Tags:** binary, bits, conversion · **Source:** Original

### Statement
For each non-negative integer, print its binary representation without leading zeros (0 is printed as `0`).

### Input
The first line contains T. Each of the next T lines contains x.

### Output
For each x, print its binary form.

### Constraints
- 1 ≤ T ≤ 10^4
- 0 ≤ x ≤ 10^18

### Sample Input
```text
3
10
0
1000000000000000000
```

### Sample Output
```text
1010
0
110111100000101101101011001110100111011001000000000000000000
```

### Sample Explanation
10 = 8 + 2 = 1010₂. The last value needs 60 bits.

### Target
O(log x) per query.

### Hints
1. The last binary digit of x is x % 2; then continue with x / 2.
2. The remainders come out in reverse order, so collect them and reverse.

### Approach
Repeatedly append `'0' + x % 2` and halve x, then reverse the string. Treat x = 0 separately.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <string>
using namespace std;

string toBinary(unsigned long long x) {
    if (x == 0) return "0";
    string bits;
    while (x > 0) {
        bits += static_cast<char>('0' + (x % 2));   // lowest bit first
        x /= 2;
    }
    reverse(bits.begin(), bits.end());
    return bits;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        unsigned long long x;
        cin >> x;
        cout << toBinary(x) << '\n';
    }
}
```

### Explanation
Each division by 2 removes the lowest bit, which is the remainder. Reading the remainders from last to first gives the binary digits from the most significant. The loop runs once per bit, at most 60 times.

### Edge Cases
- x = 0 must print `0`, not an empty line.
- Powers of two: a single 1 followed by zeros.

### Tests
#### Small values
```text
3
1
2
255
```
```text
1
10
11111111
```

## DSA01-E02 · Population Count
**Difficulty:** Easy · **Subtopic:** Bit manipulation · **Tags:** bits, popcount, bit tricks · **Source:** Original

### Statement
For each number, print how many of its bits are 1. Implement it yourself using the trick `x & (x − 1)`, which clears the lowest set bit.

### Input
T, then T integers x.

### Output
For each x, the number of set bits.

### Constraints
- 1 ≤ T ≤ 10^5
- 0 ≤ x ≤ 10^18

### Sample Input
```text
4
7
255
0
1000000000000000000
```

### Sample Output
```text
3
8
0
24
```

### Sample Explanation
7 = 111₂ has three 1s; 255 = 11111111₂ has eight.

### Target
O(number of set bits) per query.

### Hints
1. Subtracting 1 turns the lowest 1 into 0 and every 0 below it into 1.
2. So `x & (x − 1)` removes exactly one set bit. Count how many times you can do it.

### Approach
`while (x) { x &= x - 1; ++count; }` (Kernighan's method).

### Solution
```cpp
#include <iostream>
using namespace std;

int popcount(unsigned long long x) {
    int count = 0;
    while (x != 0) {
        x &= x - 1;      // clear the lowest set bit
        ++count;
    }
    return count;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        unsigned long long x;
        cin >> x;
        cout << popcount(x) << '\n';
    }
}
```

### Explanation
For x = 1100₂, x − 1 = 1011₂ and x & (x − 1) = 1000₂: the lowest set bit disappeared and nothing else changed. The loop therefore runs exactly once per set bit. Using an unsigned type keeps all bit operations well defined.

### Edge Cases
- x = 0: zero iterations.
- x = 2^k: one iteration.

### Tests
#### Powers of two and all ones
```text
3
1024
1023
1
```
```text
1
10
1
```

## DSA01-E03 · Memory Budget
**Difficulty:** Easy · **Subtopic:** Storage size · **Tags:** memory, sizeof, overflow · **Source:** Original

### Statement
Before writing code, a student wants to know whether an array fits in the memory limit. For each query, n elements of a given type and a limit L in megabytes (1 MB = 2^20 bytes), print the array size in bytes and `FITS` or `TOO BIG`.

Types and sizes: `char` 1, `int` 4, `int64` 8, `double` 8, `pointer` 8.

### Input
T, then T lines: n, type name, L.

### Output
For each query: the number of bytes, then `FITS` if bytes ≤ L · 2^20, otherwise `TOO BIG`.

### Constraints
- 1 ≤ T ≤ 10^4
- 1 ≤ n ≤ 10^12
- 1 ≤ L ≤ 10^6

### Sample Input
```text
3
1000000 int 4
100000000 int64 256
10 char 1
```

### Sample Output
```text
4000000 FITS
800000000 TOO BIG
10 FITS
```

### Sample Explanation
4 · 10^6 bytes ≤ 4 · 1048576 = 4194304, so it fits. 8 · 10^8 bytes > 256 · 1048576 = 268435456.

### Target
O(1) per query.

### Hints
1. Bytes = n · size; with n up to 10^12 the product needs `long long`.
2. The limit L · 2^20 can be 10^6 · 2^20 ≈ 10^12, also `long long`.

### Approach
Map the type name to its size, compute `n * size` and `L * (1LL << 20)` in `long long` and compare.

### Solution
```cpp
#include <iostream>
#include <string>
using namespace std;

long long sizeOf(const string& type) {
    if (type == "char") return 1;
    if (type == "int") return 4;
    return 8;                       // int64, double, pointer
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n, limitMb;
        string type;
        cin >> n >> type >> limitMb;
        long long bytes = n * sizeOf(type);          // <= 8e12
        long long limit = limitMb * (1LL << 20);     // <= ~1.05e12
        cout << bytes << ' ' << (bytes <= limit ? "FITS" : "TOO BIG") << '\n';
    }
}
```

### Explanation
Estimating memory is as important as estimating time: a 10^8-element `long long` array needs 800 MB. Note `1LL << 20`: writing `1 << 20` is fine here, but `limitMb * (1 << 20)` would multiply two `int`s if `limitMb` were an `int`.

### Edge Cases
- Exactly at the limit counts as fitting.
- n = 10^12 with an 8-byte type: 8·10^12 bytes, still a `long long`.

### Tests
#### Exactly at the limit
```text
2
262144 int 1
262145 int 1
```
```text
1048576 FITS
1048580 TOO BIG
```

## DSA01-E04 · Address of an Element
**Difficulty:** Easy · **Subtopic:** Memory addresses · **Tags:** arrays, addresses, hexadecimal · **Source:** Original

### Statement
An array starts at a base address (given in hexadecimal) and stores elements of s bytes each. For each query print the address of element i in hexadecimal, using lowercase digits and a `0x` prefix.

### Input
T, then T lines: base (hex, without `0x`), s, i.

### Output
For each query, the address of a[i].

### Constraints
- 1 ≤ T ≤ 10^4
- 0 ≤ base ≤ 10^15, 1 ≤ s ≤ 64, 0 ≤ i ≤ 10^9

### Sample Input
```text
3
1000 4 5
7ffe0000 8 3
0 1 255
```

### Sample Output
```text
0x1014
0x7ffe0018
0xff
```

### Sample Explanation
0x1000 + 5 · 4 = 0x1000 + 0x14 = 0x1014.

### Target
O(1) per query.

### Hints
1. address(a[i]) = base + i · s.
2. `cin >> hex` reads hexadecimal; `cout << hex` prints it.

### Approach
Read base with `hex`, s and i with `dec`, compute `base + i * s` in `long long`, print with `hex`.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long base, size, index;
        cin >> hex >> base >> dec >> size >> index;
        long long address = base + index * size;    // contiguous layout
        cout << "0x" << hex << address << dec << '\n';
    }
}
```

### Explanation
Because array elements are contiguous, the address of any element is one multiplication and one addition away from the base. This is the reason indexing an array is O(1). Remember to switch the stream back to decimal after printing.

### Edge Cases
- i = 0 gives the base itself.
- base = 0 (prints `0x0` for i = 0).

### Tests
#### First element
```text
2
abc 8 0
0 4 0
```
```text
0xabc
0x0
```

## DSA01-E05 · Two's Complement Byte
**Difficulty:** Easy · **Subtopic:** Two's complement · **Tags:** two's complement, binary, signed integers · **Source:** Original

### Statement
Work with 8-bit signed integers. A query `E x` encodes x (−128 ≤ x ≤ 127) as its 8-bit two's complement pattern. A query `D bits` decodes an 8-character bit pattern into its signed value.

### Input
T, then T queries.

### Output
For `E`, the 8-bit pattern; for `D`, the decimal value.

### Constraints
- 1 ≤ T ≤ 10^4
- Values and patterns are valid 8-bit signed quantities.

### Sample Input
```text
4
E 5
E -5
D 10000000
D 01111111
```

### Sample Output
```text
00000101
11111011
-128
127
```

### Sample Explanation
−5: invert 00000101 to 11111010, then add 1: 11111011. The pattern 10000000 has only the top bit set, whose weight is −128.

### Target
O(8) per query.

### Hints
1. Encoding: x mod 256 (taking x + 256 for negative x) gives the unsigned byte; print its 8 bits.
2. Decoding: the top bit is worth −128, the others +64, +32, …, +1.

### Approach
Encode: `unsigned u = (x + 256) % 256`, print bits 7..0. Decode: sum the bit weights, with weight −128 for the first character.

### Solution
```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        char kind;
        cin >> kind;
        if (kind == 'E') {
            int x;
            cin >> x;
            int u = (x + 256) % 256;                 // unsigned byte 0..255
            for (int b = 7; b >= 0; --b) cout << ((u >> b) & 1);
            cout << '\n';
        } else {
            string bits;
            cin >> bits;
            int value = (bits[0] == '1') ? -128 : 0; // top bit has negative weight
            for (int b = 1; b < 8; ++b)
                if (bits[b] == '1') value += 1 << (7 - b);
            cout << value << '\n';
        }
    }
}
```

### Explanation
Two's complement assigns weight −2^7 to the top bit, so a negative x is stored as the unsigned value x + 256. Encoding adds 256 and keeps the low 8 bits; decoding reverses the weights. Doing the arithmetic on non-negative values avoids shifting negative numbers.

### Edge Cases
- −128 has no positive counterpart in 8 bits.
- −1 is 11111111; 0 is 00000000.

### Tests
#### Extremes
```text
4
E -128
E -1
D 11111111
D 00000000
```
```text
10000000
11111111
-1
0
```

## DSA01-M01 · Row-Major and Column-Major Addresses
**Difficulty:** Medium · **Subtopic:** 2D memory layout · **Tags:** 2D arrays, row-major, addresses · **Source:** Original

### Statement
A matrix with R rows and C columns of s-byte elements starts at a base address. C and C++ store it in row-major order; Fortran and MATLAB use column-major order. For each query, print the address of element (i, j) (0-based) under both layouts.

### Input
T, then T lines: base (hex), R, C, s, i, j.

### Output
For each query, the row-major address and the column-major address, in `0x` lowercase hexadecimal, separated by a space.

### Constraints
- 1 ≤ T ≤ 10^4
- 0 ≤ base ≤ 10^12; 1 ≤ R, C ≤ 10^5; 1 ≤ s ≤ 16; 0 ≤ i < R; 0 ≤ j < C

### Sample Input
```text
2
2000 3 4 4 2 1
0 2 2 8 1 0
```

### Sample Output
```text
0x2024 0x2014
0x10 0x8
```

### Sample Explanation
Row-major: (2·4 + 1)·4 = 36 = 0x24. Column-major: (1·3 + 2)·4 = 20 = 0x14.

### Target
O(1) per query.

### Hints
1. Row-major: every full row before row i has C elements, so the offset is i·C + j elements.
2. Column-major: every full column before column j has R elements, so the offset is j·R + i.

### Approach
Compute both offsets in `long long` and add base.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long base, rows, cols, size, i, j;
        cin >> hex >> base >> dec >> rows >> cols >> size >> i >> j;
        long long rowMajor = base + (i * cols + j) * size;
        long long colMajor = base + (j * rows + i) * size;
        cout << hex << "0x" << rowMajor << " 0x" << colMajor << dec << '\n';
    }
}
```

### Explanation
The layout determines which elements are neighbours in memory. In row-major order, a[i][j] and a[i][j+1] are adjacent, so traversing row by row reads memory sequentially. The formulas generalise to more dimensions by multiplying out the sizes of the later dimensions.

### Edge Cases
- (0, 0) is the base under both layouts.
- A single row or a single column: both layouts coincide.

### Tests
#### Single row
```text
1
100 1 5 4 0 3
```
```text
0x10c 0x10c
```

## DSA01-M02 · Feature Flags
**Difficulty:** Medium · **Subtopic:** Bit manipulation · **Tags:** bits, masks, unsigned · **Source:** Original

### Statement
An application stores up to 64 on/off feature flags in one 64-bit unsigned integer, initially 0. Process the operations:

- `set i`, `clear i`, `toggle i`: change flag i (0 ≤ i < 64);
- `test i`: print 1 if flag i is on, else 0;
- `count`: print how many flags are on;
- `lowest`: print the index of the lowest flag that is on, or −1 if none.

### Input
q, then q operations.

### Output
One line for each `test`, `count` and `lowest`.

### Constraints
- 1 ≤ q ≤ 10^5
- 0 ≤ i ≤ 63

### Sample Input
```text
8
set 3
set 63
test 3
toggle 3
test 3
count
lowest
clear 63
```

### Sample Output
```text
1
0
1
63
```

### Sample Explanation
After `set 3`, `set 63` and `toggle 3`, only flag 63 is on.

### Target
O(1) per operation (count and lowest at most O(64)).

### Hints
1. The mask for flag i is `1ULL << i`. Use `1ULL`, not `1`: `1 << 63` overflows an `int`.
2. Set with `|=`, clear with `&= ~mask`, toggle with `^=`, test with `&`.
3. The lowest set bit of x is `x & (~x + 1)` (or test bits from 0 upwards).

### Approach
Apply the bit operations on an `unsigned long long`. For `count` use the `x & (x − 1)` loop; for `lowest` scan bits 0..63.

### Solution
```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int q;
    cin >> q;
    unsigned long long flags = 0;
    while (q--) {
        string op;
        cin >> op;
        if (op == "count") {
            int c = 0;
            for (unsigned long long x = flags; x != 0; x &= x - 1) ++c;
            cout << c << '\n';
        } else if (op == "lowest") {
            int low = -1;
            for (int b = 0; b < 64; ++b)
                if (flags >> b & 1ULL) { low = b; break; }
            cout << low << '\n';
        } else {
            int i;
            cin >> i;
            unsigned long long mask = 1ULL << i;     // 64-bit one
            if (op == "set") flags |= mask;
            else if (op == "clear") flags &= ~mask;
            else if (op == "toggle") flags ^= mask;
            else cout << ((flags & mask) ? 1 : 0) << '\n';
        }
    }
}
```

### Explanation
A bitmask packs 64 booleans into 8 bytes, and each operation is a single CPU instruction. Using an unsigned 64-bit type makes every shift from 0 to 63 well defined. The same idea, scaled up, is a bitset (DSA01-M05).

### Edge Cases
- Flag 63, the highest bit, needs a 64-bit unsigned mask.
- `lowest` with no flags set prints −1.
- Clearing a flag that is already off does nothing.

### Tests
#### Empty mask
```text
3
lowest
count
test 0
```
```text
-1
0
0
```

## DSA01-M03 · Byte Order
**Difficulty:** Medium · **Subtopic:** Endianness · **Tags:** bytes, endianness, hexadecimal · **Source:** Original

### Statement
A 32-bit value is stored in 4 bytes. **Big-endian** systems store the most significant byte first; **little-endian** systems (x86, most ARM) store the least significant byte first. For each value, print its bytes in both orders, as two-digit uppercase hexadecimal.

### Input
T, then T unsigned 32-bit integers.

### Output
For each value: `BE` followed by its four bytes in big-endian order, then `LE` followed by the four bytes in little-endian order.

### Constraints
- 1 ≤ T ≤ 10^4
- 0 ≤ x < 2^32

### Sample Input
```text
2
305419896
1
```

### Sample Output
```text
BE 12 34 56 78 LE 78 56 34 12
BE 00 00 00 01 LE 01 00 00 00
```

### Sample Explanation
305419896 = 0x12345678. Its most significant byte is 0x12.

### Target
O(1) per value.

### Hints
1. Byte k (k = 0 for the least significant) is `(x >> (8·k)) & 0xFF`.
2. Big-endian lists bytes 3, 2, 1, 0; little-endian lists 0, 1, 2, 3.

### Approach
Extract the four bytes with shifts and masks, then print them in both orders with `setw(2)`, `setfill('0')`, `uppercase` and `hex`.

### Solution
```cpp
#include <cstdint>
#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        uint32_t x;
        cin >> x;
        unsigned bytes[4];
        for (int k = 0; k < 4; ++k) bytes[k] = (x >> (8 * k)) & 0xFFu;   // k = 0: least significant
        cout << uppercase << hex << setfill('0');
        cout << "BE";
        for (int k = 3; k >= 0; --k) cout << ' ' << setw(2) << bytes[k];
        cout << " LE";
        for (int k = 0; k < 4; ++k) cout << ' ' << setw(2) << bytes[k];
        cout << dec << '\n';
    }
}
```

### Explanation
Shifting and masking extract each byte independently of how this machine stores integers, so the program prints the same result on every platform. Endianness matters when data crosses machines: network protocols use big-endian, and reading a binary file written on another system needs byte swapping.

### Edge Cases
- x = 0: all bytes 00.
- x = 2^32 − 1: all bytes FF.

### Tests
#### All zeros and all ones
```text
2
0
4294967295
```
```text
BE 00 00 00 00 LE 00 00 00 00
BE FF FF FF FF LE FF FF FF FF
```

## DSA01-M04 · Struct Padding
**Difficulty:** Medium · **Subtopic:** Alignment and padding · **Tags:** memory layout, alignment, structs · **Source:** Original

### Statement
A struct has k fields with sizes from {1, 2, 4, 8}. Each field's alignment equals its size: a field must start at an offset divisible by its size. The struct's total size is rounded up to a multiple of its largest field size. Print the struct's size with the fields in the given order, and the size after reordering fields from largest to smallest.

### Input
k, then k field sizes in declaration order.

### Output
The size in the given order and the size in the reordered layout.

### Constraints
- 1 ≤ k ≤ 10^5
- each size is 1, 2, 4 or 8

### Sample Input
```text
3
1 4 2
```

### Sample Output
```text
12 8
```

### Sample Explanation
Given order: char at 0, int at 4 (3 bytes of padding), short at 8, end 10, rounded to 12. Reordered (4, 2, 1): offsets 0, 4, 6, end 7, rounded to 8.

### Target
O(k log k) time.

### Hints
1. Keep a running offset. Before placing a field of size s, round the offset up to the next multiple of s.
2. Round x up to a multiple of s with `(x + s − 1) / s * s`.
3. Sorting fields by decreasing size never needs padding between fields.

### Approach
`layout(fields)`: offset = 0; for each size s: offset = roundUp(offset, s) + s; finally roundUp(offset, max size). Apply to the original order and to the sizes sorted in decreasing order.

### Solution
```cpp
#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>
using namespace std;

long long roundUp(long long x, long long s) { return (x + s - 1) / s * s; }

long long layout(const vector<long long>& sizes) {
    long long offset = 0, largest = 1;
    for (long long s : sizes) {
        offset = roundUp(offset, s) + s;     // align, then place the field
        largest = max(largest, s);
    }
    return roundUp(offset, largest);         // trailing padding for arrays of structs
}

int main() {
    int k;
    cin >> k;
    vector<long long> sizes(k);
    for (auto& s : sizes) cin >> s;
    long long given = layout(sizes);
    sort(sizes.begin(), sizes.end(), greater<long long>());
    cout << given << ' ' << layout(sizes) << '\n';
}
```

### Explanation
Padding exists so that every field sits at an aligned address, which hardware reads efficiently. The trailing padding makes every element of an array of structs aligned too. In decreasing order every offset is already a multiple of the next (smaller, power-of-two) size, so only trailing padding remains.

### Edge Cases
- A single field: no padding.
- All fields the same size: no padding in either order.

### Tests
#### Mixed eights and ones
```text
4
8 1 8 1
```
```text
32 24
```

#### One byte
```text
1
1
```
```text
1 1
```

## DSA01-M05 · Packed Boolean Array
**Difficulty:** Medium · **Subtopic:** Compact representation · **Tags:** bitset, bits, memory · **Source:** Original

### Statement
Store n booleans (all initially false) in an array of 64-bit words, one bit each, which uses 8 times less memory than `bool` per element. Support:

- `set i` and `clear i` (0-based);
- `get i`: print 0 or 1;
- `count l r`: print how many of positions l..r (inclusive) are true.

### Input
n and q, then q operations.

### Output
One line for each `get` and `count`.

### Constraints
- 1 ≤ n ≤ 10^6
- 1 ≤ q ≤ 10^4
- 0 ≤ i, l ≤ r < n

### Sample Input
```text
100 6
set 5
set 70
set 99
get 70
count 0 69
count 5 99
```

### Sample Output
```text
1
1
3
```

### Sample Explanation
Positions 5, 70 and 99 are true. Only position 5 lies in 0..69.

### Target
O(1) for set/clear/get; O((r − l)/64 + 1) for count.

### Hints
1. Bit i lives in word i / 64 at position i % 64.
2. For `count`, handle whole words with a popcount and the partial words at the two ends with masks.

### Approach
Keep `vector<uint64_t> words((n + 63) / 64)`. For `count l r`, loop over the words from l/64 to r/64, mask off bits outside [l, r] in the first and last words, and add each word's popcount.

### Solution
```cpp
#include <cstdint>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int popcount(uint64_t x) {
    int c = 0;
    while (x) { x &= x - 1; ++c; }
    return c;
}

int main() {
    int n, q;
    cin >> n >> q;
    vector<uint64_t> words((n + 63) / 64, 0);
    while (q--) {
        string op;
        cin >> op;
        if (op == "count") {
            int l, r;
            cin >> l >> r;
            int total = 0;
            for (int w = l / 64; w <= r / 64; ++w) {
                uint64_t bits = words[w];
                int lo = (w == l / 64) ? l % 64 : 0;       // first bit inside the range
                int hi = (w == r / 64) ? r % 64 : 63;      // last bit inside the range
                bits >>= lo;                                // drop bits below lo
                int width = hi - lo + 1;
                if (width < 64) bits &= (uint64_t{1} << width) - 1;   // drop bits above hi
                total += popcount(bits);
            }
            cout << total << '\n';
        } else {
            int i;
            cin >> i;
            uint64_t mask = uint64_t{1} << (i % 64);
            if (op == "set") words[i / 64] |= mask;
            else if (op == "clear") words[i / 64] &= ~mask;
            else cout << ((words[i / 64] & mask) ? 1 : 0) << '\n';
        }
    }
}
```

### Explanation
Position i maps to word i/64 and bit i%64, the same address arithmetic as an array, but at bit granularity. For `count`, shifting right by `lo` and keeping `width` bits isolates the part of each word inside the range. The check `width < 64` avoids shifting by 64, which is undefined behaviour. `std::bitset` and `vector<bool>` use this representation internally.

### Edge Cases
- A range inside one word, or exactly one position.
- Ranges that start or end on a word boundary.
- n not a multiple of 64.

### Tests
#### Single word and boundaries
```text
130 6
set 63
set 64
set 128
count 63 64
count 0 63
count 64 129
```
```text
2
1
2
```

## DSA01-H01 · Next Number with the Same Set Bits
**Difficulty:** Hard · **Subtopic:** Bit manipulation · **Tags:** bits, combinatorics, bit tricks · **Source:** Original

### Statement
A scheduler encodes which of 62 machines are busy as a bitmask with exactly k bits set. To try every combination in order, it needs the smallest number greater than x with the same number of set bits as x. For each x, print it.

### Input
T, then T integers x.

### Output
For each x, the next larger integer with the same popcount.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ x ≤ 2^60

### Sample Input
```text
4
6
7
1
12
```

### Sample Output
```text
9
11
2
17
```

### Sample Explanation
6 = 0110₂ → 1001₂ = 9. 7 = 0111₂ → 1011₂ = 11. 12 = 01100₂ → 10001₂ = 17.

### Target
O(1) per query (O(64) also acceptable).

### Hints
1. Find the lowest block of consecutive 1s. Its highest 1 must move one place left.
2. The remaining 1s of that block must move to the lowest positions.
3. With c = x & −x (lowest set bit) and r = x + c, the answer is r | (((r ^ x) >> 2) / c).

### Approach
Gosper's hack: c = lowest set bit; r = x + c moves the lowest block's carry one position up; (r ^ x) contains the bits that changed; shifting right by 2 and dividing by c moves the leftover ones to the bottom; OR them into r. Use unsigned 64-bit arithmetic.

### Solution
```cpp
#include <iostream>
using namespace std;
using u64 = unsigned long long;

u64 nextSamePopcount(u64 x) {
    u64 c = x & (~x + 1);           // lowest set bit (two's complement negation)
    u64 r = x + c;                  // carry the lowest block of ones upward
    u64 ones = ((r ^ x) >> 2) / c;  // the ones that must go back to the bottom
    return r | ones;
}

int main() {
    int t;
    cin >> t;
    while (t--) {
        u64 x;
        cin >> x;
        cout << nextSamePopcount(x) << '\n';
    }
}
```

### Explanation
Write x as …0 1…1 0…0 where the lowest block has m ones. The next larger number with m ones in total must turn the 0 just above the block into 1, and place the other m − 1 ones as low as possible. Adding c performs the first step (the block becomes 0s and the carry lands above it). `r ^ x` marks the m + 1 changed bits; shifting right by 2 and dividing by c (a power of two, so this is a shift) leaves m − 1 ones at the bottom. For x ≤ 2^60, r ≤ 2^61, so nothing overflows.

### Edge Cases
- x a power of two: the single bit moves up one place.
- A block of ones at the top of the input range (x = 2^60 − 1 style values).

### Tests
#### Power of two and a full block
```text

1152921504606846976
15
```
```text
2305843009213693952
23
```

## DSA01-H02 · Decoding IEEE 754 Floats
**Difficulty:** Hard · **Subtopic:** Floating-point representation · **Tags:** floating point, bits, IEEE 754 · **Source:** Original

### Statement
Decode 32-bit IEEE 754 single-precision patterns given as 8 hexadecimal digits. Split each pattern into sign s (1 bit), exponent field E (8 bits) and fraction F (23 bits), then classify it:

- E = 0, F = 0: `zero`; E = 0, F ≠ 0: `subnormal` (exponent −126);
- E = 255, F = 0: `infinity`; E = 255, F ≠ 0: `nan`;
- otherwise `normal` (exponent E − 127).

For `normal` and `subnormal` print the class, the sign (`+` or `-`), the unbiased exponent and the value with 9 significant digits. For `zero` and `infinity` print the class and the sign. For `nan` print `nan`.

### Input
T, then T patterns.

### Output
One line per pattern, as described.

### Constraints
- 1 ≤ T ≤ 10^4
- Each pattern is exactly 8 hexadecimal digits.

### Sample Input
```text
6
3F800000
C0200000
00000001
7F800000
7FC00000
80000000
```

### Sample Output
```text
normal + 0 1
normal - 1 -2.5
subnormal + -126 1.40129846e-45
infinity +
nan
zero -
```

### Sample Explanation
0x3F800000 has E = 127 and F = 0: 1.0 · 2^0 = 1. 0xC0200000 has s = 1, E = 128 and F = 0x200000 (binary .01): −1.25 · 2^1 = −2.5. 0x00000001 is the smallest positive subnormal, 2^−149.

### Target
O(1) per pattern.

### Hints
1. Read the pattern into a `uint32_t` with `cin >> hex`. Extract s = x >> 31, E = (x >> 23) & 0xFF, F = x & 0x7FFFFF.
2. To get the actual float value from the bits, copy them with `memcpy` (not a pointer cast, which breaks aliasing rules).
3. Print values with `setprecision(9)`.

### Approach
Extract the three fields with shifts and masks, classify, and for finite non-zero values `memcpy` the bits into a `float` and print it with 9 significant digits.

### Solution
```cpp
#include <cstdint>
#include <cstring>
#include <iomanip>
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        uint32_t bits;
        cin >> hex >> bits >> dec;
        unsigned sign = bits >> 31;
        unsigned exponent = (bits >> 23) & 0xFFu;
        unsigned fraction = bits & 0x7FFFFFu;
        char s = sign ? '-' : '+';
        float value;
        memcpy(&value, &bits, sizeof value);      // reinterpret the bits safely
        if (exponent == 255) {
            if (fraction == 0) cout << "infinity " << s << '\n';
            else cout << "nan\n";
        } else if (exponent == 0 && fraction == 0) {
            cout << "zero " << s << '\n';
        } else {
            bool normal = exponent != 0;
            int unbiased = normal ? static_cast<int>(exponent) - 127 : -126;
            cout << (normal ? "normal " : "subnormal ") << s << ' ' << unbiased << ' '
                 << setprecision(9) << value << '\n';
        }
    }
}
```

### Explanation
The exponent is stored with a bias of 127 so that it fits in an unsigned field. Normal numbers have an implicit leading 1 (1.F · 2^(E−127)); subnormals drop it (0.F · 2^−126) to fill the gap around zero. `memcpy` is the standard-conforming way to reinterpret bits. Nine significant digits are enough to identify any `float` uniquely.

### Edge Cases
- Positive and negative zero are different bit patterns.
- The smallest normal number 0x00800000 has exponent −126, like subnormals.
- NaN patterns have many fraction values; all print `nan`.


## DSA01-H03 · First-Fit Memory Allocator
**Difficulty:** Hard · **Subtopic:** Dynamic memory · **Tags:** memory allocation, contiguous storage, ordered map · **Source:** Original

### Statement
Simulate a heap-region allocator over memory addresses [0, M). Initially all memory is one free block.

- `alloc k`: find the free block with the **lowest start address** whose size is at least k. Allocate the first k bytes of it and print the start address. If no block is large enough, print `FAIL`.
- `free a`: release the allocated block that starts at a (it is guaranteed to be allocated). Merge it with any free block that is directly before or after it.

After all operations, print the number of free blocks and the size of the largest one.

### Input
M and q, then q operations.

### Output
One line per `alloc` (address or `FAIL`), then a final line: number of free blocks and largest free block size (0 if none).

### Constraints
- 1 ≤ M ≤ 10^12
- 1 ≤ q ≤ 2000
- 1 ≤ k ≤ 10^12

### Sample Input
```text
100 9
alloc 30
alloc 50
alloc 30
free 0
alloc 10
alloc 25
free 30
alloc 25
alloc 70
```

### Sample Output
```text
0
30
FAIL
0
FAIL
10
FAIL
1 65
```

### Sample Explanation
After the first two allocations, only [80, 100) is free. Freeing 0 frees [0, 30); `alloc 10` takes [0, 10). Free blocks are now [10, 30) and [80, 100), each 20 bytes, so `alloc 25` fails. Freeing 30 merges [10, 30), [30, 80) and [80, 100) into [10, 100). `alloc 25` takes [10, 35), leaving [35, 100) of size 65, so `alloc 70` fails.

### Target
O(q · B) where B is the number of free blocks (first-fit scans them in address order); O(log B) per free.

### Hints
1. Keep free blocks in a `map<start, size>` (ordered by address) and allocated blocks in another map.
2. `alloc` scans the free map in order and takes the first block that is large enough; shrink it (or remove it if used up).
3. `free a`: insert [a, a + size) and merge with the predecessor if it ends at a, and with the successor if it starts at a + size.

### Approach
Free blocks: `map<long long, long long>`. Allocation scans from the beginning; when it finds start s with size ≥ k, it erases the entry, re-inserts [s + k, size − k] if non-empty, records the allocation and prints s. Freeing looks up the block's size, inserts it, then merges with neighbours found via `lower_bound`.

### Solution
```cpp
#include <iostream>
#include <iterator>
#include <map>
#include <string>
using namespace std;

int main() {
    long long memory;
    int q;
    cin >> memory >> q;
    map<long long, long long> freeBlocks{{0, memory}};   // start -> size, ordered by address
    map<long long, long long> used;                      // start -> size
    while (q--) {
        string op;
        long long x;
        cin >> op >> x;
        if (op == "alloc") {
            bool done = false;
            for (auto it = freeBlocks.begin(); it != freeBlocks.end(); ++it) {
                if (it->second >= x) {                          // first fit
                    long long start = it->first, size = it->second;
                    freeBlocks.erase(it);
                    if (size > x) freeBlocks[start + x] = size - x;   // the leftover stays free
                    used[start] = x;
                    cout << start << '\n';
                    done = true;
                    break;
                }
            }
            if (!done) cout << "FAIL\n";
        } else {
            long long start = x, size = used[x];
            used.erase(x);
            auto next = freeBlocks.lower_bound(start);
            if (next != freeBlocks.end() && next->first == start + size) {   // merge right
                size += next->second;
                next = freeBlocks.erase(next);
            }
            if (next != freeBlocks.begin()) {
                auto prev = std::prev(next);
                if (prev->first + prev->second == start) {                  // merge left
                    prev->second += size;
                    continue;
                }
            }
            freeBlocks[start] = size;
        }
    }
    long long largest = 0;
    for (const auto& [start, size] : freeBlocks) largest = max(largest, size);
    cout << freeBlocks.size() << ' ' << largest << '\n';
}
```

### Explanation
This is how a dynamic-memory allocator manages the heap region: free memory is a set of contiguous blocks. Keeping them ordered by address makes merging easy, because only the immediate predecessor and successor can touch the freed block. Without merging, memory fragments into many small blocks and large requests fail even when enough total memory is free. A real allocator also keeps blocks indexed by size to avoid the linear first-fit scan.

### Edge Cases
- A request that exactly uses a whole free block removes it.
- Freeing a block between two free blocks merges all three.
- All memory allocated: the final line is `0 0`.



#### Merge on both sides


## DSA01-H04 · Dynamic Array Growth Cost
**Difficulty:** Hard · **Subtopic:** Static vs dynamic arrays · **Tags:** dynamic array, amortised analysis, overflow · **Source:** Original

### Statement
A dynamic array starts with capacity c₀ and size 0. Each push adds one element. When a push finds size = capacity, the array reallocates: the new capacity is max(capacity + 1, ⌊capacity · num / den⌋), and all current elements are copied. For n pushes, print the number of reallocations, the total number of element copies, and the final capacity.

n can be 10^18, so you cannot simulate push by push; simulate reallocation by reallocation.

### Input
n, c₀, num and den.

### Output
Three numbers: reallocations, total copies, final capacity.

### Constraints
- 1 ≤ n ≤ 10^18
- 1 ≤ c₀ ≤ 10^18
- 1 ≤ den < num ≤ 4

### Sample Input
```text
10 1 3 2
```

### Sample Output
```text
6 25 13
```

### Sample Explanation
Capacities grow 1 → 2 → 3 → 4 → 6 → 9 → 13. Each reallocation copies the old capacity: 1 + 2 + 3 + 4 + 6 + 9 = 25.

### Target
O(number of reallocations) = O(log n) for a constant growth factor.

### Hints
1. Elements are pushed until size reaches the capacity; the next push (if any) triggers a reallocation that copies `capacity` elements.
2. So: while capacity < n, add capacity to the copies, grow, count one reallocation.
3. Check the sizes: capacity stays below about 4n ≤ 4·10^18 and capacity · num ≤ 1.6·10^19: use `unsigned long long`.

### Approach
Loop while cap < n: copies += cap; ++reallocs; cap = max(cap + 1, cap · num / den). Use unsigned 64-bit arithmetic: the capacity before growing is below n ≤ 10^18, so cap · num ≤ 4·10^18.

### Solution
```cpp
#include <algorithm>
#include <iostream>
using namespace std;
using u64 = unsigned long long;

int main() {
    u64 n, capacity, num, den;
    cin >> n >> capacity >> num >> den;
    u64 reallocations = 0, copies = 0;
    while (capacity < n) {            // the push after the array is full needs more room
        copies += capacity;           // copy every current element
        ++reallocations;
        capacity = max(capacity + 1, capacity * num / den);   // capacity < n <= 1e18, so no overflow
    }
    cout << reallocations << ' ' << copies << ' ' << capacity << '\n';
}
```

### Explanation
With factor 2, the copies are 1 + 2 + 4 + … < 2n, so the cost per push is O(1) amortised, even though one push can cost O(n). A smaller factor (3/2) wastes less memory but copies more often. The `capacity + 1` rule matters only for tiny capacities, where ⌊capacity · 3/2⌋ would not grow (1 · 3/2 = 1). The total copies stay below the sum of a geometric series, at most about 4n for factor 4/3, which fits in 64 bits.

### Edge Cases
- c₀ ≥ n: no reallocation at all.
- c₀ = 1 with factor 3/2: the +1 rule is needed to make progress.
- n = 10^18: about 60 reallocations for factor 2.

## DSA01-H05 · Total Set Bits from 1 to n
**Difficulty:** Hard · **Subtopic:** Binary patterns · **Tags:** bits, counting, overflow · **Source:** Original

### Statement
Print the total number of 1 bits in the binary representations of all integers from 1 to n. With n up to 10^17, counting number by number is impossible.

### Input
T, then T integers n.

### Output
For each n, the total number of set bits in 1, 2, …, n.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ n ≤ 10^17

### Sample Input
```text
4
1
3
7
100
```

### Sample Output
```text
1
4
12
319
```

### Sample Explanation
1, 10, 11 contain 1 + 1 + 2 = 4 ones. From 1 to 7: 1+1+2+1+2+2+3 = 12.

### Target
O(log n) per query.

### Hints
1. Count bit position b separately. Looking at 0, 1, 2, …, bit b repeats a pattern of 2^b zeros followed by 2^b ones.
2. Among the numbers 0..n (that is n + 1 numbers), there are ⌊(n+1) / 2^(b+1)⌋ full periods, each with 2^b ones.
3. The partial period at the end contributes max(0, (n+1) mod 2^(b+1) − 2^b) ones.

### Approach
For each b with 2^b ≤ n: period = 2^(b+1); add ⌊(n+1)/period⌋ · 2^b + max(0, (n+1) mod period − 2^b). About 57 positions for n ≤ 10^17; the total is below 3·10^18.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n;
        cin >> n;
        long long total = 0;
        for (int b = 0; (1LL << b) <= n; ++b) {
            long long half = 1LL << b, period = half << 1;
            long long count = n + 1;                       // numbers 0..n
            total += (count / period) * half;              // full periods
            long long rest = count % period - half;        // ones in the partial period
            if (rest > 0) total += rest;
        }
        cout << total << '\n';
    }
}
```

### Explanation
Bit b of consecutive integers cycles through 2^b zeros and 2^b ones, so the number of ones up to n is a closed-form count per position. Summing over the about log₂ n positions gives O(log n). For n = 10^17 the total is about 2.8·10^18, inside the `long long` range, which is why the limit is 10^17 rather than 10^18.

### Edge Cases
- n = 1: only bit 0.
- n = 2^k − 1: every position contributes exactly 2^(k−1).
- The largest n stays within `long long`.

#### Largest input
```text
1
100000000000000000
```
```text
2804216299269586964
```
