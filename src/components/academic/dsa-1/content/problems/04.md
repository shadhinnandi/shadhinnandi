# Asymptotic Analysis: Practice Problems

Analysis becomes practical in two ways: counting steps exactly, and replacing a slow algorithm by one whose growth rate fits the constraints. Most problems here state a naive approach that is too slow; your task is to find the right complexity class.

## DSA04-E01 · Loop Iteration Counts
**Difficulty:** Easy · **Subtopic:** Counting loop iterations · **Tags:** loops, summation, logarithm · **Source:** Original

### Statement
For a given n, print exactly how many times the body of each loop runs:

1. `for (i = 0; i < n; ++i)`
2. `for (i = 0; i < n; ++i) for (j = i + 1; j < n; ++j)`
3. `for (i = n; i > 0; i /= 2)`

### Input
T, then T values of n.

### Output
For each n, the three counts.

### Constraints
- 1 ≤ T ≤ 10^5
- 1 ≤ n ≤ 10^9

### Sample Input
```text
3
5
1
1000000000
```

### Sample Output
```text
5 10 3
1 0 1
1000000000 499999999500000000 30
```

### Sample Explanation
For n = 5: the triangular loop runs 4 + 3 + 2 + 1 + 0 = 10 times; the halving loop sees 5, 2, 1.

### Target
O(log n) per query (do not run the loops).

### Hints
1. The triangular loop runs (n − 1) + (n − 2) + … + 0 = n(n − 1)/2 times.
2. The halving loop runs once per binary digit of n: ⌊log₂ n⌋ + 1 times.

### Approach
Print n, n(n − 1)/2 (in `long long`) and the bit length of n.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n;
        cin >> n;
        long long triangular = n * (n - 1) / 2;   // sum of 0 .. n-1
        int halving = 0;
        for (long long x = n; x > 0; x /= 2) ++halving;   // bits of n
        cout << n << ' ' << triangular << ' ' << halving << '\n';
    }
}
```

### Explanation
Exact counting is the first step of every analysis: the triangular loop is n(n−1)/2 = Θ(n²), still quadratic even though it does half the work of a full square loop; the halving loop is Θ(log n). Running the loops for n = 10^9 would take seconds (the triangular one, years).

### Edge Cases
- n = 1: the inner loop never runs.
- Powers of two (n = 8 gives 4 halvings: 8, 4, 2, 1).

### Tests
#### Power of two
```text
1
8
```
```text
8 28 4
```

## DSA04-E02 · Order of Growth
**Difficulty:** Easy · **Subtopic:** Growth rates · **Tags:** growth rates, sorting, big-O · **Source:** Original

### Statement
Sort complexity classes from slowest-growing to fastest-growing. The possible names are: `1`, `logn`, `sqrtn`, `n`, `nlogn`, `n^2`, `n^3`, `2^n`, `n!`.

### Input
k, then k distinct names.

### Output
The names in increasing order of growth, separated by spaces.

### Constraints
- 1 ≤ k ≤ 9

### Sample Input
```text
4
n^2 logn 2^n n
```

### Sample Output
```text
logn n n^2 2^n
```

### Sample Explanation
log n < n < n² < 2^n for large n.

### Target
O(k log k).

### Hints
1. The full order is 1 < log n < √n < n < n log n < n² < n³ < 2^n < n!.
2. Give each name its rank in that order and sort by rank.

### Approach
Store the nine names in growth order; map each input name to its index and sort by index.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    const vector<string> order = {"1", "logn", "sqrtn", "n", "nlogn", "n^2", "n^3", "2^n", "n!"};
    auto rank = [&](const string& s) { return find(order.begin(), order.end(), s) - order.begin(); };
    int k;
    cin >> k;
    vector<string> names(k);
    for (auto& s : names) cin >> s;
    sort(names.begin(), names.end(), [&](const string& a, const string& b) { return rank(a) < rank(b); });
    for (int i = 0; i < k; ++i) cout << names[i] << (i + 1 < k ? ' ' : '\n');
}
```

### Explanation
Each class is little-o of the next: for example n/2^n → 0 and 2^n/n! → 0 as n → ∞. Knowing this hierarchy by heart lets you compare algorithms instantly and recognise when an exponential algorithm is only usable for tiny inputs.

### Edge Cases
- A single name.
- All nine names.

### Tests
#### All classes reversed
```text
9
n! 2^n n^3 n^2 nlogn n sqrtn logn 1
```
```text
1 logn sqrtn n nlogn n^2 n^3 2^n n!
```

## DSA04-E03 · Linear Search Comparisons
**Difficulty:** Easy · **Subtopic:** Best, average and worst case · **Tags:** searching, worst case, best case · **Source:** Original

### Statement
For each query, print how many element comparisons a left-to-right linear search makes before it stops: it stops at the first match, or after comparing with every element if the value is absent.

### Input
n, then n integers; q, then q queries.

### Output
For each query, the number of comparisons.

### Constraints
- 1 ≤ n, q ≤ 10^5
- |values| ≤ 10^9

### Sample Input
```text
5
4 2 7 2 9
3
4
2
5
```

### Sample Output
```text
1
2
5
```

### Sample Explanation
4 is found immediately (best case, 1 comparison); 5 is absent (worst case, n = 5 comparisons).

### Target
O(n + q) using precomputation (O(n·q) brute force is too slow for the limits).

### Hints
1. The answer for a present value is (index of its first occurrence) + 1.
2. Precompute the first occurrence of every value in a hash map, then answer each query in O(1).

### Approach
One pass over the array records the first index of each value. A query answers `first + 1` if present, otherwise n.

### Solution
```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    int n;
    cin >> n;
    unordered_map<long long, int> first;
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        first.emplace(x, i);                 // keeps the first index only
    }
    int q;
    cin >> q;
    while (q--) {
        long long x;
        cin >> x;
        auto it = first.find(x);
        cout << (it == first.end() ? n : it->second + 1) << '\n';
    }
}
```

### Explanation
This makes the case analysis concrete: the best case is 1 comparison, the worst case n, and the average over present values depends on where they are. The precomputation itself is an asymptotic improvement: O(n·q) = 10^10 becomes O(n + q). `emplace` does nothing when the key exists, so the first index is kept.

### Edge Cases
- Duplicate values: the first occurrence counts.
- Every query absent: always n.

### Tests
#### Last position and absent
```text
3
1 2 3
2
3
0
```
```text
3
3
```

## DSA04-E04 · Duplicate Detection
**Difficulty:** Easy · **Subtopic:** Improving a quadratic algorithm · **Tags:** sorting, complexity, duplicates · **Source:** Original

### Statement
Print `YES` if some value appears at least twice in the list, otherwise `NO`. Comparing every pair is O(n²) ≈ 2·10^10 for the largest input, far too slow.

### Input
n, then n integers.

### Output
`YES` or `NO`.

### Constraints
- 1 ≤ n ≤ 2·10^5
- |values| ≤ 10^9

### Sample Input
```text
5
3 8 1 8 5
```

### Sample Output
```text
YES
```

### Sample Explanation
8 appears twice.

### Target
O(n log n) time.

### Hints
1. After sorting, equal values are next to each other.
2. One scan comparing neighbours then decides.

### Approach
Sort, then check whether any `a[i] == a[i+1]`.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    sort(a.begin(), a.end());                         // O(n log n)
    bool dup = adjacent_find(a.begin(), a.end()) != a.end();   // O(n): equal neighbours
    cout << (dup ? "YES" : "NO") << '\n';
}
```

### Explanation
Θ(n log n) + Θ(n) = Θ(n log n), about 3.5·10^6 steps for n = 2·10^5, compared with 2·10^10 for all pairs. A hash set gives O(n) expected time; sorting gives a guaranteed bound and needs no hashing.

### Edge Cases
- n = 1: no duplicates.
- All values equal.

### Tests
#### One element
```text
1
4
```
```text
NO
```

#### All distinct
```text
4
4 3 2 1
```
```text
NO
```

## DSA04-E05 · Harmonic Loop Count
**Difficulty:** Easy · **Subtopic:** Harmonic loops · **Tags:** loops, harmonic series, counting · **Source:** Original

### Statement
Print exactly how many times the inner body of this loop runs:

```text
for i = 1 to n:
    for j = i to n step i:
        body
```

### Input
One integer n.

### Output
The number of body executions.

### Constraints
- 1 ≤ n ≤ 10^6

### Sample Input
```text
10
```

### Sample Output
```text
27
```

### Sample Explanation
The inner loop runs ⌊10/i⌋ times: 10 + 5 + 3 + 2 + 2 + 1 + 1 + 1 + 1 + 1 = 27.

### Target
O(n) time.

### Hints
1. For a fixed i, j takes the values i, 2i, 3i, …, up to n: that is ⌊n/i⌋ values.
2. Sum ⌊n/i⌋ for i = 1 … n in a single loop.

### Approach
`total += n / i` for i from 1 to n.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    long long n;
    cin >> n;
    long long total = 0;
    for (long long i = 1; i <= n; ++i) total += n / i;   // inner loop runs floor(n/i) times
    cout << total << '\n';
}
```

### Explanation
The sum is n(1/1 + 1/2 + … + 1/n) minus rounding, about n ln n. So this double loop is Θ(n log n), not Θ(n²), even though it looks like two nested loops. For n = 10^6 the count is about 1.4·10^7. DSA04-H01 computes the same sum for n up to 10^12.

### Edge Cases
- n = 1: one execution.


## DSA04-M01 · Smallest Witness n₀
**Difficulty:** Medium · **Subtopic:** Formal Big-O definitions · **Tags:** big-O, proofs, binary search · **Source:** Original

### Statement
For f(n) = a₂n² + a₁n + a₀ and a constant c, the claim f(n) = O(n²) with witness c needs some n₀ such that f(n) ≤ c·n² for every n ≥ n₀. For each query, print the smallest such n₀ ≥ 1, or `NEVER` if no n₀ works for this c.

### Input
T, then T lines with a₂, a₁, a₀ and c.

### Output
For each query, the smallest n₀ or `NEVER`.

### Constraints
- 1 ≤ T ≤ 10^4
- 0 ≤ a₂, a₁, a₀ ≤ 10^6; 1 ≤ c ≤ 10^6

### Sample Input
```text
3
3 5 2 4
3 5 2 10
3 5 2 3
```

### Sample Output
```text
6
1
NEVER
```

### Sample Explanation
With c = 4 we need n² ≥ 5n + 2, first true at n = 6 (36 ≥ 32; at n = 5, 25 < 27). With c = 10, 10n² ≥ 3n² + 5n + 2 already holds at n = 1. With c = 3 = a₂, the extra 5n + 2 always exceeds 0.

### Target
O(log(a₁ + a₀)) per query.

### Hints
1. Let g(n) = (c − a₂)n² − a₁n − a₀. The claim holds at n exactly when g(n) ≥ 0.
2. If c < a₂, or c = a₂ with a₁ + a₀ > 0, g(n) < 0 for every n ≥ 1: `NEVER`. If c = a₂ and a₁ = a₀ = 0, the answer is 1.
3. If c > a₂, g is negative up to some point and non-negative afterwards, and g(n) ≥ 0 for n = a₁ + a₀ + 1. Binary search the first n where g(n) ≥ 0.

### Approach
Handle c ≤ a₂ directly. Otherwise binary search n in [1, a₁ + a₀ + 1] for the first n with (c − a₂)n² ≥ a₁n + a₀. Values stay below 10^6 · (2·10^6)² = 4·10^18, inside `long long`.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long a2, a1, a0, c;
        cin >> a2 >> a1 >> a0 >> c;
        if (c < a2 || (c == a2 && a1 + a0 > 0)) { cout << "NEVER\n"; continue; }
        if (c == a2) { cout << 1 << '\n'; continue; }       // f(n) = c n^2 exactly
        long long d = c - a2;
        auto holds = [&](long long n) { return d * n * n >= a1 * n + a0; };
        long long lo = 1, hi = a1 + a0 + 1;                  // holds(hi) is guaranteed
        while (lo < hi) {
            long long mid = lo + (hi - lo) / 2;
            if (holds(mid)) hi = mid;
            else lo = mid + 1;
        }
        cout << lo << '\n';
    }
}
```

### Explanation
g(0) = −a₀ ≤ 0 and g is a convex parabola when d > 0, so the set where g < 0 is an interval starting at or before 0: once g(n) ≥ 0 for some n ≥ 1, it stays non-negative. That monotonicity makes binary search valid. For n ≥ a₁ + a₀ + 1, d·n² ≥ n² ≥ (a₁ + a₀ + 1)·n > a₁n + a₀, so the upper end always satisfies the claim. This mirrors a hand proof: pick c, then find an n₀ that makes the inequality true.

### Edge Cases
- a₁ = a₀ = 0 and c ≥ a₂: n₀ = 1.
- c exactly a₂: only works when the lower terms are zero.
- Large coefficients (products near 4·10^18).

### Tests
#### Pure quadratic and large values
```text
2
7 0 0 7
1 1000000 1000000 2
```
```text
1
1000001
```

## DSA04-M02 · Pairs with a Given Sum
**Difficulty:** Medium · **Subtopic:** From O(n²) to O(n) · **Tags:** hashing, counting, complexity · **Source:** Original

### Statement
Count the pairs of positions i < j with aᵢ + aⱼ = K. The brute-force O(n²) check is too slow for n = 2·10^5.

### Input
n and K, then n integers.

### Output
The number of pairs.

### Constraints
- 1 ≤ n ≤ 2·10^5
- |aᵢ|, |K| ≤ 10^9

### Sample Input
```text
5 6
1 5 3 3 2
```

### Sample Output
```text
2
```

### Sample Explanation
1 + 5 = 6 and 3 + 3 = 6.

### Target
O(n) expected time (or O(n log n) with an ordered map).

### Hints
1. Process the array left to right. For position j, how many earlier positions i have aᵢ = K − aⱼ?
2. Keep a count of every value seen so far.
3. The answer can reach about 2·10^10: use `long long`.

### Approach
`count` map of values seen. For each aⱼ: answer += count[K − aⱼ]; then count[aⱼ]++.

### Solution
```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    int n;
    long long k;
    cin >> n >> k;
    unordered_map<long long, long long> seen;    // value -> occurrences so far
    seen.reserve(2 * n);
    long long pairs = 0;
    for (int j = 0; j < n; ++j) {
        long long x;
        cin >> x;
        auto it = seen.find(k - x);
        if (it != seen.end()) pairs += it->second;   // partners to the left of j
        ++seen[x];
    }
    cout << pairs << '\n';
}
```

### Explanation
Each pair is counted exactly once, at its right element j, because only earlier elements are in the map at that time. Each step is O(1) expected, so the algorithm is Θ(n) instead of Θ(n²). The values K − aⱼ reach 2·10^9 in absolute value, so the keys are `long long`.

### Edge Cases
- K = 2x with several copies of x: C(m, 2) pairs.
- No pairs at all.

### Tests
#### Four equal values
```text
4 4
2 2 2 2
```
```text
6
```

## DSA04-M03 · Best Window Sum
**Difficulty:** Medium · **Subtopic:** Sliding window · **Tags:** sliding window, arrays, complexity · **Source:** Original

### Statement
A sensor reports n readings. Find the maximum sum of any k consecutive readings. Recomputing each window from scratch costs O(n·k), up to 10^10 operations.

### Input
n and k, then n integers.

### Output
The maximum window sum.

### Constraints
- 1 ≤ k ≤ n ≤ 2·10^5
- |values| ≤ 10^9

### Sample Input
```text
6 3
1 -2 3 4 -1 2
```

### Sample Output
```text
6
```

### Sample Explanation
The window sums are 2, 5, 6 and 5.

### Target
O(n) time, O(1) extra space.

### Hints
1. Neighbouring windows share k − 1 elements.
2. Slide: add the element entering the window and subtract the one leaving.

### Approach
Sum the first k elements, then for i = k … n − 1 update `sum += a[i] − a[i − k]` and track the maximum.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    long long sum = 0;
    for (int i = 0; i < k; ++i) sum += a[i];
    long long best = sum;
    for (int i = k; i < n; ++i) {
        sum += a[i] - a[i - k];        // slide the window one step right
        best = max(best, sum);
    }
    cout << best << '\n';
}
```

### Explanation
Each step does O(1) work instead of O(k), so the total drops from Θ(n·k) to Θ(n). The sliding window is one of the most common optimisations: it reuses the previous window's result instead of recomputing it.

### Edge Cases
- k = n: one window.
- k = 1: the maximum element.
- All negative values.

### Tests
#### Whole array
```text
3 3
-1 -2 -3
```
```text
-6
```

## DSA04-M04 · Guess the Complexity
**Difficulty:** Medium · **Subtopic:** Empirical growth analysis · **Tags:** growth rates, doubling experiment, analysis · **Source:** Original

### Statement
A student measured the number of basic steps of a mystery algorithm for n = 1000, 2000, 4000 and 8000. Classify the algorithm as `O(n)`, `O(n log n)`, `O(n^2)` or `O(n^3)` using a doubling experiment: when n doubles, these classes multiply the cost by about 2, a little more than 2, 4 and 8 respectively.

Use this rule: let g = (c₈₀₀₀ / c₁₀₀₀)^(1/3), the average growth factor per doubling. Answer `O(n)` if g < 2.09, `O(n log n)` if g < 2.83, `O(n^2)` if g < 5.66, and `O(n^3)` otherwise.

### Input
T, then T lines of four step counts.

### Output
One classification per line.

### Constraints
- 1 ≤ T ≤ 10^4
- 1 ≤ counts ≤ 10^15, increasing

### Sample Input
```text
4
3000 6000 12000 24000
49829 109658 239316 518631
500000 2000000 8000000 32000000
1000000000 8000000000 64000000000 512000000000
```

### Sample Output
```text
O(n)
O(n log n)
O(n^2)
O(n^3)
```

### Sample Explanation
The second line is about 5·n·log₂ n: its growth factor is about 2.18 per doubling. The third is n²/2 (factor 4).

### Target
O(1) per line.

### Hints
1. If T(n) = c·n^k, then T(2n)/T(n) = 2^k: the exponent shows in the ratio.
2. For n log n the ratio is 2·log(2n)/log(n), slightly above 2 and shrinking slowly.
3. The thresholds are geometric means of neighbouring ratios (√(2·2.18) ≈ 2.09, √8, √32).

### Approach
Compute g with `cbrt` (or `pow`) in floating point and compare with the thresholds.

### Solution
```cpp
#include <cmath>
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        double c[4];
        for (double& x : c) cin >> x;
        double g = cbrt(c[3] / c[0]);            // average factor per doubling of n
        if (g < 2.09) cout << "O(n)\n";
        else if (g < 2.83) cout << "O(n log n)\n";
        else if (g < 5.66) cout << "O(n^2)\n";
        else cout << "O(n^3)\n";
    }
}
```

### Explanation
A doubling experiment estimates the growth rate from measurements: ratios of about 2^k reveal Θ(n^k). Lower-order terms push early ratios slightly off (2n + 100 grows by about 1.97), which is why the rule averages three doublings and places thresholds midway between the classes. Real measurements are noisier, so in practice you also check larger n.

### Edge Cases
- A linear algorithm with a large constant term (ratio slightly below 2).
- Floating-point is safe here because the thresholds are far from the true ratios.

### Tests
#### Linear with an offset
```text
1
2100 4100 8100 16100
```
```text
O(n)
```

## DSA04-M05 · Count Smaller Elements
**Difficulty:** Medium · **Subtopic:** Preprocessing for many queries · **Tags:** sorting, binary search, complexity · **Source:** Original

### Statement
For each query value x, print how many elements of the array are strictly smaller than x. With n and q up to 2·10^5, scanning the array per query is 4·10^10 operations.

### Input
n, then n integers; q, then q queries.

### Output
One count per query.

### Constraints
- 1 ≤ n, q ≤ 2·10^5
- |values| ≤ 10^9

### Sample Input
```text
5
5 1 4 2 8
3
4
9
1
```

### Sample Output
```text
2
5
0
```

### Sample Explanation
Elements smaller than 4 are 1 and 2. Every element is smaller than 9; none is smaller than 1.

### Target
O((n + q) log n).

### Hints
1. Sort the array once.
2. In a sorted array, the number of elements smaller than x is the index of the first element ≥ x.

### Approach
Sort, then answer each query with `lower_bound(a.begin(), a.end(), x) − a.begin()`.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    sort(a.begin(), a.end());                     // pay O(n log n) once
    int q;
    cin >> q;
    while (q--) {
        long long x;
        cin >> x;
        cout << lower_bound(a.begin(), a.end(), x) - a.begin() << '\n';   // O(log n) each
    }
}
```

### Explanation
Preprocessing changes the cost model: O(n log n) once plus O(log n) per query, instead of O(n) per query. With q comparable to n, the total falls from Θ(n·q) to Θ((n + q) log n). This trade-off (invest in preprocessing, answer queries fast) appears throughout the course.

### Edge Cases
- Duplicates equal to x are not counted (strictly smaller).
- x below the minimum or above the maximum.

### Tests
#### Duplicates of x


## DSA04-H01 · Exact Harmonic Count for Huge n
**Difficulty:** Hard · **Subtopic:** Beating Θ(n) with structure · **Tags:** math, block decomposition, harmonic series · **Source:** Original

### Statement
Compute S(n) = ⌊n/1⌋ + ⌊n/2⌋ + … + ⌊n/n⌋ (the iteration count of the harmonic double loop) for n up to 10^12. A loop over i is 10^12 steps, far too slow.

### Input
T, then T values of n.

### Output
S(n) for each n.

### Constraints
- 1 ≤ T ≤ 10
- 1 ≤ n ≤ 10^12

### Sample Input
```text
2
10
1000000000000
```

### Sample Output
```text
27
27785452449086
```

### Sample Explanation
For n = 10: 10 + 5 + 3 + 2 + 2 + 1 + 1 + 1 + 1 + 1 = 27.

### Target
O(√n) per query.

### Hints
1. ⌊n/i⌋ takes at most about 2√n distinct values as i goes from 1 to n.
2. For a value q = ⌊n/i⌋, the largest i' with the same quotient is ⌊n/q⌋. All i in [i, i'] contribute q each.
3. Jump from block to block: i = i' + 1.

### Approach
`i = 1; while i ≤ n: q = n / i; last = n / q; S += q·(last − i + 1); i = last + 1`. S is about n ln n ≈ 2.8·10^13 for n = 10^12, well within `long long`.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        long long n;
        cin >> n;
        long long total = 0;
        for (long long i = 1; i <= n;) {
            long long q = n / i;
            long long last = n / q;                 // largest i' with n / i' == q
            total += q * (last - i + 1);            // the whole block at once
            i = last + 1;
        }
        cout << total << '\n';
    }
}
```

### Explanation
For i ≤ √n there are at most √n blocks; for i > √n the quotient is below √n, so at most √n more blocks: O(√n) blocks in total, about 2·10^6 for n = 10^12. Each block's value is constant, so the block contributes q·(length) exactly. This is an example where understanding the *structure* of a sum, not just its growth rate, gives a faster algorithm.

### Edge Cases
- n = 1.
- Perfect squares (the two regimes meet at √n).

## DSA04-H02 · Pairs Within Distance
**Difficulty:** Hard · **Subtopic:** Sorting plus two pointers · **Tags:** two pointers, sorting, counting · **Source:** Original

### Statement
Count the pairs of positions i < j with |aᵢ − aⱼ| ≤ D. All pairs is O(n²); find an O(n log n) method.

### Input
n and D, then n integers.

### Output
The number of pairs.

### Constraints
- 1 ≤ n ≤ 2·10^5
- 0 ≤ D ≤ 2·10^9, |aᵢ| ≤ 10^9

### Sample Input
```text
5 2
1 3 4 8 9
```

### Sample Output
```text
3
```

### Sample Explanation
The pairs (1, 3), (3, 4) and (8, 9) differ by at most 2.

### Target
O(n log n) time.

### Hints
1. The order of positions does not matter for the count, so sort the values.
2. In sorted order, for each right end j the valid left ends form a contiguous block ending at j − 1.
3. As j moves right, the left boundary only moves right: two pointers.

### Approach
Sort. Keep `left`; for each j, advance `left` while a[j] − a[left] > D; add j − left. Total pointer moves are O(n).

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    long long d;
    cin >> n >> d;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    sort(a.begin(), a.end());
    long long pairs = 0;
    int left = 0;
    for (int j = 0; j < n; ++j) {
        while (a[j] - a[left] > d) ++left;    // left only ever moves forward
        pairs += j - left;                     // partners left..j-1 are all within d
    }
    cout << pairs << '\n';
}
```

### Explanation
After sorting, if a[left] is within D of a[j], so is every element between them, so the valid partners of j form one block. The left pointer is monotone, so across all j it moves at most n times: the scan is Θ(n), and sorting dominates. The count can reach about 2·10^10.

### Edge Cases
- D = 0: count pairs of equal values.
- All values equal: n(n − 1)/2 pairs.

### Tests
#### Equal values with D zero
```text
4 0
5 5 5 1
```
```text
3
```

## DSA04-H03 · Subarrays Summing to K
**Difficulty:** Hard · **Subtopic:** Prefix sums with hashing · **Tags:** prefix sums, hashing, counting, complexity · **Source:** Original

### Statement
Count the contiguous subarrays whose sum is exactly K. Values may be negative, so a sliding window does not work, and all O(n²) subarrays are too many.

### Input
n and K, then n integers.

### Output
The number of subarrays.

### Constraints
- 1 ≤ n ≤ 2·10^5
- |values| ≤ 10^9, |K| ≤ 10^15

### Sample Input
```text
5 3
1 2 1 -1 3
```

### Sample Output
```text
5
```

### Sample Explanation
The subarrays [1, 2], [2, 1], [1, 2, 1, −1], [1, −1, 3] and [3] sum to 3.

### Target
O(n) expected time.

### Hints
1. With prefix sums P (P₀ = 0, Pⱼ = a₁ + … + aⱼ), the subarray (i, j] sums to Pⱼ − Pᵢ.
2. For each j, count earlier prefixes Pᵢ = Pⱼ − K.
3. Store prefix-sum counts in a hash map, starting with P₀ = 0 counted once.

### Approach
Running prefix sum; map from prefix value to how many times it has occurred. For each new prefix, add the count of (prefix − K), then record the prefix.

### Solution
```cpp
#include <iostream>
#include <unordered_map>
using namespace std;

int main() {
    int n;
    long long k;
    cin >> n >> k;
    unordered_map<long long, long long> seen{{0, 1}};   // the empty prefix
    seen.reserve(2 * n + 2);
    long long prefix = 0, count = 0;
    for (int j = 0; j < n; ++j) {
        long long x;
        cin >> x;
        prefix += x;
        auto it = seen.find(prefix - k);
        if (it != seen.end()) count += it->second;     // subarrays ending at j with sum k
        ++seen[prefix];
    }
    cout << count << '\n';
}
```

### Explanation
Every subarray is a difference of two prefix sums, so counting subarrays with sum K is counting earlier prefixes equal to Pⱼ − K, which the map answers in O(1) expected time. This turns Θ(n²) into Θ(n). The sliding-window trick fails with negative values because extending a window can decrease its sum.

### Edge Cases
- K = 0 with zeros in the array.
- The whole array as the only answer.
- Prefix sums reach 2·10^14 in absolute value.

### Tests
#### Zeros and K zero
```text

0 0 0
```
```text

```

## DSA04-H04 · K-th Smallest Pair Distance
**Difficulty:** Hard · **Subtopic:** Binary search on the answer · **Tags:** binary search, two pointers, sorting, complexity · **Source:** Original

### Statement
For all n(n − 1)/2 pairs i < j, consider the distance |aᵢ − aⱼ|. Print the k-th smallest distance. Listing every distance costs O(n²) time and memory (5·10^9 pairs for n = 10^5).

### Input
n and k, then n integers.

### Output
The k-th smallest pair distance.

### Constraints
- 2 ≤ n ≤ 10^5
- 1 ≤ k ≤ n(n − 1)/2
- 0 ≤ aᵢ ≤ 10^9

### Sample Input
```text
4 3
1 3 1 6
```

### Sample Output
```text
2
```

### Sample Explanation
The distances are 2, 0, 5, 2, 3, 5; sorted: 0, 2, 2, 3, 5, 5. The third is 2.

### Target
O(n log n + n log W), where W is the largest value.

### Hints
1. Instead of finding the k-th distance directly, ask: "how many pairs have distance ≤ d?" This count grows with d.
2. Counting pairs with distance ≤ d is DSA04-H02: sort plus two pointers, O(n).
3. Binary search the smallest d whose count is at least k.

### Approach
Sort. Binary search d in [0, max − min]. For each candidate, count pairs within d with two pointers; move the search range accordingly.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

vector<long long> a;

long long pairsWithin(long long d) {           // pairs with distance <= d, O(n)
    long long count = 0;
    size_t left = 0;
    for (size_t j = 0; j < a.size(); ++j) {
        while (a[j] - a[left] > d) ++left;
        count += static_cast<long long>(j - left);
    }
    return count;
}

int main() {
    int n;
    long long k;
    cin >> n >> k;
    a.resize(n);
    for (auto& x : a) cin >> x;
    sort(a.begin(), a.end());
    long long lo = 0, hi = a.back() - a.front();   // the answer lies in [lo, hi]
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (pairsWithin(mid) >= k) hi = mid;      // at least k distances are <= mid
        else lo = mid + 1;
    }
    cout << lo << '\n';
}
```

### Explanation
The function count(d) is non-decreasing, and the answer is the smallest d with count(d) ≥ k, so binary search applies. Each step is O(n), and there are O(log W) ≈ 30 steps, so the whole algorithm is O(n log n + n log W) ≈ 3·10^6 operations instead of 5·10^9. "Binary search on the answer" converts an optimisation question into a sequence of yes/no questions.

### Edge Cases
- k = 1: the smallest distance (0 if there are duplicates).
- k = n(n − 1)/2: the largest distance.
- All values equal.

### Tests
#### Largest distance
```text
3 3
10 1 5
```
```text

```

## DSA04-H05 · Zero-Sum Triplets
**Difficulty:** Hard · **Subtopic:** From O(n³) to O(n²) · **Tags:** two pointers, sorting, counting · **Source:** Original

### Statement
Count the triples of positions i < j < k with aᵢ + aⱼ + aₖ = 0. Different positions count separately even if their values are equal. The O(n³) brute force is about 4.5·10^9 triples for n = 3000.

### Input
n, then n integers.

### Output
The number of triples.

### Constraints
- 3 ≤ n ≤ 3000
- |aᵢ| ≤ 10^9

### Sample Input
```text
6
-1 0 1 2 -1 -4
```

### Sample Output
```text
3
```

### Sample Explanation
(−1, 0, 1) can use either of the two −1s, and (−1, −1, 2) uses both: three triples.

### Target
O(n²) time.

### Hints
1. Sort. Fix the smallest element a[i]; count pairs in a[i+1..n−1] summing to −a[i].
2. Use two pointers moving inwards. When a[l] + a[r] equals the target, handle runs of equal values.
3. If a[l] = a[r], every pair inside that run works: m(m − 1)/2 pairs.

### Approach
For each i: l = i + 1, r = n − 1. While l < r: compare a[l] + a[r] with −a[i] and move a pointer. On a match with a[l] ≠ a[r], count the run lengths cl and cr and add cl·cr; skip both runs. On a match with a[l] = a[r], add m(m − 1)/2 for m = r − l + 1 and stop.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    sort(a.begin(), a.end());
    long long triples = 0;
    for (int i = 0; i < n; ++i) {
        long long target = -a[i];
        int l = i + 1, r = n - 1;
        while (l < r) {
            long long s = a[l] + a[r];
            if (s < target) ++l;
            else if (s > target) --r;
            else if (a[l] == a[r]) {                       // all remaining values equal
                long long m = r - l + 1;
                triples += m * (m - 1) / 2;
                break;
            } else {
                long long cl = 1, cr = 1;
                while (l + cl < r && a[l + cl] == a[l]) ++cl;   // run of a[l]
                while (r - cr > l && a[r - cr] == a[r]) ++cr;   // run of a[r]
                triples += cl * cr;
                l += cl;
                r -= cr;
            }
        }
    }
    cout << triples << '\n';
}
```

### Explanation
Sorting lets the pair search for each i run in O(n) with two pointers, because a larger sum is fixed by moving r left and a smaller one by moving l right. Counting runs of equal values handles duplicates without listing every pair. Fixing i as the smallest index of the sorted order ensures each triple of positions is counted once. Total: O(n²) ≈ 9·10^6 steps.

### Edge Cases
- All zeros: C(n, 3) triples.
- No triple at all.
- Values up to 10^9: sums up to 3·10^9 need `long long`.
