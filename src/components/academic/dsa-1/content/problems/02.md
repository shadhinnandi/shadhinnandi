# Abstract Data Types: Practice Problems

Each problem asks you to implement an ADT: decide what the operations must guarantee (preconditions, postconditions, invariants), then choose a structure that makes the frequent operations cheap.

## DSA02-E01 · Bounded Stack
**Difficulty:** Easy · **Subtopic:** Stack ADT and preconditions · **Tags:** stack, preconditions, array · **Source:** Original

### Statement
Implement a stack with a fixed capacity c that checks its preconditions instead of crashing.

- `push x`: if the stack holds c elements, print `OVERFLOW` and do nothing; otherwise push x (no output).
- `pop`: print and remove the top element, or print `UNDERFLOW` if empty.
- `top`: print the top element, or `UNDERFLOW` if empty.
- `size`: print the number of elements.

### Input
c and q, then q operations.

### Output
One line for every operation that produces output.

### Constraints
- 1 ≤ c ≤ 10^5, 1 ≤ q ≤ 2·10^5
- |x| ≤ 10^9

### Sample Input
```text
2 8
push 1
push 2
push 3
top
pop
pop
pop
size
```

### Sample Output
```text
OVERFLOW
2
2
1
UNDERFLOW
0
```

### Sample Explanation
The third push finds the stack full. After popping 2 and 1, the stack is empty, so the third pop underflows.

### Target
O(1) per operation, O(c) memory.

### Hints
1. Store the elements in an array of size c and keep an index `topIndex` (number of elements).
2. Each operation first checks its precondition: `topIndex < c` for push, `topIndex > 0` for pop and top.

### Approach
A `vector<long long>` of size c and a count n. Push writes `data[n++]`, pop reads `data[--n]`. The invariant is 0 ≤ n ≤ c, with the top at `data[n − 1]`.

### Solution
```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class BoundedStack {
    vector<long long> data;
    int count = 0;                       // invariant: 0 <= count <= capacity
public:
    explicit BoundedStack(int capacity) : data(capacity) {}
    bool full() const { return count == static_cast<int>(data.size()); }
    bool empty() const { return count == 0; }
    void push(long long x) { data[count++] = x; }   // precondition: !full()
    long long pop() { return data[--count]; }       // precondition: !empty()
    long long top() const { return data[count - 1]; }
    int size() const { return count; }
};

int main() {
    int capacity, q;
    cin >> capacity >> q;
    BoundedStack s(capacity);
    while (q--) {
        string op;
        cin >> op;
        if (op == "push") {
            long long x;
            cin >> x;
            if (s.full()) cout << "OVERFLOW\n";
            else s.push(x);
        } else if (op == "pop") {
            if (s.empty()) cout << "UNDERFLOW\n";
            else cout << s.pop() << '\n';
        } else if (op == "top") {
            if (s.empty()) cout << "UNDERFLOW\n";
            else cout << s.top() << '\n';
        } else {
            cout << s.size() << '\n';
        }
    }
}
```

### Explanation
The class keeps its invariant private: only its methods change `count`. The caller (here `main`) checks each precondition before calling, which is how the ADT contract divides responsibility. Every operation is a constant amount of work.

### Edge Cases
- Capacity 1.
- `pop` and `top` on an empty stack.
- Pushing after an overflow (the stack is unchanged).

### Tests
#### Capacity one
```text
1 4
push 5
push 6
pop
top
```
```text
OVERFLOW
5
UNDERFLOW
```

## DSA02-E02 · List ADT on an Array
**Difficulty:** Easy · **Subtopic:** List ADT · **Tags:** list, array, preconditions · **Source:** Original

### Statement
Implement the List ADT with positions 0 … size − 1:

- `insert i x`: insert x so that it becomes position i (valid if 0 ≤ i ≤ size);
- `erase i`: remove position i (valid if 0 ≤ i < size);
- `get i`: print the element at position i (valid if 0 ≤ i < size).

If an index is invalid, print `INVALID` and do nothing. After all operations, print the list, or `EMPTY`.

### Input
q, then q operations.

### Output
One line per `get` or invalid operation, then the final list.

### Constraints
- 1 ≤ q ≤ 10^4
- −10^9 ≤ i, x ≤ 10^9

### Sample Input
```text
7
insert 0 5
insert 1 7
insert 0 3
get 1
erase 0
get 5
insert 9 1
```

### Sample Output
```text
5
INVALID
INVALID
5 7
```

### Sample Explanation
After the three inserts the list is 3 5 7, so position 1 holds 5. Erasing position 0 leaves 5 7. Position 5 and insert position 9 are out of range.

### Target
O(n) per insert/erase, O(1) per get.

### Hints
1. Note the different valid ranges: `insert` may use position size (append), `erase` and `get` may not.
2. `vector::insert(begin() + i, x)` shifts the later elements right; `erase` shifts them left.

### Approach
Use a `vector<long long>`. Check the index range for each operation; perform `insert`, `erase` or indexing otherwise.

### Solution
```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    int q;
    cin >> q;
    vector<long long> list;
    while (q--) {
        string op;
        long long i;
        cin >> op >> i;
        long long n = static_cast<long long>(list.size());
        if (op == "insert") {
            long long x;
            cin >> x;
            if (i < 0 || i > n) cout << "INVALID\n";            // 0 <= i <= size
            else list.insert(list.begin() + i, x);
        } else if (i < 0 || i >= n) {                           // 0 <= i < size
            cout << "INVALID\n";
        } else if (op == "erase") {
            list.erase(list.begin() + i);
        } else {
            cout << list[i] << '\n';
        }
    }
    if (list.empty()) cout << "EMPTY\n";
    for (size_t k = 0; k < list.size(); ++k) cout << list[k] << (k + 1 < list.size() ? ' ' : '\n');
}
```

### Explanation
A contiguous array gives O(1) `get` but O(n) `insert` and `erase`, because the elements after position i must shift. A linked list (Module 08) reverses this trade-off. Checking indexes against `size` first prevents out-of-bounds access, which is undefined behaviour.

### Edge Cases
- Inserting at position size (the end) is valid.
- Negative indexes.
- Erasing the only element leaves `EMPTY`.

### Tests
#### Becomes empty
```text
3
insert 0 1
erase 0
erase 0
```
```text
INVALID
EMPTY
```

## DSA02-E03 · Set ADT on a Sorted Array
**Difficulty:** Easy · **Subtopic:** Set ADT · **Tags:** set, sorted array, binary search · **Source:** Original

### Statement
Implement a set of integers stored in a sorted array.

- `add x`: print `added` or `exists`;
- `remove x`: print `removed` or `missing`;
- `has x`: print `yes` or `no`.

At the end, print the size followed by the elements in increasing order.

### Input
q, then q operations.

### Output
One line per operation, then the final line.

### Constraints
- 1 ≤ q ≤ 10^4
- |x| ≤ 10^9

### Sample Input
```text
6
add 5
add 1
add 5
has 1
remove 7
remove 5
```

### Sample Output
```text
added
added
exists
yes
missing
removed
1 1
```

### Sample Explanation
After the operations the set is {1}.

### Target
O(log n) for `has`, O(n) for `add`/`remove`.

### Hints
1. Keep the array sorted at all times (the invariant). Then binary search finds x or the place where it belongs.
2. `lower_bound` returns the first element ≥ x.

### Approach
Use `lower_bound` to locate x. For `add`, insert at that position if absent; for `remove`, erase it if present.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    int q;
    cin >> q;
    vector<long long> items;                     // invariant: sorted, no duplicates
    while (q--) {
        string op;
        long long x;
        cin >> op >> x;
        auto it = lower_bound(items.begin(), items.end(), x);
        bool present = it != items.end() && *it == x;
        if (op == "add") {
            if (present) cout << "exists\n";
            else { items.insert(it, x); cout << "added\n"; }
        } else if (op == "remove") {
            if (present) { items.erase(it); cout << "removed\n"; }
            else cout << "missing\n";
        } else {
            cout << (present ? "yes" : "no") << '\n';
        }
    }
    cout << items.size();
    for (long long v : items) cout << ' ' << v;
    cout << '\n';
}
```

### Explanation
The sorted-array invariant makes membership a binary search (O(log n)) and gives ordered output for free, at the price of O(n) shifting on updates. A hash set makes updates O(1) expected but loses the order; a balanced BST gives O(log n) for everything. Module 17 compares them in detail.

### Edge Cases
- Removing from an empty set.
- Adding the same value repeatedly.
- The final set is empty: print `0`.

### Tests
#### Empty at the end
```text
2
add -3
remove -3
```
```text
added
removed
0
```

## DSA02-E04 · Word Frequency Map
**Difficulty:** Easy · **Subtopic:** Map ADT · **Tags:** map, dictionary, strings · **Source:** Original

### Statement
Count how often each word occurs in a text and print every distinct word with its count, in alphabetical order.

### Input
n, then n words (lowercase letters).

### Output
One line per distinct word: the word and its count.

### Constraints
- 1 ≤ n ≤ 2·10^5
- Each word has 1 to 20 letters.

### Sample Input
```text
7
the cat saw the dog and the
```

### Sample Output
```text
and 1
cat 1
dog 1
saw 1
the 3
```

### Sample Explanation
"the" occurs three times; every other word once.

### Target
O(n log d) with an ordered map (d distinct words).

### Hints
1. A Map ADT stores key → value pairs; here key = word, value = count.
2. `std::map` keeps keys sorted, so iterating it prints the words alphabetically.

### Approach
`map<string, int> freq; freq[word]++` for each word, then iterate the map.

### Solution
```cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    map<string, int> freq;          // ordered map: keys iterate in sorted order
    for (int i = 0; i < n; ++i) {
        string word;
        cin >> word;
        ++freq[word];               // missing keys start at 0
    }
    for (const auto& [word, count] : freq) cout << word << ' ' << count << '\n';
}
```

### Explanation
`operator[]` inserts a missing key with value 0 and returns a reference, so `++freq[word]` both inserts and counts. A balanced-tree map keeps keys ordered (O(log d) per operation); `unordered_map` would be O(1) expected but would need a separate sort for alphabetical output.

### Edge Cases
- All words the same.
- All words different.
- n = 1.

### Tests
#### One word repeated
```text
3
go go go
```
```text
go 3
```

## DSA02-E05 · Bank Account ADT
**Difficulty:** Easy · **Subtopic:** Invariants · **Tags:** invariants, preconditions, class design · **Source:** Original

### Statement
An account starts with balance 0. Its invariant is that the balance is never negative.

- `deposit a`: add a (no output);
- `withdraw a`: if a ≤ balance, subtract it (no output), otherwise print `REJECTED`;
- `balance`: print the balance.

### Input
q, then q operations.

### Output
One line per `balance` and per rejected withdrawal.

### Constraints
- 1 ≤ q ≤ 2·10^5
- 1 ≤ a ≤ 10^9

### Sample Input
```text
5
deposit 100
withdraw 30
withdraw 80
balance
deposit 5
```

### Sample Output
```text
REJECTED
70
```

### Sample Explanation
After withdrawing 30 the balance is 70, so withdrawing 80 would break the invariant.

### Target
O(1) per operation.

### Hints
1. The withdraw precondition is a ≤ balance. Check it before changing anything.
2. 2·10^5 deposits of 10^9 overflow an `int`.

### Approach
A class with a private `long long` balance; `withdraw` returns false instead of breaking the invariant.

### Solution
```cpp
#include <iostream>
#include <string>
using namespace std;

class Account {
    long long balance_ = 0;                // invariant: balance_ >= 0
public:
    void deposit(long long a) { balance_ += a; }
    bool withdraw(long long a) {
        if (a > balance_) return false;    // would break the invariant
        balance_ -= a;
        return true;
    }
    long long balance() const { return balance_; }
};

int main() {
    int q;
    cin >> q;
    Account acc;
    while (q--) {
        string op;
        cin >> op;
        if (op == "balance") {
            cout << acc.balance() << '\n';
        } else {
            long long a;
            cin >> a;
            if (op == "deposit") acc.deposit(a);
            else if (!acc.withdraw(a)) cout << "REJECTED\n";
        }
    }
}
```

### Explanation
Making the balance private means no code outside the class can set it negative; every path that changes it preserves the invariant. The total can reach 2·10^14, so the field is `long long`.

### Edge Cases
- Withdrawing exactly the whole balance is allowed.
- Withdrawing from a zero balance.

### Tests
#### Exact withdrawal
```text
4
deposit 50
withdraw 50
withdraw 1
balance
```
```text
REJECTED
0
```

## DSA02-M01 · Queue from Two Stacks
**Difficulty:** Medium · **Subtopic:** Implementing one ADT with another · **Tags:** queue, stack, amortised analysis · **Source:** Original

### Statement
Implement a FIFO queue using only two stacks (two `vector`s used with `push_back`, `back` and `pop_back`).

- `enqueue x`;
- `dequeue`: print and remove the front, or `EMPTY`;
- `front`: print the front, or `EMPTY`;
- `size`: print the number of elements.

### Input
q, then q operations.

### Output
One line per `dequeue`, `front` and `size`.

### Constraints
- 1 ≤ q ≤ 2·10^5
- |x| ≤ 10^9

### Sample Input
```text
7
enqueue 1
enqueue 2
dequeue
enqueue 3
front
dequeue
size
```

### Sample Output
```text
1
2
2
1
```

### Sample Explanation
The queue is [1, 2], then [2], then [2, 3]; the front is 2, and after removing it [3] remains.

### Target
O(1) amortised per operation.

### Hints
1. Push new elements onto an `in` stack. Take elements from an `out` stack.
2. When `out` is empty and you need the front, move every element from `in` to `out`: this reverses their order, putting the oldest on top.
3. Each element is moved at most once, so the total work over q operations is O(q).

### Approach
`in` receives enqueues. Before `front` or `dequeue`, if `out` is empty, pop everything from `in` and push it onto `out`. The front is `out.back()`.

### Solution
```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class TwoStackQueue {
    vector<long long> in, out;     // out's top is the queue front
    void shift() {                 // move in -> out only when out is empty
        if (out.empty())
            while (!in.empty()) { out.push_back(in.back()); in.pop_back(); }
    }
public:
    void enqueue(long long x) { in.push_back(x); }
    bool empty() const { return in.empty() && out.empty(); }
    size_t size() const { return in.size() + out.size(); }
    long long front() { shift(); return out.back(); }          // precondition: !empty()
    long long dequeue() { shift(); long long x = out.back(); out.pop_back(); return x; }
};

int main() {
    int q;
    cin >> q;
    TwoStackQueue queue;
    while (q--) {
        string op;
        cin >> op;
        if (op == "enqueue") {
            long long x;
            cin >> x;
            queue.enqueue(x);
        } else if (op == "size") {
            cout << queue.size() << '\n';
        } else if (queue.empty()) {
            cout << "EMPTY\n";
        } else {
            cout << (op == "front" ? queue.front() : queue.dequeue()) << '\n';
        }
    }
}
```

### Explanation
Reversing a stack once turns LIFO into FIFO. Moving elements only when `out` is empty preserves the order: everything in `out` is older than everything in `in`. A single `dequeue` can cost O(n), but each element is pushed and popped at most twice in total, so the amortised cost is O(1). This is the classic example of implementing one ADT on top of another.

### Edge Cases
- `dequeue` on an empty queue.
- Interleaving enqueues after a shift (new elements go to `in` and wait).

### Tests
#### Empty and refill
```text
6
dequeue
enqueue 9
front
dequeue
front
size
```
```text
EMPTY
9
9
EMPTY
0
```

## DSA02-M02 · Stack with Constant-Time Minimum
**Difficulty:** Medium · **Subtopic:** Augmented ADT · **Tags:** stack, invariants, design · **Source:** Original

### Statement
Design a stack that also reports its minimum element in O(1).

- `push x`;
- `pop`: remove the top (print `EMPTY` if empty);
- `min`: print the smallest element currently in the stack, or `EMPTY`.

### Input
q, then q operations.

### Output
One line per `min`, and per `pop` on an empty stack.

### Constraints
- 1 ≤ q ≤ 2·10^5
- |x| ≤ 10^9

### Sample Input
```text
8
push 5
push 3
push 7
min
pop
pop
min
pop
```

### Sample Output
```text
3
5
```

### Sample Explanation
Minimums: after 5, 3, 7 the minimum is 3. Popping 7 and 3 leaves 5.

### Target
O(1) per operation.

### Hints
1. A single "current minimum" variable is not enough: when the minimum is popped, you need the previous minimum.
2. Store, with every element, the minimum of the stack *up to and including* that element.

### Approach
Push pairs (x, min(x, minBelow)). The minimum of the whole stack is always the second value of the top pair.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

int main() {
    int q;
    cin >> q;
    vector<pair<long long, long long>> st;   // (value, minimum of this element and all below)
    while (q--) {
        string op;
        cin >> op;
        if (op == "push") {
            long long x;
            cin >> x;
            long long m = st.empty() ? x : min(x, st.back().second);
            st.push_back({x, m});
        } else if (st.empty()) {
            cout << "EMPTY\n";
        } else if (op == "pop") {
            st.pop_back();
        } else {
            cout << st.back().second << '\n';
        }
    }
}
```

### Explanation
Invariant: `st[i].second` is the minimum of `st[0..i]`. Push establishes it for the new top from the old top's value; pop simply removes the top, and the element below already stores its own correct minimum. This costs O(n) extra memory; a variant pushes onto a second stack only when x ≤ current minimum.

### Edge Cases
- Duplicate minimums (push 2, push 2, pop: the minimum is still 2).
- `min` or `pop` on an empty stack.

### Tests
#### Duplicate minimum
```text
5
push 2
push 2
pop
min
pop
```
```text
2
```

## DSA02-M03 · Emergency Room Queue
**Difficulty:** Medium · **Subtopic:** Priority Queue ADT · **Tags:** priority queue, heap, tie-breaking · **Source:** Original

### Statement
Patients arrive with a severity from 1 to 10. A doctor always treats the most severe patient; among equal severities, the one who arrived first.

- `arrive name s`: a patient arrives;
- `treat`: print the name of the patient treated next, or `NONE` if nobody is waiting.

### Input
q, then q operations.

### Output
One line per `treat`.

### Constraints
- 1 ≤ q ≤ 2·10^5
- 1 ≤ s ≤ 10; names are 1–20 letters

### Sample Input
```text
6
arrive Ana 3
arrive Bo 7
arrive Cy 7
treat
treat
treat
```

### Sample Output
```text
Bo
Cy
Ana
```

### Sample Explanation
Bo and Cy both have severity 7; Bo arrived first.

### Target
O(log n) per operation.

### Hints
1. A priority queue only knows one priority. Combine severity and arrival order into one key.
2. Use (severity, −arrivalNumber) so a larger severity wins and, on ties, a smaller arrival number wins.

### Approach
`priority_queue<tuple<int, int, string>>` with (severity, −arrival index, name). `top()` is the next patient.

### Solution
```cpp
#include <iostream>
#include <queue>
#include <string>
#include <tuple>
using namespace std;

int main() {
    int q;
    cin >> q;
    priority_queue<tuple<int, int, string>> waiting;   // max-heap on (severity, -arrival)
    int arrival = 0;
    while (q--) {
        string op;
        cin >> op;
        if (op == "arrive") {
            string name;
            int severity;
            cin >> name >> severity;
            waiting.emplace(severity, -arrival, name);
            ++arrival;
        } else if (waiting.empty()) {
            cout << "NONE\n";
        } else {
            cout << get<2>(waiting.top()) << '\n';
            waiting.pop();
        }
    }
}
```

### Explanation
The Priority Queue ADT promises "always extract the highest priority". `std::priority_queue` is a binary heap (Module 14) with O(log n) insertion and extraction. A heap is not stable by itself, so the arrival number makes the order well defined.

### Edge Cases
- `treat` with nobody waiting.
- All patients with the same severity: first come, first served.

### Tests
#### Ties and empty queue
```text
5
arrive Zed 2
arrive Amy 2
treat
treat
treat
```
```text
Zed
Amy
NONE
```

## DSA02-M04 · Multiset Inventory
**Difficulty:** Medium · **Subtopic:** Map-based multiset · **Tags:** multiset, map, counting · **Source:** Original

### Statement
A warehouse stores items identified by integer codes; several items may share a code.

- `add x`: one more item with code x;
- `remove x`: remove one item with code x, or print `missing`;
- `count x`: print the number of items with code x;
- `distinct`: print the number of distinct codes in stock.

### Input
q, then q operations.

### Output
One line per `count`, `distinct` and failed `remove`.

### Constraints
- 1 ≤ q ≤ 2·10^5
- |x| ≤ 10^9

### Sample Input
```text
7
add 4
add 4
add 9
count 4
remove 4
distinct
remove 5
```

### Sample Output
```text
2
2
missing
```

### Sample Explanation
After the removal, codes 4 (one item) and 9 remain: two distinct codes.

### Target
O(log d) per operation.

### Hints
1. Store code → count in a map rather than every item separately.
2. When a count drops to 0, erase the key, so the map size is the number of distinct codes.

### Approach
`map<long long, int>`. `remove` decrements and erases at zero; `distinct` is `map.size()`.

### Solution
```cpp
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    int q;
    cin >> q;
    map<long long, int> stock;          // code -> count (> 0)
    while (q--) {
        string op;
        cin >> op;
        if (op == "distinct") {
            cout << stock.size() << '\n';
            continue;
        }
        long long x;
        cin >> x;
        if (op == "add") {
            ++stock[x];
        } else if (op == "count") {
            auto it = stock.find(x);
            cout << (it == stock.end() ? 0 : it->second) << '\n';
        } else {
            auto it = stock.find(x);
            if (it == stock.end()) cout << "missing\n";
            else if (--it->second == 0) stock.erase(it);   // keep the invariant: counts > 0
        }
    }
}
```

### Explanation
Representing a multiset as code → count uses memory proportional to the number of distinct codes, not items. The invariant "every stored count is positive" makes `distinct` simply the map size. Using `find` for `count` avoids inserting zero entries, which `operator[]` would do.

### Edge Cases
- Removing the last item of a code.
- Counting a code that never existed (0, without inserting it).

### Tests
#### Remove to zero
```text
4
add 1
remove 1
count 1
distinct
```
```text
0
0
```

## DSA02-M05 · Circular Buffer Deque

### Statement
Implement a double-ended queue from scratch (without `std::deque` or `std::list`) using a circular array that doubles its capacity when full.

- `push_front x`, `push_back x`;

- `size`: print the size.

### Input
q, then q operations.

### Output
One line per pop and per `size`.

### Constraints
- 1 ≤ q ≤ 2·10^5
- |x| ≤ 10^9

### Sample Input
```text
7

push_back 2
push_front 0
pop_back
pop_front
size
pop_front
```

### Sample Output
```text
2
0
1
1
```

The deque becomes [0, 1, 2]; popping the back gives 2, the front gives 0, leaving [1].

### Target
O(1) amortised per operation.

### Hints
1. Keep `head` (index of the front), `count` and a buffer of capacity cap. The i-th element is at `(head + i) % cap`.
2. `push_front` moves head one step backwards: `head = (head − 1 + cap) % cap`.
3. When full, copy the elements in order into a buffer twice as large and reset head to 0.

### Approach
Circular indexing with wraparound, plus doubling when `count == cap`. Each operation is O(1) except a resize, which is O(n) but happens rarely enough to be O(1) amortised.

### Solution
```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Deque {
    vector<long long> buf = vector<long long>(4);
    size_t head = 0, count = 0;              // element i lives at (head + i) % buf.size()
    void grow() {
        vector<long long> bigger(buf.size() * 2);
        for (size_t i = 0; i < count; ++i) bigger[i] = buf[(head + i) % buf.size()];
        buf.swap(bigger);
        head = 0;
    }
public:
    size_t size() const { return count; }
    void pushBack(long long x) {
        if (count == buf.size()) grow();
        buf[(head + count) % buf.size()] = x;
        ++count;
    }
    void pushFront(long long x) {
        if (count == buf.size()) grow();
        head = (head + buf.size() - 1) % buf.size();   // step back with wraparound
        buf[head] = x;
        ++count;
    }
    long long popFront() {                           // precondition: size() > 0
        long long x = buf[head];
        head = (head + 1) % buf.size();
        --count;
        return x;
    }
    long long popBack() {                            // precondition: size() > 0
        --count;
        return buf[(head + count) % buf.size()];
    }
};

int main() {
    int q;
    cin >> q;
    Deque d;
    while (q--) {
        string op;
        cin >> op;
        if (op == "push_front" || op == "push_back") {
            long long x;
            cin >> x;
            if (op == "push_front") d.pushFront(x);
            else d.pushBack(x);
        } else if (op == "size") {
            cout << d.size() << '\n';
        } else if (d.size() == 0) {
            cout << "EMPTY\n";
        } else {
            cout << (op == "pop_front" ? d.popFront() : d.popBack()) << '\n';
        }
    }
}
```

### Explanation
The circular array treats the buffer as a ring, so both ends can grow and shrink in O(1) without shifting. Adding `buf.size() − 1` instead of subtracting 1 keeps `head` non-negative with unsigned indices. Resizing copies elements in logical order, which "unwraps" the ring. Module 10 develops circular queues in detail.

### Edge Cases
- Popping from an empty deque.
- Wraparound: push_front on an empty buffer moves head to the last slot.
- Many pushes trigger several resizes.

```text
push_back 5
pop_front
pop_back
size
pop_front
```

## DSA02-H01 · LRU Cache
**Difficulty:** Hard · **Subtopic:** Composite ADT (map + list) · **Tags:** cache, hash map, linked list, design · **Source:** Original

### Statement
A web server caches up to c pages. When the cache is full and a new page must be stored, it evicts the **least recently used** page (the one not read or written for the longest time).

- `get k`: print the value stored for key k, or −1 if absent. A successful get makes k the most recently used.
- `put k v`: store v for key k (updating it if present) and make k the most recently used. If this makes the cache exceed c keys, evict the least recently used key.

### Input
c and q, then q operations.

### Output
One line per `get`.

### Constraints
- 1 ≤ c ≤ 10^5, 1 ≤ q ≤ 2·10^5
- 0 ≤ k, v ≤ 10^9

### Sample Input
```text
2 7
put 1 10
put 2 20
get 1
put 3 30
get 2
get 3
get 1
```

### Sample Output
```text
10
-1
30
10
```

### Sample Explanation
After `get 1`, key 2 is the least recently used, so `put 3` evicts key 2.

### Target
O(1) expected per operation.

### Hints
1. You need two things fast: find a key (a hash map) and maintain the usage order with O(1) moves (a doubly linked list).
2. Keep the list ordered from most to least recently used; the map stores, for each key, an iterator to its list node.
3. `list::splice` moves a node to the front in O(1) without invalidating iterators.

### Approach
`list<pair<key, value>> order` (front = most recent) and `unordered_map<key, list iterator> where`. `get`: if present, splice its node to the front and print the value. `put`: if present, update and splice; otherwise push_front and, if the size exceeds c, erase the back node and its map entry.

### Solution
```cpp
#include <iostream>
#include <list>
#include <string>
#include <unordered_map>
#include <utility>
using namespace std;

class LRUCache {
    size_t capacity;
    list<pair<long long, long long>> order;   // front = most recently used
    unordered_map<long long, list<pair<long long, long long>>::iterator> where;
public:
    explicit LRUCache(size_t c) : capacity(c) {}
    long long get(long long key) {
        auto it = where.find(key);
        if (it == where.end()) return -1;
        order.splice(order.begin(), order, it->second);   // move to front, O(1)
        return it->second->second;
    }
    void put(long long key, long long value) {
        auto it = where.find(key);
        if (it != where.end()) {
            it->second->second = value;
            order.splice(order.begin(), order, it->second);
            return;
        }
        order.emplace_front(key, value);
        where[key] = order.begin();
        if (order.size() > capacity) {                    // evict the least recently used
            where.erase(order.back().first);
            order.pop_back();
        }
    }
};

int main() {
    size_t capacity;
    int q;
    cin >> capacity >> q;
    LRUCache cache(capacity);
    while (q--) {
        string op;
        long long key;
        cin >> op >> key;
        if (op == "get") {
            cout << cache.get(key) << '\n';
        } else {
            long long value;
            cin >> value;
            cache.put(key, value);
        }
    }
}
```

### Explanation
Neither structure alone suffices: a map cannot tell which key is least recently used, and a list cannot find a key in O(1). Together, the map gives O(1) lookup of a node and the list gives O(1) reordering and eviction. `splice` relinks a node without copying it, so the stored iterators stay valid. This is the standard design in real caches and a frequent interview question.

### Edge Cases
- Capacity 1: every new key evicts the previous one.
- `put` on an existing key updates it without eviction.
- `get` on a missing key does not change the order.

### Tests
#### Capacity one and updates
```text
1 5
put 1 1
put 1 5
get 1
put 2 2
get 1
```
```text
5
-1
```

## DSA02-H02 · Text Editor Buffer
**Difficulty:** Hard · **Subtopic:** Two-stack buffer with a cursor · **Tags:** stack, design, strings · **Source:** Original

### Statement
Implement a text buffer with a cursor, starting empty with the cursor at position 0.

- `type s`: insert the string s at the cursor; the cursor ends after it;
- `left k` / `right k`: move the cursor up to k characters (stopping at the ends);
- `backspace k`: delete up to k characters to the left of the cursor.

After all operations, print the text (print `EMPTY` if the text is empty).

### Input
q, then q operations.

### Output
The final text.

### Constraints
- 1 ≤ q ≤ 10^5
- s consists of lowercase letters; total typed length ≤ 10^6
- 1 ≤ k ≤ 10^9; the sum of min(k, characters that can actually move or be deleted) is at most 2·10^6

### Sample Input
```text
6
type hello
left 2
type XX
backspace 1
right 5
type !
```

### Sample Output
```text
helXlo!
```

### Sample Explanation
"hello" with the cursor moved before "lo"; typing "XX" gives "helXX|lo"; backspace removes one X; the cursor moves to the end (only 2 steps were possible) and "!" is appended.

### Target
O(1) per character typed, moved or deleted.

### Hints
1. Split the text at the cursor: a left part and a right part.
2. Store the left part as a stack (its top is the character before the cursor) and the right part as a stack (its top is the character after the cursor).
3. Moving left pops from the left stack and pushes onto the right stack.

### Approach
Two `vector<char>` stacks. `type` pushes onto `left`; `backspace` pops `left`; `left k` moves min(k, |left|) characters from `left` to `right`; `right k` moves back. At the end, print `left` in order followed by `right` reversed.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    int q;
    cin >> q;
    vector<char> before, after;        // before: chars left of cursor; after: chars right (top = nearest)
    while (q--) {
        string op;
        cin >> op;
        if (op == "type") {
            string s;
            cin >> s;
            for (char c : s) before.push_back(c);
            continue;
        }
        long long k;
        cin >> k;
        if (op == "left") {
            for (long long i = 0; i < k && !before.empty(); ++i) { after.push_back(before.back()); before.pop_back(); }
        } else if (op == "right") {
            for (long long i = 0; i < k && !after.empty(); ++i) { before.push_back(after.back()); after.pop_back(); }
        } else {
            for (long long i = 0; i < k && !before.empty(); ++i) before.pop_back();
        }
    }
    string text(before.begin(), before.end());
    text.append(after.rbegin(), after.rend());
    cout << (text.empty() ? "EMPTY" : text) << '\n';
}
```

### Explanation
Every editing operation happens at the cursor, which is exactly the top of both stacks, so each character costs O(1). A single string would make every insertion in the middle O(n). The loops stop when a stack runs out, so a huge k never costs more than the characters actually available. Real editors use the same idea under the name *gap buffer*.

### Edge Cases
- Moving or deleting more characters than exist.
- Deleting everything: print `EMPTY`.
- Typing at the very beginning (after `left` to position 0).

### Tests
#### Delete everything
```text
3
type abc
backspace 1000000000
right 3
```
```text
EMPTY
```

#### Insert at the start
```text
3
type world
left 9
type hello
```
```text
helloworld
```

## DSA02-H03 · Task Manager with Priority Changes
**Difficulty:** Hard · **Subtopic:** Choosing an implementation · **Tags:** priority queue, ordered set, hash map, design · **Source:** Original

### Statement
A task manager holds tasks with unique ids and integer priorities.

- `add id p`: add a task (the id is not currently present);
- `change id p`: change the priority of an existing task;
- `remove id`: delete an existing task;
- `top`: print the id of the task with the highest priority (ties: smaller id), or `EMPTY`;
- `pop`: like `top`, but also remove that task.

A plain binary heap cannot change or remove arbitrary elements efficiently, so choose a different implementation of the Priority Queue ADT.

### Input
q, then q operations.

### Output
One line per `top` and `pop`.

### Constraints
- 1 ≤ q ≤ 2·10^5
- 1 ≤ id ≤ 10^9, |p| ≤ 10^9; `change` and `remove` always refer to present ids

### Sample Input
```text
8
add 1 5
add 2 9
add 3 9
top
change 2 1
pop
remove 1
top
```

### Sample Output
```text
2
3
2
```

### Sample Explanation
Tasks 2 and 3 tie at priority 9, so 2 is on top. After task 2 drops to priority 1, task 3 is popped. Removing task 1 leaves only task 2.

### Target
O(log n) per operation.

### Hints
1. An ordered set of (priority, id) pairs supports insert, erase of a *specific* pair, and max in O(log n).
2. To erase a task by id, you need its current priority: keep a hash map id → priority.
3. Order the set so the best task is first: store (−priority, id).

### Approach
`set<pair<long long, long long>> tasks` holding (−p, id), and `unordered_map<long long, long long> priority`. `change` erases the old pair and inserts the new one. `top` is `tasks.begin()`.

### Solution
```cpp
#include <iostream>
#include <set>
#include <string>
#include <unordered_map>
#include <utility>
using namespace std;

int main() {
    int q;
    cin >> q;
    set<pair<long long, long long>> tasks;          // (-priority, id): begin() is the best task
    unordered_map<long long, long long> priority;   // id -> current priority
    while (q--) {
        string op;
        cin >> op;
        if (op == "top" || op == "pop") {
            if (tasks.empty()) { cout << "EMPTY\n"; continue; }
            long long id = tasks.begin()->second;
            cout << id << '\n';
            if (op == "pop") { tasks.erase(tasks.begin()); priority.erase(id); }
            continue;
        }
        long long id;
        cin >> id;
        if (op == "remove") {
            tasks.erase({-priority[id], id});
            priority.erase(id);
            continue;
        }
        long long p;
        cin >> p;
        if (op == "change") tasks.erase({-priority[id], id});
        tasks.insert({-p, id});
        priority[id] = p;
    }
}
```

### Explanation
The ADT (priority queue with updates) is the same as before, but the required operations changed, so the implementation changes too: a balanced BST (`std::set`) can delete any element in O(log n), while `std::priority_queue` cannot. The hash map tells us which pair to delete. Negating the priority makes the smallest pair the best task, with ties broken by the smaller id automatically.

### Edge Cases
- `top`/`pop` on an empty manager.
- Changing a priority to the same value.
- Ties on priority.

### Tests
#### Empty and same-priority change
```text
5
pop
add 7 3
change 7 3
pop
top
```
```text
EMPTY
7
EMPTY
```

## DSA02-H04 · Undo and Redo on a Set
**Difficulty:** Hard · **Subtopic:** ADT with history · **Tags:** stack, set, undo, design · **Source:** Original

### Statement
Implement a set of integers with undo and redo.

- `add x`, `remove x`: if the operation changes the set, record it in the history; otherwise it is ignored completely;
- `undo`: revert the most recent recorded change (print `NOTHING` if there is none);
- `redo`: re-apply the most recently undone change (print `NOTHING` if there is none). Any new recorded change clears the redo history;
- `has x`: print `yes` or `no`.

### Input
q, then q operations.

### Output
One line per `has`, and per `undo`/`redo` that has nothing to do.

### Constraints
- 1 ≤ q ≤ 2·10^5
- |x| ≤ 10^9

### Sample Input
```text
9
add 5
add 6
undo
has 6
redo
has 6
remove 5
redo
has 5
```

### Sample Output
```text
no
yes
NOTHING
no
```

### Sample Explanation
`undo` removes 6; `redo` adds it back. `remove 5` is a new change, which clears the redo history, so the next `redo` has nothing to do.

### Target
O(1) expected per operation.

### Hints
1. Represent each change as (type, value); its inverse swaps add and remove.
2. Use two stacks: `undoStack` holds applied changes, `redoStack` holds undone ones.
3. Only changes that actually modify the set are pushed; ignoring no-op changes keeps undo meaningful.

### Approach
`unordered_set` for the data. `apply(change)` performs it. `undo`: pop from `undoStack`, apply its inverse, push onto `redoStack`. `redo`: pop from `redoStack`, apply it, push onto `undoStack`. New effective changes push onto `undoStack` and clear `redoStack`.

### Solution
```cpp
#include <iostream>
#include <string>
#include <unordered_set>
#include <utility>
#include <vector>
using namespace std;

using Change = pair<bool, long long>;   // (isAdd, value)

unordered_set<long long> items;

void apply(const Change& c) {
    if (c.first) items.insert(c.second);
    else items.erase(c.second);
}

int main() {
    int q;
    cin >> q;
    vector<Change> undoStack, redoStack;
    while (q--) {
        string op;
        cin >> op;
        if (op == "undo" || op == "redo") {
            auto& from = (op == "undo") ? undoStack : redoStack;
            auto& to = (op == "undo") ? redoStack : undoStack;
            if (from.empty()) { cout << "NOTHING\n"; continue; }
            Change c = from.back();
            from.pop_back();
            apply(op == "undo" ? Change{!c.first, c.second} : c);   // undo applies the inverse
            to.push_back(c);
            continue;
        }
        long long x;
        cin >> x;
        if (op == "has") {
            cout << (items.count(x) ? "yes" : "no") << '\n';
            continue;
        }
        bool isAdd = op == "add";
        bool changes = isAdd ? !items.count(x) : items.count(x) > 0;
        if (!changes) continue;                                     // no-op: not recorded
        Change c{isAdd, x};
        apply(c);
        undoStack.push_back(c);
        redoStack.clear();                                          // a new change ends the redo branch
    }
}
```

### Explanation
Because only effective changes are recorded, each change's inverse exactly restores the previous state: undoing "add 5" (which added a new element) removes 5, and undoing "remove 5" (which removed an existing element) adds it back. The two stacks model a timeline; a new change discards the "future". Editors, drawing programs and databases implement undo the same way (Module 09 revisits stacks).

### Edge Cases
- Undo/redo with empty histories.
- Adding an element that is already present (ignored, not recorded).
- Several undos followed by several redos.

### Tests
#### No-op changes are not recorded
```text
6
add 1
add 1
undo
has 1
undo
redo
```
```text
no
NOTHING
```

## DSA02-H05 · Interval Coverage Set
**Difficulty:** Hard · **Subtopic:** Map of disjoint intervals · **Tags:** ordered map, intervals, invariants · **Source:** Original

### Statement
A booking system tracks which time units are reserved, as a set of half-open intervals [l, r).

- `add l r`: mark [l, r) as reserved;
- `remove l r`: mark [l, r) as free;
- `query x`: print `yes` if time x is reserved, else `no`;
- `total`: print the total reserved length.

### Input
q, then q operations.

### Output
One line per `query` and `total`.

### Constraints
- 1 ≤ q ≤ 2·10^5
- 0 ≤ l < r ≤ 10^9, 0 ≤ x ≤ 10^9

### Sample Input
```text
8
add 1 5
add 3 8
query 7
remove 2 4
query 3
total
add 8 10
total
```

### Sample Output
```text
yes
no
5
7
```

### Sample Explanation
After the adds, [1, 8) is reserved. Removing [2, 4) leaves [1, 2) and [4, 8), total 5. Adding [8, 10) touches [4, 8), giving [4, 10): total 1 + 6 = 7.

### Target
O(log n) amortised per operation.

### Hints
1. Store disjoint, non-touching intervals in a `map<start, end>` (the invariant).
2. `add`: find every stored interval that overlaps or touches [l, r), extend l and r to cover them, erase them, insert the merged one.
3. `remove`: every overlapping interval is cut; keep its parts left of l and right of r. Update the total as you go.

### Approach
Maintain `map<long long, long long> segs` and `long long covered`. For `add`, start at the last interval with start ≤ l (if it reaches l) and absorb all intervals with start ≤ r. For `remove`, collect overlapping intervals, erase them and re-insert the leftover pieces. `query x` checks the interval with the largest start ≤ x. Each interval is inserted once and erased once, so the total work is O(q log q).

### Solution
```cpp
#include <iostream>
#include <iterator>
#include <map>
#include <string>
using namespace std;

map<long long, long long> segs;     // start -> end; disjoint and not touching
long long covered = 0;

void addRange(long long l, long long r) {
    auto it = segs.upper_bound(l);
    if (it != segs.begin() && prev(it)->second >= l) --it;     // previous interval reaches l
    while (it != segs.end() && it->first <= r) {                 // overlaps or touches [l, r)
        l = min(l, it->first);
        r = max(r, it->second);
        covered -= it->second - it->first;
        it = segs.erase(it);
    }
    segs[l] = r;
    covered += r - l;
}

void removeRange(long long l, long long r) {
    auto it = segs.upper_bound(l);
    if (it != segs.begin() && prev(it)->second > l) --it;      // previous interval covers l
    while (it != segs.end() && it->first < r) {
        long long s = it->first, e = it->second;
        covered -= e - s;
        it = segs.erase(it);
        if (s < l) { segs[s] = l; covered += l - s; }           // keep the left piece
        if (e > r) { segs[r] = e; covered += e - r; }           // keep the right piece
    }
}

bool reserved(long long x) {
    auto it = segs.upper_bound(x);
    return it != segs.begin() && prev(it)->second > x;
}

int main() {
    int q;
    cin >> q;
    while (q--) {
        string op;
        cin >> op;
        if (op == "total") { cout << covered << '\n'; continue; }
        if (op == "query") {
            long long x;
            cin >> x;
            cout << (reserved(x) ? "yes" : "no") << '\n';
            continue;
        }
        long long l, r;
        cin >> l >> r;
        if (op == "add") addRange(l, r);
        else removeRange(l, r);
    }
}
```

### Explanation
The invariant (disjoint, non-touching intervals keyed by start) makes `query` a single predecessor search and keeps `total` up to date incrementally. In `removeRange`, a right piece is only created for the last overlapping interval (intervals are disjoint), and it starts at key r, which fails the loop condition `it->first < r`; so no piece is ever cut twice. Because each operation erases what it merges or cuts, the amortised cost is O(log n).

### Edge Cases
- Touching intervals ([1, 3) and [3, 5)) merge into one.
- Removing a range strictly inside one interval splits it in two.
- Removing a free range changes nothing.

### Tests
#### Split and re-merge
```text
6
add 0 10
remove 3 4
query 3
total
add 3 4
total
```
```text
no
9
10
```
