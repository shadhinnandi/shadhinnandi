## DSA10-E01 · Queue Operations
**Difficulty:** Easy · **Subtopic:** Queue ADT · **Tags:** queue, FIFO, simulation · **Source:** Original

### Statement
Process `enqueue x`, `dequeue` (print value or `EMPTY`), `front` (print or `EMPTY`) and `size`.

### Input
q, then q operations.

### Output
One line per dequeue, front and size.

### Constraints
- 1 ≤ q ≤ 2·10^5

### Sample Input
```text
7
enqueue 1
enqueue 2
front
dequeue
size
dequeue
dequeue
```

### Sample Output
```text
1
1
1
2
EMPTY
```

### Sample Explanation
Elements leave in arrival order.

### Target
O(1) per operation.

### Hints
1. `std::queue` provides push, pop, front.
2. Check emptiness before front or pop.

### Approach
Direct use of `std::queue`.

### Solution
```cpp
#include <iostream>
#include <queue>
#include <string>
using namespace std;

int main() {
    int q;
    cin >> q;
    queue<long long> qu;
    while (q--) {
        string op;
        cin >> op;
        if (op == "enqueue") { long long x; cin >> x; qu.push(x); }
        else if (op == "size") cout << qu.size() << '\n';
        else if (qu.empty()) cout << "EMPTY\n";
        else { cout << qu.front() << '\n'; if (op == "dequeue") qu.pop(); }
    }
}
```

### Explanation
FIFO: insertion at the rear, removal at the front, both O(1).

### Edge Cases
- Dequeue on empty (calling `pop` on an empty `std::queue` is undefined).

### Tests
#### Empty front
```text
1
front
```
```text
EMPTY
```

## DSA10-E02 · Circular Queue
**Difficulty:** Easy · **Subtopic:** Wraparound indexing · **Tags:** circular queue, array, overflow · **Source:** Original

### Statement
Implement a circular queue of capacity c with `enqueue x` (print `OVERFLOW` when full), `dequeue` (print the value or `UNDERFLOW`), `front` and `rear` (print or `EMPTY`).

### Input
c and q, then q operations.

### Output
One line per printing operation.

### Constraints
- 1 ≤ c ≤ 10^5, 1 ≤ q ≤ 2·10^5

### Sample Input
```text
3 12
enqueue 1
enqueue 2
enqueue 3
enqueue 4
dequeue
enqueue 5
rear
front
dequeue
dequeue
dequeue
dequeue
```

### Sample Output
```text
OVERFLOW
1
5
2
2
3
5
UNDERFLOW
```

### Sample Explanation
After removing 1, slot 0 is reused for 5 (wraparound).

### Target
O(1) per operation.

### Hints
1. Store head and count; rear index = (head + count − 1) mod c.
2. A count distinguishes full from empty.

### Approach
Array with modular indices.

### Solution
```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    int c, q;
    cin >> c >> q;
    vector<long long> buf(c);
    int head = 0, count = 0;
    while (q--) {
        string op;
        cin >> op;
        if (op == "enqueue") {
            long long x;
            cin >> x;
            if (count == c) cout << "OVERFLOW\n";
            else { buf[(head + count) % c] = x; ++count; }
        } else if (op == "dequeue") {
            if (count == 0) cout << "UNDERFLOW\n";
            else { cout << buf[head] << '\n'; head = (head + 1) % c; --count; }
        } else if (count == 0) cout << "EMPTY\n";
        else cout << (op == "front" ? buf[head] : buf[(head + count - 1) % c]) << '\n';
    }
}
```

### Explanation
The modulus wraps indices around, so freed slots at the start are reused without shifting.

### Edge Cases
- Capacity 1; repeated wraparound.

### Tests
#### Capacity one
```text
1 3
enqueue 7
enqueue 8
rear
```
```text
OVERFLOW
7
```

## DSA10-E04 · Card Rotation
**Difficulty:** Easy · **Subtopic:** Queue simulation · **Tags:** queue, simulation · **Source:** Original

### Statement
Cards 1..n are stacked with 1 on top. Repeatedly discard the top card and then move the new top card to the bottom, until one card remains. Print the discarded cards in order (or `NONE`), then the last card.

### Input
n.

### Output
Two lines.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
```

### Sample Output
```text
1 3 2
4
```

### Sample Explanation
1 2 3 4 → discard 1, move 2: 3 4 2 → discard 3, move 4: 2 4 → discard 2: 4.

### Target
O(n).

### Hints
1. The deck behaves like a queue: take from the front, put at the back.
2. Stop when one card is left; print `NONE` if nothing was discarded.

### Approach
`std::queue` simulation.

### Solution
```cpp
#include <iostream>
#include <queue>
using namespace std;

int main() {
    int n;
    cin >> n;
    queue<int> deck;
    for (int i = 1; i <= n; ++i) deck.push(i);
    bool first = true;
    while (deck.size() > 1) {
        cout << (first ? "" : " ") << deck.front();
        first = false;
        deck.pop();
        deck.push(deck.front());
        deck.pop();
    }
    cout << (first ? "NONE" : "") << '\n' << deck.front() << '\n';
}
```

### Explanation
Each step is two O(1) queue operations; the loop runs n − 1 times.

### Edge Cases
- n = 1: nothing discarded.

### Tests
#### One card
```text
1
```
```text
NONE
1
```

## DSA10-E05 · Deque Palindrome Check
**Difficulty:** Easy · **Subtopic:** Deque · **Tags:** deque, strings · **Source:** Original

### Statement
Use a deque to check whether a word is a palindrome: repeatedly remove and compare both ends.

### Input
One word.

### Output
`YES` or `NO`.

### Constraints
- 1 ≤ length ≤ 2·10^5

### Sample Input
```text
racecar
```

### Sample Output
```text
YES
```

### Sample Explanation
Every pair of ends matches.

### Target
O(n).

### Hints
1. pop_front and pop_back are both O(1) in a deque.
2. Compare the two ends before removing them; stop when at most one character remains.

### Approach
Compare front and back until at most one character is left.

### Solution
```cpp
#include <deque>
#include <iostream>
#include <string>
using namespace std;

int main() {
    string s;
    cin >> s;
    deque<char> d(s.begin(), s.end());
    bool ok = true;
    while (d.size() > 1) {
        if (d.front() != d.back()) { ok = false; break; }
        d.pop_front();
        d.pop_back();
    }
    cout << (ok ? "YES" : "NO") << '\n';
}
```

### Explanation
A deque allows removal at both ends in O(1), which a queue or stack alone does not.

### Edge Cases
- One character.

### Tests
#### Not palindrome
```text
abca
```
```text
NO
```

## DSA10-M01 · Sliding Window Maximum
**Difficulty:** Medium · **Subtopic:** Monotonic deque · **Tags:** deque, sliding window, arrays · **Source:** Original

### Statement
Print the maximum of every window of k consecutive elements.

### Input
n and k, then n integers.

### Output
n − k + 1 maxima.

### Constraints
- 1 ≤ k ≤ n ≤ 2·10^5

### Sample Input
```text
8 3
1 3 -1 -3 5 3 6 7
```

### Sample Output
```text
3 3 5 5 6 7
```

### Sample Explanation
Windows [1 3 −1], [3 −1 −3], …

### Target
O(n).

### Hints
1. Keep indices in a deque with decreasing values; the front is the window maximum.
2. Drop the front when it leaves the window; drop smaller back elements when a new one arrives.

### Approach
Monotonic deque of indices.

### Solution
```cpp
#include <deque>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, k;
    cin >> n >> k;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    deque<int> d;
    vector<long long> out;
    for (int i = 0; i < n; ++i) {
        if (!d.empty() && d.front() <= i - k) d.pop_front();     // left the window
        while (!d.empty() && a[d.back()] <= a[i]) d.pop_back();  // can never be a maximum again
        d.push_back(i);
        if (i >= k - 1) out.push_back(a[d.front()]);
    }
    for (size_t j = 0; j < out.size(); ++j) cout << out[j] << (j + 1 < out.size() ? ' ' : '\n');
}
```

### Explanation
Each index enters and leaves the deque once: O(n), versus O(n·k) recomputation.

### Edge Cases
- k = 1; k = n.

### Tests
#### Whole array
```text
3 3
2 9 4
```
```text
9
```

## DSA10-M02 · Single Teller Waiting Times
**Difficulty:** Medium · **Subtopic:** Queue simulation with arrivals · **Tags:** queue, simulation, scheduling · **Source:** Original

### Statement
Customers arrive at non-decreasing times with given service times; one teller serves them in arrival order. Print each customer's waiting time (start − arrival).

### Input
n, then n lines arrival service.

### Output
n waiting times.

### Constraints
- 1 ≤ n ≤ 2·10^5, 0 ≤ times ≤ 10^9

### Sample Input
```text
4
0 5
1 3
2 1
10 2
```

### Sample Output
```text
0 4 6 0
```

### Sample Explanation
Starts at 0, 5, 8 and 10.

### Target
O(n).

### Hints
1. Track when the teller becomes free.
2. start = max(arrival, free).

### Approach
Single pass with the teller's free time.

### Solution
```cpp
#include <algorithm>
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;
    long long freeAt = 0;
    for (int i = 0; i < n; ++i) {
        long long arrive, service;
        cin >> arrive >> service;
        long long start = max(arrive, freeAt);
        cout << start - arrive << (i + 1 < n ? ' ' : '\n');
        freeAt = start + service;
    }
}
```

### Explanation
Because service is FIFO, the queue state is summarised by one number: when the teller is next free.

### Edge Cases
- Idle gaps; simultaneous arrivals.

### Tests

```text

```

### Statement
Requests arrive at strictly increasing times t (milliseconds). After each request print how many requests happened in [t − 3000, t].

### Input
n, then n times.

### Output

### Constraints

### Sample Input
```text

```

### Sample Output
```text

```

### Sample Explanation
At 3002 the request at 1 is too old.

### Target
O(n) amortised.

### Hints
1. Keep recent times in a queue.
2. Drop times older than t − 3000 from the front.

### Approach
Queue as a moving time window.

### Solution
```cpp
#include <iostream>
#include <queue>
using namespace std;

int main() {
    int n;

    for (int i = 0; i < n; ++i) {
        long long t;
        cin >> t;

}
```

### Explanation

```cpp
#include <iostream>
```

## DSA10-M05 · Round-Robin Scheduling
**Difficulty:** Medium · **Subtopic:** CPU scheduling queue · **Tags:** queue, scheduling, simulation · **Source:** Original

### Statement
n processes (numbered 1..n) with burst times arrive at time 0 in order. The CPU runs the front process for min(quantum, remaining) time; unfinished processes go to the back. Print each process's number and completion time in completion order.

### Input
n and quantum, then n burst times.

### Output
n lines: process and completion time.

### Constraints
- 1 ≤ n ≤ 10^4, 1 ≤ quantum, burst ≤ 10^4

### Sample Input
```text
3 2
5 2 1
```

### Sample Output
```text
2 4
3 5
1 8
```

### Sample Explanation
P1 runs 0–2, P2 2–4 (done), P3 4–5 (done), P1 5–7, 7–8.

### Target
O(total bursts / quantum + n).

### Hints
1. Queue of (id, remaining).
2. Re-enqueue only if work remains.

### Approach
Direct simulation.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <queue>
#include <utility>
using namespace std;

int main() {
    int n;
    long long quantum;
    cin >> n >> quantum;
    queue<pair<int, long long>> ready;
    for (int i = 1; i <= n; ++i) { long long b; cin >> b; ready.push({i, b}); }
    long long clock = 0;
    while (!ready.empty()) {
        auto [id, left] = ready.front();
        ready.pop();
        long long run = min(quantum, left);
        clock += run;
        if (left > run) ready.push({id, left - run});
        else cout << id << ' ' << clock << '\n';
    }
}
```

### Explanation
The ready queue gives every process a fair turn, the defining property of round robin.

### Edge Cases
- Quantum larger than every burst (FIFO).

### Tests
#### Large quantum
```text
2 100
3 4
```
```text
1 3
2 7
```

## DSA10-H01 · Shortest Subarray with Sum at Least K
**Difficulty:** Hard · **Subtopic:** Monotonic deque on prefix sums · **Tags:** deque, prefix sums, optimisation · **Source:** Original

### Statement
Values may be negative. Print the length of the shortest non-empty subarray with sum ≥ K, or −1.

### Input
n and K, then n integers.

### Output
The length or −1.

### Constraints
- 1 ≤ n ≤ 2·10^5, |aᵢ| ≤ 10^9, 1 ≤ K ≤ 10^15

### Sample Input
```text
5 167
84 -37 32 40 95
```

### Sample Output
```text
3
```

### Sample Explanation
32 + 40 + 95 = 167.

### Target
O(n).

### Hints
1. With prefix sums P, we want the largest i < j with P[j] − P[i] ≥ K.
2. Keep a deque of indices with increasing P; pop the front while it satisfies the condition (it cannot do better later).
3. Pop the back while P[back] ≥ P[j] (a later, smaller prefix is always a better start).

### Approach
Monotonic deque over prefix sums.

### Solution
```cpp
#include <deque>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    long long k;
    cin >> n >> k;
    vector<long long> p(n + 1, 0);
    for (int i = 0; i < n; ++i) { long long x; cin >> x; p[i + 1] = p[i] + x; }
    deque<int> d;
    int best = -1;
    for (int j = 0; j <= n; ++j) {
        while (!d.empty() && p[j] - p[d.front()] >= k) {
            int len = j - d.front();
            if (best == -1 || len < best) best = len;
            d.pop_front();
        }
        while (!d.empty() && p[d.back()] >= p[j]) d.pop_back();
        d.push_back(j);
    }
    cout << best << '\n';
}
```

### Explanation
Both pops are justified by dominance arguments, and each index enters and leaves once: O(n). A plain sliding window fails with negative values.

### Edge Cases
- No valid subarray.

### Tests
#### Impossible
```text
2 4
1 2
```
```text
-1
```

#### With negative
```text
3 3
2 -1 2
```
```text
3
```

**Difficulty:** Hard · **Subtopic:** Priority queue from queues · **Tags:** priority queue, queue, scheduling · **Source:** Original

Jobs have priorities 1 to 10 (10 is highest). `add name p` adds a job; `next` prints the job to run (highest priority, FIFO among equals) or `IDLE`; `count` prints the number of waiting jobs.

### Input
q, then q operations.

### Output
One line per `next` and `count`.

### Constraints
- 1 ≤ q ≤ 2·10^5

### Sample Input
```text
6
add backup 2
add email 7
add report 7
next
next
next
```

### Sample Output
```text
email
report
backup
```

### Sample Explanation
Priority 7 first, in arrival order.

### Target
O(10) per operation.

### Hints
1. With few priority levels, one FIFO queue per level beats a heap.
2. `next` scans levels from 10 down to 1.

### Approach
Array of 11 queues.

### Solution
```cpp
#include <iostream>
#include <queue>
#include <string>
using namespace std;

int main() {
    int q;
    cin >> q;
    queue<string> level[11];
    long long waiting = 0;
    while (q--) {
        string op;
        cin >> op;
        if (op == "add") { string name; int p; cin >> name >> p; level[p].push(name); ++waiting; }
        else if (op == "count") cout << waiting << '\n';
        else {
            bool found = false;
            for (int p = 10; p >= 1 && !found; --p)
                if (!level[p].empty()) { cout << level[p].front() << '\n'; level[p].pop(); --waiting; found = true; }
            if (!found) cout << "IDLE\n";
        }
    }
}
```

### Explanation
This bucket structure implements the Priority Queue ADT in O(levels) with stable FIFO ties, which a binary heap does not guarantee.

### Edge Cases
- `next` with nothing waiting.

### Tests
#### Idle
```text
2
next
count
```
```text
IDLE
0
```

## DSA10-H03 · Circular Tour
**Difficulty:** Hard · **Subtopic:** Circular route reasoning · **Tags:** greedy, circular array, queue · **Source:** Original

### Statement
A bus visits n stations in a circle. Station i provides gas[i] fuel, and driving to the next station costs cost[i]. Print the smallest starting station from which the bus completes the circle with a tank starting empty, or −1.

### Input
n, then gas, then cost.

### Output
The start index or −1.

### Constraints
- 1 ≤ n ≤ 2·10^5, 0 ≤ values ≤ 10^9

### Sample Input
```text
5
1 2 3 4 5
3 4 5 1 2
```

### Sample Output
```text
3
```

### Sample Explanation
From 3: 4−1, +5−2, +1−3, +2−4, +3−5 never goes negative.

### Target
O(n).

### Hints
1. If the total gas is less than the total cost, it is impossible.
2. If the tank goes negative at station j starting from s, no station between s and j can be the start: restart at j + 1.

### Approach
Single pass with a running tank and a candidate start.

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> gas(n), cost(n);
    for (auto& g : gas) cin >> g;
    for (auto& c : cost) cin >> c;
    long long total = 0, tank = 0;
    int start = 0;
    for (int i = 0; i < n; ++i) {
        total += gas[i] - cost[i];
        tank += gas[i] - cost[i];
        if (tank < 0) { start = i + 1; tank = 0; }
    }
    cout << (total < 0 ? -1 : start) << '\n';
}
```

### Explanation
A failed run from s to j proves every start in [s, j] fails, so each station is examined once. If the total is non-negative, the last candidate succeeds.

### Edge Cases
- n = 1.

### Tests
#### Impossible
```text
3
2 3 4
3 4 3
```
```text
-1
```

## DSA10-H04 · Queue with Minimum
**Difficulty:** Hard · **Subtopic:** Queue from two min-stacks · **Tags:** queue, stack, amortised analysis · **Source:** Original

### Statement
Implement a queue supporting `push x`, `pop` (print value or `EMPTY`) and `min` (print the minimum or `EMPTY`) in amortised O(1).

### Input
q, then q operations.

### Output
One line per pop and min.

### Constraints
- 1 ≤ q ≤ 2·10^5

### Sample Input
```text
6
push 5
push 2
push 7
min
pop
pop
```

### Sample Output
```text
2
5
2
```

### Sample Explanation
After popping 5 and 2, only 7 remains.

### Target
O(1) amortised.

### Hints
1. Build the queue from two stacks (DSA02-M01).
2. Each stack stores its running minimum (DSA02-M02); the queue minimum is the smaller of the two.

### Approach
Two stacks of (value, min-so-far).

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

using Stack = vector<pair<long long, long long>>;      // (value, minimum up to here)

void push(Stack& s, long long x) { s.push_back({x, s.empty() ? x : min(x, s.back().second)}); }

int main() {
    int q;
    cin >> q;
    Stack in, out;
    while (q--) {
        string op;
        cin >> op;
        if (op == "push") { long long x; cin >> x; push(in, x); continue; }
        if (in.empty() && out.empty()) { cout << "EMPTY\n"; continue; }
        if (op == "min") {
            long long m = in.empty() ? out.back().second : out.empty() ? in.back().second : min(in.back().second, out.back().second);
            cout << m << '\n';
        } else {
            if (out.empty()) while (!in.empty()) { push(out, in.back().first); in.pop_back(); }
            cout << out.back().first << '\n';
            out.pop_back();
        }
    }
}
```

### Explanation
Each element moves from `in` to `out` at most once, and both stacks keep their minima valid, so all operations are amortised O(1).

### Edge Cases
- Operations on an empty queue.

### Tests
#### Empty
```text
2
min
pop
```
```text
EMPTY
```

## DSA10-H05 · Task Scheduler with Cooldown
**Difficulty:** Hard · **Subtopic:** Priority queue plus waiting queue · **Tags:** priority queue, queue, greedy, simulation · **Source:** Original

### Statement
Tasks are capital letters, each taking one unit of time. The same task must be separated by at least c other units (tasks or idle). Print the minimum total time to run all tasks.

### Input
A string of tasks, then c.

### Output
The minimum time.

### Constraints
- 1 ≤ length ≤ 10^5, 0 ≤ c ≤ 100

### Sample Input
```text
AAABBB 2
```

### Sample Output
```text
8
```

### Sample Explanation
A B idle A B idle A B.

### Target
O(length log 26).

### Hints
1. Always run the available task with the most remaining copies (max-heap).
2. A task that just ran waits in a FIFO queue until its cooldown ends.

### Approach
Max-heap of remaining counts and a queue of (count, ready time).

### Solution
```cpp
#include <iostream>
#include <queue>
#include <string>
#include <utility>
using namespace std;

int main() {
    string tasks;
    long long cooldown;
    cin >> tasks >> cooldown;
    int count[26] = {};
    for (char c : tasks) ++count[c - 'A'];
    priority_queue<int> ready;
    for (int c : count) if (c) ready.push(c);
    queue<pair<int, long long>> waiting;          // (remaining, time it becomes ready)
    long long time = 0;
    while (!ready.empty() || !waiting.empty()) {
        ++time;
        if (!ready.empty()) {
            int left = ready.top() - 1;
            ready.pop();
            if (left > 0) waiting.push({left, time + cooldown});
        }
        if (!waiting.empty() && waiting.front().second == time) {
            ready.push(waiting.front().first);
            waiting.pop();
        }
    }
    cout << time << '\n';
}
```

### Explanation
Greedily running the most frequent available task minimises idle slots; the cooldown queue is FIFO because tasks become ready in the order they ran.

### Edge Cases
- c = 0: the length itself.
- One dominant task.
