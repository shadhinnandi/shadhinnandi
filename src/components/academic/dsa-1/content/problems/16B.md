# Merge Sort: Practice Problems

Merging, stability, the n log n recurrence, and divide-and-conquer counting built on the merge step.

## DSA16B-E01 · Merge Sort
**Difficulty:** Easy · **Subtopic:** Top-down merge sort · **Tags:** merge sort, recursion, sorting · **Source:** Original

### Statement
Sort the array with your own merge sort.

### Input
n, then n integers.

### Output
The sorted array.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
7
38 27 43 3 9 82 10
```

### Sample Output
```text
3 9 10 27 38 43 82
```

### Sample Explanation
Sort halves, then merge.

### Target
O(n log n), O(n) buffer.

### Hints
1. Allocate one buffer once and reuse it.
2. On ties take from the left half.

### Approach
Recursive merge sort on [lo, hi).

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<long long> a, buf;

void sortRange(int lo, int hi) {
    if (hi - lo < 2) return;
    int mid = lo + (hi - lo) / 2;
    sortRange(lo, mid);
    sortRange(mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) buf[k++] = (a[j] < a[i]) ? a[j++] : a[i++];
    while (i < mid) buf[k++] = a[i++];
    while (j < hi) buf[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buf[k];
}

int main() {
    int n;
    cin >> n;
    a.resize(n);
    buf.resize(n);
    for (auto& x : a) cin >> x;
    sortRange(0, n);
    for (int i = 0; i < n; ++i) cout << a[i] << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
T(n) = 2T(n/2) + Θ(n) = Θ(n log n) in every case.

### Edge Cases
- n = 1; duplicates.

### Tests
#### Reversed
```text
4
4 3 2 1
```
```text
1 2 3 4
```

## DSA16B-E02 · Counting Comparisons
**Difficulty:** Easy · **Subtopic:** Cost of merging · **Tags:** merge sort, counting, analysis · **Source:** Original

### Statement
Run top-down merge sort (split at n/2) and print the number of element comparisons made while merging.

### Input
n, then n integers.

### Output
The comparison count.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
8
5 2 4 7 1 3 2 6
```

### Sample Output
```text
17
```

### Sample Explanation
Merging two lists of total length m uses at most m − 1 comparisons.

### Target
O(n log n).

### Hints
1. Count one comparison per iteration of the main merge loop.
2. Copying leftovers costs no comparisons.

### Approach
Merge sort with a counter.

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<long long> a, buf;
long long comparisons = 0;

void sortRange(int lo, int hi) {
    if (hi - lo < 2) return;
    int mid = lo + (hi - lo) / 2;
    sortRange(lo, mid);
    sortRange(mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) { ++comparisons; buf[k++] = (a[j] < a[i]) ? a[j++] : a[i++]; }
    while (i < mid) buf[k++] = a[i++];
    while (j < hi) buf[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buf[k];
}

int main() {
    int n;
    cin >> n;
    a.resize(n);
    buf.resize(n);
    for (auto& x : a) cin >> x;
    sortRange(0, n);
    cout << comparisons << '\n';
}
```

### Explanation
The count lies between (n/2)·log₂ n (best) and about n log₂ n (worst): always Θ(n log n).

### Edge Cases
- Sorted input still needs comparisons.

### Tests
#### Sorted
```text
4
1 2 3 4
```
```text
4
```

## DSA16B-E03 · Stable Ranking
**Difficulty:** Easy · **Subtopic:** Stability · **Tags:** merge sort, stability, records · **Source:** Original

### Statement
Sort students by score in descending order with merge sort; students with equal scores keep their input order. Print the names.

### Input
n, then n lines name score.

### Output
Names in ranking order.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
ana 80
bo 90
cy 80
di 90
```

### Sample Output
```text
bo di ana cy
```

### Sample Explanation
bo came before di, and ana before cy.

### Target
O(n log n).

### Hints
1. Take from the left half unless the right element is strictly better.
2. That tie rule is exactly what makes merge sort stable.

### Approach
Merge sort on records with a descending key.

### Solution
```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

using Rec = pair<string, long long>;
vector<Rec> a, buf;

void sortRange(int lo, int hi) {
    if (hi - lo < 2) return;
    int mid = lo + (hi - lo) / 2;
    sortRange(lo, mid);
    sortRange(mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) buf[k++] = (a[j].second > a[i].second) ? a[j++] : a[i++];   // strictly better only
    while (i < mid) buf[k++] = a[i++];
    while (j < hi) buf[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buf[k];
}

int main() {
    int n;
    cin >> n;
    a.resize(n);
    buf.resize(n);
    for (auto& [name, score] : a) cin >> name >> score;
    sortRange(0, n);
    for (int i = 0; i < n; ++i) cout << a[i].first << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
Equal keys are always taken from the left half first, so their relative order never changes.

### Edge Cases
- All scores equal: input order.

### Tests
#### All equal
```text
3
x 1
y 1
z 1
```
```text
x y z
```

## DSA16B-E04 · Bottom-Up Passes
**Difficulty:** Easy · **Subtopic:** Iterative merge sort · **Tags:** merge sort, iteration, tracing · **Source:** Original

### Statement
Run bottom-up merge sort (merge runs of width 1, then 2, 4, …) and print the array after each pass.

### Input
n, then n integers.

### Output
One line per pass.

### Constraints
- 2 ≤ n ≤ 1000

### Sample Input
```text
6
5 2 4 7 1 3
```

### Sample Output
```text
2 5 4 7 1 3
2 4 5 7 1 3
1 2 3 4 5 7
```

### Sample Explanation
Widths 1, 2 and 4.

### Target
O(n log n), no recursion.

### Hints
1. For width w, merge [lo, lo+w) with [lo+w, lo+2w) for lo = 0, 2w, 4w, …
2. The last block may be shorter.

### Approach
Iterative passes with `std::inplace_merge`.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    for (int w = 1; w < n; w *= 2) {
        for (int lo = 0; lo + w < n; lo += 2 * w)
            inplace_merge(a.begin() + lo, a.begin() + lo + w, a.begin() + min(lo + 2 * w, n));
        for (int i = 0; i < n; ++i) cout << a[i] << (i + 1 < n ? ' ' : '\n');
    }
}
```

### Explanation
⌈log₂ n⌉ passes, each linear: the same Θ(n log n) without a recursion stack.

### Edge Cases
- n not a power of two.

### Tests
#### Two
```text
2
2 1
```
```text
1 2
```

## DSA16B-E05 · Recursion Shape
**Difficulty:** Easy · **Subtopic:** Recursion tree · **Tags:** merge sort, recursion tree, analysis · **Source:** Original

### Statement
For merge sort on n elements (split at ⌊n/2⌋, stop at size 1), print the recursion depth (levels of merging) and the number of merge operations.

### Input
T, then T values of n.

### Output
Depth and merges for each n.

### Constraints
- 1 ≤ n ≤ 10^18

### Sample Input
```text
3
8
5
1
```

### Sample Output
```text
3 7
3 4
0 0
```

### Sample Explanation
n leaves need n − 1 merges; the depth is ⌈log₂ n⌉.

### Target
O(log n).

### Hints
1. Every merge joins two pieces into one: n pieces need n − 1 merges.
2. The largest piece halves (rounded up) at each level.

### Approach
Count halvings of the larger half.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        unsigned long long n;
        cin >> n;
        int depth = 0;
        for (unsigned long long s = n; s > 1; s = (s + 1) / 2) ++depth;   // ceil(log2 n)
        cout << depth << ' ' << n - 1 << '\n';
    }
}
```

### Explanation
The recursion tree is a full binary tree with n leaves and n − 1 internal nodes (merges), of height ⌈log₂ n⌉.

### Edge Cases
- n = 1: nothing to merge.

### Tests
#### Power of two
```text
1
1024
```
```text
10 1023
```

## DSA16B-M01 · Two-Key Ordering by Stable Passes
**Difficulty:** Medium · **Subtopic:** Stability for multi-key sorting · **Tags:** merge sort, stability, records · **Source:** Original

### Statement
Sort students by grade descending, then by name ascending, using two passes of a stable merge sort: first by name, then by grade.

### Input
n, then n lines name grade.

### Output
Names in final order.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
dan 3
amy 4
cat 3
bob 4
```

### Sample Output
```text
amy bob cat dan
```

### Sample Explanation
Grade 4: amy, bob; grade 3: cat, dan.

### Target
O(n log n).

### Hints
1. Sort by the least important key first.
2. A stable sort by the main key keeps the earlier order among ties.

### Approach
Generic stable merge sort with a comparator, applied twice.

### Solution
```cpp
#include <functional>
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

using Rec = pair<string, int>;

void mergeSort(vector<Rec>& a, vector<Rec>& buf, int lo, int hi, const function<bool(const Rec&, const Rec&)>& before) {
    if (hi - lo < 2) return;
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, buf, lo, mid, before);
    mergeSort(a, buf, mid, hi, before);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) buf[k++] = before(a[j], a[i]) ? a[j++] : a[i++];
    while (i < mid) buf[k++] = a[i++];
    while (j < hi) buf[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buf[k];
}

int main() {
    int n;
    cin >> n;
    vector<Rec> a(n), buf(n);
    for (auto& [name, g] : a) cin >> name >> g;
    mergeSort(a, buf, 0, n, [](const Rec& x, const Rec& y) { return x.first < y.first; });     // secondary key
    mergeSort(a, buf, 0, n, [](const Rec& x, const Rec& y) { return x.second > y.second; });   // primary key
    for (int i = 0; i < n; ++i) cout << a[i].first << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
This is how spreadsheets sort by several columns, and it is exactly why radix sort needs a stable inner sort.

### Edge Cases
- Equal names and grades.

### Tests
#### One grade
```text
3
c 1
a 1
b 1
```
```text
a b c
```

## DSA16B-M02 · External Sort Planning
**Difficulty:** Medium · **Subtopic:** External merge sort · **Tags:** merge sort, external sorting, analysis · **Source:** Original

### Statement
n records must be sorted with memory for M records. Phase 1 creates ⌈n/M⌉ sorted runs. Each later pass merges up to k runs at once. Print the number of runs and the number of merge passes.

### Input
T, then T lines n M k.

### Output
Runs and passes per line.

### Constraints
- 1 ≤ n, M ≤ 10^18, 2 ≤ k ≤ 10^9

### Sample Input
```text
2
1000000 10000 10
5 10 2
```

### Sample Output
```text
100 2
1 0
```

### Sample Explanation
100 runs → 10 → 1 with fan-in 10: two passes.

### Target
O(log runs).

### Hints
1. Each pass divides the number of runs by k, rounding up.
2. Use integer arithmetic only.

### Approach
Simulate the run count.

### Solution
```cpp
#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        unsigned long long n, m, k;
        cin >> n >> m >> k;
        unsigned long long runs = (n + m - 1) / m;           // n + m <= 2e18: no overflow
        int passes = 0;
        for (unsigned long long r = runs; r > 1; r = (r + k - 1) / k) ++passes;
        cout << runs << ' ' << passes << '\n';
    }
}
```

### Explanation
Databases sort data larger than memory this way; the number of passes, ⌈log_k(runs)⌉, determines the disk I/O.

### Edge Cases
- Everything fits in memory: 0 passes.

### Tests
#### Binary merging
```text
1
8 1 2
```
```text
8 3
```

## DSA16B-M03 · Sorted Union
**Difficulty:** Medium · **Subtopic:** Merge with deduplication · **Tags:** merging, sets, two pointers · **Source:** Original

### Statement
Two sorted arrays may contain repeats. Print their sorted union without duplicates.

### Input
n and A; m and B.

### Output
The union.

### Constraints
- 1 ≤ n, m ≤ 2·10^5

### Sample Input
```text
4
1 2 2 5
3
2 3 5
```

### Sample Output
```text
1 2 3 5
```

### Sample Explanation
Each value once.

### Target
O(n + m).

### Hints
1. Merge as usual.
2. Skip a value equal to the last one written.

### Approach
Merge with a "last written" check.

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, m;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    cin >> m;
    vector<long long> b(m);
    for (auto& x : b) cin >> x;
    vector<long long> out;
    int i = 0, j = 0;
    while (i < n || j < m) {
        long long v = (j == m || (i < n && a[i] <= b[j])) ? a[i++] : b[j++];
        if (out.empty() || out.back() != v) out.push_back(v);
    }
    for (size_t k = 0; k < out.size(); ++k) cout << out[k] << (k + 1 < out.size() ? ' ' : '\n');
}
```

### Explanation
The merge order guarantees equal values are adjacent in the output, so one comparison removes duplicates.

### Edge Cases
- Identical arrays.

### Tests
#### Identical
```text
2
1 1
2
1 1
```
```text

```

## DSA16B-M04 · Merge Overlapping Intervals
**Difficulty:** Medium · **Subtopic:** Sorting then a linear merge · **Tags:** sorting, intervals, merging · **Source:** Original

### Statement
Merge overlapping or touching closed intervals [l, r] and print the result sorted.

### Input
n, then n lines l r.

### Output
One merged interval per line.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
1 3
8 10
2 6
15 18
```

### Sample Output
```text
1 6
8 10
15 18
```

### Sample Explanation
[1,3] and [2,6] overlap.

### Target
O(n log n).

### Hints
1. Sort by start.
2. Extend the current interval while the next start ≤ current end.

### Approach
Sort then sweep.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<pair<long long, long long>> v(n);
    for (auto& [l, r] : v) cin >> l >> r;
    sort(v.begin(), v.end());
    vector<pair<long long, long long>> out;
    for (auto [l, r] : v) {
        if (!out.empty() && l <= out.back().second) out.back().second = max(out.back().second, r);
        else out.push_back({l, r});
    }
    for (auto [l, r] : out) cout << l << ' ' << r << '\n';
}
```

### Explanation
After sorting, overlapping intervals are contiguous, so one pass merges them.

### Edge Cases
- Touching intervals [1,2] and [2,3].

### Tests
#### Touching
```text
2
1 2
2 3
```


## DSA16B-M05 · Natural Runs
**Difficulty:** Medium · **Subtopic:** Natural merge sort · **Tags:** merge sort, runs, analysis · **Source:** Original

### Statement
A run is a maximal non-decreasing block. Print the number of runs and the number of merge passes that natural merge sort needs (each pass merges runs in pairs).

### Input
n, then n integers.

### Output
Runs and passes.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
7
1 3 5 2 4 0 6
```

### Sample Output
```text
3 2
```

### Sample Explanation
Runs [1 3 5], [2 4], [0 6]: 3 → 2 → 1 runs.

### Target
O(n).

### Hints
1. A new run starts whenever a[i] < a[i − 1].
2. Each pass halves the run count (rounding up).

### Approach
Count descents, then simulate halvings.

### Solution
```cpp
#include <iostream>

int main() {
```

## DSA16B-H01 · Smaller Elements to the Right
**Difficulty:** Hard · **Subtopic:** Merge sort with indices · **Tags:** merge sort, counting, divide and conquer · **Source:** Original

### Statement
For each position, print how many later elements are strictly smaller.

### Input
n, then n integers.

### Output
n counts.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
5 2 6 1
```

### Sample Output
```text
2 1 1 0
```

### Sample Explanation
After 5 come 2 and 1.

### Target
O(n log n).

### Hints
1. Sort indices by value with merge sort.
2. When a left element is placed, every right element already placed is smaller and was to its right.

### Approach
Merge sort over indices; count right-half elements taken before each left element.

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<long long> a, cnt;
vector<int> idx, buf;

void solve(int lo, int hi) {
    if (hi - lo < 2) return;
    int mid = lo + (hi - lo) / 2;
    solve(lo, mid);
    solve(mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid || j < hi) {
        if (j == hi || (i < mid && a[idx[i]] <= a[idx[j]])) {
            cnt[idx[i]] += j - mid;              // right elements already placed are smaller
            buf[k++] = idx[i++];
        } else {
            buf[k++] = idx[j++];
        }
    }
    for (k = lo; k < hi; ++k) idx[k] = buf[k];
}

int main() {
    int n;
    cin >> n;
    a.resize(n);
    cnt.assign(n, 0);
    idx.resize(n);
    buf.resize(n);
    for (int i = 0; i < n; ++i) { cin >> a[i]; idx[i] = i; }
    solve(0, n);
    for (int i = 0; i < n; ++i) cout << cnt[i] << (i + 1 < n ? ' ' : '\n');
}
```

### Explanation
Taking left elements first on ties ensures equal values are not counted as smaller.

### Edge Cases
- Equal values; sorted input (all zeros).

### Tests
#### Equal values
```text
3
2 2 2
```
```text
0 0 0
```

## DSA16B-H02 · Range Sum Count
**Difficulty:** Hard · **Subtopic:** Merge sort on prefix sums · **Tags:** merge sort, prefix sums, counting · **Source:** Original

### Statement
Count subarrays whose sum lies in [L, R].

### Input
n, L and R, then n integers.

### Output
The count.

### Constraints
- 1 ≤ n ≤ 10^5, |values| ≤ 10^9, |L|, |R| ≤ 10^15, L ≤ R

### Sample Input
```text
3 -2 2
-2 5 -1
```

### Sample Output
```text
3
```

### Sample Explanation
[−2], [−1] and [−2, 5, −1] have sums in range.

### Target
O(n log n).

### Hints
1. Subarray sums are differences P[j] − P[i] of prefix sums with i < j.
2. While merge-sorting prefix sums, for each left P[i] count right P[j] with P[i] + L ≤ P[j] ≤ P[i] + R using two moving pointers.

### Approach
Divide and conquer over the prefix array.

### Solution
```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

vector<long long> p;
long long L, R;

long long solve(int lo, int hi) {                        // p[lo, hi)
    if (hi - lo < 2) return 0;
    int mid = lo + (hi - lo) / 2;
    long long count = solve(lo, mid) + solve(mid, hi);
    int a = mid, b = mid;
    for (int i = lo; i < mid; ++i) {                     // both halves sorted
        while (a < hi && p[a] - p[i] < L) ++a;
        while (b < hi && p[b] - p[i] <= R) ++b;
        count += b - a;
    }
    inplace_merge(p.begin() + lo, p.begin() + mid, p.begin() + hi);
    return count;
}

int main() {
    int n;
    cin >> n >> L >> R;
    p.assign(n + 1, 0);
    for (int i = 0; i < n; ++i) { long long x; cin >> x; p[i + 1] = p[i] + x; }
    cout << solve(0, n + 1) << '\n';
}
```

### Explanation
Sorting each half does not change which pairs cross the middle (all left indices precede all right ones), and the window pointers only move forward: Θ(n log n).

### Edge Cases
- Every subarray in range: n(n+1)/2.

### Tests
#### All in range
```text
2 0 10
1 1
```
```text
3
```

## DSA16B-H03 · Ranking Disagreement
**Difficulty:** Hard · **Subtopic:** Inversions between rankings · **Tags:** merge sort, inversions, permutations · **Source:** Original

### Statement
Two judges rank the same n contestants (two permutations of 1..n). Print the number of pairs the judges order differently (the Kendall tau distance).

### Input
n, ranking p, ranking q.

### Output
The number of disagreeing pairs.

### Constraints
- 1 ≤ n ≤ 2·10^5

### Sample Input
```text
4
1 2 3 4
2 1 4 3
```

### Sample Output
```text
2
```

### Sample Explanation
(1,2) and (3,4) are swapped.

### Target
O(n log n).

### Hints
1. Replace each contestant in p by its position in q.
2. Disagreements are inversions of that sequence.

### Approach
Relabel, then merge-sort inversion counting.

### Solution
```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<int> a, buf;

long long inversions(int lo, int hi) {
    if (hi - lo < 2) return 0;
    int mid = lo + (hi - lo) / 2;
    long long inv = inversions(lo, mid) + inversions(mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) {
        if (a[j] < a[i]) { inv += mid - i; buf[k++] = a[j++]; }
        else buf[k++] = a[i++];
    }
    while (i < mid) buf[k++] = a[i++];
    while (j < hi) buf[k++] = a[j++];
    for (k = lo; k < hi; ++k) a[k] = buf[k];
    return inv;
}

int main() {
    int n;
    cin >> n;
    vector<int> p(n), posQ(n + 1);
    for (auto& x : p) cin >> x;
    for (int i = 0; i < n; ++i) { int x; cin >> x; posQ[x] = i; }
    a.resize(n);
    buf.resize(n);
    for (int i = 0; i < n; ++i) a[i] = posQ[p[i]];
    cout << inversions(0, n) << '\n';
}
```

### Explanation
A pair disagrees exactly when the q-positions appear in decreasing order in p's order.

### Edge Cases
- Identical rankings: 0; reversed: n(n−1)/2.

## DSA16B-H04 · Median of Two Sorted Arrays
**Difficulty:** Hard · **Subtopic:** Merging without merging · **Tags:** binary search, sorted arrays, divide and conquer · **Source:** Original

### Statement
Print the lower median (the ⌈(n+m)/2⌉-th smallest) of the union of two sorted arrays in O(log(min(n, m))).

### Input
n and A; m and B.

### Output
The lower median.

### Constraints
- 1 ≤ n, m ≤ 2·10^5

### Sample Input
```text
2
1 3
2
2 4
```

### Sample Output
```text
2
```

### Sample Explanation
Union 1 2 3 4; the 2nd smallest is 2.

### Target
O(log min(n, m)).

### Hints
1. Choose i elements from A and k − i from B for the left part, k = ⌈(n+m)/2⌉.
2. Binary search i so that A[i−1] ≤ B[k−i] and B[k−i−1] ≤ A[i]; the answer is the larger left-side maximum.

### Approach
Partition binary search on the shorter array.

### Solution
```cpp
#include <algorithm>
#include <climits>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, m;
    cin >> n;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    cin >> m;
    vector<long long> b(m);
    for (auto& x : b) cin >> x;
    if (n > m) { swap(a, b); swap(n, m); }
    int k = (n + m + 1) / 2;
    int lo = max(0, k - m), hi = min(n, k);
    while (lo <= hi) {
        int i = lo + (hi - lo) / 2, j = k - i;
        long long aLeft = i > 0 ? a[i - 1] : LLONG_MIN, aRight = i < n ? a[i] : LLONG_MAX;
        long long bLeft = j > 0 ? b[j - 1] : LLONG_MIN, bRight = j < m ? b[j] : LLONG_MAX;
        if (aLeft > bRight) hi = i - 1;
        else if (bLeft > aRight) lo = i + 1;
        else { cout << max(aLeft, bLeft) << '\n'; return 0; }
    }
}
```

### Explanation
The left part must contain exactly the k smallest elements; the two cross conditions certify that, and they change monotonically with i.

### Edge Cases
- One array entirely smaller than the other.

### Tests
#### Disjoint ranges
```text
1
10
3
1 2 3
```
```text
2
```

## DSA16B-H05 · Sorting with Limited Memory
**Difficulty:** Hard · **Subtopic:** Run generation and k-way merge · **Tags:** merge sort, heap, external sorting · **Source:** Original

### Statement
Simulate external sorting: split the input into runs of M elements, sort each run, then merge all runs with a min-heap. Print the number of runs, then the sorted data.

### Input
n and M, then n integers.

### Output
The run count, then the sorted array.

### Constraints
- 1 ≤ n ≤ 2·10^5, 1 ≤ M ≤ n

### Sample Input
```text
7 3
9 4 7 1 8 2 5
```

### Sample Output
```text
3
1 2 4 5 7 8 9
```

### Sample Explanation
Runs [4 7 9], [1 2 8], [5].

### Target
O(n log M + n log(n/M)).

### Hints
1. Sort each block of M with any O(M log M) sort.
2. Merge with a heap of run heads.

### Approach
Run generation then a heap merge.

### Solution
```cpp
#include <algorithm>
#include <functional>
#include <iostream>
#include <queue>
#include <tuple>
#include <vector>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<long long> a(n);
    for (auto& x : a) cin >> x;
    vector<vector<long long>> runs;
    for (int lo = 0; lo < n; lo += m) {
        vector<long long> run(a.begin() + lo, a.begin() + min(n, lo + m));
        sort(run.begin(), run.end());                           // fits "in memory"
        runs.push_back(run);
    }
    using T = tuple<long long, int, int>;
    priority_queue<T, vector<T>, greater<T>> heap;
    for (int r = 0; r < static_cast<int>(runs.size()); ++r) heap.emplace(runs[r][0], r, 0);
    cout << runs.size() << '\n';
    int printed = 0;
    while (!heap.empty()) {
        auto [v, r, i] = heap.top();
        heap.pop();
        cout << v << (++printed < n ? ' ' : '\n');
        if (i + 1 < static_cast<int>(runs[r].size())) heap.emplace(runs[r][i + 1], r, i + 1);
    }
}
```

### Explanation
Only one element per run needs to be in memory during merging, which is why this scales to data far larger than RAM.

### Edge Cases
- M = n: one run.

### Tests
#### One run
```text
3 3
3 1 2
```
```text
1
1 2 3
```
