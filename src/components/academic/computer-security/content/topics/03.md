# Symmetric and Asymmetric Cryptography

## Basic terms

- **Plaintext (M)**: the original readable message.
- **Ciphertext (C)**: the scrambled message after encryption.
- **Key**: the secret value that controls encryption and decryption.
- **Encryption**: plaintext to ciphertext. **Decryption**: ciphertext to plaintext.

## Symmetric cryptography (secret key)

The sender and receiver use the **same secret key** to encrypt and decrypt.

```text
          shared key K                       shared key K
               |                                  |
Plaintext --> [Encrypt] --> Ciphertext --> [Decrypt] --> Plaintext
```

- **Examples:** AES, DES, 3DES, RC4.
- **Strength:** very fast, good for large amounts of data.
- **Problem:** both sides must already share the key secretly (key distribution problem). With n users, every pair needs its own key: n(n − 1)/2 keys.

## Asymmetric cryptography (public key)

Each user has a **key pair**: a **public key** that everyone may know and a **private key** that only the owner keeps.

- Encrypt with the receiver's **public key**; only the receiver's **private key** can decrypt.
- Sign with the sender's **private key**; anyone can verify with the sender's **public key**.

```text
          Bob's public key                  Bob's private key
               |                                  |
Plaintext --> [Encrypt] --> Ciphertext --> [Decrypt] --> Plaintext
```

- **Examples:** RSA, Diffie-Hellman (key exchange), ElGamal, ECC.
- **Strength:** no need to share a secret in advance; gives digital signatures and non-repudiation.
- **Problem:** much slower; keys are longer; we must trust that a public key really belongs to its owner (solved by a Certification Authority).

## Comparison

| Point | Symmetric | Asymmetric |
|---|---|---|
| Keys | One shared secret key | Public and private key pair |
| Speed | Fast | Slow |
| Key sharing | Key must be sent secretly | Public key can be sent openly |
| Keys for n users | n(n − 1)/2 | 2n (one pair each) |
| Main use | Encrypting bulk data | Key exchange, digital signatures |
| Non-repudiation | No (both sides have the same key) | Yes (only the owner has the private key) |
| Examples | AES, DES | RSA, Diffie-Hellman |

**In practice both are used together (hybrid):** asymmetric cryptography (RSA or Diffie-Hellman) safely sets up a session key, then symmetric cryptography (AES) encrypts the actual data. HTTPS works this way.

## Exam-ready answers

**Q. Compare symmetric and asymmetric cryptography with example. (4 marks)**

| Symmetric | Asymmetric |
|---|---|
| Uses one shared secret key for both encryption and decryption. | Uses a public key to encrypt and a private key to decrypt. |
| Fast, suitable for large data. | Slow, used for small data such as keys and signatures. |
| The key must be shared secretly in advance (key distribution problem). | The public key can be shared openly. |
| Cannot give non-repudiation. | Gives digital signatures and non-repudiation. |
| Example: AES, DES. | Example: RSA, Diffie-Hellman. |

Example: in HTTPS, the browser and server use RSA or Diffie-Hellman (asymmetric) to agree on a session key, then encrypt the web traffic with AES (symmetric).
