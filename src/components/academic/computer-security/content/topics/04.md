# RSA Algorithm

## What is RSA?

**RSA** (Rivest, Shamir, Adleman) is an **asymmetric** algorithm. Each user has a public key **(e, n)** that anyone can use to encrypt, and a private key **d** that only the owner uses to decrypt.

RSA is secure because it is easy to multiply two large primes p × q = n, but very hard to find p and q again from n. Without p and q, the attacker cannot compute z or d.

## Key generation (done by the receiver)

1. Choose two prime numbers **p** and **q**.
2. Compute **n = p × q**.
3. Compute **z = (p − 1)(q − 1)**. (Some books call this φ(n).)
4. Choose **e** such that 1 < e < z and e has no common factor with z (gcd(e, z) = 1).
5. Compute **d = e<sup>−1</sup> mod z**, so that (e × d) mod z = 1.
6. Public key = **(e, n)**. Private key = **d** (keep p, q and z secret too).

**Choosing the smallest e:** try e = 2, 3, 5, 7, ... and take the first one with no common factor with z. Since z is always even, e = 2 never works.

## Encryption and decryption

```calc
# Encryption (sender, with the receiver's public key)
C = M^{e} mod n
# Decryption (receiver, with the private key d)
M = C^{d} mod n
```

The message must be smaller than n (M < n).

```seq
Receiver | Sender
Receiver: chooses p, q, e; n = p × q; z = (p − 1)(q − 1); d = e^{−1} mod z
Receiver -> Sender: public key (e, n)
Sender: C = M^{e} mod n
Sender -> Receiver: ciphertext C
Receiver: M = C^{d} mod n
```

## Worked example 1: message exchange

**Boshir wants to send M = 4 to Anis. Anis has a public key (e, n) with p = 3, q = 11, e = 3. Show the message exchange using RSA.**

```seq
Anis | Boshir
Anis: p = 3, q = 11, e = 3; n = 33, z = 20, d = 7
Anis -> Boshir: public key (e, n) = (3, 33)
Boshir: C = 4^{3} mod 33 = 31
Boshir -> Anis: C = 31
Anis: M = 31^{7} mod 33 = 4
```

**Given values**

```calc
M = 4
n = p × q = 3 × 11 = 33
z = (p − 1)(q − 1) = 2 × 10 = 20
e = 3
```

**At Boshir's side: encrypt M into C**

```calc
C = M^{e} mod n
  = 4^{3} mod 33
  = 64 mod 33
  = 31
∴ C = 31
```

**At Anis's side: find the private key d**

```calc
d = e^{−1} mod z
  = 3^{−1} mod 20
  = (1 + 20 × k) / 3 mod 20
  = (1 + 20 × 1) / 3 mod 20   [k = 1]
  = 21 / 3 mod 20
  = 7
∴ d = 7
```

**At Anis's side: decrypt C into M**

```calc
M = C^{d} mod n
  = 31^{7} mod 33
  = (31^{2} mod 33)^{3} × 31 mod 33
  = 4^{3} × 31 mod 33   [961 mod 33 = 4]
  = 64 × 31 mod 33
  = 1984 mod 33
  = 4
∴ M = 4
```

Anis gets back M = 4, so the decryption is correct.

## Worked example 2: man-in-the-middle on RSA

**Sharif, Rubel and an adversary Zandra use RSA:**

| | Sharif | Rubel | Zandra |
|---|---|---|---|
| Message M | 11 | 8 | 3 |
| Primes (p, q) | (3, 11) | (7, 11) | (5, 7) |
| Public key e | 13 | 19 | 11 |

Sharif wants to talk to Rubel, but Zandra takes over the channel. Zandra sends Sharif **his own** public key, pretending to be Rubel. Sharif sends M = 11 to Zandra, and Zandra replies with M = 3. Zandra discards everything Rubel sends. Calculate all ciphertexts and decrypted messages, and show the exchange.

```seq
Sharif | Zandra | Rubel
Zandra -> Sharif: (e_Z, n_Z) = (11, 35), posing as Rubel
Sharif -> Zandra: (e_S, n_S) = (13, 33)
Sharif: C_S = 11^{11} mod 35 = 16
Sharif -> Zandra: C_S = 16
Zandra: M_S = 16^{11} mod 35 = 11
Zandra: C_Z = 3^{13} mod 33 = 27
Zandra -> Sharif: C_Z = 27
Sharif: M_Z = 27^{17} mod 33 = 3
Rubel -> Zandra: messages for Sharif (discarded)
```

**Key values**

```calc
# Zandra
n_Z = p_Z × q_Z = 5 × 7 = 35
z_Z = (p_Z − 1)(q_Z − 1) = 4 × 6 = 24
e_Z = 11
# Sharif
n_S = p_S × q_S = 3 × 11 = 33
z_S = (p_S − 1)(q_S − 1) = 2 × 10 = 20
e_S = 13
```

**Step 1: Sharif encrypts M<sub>S</sub> = 11 with Zandra's public key**

```calc
C_S = M_S^{e_Z} mod n_Z
    = 11^{11} mod 35
    = (11^{5} mod 35)^{2} × 11 mod 35
    = 16^{2} × 11 mod 35   [11^{5} = 161051, 161051 mod 35 = 16]
    = 256 mod 35 × 11 mod 35
    = 11 × 11 mod 35   [256 mod 35 = 11]
    = 121 mod 35
    = 16
∴ C_S = 16
```

**Step 2: Zandra finds her private key and decrypts**

```calc
d_Z = e_Z^{−1} mod z_Z
    = 11^{−1} mod 24
    = (1 + 24 × k) / 11 mod 24
    = (1 + 24 × 5) / 11 mod 24   [k = 5]
    = 121 / 11 mod 24
    = 11
∴ d_Z = 11
```

```calc
M_S = C_S^{d_Z} mod n_Z
    = 16^{11} mod 35
    = (16^{2} mod 35)^{5} × 16 mod 35
    = 11^{5} × 16 mod 35   [256 mod 35 = 11]
    = 16 × 16 mod 35   [11^{5} mod 35 = 16]
    = 256 mod 35
    = 11
∴ Zandra reads M_S = 11
```

**Step 3: Zandra encrypts her reply M<sub>Z</sub> = 3 with Sharif's public key**

```calc
C_Z = M_Z^{e_S} mod n_S
    = 3^{13} mod 33
    = (3^{2})^{6} × 3 mod 33
    = 9^{6} × 3 mod 33
    = 9 × 3 mod 33   [9^{3} = 729, 729 mod 33 = 3, so 9^{6} mod 33 = 3^{2} = 9]
    = 27
∴ C_Z = 27
```

**Step 4: Sharif finds his private key and decrypts**

```calc
d_S = e_S^{−1} mod z_S
    = 13^{−1} mod 20
    = (1 + 20 × k) / 13 mod 20
    = (1 + 20 × 11) / 13 mod 20   [k = 11]
    = 221 / 13 mod 20
    = 17
∴ d_S = 17
```

```calc
M_Z = C_Z^{d_S} mod n_S
    = 27^{17} mod 33
    = (27^{2} mod 33)^{8} × 27 mod 33
    = 3^{8} × 27 mod 33   [729 mod 33 = 3]
    = 27 × 27 mod 33   [3^{8} = 6561, 6561 mod 33 = 27]
    = 729 mod 33
    = 3
∴ Sharif reads M_Z = 3
```

Sharif believes he is talking to Rubel, but every message goes to Zandra. **Lesson:** RSA alone does not prove whose public key you received. A **Certification Authority** must certify that the key really belongs to Rubel.

## Exam-ready answers

**Q. Write the steps of the RSA algorithm. (4 marks)**

1. Choose two primes p and q; compute n = p × q and z = (p − 1)(q − 1).
2. Choose e with 1 < e < z and gcd(e, z) = 1.
3. Compute the private key d = e<sup>−1</sup> mod z.
4. Public key (e, n) is published; d is kept secret.
5. Encryption: C = M<sup>e</sup> mod n. Decryption: M = C<sup>d</sup> mod n.

Security: finding d needs z, and finding z needs the factors p and q of n, which is very hard for large n.

**Q. Can RSA alone stop a man-in-the-middle? (3 marks)**

No. If an attacker sends you their own public key while pretending to be your friend, you encrypt for the attacker. The attacker decrypts, reads or changes the message, and re-encrypts it for the real receiver. A Certification Authority must sign public keys (digital certificates) so the receiver can check who really owns a key.
