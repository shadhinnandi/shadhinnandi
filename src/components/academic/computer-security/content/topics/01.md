# Security Basics

## The CIA triad

The three main goals of computer security:

| Goal | Meaning | Example of a violation |
|---|---|---|
| **Confidentiality** | Only authorised people can read the data. | An attacker sniffs a password on the network. |
| **Integrity** | Data is not changed without permission, and changes can be detected. | An attacker changes the amount in a bank transfer. |
| **Availability** | The system and data are usable when needed. | A DoS attack or ransomware stops users from reaching the data. |

Two more goals often appear with them:

- **Authenticity**: you can be sure who sent the data.
- **Non-repudiation**: the sender cannot later deny sending it (digital signatures give this).

## Four categories of attack

Every attack on data in transit falls into one of these:

| Category | What the attacker does | Goal attacked | Examples |
|---|---|---|---|
| **Interruption** | Stops data or a service from reaching the user. | Availability | DoS, DDoS, cutting a cable |
| **Interception** | Secretly reads or copies data. | Confidentiality | Sniffing, eavesdropping, MITM listening |
| **Modification** | Changes data on the way. | Integrity | MITM changing a message |
| **Fabrication** | Creates fake data or pretends to be someone else. | Authenticity | IP or MAC spoofing, fake messages |

```text
Normal:        Source  ------------------------------>  Destination
Interruption:  Source  -------X                         Destination
Interception:  Source  ------------------------------>  Destination
                                |
                                +--> Attacker (copy)
Modification:  Source  --> Attacker (changes it) ---->  Destination
Fabrication:              Attacker (fake data) ----->  Destination
```

## Security design principles

These rules (Saltzer and Schroeder) guide how a secure system should be built.

1. **Economy of mechanism**: keep the design simple and small. Complex systems have more hidden bugs and are hard to test.
2. **Fail-safe defaults**: deny access by default; allow only what is clearly permitted.
3. **Complete mediation**: check permission on every access, not only the first time.
4. **Open design**: security must not depend on keeping the design secret. Only the **keys** should be secret. (Kerckhoffs's principle.)
5. **Separation of privilege**: important actions need more than one condition, for example two keys or two people.
6. **Least privilege**: every user and program gets only the rights it needs, nothing more.
7. **Least common mechanism**: share as few resources between users as possible.
8. **Psychological acceptability**: security should be easy to use, or people will avoid it.

**Why secrecy is weak security ("security through obscurity"):** a secret design is never reviewed by experts, so its flaws stay hidden until an attacker finds them. Once the design leaks or is reverse engineered, every system using it is broken at once, and it cannot be fixed just by changing a key.

## Password strength

If a password has length **L** and every character is chosen from a set of **c** characters:

```calc
Number of passwords = c^{L}
Average guesses = c^{L} / 2   [on average the attacker finds it halfway]
Average time = (c^{L} / 2) × (time per guess)
```

**Worked example.** An 8-character password uses only lowercase letters (26 characters). An attacker tests one password every microsecond (10<sup>−6</sup> s).

```calc
# Number of possible passwords
26^{8} = 208827064576
# Average number of guesses
208827064576 / 2 = 104413532288
# Average time
104413532288 µs = 104413.5 s
                = 104413.5 / 3600 hours
                ≈ 29 hours
∴ Average time ≈ 29 hours
```

So a short lowercase password falls in about a day. Longer passwords and bigger character sets make the number grow very fast, because the length is in the **exponent**.

## Exam-ready answers

**Q. What is the CIA triad? (3 marks)**

The CIA triad is the three basic goals of security:
- **Confidentiality**: data is read only by authorised users (protected by encryption, access control).
- **Integrity**: data is not changed without permission (protected by hashes, digital signatures).
- **Availability**: data and services are ready when needed (protected by backups, redundancy, DoS defence).

**Q. Name the four categories of attack. (4 marks)**

- **Interruption**: the service is stopped (attacks availability), e.g. DoS.
- **Interception**: data is secretly read (attacks confidentiality), e.g. sniffing.
- **Modification**: data is changed in transit (attacks integrity), e.g. MITM.
- **Fabrication**: fake data is inserted or identity is faked (attacks authenticity), e.g. spoofing.

**Q. Why does "open design" give better security than keeping a design secret? (3 marks)**

- In open design only the key is secret, so the system stays safe even if attackers know how it works.
- Public designs are reviewed by many experts, so flaws are found and fixed early.
- A secret design gives false confidence: once it leaks, every system using it is broken and cannot be fixed by changing a key.
