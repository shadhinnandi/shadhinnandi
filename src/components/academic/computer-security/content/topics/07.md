# ARP Spoofing and Man-in-the-Middle

## What is ARP?

**ARP (Address Resolution Protocol)** finds the **MAC address** that belongs to an **IP address** on a local network (LAN). Inside a LAN, frames are delivered by MAC address, so a host must know the MAC address before it can send.

How it works:

1. Host A wants to send to IP B but does not know B's MAC address.
2. A **broadcasts** an ARP request: "Who has IP B? Tell IP A."
3. Host B replies (unicast): "IP B is at MAC 0xB."
4. A stores the pair (IP B, 0xB) in its **ARP table** (ARP cache) and uses it for future frames.

| IP | MAC |
|---|---|
| IP B | 0xB |
| IP of router | 0xR |

## What is ARP spoofing?

**ARP spoofing (ARP cache poisoning)** is an attack in which a malicious machine sends **fake ARP replies** so that other machines store a wrong IP-to-MAC mapping, usually the attacker's own MAC address for someone else's IP.

**Why it is possible:**

- ARP is **stateless**: a host accepts an ARP reply and updates its table even if it never sent a request.
- ARP has **no authentication**: any host can claim any IP address, and machines simply trust each other.
- The attacker only needs to be on the **same LAN**.

## ARP spoofing as a man-in-the-middle attack

A **man-in-the-middle (MITM)** attacker secretly sits between two parties and relays, reads or changes their traffic.

1. The attacker M sends victim A a fake reply: "IP of B is at MAC 0xM."
2. The attacker sends victim B a fake reply: "IP of A is at MAC 0xM."
3. Both ARP tables are now poisoned. A's frames for B, and B's frames for A, go to M.
4. M forwards each frame to the real destination, so the connection keeps working and nobody notices.
5. While relaying, M can **read** the traffic (passwords, cookies), **change** it, or **drop** it.
6. M keeps sending fake replies regularly so the entries do not expire.

Usually one of the two victims is the **router (gateway)**, so the attacker sees all of the victim's Internet traffic.

```text
Before:   A  <------------------------------>  B (or Router)

After:    A  ------>  Attacker M  ------>  B (or Router)
             <------              <------
          A's table: IP B -> 0xM        B's table: IP A -> 0xM
```

## How ARP spoofing steals credentials

1. The attacker poisons the ARP tables of the employee's PC and the gateway (or the login server).
2. All traffic between them now passes through the attacker's machine.
3. When the employee logs in, the attacker captures the username and password if the login is not encrypted (plain HTTP, FTP, Telnet).
4. Even with encryption, the attacker may try to strip HTTPS to HTTP, or redirect the victim to a fake login page on a malicious server.
5. With the stolen credentials or session cookies, the attacker logs in as the employee.

## Defence against ARP spoofing

- **Static ARP entries** for important hosts such as the gateway. These cannot be poisoned, but they are hard to manage in a big network.
- **Dynamic ARP Inspection (DAI)** on switches: the switch checks ARP packets against a trusted IP-to-MAC table (from DHCP snooping) and drops fake ones. It may slow switching a little.
- **Detect duplicate MAC addresses**: one MAC address appearing for several IP addresses is a sign of spoofing.
- **Detection software** such as Arpwatch, XArp and Anti-ARPspoof, which alert when a mapping changes.
- **Encrypt traffic** (HTTPS, SSH, VPN), so even intercepted traffic cannot be read or changed.
- **Port security and VLANs** to limit who can join each network segment.

## Exam-ready answers

**Q. What is ARP spoofing? Why does it work? (3 marks)**

ARP spoofing is an attack where a machine sends fake ARP replies to put a false IP-to-MAC mapping in other hosts' ARP tables, usually mapping the victim's or gateway's IP to the attacker's MAC.
It works because ARP is stateless (replies are accepted without a request) and unauthenticated (hosts trust any reply). So the attacker's traffic redirection is accepted silently.

**Q. How can ARP spoofing be defended? (4 marks)**

- **Static ARP entries** for critical hosts like the gateway.
- **Dynamic ARP Inspection** on switches to drop ARP replies that do not match trusted bindings.
- **Monitoring tools** (Arpwatch, XArp) and checking for one MAC address mapped to many IPs.
- **End-to-end encryption** (HTTPS, SSH, VPN) so that intercepted data is useless.
