# Worms, Rootkits and Other Malware

## Worm

A **worm** is a **standalone** malicious program that spreads **automatically** from computer to computer over a network, **without human help** and without needing a host program.

**Virus vs worm:**

| Virus | Worm |
|---|---|
| Needs a host file | Standalone program |
| Needs a user to run the infected file | Spreads by itself over the network |
| Spreads slowly | Can spread very fast |

**Example: Morris Worm (1988).** It had no harmful payload, but it kept making copies of itself, which slowed infected machines down badly. It infected about 10% of all Internet hosts of that time.

**How a worm spreads, in short:** it finds new targets (often by scanning random IP addresses), infects the vulnerable ones through an unpatched flaw or a tricked user, and every infected host then repeats the process.

## Worm propagation model

The **classic epidemic model** describes how a worm spreads over time.

- **N** = total number of vulnerable hosts
- **I(t)** = number of infected hosts at time t
- **S(t)** = number of susceptible (not yet infected) hosts at time t
- **β** = infection rate

```calc
I(t) + S(t) = N
dI/dt = β × I(t) × S(t)
```

The infection speed depends on **both** the infected hosts (who spread it) and the susceptible hosts (who can still be infected).

**How I(t) and S(t) change over time (an S-shaped curve):**

1. **Slow start:** at first I(t) is very small, so few hosts are spreading it. Growth is slow and S(t) ≈ N.
2. **Fast spread:** as I(t) grows, spreading speeds up almost exponentially. It is fastest when I(t) = S(t) = N/2.
3. **Saturation:** S(t) becomes small, few targets are left, and the growth slows. I(t) approaches N and S(t) approaches 0.

**Lesson for defenders:** early detection and patching matter most, because once the fast phase starts, the worm reaches most vulnerable hosts very quickly.

## Rootkit

A **rootkit** is stealth software that **hides** malware (processes, files, registry keys, network ports, user accounts) from the user and from security tools. It is not always malware itself, but malware uses it to stay hidden.

**How it hides, in short:** it intercepts or modifies operating system functions so that hidden items are left out of the results. Main techniques:

- User-mode API filtering
- Kernel-mode API filtering
- Kernel-mode data structure manipulation
- Process hijacking

**Detection:** every hiding technique has weak points:

- **Unfiltered APIs:** compare results from a high-level and a low-level view; hidden items show up as differences.
- **Side effects:** hiding leaves traces that can be detected.
- **Tools:** Microsoft Strider, RKDetect, Sysinternals RootkitRevealer.

**Removal:** the recommended way is to **reformat and reinstall** the operating system, unless trusted removal instructions exist. Renaming detected files is not enough, since some parts may be missed.

## Trojan horse

A **trojan horse** is a program that **looks useful** but secretly does something harmful, such as installing a keylogger, stealing passwords or opening a backdoor. Users install it themselves, believing it is genuine. Unlike a virus or worm, it does not copy itself.

**Spyware** is malware that secretly collects the user's information (passwords, browsing, contacts, account sessions) and sends it to the attacker. Trojans are a common way to install spyware.

## Logic bomb and insider threats

A **logic bomb** is malicious code hidden inside a normal program that runs only when a condition is met, for example a date, or when an employee's name is removed from the payroll. Insiders such as developers can plant logic bombs or **backdoors** (hidden ways to bypass login).

**Countermeasures:** code review of every change, separation of duties, least privilege, removing access as soon as an employee leaves, audit logs, and monitoring of transactions.

## Ransomware

**Ransomware** is malware that **encrypts the victim's files or locks the system** and demands payment (a ransom) for the key.

- **How it gets in:** malicious email attachments and links, infected downloads, unpatched software vulnerabilities.
- **Impact:** loss of access to data (availability), business or service shutdown, financial loss from ransom and recovery, possible data leak, damaged reputation. Paying does not guarantee recovery.

**Prevention:**

- Regular **offline or offsite backups**, tested for recovery.
- **Patch** the operating system and software quickly.
- Email filtering and **user awareness training** against phishing.
- Anti-virus / endpoint protection, and blocking unknown programs.
- **Least privilege** and network segmentation to limit spread.

## Zero-day attack

A **zero-day attack** exploits a vulnerability that is **unknown to the vendor or not yet patched**. "Zero day" means the developers have had zero days to fix it before it is used.

- **Example:** Stuxnet (2010) used several unknown Windows vulnerabilities to attack industrial control systems.
- **Prevention (no patch exists yet):** keep everything updated so the window is short; use heuristic and behaviour-based detection, intrusion detection and prevention systems, sandboxing, least privilege and network segmentation; apply vendor workarounds and patches as soon as they appear.

## Exam-ready answers

**Q. What is a worm? How is it different from a virus? (3 marks)**

A worm is a standalone malicious program that spreads automatically over a network by copying itself to other systems, with no human help. A virus needs a host file and a user to run it; a worm does not, so it spreads much faster. Example: Morris Worm (1988).

**Q. What is ransomware? Its impact and prevention. (3 marks)**

Ransomware encrypts files or locks the system and demands a ransom for access.
- **Impact:** data becomes unavailable, services stop, money is lost and data may leak.
- **Prevention:** offline backups, regular patching, email filtering and user training, anti-virus, least privilege.

**Q. What is a zero-day exploit? How can it be prevented? (3 marks)**

A zero-day exploit attacks a software flaw that the vendor does not know about or has not patched yet. Example: Stuxnet. Since no patch exists, use behaviour-based detection, IDS/IPS, sandboxing, least privilege and segmentation, and patch quickly when a fix is released.
