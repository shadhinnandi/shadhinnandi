# Practice Problems: Encapsulation, Abstraction and Access Control

These problems practise designing classes that protect their own rules: private fields,
validated changes, read-only data, hidden implementation details and immutable value
objects. Programs read input without prompts and print exactly the sample output.

## Problem 1: An Account That Never Goes Negative
**Level:** Basic

### Problem Statement
Write a class `SavingsAccount` with a private `int` field `balance` (in Tk, starting at
0) and these public methods:

- `boolean deposit(int amount)`: refuses amounts that are not positive.
- `boolean withdraw(int amount)`: refuses amounts that are not positive or larger than
  the balance.
- `int getBalance()`

There is no `setBalance`. The program reads an integer `n`, then `n` commands, each
`D <amount>` (deposit) or `W <amount>` (withdraw). After each command print `OK` or
`REFUSED`, a space, and the balance after the command.

### Sample Input
```text
5
D 500
W 200
W 400
D -50
W 300
```

### Sample Output
```text
OK 500
OK 300
REFUSED 300
REFUSED 300
OK 0
```

### Solution
```java
import java.util.Scanner;

class SavingsAccount {
    private int balance;

    public boolean deposit(int amount) {
        if (amount <= 0) {
            return false;
        }
        balance = balance + amount;
        return true;
    }

    public boolean withdraw(int amount) {
        if (amount <= 0 || amount > balance) {
            return false;
        }
        balance = balance - amount;
        return true;
    }

    public int getBalance() {
        return balance;
    }
}

public class NeverNegative {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        SavingsAccount account = new SavingsAccount();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            int amount = in.nextInt();
            boolean ok;
            if (command.equals("D")) {
                ok = account.deposit(amount);
            } else {
                ok = account.withdraw(amount);
            }
            System.out.println((ok ? "OK " : "REFUSED ") + account.getBalance());
        }
    }
}
```

### Explanation
The invariant is `balance >= 0`. Because `balance` is private and there is no setter,
the only code that can change it is `deposit` and `withdraw`, and both check the rule
before changing anything. A refused withdrawal of 400 leaves the balance at 300, and a
negative "deposit" (which would really be a hidden withdrawal) is refused too. `main`
cannot break the rule even by accident: `account.balance = -100` would not compile.

## Problem 2: Grade Record with a Valid Range
**Level:** Basic

### Problem Statement
Write a class `GradeRecord` for one course with a private final course code and private
`int marks` (starting at 0). Provide:

- `boolean setMarks(int newMarks)`: accepts only 0 to 100; otherwise keeps the old marks
  and returns `false`.
- `int getMarks()` and `String getCourseCode()`.
- `String getLetter()`: `A` for 80 or more, `B` for 65 to 79, `C` for 50 to 64, `F`
  below 50. The letter is computed from the marks, not stored.

The program reads the course code (one line), an integer `n`, and `n` marks. For each
mark print `Saved <marks>` or `Rejected <value> (keeping <old marks>)`. Finally print
`<course code>: <marks> (<letter>)`.

### Sample Input
```text
CSE 1111
4
72
105
-3
88
```

### Sample Output
```text
Saved 72
Rejected 105 (keeping 72)
Rejected -3 (keeping 72)
Saved 88
CSE 1111: 88 (A)
```

### Solution
```java
import java.util.Scanner;

class GradeRecord {
    private final String courseCode;
    private int marks;

    GradeRecord(String courseCode) {
        this.courseCode = courseCode;
    }

    public boolean setMarks(int newMarks) {
        if (newMarks < 0 || newMarks > 100) {
            return false;
        }
        marks = newMarks;
        return true;
    }

    public int getMarks() {
        return marks;
    }

    public String getCourseCode() {
        return courseCode;
    }

    public String getLetter() {
        if (marks >= 80) {
            return "A";
        } else if (marks >= 65) {
            return "B";
        } else if (marks >= 50) {
            return "C";
        }
        return "F";
    }
}

public class GradeRange {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        GradeRecord record = new GradeRecord(in.nextLine());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            int value = in.nextInt();
            if (record.setMarks(value)) {
                System.out.println("Saved " + value);
            } else {
                System.out.println("Rejected " + value + " (keeping "
                        + record.getMarks() + ")");
            }
        }
        System.out.println(record.getCourseCode() + ": " + record.getMarks()
                + " (" + record.getLetter() + ")");
    }
}
```

### Explanation
`setMarks` checks first and stores second, so the field can never hold 105 or -3, and a
rejected value leaves the previous marks in place. The letter grade has no field of its
own: `getLetter()` computes it from `marks` every time. If the letter were a separate
field, someone could update the marks and forget the letter, and the two would disagree.
Computing derived values instead of storing them removes that risk. The course code is
`final` and has no setter, because a grade record never moves to another course.

## Problem 3: Read-Only Member ID
**Level:** Basic

### Problem Statement
Write a class `LibraryMember` with:

- a private final member ID (getter only, no setter),
- a private name (getter only),
- a private phone number, initially `none`, with
  `boolean setPhone(String phone)` that accepts only exactly 11 characters that are all
  digits and start with `01`.

The program reads the member ID (one line), the name (one line), an integer `n` and then
`n` phone numbers, one per line. For each, print `Phone updated` or
`Invalid phone: <value>`. Finally print `Member <id>: <name>, phone <phone>`.

### Sample Input
```text
M-2041
Sadia Islam
3
01712345678
0171234567
0181234ab78
```

### Sample Output
```text
Phone updated
Invalid phone: 0171234567
Invalid phone: 0181234ab78
Member M-2041: Sadia Islam, phone 01712345678
```

### Solution
```java
import java.util.Scanner;

class LibraryMember {
    private final String memberId;
    private final String name;
    private String phone = "none";

    LibraryMember(String memberId, String name) {
        this.memberId = memberId;
        this.name = name;
    }

    public boolean setPhone(String newPhone) {
        if (newPhone.length() != 11 || !newPhone.startsWith("01")) {
            return false;
        }
        for (int i = 0; i < newPhone.length(); i++) {
            char c = newPhone.charAt(i);
            if (c < '0' || c > '9') {
                return false;
            }
        }
        phone = newPhone;
        return true;
    }

    public String getMemberId() {
        return memberId;
    }

    public String getName() {
        return name;
    }

    public String getPhone() {
        return phone;
    }
}

public class MemberCard {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String id = in.nextLine();
        String name = in.nextLine();
        LibraryMember member = new LibraryMember(id, name);
        int n = Integer.parseInt(in.nextLine().trim());
        for (int i = 0; i < n; i++) {
            String phone = in.nextLine().trim();
            if (member.setPhone(phone)) {
                System.out.println("Phone updated");
            } else {
                System.out.println("Invalid phone: " + phone);
            }
        }
        System.out.println("Member " + member.getMemberId() + ": " + member.getName()
                + ", phone " + member.getPhone());
    }
}
```

### Explanation
Not every field gets a setter. The member ID identifies the member, so it is `final`
with a getter only. The name has no setter in this program because nothing needs to
change it. Only the phone number may change, and `setPhone` checks the length, the
`01` prefix and that every character is a digit before storing it. The whole input is
read with `nextLine()` so the program never mixes `nextInt()` and `nextLine()`.

## Problem 4: Temperature Sensor Readings
**Level:** Basic

### Problem Statement
Write a class `TemperatureSensor` that remembers the last valid reading in Celsius.
A reading is valid only from -40.0 to 125.0 (inclusive); invalid readings are ignored
and counted. Provide `boolean record(double celsius)`, `boolean hasReading()`,
`double getCelsius()`, `double getFahrenheit()` and `int getRejectedCount()`. The class
stores only Celsius; Fahrenheit is computed (`F = C * 9 / 5 + 32`).

The program reads `n` and then `n` readings. For each invalid reading print
`Ignored <value>`. At the end print `Last valid: <C> C = <F> F` (or `No valid reading`
if there was none) and `Rejected readings: <count>`. Print temperatures with two
decimals.

### Sample Input
```text
5
28.5
31.0
-80
130.25
31.5
```

### Sample Output
```text
Ignored -80.00
Ignored 130.25
Last valid: 31.50 C = 88.70 F
Rejected readings: 2
```

### Solution
```java
import java.util.Scanner;

class TemperatureSensor {
    private double celsius;
    private boolean hasReading;
    private int rejectedCount;

    public boolean record(double value) {
        if (value < -40.0 || value > 125.0) {
            rejectedCount++;
            return false;
        }
        celsius = value;
        hasReading = true;
        return true;
    }

    public boolean hasReading() {
        return hasReading;
    }

    public double getCelsius() {
        return celsius;
    }

    public double getFahrenheit() {
        return celsius * 9 / 5 + 32;
    }

    public int getRejectedCount() {
        return rejectedCount;
    }
}

public class SensorReadings {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        TemperatureSensor sensor = new TemperatureSensor();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            double value = in.nextDouble();
            if (!sensor.record(value)) {
                System.out.printf("Ignored %.2f%n", value);
            }
        }
        if (sensor.hasReading()) {
            System.out.printf("Last valid: %.2f C = %.2f F%n",
                    sensor.getCelsius(), sensor.getFahrenheit());
        } else {
            System.out.println("No valid reading");
        }
        System.out.println("Rejected readings: " + sensor.getRejectedCount());
    }
}
```

### Explanation
This is abstraction in a small form: callers ask for Celsius or Fahrenheit and do not
know that only Celsius is stored. If the sensor later stores Kelvin instead, only the
inside of the class changes. The `hasReading` flag solves a real problem: a new sensor
has `celsius = 0.0` by default, and without the flag a caller could not tell "it is 0
degrees" from "nothing was measured yet". The rejected counter has a getter but no
setter, so only `record` can increase it.

## Problem 5: A Locker That Never Reveals Its PIN
**Level:** Basic

### Problem Statement
Write a class `Locker` with a private PIN and a private `boolean` that says whether it
is open. The PIN must have **no getter**. Provide:

- `boolean unlock(String pin)`: opens the locker if the PIN matches.
- `void lock()`
- `boolean changePin(String oldPin, String newPin)`: works only if `oldPin` is correct
  and `newPin` is exactly 4 digits.
- `boolean isOpen()`

The program reads the initial PIN, then `n` commands: `U <pin>`, `L`, or
`C <old> <new>`. Print `Unlocked` or `Wrong PIN` for `U`, `Locked` for `L`, and
`PIN changed` or `PIN not changed` for `C`. Finally print `Locker is open` or
`Locker is closed`.

### Sample Input
```text
1234
6
U 1111
U 1234
L
C 1234 98a7
C 1234 9876
U 1234
```

### Sample Output
```text
Wrong PIN
Unlocked
Locked
PIN not changed
PIN changed
Wrong PIN
Locker is closed
```

### Solution
```java
import java.util.Scanner;

class Locker {
    private String pin;
    private boolean open;

    Locker(String pin) {
        this.pin = pin;
    }

    public boolean unlock(String attempt) {
        if (!pin.equals(attempt)) {
            return false;
        }
        open = true;
        return true;
    }

    public void lock() {
        open = false;
    }

    public boolean changePin(String oldPin, String newPin) {
        if (!pin.equals(oldPin) || !isFourDigits(newPin)) {
            return false;
        }
        pin = newPin;
        return true;
    }

    public boolean isOpen() {
        return open;
    }

    private boolean isFourDigits(String s) {
        if (s.length() != 4) {
            return false;
        }
        for (int i = 0; i < 4; i++) {
            if (!Character.isDigit(s.charAt(i))) {
                return false;
            }
        }
        return true;
    }
}

public class LockerDemo {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Locker locker = new Locker(in.next());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("U")) {
                System.out.println(locker.unlock(in.next()) ? "Unlocked" : "Wrong PIN");
            } else if (command.equals("L")) {
                locker.lock();
                System.out.println("Locked");
            } else {
                String oldPin = in.next();
                String newPin = in.next();
                boolean ok = locker.changePin(oldPin, newPin);
                System.out.println(ok ? "PIN changed" : "PIN not changed");
            }
        }
        System.out.println(locker.isOpen() ? "Locker is open" : "Locker is closed");
    }
}
```

### Explanation
Some data should never leave the object. Other code may *ask* the locker to check a
PIN (`unlock`) but can never *read* it, because no method returns it. Compare PINs with
`equals`, never `==`, since they are `String` objects. The digit check is a private
helper: callers only need to know that a bad new PIN is refused, not how it is
checked. After the change, the old PIN `1234` no longer works.

## Problem 6: Inventory Item with Reorder Alert
**Level:** Intermediate

### Problem Statement
Write a class `InventoryItem` with a private final name, a private final reorder level,
a private unit price (Tk, always positive) and a private stock (never negative).
Provide `sell(int qty)`, `restock(int qty)` and `setPrice(int price)`, each returning
`boolean`, plus `boolean needsReorder()` (stock at or below the reorder level) and
`int getStockValue()` (price times stock). Quantities must be positive; a sale larger
than the stock is refused.

Input: the item name (one line), then `price stock reorderLevel`, then `n` commands
`SELL q`, `RESTOCK q` or `PRICE p`. For each command print
`<COMMAND> <value>: OK` or `<COMMAND> <value>: REFUSED`, followed by
` (stock <s>, price <p>)`. After a successful `SELL` that leaves the item needing a
reorder, also print `  Reorder alert: <name>`. Finally print
`<name>: stock <s>, value Tk <value>`.

### Sample Input
```text
USB Cable
150 20 5
7
SELL 8
SELL 15
RESTOCK 0
SELL 9
PRICE 0
RESTOCK 10
PRICE 180
```

### Sample Output
```text
SELL 8: OK (stock 12, price 150)
SELL 15: REFUSED (stock 12, price 150)
RESTOCK 0: REFUSED (stock 12, price 150)
SELL 9: OK (stock 3, price 150)
  Reorder alert: USB Cable
PRICE 0: REFUSED (stock 3, price 150)
RESTOCK 10: OK (stock 13, price 150)
PRICE 180: OK (stock 13, price 180)
USB Cable: stock 13, value Tk 2340
```

### Solution
```java
import java.util.Scanner;

class InventoryItem {
    private final String name;
    private final int reorderLevel;
    private int unitPrice;
    private int stock;

    InventoryItem(String name, int unitPrice, int stock, int reorderLevel) {
        this.name = name;
        this.unitPrice = unitPrice;
        this.stock = stock;
        this.reorderLevel = reorderLevel;
    }

    public boolean sell(int qty) {
        if (qty <= 0 || qty > stock) {
            return false;
        }
        stock = stock - qty;
        return true;
    }

    public boolean restock(int qty) {
        if (qty <= 0) {
            return false;
        }
        stock = stock + qty;
        return true;
    }

    public boolean setPrice(int price) {
        if (price <= 0) {
            return false;
        }
        unitPrice = price;
        return true;
    }

    public boolean needsReorder() {
        return stock <= reorderLevel;
    }

    public int getStockValue() {
        return unitPrice * stock;
    }

    public String getName() {
        return name;
    }

    public int getStock() {
        return stock;
    }

    public int getUnitPrice() {
        return unitPrice;
    }
}

public class InventoryDesk {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String name = in.nextLine();
        int price = in.nextInt();
        int stock = in.nextInt();
        int reorder = in.nextInt();
        InventoryItem item = new InventoryItem(name, price, stock, reorder);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            int value = in.nextInt();
            boolean ok;
            if (command.equals("SELL")) {
                ok = item.sell(value);
            } else if (command.equals("RESTOCK")) {
                ok = item.restock(value);
            } else {
                ok = item.setPrice(value);
            }
            System.out.println(command + " " + value + ": " + (ok ? "OK" : "REFUSED")
                    + " (stock " + item.getStock() + ", price "
                    + item.getUnitPrice() + ")");
            if (ok && command.equals("SELL") && item.needsReorder()) {
                System.out.println("  Reorder alert: " + item.getName());
            }
        }
        System.out.println(item.getName() + ": stock " + item.getStock()
                + ", value Tk " + item.getStockValue());
    }
}
```

### Explanation
The class protects two invariants at once: `stock >= 0` and `unitPrice > 0`. Stock has
no setter; it changes only through `sell` and `restock`, which describe what actually
happens in a shop and can each apply their own rule. Price does get a setter, because
changing a price is a legal business action, but the setter rejects zero and negative
values. `needsReorder()` and `getStockValue()` are computed from the fields, so they are
always consistent with the current stock and price. `main` contains no business rules;
it only reads commands and reports.

## Problem 7: An Immutable Fraction
**Level:** Intermediate

### Problem Statement
Write an immutable class `Fraction` with private final numerator and denominator. The
constructor stores the fraction in lowest terms with a positive denominator
(`2/-4` becomes `-1/2`, `0/5` becomes `0/1`). Provide `plus`, `minus`, `times` and
`dividedBy`, each returning a **new** `Fraction`, plus `boolean isZero()` and
`toString()` (print `a/b`, or just `a` when the denominator is 1).

Input: two lines, each with a numerator and a non-zero denominator, giving `x` and `y`.
Print `x = ..., y = ...`, then the sum, difference, product and quotient as shown. If
`y` is zero, print `x / y = undefined` instead of dividing. Finally print
`x is still <x>`.

### Sample Input
```text
1 2
-3 4
```

### Sample Output
```text
x = 1/2, y = -3/4
x + y = -1/4
x - y = 5/4
x * y = -3/8
x / y = -2/3
x is still 1/2
```

### Solution
```java
import java.util.Scanner;

class Fraction {
    private final int num;
    private final int den;

    Fraction(int numerator, int denominator) {
        if (denominator < 0) {
            numerator = -numerator;
            denominator = -denominator;
        }
        int g = gcd(Math.abs(numerator), denominator);
        num = numerator / g;
        den = denominator / g;
    }

    public Fraction plus(Fraction o) {
        return new Fraction(num * o.den + o.num * den, den * o.den);
    }

    public Fraction minus(Fraction o) {
        return new Fraction(num * o.den - o.num * den, den * o.den);
    }

    public Fraction times(Fraction o) {
        return new Fraction(num * o.num, den * o.den);
    }

    public Fraction dividedBy(Fraction o) {
        return new Fraction(num * o.den, den * o.num);
    }

    public boolean isZero() {
        return num == 0;
    }

    public String toString() {
        if (den == 1) {
            return String.valueOf(num);
        }
        return num + "/" + den;
    }

    private int gcd(int a, int b) {
        if (b == 0) {
            return a;
        }
        return gcd(b, a % b);
    }
}

public class FractionCalc {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Fraction x = new Fraction(in.nextInt(), in.nextInt());
        Fraction y = new Fraction(in.nextInt(), in.nextInt());
        System.out.println("x = " + x + ", y = " + y);
        System.out.println("x + y = " + x.plus(y));
        System.out.println("x - y = " + x.minus(y));
        System.out.println("x * y = " + x.times(y));
        if (y.isZero()) {
            System.out.println("x / y = undefined");
        } else {
            System.out.println("x / y = " + x.dividedBy(y));
        }
        System.out.println("x is still " + x);
    }
}
```

### Explanation
All the "normalising" work happens once, in the constructor, so every `Fraction` that
exists is already in lowest terms with a positive denominator: that is the class's
invariant, and since the fields are `final` nothing can break it later. The arithmetic
methods read `o.num` and `o.den` directly, which is allowed because `private` is checked
per class, not per object. Each operation builds a new object, so `x` is unchanged at
the end. The constructor changes its parameters (not the fields) before assigning each
`final` field exactly once. Division by a zero fraction is prevented by the caller
checking `isZero()`; in Chapter 11 the class could throw an exception instead.

## Problem 8: Class Attendance Tracker
**Level:** Intermediate

### Problem Statement
A course has a fixed number of planned classes in a trimester. Write a class
`Attendance` with a private final `totalClasses` and private counters `held` and
`attended`. The invariant is `0 <= attended <= held <= totalClasses`.

- `boolean markPresent()` and `boolean markAbsent()` refuse once all classes are held.
- `double getPercentage()`: attended as a percentage of held classes (0 if none held).
- `int presentsNeeded(int targetPercent)`: the smallest number of further presents
  needed so that `attended` reaches `targetPercent` of `totalClasses`, or `-1` if that
  is no longer possible with the remaining classes.

Input: `totalClasses` on the first line, then one word of marks such as `PPAP`, where
`P` is present and `A` is absent. Any other character, and any mark after all classes
are held, is ignored and counted. Print:

```text
Held: <held> of <total>
Attended: <attended> (<percentage with one decimal>%)
Ignored marks: <count>
Presents needed for 75%: <number or impossible>
```

### Sample Input
```text
10
PPAPPXPAP
```

### Sample Output
```text
Held: 8 of 10
Attended: 6 (75.0%)
Ignored marks: 1
Presents needed for 75%: 2
```

### Solution
```java
import java.util.Scanner;

class Attendance {
    private final int totalClasses;
    private int held;
    private int attended;

    Attendance(int totalClasses) {
        this.totalClasses = totalClasses;
    }

    public boolean markPresent() {
        if (held == totalClasses) {
            return false;
        }
        held++;
        attended++;
        return true;
    }

    public boolean markAbsent() {
        if (held == totalClasses) {
            return false;
        }
        held++;
        return true;
    }

    public double getPercentage() {
        if (held == 0) {
            return 0.0;
        }
        return attended * 100.0 / held;
    }

    public int presentsNeeded(int targetPercent) {
        int required = (targetPercent * totalClasses + 99) / 100;
        int needed = Math.max(0, required - attended);
        if (needed > totalClasses - held) {
            return -1;
        }
        return needed;
    }

    public int getHeld() {
        return held;
    }

    public int getAttended() {
        return attended;
    }

    public int getTotalClasses() {
        return totalClasses;
    }
}

public class AttendanceTracker {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Attendance record = new Attendance(in.nextInt());
        String marks = in.next();
        int ignored = 0;
        for (int i = 0; i < marks.length(); i++) {
            char c = marks.charAt(i);
            boolean ok = false;
            if (c == 'P') {
                ok = record.markPresent();
            } else if (c == 'A') {
                ok = record.markAbsent();
            }
            if (!ok) {
                ignored++;
            }
        }
        System.out.println("Held: " + record.getHeld() + " of " + record.getTotalClasses());
        System.out.printf("Attended: %d (%.1f%%)%n", record.getAttended(),
                record.getPercentage());
        System.out.println("Ignored marks: " + ignored);
        int needed = record.presentsNeeded(75);
        System.out.println("Presents needed for 75%: "
                + (needed < 0 ? "impossible" : String.valueOf(needed)));
    }
}
```

### Explanation
Three counters are tied together by one invariant. If `held` and `attended` had
setters, a caller could set `attended = 9, held = 5`. Instead, the only changes are
"one more present" and "one more absent", and each keeps the invariant true and stops
at `totalClasses`. The calculation in `presentsNeeded` rounds `75% of 10 = 7.5` up to 8
with the integer trick `(a + 99) / 100`, then compares what is needed with the classes
still left. Callers get the answer without knowing the formula, which is abstraction.
Note `%%` in `printf` prints a literal percent sign.

## Problem 9: Class Routine with an Immutable Clock Time
**Level:** Intermediate

### Problem Statement
Write an immutable class `ClockTime` that stores a time of day as minutes since
midnight in one private final field. The constructor takes any number of minutes and
wraps it into the range 0 to 1439 (so 1500 becomes 01:00 and -30 becomes 23:30).
Provide `ClockTime plusMinutes(int m)` (returns a new object),
`boolean isAfter(ClockTime other)` and `toString()` in `HH:MM` form.

Input: the first class's start time `HH MM`, then `n`, then `n` lines with a course code
and a duration in minutes. Classes run back to back with a 10-minute break between
them. Print each class as `<code> <start>-<end>`, adding ` (after 17:00)` when the class
ends after 17:00. Then print `Day ends at <time>` and `Routine started at <time>`.

### Sample Input
```text
08 30
4
CSE1111 80
MAT1101 75
PHY1103 150
CSE1112 180
```

### Sample Output
```text
CSE1111 08:30-09:50
MAT1101 10:00-11:15
PHY1103 11:25-13:55
CSE1112 14:05-17:05 (after 17:00)
Day ends at 17:05
Routine started at 08:30
```

### Solution
```java
import java.util.Scanner;

class ClockTime {
    private final int minutes;

    ClockTime(int totalMinutes) {
        minutes = ((totalMinutes % 1440) + 1440) % 1440;
    }

    public ClockTime plusMinutes(int m) {
        return new ClockTime(minutes + m);
    }

    public boolean isAfter(ClockTime other) {
        return minutes > other.minutes;
    }

    public int getHour() {
        return minutes / 60;
    }

    public int getMinute() {
        return minutes % 60;
    }

    public String toString() {
        return String.format("%02d:%02d", getHour(), getMinute());
    }
}

public class ClassRoutine {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int hour = in.nextInt();
        int minute = in.nextInt();
        ClockTime dayStart = new ClockTime(hour * 60 + minute);
        ClockTime limit = new ClockTime(17 * 60);
        int n = in.nextInt();
        ClockTime start = dayStart;
        ClockTime end = dayStart;
        for (int i = 0; i < n; i++) {
            String code = in.next();
            int duration = in.nextInt();
            end = start.plusMinutes(duration);
            String line = code + " " + start + "-" + end;
            if (end.isAfter(limit)) {
                line = line + " (after 17:00)";
            }
            System.out.println(line);
            start = end.plusMinutes(10);
        }
        System.out.println("Day ends at " + end);
        System.out.println("Routine started at " + dayStart);
    }
}
```

### Explanation
Storing one number (minutes since midnight) instead of separate hour and minute fields
makes the invariant easy: the constructor wraps the value once, and because the field
is `final` it can never leave the valid range. Hours and minutes are computed by the
getters, so callers still see a friendly interface (abstraction). `start = start...`
style updates replace the variable's reference with a new object; the old `ClockTime`
objects are never modified, which is why `dayStart` still prints 08:30 at the end even
though `start` began as the same object. The formula `((t % 1440) + 1440) % 1440` also
handles negative input, because Java's `%` can return a negative result.

## Problem 10: Prepaid Electricity Meter
**Level:** Intermediate

### Problem Statement
A prepaid meter (tariff is hypothetical) has a private balance in Tk and a private count
of units used this month. Units are charged by slab, counting from the start of the
month: units 1 to 75 cost 5 Tk each, units 76 to 200 cost 7 Tk each, and every unit

- `boolean recharge(int amount)`: amount must be positive and the balance may not go
  above 10000 Tk.
- `int quote(int units)`: the cost of using `units` more units now.
- `boolean consume(int units)`: refused if `units` is not positive or the cost is more
  than the balance; otherwise deducts the cost and adds the units.
- `void startNewMonth()`: resets the monthly unit count (not the balance).

The tariff rule must be private. Commands: `R <amount>`, `U <units>`, `M` and `S`.
Print exactly as in the sample (for a refused `U`, print
`Use <u> units: REFUSED, balance <b>`). `S` prints
`Balance <b> Tk, <units> units this month`.

### Sample Input
```text
9
R 1000
U 60
U 40
U 200
R 2000
U 120
M
U 10
S
```

### Sample Output
```text
Recharge 1000: OK, balance 1000
Use 60 units: OK, cost 300, balance 700
Use 40 units: OK, cost 250, balance 450
Use 200 units: REFUSED, balance 450
Recharge 2000: OK, balance 2450
Use 120 units: OK, cost 900, balance 1550
New month
Use 10 units: OK, cost 50, balance 1500

```

### Solution
```java
import java.util.Scanner;

class PrepaidMeter {
    private int balance;
    private int unitsThisMonth;

    public boolean recharge(int amount) {
        if (amount <= 0 || balance + amount > 10000) {
            return false;
        }
        balance = balance + amount;
        return true;
    }

    public int quote(int units) {
        int cost = 0;
        for (int k = unitsThisMonth + 1; k <= unitsThisMonth + units; k++) {
            cost = cost + rateForUnit(k);
        }
        return cost;
    }

    public boolean consume(int units) {
        if (units <= 0) {
            return false;
        }
        int cost = quote(units);
        if (cost > balance) {
            return false;
        }
        balance = balance - cost;
        unitsThisMonth = unitsThisMonth + units;
        return true;
    }

    public void startNewMonth() {
        unitsThisMonth = 0;
    }

    public int getBalance() {
        return balance;
    }

    public int getUnitsThisMonth() {
        return unitsThisMonth;
    }

    private int rateForUnit(int unitNumber) {
        if (unitNumber <= 75) {
            return 5;
        } else if (unitNumber <= 200) {
            return 7;
        }
        return 10;
    }
}

public class MeterConsole {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        PrepaidMeter meter = new PrepaidMeter();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("R")) {
                int amount = in.nextInt();
                boolean ok = meter.recharge(amount);
                System.out.println("Recharge " + amount + ": " + (ok ? "OK" : "REFUSED")
                        + ", balance " + meter.getBalance());
            } else if (command.equals("U")) {
                int units = in.nextInt();
                int cost = meter.quote(units);
                if (meter.consume(units)) {
                    System.out.println("Use " + units + " units: OK, cost " + cost
                            + ", balance " + meter.getBalance());
                } else {
                    System.out.println("Use " + units + " units: REFUSED, balance "
                            + meter.getBalance());
                }
            } else if (command.equals("M")) {
                meter.startNewMonth();
                System.out.println("New month");
            } else {
                System.out.println("Balance " + meter.getBalance() + " Tk, "
                        + meter.getUnitsThisMonth() + " units this month");
            }
        }
    }
}
```

### Explanation
This problem shows encapsulation and abstraction together. Encapsulation: the balance
and unit count are private, the balance cannot go negative or above the limit, and the
unit count changes only with a successful `consume`. Abstraction: callers use
`quote` and `consume` without knowing the slabs; `rateForUnit` is private, so a new
tariff means editing one method. Charging unit by unit makes slab boundaries easy:
the 40 units after the first 60 are 15 units at 5 Tk plus 25 at 7 Tk = 250 Tk. A refused
`consume` changes nothing, so the meter is never left half-charged.

## Problem 11: Two Accounts, Transfers and a Daily Limit
**Level:** Advanced

### Problem Statement
A small bank branch (rules are hypothetical) manages exactly two accounts. Write:

- `Account`: private final ID, owner and daily withdrawal limit; private balance and
  amount withdrawn today. Methods `deposit`, `canWithdraw`, `withdraw` (refuses if the
  amount is not positive, exceeds the balance, or would push today's withdrawals above
  the limit), `startNewDay`, and getters for ID, owner and balance only.
- `Bank`: holds the two accounts and the total cash that came in and went out. Methods
  `deposit(id, amount)`, `withdraw(id, amount)`, `transfer(fromId, toId, amount)`,
  `newDay()` and `boolean booksBalance()` (sum of balances equals cash in minus cash
  out). A transfer counts toward the sender's daily limit, must name two different
  existing accounts, and must either fully happen or not happen at all.

Input: two lines `id owner dailyLimit`, then `n` commands: `DEP id amount`,
`WD id amount`, `TR fromId toId amount`, `DAY`. Print one line per command as in the
sample, then each account as `<id> <owner>: <balance> Tk`, then
`Books balanced: yes` or `no`.

### Sample Input

### Sample Output

### Solution
```java
import java.util.Scanner;

class Account {
    private final String id;
    private final String owner;
    private final int dailyLimit;
    private int balance;
    private int withdrawnToday;

    Account(String id, String owner, int dailyLimit) {
        this.id = id;
        this.owner = owner;
        this.dailyLimit = dailyLimit;
    }

    public boolean deposit(int amount) {
        if (amount <= 0) {
            return false;
        }
        balance = balance + amount;
        return true;
    }

    public boolean canWithdraw(int amount) {
        return amount > 0 && amount <= balance && withdrawnToday + amount <= dailyLimit;
    }

    public boolean withdraw(int amount) {
        if (!canWithdraw(amount)) {
            return false;
        }
        balance = balance - amount;
        withdrawnToday = withdrawnToday + amount;
        return true;
    }

    public void startNewDay() {
        withdrawnToday = 0;
    }

    public String getId() {
        return id;
    }

    public String getOwner() {
        return owner;
    }

    public int getBalance() {
        return balance;
    }
}

class Bank {
    private final Account first;
    private final Account second;
    private long cashIn;
    private long cashOut;

    Bank(Account first, Account second) {
        this.first = first;
        this.second = second;
    }

    public boolean deposit(String id, int amount) {
        Account acc = find(id);
        if (acc == null || !acc.deposit(amount)) {
            return false;
        }
        cashIn = cashIn + amount;
        return true;
    }

    public boolean withdraw(String id, int amount) {
        Account acc = find(id);
        if (acc == null || !acc.withdraw(amount)) {
            return false;
        }
        cashOut = cashOut + amount;
        return true;
    }

    public boolean transfer(String fromId, String toId, int amount) {
        Account from = find(fromId);
        Account to = find(toId);
        if (from == null || to == null || from == to || !from.canWithdraw(amount)) {
            return false;
        }
        from.withdraw(amount);
        to.deposit(amount);
        return true;
    }

    public void newDay() {
        first.startNewDay();
        second.startNewDay();
    }

    public boolean booksBalance() {
        return first.getBalance() + second.getBalance() == cashIn - cashOut;
    }

    public String report() {
        return line(first) + "\n" + line(second);
    }

    private String line(Account a) {
        return a.getId() + " " + a.getOwner() + ": " + a.getBalance() + " Tk";
    }

    private Account find(String id) {
        if (first.getId().equals(id)) {
            return first;
        }
        if (second.getId().equals(id)) {
            return second;
        }
        return null;
    }
}

public class BranchLedger {
    static Account readAccount(Scanner in) {
        String id = in.next();
        String owner = in.next();
        int limit = in.nextInt();
        return new Account(id, owner, limit);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Bank bank = new Bank(readAccount(in), readAccount(in));
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("DAY")) {
                bank.newDay();
                System.out.println("New day");
            } else if (command.equals("TR")) {
                String from = in.next();
                String to = in.next();
                int amount = in.nextInt();
                boolean ok = bank.transfer(from, to, amount);
                System.out.println("Transfer " + amount + " " + from + " -> " + to
                        + ": " + (ok ? "OK" : "REFUSED"));
            } else {
                String id = in.next();
                int amount = in.nextInt();
                if (command.equals("DEP")) {
                    boolean ok = bank.deposit(id, amount);
                    System.out.println("Deposit " + amount + " to " + id + ": "
                            + (ok ? "OK" : "REFUSED"));
                } else {
                    boolean ok = bank.withdraw(id, amount);
                    System.out.println("Withdraw " + amount + " from " + id + ": "
                            + (ok ? "OK" : "REFUSED"));
                }
            }
        }
        System.out.println(bank.report());
        System.out.println("Books balanced: " + (bank.booksBalance() ? "yes" : "no"));
    }
}
```

### Explanation
There are invariants at two levels. Each `Account` guards its own: balance never
negative, today's withdrawals never above the limit. The `Bank` guards a system-wide
one: money is never created or destroyed by a transfer, so the sum of balances always
equals cash in minus cash out. `transfer` keeps it by checking `canWithdraw` *before*
touching either account; after that check, the withdrawal and the deposit cannot fail,
so the transfer is all-or-nothing. `withdrawnToday` has no getter and no setter; it is
used only inside `Account`. `find` and `line` are private helpers, and `main` never
holds an `Account` reference after creating the bank, so it cannot bypass the bank's
bookkeeping. `from == to` compares references on purpose: it asks "is this the same
account object?".

```java
import java.util.Scanner;

class CourseResult {
    private final String code;
    private final int credits;
    private final int marks;

    CourseResult(String code, int credits, int marks) {
        this.code = code;
        this.credits = credits;
        this.marks = marks;
    }

    public String getCode() {
        return code;
    }

    public int getCredits() {
        return credits;
    }

    public int getMarks() {
        return marks;
    }

    public String getLetter() {
        if (marks >= 80) {
            return "A+";
        } else if (marks >= 75) {
            return "A";
        } else if (marks >= 70) {
            return "A-";
        } else if (marks >= 65) {
            return "B+";
        } else if (marks >= 60) {
            return "B";
        } else if (marks >= 55) {
            return "B-";
        } else if (marks >= 50) {
            return "C+";
        } else if (marks >= 45) {
            return "C";
        } else if (marks >= 40) {
            return "D";
        }
        return "F";
    }

    public double getGradePoint() {
        if (marks >= 80) {
            return 4.00;
        } else if (marks >= 75) {
            return 3.75;
        } else if (marks >= 70) {
            return 3.50;
        } else if (marks >= 65) {
            return 3.25;
        } else if (marks >= 60) {
            return 3.00;
        } else if (marks >= 55) {
            return 2.75;
        } else if (marks >= 50) {
            return 2.50;
        } else if (marks >= 45) {
            return 2.25;
        } else if (marks >= 40) {
            return 2.00;
        }
        return 0.00;
    }
}

class Transcript {
    private final String studentName;
    private int attemptedCredits;
    private int earnedCredits;
    private double weightedPoints;
    private CourseResult best;

    Transcript(String studentName) {
        this.studentName = studentName;
    }

    /** Adds a valid course; returns the line that reports what happened. */
    public String add(String code, int credits, int marks) {
        if (credits < 1 || credits > 4) {
            return "Rejected " + code + ": credits must be 1 to 4";
        }
        if (marks < 0 || marks > 100) {
            return "Rejected " + code + ": marks must be 0 to 100";
        }
        CourseResult result = new CourseResult(code, credits, marks);
        attemptedCredits += credits;
        if (!result.getLetter().equals("F")) {
            earnedCredits += credits;
        }
        weightedPoints += credits * result.getGradePoint();
        if (best == null || marks > best.getMarks()) {
            best = result;
        }
        return String.format("%s %d cr %d %s %.2f", code, credits, marks,
                result.getLetter(), result.getGradePoint());
    }

    public double getGpa() {
        if (attemptedCredits == 0) {
            return 0.0;
        }
        return weightedPoints / attemptedCredits;
    }

    public String getStanding() {
        double gpa = getGpa();
        if (gpa >= 3.75) {
            return "Excellent";
        } else if (gpa >= 2.00) {
            return "Good standing";
        }
        return "Probation";
    }

    public void printSummary() {
        System.out.println("Student: " + studentName);
        System.out.println("Credits attempted: " + attemptedCredits + ", earned: " + earnedCredits);
        System.out.printf("GPA: %.2f (%s)%n", getGpa(), getStanding());
        if (best != null) {
            System.out.println("Best course: " + best.getCode() + " (" + best.getMarks() + ")");
        }
    }
}

public class TrimesterTranscript {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Transcript transcript = new Transcript(in.nextLine());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String code = in.next();
            int credits = in.nextInt();
            int marks = in.nextInt();
            System.out.println(transcript.add(code, credits, marks));
        }
        transcript.printSummary();
    }
}
```

### Explanation
`CourseResult` is immutable: every field is `private final`, there are no setters, and
the letter and grade point are *computed* from the marks instead of being stored, so
they can never disagree with them. `Transcript` is the only place that creates
`CourseResult` objects, and it does so only after checking credits and marks, so an
invalid result can never exist. Instead of storing every course, it keeps exactly the
running totals it needs (attempted credits, earned credits, weighted points) and a
reference to the best result. Callers never see those totals as fields; they ask
`getGpa()` and `getStanding()`, which is abstraction at work: how the GPA is computed is
hidden behind one method. `add` returns a description of what happened instead of printing it, so
`Transcript` holds the rules and `main` does all the printing. With the sample, the weighted points are
`3×4.00 + 3×3.50 + 3×0.00 + 1×3.75 = 26.25` over 10 attempted credits, so the GPA is
`2.625`, printed as `2.63`.

### Solution
```java
import java.util.Scanner;

class Fare {
    private final int from;
    private final int to;
    private final int amount;

    Fare(int from, int to) {
        this.from = from;
        this.to = to;
        this.amount = 20 + 5 * Math.abs(from - to);
    }

    public int getFrom() {
        return from;
    }

    public int getTo() {
        return to;
    }

    public int getAmount() {
        return amount;
    }
}

class MetroCard {
    private static final int DAILY_CAP = 100;
    private static final int MAX_BALANCE = 1000;

    private int balance;
    private int chargedToday;
    private int trips;
    private int totalCharged;

    public String topUp(int amount) {
        if (amount <= 0) {
            return "Invalid amount";
        }
        if (balance + amount > MAX_BALANCE) {
            return "Top-up refused: balance limit " + MAX_BALANCE;
        }
        balance += amount;
        return "Topped up " + amount + ", balance " + balance;
    }

    public String tap(Fare fare) {
        int charge = Math.min(fare.getAmount(), DAILY_CAP - chargedToday);
        if (charge > balance) {
            return "Insufficient balance: need " + charge + ", have " + balance;
        }
        balance -= charge;
        chargedToday += charge;
        totalCharged += charge;
        trips++;
        return "Trip " + fare.getFrom() + "->" + fare.getTo() + ": fare " + fare.getAmount()
                + ", charged " + charge + ", balance " + balance;
    }

    public String newDay() {
        chargedToday = 0;
        return "New day";
    }

    public String summary() {
        return "Trips: " + trips + ", total charged: " + totalCharged + ", balance: " + balance;
    }
}

public class MetroCardDemo {
    static boolean validStation(int s) {
        return s >= 1 && s <= 10;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        MetroCard card = new MetroCard();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("TOPUP")) {
                System.out.println(card.topUp(in.nextInt()));
            } else if (command.equals("TAP")) {
                int from = in.nextInt();
                int to = in.nextInt();
                if (!validStation(from) || !validStation(to)) {
                    System.out.println("Unknown station");
                } else if (from == to) {
                    System.out.println("Same station");
                } else {
                    System.out.println(card.tap(new Fare(from, to)));
                }
            } else if (command.equals("DAY")) {
                System.out.println(card.newDay());
            }
        }
        System.out.println(card.summary());
    }
}
```

### Explanation
`MetroCard` protects two invariants: the balance stays between 0 and 1000, and no more
than 100 Tk is charged in one day. Both are enforced in one place because every change
goes through `topUp`, `tap` or `newDay`; the fields are `private`, so no other code can
break the rules by assigning to them. The fare rule lives in the immutable `Fare`
class: once created, a fare cannot change, and its amount is always consistent with its
stations. `tap` shows abstraction: the caller hands over a `Fare` and gets back a
result line, without knowing about the daily cap. The cap works by charging
`min(fare, 100 − chargedToday)`, so the trip that crosses 100 pays only the remainder
and later trips pay 0 until `newDay()` resets the counter. Station validation stays in
`main` because it is about reading input, not about the card's own state.
