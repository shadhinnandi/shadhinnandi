# Practice Problems: Multithreaded Programming

These problems practise creating threads, waiting for them, protecting shared data and
using thread pools. Every program prints in a fixed order: threads store their results
and `main` prints them after `join()` (or after `Future.get()`), so the output is the
same on every run. Programs read input without prompts and print exactly the sample output.

## Problem 1: Range Sum on a Worker Thread
**Level:** Basic

### Problem Statement
Write a class `RangeSumThread` that **extends `Thread`**. Its constructor takes a thread
name and two numbers `from` and `to`. Its `run()` method adds all integers from `from`
to `to` (inclusive) and stores the sum in a field. It also stores the name of the thread
that executed `run()` (use `Thread.currentThread().getName()`).

The program reads two integers `from` and `to` (`from <= to`, both between 1 and
1,000,000). It creates a `RangeSumThread` named `summer`, starts it, waits for it with
`join()`, and prints:

```text
Sum of <from>..<to> = <sum>
Computed by thread: <name>
```

### Sample Input
```text
1 100000
```

### Sample Output
```text
Sum of 1..100000 = 5000050000
Computed by thread: summer
```

### Solution
```java
import java.util.Scanner;

class RangeSumThread extends Thread {
    private final long from;
    private final long to;
    private long sum;
    private String computedBy;

    RangeSumThread(String name, long from, long to) {
        super(name);
        this.from = from;
        this.to = to;
    }

    @Override
    public void run() {
        long total = 0;
        for (long i = from; i <= to; i++) {
            total += i;
        }
        sum = total;
        computedBy = Thread.currentThread().getName();
    }

    long getSum() {
        return sum;
    }

    String getComputedBy() {
        return computedBy;
    }
}

public class RangeSumWorker {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        long from = in.nextLong();
        long to = in.nextLong();

        RangeSumThread worker = new RangeSumThread("summer", from, to);
        worker.start();
        worker.join();

        System.out.println("Sum of " + from + ".." + to + " = " + worker.getSum());
        System.out.println("Computed by thread: " + worker.getComputedBy());
    }
}
```

### Explanation
- `start()` creates a new thread, and that thread calls `run()`. The output line
  `Computed by thread: summer` proves the sum was not computed by `main`.
- `main` calls `join()` before reading `getSum()`. Without `join()`, `main` could read
  the field while it is still 0.
- The sum uses `long` because 1 + 2 + ... + 1,000,000 is about 5 * 10^11, larger than
  the maximum `int`.
- `main` declares `throws InterruptedException` because `join()` can throw it.

## Problem 2: Factorials in Parallel
**Level:** Basic

### Problem Statement
Write a class `FactorialTask` that **implements `Runnable`**. It receives a number `k`
in its constructor; `run()` computes `k!` as a `long` and stores it in a field.

The program reads `n`, then `n` integers (each between 0 and 20). It creates one
`FactorialTask` and one `Thread` per number, starts **all** threads, then joins **all**
threads, and finally prints one line per number in input order: `k! = <value>`.

### Sample Input
```text
4
5 10 0 20
```

### Sample Output
```text
5! = 120
10! = 3628800
0! = 1
20! = 2432902008176640000
```

### Solution
```java
import java.util.Scanner;

class FactorialTask implements Runnable {
    private final int k;
    private long result;

    FactorialTask(int k) {
        this.k = k;
    }

    @Override
    public void run() {
        long product = 1;
        for (int i = 2; i <= k; i++) {
            product *= i;
        }
        result = product;
    }

    int getK() {
        return k;
    }

    long getResult() {
        return result;
    }
}

public class ParallelFactorials {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        FactorialTask[] tasks = new FactorialTask[n];
        Thread[] threads = new Thread[n];

        for (int i = 0; i < n; i++) {
            tasks[i] = new FactorialTask(in.nextInt());
            threads[i] = new Thread(tasks[i]);
            threads[i].start();
        }
        for (int i = 0; i < n; i++) {
            threads[i].join();
        }
        for (int i = 0; i < n; i++) {
            System.out.println(tasks[i].getK() + "! = " + tasks[i].getResult());
        }
    }
}
```

### Explanation
- The task (what to compute) and the thread (who runs it) are separate objects. The
  `tasks` array keeps the results; the `threads` array is only needed for `join()`.
- All threads start before the first `join()`, so they can run at the same time.
  Starting and joining inside one loop would run them one after another.
- Each task writes only its own `result` field, so no two threads share a variable and
  no locking is needed.
- Printing happens in a separate loop after all joins, in array order, so the output
  order never depends on which thread finished first.
- `20!` is the largest factorial that fits in a `long`; that is why the input stops at 20.

## Problem 3: Exam Countdown Timer
**Level:** Basic

### Problem Statement
An invigilator wants a countdown timer that runs on its own thread. Write a class
`CountdownTimer implements Runnable` that receives `n` and, in `run()`, prints the
numbers `n`, `n-1`, ..., `1` (one per line), sleeping 10 ms after each number to
simulate one second. Then it prints `Time is up!`.

`main` reads `n` (1 to 5), prints `Exam starts`, starts the timer thread, waits for it
with `join()`, and prints `Papers collected`. Inside `run()`, handle
`InterruptedException` by restoring the interrupt flag and returning.

### Sample Input
```text
3
```

### Sample Output
```text
Exam starts
3
2
1
Time is up!
Papers collected
```

### Solution
```java
import java.util.Scanner;

class CountdownTimer implements Runnable {
    private final int seconds;

    CountdownTimer(int seconds) {
        this.seconds = seconds;
    }

    @Override
    public void run() {
        for (int s = seconds; s >= 1; s--) {
            System.out.println(s);
            try {
                Thread.sleep(10);          // one simulated second
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
        }
        System.out.println("Time is up!");
    }
}

public class ExamCountdown {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        System.out.println("Exam starts");
        Thread timer = new Thread(new CountdownTimer(n), "timer");
        timer.start();
        timer.join();
        System.out.println("Papers collected");
    }
}
```

### Explanation
- `Thread.sleep(10)` pauses only the timer thread (the thread that calls it).
- The output order is fixed because only one thread prints at a time: `main` prints
  before `start()` and again only after `join()` has returned.
- `run()` cannot declare `throws InterruptedException` (the `Runnable.run()` method
  does not), so it catches the exception, restores the interrupt flag and stops.
- The total sleep is at most 5 * 10 ms, so the program finishes almost at once.

## Problem 4: Library Notice Board
**Level:** Basic

### Problem Statement
The library notice board shows a message, and the program also shows *which thread*
displayed it. Write a class `Notice implements Runnable` that stores a message. Its
`run()` prints `[<thread name>] <message>`, where the thread name comes from
`Thread.currentThread().getName()`.

The program reads a thread name (one word) on the first line and a message (a whole
line) on the second. It creates a `Thread` with that `Notice` and that name, then:

1. prints `State: ` and the thread's state,
2. calls `run()` directly on the `Thread` object,
3. calls `start()` and then `join()`,
4. prints `State: ` and the thread's state again.

### Sample Input
```text
notice-board
Library closes at 9 PM during exam week
```

### Sample Output
```text
State: NEW
[main] Library closes at 9 PM during exam week
[notice-board] Library closes at 9 PM during exam week
State: TERMINATED
```

### Solution
```java
import java.util.Scanner;

class Notice implements Runnable {
    private final String message;

    Notice(String message) {
        this.message = message;
    }

    @Override
    public void run() {
        String who = Thread.currentThread().getName();
        System.out.println("[" + who + "] " + message);
    }
}

public class NoticeBoard {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        String threadName = in.nextLine().trim();
        String message = in.nextLine();

        Thread board = new Thread(new Notice(message), threadName);
        System.out.println("State: " + board.getState());
        board.run();       // ordinary method call: executed by main
        board.start();     // a new thread executes run()
        board.join();
        System.out.println("State: " + board.getState());
    }
}
```

### Explanation
- `board.run()` is a normal method call. `Thread.run()` simply calls the `Runnable`'s
  `run()`, on the current thread, so the first notice shows `[main]`.
- `board.start()` creates the new thread named `notice-board`, and *that* thread calls
  `run()`, so the second notice shows the thread's own name.
- Calling `run()` first does not "use up" the thread: the state is still `NEW` until
  `start()` is called. After `join()` the state is `TERMINATED`.
- The message is read with `nextLine()` because it contains spaces.

## Problem 5: Campus Shuttle Ticket Scanners
**Level:** Basic

### Problem Statement
The campus shuttle has `k` ticket scanners, each running on its own thread. All scanners
add to one shared counter. Use an `AtomicInteger` for the counter.

The program reads `k`, then `k` integers: the number of scans each scanner performs.
Each scanner thread calls `incrementAndGet()` once per scan. After all threads are
joined, print the total number of scans and the fare collected at Tk 20 per scan:

```text
Total scans: <count>
Fare collected: Tk <amount>
```

### Sample Input
```text
3
12000 8000 15000
```

### Sample Output
```text
Total scans: 35000
Fare collected: Tk 700000
```

### Solution
```java
import java.util.Scanner;
import java.util.concurrent.atomic.AtomicInteger;

class TicketScanner implements Runnable {
    private final AtomicInteger counter;
    private final int scans;

    TicketScanner(AtomicInteger counter, int scans) {
        this.counter = counter;
        this.scans = scans;
    }

    @Override
    public void run() {
        for (int i = 0; i < scans; i++) {
            counter.incrementAndGet();
        }
    }
}

public class ShuttleScanners {
    static final int FARE = 20;

    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int k = in.nextInt();
        AtomicInteger totalScans = new AtomicInteger();
        Thread[] scanners = new Thread[k];

        for (int i = 0; i < k; i++) {
            scanners[i] = new Thread(new TicketScanner(totalScans, in.nextInt()));
            scanners[i].start();
        }
        for (int i = 0; i < k; i++) {
            scanners[i].join();
        }
        System.out.println("Total scans: " + totalScans.get());
        System.out.println("Fare collected: Tk " + totalScans.get() * FARE);
    }
}
```

### Explanation
- All scanner threads share one `AtomicInteger`. `incrementAndGet()` does the
  read-add-write as one indivisible step, so no scan is lost even when threads run at
  the same time.
- With a plain `int` field and `count++`, the total would often be smaller than 35000,
  and different on every run.
- The total is read only after every thread is joined, so all increments are finished.
- The task class is called `TicketScanner`, not `Scanner`, because `java.util.Scanner`
  is already imported and the two names would clash.

## Problem 6: One Account, Two ATMs
**Level:** Intermediate

### Problem Statement
A student's account is used by two ATMs at the same time. ATM A performs `d`
deposits of `x` Tk each; ATM B performs `w` withdrawals of `y` Tk each. Each ATM runs on
its own thread and both share one `SharedAccount` object.

Write `SharedAccount` with `synchronized` methods `deposit(long)`, `withdraw(long)`
(returns `false` and changes nothing if the balance is too small) and `getBalance()`.
Write a `Runnable` class `Atm` that performs its operations and counts failed
withdrawals.

Input: the opening balance, then `d x`, then `w y`. The input guarantees
`w × y <= opening balance`, so no withdrawal can fail whatever the order. Print:

```text
ATM A deposited <d> x Tk <x>
ATM B withdrew <w> x Tk <y> (<f> failed)
Final balance: Tk <balance>
```

### Sample Input
```text
20000
20000 1
15000 1
```

### Sample Output
```text
ATM A deposited 20000 x Tk 1
ATM B withdrew 15000 x Tk 1 (0 failed)
Final balance: Tk 25000
```

### Solution
```java
import java.util.Scanner;

class SharedAccount {
    private long balance;

    SharedAccount(long opening) {
        balance = opening;
    }

    synchronized void deposit(long amount) {
        balance += amount;
    }

    synchronized boolean withdraw(long amount) {
        if (amount > balance) {
            return false;
        }
        balance -= amount;
        return true;
    }

    synchronized long getBalance() {
        return balance;
    }
}

class Atm implements Runnable {
    private final SharedAccount account;
    private final boolean depositing;
    private final int count;
    private final long amount;
    private int failed;

    Atm(SharedAccount account, boolean depositing, int count, long amount) {
        this.account = account;
        this.depositing = depositing;
        this.count = count;
        this.amount = amount;
    }

    @Override
    public void run() {
        for (int i = 0; i < count; i++) {
            if (depositing) {
                account.deposit(amount);
            } else if (!account.withdraw(amount)) {
                failed++;
            }
        }
    }

    int getFailed() {
        return failed;
    }
}

public class TwoAtms {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        SharedAccount account = new SharedAccount(in.nextLong());
        int d = in.nextInt();
        long x = in.nextLong();
        int w = in.nextInt();
        long y = in.nextLong();

        Atm atmA = new Atm(account, true, d, x);
        Atm atmB = new Atm(account, false, w, y);
        Thread a = new Thread(atmA);
        Thread b = new Thread(atmB);
        a.start();
        b.start();
        a.join();
        b.join();

        System.out.println("ATM A deposited " + d + " x Tk " + x);
        System.out.println("ATM B withdrew " + w + " x Tk " + y + " (" + atmB.getFailed() + " failed)");
        System.out.println("Final balance: Tk " + account.getBalance());
    }
}
```

### Explanation
`balance += amount` is really three steps (read, add, write). Without `synchronized`,
ATM A and ATM B could both read the same old balance and one update would be lost, so
the final balance would be wrong and different on each run. Marking `deposit`,
`withdraw` and `getBalance` as `synchronized` means only one thread at a time can run
any of them on the same account object, so every update sees the result of the
previous one. The check and the change in `withdraw` are inside the same synchronized
method; if they were separate calls, another thread could change the balance between
them. `failed` is only touched by ATM B's own thread and read after `join()`, so it
needs no locking.

## Problem 7: Word Counts with Futures
**Level:** Intermediate

### Problem Statement
A notice board app counts the words in each notice. Read `n`, then `n` lines of text.
Submit one `Callable<Integer>` per line to a fixed thread pool of 3 threads; each task
returns the number of words in its line (words are separated by one or more spaces; an
empty line has 0 words). Collect the `Future` objects in submission order and print:

```text
Line <i>: <count> words
...
Total: <sum> words
```

Shut the pool down at the end.

### Sample Input
```text
3
Java threads run tasks in parallel

Each   future returns one result
```

### Sample Output
```text
Line 1: 6 words
Line 2: 0 words
Line 3: 5 words
Total: 11 words
```

### Solution
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

class WordCountTask implements Callable<Integer> {
    private final String line;

    WordCountTask(String line) {
        this.line = line;
    }

    @Override
    public Integer call() {
        String trimmed = line.trim();
        if (trimmed.isEmpty()) {
            return 0;
        }
        return trimmed.split("\\s+").length;
    }
}

public class NoticeWordCounts {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());

        ExecutorService pool = Executors.newFixedThreadPool(3);
        List<Future<Integer>> results = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            results.add(pool.submit(new WordCountTask(in.nextLine())));
        }

        int total = 0;
        for (int i = 0; i < results.size(); i++) {
            int count = results.get(i).get();
            System.out.println("Line " + (i + 1) + ": " + count + " words");
            total += count;
        }
        System.out.println("Total: " + total + " words");
        pool.shutdown();
    }
}
```

### Explanation
A `Callable` is like a `Runnable` that returns a value. `submit` hands the task to the
pool and immediately returns a `Future`, a placeholder for the result. The tasks may
finish in any order, but `main` calls `get()` on the futures in the order they were
submitted; `get()` waits until that particular result is ready. That is why the output
order never changes. The first line is read with `nextLine()` and parsed, so no
leftover newline is left behind before the text lines. `get()` can throw
`ExecutionException` (the task itself failed) or `InterruptedException` (the waiting
thread was interrupted); `main` declares both. `shutdown()` lets the pool's threads
finish and end, so the program can exit.

## Problem 8: Counting Primes in Parallel
**Level:** Intermediate

### Problem Statement
Count the primes from 1 to `N` using `k` threads. Split the range into `k` parts of
`N / k` numbers each; the last part also takes any remainder. Each part is handled by a
`PrimeCounter` thread object that stores its own count. After joining all threads,
print each part and the total:

```text
Range <from>-<to>: <count> primes
...
Total: <total> primes
```

Use trial division up to the square root (`i * i <= n`).

### Sample Input
```text
100 4
```

### Sample Output
```text
Range 1-25: 9 primes
Range 26-50: 6 primes
Range 51-75: 6 primes
Range 76-100: 4 primes
Total: 25 primes
```

### Solution
```java
import java.util.Scanner;

class PrimeCounter extends Thread {
    private final int from;
    private final int to;
    private int count;

    PrimeCounter(int from, int to) {
        this.from = from;
        this.to = to;
    }

    static boolean isPrime(int n) {
        if (n < 2) {
            return false;
        }
        for (int i = 2; i * i <= n; i++) {
            if (n % i == 0) {
                return false;
            }
        }
        return true;
    }

    @Override
    public void run() {
        for (int n = from; n <= to; n++) {
            if (isPrime(n)) {
                count++;
            }
        }
    }

    int getFrom() {
        return from;
    }

    int getTo() {
        return to;
    }

    int getCount() {
        return count;
    }
}

public class ParallelPrimes {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int k = in.nextInt();
        int size = n / k;

        PrimeCounter[] parts = new PrimeCounter[k];
        for (int i = 0; i < k; i++) {
            int from = i * size + 1;
            int to = (i == k - 1) ? n : (i + 1) * size;
            parts[i] = new PrimeCounter(from, to);
            parts[i].start();
        }

        int total = 0;
        for (PrimeCounter part : parts) {
            part.join();
            System.out.println("Range " + part.getFrom() + "-" + part.getTo() + ": "
                    + part.getCount() + " primes");
            total += part.getCount();
        }
        System.out.println("Total: " + total + " primes");
    }
}
```

### Explanation
The parts do not overlap and each thread writes only its own `count` field, so there is
no shared data and no locking is needed. This is the easiest kind of parallel program:
split the work, let each thread work on its own piece, then combine. `main` joins each
thread before reading its count; `join()` also guarantees that the thread's writes are
visible to `main`. Printing happens only in `main`, in part order, so the output is the
same on every run even though the threads finish in different orders. Note that the
parts are equal in size but not in work: checking large numbers takes longer, so the
last thread usually finishes last.

## Problem 9: Hall Booking Without Overselling
**Level:** Intermediate

### Problem Statement
A convocation hall has `S` seats. `k` booking agents run at the same time; agent `i`
tries to book `r[i]` seats, one seat per call to `hall.tryBook()`. `tryBook()` returns
`true` and takes a seat if one is free, otherwise `false`.

Write a `Hall` class whose `tryBook()` is safe under concurrency, and an `Agent`
`Runnable`. Which agent gets which seat depends on timing, so print only facts that do
not depend on timing:

```text
Seats: <S>
Requested: <sum of r>
Booked: <booked>
Refused: <refused>
Seats left: <left>
```

### Sample Input
```text
500 4
200 150 180 90
```

### Sample Output
```text
Seats: 500
Requested: 620
Booked: 500
Refused: 120
Seats left: 0
```

### Solution
```java
import java.util.Scanner;

class Hall {
    private final int capacity;
    private int booked;

    Hall(int capacity) {
        this.capacity = capacity;
    }

    synchronized boolean tryBook() {
        if (booked == capacity) {
            return false;
        }
        booked++;
        return true;
    }

    synchronized int getBooked() {
        return booked;
    }

    int getCapacity() {
        return capacity;
    }
}

class Agent implements Runnable {
    private final Hall hall;
    private final int requests;
    private int refused;

    Agent(Hall hall, int requests) {
        this.hall = hall;
        this.requests = requests;
    }

    @Override
    public void run() {
        for (int i = 0; i < requests; i++) {
            if (!hall.tryBook()) {
                refused++;
            }
        }
    }

    int getRefused() {
        return refused;
    }
}

public class HallBooking {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        Hall hall = new Hall(in.nextInt());
        int k = in.nextInt();

        Agent[] agents = new Agent[k];
        Thread[] threads = new Thread[k];
        int requested = 0;
        for (int i = 0; i < k; i++) {
            int r = in.nextInt();
            requested += r;
            agents[i] = new Agent(hall, r);
            threads[i] = new Thread(agents[i]);
            threads[i].start();
        }

        int refused = 0;
        for (int i = 0; i < k; i++) {
            threads[i].join();
            refused += agents[i].getRefused();
        }

        System.out.println("Seats: " + hall.getCapacity());
        System.out.println("Requested: " + requested);
        System.out.println("Booked: " + hall.getBooked());
        System.out.println("Refused: " + refused);
        System.out.println("Seats left: " + (hall.getCapacity() - hall.getBooked()));
    }
}
```

### Explanation
"Is a seat free?" and "take it" must happen as one step. If two agents could both see
the last free seat before either took it, the hall would be oversold. Making
`tryBook()` `synchronized` puts the check and the update under one lock. The totals are
deterministic (`Booked` is always `min(S, requested)`), but the split between agents is
not, which is why the program does not print per-agent results. Each agent counts its
own refusals in a private field, and `main` adds them up only after `join()`.

## Problem 10: Parallel Chunk Sort and Merge
**Level:** Advanced

### Problem Statement
Sorting large mark lists can be split across threads. Read `n` and `k`, then `n`
integers. Split the list into `k` chunks of `n / k` numbers (the last chunk also takes
the remainder). Sort each chunk on its own thread (`Arrays.sort` on a copy of the
chunk is fine). After joining, print every sorted chunk, then merge the chunks one by
one (merge chunk 1 with chunk 2, then the result with chunk 3, and so on) using a
`merge(int[] a, int[] b)` method you write yourself, and print the result:

```text
Chunk <i>: <numbers>
...
Sorted: <numbers>
```

### Sample Input
```text
10 3
42 7 19 3 88 15 61 27 5 50
```

### Sample Output
```text
Chunk 1: 7 19 42
Chunk 2: 3 15 88
Chunk 3: 5 27 50 61
Sorted: 3 5 7 15 19 27 42 50 61 88
```

### Solution
```java
import java.util.Arrays;
import java.util.Scanner;

class ChunkSorter implements Runnable {
    private final int[] chunk;

    ChunkSorter(int[] chunk) {
        this.chunk = chunk;
    }

    @Override
    public void run() {
        Arrays.sort(chunk);
    }

    int[] getChunk() {
        return chunk;
    }
}

public class ParallelChunkSort {
    static int[] merge(int[] a, int[] b) {
        int[] result = new int[a.length + b.length];
        int i = 0;
        int j = 0;
        int k = 0;
        while (i < a.length && j < b.length) {
            if (a[i] <= b[j]) {
                result[k++] = a[i++];
            } else {
                result[k++] = b[j++];
            }
        }
        while (i < a.length) {
            result[k++] = a[i++];
        }
        while (j < b.length) {
            result[k++] = b[j++];
        }
        return result;
    }

    static String join(int[] values) {
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < values.length; i++) {
            if (i > 0) {
                sb.append(' ');
            }
            sb.append(values[i]);
        }
        return sb.toString();
    }

    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int k = in.nextInt();
        int[] data = new int[n];
        for (int i = 0; i < n; i++) {
            data[i] = in.nextInt();
        }

        int size = n / k;
        ChunkSorter[] sorters = new ChunkSorter[k];
        Thread[] threads = new Thread[k];
        for (int i = 0; i < k; i++) {
            int from = i * size;
            int to = (i == k - 1) ? n : from + size;
            sorters[i] = new ChunkSorter(Arrays.copyOfRange(data, from, to));
            threads[i] = new Thread(sorters[i]);
            threads[i].start();
        }

        int[] sorted = new int[0];
        for (int i = 0; i < k; i++) {
            threads[i].join();
            int[] chunk = sorters[i].getChunk();
            System.out.println("Chunk " + (i + 1) + ": " + join(chunk));
            sorted = merge(sorted, chunk);
        }
        System.out.println("Sorted: " + join(sorted));
    }
}
```

### Explanation
Each thread receives its own copy of a chunk (`Arrays.copyOfRange`), so no two threads
ever touch the same array and no locking is needed. After `join()`, `main` can safely
read the sorted chunk. Merging two sorted arrays is the heart of merge sort: walk both
arrays with two indexes and always take the smaller front element; when one array runs
out, copy the rest of the other. Merging starts from an empty array, so the first merge
simply copies chunk 1. Sorting is the expensive part (`O(m log m)` per chunk) and runs
in parallel; the merges are cheap linear passes. Real libraries use the same idea, for
example `Arrays.parallelSort`.

## Problem 11: Bank Transfers Without Deadlock
**Level:** Advanced

### Problem Statement
A bank processes transfers between `m` accounts (numbered from 1) using `k` worker
threads. Transfer `i` (counting from 0) is handled by worker `i % k`. A transfer must
lock **both** accounts so that no other transfer changes them halfway.

If two workers lock accounts in different orders (one locks 1 then 2, the other locks
2 then 1), each can wait forever for the other: a **deadlock**. Avoid it by always
locking the account with the smaller number first.

Input: `m`, the `m` opening balances, then `t k`, then `t` lines `from to amount`. The
input guarantees that every account's opening balance covers all its outgoing
transfers, so no transfer can fail. Print:

```text
Total before: Tk <sum>
Transfers done: <t>
Account <id>: Tk <balance>
...
Total after: Tk <sum>
```

### Sample Input
```text
3
1000 500 800
6 2
1 2 200
2 3 100
3 1 300
1 3 150
2 1 50
3 2 400
```

### Sample Output
```text
Total before: Tk 2300
Transfers done: 6
Account 1: Tk 1000
Account 2: Tk 950
Account 3: Tk 350
Total after: Tk 2300
```

### Solution
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;
import java.util.concurrent.atomic.AtomicInteger;

class Account {
    private final int id;
    private long balance;

    Account(int id, long balance) {
        this.id = id;
        this.balance = balance;
    }

    int getId() {
        return id;
    }

    long getBalance() {
        return balance;
    }

    void add(long amount) {
        balance += amount;
    }
}

class Transfer {
    final Account from;
    final Account to;
    final long amount;

    Transfer(Account from, Account to, long amount) {
        this.from = from;
        this.to = to;
        this.amount = amount;
    }

    /** Locks the lower-numbered account first, so two transfers never deadlock. */
    void execute() {
        Account first = from.getId() < to.getId() ? from : to;
        Account second = (first == from) ? to : from;
        synchronized (first) {
            synchronized (second) {
                from.add(-amount);
                to.add(amount);
            }
        }
    }
}

class Worker implements Runnable {
    private final List<Transfer> jobs = new ArrayList<>();
    private final AtomicInteger done;

    Worker(AtomicInteger done) {
        this.done = done;
    }

    void assign(Transfer t) {
        jobs.add(t);
    }

    @Override
    public void run() {
        for (Transfer t : jobs) {
            t.execute();
            done.incrementAndGet();
        }
    }
}

public class SafeTransfers {
    static long total(Account[] accounts) {
        long sum = 0;
        for (Account a : accounts) {
            synchronized (a) {
                sum += a.getBalance();
            }
        }
        return sum;
    }

    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int m = in.nextInt();
        Account[] accounts = new Account[m];
        for (int i = 0; i < m; i++) {
            accounts[i] = new Account(i + 1, in.nextLong());
        }
        int t = in.nextInt();
        int k = in.nextInt();

        AtomicInteger done = new AtomicInteger();
        Worker[] workers = new Worker[k];
        for (int i = 0; i < k; i++) {
            workers[i] = new Worker(done);
        }
        for (int i = 0; i < t; i++) {
            Account from = accounts[in.nextInt() - 1];
            Account to = accounts[in.nextInt() - 1];
            workers[i % k].assign(new Transfer(from, to, in.nextLong()));
        }

        System.out.println("Total before: Tk " + total(accounts));
        Thread[] threads = new Thread[k];
        for (int i = 0; i < k; i++) {
            threads[i] = new Thread(workers[i]);
            threads[i].start();
        }
        for (Thread thread : threads) {
            thread.join();
        }

        System.out.println("Transfers done: " + done.get());
        for (Account a : accounts) {
            System.out.println("Account " + a.getId() + ": Tk " + a.getBalance());
        }
        System.out.println("Total after: Tk " + total(accounts));
    }
}
```

### Explanation
Each transfer holds two locks, one per account, because it changes two objects that
must stay consistent with each other. Deadlock needs a cycle of waiting: worker 1 holds
account A and waits for B while worker 2 holds B and waits for A. Locking in one global
order (smaller id first) makes such a cycle impossible: whoever gets the smaller
account first will also be able to get the larger one. Because the input guarantees
that no transfer fails, the final balances do not depend on the order in which the
workers run, so the output is deterministic. The total is the same before and after:
money moves between accounts but is never created or lost, which is a good invariant to
check in any banking program.

## Problem 12: Matrix Multiplication with a Thread Pool
**Level:** Advanced

### Problem Statement
Multiply an `r × n` matrix `A` by an `n × c` matrix `B`. Each row of the result
depends only on one row of `A` and all of `B`, so the rows can be computed in parallel.
Create a fixed thread pool of 4 threads and submit one `Callable<long[]>` per result
row. Collect the futures in row order and print the result matrix, one row per line,
numbers separated by single spaces. If the inner sizes do not match, print
`Cannot multiply <r>x<n> by <n2>x<c>` instead.

Input: `r n`, then `r` rows of `A`; `n2 c`, then `n2` rows of `B`.

### Sample Input
```text
2 3
1 2 3
4 5 6
3 2
7 8
9 10
11 12
```

### Sample Output
```text
58 64
139 154
```

### Solution
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

class RowTask implements Callable<long[]> {
    private final long[] row;
    private final long[][] b;

    RowTask(long[] row, long[][] b) {
        this.row = row;
        this.b = b;
    }

    @Override
    public long[] call() {
        int columns = b[0].length;
        long[] result = new long[columns];
        for (int j = 0; j < columns; j++) {
            long sum = 0;
            for (int x = 0; x < row.length; x++) {
                sum += row[x] * b[x][j];
            }
            result[j] = sum;
        }
        return result;
    }
}

public class ParallelMatrix {
    static long[][] read(Scanner in, int rows, int cols) {
        long[][] m = new long[rows][cols];
        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                m[i][j] = in.nextLong();
            }
        }
        return m;
    }

    public static void main(String[] args) throws InterruptedException, ExecutionException {
        Scanner in = new Scanner(System.in);
        int r = in.nextInt();
        int n = in.nextInt();
        long[][] a = read(in, r, n);
        int n2 = in.nextInt();
        int c = in.nextInt();
        long[][] b = read(in, n2, c);
        if (n != n2) {
            System.out.println("Cannot multiply " + r + "x" + n + " by " + n2 + "x" + c);
            return;
        }

        ExecutorService pool = Executors.newFixedThreadPool(4);
        try {
            List<Future<long[]>> rows = new ArrayList<>();
            for (int i = 0; i < r; i++) {
                rows.add(pool.submit(new RowTask(a[i], b)));
            }
            for (Future<long[]> future : rows) {
                long[] row = future.get();
                StringBuilder line = new StringBuilder();
                for (int j = 0; j < row.length; j++) {
                    if (j > 0) {
                        line.append(' ');
                    }
                    line.append(row[j]);
                }
                System.out.println(line);
            }
        } finally {
            pool.shutdown();
        }
    }
}
```

### Explanation
Every task only *reads* the shared matrices `A` and `B` and writes into its own new
`result` array, so the tasks never interfere and need no locks. Result row `i` is the
dot product of row `i` of `A` with every column of `B`; for the sample,
`1×7 + 2×9 + 3×11 = 58`. The futures are stored in row order and `get()` is called in
that order, so the printed matrix is correct even if row 2 finishes before row 1.
`shutdown()` is in a `finally` block so the pool is shut down even if a task throws.
The size check comes first because multiplying matrices whose inner dimensions differ
is undefined.
