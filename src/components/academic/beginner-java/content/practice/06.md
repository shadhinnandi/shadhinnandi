# Practice Problems: Constructors and Object Lifecycle

These problems practise building objects correctly: overloaded and chained constructors,
validation and `final` fields, copy constructors with shallow and deep copies, and the
end of an object's life (garbage-collection eligibility and `try-with-resources`).
Programs read input without prompts and print exactly the sample output.

## Problem 1: Canteen Menu Items
**Level:** Basic

### Problem Statement
Write a class `MenuItem` with a name, a price in Tk and a `boolean` that says whether it
is available. Give it three constructors:

- `MenuItem(String name, int price, boolean available)` stores all three values;
- `MenuItem(String name, int price)` makes an available item;
- `MenuItem(String name)` makes an available item with the standard price of Tk 20.

The two shorter constructors must chain with `this(...)`; only the complete constructor
assigns fields.

Input: line 1 has a name, a price and `true`/`false`; line 2 has a name and a price;
line 3 has only a name (all names are one word). Create one item from each line with the
matching constructor and print each as `<name> - Tk <price> (available)` or
`<name> - Tk <price> (sold out)`.

### Sample Input
```text
Khichuri 80 false
Singara 10
Tea
```

### Sample Output
```text
Khichuri - Tk 80 (sold out)
Singara - Tk 10 (available)
Tea - Tk 20 (available)
```

### Solution
```java
import java.util.Scanner;

class MenuItem {
    private String name;
    private int price;
    private boolean available;

    MenuItem(String name, int price, boolean available) {
        this.name = name;
        this.price = price;
        this.available = available;
    }

    MenuItem(String name, int price) {
        this(name, price, true);
    }

    MenuItem(String name) {
        this(name, 20);
    }

    String describe() {
        String state = available ? "available" : "sold out";
        return name + " - Tk " + price + " (" + state + ")";
    }
}

public class CanteenMenu {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String name1 = in.next();
        int price1 = in.nextInt();
        boolean available1 = in.nextBoolean();
        String name2 = in.next();
        int price2 = in.nextInt();
        String name3 = in.next();

        MenuItem first = new MenuItem(name1, price1, available1);
        MenuItem second = new MenuItem(name2, price2);
        MenuItem third = new MenuItem(name3);

        System.out.println(first.describe());
        System.out.println(second.describe());
        System.out.println(third.describe());
    }
}
```

### Explanation
The compiler chooses a constructor by the number and types of the arguments.
`new MenuItem(name3)` runs `MenuItem(String)`, which calls `this(name, 20)`, which in turn
calls `this(name, price, true)`. Every item is therefore built by the same complete
constructor, so a future rule (for example, "price must not be negative") needs to be
added in only one place. `nextBoolean()` reads the words `true` and `false` directly.

## Problem 2: Student Records with CGPA Validation
**Level:** Basic

### Problem Statement
Write a class `Student` with a private ID (`String`) and a private CGPA (`double`). Its
constructor `Student(String id, double cgpa)` must reject a CGPA below 0.00 or above
4.00: it prints `Invalid CGPA <cgpa> for <id>, using 0.00` (CGPA with 2 decimals) and
stores 0.00 instead. Add a method `describe()` that returns `<id>: CGPA <cgpa>` with 2
decimals.

Input: an integer `n`, then `n` lines, each with an ID and a CGPA. For each line, create
a `Student` and print its description. Validation messages appear while the object is
being created, before its description.

### Sample Input
```text
3
011221001 3.75
011221002 4.20
011221003 -1
```

### Sample Output
```text
011221001: CGPA 3.75
Invalid CGPA 4.20 for 011221002, using 0.00
011221002: CGPA 0.00
Invalid CGPA -1.00 for 011221003, using 0.00
011221003: CGPA 0.00
```

### Solution
```java
import java.util.Scanner;

class Student {
    private String id;
    private double cgpa;

    Student(String id, double cgpa) {
        if (cgpa < 0.0 || cgpa > 4.0) {
            System.out.printf("Invalid CGPA %.2f for %s, using 0.00%n", cgpa, id);
            cgpa = 0.0;
        }
        this.id = id;
        this.cgpa = cgpa;
    }

    String describe() {
        return String.format("%s: CGPA %.2f", id, cgpa);
    }
}

public class StudentRecords {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String id = in.next();
            double cgpa = in.nextDouble();
            Student s = new Student(id, cgpa);
            System.out.println(s.describe());
        }
    }
}
```

### Explanation
The constructor is the object's gatekeeper: the check happens before the value is stored,
so a `Student` never holds an impossible CGPA, not even for a moment. The parameter
`cgpa` is corrected first and then copied into the field `this.cgpa`. Because there is no
setter for the CGPA, the constructor is the only way in, and every object is valid from
its first moment. In Chapter 11 you will learn to throw an exception here instead of
silently replacing the value.

## Problem 3: Vehicle with a Fixed Registration Number
**Level:** Basic

### Problem Statement
A campus transport office tracks its vehicles. Write a class `Vehicle` with a `private
final String regNo` and a `private int odometer` (in km). The constructor
`Vehicle(String regNo, int startKm)` stores both; a negative `startKm` is stored as 0.
A method `drive(int km)` adds `km` to the odometer if `km > 0`; otherwise it prints
`Ignored invalid trip <km>` and changes nothing. A method `describe()` returns
`<regNo>: <odometer> km`.

Input: a registration number and a starting reading, then an integer `n`, then `n` trip
lengths. Print the description once after creation and once after every trip.

### Sample Input
```text
CAMPUS-BUS-07 -20
3
120
-5
40
```

### Sample Output
```text
CAMPUS-BUS-07: 0 km
CAMPUS-BUS-07: 120 km
Ignored invalid trip -5
CAMPUS-BUS-07: 120 km
CAMPUS-BUS-07: 160 km
```

### Solution
```java
import java.util.Scanner;

class Vehicle {
    private final String regNo;
    private int odometer;

    Vehicle(String regNo, int startKm) {
        this.regNo = regNo;
        if (startKm < 0) {
            startKm = 0;
        }
        this.odometer = startKm;
    }

    void drive(int km) {
        if (km > 0) {
            odometer = odometer + km;
        } else {
            System.out.println("Ignored invalid trip " + km);
        }
    }

    String describe() {
        return regNo + ": " + odometer + " km";
    }
}

public class VehicleLog {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Vehicle bus = new Vehicle(in.next(), in.nextInt());
        System.out.println(bus.describe());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            bus.drive(in.nextInt());
            System.out.println(bus.describe());
        }
    }
}
```

### Explanation
The registration number identifies the vehicle for its whole life, so it is `final`: the
constructor must assign it exactly once, and no method may change it afterwards (a
`setRegNo` method would not even compile). The odometer changes, so it is not `final`, but
it is still protected: it starts non-negative and only `drive` can increase it. Fields that
never change and fields that change under rules are the two halves of a well-designed
class. (In `new Vehicle(in.next(), in.nextInt())` Java evaluates arguments from left to
right, so the registration number is read first.)

## Problem 4: Reward Points and Initialization Order
**Level:** Basic

### Problem Statement
A canteen gives every new reward account 10 joining points, then a 5-point welcome bonus,
then the referral points of the person who invited the student. Model this with a class
`RewardAccount` that uses all three initialization places, in this order:

1. a field initializer `private int points = 10;`
2. an instance initializer block that prints `Field initializer gave <points> points`,
   adds 5, and prints `Initializer block added welcome bonus: <points>`;
3. a constructor `RewardAccount(String owner, int referral)` that prints
   `Constructor starts with <points> points`, adds `referral`, and prints
   `<owner> ends with <points> points`.

Input: two lines, each with an owner name and referral points. Create one account per
line, printing `Creating account for <owner>` before each `new`.

### Sample Input
```text
Mitu 7
Rafi 0
```

### Sample Output
```text
Creating account for Mitu
Field initializer gave 10 points
Initializer block added welcome bonus: 15
Constructor starts with 15 points
Mitu ends with 22 points
Creating account for Rafi
Field initializer gave 10 points
Initializer block added welcome bonus: 15
Constructor starts with 15 points
Rafi ends with 15 points
```

### Solution
```java
import java.util.Scanner;

class RewardAccount {
    private String owner;
    private int points = 10;

    {
        System.out.println("Field initializer gave " + points + " points");
        points = points + 5;
        System.out.println("Initializer block added welcome bonus: " + points);
    }

    RewardAccount(String owner, int referral) {
        System.out.println("Constructor starts with " + points + " points");
        this.owner = owner;
        points = points + referral;
        System.out.println(owner + " ends with " + points + " points");
    }

    String getOwner() {
        return owner;
    }
}

public class RewardPoints {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        for (int i = 0; i < 2; i++) {
            String owner = in.next();
            int referral = in.nextInt();
            System.out.println("Creating account for " + owner);
            RewardAccount account = new RewardAccount(owner, referral);
            account.getOwner();
        }
    }
}
```

### Explanation
During `new`, Java first gives `points` its default value 0, then runs the field
initializer (10) and the instance initializer block (15) in the order they appear in the
class, and only then the constructor body. That is why the constructor already sees 15.
The whole sequence runs again for every new object: each account gets its own `points`
field and its own trip through the initializers. In real code you would usually write
this set-up directly in the constructor; the block is used here to make the order
visible.

## Problem 5: Rescheduling a Class with a Copy Constructor
**Level:** Basic

### Problem Statement
Write a class `ClassTime` with private `hour` (0–23) and `minute` (0–59) fields, a
constructor `ClassTime(int hour, int minute)`, a **copy constructor**
`ClassTime(ClassTime other)`, a method `delay(int minutes)` that moves the time forward
(wrapping past midnight), and a method `format()` that returns `HH:MM` with two digits
each.

Input: an hour, a minute and a delay in minutes. Create the original time, make a copy
with the copy constructor, delay only the copy, and print:

```text
Original class: <original>
Make-up class: <copy>
```

### Sample Input
```text
11 40 95
```

### Sample Output
```text
Original class: 11:40
Make-up class: 13:15
```

### Solution
```java
import java.util.Scanner;

class ClassTime {
    private int hour;
    private int minute;

    ClassTime(int hour, int minute) {
        this.hour = hour;
        this.minute = minute;
    }

    ClassTime(ClassTime other) {
        this.hour = other.hour;
        this.minute = other.minute;
    }

    void delay(int minutes) {
        int total = hour * 60 + minute + minutes;
        hour = (total / 60) % 24;
        minute = total % 60;
    }

    String format() {
        return String.format("%02d:%02d", hour, minute);
    }
}

public class Reschedule {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int hour = in.nextInt();
        int minute = in.nextInt();
        int delay = in.nextInt();

        ClassTime original = new ClassTime(hour, minute);
        ClassTime makeUp = new ClassTime(original);
        makeUp.delay(delay);

        System.out.println("Original class: " + original.format());
        System.out.println("Make-up class: " + makeUp.format());
    }
}
```

### Explanation
Java has no built-in copy constructor, so `ClassTime(ClassTime other)` is an ordinary
constructor written by hand. It may read `other.hour` directly because private access is
per class, not per object. Both fields are primitives, so copying their values already
gives a fully independent object: here shallow and deep copy are the same thing. Writing
`ClassTime makeUp = original;` instead would copy only the reference, and delaying
`makeUp` would also move the original class.

## Problem 6: Course Sections with Constructor Chaining
**Level:** Intermediate

### Problem Statement
Write a class `Section` with a `final` course code, a capacity and a room, and three
constructors:

- `Section(String code, int capacity, String room)`: the complete constructor. A
  capacity outside 10–60 is not allowed: print
  `Capacity <capacity> not allowed for <code>, using 40` and use 40.
- `Section(String code, int capacity)`: room `TBA`.
- `Section(String code)`: capacity 40, room `TBA`.

The shorter constructors must chain with `this(...)`, so the capacity rule is written
only once.

Input: an integer `n`, then `n` lines. Each line starts with `k` (1, 2 or 3), the number
of values that follow: `1 <code>`, `2 <code> <capacity>` or
`3 <code> <capacity> <room>`. Create each section with the matching constructor and print
`<code> | capacity <capacity> | room <room>`. Finally print
`Sections without a room: <count>`.

### Sample Input
```text
4
1 CSE1115
2 MAT1101 35
3 PHY1103 55 Room-402
2 ENG1011 90
```

### Sample Output
```text
CSE1115 | capacity 40 | room TBA
MAT1101 | capacity 35 | room TBA
PHY1103 | capacity 55 | room Room-402
Capacity 90 not allowed for ENG1011, using 40
ENG1011 | capacity 40 | room TBA
Sections without a room: 3
```

### Solution
```java
import java.util.Scanner;

class Section {
    private final String code;
    private int capacity;
    private String room;

    Section(String code, int capacity, String room) {
        this.code = code;
        if (capacity < 10 || capacity > 60) {
            System.out.println("Capacity " + capacity + " not allowed for "
                    + code + ", using 40");
            capacity = 40;
        }
        this.capacity = capacity;
        this.room = room;
    }

    Section(String code, int capacity) {
        this(code, capacity, "TBA");
    }

    Section(String code) {
        this(code, 40);
    }

    boolean hasRoom() {
        return !room.equals("TBA");
    }

    String describe() {
        return code + " | capacity " + capacity + " | room " + room;
    }
}

public class SectionSetup {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int withoutRoom = 0;
        for (int i = 0; i < n; i++) {
            int k = in.nextInt();
            String code = in.next();
            Section section;
            if (k == 1) {
                section = new Section(code);
            } else if (k == 2) {
                section = new Section(code, in.nextInt());
            } else {
                int capacity = in.nextInt();
                String room = in.next();
                section = new Section(code, capacity, room);
            }
            System.out.println(section.describe());
            if (!section.hasRoom()) {
                withoutRoom++;
            }
        }
        System.out.println("Sections without a room: " + withoutRoom);
    }
}
```

### Explanation
- The chain is `Section(code)` → `Section(code, 40)` → `Section(code, 40, "TBA")`. All
  roads lead to the complete constructor, so the capacity check cannot be skipped.
- `code` is `final` and assigned in the complete constructor; the shorter constructors
  count as assigning it because they chain there.
- `main` declares `Section section;` without a value and assigns it in every branch of
  the `if`, so the compiler knows it is set before `describe()` is called.
- `hasRoom()` uses `equals`, not `==`, to compare `String` contents.

## Problem 7: Make-up Exam with a Deep Copy
**Level:** Intermediate

### Problem Statement
Write a class `TimeSlot` with a day number, an hour, a minute and a duration in minutes,
a copy constructor, a method `shift(int minutes)` that moves the start forward (minutes
roll over into hours, hours into days), and `describe()` returning
`day <d> at <HH:MM> for <duration> min`.

Write a class `Exam` with a `final` course code and a `TimeSlot`:

- `Exam(String course, TimeSlot slot)` stores its **own copy** of `slot`;
- `Exam(Exam other, int shiftMinutes)` creates a make-up exam: it chains to the first
  constructor with `other`'s course and slot, then shifts its own slot.

Input: a course code; a day, hour, minute and duration; a make-up shift in minutes. In
`main`, create a `TimeSlot`, the regular exam and the make-up exam, and print both
exams. Then `main` reuses its own `TimeSlot` object for a quiz by shifting it 60 minutes;
print the quiz slot and the regular exam again (it must not change).

### Sample Input
```text
CSE2215
14 10 30 120
1530
```

### Sample Output
```text
Regular: CSE2215, day 14 at 10:30 for 120 min
Make-up: CSE2215, day 15 at 12:00 for 120 min
Quiz slot: day 14 at 11:30 for 120 min
Regular: CSE2215, day 14 at 10:30 for 120 min
```

### Solution
```java
import java.util.Scanner;

class TimeSlot {
    private int day;
    private int hour;
    private int minute;
    private int duration;

    TimeSlot(int day, int hour, int minute, int duration) {
        this.day = day;
        this.hour = hour;
        this.minute = minute;
        this.duration = duration;
    }

    TimeSlot(TimeSlot other) {
        this(other.day, other.hour, other.minute, other.duration);
    }

    void shift(int minutes) {
        int total = hour * 60 + minute + minutes;
        day = day + total / (24 * 60);
        total = total % (24 * 60);
        hour = total / 60;
        minute = total % 60;
    }

    String describe() {
        return String.format("day %d at %02d:%02d for %d min", day, hour, minute, duration);
    }
}

class Exam {
    private final String course;
    private final TimeSlot slot;

    Exam(String course, TimeSlot slot) {
        this.course = course;
        this.slot = new TimeSlot(slot);
    }

    Exam(Exam other, int shiftMinutes) {
        this(other.course, other.slot);
        slot.shift(shiftMinutes);
    }

    String describe() {
        return course + ", " + slot.describe();
    }
}

public class MakeUpExam {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String course = in.next();
        TimeSlot slot = new TimeSlot(in.nextInt(), in.nextInt(), in.nextInt(), in.nextInt());
        int shift = in.nextInt();

        Exam regular = new Exam(course, slot);
        Exam makeUp = new Exam(regular, shift);
        System.out.println("Regular: " + regular.describe());
        System.out.println("Make-up: " + makeUp.describe());

        slot.shift(60);
        System.out.println("Quiz slot: " + slot.describe());
        System.out.println("Regular: " + regular.describe());
    }
}
```

### Explanation
`TimeSlot` is mutable, so sharing one between objects is dangerous. The `Exam` constructor
therefore stores `new TimeSlot(slot)`, a private copy (often called a *defensive copy*).
Because the make-up constructor chains to that constructor, it also gets its own copy,
and shifting it leaves the regular exam alone. The last two lines prove the second
benefit: when `main` later changes the `TimeSlot` it passed in, the regular exam is not
affected. The field `slot` can still be `final`: `final` fixes which object the field
refers to, not the contents of that object. The `TimeSlot` copy constructor itself
chains with `this(...)` to the four-value constructor.

## Problem 8: Lab Printer Session
**Level:** Intermediate

### Problem Statement
Write a class `PrintSession` that implements `AutoCloseable`:

- The constructor `PrintSession(String student, int sheets)` loads paper into the tray. The
  tray holds at most 50 sheets: a larger number is reduced to 50 with the message
  `Tray holds at most 50 sheets`. Then it prints
  `Session opened for <student> with <sheets> sheets`.
- `print(int pages)` numbers each job from 1 and prints one of:
  `Job <j>: printed <pages> page(s)`, `Job <j>: invalid page count <pages>` (for
  `pages <= 0`), or `Job <j>: not enough paper (<pages> needed, <left> left)`.
- `isEmpty()` returns `true` when no sheets are left.
- `close()` prints `Session closed for <student>: <p> page(s) printed, Tk <cost>`, where
  each page costs Tk 2.

Input: a student name, a number of sheets, an integer `n` and `n` page counts. Use the
session in a `try-with-resources` block. After a successful job that empties the tray,
print `Tray empty, ending session early` and stop processing jobs. After the `try` block,
print `After the try block`.

### Sample Input
```text
Mitu 20
6
5
12
-3
6
3
2
```

### Sample Output
```text
Session opened for Mitu with 20 sheets
Job 1: printed 5 page(s)
Job 2: printed 12 page(s)
Job 3: invalid page count -3
Job 4: not enough paper (6 needed, 3 left)
Job 5: printed 3 page(s)
Tray empty, ending session early
Session closed for Mitu: 20 page(s) printed, Tk 40
After the try block
```

### Solution
```java
import java.util.Scanner;

class PrintSession implements AutoCloseable {
    private final String student;
    private int sheetsLeft;
    private int printed;
    private int jobNumber;

    PrintSession(String student, int sheets) {
        this.student = student;
        if (sheets > 50) {
            System.out.println("Tray holds at most 50 sheets");
            sheets = 50;
        }
        this.sheetsLeft = sheets;
        System.out.println("Session opened for " + student + " with " + sheets + " sheets");
    }

    void print(int pages) {
        jobNumber++;
        if (pages <= 0) {
            System.out.println("Job " + jobNumber + ": invalid page count " + pages);
        } else if (pages > sheetsLeft) {
            System.out.println("Job " + jobNumber + ": not enough paper (" + pages
                    + " needed, " + sheetsLeft + " left)");
        } else {
            sheetsLeft = sheetsLeft - pages;
            printed = printed + pages;
            System.out.println("Job " + jobNumber + ": printed " + pages + " page(s)");
        }
    }

    boolean isEmpty() {
        return sheetsLeft == 0;
    }

    public void close() {
        System.out.println("Session closed for " + student + ": " + printed
                + " page(s) printed, Tk " + printed * 2);
    }
}

public class LabPrinter {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String student = in.next();
        int sheets = in.nextInt();
        int n = in.nextInt();
        try (PrintSession session = new PrintSession(student, sheets)) {
            for (int i = 0; i < n; i++) {
                session.print(in.nextInt());
                if (session.isEmpty()) {
                    System.out.println("Tray empty, ending session early");
                    break;
                }
            }
        }
        System.out.println("After the try block");
    }
}
```

### Explanation
The printer session is a *resource*: it must be closed at a known moment, not "some time
later". The garbage collector cannot promise that, so the class implements
`AutoCloseable` and `main` opens it in `try (...)`. When the loop `break`s out early, the
block still ends and Java calls `close()` automatically, before `After the try block` is
printed. The constructor validates the paper count before storing it, and `isEmpty()`
lets `main` decide what to do without reaching into the object's fields. (If the tray
starts with 0 sheets, the first job will be refused and the loop never stops early.)

## Problem 9: Which Objects Are Eligible for Garbage Collection?
**Level:** Intermediate

### Problem Statement
An object becomes eligible for garbage collection when no variable can reach it. Simulate
three reference variables `a`, `b` and `c` of a class `Tag` (each `Tag` has a `final int
id`; the first object created gets id 1, the next id 2, and so on). All three start as
`null`. Commands:

- `NEW x`: `x = new Tag(<next id>)`
- `COPY x y`: `x = y` (now both refer to the same object, or both are `null`)
- `NULL x`: `x = null`

Put `a`, `b`, `c` as fields in a class `Roots` with methods `get(String name)`,
`set(String name, Tag value)` and `holders(int id)`, which returns the names of the
variables that refer to the object with that id.

Input: an integer `n` and `n` commands. Afterwards, for every created object in id order,
print `Object <id>: reachable from <names>` (names separated by spaces, in the order a, b,
c) or `Object <id>: eligible for GC`. Finally print `Eligible: <e> of <total>`.

### Sample Input
```text
6
NEW a
NEW b
COPY c a
NEW a
NULL c
COPY b a
```

### Sample Output
```text
Object 1: eligible for GC
Object 2: eligible for GC
Object 3: reachable from a b
Eligible: 2 of 3
```

### Solution
```java
import java.util.Scanner;

class Tag {
    private final int id;

    Tag(int id) {
        this.id = id;
    }

    int getId() {
        return id;
    }
}

class Roots {
    private Tag a;
    private Tag b;
    private Tag c;

    Tag get(String name) {
        if (name.equals("a")) {
            return a;
        } else if (name.equals("b")) {
            return b;
        }
        return c;
    }

    void set(String name, Tag value) {
        if (name.equals("a")) {
            a = value;
        } else if (name.equals("b")) {
            b = value;
        } else {
            c = value;
        }
    }

    String holders(int id) {
        String result = "";
        if (a != null && a.getId() == id) {
            result = result + " a";
        }
        if (b != null && b.getId() == id) {
            result = result + " b";
        }
        if (c != null && c.getId() == id) {
            result = result + " c";
        }
        return result;
    }
}

public class GcEligibility {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Roots roots = new Roots();
        int created = 0;
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            String x = in.next();
            if (command.equals("NEW")) {
                created++;
                roots.set(x, new Tag(created));
            } else if (command.equals("COPY")) {
                roots.set(x, roots.get(in.next()));
            } else {
                roots.set(x, null);
            }
        }
        int eligible = 0;
        for (int id = 1; id <= created; id++) {
            String names = roots.holders(id);
            if (names.isEmpty()) {
                System.out.println("Object " + id + ": eligible for GC");
                eligible++;
            } else {
                System.out.println("Object " + id + ": reachable from" + names);
            }
        }
        System.out.println("Eligible: " + eligible + " of " + created);
    }
}
```

### Explanation
The program uses real Java references: `COPY c a` really makes `c` refer to the same
`Tag` object as `a`. Object 1 loses its references in two steps (`a` is reassigned, then
`c` is set to `null`); object 2 loses its only reference when `b` is reassigned. Those
are exactly the ways an object becomes unreachable. Note that "eligible" does not mean
"already collected": the JVM's garbage collector reclaims such objects at a time it
chooses. Each `holders` check tests for `null` first, because calling `getId()` through a
`null` reference would crash the program.

## Problem 10: Assignment Drafts with Mutable Text
**Level:** Intermediate

### Problem Statement
Write a class `Draft` with a `String` title, a `StringBuilder` body and an `int`
version. The constructor `Draft(String title, String text)` creates version 1. The copy
constructor `Draft(Draft other)` creates the next version: same title, the same text in
a **new** `StringBuilder`, and `other`'s version plus 1. Add `append(String text)` (adds a
space and the text), `rename(String title)` and `describe()` returning
`<title> v<version>: <body>`.

Input: a title line and a body line. Create the original draft and immediately a copy
with the copy constructor. Then read an integer `n` and `n` command lines: `O <text>`
appends to the original, `C <text>` appends to the copy, `R <text>` renames the copy.
Finally print `Original: <original>` and `Copy: <copy>`.

### Sample Input
```text
Lab Report
Objective: test constructors.
4
C Added results table.
O Fixed a typo.
R Lab Report Final
C Added conclusion.
```

### Sample Output
```text
Original: Lab Report v1: Objective: test constructors. Fixed a typo.
Copy: Lab Report Final v2: Objective: test constructors. Added results table. Added conclusion.
```

### Solution
```java
import java.util.Scanner;

class Draft {
    private String title;
    private StringBuilder body;
    private int version;

    Draft(String title, String text) {
        this.title = title;
        this.body = new StringBuilder(text);
        this.version = 1;
    }

    Draft(Draft other) {
        this.title = other.title;
        this.body = new StringBuilder(other.body);
        this.version = other.version + 1;
    }

    void append(String text) {
        body.append(" ");
        body.append(text);
    }

    void rename(String title) {
        this.title = title;
    }

    String describe() {
        return title + " v" + version + ": " + body;
    }
}

public class DraftVersions {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String title = in.nextLine();
        String text = in.nextLine();
        Draft original = new Draft(title, text);
        Draft copy = new Draft(original);

        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String target = in.next();
            String value = in.nextLine().trim();
            if (target.equals("O")) {
                original.append(value);
            } else if (target.equals("C")) {
                copy.append(value);
            } else {
                copy.rename(value);
            }
        }
        System.out.println("Original: " + original.describe());
        System.out.println("Copy: " + copy.describe());
    }
}
```

### Explanation
The copy constructor treats each field according to its type. `version` is a primitive,
so its value is simply computed and stored. `title` is a `String`, which is immutable, so
sharing the reference is safe: `rename` puts a *new* reference into the copy and the
original keeps its own. `body` is a mutable `StringBuilder`, so the copy gets
`new StringBuilder(other.body)`; with `this.body = other.body` instead, every `append` on
one draft would appear in the other. A copy constructor does not have to copy everything
unchanged: here it also increases the version number.

**Level:** Advanced

### Problem Statement

- `Instructor`: a `final` name and an office; `moveOffice(String office)`; `describe()`

- `Schedule`: a day and a start hour, a copy constructor, `change(String day, int hour)`,

### Solution
```java
import java.util.Scanner;

class Instructor {
    private final String name;
    private String office;

    Instructor(String name, String office) {
        this.name = name;
        this.office = office;
    }

    void moveOffice(String office) {
        this.office = office;
    }

    String getName() {
        return name;
    }

    String describe() {
        return name + " (" + office + ")";
    }
}

class Schedule {
    private String day;
    private int hour;

    Schedule(String day, int hour) {
        this.day = day;
        this.hour = hour;
    }

    Schedule(Schedule other) {
        this(other.day, other.hour);
    }

    void change(String day, int hour) {
        this.day = day;
        this.hour = hour;
    }

    String describe() {
        return String.format("%s %02d:00", day, hour);
    }
}

class Section {
    private final String code;
    private String name;
    private Instructor instructor;
    private Schedule schedule;
    private final int seats;
    private int enrolled;

    Section(String code, String name, Instructor instructor, Schedule schedule, int seats) {
        this.code = code;
        this.name = name;
        this.instructor = instructor;
        this.schedule = new Schedule(schedule);
        this.seats = seats;
        this.enrolled = 0;
    }

    Section(Section other, String newName) {
        this.code = other.code;
        this.name = newName;
        this.instructor = other.instructor;            // same person: share
        this.schedule = new Schedule(other.schedule);  // own timetable: copy
        this.seats = other.seats;
        this.enrolled = 0;                             // a new section starts empty
    }

    String getName() {
        return name;
    }

    Instructor getInstructor() {
        return instructor;
    }

    int seatsLeft() {
        return seats - enrolled;
    }

    boolean enroll(int count) {
        if (count < 1 || count > seatsLeft()) {
            return false;
        }
        enrolled = enrolled + count;
        return true;
    }

    boolean reschedule(String day, int hour) {
        if (hour < 8 || hour > 17) {
            return false;
        }
        schedule.change(day, hour);
        return true;
    }

    String describe() {
        return code + "-" + name + " | " + schedule.describe() + " | "
                + instructor.describe() + " | " + enrolled + "/" + seats;
    }
}

public class NewSection {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String code = in.next();
        String oldName = in.next();
        Instructor teacher = new Instructor(in.next(), in.next());
        Schedule schedule = new Schedule(in.next(), in.nextInt());
        int seats = in.nextInt();
        int alreadyEnrolled = in.nextInt();

        Section oldSection = new Section(code, oldName, teacher, schedule, seats);
        oldSection.enroll(alreadyEnrolled);

        Section newSection = new Section(oldSection, in.next());
        System.out.println("Section " + newSection.getName() + " created from " + oldName);

        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("RESCHEDULE")) {
                String day = in.next();
                int hour = in.nextInt();
                if (newSection.reschedule(day, hour)) {
                    System.out.printf("%s rescheduled to %s %02d:00%n",
                            newSection.getName(), day, hour);
                } else {
                    System.out.println("Invalid hour " + hour);
                }
            } else if (command.equals("ENROLL")) {
                int k = in.nextInt();
                if (newSection.enroll(k)) {
                    System.out.println("Enrolled " + k + " in " + newSection.getName()
                            + " (" + newSection.seatsLeft() + " seats left)");
                } else {
                    System.out.println("Cannot enroll " + k + " in " + newSection.getName()
                            + ": only " + newSection.seatsLeft() + " seats left");
                }
            } else {
                String office = in.next();
                Instructor person = newSection.getInstructor();
                person.moveOffice(office);
                System.out.println(person.getName() + " moved to " + office);
            }
        }
        System.out.println(oldSection.describe());
        System.out.println(newSection.describe());
    }
}
```

### Explanation
- Shallow or deep is decided **per field**. The schedule must be copied, otherwise
  rescheduling section B would also move section A. The instructor must be **shared**:
  there is one real Nusrat, so when she changes office, both sections must show it. The
  output proves both decisions: A keeps `Sun 09:00`, yet both show the new office.
- The copy constructor also *resets* `enrolled` to 0. A copy constructor builds a new,
  valid object from an old one; it does not have to clone every value blindly.
- The first constructor also copies the `Schedule` it receives, so `main`'s `schedule`
  variable cannot change a section later.
- `code` and `seats` are `final`, and both constructors assign them exactly once.
- The rules (`enroll`, `reschedule`) live in `Section` and return `boolean`, so `main`
  only reads input and prints.

## Problem 12: Bank Transfers that Roll Back Automatically
**Level:** Advanced

### Problem Statement
Write three classes:

- `Account`: a `final` owner name and a balance in Tk (a negative starting balance is
  stored as 0).
- `BankConnection implements AutoCloseable`: prints `Connection opened` when created.
  `begin(Account from, Account to)` returns a new numbered `Transfer` (numbers start at
  1). It counts started and committed transfers, and `close()` prints
  `Connection closed: <committed> of <started> transfer(s) committed`.
- `Transfer implements AutoCloseable`: `stage(int amount)` succeeds only if
  `0 < amount <= from's balance` and remembers the amount; `commit()` moves the staged
  money and marks the transfer committed. `close()` prints
  `Transfer #<k> committed: Tk <amount> from <from> to <to>` if it was committed,
  otherwise `Transfer #<k> rolled back` (balances unchanged).

Input: two lines `<owner> <balance>`, then `n` and `n` requests
`<from> <to> <amount> <Y|N>` (the names are the two owners; `Y` means the customer
confirms). Process each request in a method that opens the transfer with
`try-with-resources`: if staging fails, print `Cannot stage Tk <amount> from <from>` and
return; if not confirmed, print `Not confirmed by <from>`; otherwise commit. All
transfers happen inside one `try-with-resources` block for the connection; at its end
print each balance as `<owner>: Tk <balance>`. After the connection is closed, print
`Program finished`.

### Sample Input
```text
Rahim 1000
Karim 500
4
Rahim Karim 300 Y
Karim Rahim 900 Y
Rahim Karim 200 N
Karim Rahim 800 Y
```

### Sample Output
```text
Connection opened
Transfer #1 committed: Tk 300 from Rahim to Karim
Cannot stage Tk 900 from Karim
Transfer #2 rolled back
Not confirmed by Rahim
Transfer #3 rolled back
Transfer #4 committed: Tk 800 from Karim to Rahim
Rahim: Tk 1500
Karim: Tk 0
Connection closed: 2 of 4 transfer(s) committed
Program finished
```

### Solution
```java
import java.util.Scanner;

class Account {
    private final String owner;
    private int balance;

    Account(String owner, int balance) {
        this.owner = owner;
        if (balance < 0) {
            balance = 0;
        }
        this.balance = balance;
    }

    String getOwner() {
        return owner;
    }

    int getBalance() {
        return balance;
    }

    void add(int amount) {
        balance = balance + amount;
    }
}

class BankConnection implements AutoCloseable {
    private int started;
    private int committed;

    BankConnection() {
        System.out.println("Connection opened");
    }

    Transfer begin(Account from, Account to) {
        started++;
        return new Transfer(started, from, to, this);
    }

    void recordCommit() {
        committed++;
    }

    public void close() {
        System.out.println("Connection closed: " + committed + " of " + started
                + " transfer(s) committed");
    }
}

class Transfer implements AutoCloseable {
    private final int number;
    private final Account from;
    private final Account to;
    private final BankConnection connection;
    private int staged;
    private boolean committed;

    Transfer(int number, Account from, Account to, BankConnection connection) {
        this.number = number;
        this.from = from;
        this.to = to;
        this.connection = connection;
    }

    boolean stage(int amount) {
        if (amount <= 0 || amount > from.getBalance()) {
            return false;
        }
        staged = amount;
        return true;
    }

    void commit() {
        from.add(-staged);
        to.add(staged);
        committed = true;
        connection.recordCommit();
    }

    public void close() {
        if (committed) {
            System.out.println("Transfer #" + number + " committed: Tk " + staged
                    + " from " + from.getOwner() + " to " + to.getOwner());
        } else {
            System.out.println("Transfer #" + number + " rolled back");
        }
    }
}

public class SafeTransfers {
    static void process(BankConnection connection, Account from, Account to,
            int amount, boolean confirmed) {
        try (Transfer transfer = connection.begin(from, to)) {
            if (!transfer.stage(amount)) {
                System.out.println("Cannot stage Tk " + amount + " from " + from.getOwner());
                return;
            }
            if (confirmed) {
                transfer.commit();
            } else {
                System.out.println("Not confirmed by " + from.getOwner());
            }
        }
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Account first = new Account(in.next(), in.nextInt());
        Account second = new Account(in.next(), in.nextInt());
        int n = in.nextInt();
        try (BankConnection connection = new BankConnection()) {
            for (int i = 0; i < n; i++) {
                String fromName = in.next();
                in.next();
                int amount = in.nextInt();
                boolean confirmed = in.next().equals("Y");
                if (fromName.equals(first.getOwner())) {
                    process(connection, first, second, amount, confirmed);
                } else {
                    process(connection, second, first, amount, confirmed);
                }
            }
            System.out.println(first.getOwner() + ": Tk " + first.getBalance());
            System.out.println(second.getOwner() + ": Tk " + second.getBalance());
        }
        System.out.println("Program finished");
    }
}
```

### Explanation
- Each transfer is a short-lived resource opened inside `process`. Whatever path the
  method takes (an early `return` after a failed stage, an unconfirmed request, or a
  commit), `close()` runs at the end of the `try` block and reports the result. That
  guarantee is what makes "roll back unless committed" safe.
- Staging only *remembers* the amount; balances change only in `commit()`. So a
  rolled-back transfer has nothing to undo.
- The connection is the outer resource: it stays open for all transfers and is closed
  last, after the balances are printed, which is why `Connection closed` comes just
  before `Program finished`.
- `Transfer` keeps a reference to its `BankConnection` (given in its constructor) so it
  can report commits back; the connection owns the counters, so no global variables are
  needed.
- In `main`, the second name of each request is read and skipped with `in.next()`,
  because the receiver is always the other account.

## Problem 13: Payroll with Payslip Snapshots
**Level:** Advanced

### Problem Statement
Write a class `Employee` with a `final` name, a grade (1–3), a basic salary that depends

Constructors:

### Solution
```java
import java.util.Scanner;

class Employee {
    private final String name;
    private int grade;
    private int allowance;

    Employee(String name, int grade, int allowance) {
        this.name = name;
        if (grade < 1 || grade > 3) {
            System.out.println("Grade " + grade + " invalid for " + name + ", using 1");
            grade = 1;
        }
        if (allowance < 0) {
            System.out.println("Negative allowance " + allowance + " for " + name
                    + ", using 0");
            allowance = 0;
        }
        this.grade = grade;
        this.allowance = allowance;
    }

    Employee(String name, int grade) {
        this(name, grade, 0);
    }

    Employee(String name) {
        this(name, 1);
    }

    void promote() {
        if (grade == 3) {
            System.out.println(name + " is already at the top grade");
        } else {
            grade++;
            System.out.println(name + " promoted to grade " + grade);
        }
    }

    String getName() {
        return name;
    }

    int getGrade() {
        return grade;
    }

    int getBasic() {
        if (grade == 1) {
            return 20000;
        } else if (grade == 2) {
            return 30000;
        }
        return 45000;
    }

    int getAllowance() {
        return allowance;
    }
}

class Payslip {
    private final String month;
    private final String name;
    private final int grade;
    private final int basic;
    private final int houseRent;
    private final int allowance;

    Payslip(Employee e, String month) {
        this.month = month;
        this.name = e.getName();
        this.grade = e.getGrade();
        this.basic = e.getBasic();
        this.houseRent = basic * 40 / 100;
        this.allowance = e.getAllowance();
    }

    int gross() {
        return basic + houseRent + allowance;
    }

    String describe() {
        return month + ": " + name + " | grade " + grade + " | basic " + basic
                + " | house " + houseRent + " | allowance " + allowance
                + " | gross " + gross();
    }
}

public class PayrollSnapshots {
    static Employee readEmployee(Scanner in) {
        int k = in.nextInt();
        String name = in.next();
        if (k == 1) {
            return new Employee(name);
        } else if (k == 2) {
            return new Employee(name, in.nextInt());
        }
        int grade = in.nextInt();
        int allowance = in.nextInt();
        return new Employee(name, grade, allowance);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Employee e1 = readEmployee(in);
        Employee e2 = readEmployee(in);
        Employee e3 = readEmployee(in);

        Payslip jan1 = new Payslip(e1, "January");
        System.out.println("January payslips:");
        System.out.println("  " + jan1.describe());
        System.out.println("  " + new Payslip(e2, "January").describe());
        System.out.println("  " + new Payslip(e3, "January").describe());

        int m = in.nextInt();
        for (int i = 0; i < m; i++) {
            String name = in.next();
            if (name.equals(e1.getName())) {
                e1.promote();
            } else if (name.equals(e2.getName())) {
                e2.promote();
            } else if (name.equals(e3.getName())) {
                e3.promote();
            } else {
                System.out.println("No employee named " + name);
            }
        }

        System.out.println("February payslips:");
        System.out.println("  " + new Payslip(e1, "February").describe());
        System.out.println("  " + new Payslip(e2, "February").describe());
        System.out.println("  " + new Payslip(e3, "February").describe());
        System.out.println("Stored January payslip of " + e1.getName() + ":");
        System.out.println("  " + jan1.describe());
    }
}
```

### Explanation
- The three `Employee` constructors chain to one complete constructor, so both
  validation rules are written once and apply to every way of hiring.
- The basic salary is not stored: `getBasic()` derives it from the grade, so the two can
  never disagree after a promotion.
- `Payslip`'s constructor takes another object but is not a copy constructor of
  `Employee`: it copies the *values* it needs into its own `final` fields. That makes a
  payslip a snapshot. Had it stored a reference to the `Employee` and read the grade
  later, the January payslip would silently change after the promotion, which is wrong
  for a salary record.
- The last line proves it: Imran's stored January payslip still shows grade 2.
- Objects such as `new Payslip(e2, "January")` that are printed and then not stored
  become unreachable right after the line runs; the garbage collector will reclaim them
  when it decides to.

## Problem 14: Game Checkpoints with Deep Copies

### Problem Statement
In a small console adventure, the hero can save a checkpoint and load it later. Write:

- `Stats` (hp, coins) with a copy constructor, `hit(int damage)` (hp never goes below 0)
  and `addCoins(int k)`;
- `Hero` with a `final` name, a `Position` and a `Stats`. `Hero(String name)` starts at
  (0, 0) with 100 HP and 0 coins. The copy constructor `Hero(Hero other)` is a **deep
  copy**.

Input: the hero's name and `n` commands. Each command prints one line:

- `MOVE dx dy` → `Moved to (x, y)`
- `HIT d` → `HP: <hp>`, or `HP: 0 (fainted)` when it reaches 0
- `COIN k` → `Coins: <coins>`
- `SAVE` → stores a copy of the hero as the checkpoint → `Checkpoint saved`
- `LOAD` → replaces the hero with a copy of the checkpoint → `Checkpoint loaded`, or
  `No checkpoint yet` if nothing was saved
- `SHOW` → `<name> at (x, y) | HP <hp> | coins <coins>`

Loading twice must give the same result both times, so the checkpoint itself must never
change.

### Sample Input
```text
Tanvir
13

SHOW
MOVE 2 3
COIN 5

HIT 40
MOVE -1 0
SHOW
LOAD

LOAD

SHOW
```

### Sample Output
```text

Moved to (2, 3)
Coins: 5
Checkpoint saved
```

### Solution
```java
import java.util.Scanner;

class Position {
    private int x;
    private int y;

    Position(int x, int y) {
        this.x = x;
        this.y = y;
    }

    Position(Position other) {
        this(other.x, other.y);
    }

    void move(int dx, int dy) {
        x = x + dx;
        y = y + dy;
    }

    String describe() {
        return "(" + x + ", " + y + ")";
    }
}

class Stats {
    private int hp;
    private int coins;

    Stats(int hp, int coins) {
        this.hp = hp;
        this.coins = coins;
    }

    Stats(Stats other) {
        this(other.hp, other.coins);
    }

    void hit(int damage) {
        hp = hp - damage;
        if (hp < 0) {
            hp = 0;
        }
    }

    void addCoins(int k) {
        coins = coins + k;
    }

    int getHp() {
        return hp;
    }

    int getCoins() {
        return coins;
    }
}

class Hero {
    private final String name;
    private final Position position;
    private final Stats stats;

    Hero(String name) {
        this.name = name;
        this.position = new Position(0, 0);
        this.stats = new Stats(100, 0);
    }

    Hero(Hero other) {
        this.name = other.name;
        this.position = new Position(other.position);
        this.stats = new Stats(other.stats);
    }

    Position getPosition() {
        return position;
    }

    Stats getStats() {
        return stats;
    }

    String describe() {
        return name + " at " + position.describe() + " | HP " + stats.getHp()
                + " | coins " + stats.getCoins();
    }
}

public class Checkpoints {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Hero hero = new Hero(in.next());
        Hero checkpoint = null;
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("MOVE")) {
                int dx = in.nextInt();
                int dy = in.nextInt();
                hero.getPosition().move(dx, dy);
                System.out.println("Moved to " + hero.getPosition().describe());
            } else if (command.equals("HIT")) {
                hero.getStats().hit(in.nextInt());
                int hp = hero.getStats().getHp();
                System.out.println(hp == 0 ? "HP: 0 (fainted)" : "HP: " + hp);
            } else if (command.equals("COIN")) {
                hero.getStats().addCoins(in.nextInt());
                System.out.println("Coins: " + hero.getStats().getCoins());
            } else if (command.equals("SAVE")) {
                checkpoint = new Hero(hero);
                System.out.println("Checkpoint saved");
            } else if (command.equals("LOAD")) {
                if (checkpoint == null) {
                    System.out.println("No checkpoint yet");
                } else {
                    hero = new Hero(checkpoint);
                    System.out.println("Checkpoint loaded");
                }
            } else {
                System.out.println(hero.describe());
            }
        }
    }
}
```

### Explanation
- `SAVE` must copy deeply. With a shallow copy, the checkpoint would share the hero's
  `Position` and `Stats`, so every later `MOVE` or `HIT` would also change the "saved"
  game.
- `LOAD` must copy **again**: `hero = new Hero(checkpoint)`. Writing
  `hero = checkpoint` would make the hero and the checkpoint the same object, and the
  `HIT 100` after the first load would destroy the checkpoint. The second `LOAD` in the
  sample proves the checkpoint survived: the hero is back at (2, 3) with 100 HP.
- After `hero = new Hero(checkpoint)`, the previous hero object has no reference left, so
  it becomes eligible for garbage collection. No code is needed to "delete" it.
- The fields of `Hero` are `final`: a hero always keeps the same `Position` and `Stats`
  objects, while their contents change through their methods.
- `getPosition()` and `getStats()` return the hero's own objects so `main` can call their
  methods; Chapter 08 discusses the trade-offs of returning references like this.

## Problem 15: A Mark-and-Sweep Garbage Collector Simulation
**Level:** Advanced

### Problem Statement
Real garbage collectors find unreachable objects by starting from the program's live
variables (the *roots*) and following references. Simulate a simple **mark-and-sweep**
collector. (This is a model to understand reachability; the JVM's real collectors are
more advanced, and they run at times the JVM chooses.)

- `Node`: a `final int id` (1, 2, 3, ... in creation order), a `next` reference to
  another `Node` (or `null`), a `marked` flag, and a link used by the heap to keep its
  list of all objects.
- `Heap`: keeps every created node in a linked list in creation order. `create()` makes
  a new node. `collect(Node a, Node b, Node c)` performs one GC: unmark all nodes, mark
  every node reachable from the roots `a`, `b`, `c` by following `next` (stop at a node
  that is already marked, so cycles do not loop forever), then remove every unmarked
  node from the list.

Roots are three variables `a`, `b`, `c` (all `null` at first). Commands:

- `NEW x`: `x` refers to a new node
- `SET x y`: `x` refers to the same node as `y`
- `NULL x`: `x = null`
- `LINK x y`: the node of `x` gets `next` = the node of `y`; if `x` is `null`, print
  `Cannot link: <x> is null`
- `GC`: run a collection and print
  `GC #<k>: collected <ids or none> | live <ids or none>` (ids in creation order,
  separated by spaces)

Input: an integer `n` and `n` commands.

### Sample Input
```text
14
NEW a
NEW b
LINK a b
LINK b a
NEW c
LINK c a
NULL a
NULL b
LINK a c
GC
NEW a
SET c a
GC
GC
```

### Sample Output
```text
Cannot link: a is null
GC #1: collected none | live 1 2 3
GC #2: collected 1 2 3 | live 4
GC #3: collected none | live 4
```

### Solution
```java
import java.util.Scanner;

class Node {
    private final int id;
    private Node next;
    private boolean marked;
    private Node nextInHeap;

    Node(int id) {
        this.id = id;
    }

    int getId() {
        return id;
    }

    Node getNext() {
        return next;
    }

    void setNext(Node next) {
        this.next = next;
    }

    boolean isMarked() {
        return marked;
    }

    void setMarked(boolean marked) {
        this.marked = marked;
    }

    Node getNextInHeap() {
        return nextInHeap;
    }

    void setNextInHeap(Node node) {
        nextInHeap = node;
    }
}

class Heap {
    private Node first;
    private Node last;
    private int created;
    private int collections;

    Node create() {
        created++;
        Node node = new Node(created);
        if (first == null) {
            first = node;
        } else {
            last.setNextInHeap(node);
        }
        last = node;
        return node;
    }

    private void mark(Node root) {
        Node current = root;
        while (current != null && !current.isMarked()) {
            current.setMarked(true);
            current = current.getNext();
        }
    }

    void collect(Node a, Node b, Node c) {
        collections++;
        for (Node n = first; n != null; n = n.getNextInHeap()) {
            n.setMarked(false);
        }
        mark(a);
        mark(b);
        mark(c);

        String collected = "";
        String live = "";
        Node previous = null;
        for (Node n = first; n != null; n = n.getNextInHeap()) {
            if (n.isMarked()) {
                live = live + " " + n.getId();
                previous = n;
            } else {
                collected = collected + " " + n.getId();
                if (previous == null) {
                    first = n.getNextInHeap();
                } else {
                    previous.setNextInHeap(n.getNextInHeap());
                }
            }
        }
        last = previous;
        System.out.println("GC #" + collections + ": collected " + orNone(collected)
                + " | live " + orNone(live));
    }

    private String orNone(String ids) {
        if (ids.isEmpty()) {
            return "none";
        }
        return ids.trim();
    }
}

class Roots {
    private Node a;
    private Node b;
    private Node c;

    Node get(String name) {
        if (name.equals("a")) {
            return a;
        } else if (name.equals("b")) {
            return b;
        }
        return c;
    }

    void set(String name, Node node) {
        if (name.equals("a")) {
            a = node;
        } else if (name.equals("b")) {
            b = node;
        } else {
            c = node;
        }
    }

    void collect(Heap heap) {
        heap.collect(a, b, c);
    }
}

public class MarkAndSweep {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Heap heap = new Heap();
        Roots roots = new Roots();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("GC")) {
                roots.collect(heap);
            } else if (command.equals("NEW")) {
                roots.set(in.next(), heap.create());
            } else if (command.equals("NULL")) {
                roots.set(in.next(), null);
            } else if (command.equals("SET")) {
                String x = in.next();
                roots.set(x, roots.get(in.next()));
            } else {
                String x = in.next();
                String y = in.next();
                Node source = roots.get(x);
                if (source == null) {
                    System.out.println("Cannot link: " + x + " is null");
                } else {
                    source.setNext(roots.get(y));
                }
            }
        }
    }
}
```

### Explanation
- **Mark:** starting from each root, `mark` follows `next` references and sets `marked`.
  It stops at a node that is already marked, which also handles cycles.
- **Sweep:** the heap walks its list of all nodes; unmarked nodes are unreachable, so they
  are "collected" by unlinking them from the list. `previous` remembers the last live node
  so that removing works in the middle of the list, and `last` is updated so that later
  `create()` calls still append correctly.
- **Cycles:** nodes 1 and 2 point to each other. In GC #1 they are live only because `c`
  reaches them through node 3. In GC #2 no root reaches 1, 2 or 3, so all three are
  collected, even though 1 and 2 still refer to each other. Reachability from the roots
  is what matters, not whether some reference to an object exists somewhere.
- **Real Java:** in this simulation the heap's list keeps the nodes alive for the real
  JVM; once a node is removed from the list and no root refers to it, it really becomes
  eligible for Java's own garbage collector.
- The `Node` link fields (`next`, `nextInHeap`) show that an object can hold references
  to other objects of the same class; Chapter 08 explores references further.
