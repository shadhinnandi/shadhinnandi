# Practice Problems: Polymorphism, Abstract Classes and Interfaces

These problems practise overloading, overriding with dynamic dispatch, abstract classes,
interfaces (including `default` methods) and safe downcasting. In most of them, `main`
works only with a superclass or interface type and never asks "which class is this?".
Programs read input without prompts and print exactly the sample output.

## Problem 1: Canteen Price Tags with Overloading
**Level:** Basic

### Problem Statement
The canteen prints price tags. Write a class `PriceTag` with three overloaded
`static String tag(...)` methods:

- `tag(String item, int price)` → `<item>: Tk <price>`
- `tag(String item, int price, int percentOff)` → `<item>: Tk <new price> (<percentOff>% off)`,
  where the new price is `price - price * percentOff / 100` (integer arithmetic)
- `tag(String item, double weightKg, int pricePerKg)` → `<item>: <weight> kg x Tk <pricePerKg> = Tk <total>`,
  with the weight printed with 1 decimal place and the total rounded to the nearest
  whole Tk with `Math.round`.

Input: `n`, then `n` lines. Each line starts with a type letter: `P item price`,
`D item price percent` or `W item weight pricePerKg`. Item names are single words.
Print the tag for each line by calling the matching overload.

### Sample Input
```text
4
P Singara 10
D Biryani 180 15
W Mango 2.5 140
P Tea 15
```

### Sample Output
```text
Singara: Tk 10
Biryani: Tk 153 (15% off)
Mango: 2.5 kg x Tk 140 = Tk 350
Tea: Tk 15
```

### Solution
```java
import java.util.Scanner;

class PriceTag {
    static String tag(String item, int price) {
        return item + ": Tk " + price;
    }

    static String tag(String item, int price, int percentOff) {
        int newPrice = price - price * percentOff / 100;
        return item + ": Tk " + newPrice + " (" + percentOff + "% off)";
    }

    static String tag(String item, double weightKg, int pricePerKg) {
        long total = Math.round(weightKg * pricePerKg);
        return String.format("%s: %.1f kg x Tk %d = Tk %d", item, weightKg, pricePerKg, total);
    }
}

public class CanteenTags {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String type = in.next();
            String item = in.next();
            if (type.equals("P")) {
                System.out.println(PriceTag.tag(item, in.nextInt()));
            } else if (type.equals("D")) {
                int price = in.nextInt();
                int percent = in.nextInt();
                System.out.println(PriceTag.tag(item, price, percent));
            } else {
                double weight = in.nextDouble();
                int perKg = in.nextInt();
                System.out.println(PriceTag.tag(item, weight, perKg));
            }
        }
    }
}
```

### Explanation
All three methods are called `tag`, but their parameter lists differ, so the compiler
can tell them apart. This choice is made at **compile time**, from the types of the
arguments: `tag(item, price, percent)` has `(String, int, int)` and
`tag(item, weight, perKg)` has `(String, double, int)`. That is compile-time
polymorphism. Note that the return type plays no part in choosing an overload; two
methods that differ only in return type would not compile.

## Problem 2: Notification Channels
**Level:** Basic

### Problem Statement
The exam office sends result alerts through different channels. Write an interface
`Notifier` with `String send(String to, String message)` and three classes that
implement it:

- `SmsNotifier`: `SMS to <to>: <message>`, but the message is cut to its first 20
  characters if it is longer;
- `EmailNotifier`: `Email to <to>@uni.edu: <message>`;
- `AppNotifier`: `App push to <to>: <MESSAGE IN UPPER CASE>`.

Input: a message line, then `n`, then `n` lines `channel recipient` where channel is
`sms`, `email` or `app`. Create the right notifier for each line, store it in a
variable of type `Notifier`, and print the result of `send`.

### Sample Input
```text
Your CSE 1115 result is published
3
sms 01711000000
email rahim
app nusrat
```

### Sample Output
```text
SMS to 01711000000: Your CSE 1115 result
Email to rahim@uni.edu: Your CSE 1115 result is published
App push to nusrat: YOUR CSE 1115 RESULT IS PUBLISHED
```

### Solution
```java
import java.util.Scanner;

interface Notifier {
    String send(String to, String message);
}

class SmsNotifier implements Notifier {
    private static final int LIMIT = 20;

    @Override
    public String send(String to, String message) {
        String text = message.length() > LIMIT ? message.substring(0, LIMIT) : message;
        return "SMS to " + to + ": " + text;
    }
}

class EmailNotifier implements Notifier {
    @Override
    public String send(String to, String message) {
        return "Email to " + to + "@uni.edu: " + message;
    }
}

class AppNotifier implements Notifier {
    @Override
    public String send(String to, String message) {
        return "App push to " + to + ": " + message.toUpperCase();
    }
}

public class ResultAlerts {
    static Notifier create(String channel) {
        if (channel.equals("sms")) {
            return new SmsNotifier();
        } else if (channel.equals("email")) {
            return new EmailNotifier();
        }
        return new AppNotifier();
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String message = in.nextLine();
        int n = Integer.parseInt(in.nextLine().trim());
        for (int i = 0; i < n; i++) {
            Notifier notifier = create(in.next());
            System.out.println(notifier.send(in.next(), message));
        }
    }
}
```

### Explanation
`main` only knows the interface type `Notifier`. The call `notifier.send(...)` is the
same line of code every time, yet it runs three different methods: the JVM looks at
the actual object and runs that class's `send`. This is runtime polymorphism through an
interface. Only `create` knows the concrete classes; adding a new channel means writing
one new class and one new branch in `create`, while the sending loop stays unchanged.

## Problem 3: Energy Use of Campus Devices
**Level:** Basic

### Problem Statement
Write an abstract class `Device` with a name, an abstract method
`double watts()` and a concrete method `double energyKwh(double hours)` that returns
`watts() * hours / 1000`. Write three subclasses:

- `Fan(name, speed)`: `20 + 15 × speed` watts (speed 1 to 5);
- `Light(name)`: 12 watts;
- `AirConditioner(name, tons)`: `1200 × tons` watts.

Input: `n`, then `n` lines `fan name speed hours`, `light name hours` or
`ac name tons hours`. For each device print
`<name>: <watts> W x <hours> h = <kWh> kWh` (watts with 0 decimals, hours with 1, kWh
with 2), then `Total: <kWh> kWh`.

### Sample Input
```text
4
fan Room301Fan 3 8
light CorridorLight 12
ac LabAC 1.5 6
light Room301Light 8
```

### Sample Output
```text
Room301Fan: 65 W x 8.0 h = 0.52 kWh
CorridorLight: 12 W x 12.0 h = 0.14 kWh
LabAC: 1800 W x 6.0 h = 10.80 kWh
Room301Light: 12 W x 8.0 h = 0.10 kWh
Total: 11.56 kWh
```

### Solution
```java
import java.util.Scanner;

abstract class Device {
    private final String name;

    Device(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    abstract double watts();

    double energyKwh(double hours) {
        return watts() * hours / 1000;
    }
}

class Fan extends Device {
    private final int speed;

    Fan(String name, int speed) {
        super(name);
        this.speed = speed;
    }

    @Override
    double watts() {
        return 20 + 15 * speed;
    }
}

class Light extends Device {
    Light(String name) {
        super(name);
    }

    @Override
    double watts() {
        return 12;
    }
}

class AirConditioner extends Device {
    private final double tons;

    AirConditioner(String name, double tons) {
        super(name);
        this.tons = tons;
    }

    @Override
    double watts() {
        return 1200 * tons;
    }
}

public class CampusEnergy {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        double total = 0;
        for (int i = 0; i < n; i++) {
            String type = in.next();
            String name = in.next();
            Device device;
            if (type.equals("fan")) {
                device = new Fan(name, in.nextInt());
            } else if (type.equals("light")) {
                device = new Light(name);
            } else {
                device = new AirConditioner(name, in.nextDouble());
            }
            double hours = in.nextDouble();
            double kwh = device.energyKwh(hours);
            total += kwh;
            System.out.printf("%s: %.0f W x %.1f h = %.2f kWh%n",
                    device.getName(), device.watts(), hours, kwh);
        }
        System.out.printf("Total: %.2f kWh%n", total);
    }
}
```

### Explanation
`Device` is abstract because "a device" on its own has no wattage; only real kinds of
device do. You cannot write `new Device(...)`, but you can have variables of type
`Device`. The concrete method `energyKwh` is written once in the abstract class and
calls the abstract method `watts()`. When it runs on a `Fan`, the call to `watts()`
dispatches to `Fan.watts()`, even though the code calling it lives in `Device`. This
"common algorithm in the superclass, varying step in the subclasses" is one of the
most useful patterns with abstract classes.

## Problem 4: Parking Lot Report with Safe Downcasting
**Level:** Basic

### Problem Statement
A parking lot keeps an `ArrayList<Vehicle>`. Every `Vehicle` has a plate number and an
overridden `int hourlyRate()`: `Car` 40, `Motorbike` 20, `Truck` 100. Only trucks also
have a load in tonnes, available through a `Truck`-only method `double getLoad()`.

Input: `n`, then `n` lines `car plate`, `bike plate` or `truck plate load`, then the
number of hours `h`. For each vehicle print `<plate>: Tk <rate × h>`; for trucks add
` (load <load> t)` with one decimal place. Use the pattern form of `instanceof` to reach
`getLoad()`. Finally print `Collected: Tk <total>`.

### Sample Input
```text
3
car DHA-1234
truck CTG-7788 7.5
bike DHA-5501
3
```

### Sample Output
```text
DHA-1234: Tk 120
CTG-7788: Tk 300 (load 7.5 t)
DHA-5501: Tk 60
Collected: Tk 480
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

abstract class Vehicle {
    private final String plate;

    Vehicle(String plate) {
        this.plate = plate;
    }

    String getPlate() {
        return plate;
    }

    abstract int hourlyRate();
}

class Car extends Vehicle {
    Car(String plate) {
        super(plate);
    }

    @Override
    int hourlyRate() {
        return 40;
    }
}

class Motorbike extends Vehicle {
    Motorbike(String plate) {
        super(plate);
    }

    @Override
    int hourlyRate() {
        return 20;
    }
}

class Truck extends Vehicle {
    private final double load;

    Truck(String plate, double load) {
        super(plate);
        this.load = load;
    }

    double getLoad() {
        return load;
    }

    @Override
    int hourlyRate() {
        return 100;
    }
}

public class ParkingLot {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        ArrayList<Vehicle> lot = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            String type = in.next();
            String plate = in.next();
            if (type.equals("car")) {
                lot.add(new Car(plate));
            } else if (type.equals("bike")) {
                lot.add(new Motorbike(plate));
            } else {
                lot.add(new Truck(plate, in.nextDouble()));
            }
        }
        int hours = in.nextInt();

        int total = 0;
        for (Vehicle v : lot) {
            int fee = v.hourlyRate() * hours;
            total += fee;
            String line = v.getPlate() + ": Tk " + fee;
            if (v instanceof Truck truck) {
                line += String.format(" (load %.1f t)", truck.getLoad());
            }
            System.out.println(line);
        }
        System.out.println("Collected: Tk " + total);
    }
}
```

### Explanation
The fee needs no type check at all: `v.hourlyRate()` dispatches to the right subclass.
The load is different: `getLoad()` exists only in `Truck`, so a `Vehicle` variable
cannot call it. `v instanceof Truck truck` checks the object's real class and, only if
the check succeeds, gives you a new variable `truck` of type `Truck`. This is a safe
downcast: there is no way to get a `ClassCastException`. Use `instanceof` like this for
behaviour that truly belongs to one subclass, not as a replacement for overriding.

## Problem 5: Payment Methods and Fees
**Level:** Intermediate

### Problem Statement
The university fee portal accepts three payment methods. Write an abstract class
`Payment` with the amount, an abstract `long fee()` and a concrete method
`long total()` that returns `amount + fee()`, plus an abstract `String label()`.

- `CardPayment`: fee is 1.5% of the amount, rounded to the nearest Tk with
  `Math.round(amount * 0.015)`;
- `WalletPayment`: fee is 1.85%, rounded the same way, but never more than 50 Tk;
- `BankTransfer`: fee is a flat 25 Tk, but free for amounts of 20000 Tk or more.

Input: `n`, then `n` lines `card|wallet|bank amount`. Print one line per payment
`<label> <amount>: fee <fee>, total <total>`, where the label is `Card`, `Wallet` or
`Bank`. Then print `Fees collected: <sum of fees>` and the label of the method that
charged the **highest single fee** as `Highest fee: <label> <amount>` (the first one
wins a tie).

### Sample Input
```text
5
card 18000
wallet 18000
bank 18000
bank 25000
wallet 1500
```

### Sample Output
```text
Card 18000: fee 270, total 18270
Wallet 18000: fee 50, total 18050
Bank 18000: fee 25, total 18025
Bank 25000: fee 0, total 25000
Wallet 1500: fee 28, total 1528
Fees collected: 373
Highest fee: Card 18000
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

abstract class Payment {
    protected final long amount;

    Payment(long amount) {
        this.amount = amount;
    }

    long getAmount() {
        return amount;
    }

    abstract long fee();

    abstract String label();

    long total() {
        return amount + fee();
    }

    @Override
    public String toString() {
        return label() + " " + amount + ": fee " + fee() + ", total " + total();
    }
}

class CardPayment extends Payment {
    CardPayment(long amount) {
        super(amount);
    }

    @Override
    long fee() {
        return Math.round(amount * 0.015);
    }

    @Override
    String label() {
        return "Card";
    }
}

class WalletPayment extends Payment {
    private static final long MAX_FEE = 50;

    WalletPayment(long amount) {
        super(amount);
    }

    @Override
    long fee() {
        return Math.min(MAX_FEE, Math.round(amount * 0.0185));
    }

    @Override
    String label() {
        return "Wallet";
    }
}

class BankTransfer extends Payment {
    BankTransfer(long amount) {
        super(amount);
    }

    @Override
    long fee() {
        return amount >= 20000 ? 0 : 25;
    }

    @Override
    String label() {
        return "Bank";
    }
}

public class FeePortal {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        ArrayList<Payment> payments = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            String type = in.next();
            long amount = in.nextLong();
            if (type.equals("card")) {
                payments.add(new CardPayment(amount));
            } else if (type.equals("wallet")) {
                payments.add(new WalletPayment(amount));
            } else {
                payments.add(new BankTransfer(amount));
            }
        }

        long fees = 0;
        Payment highest = null;
        for (Payment p : payments) {
            System.out.println(p);
            fees += p.fee();
            if (highest == null || p.fee() > highest.fee()) {
                highest = p;
            }
        }
        System.out.println("Fees collected: " + fees);
        if (highest != null) {
            System.out.println("Highest fee: " + highest.label() + " " + highest.getAmount());
        }
    }
}
```

### Explanation
`toString()` is written once in `Payment` and builds the line from `label()`, `fee()`
and `total()`. Each of those calls is dynamically dispatched, so the same `toString`
produces correct lines for all three classes. `println(p)` itself calls `toString()`
polymorphically. The search for the highest fee also works on the `Payment` type only.
`amount` is `protected final`: subclasses can read it to compute their fee, but nobody
can change it after construction.

## Problem 6: Auto-Graded Exam Questions
**Level:** Intermediate

### Problem Statement
An online quiz has different kinds of questions. Write an abstract class `Question`
with the question text and the marks it is worth, an abstract method
`double score(String answer)` and a concrete method `String result(String answer)` that
returns `<text>: <score>/<marks>` with scores printed with one decimal place.

- `MultipleChoice(text, marks, correctLetter)`: full marks if the answer equals the
  correct letter ignoring case, otherwise 0;
- `TrueFalse(text, marks, correct)`: full marks for the right `true`/`false`, minus
  half the marks for a wrong answer (negative marking), 0 for the answer `skip`;
- `ShortAnswer(text, marks, keyword1, keyword2)`: half the marks for each keyword that
  appears in the answer (case-insensitive).

Input: `n`, then for each question one line with its type and data, and one line with
the student's answer. Question lines are `MCQ marks letter text...`,
`TF marks true|false text...` or `SA marks keyword1 keyword2 text...` (the text is the
rest of the line). Print each result, then `Total: <sum>/<total marks>` with one
decimal place.

### Sample Input
```text
4
MCQ 2 b Which keyword creates an object?
B
TF 2 false A class can extend two classes.
true
SA 4 heap reference Where do objects live and how do we reach them?
Objects live on the heap and we use a Reference
TF 1 true Interfaces can have default methods.
skip
```

### Sample Output
```text
Which keyword creates an object?: 2.0/2.0
A class can extend two classes.: -1.0/2.0
Where do objects live and how do we reach them?: 4.0/4.0
Interfaces can have default methods.: 0.0/1.0
Total: 5.0/9.0
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

abstract class Question {
    private final String text;
    protected final double marks;

    Question(String text, double marks) {
        this.text = text;
        this.marks = marks;
    }

    double getMarks() {
        return marks;
    }

    abstract double score(String answer);

    String result(String answer) {
        return String.format("%s: %.1f/%.1f", text, score(answer), marks);
    }
}

class MultipleChoice extends Question {
    private final String correct;

    MultipleChoice(String text, double marks, String correct) {
        super(text, marks);
        this.correct = correct;
    }

    @Override
    double score(String answer) {
        return answer.trim().equalsIgnoreCase(correct) ? marks : 0;
    }
}

class TrueFalse extends Question {
    private final boolean correct;

    TrueFalse(String text, double marks, boolean correct) {
        super(text, marks);
        this.correct = correct;
    }

    @Override
    double score(String answer) {
        String a = answer.trim().toLowerCase();
        if (a.equals("skip")) {
            return 0;
        }
        boolean given = a.equals("true");
        return given == correct ? marks : -marks / 2;
    }
}

class ShortAnswer extends Question {
    private final String keyword1;
    private final String keyword2;

    ShortAnswer(String text, double marks, String keyword1, String keyword2) {
        super(text, marks);
        this.keyword1 = keyword1.toLowerCase();
        this.keyword2 = keyword2.toLowerCase();
    }

    @Override
    double score(String answer) {
        String a = answer.toLowerCase();
        double s = 0;
        if (a.contains(keyword1)) {
            s += marks / 2;
        }
        if (a.contains(keyword2)) {
            s += marks / 2;
        }
        return s;
    }
}

public class AutoGrader {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());
        ArrayList<Question> questions = new ArrayList<>();
        ArrayList<String> answers = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            Scanner line = new Scanner(in.nextLine());
            String type = line.next();
            double marks = line.nextDouble();
            if (type.equals("MCQ")) {
                String letter = line.next();
                questions.add(new MultipleChoice(line.nextLine().trim(), marks, letter));
            } else if (type.equals("TF")) {
                boolean correct = line.nextBoolean();
                questions.add(new TrueFalse(line.nextLine().trim(), marks, correct));
            } else {
                String k1 = line.next();
                String k2 = line.next();
                questions.add(new ShortAnswer(line.nextLine().trim(), marks, k1, k2));
            }
            answers.add(in.nextLine());
        }

        double total = 0;
        double possible = 0;
        for (int i = 0; i < questions.size(); i++) {
            Question q = questions.get(i);
            System.out.println(q.result(answers.get(i)));
            total += q.score(answers.get(i));
            possible += q.getMarks();
        }
        System.out.printf("Total: %.1f/%.1f%n", total, possible);
    }
}
```

### Explanation
`result()` is a concrete method in the abstract class that calls the abstract
`score()`. Each question type supplies its own marking rule, and the grading loop in
`main` treats them all as `Question`. A second `Scanner` reads the fields of one line,
which lets the question text (the rest of the line) contain spaces. Notice how easy it
would be to add a new question type, such as numeric answers with a tolerance: one new
subclass, and the grading loop does not change. That is the main benefit of
polymorphism: code that uses an abstraction does not need to change when new kinds of
objects are added.

## Problem 7: Shopping Cart with Default Methods
**Level:** Intermediate

### Problem Statement
A campus store sells items that may be discounted, taxed, both or neither. Write two
interfaces:

- `Discountable` with `default int discountPercent()` returning 0;
- `Taxable` with `default int taxPercent()` returning 5.

Write an abstract class `Item` (name and base price) with an abstract
`int finalPrice()`, and four item classes:

- `Book implements Discountable` (overrides the discount to 10%, no tax);
- `Gadget implements Taxable` (uses the default 5% tax);
- `Snack` (neither);
- `Hoodie implements Discountable, Taxable` (overrides both: discount 20%, tax 8%).

The final price is computed as: `price - price * discount / 100`, then
`+ result * tax / 100` (integer arithmetic). To read the percentages, check
`item instanceof Discountable d` and `item instanceof Taxable t` in **one helper method
of `Item`**, not in every subclass.

Input: `n`, then `n` lines `type name price`. Print
`<name>: <price> -> <final> (discount <d>%, tax <t>%)` for each item, then
`Cart total: <sum>`.

### Sample Input
```text
4
book CleanCode 1200
gadget PowerBank 2000
snack Chanachur 60
hoodie UniHoodie 1500
```

### Sample Output
```text
CleanCode: 1200 -> 1080 (discount 10%, tax 0%)
PowerBank: 2000 -> 2100 (discount 0%, tax 5%)
Chanachur: 60 -> 60 (discount 0%, tax 0%)
UniHoodie: 1500 -> 1296 (discount 20%, tax 8%)
Cart total: 4536
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

interface Discountable {
    default int discountPercent() {
        return 0;
    }
}

interface Taxable {
    default int taxPercent() {
        return 5;
    }
}

abstract class Item {
    private final String name;
    protected final int price;

    Item(String name, int price) {
        this.name = name;
        this.price = price;
    }

    String getName() {
        return name;
    }

    int discount() {
        if (this instanceof Discountable d) {
            return d.discountPercent();
        }
        return 0;
    }

    int tax() {
        if (this instanceof Taxable t) {
            return t.taxPercent();
        }
        return 0;
    }

    int finalPrice() {
        int afterDiscount = price - price * discount() / 100;
        return afterDiscount + afterDiscount * tax() / 100;
    }

    String describe() {
        return name + ": " + price + " -> " + finalPrice()
                + " (discount " + discount() + "%, tax " + tax() + "%)";
    }
}

class Book extends Item implements Discountable {
    Book(String name, int price) {
        super(name, price);
    }

    @Override
    public int discountPercent() {
        return 10;
    }
}

class Gadget extends Item implements Taxable {
    Gadget(String name, int price) {
        super(name, price);
    }
}

class Snack extends Item {
    Snack(String name, int price) {
        super(name, price);
    }
}

class Hoodie extends Item implements Discountable, Taxable {
    Hoodie(String name, int price) {
        super(name, price);
    }

    @Override
    public int discountPercent() {
        return 20;
    }

    @Override
    public int taxPercent() {
        return 8;
    }
}

public class CampusStore {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        ArrayList<Item> cart = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            String type = in.next();
            String name = in.next();
            int price = in.nextInt();
            if (type.equals("book")) {
                cart.add(new Book(name, price));
            } else if (type.equals("gadget")) {
                cart.add(new Gadget(name, price));
            } else if (type.equals("hoodie")) {
                cart.add(new Hoodie(name, price));
            } else {
                cart.add(new Snack(name, price));
            }
        }
        int total = 0;
        for (Item item : cart) {
            System.out.println(item.describe());
            total += item.finalPrice();
        }
        System.out.println("Cart total: " + total);
    }
}
```

### Explanation
A class can extend only one class but can implement many interfaces, so `Hoodie` is an
`Item`, a `Discountable` and a `Taxable` at the same time. `default` methods give each
interface a sensible standard behaviour: `Gadget` gets the 5% tax without writing any
code, while `Hoodie` overrides both defaults. The `instanceof` checks live in one place
(`Item.discount()` and `Item.tax()`), which keeps the subclasses tiny. `finalPrice()` is
no longer abstract: the varying parts are the interface methods, and the price formula
is shared. In a bigger system you would usually make discount and tax plain overridable
methods; this problem shows how interfaces can add optional abilities to a hierarchy.

## Problem 8: Remote Control with Undo
**Level:** Intermediate

### Problem Statement
A smart classroom has a light and a projector. Each button press is a **command
object**. Write an interface `Command` with `String execute()` and `String undo()`,
and these classes:

- `Light` (on/off) and `Projector` (on/off and an input source, default `HDMI`);
- `LightOn`, `LightOff`: switch the light and undo by restoring the previous state;
- `ProjectorSource(projector, source)`: switches the projector on and selects a source;
  undo restores the previous on/off state and source.

A `Remote` keeps the executed commands in an `ArrayList<Command>` used as a stack.
`press(Command c)` executes it and pushes it; `undo()` pops the last command and undoes
it, or returns `Nothing to undo`.

Input: `n`, then `n` lines: `LIGHT_ON`, `LIGHT_OFF`, `SOURCE <name>` or `UNDO`. Print
the message returned by every press or undo. Messages:
`Light on`, `Light off`, `Projector on, source <s>`, and for undo
`Undo: light <on|off>` / `Undo: projector <on|off>, source <s>` describing the restored
state. Finally print `Light: <on|off>, Projector: <on|off> (<source>)`.

### Sample Input
```text
6
LIGHT_ON
SOURCE VGA
SOURCE HDMI
UNDO
UNDO
UNDO
```

### Sample Output
```text
Light on
Projector on, source VGA
Projector on, source HDMI
Undo: projector on, source VGA
Undo: projector off, source HDMI
Undo: light off
Light: off, Projector: off (HDMI)
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

interface Command {
    String execute();

    String undo();
}

class Light {
    private boolean on;

    boolean isOn() {
        return on;
    }

    void setOn(boolean on) {
        this.on = on;
    }

    String state() {
        return on ? "on" : "off";
    }
}

class Projector {
    private boolean on;
    private String source = "HDMI";

    boolean isOn() {
        return on;
    }

    String getSource() {
        return source;
    }

    void set(boolean on, String source) {
        this.on = on;
        this.source = source;
    }

    String state() {
        return (on ? "on" : "off") + ", source " + source;
    }
}

class LightSwitch implements Command {
    private final Light light;
    private final boolean target;
    private boolean before;

    LightSwitch(Light light, boolean target) {
        this.light = light;
        this.target = target;
    }

    @Override
    public String execute() {
        before = light.isOn();
        light.setOn(target);
        return "Light " + light.state();
    }

    @Override
    public String undo() {
        light.setOn(before);
        return "Undo: light " + light.state();
    }
}

class ProjectorSource implements Command {
    private final Projector projector;
    private final String source;
    private boolean wasOn;
    private String oldSource;

    ProjectorSource(Projector projector, String source) {
        this.projector = projector;
        this.source = source;
    }

    @Override
    public String execute() {
        wasOn = projector.isOn();
        oldSource = projector.getSource();
        projector.set(true, source);
        return "Projector on, source " + source;
    }

    @Override
    public String undo() {
        projector.set(wasOn, oldSource);
        return "Undo: projector " + projector.state();
    }
}

class Remote {
    private final ArrayList<Command> history = new ArrayList<>();

    String press(Command c) {
        history.add(c);
        return c.execute();
    }

    String undo() {
        if (history.isEmpty()) {
            return "Nothing to undo";
        }
        return history.remove(history.size() - 1).undo();
    }
}

public class ClassroomRemote {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Light light = new Light();
        Projector projector = new Projector();
        Remote remote = new Remote();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String action = in.next();
            String message;
            if (action.equals("LIGHT_ON")) {
                message = remote.press(new LightSwitch(light, true));
            } else if (action.equals("LIGHT_OFF")) {
                message = remote.press(new LightSwitch(light, false));
            } else if (action.equals("SOURCE")) {
                message = remote.press(new ProjectorSource(projector, in.next()));
            } else {
                message = remote.undo();
            }
            System.out.println(message);
        }
        System.out.println("Light: " + light.state() + ", Projector: "
                + (projector.isOn() ? "on" : "off") + " (" + projector.getSource() + ")");
    }
}
```

### Explanation
Each button press becomes an object that knows how to do its action **and** how to
reverse it. The `Remote` does not know what a light or a projector is: it stores
`Command` references and calls `execute()` and `undo()` on them, which dispatch to the
right class at run time. Each command records the state it changed (`before`,
`wasOn`, `oldSource`) at the moment it runs, which is what makes undo exact. The two
light commands are one class with a `target` field, which avoids two nearly identical
classes. This design is known as the Command pattern; it is how editors implement
multi-level undo.

## Problem 9: Ride Fares with a Template Method
**Level:** Advanced

### Problem Statement
A ride-sharing app computes every fare in the same steps but each vehicle type fills
in some steps differently. Write an abstract class `Ride` with the distance (km) and
minutes, and a **`final`** method `int fare()` that always computes:

1. `base()` + `perKm() × km` + `perMinute() × minutes`;
2. then applies `surge(subtotal)` (default: no change);
3. then never returns less than `minimumFare()`.

`base`, `perKm`, `perMinute` and `minimumFare` are abstract. Subclasses:

| Type | base | per km | per minute | minimum | surge |
|---|---|---|---|---|---|
| `Bike` | 20 | 12 | 1 | 40 | none |
| `Auto` (CNG) | 30 | 18 | 2 | 60 | none |
| `Car` | 50 | 28 | 3 | 120 | +25% (integer) if `peak` |

`Car` takes an extra boolean `peak` in its constructor. Also print a breakdown with a
`String describe()` that is written once in `Ride` and uses an abstract `String name()`.

Input: `n`, then `n` lines `bike km minutes`, `auto km minutes` or
`car km minutes peak|offpeak`. Print `<name> <km> km <minutes> min: Tk <fare>` per ride,
then `Cheapest: <name> Tk <fare>` (first one wins a tie).

### Sample Input
```text
4
bike 1 4
auto 6 22
car 6 22 peak
car 2 6 offpeak
```

### Sample Output
```text
Bike 1 km 4 min: Tk 40
Auto 6 km 22 min: Tk 182
Car (peak) 6 km 22 min: Tk 355
Car 2 km 6 min: Tk 124
Cheapest: Bike Tk 40
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

abstract class Ride {
    private final int km;
    private final int minutes;

    Ride(int km, int minutes) {
        this.km = km;
        this.minutes = minutes;
    }

    abstract String name();

    abstract int base();

    abstract int perKm();

    abstract int perMinute();

    abstract int minimumFare();

    int surge(int subtotal) {
        return subtotal;
    }

    final int fare() {
        int subtotal = base() + perKm() * km + perMinute() * minutes;
        int withSurge = surge(subtotal);
        return Math.max(withSurge, minimumFare());
    }

    String describe() {
        return name() + " " + km + " km " + minutes + " min: Tk " + fare();
    }
}

class Bike extends Ride {
    Bike(int km, int minutes) {
        super(km, minutes);
    }

    @Override
    String name() {
        return "Bike";
    }

    @Override
    int base() {
        return 20;
    }

    @Override
    int perKm() {
        return 12;
    }

    @Override
    int perMinute() {
        return 1;
    }

    @Override
    int minimumFare() {
        return 40;
    }
}

class Auto extends Ride {
    Auto(int km, int minutes) {
        super(km, minutes);
    }

    @Override
    String name() {
        return "Auto";
    }

    @Override
    int base() {
        return 30;
    }

    @Override
    int perKm() {
        return 18;
    }

    @Override
    int perMinute() {
        return 2;
    }

    @Override
    int minimumFare() {
        return 60;
    }
}

class Car extends Ride {
    private final boolean peak;

    Car(int km, int minutes, boolean peak) {
        super(km, minutes);
        this.peak = peak;
    }

    @Override
    String name() {
        return peak ? "Car (peak)" : "Car";
    }

    @Override
    int base() {
        return 50;
    }

    @Override
    int perKm() {
        return 28;
    }

    @Override
    int perMinute() {
        return 3;
    }

    @Override
    int minimumFare() {
        return 120;
    }

    @Override
    int surge(int subtotal) {
        return peak ? subtotal + subtotal / 4 : subtotal;
    }
}

public class RideFares {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        ArrayList<Ride> rides = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            String type = in.next();
            int km = in.nextInt();
            int minutes = in.nextInt();
            if (type.equals("bike")) {
                rides.add(new Bike(km, minutes));
            } else if (type.equals("auto")) {
                rides.add(new Auto(km, minutes));
            } else {
                rides.add(new Car(km, minutes, in.next().equals("peak")));
            }
        }
        Ride cheapest = null;
        for (Ride r : rides) {
            System.out.println(r.describe());
            if (cheapest == null || r.fare() < cheapest.fare()) {
                cheapest = r;
            }
        }
        if (cheapest != null) {
            System.out.println("Cheapest: " + cheapest.name() + " Tk " + cheapest.fare());
        }
    }
}
```

### Explanation
`fare()` is a **template method**: it fixes the order of the steps and is `final`, so
no subclass can change the overall rule (for example, skip the minimum fare). The
steps themselves are abstract or overridable methods, and dynamic dispatch picks each
subclass's version. `surge` has a default implementation in `Ride`, so only `Car`
needs to override it. This shows the difference between the two uses of overriding:
methods that *must* differ (abstract) and methods that *may* differ (concrete with a
default). For the sample, the 1 km bike ride costs 20 + 12 + 4 = 36, which is raised
to the 40 Tk minimum.

## Problem 10: Library Loans for Different Members and Items
**Level:** Advanced

### Problem Statement
In the university library, the loan period and the late fine depend on **both** the
item and the member:

| Item | loan days | fine per late day |
|---|---|---|
| `Book` | 14 | 5 |
| `Journal` | 7 | 10 |
| `Thesis` | 3 | 20 |

| Member | effect |
|---|---|
| `Student` | as in the table, at most 3 items at a time |
| `Faculty` | loan days doubled, fines halved (integer division), at most 10 items |

Write an abstract class `LibraryItem` (code; abstract `loanDays()` and `finePerDay()`)
and an abstract class `Member` (name; abstract `maxItems()`, `int loanDaysFor(LibraryItem)`
and `int fineFor(LibraryItem, int daysLate)`; a concrete count of items on loan). The
member's methods ask the item for its base values, so **no class ever checks the
concrete class of another**.

Input: members first: `m`, then `m` lines `student|faculty name`; then `q` commands:

- `BORROW name code type` (type is `book`, `journal` or `thesis`) → `<name> borrowed <code> for <days> days`
  or `<name> cannot borrow more than <max> items`;
- `RETURN name code type daysKept` → `<name> returned <code>: on time` or
  `<name> returned <code>: <late> days late, fine Tk <fine>`.

A returned item reduces the member's count by one. Assume every RETURN matches an
earlier BORROW. Item objects are created from `code` and `type` on each command.

### Sample Input
```text
2
student Rafi
faculty DrHasan
8
BORROW Rafi B101 book
BORROW Rafi J20 journal
BORROW DrHasan T7 thesis
RETURN Rafi J20 journal 10
RETURN DrHasan T7 thesis 9
BORROW Rafi T8 thesis
BORROW Rafi B102 book
BORROW Rafi B103 book
```

### Sample Output
```text
Rafi borrowed B101 for 14 days
Rafi borrowed J20 for 7 days
DrHasan borrowed T7 for 6 days
Rafi returned J20: 3 days late, fine Tk 30
DrHasan returned T7: 3 days late, fine Tk 30
Rafi borrowed T8 for 3 days
Rafi borrowed B102 for 14 days
Rafi cannot borrow more than 3 items
```

### Solution
```java
import java.util.ArrayList;
import java.util.Scanner;

abstract class LibraryItem {
    private final String code;

    LibraryItem(String code) {
        this.code = code;
    }

    String getCode() {
        return code;
    }

    abstract int loanDays();

    abstract int finePerDay();

    static LibraryItem create(String code, String type) {
        if (type.equals("book")) {
            return new Book(code);
        } else if (type.equals("journal")) {
            return new Journal(code);
        }
        return new Thesis(code);
    }
}

class Book extends LibraryItem {
    Book(String code) {
        super(code);
    }

    @Override
    int loanDays() {
        return 14;
    }

    @Override
    int finePerDay() {
        return 5;
    }
}

class Journal extends LibraryItem {
    Journal(String code) {
        super(code);
    }

    @Override
    int loanDays() {
        return 7;
    }

    @Override
    int finePerDay() {
        return 10;
    }
}

class Thesis extends LibraryItem {
    Thesis(String code) {
        super(code);
    }

    @Override
    int loanDays() {
        return 3;
    }

    @Override
    int finePerDay() {
        return 20;
    }
}

abstract class Member {
    private final String name;
    private int onLoan;

    Member(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    abstract int maxItems();

    abstract int loanDaysFor(LibraryItem item);

    abstract int fineFor(LibraryItem item, int daysLate);

    String borrow(LibraryItem item) {
        if (onLoan >= maxItems()) {
            return name + " cannot borrow more than " + maxItems() + " items";
        }
        onLoan++;
        return name + " borrowed " + item.getCode() + " for " + loanDaysFor(item) + " days";
    }

    String giveBack(LibraryItem item, int daysKept) {
        onLoan--;
        int late = daysKept - loanDaysFor(item);
        if (late <= 0) {
            return name + " returned " + item.getCode() + ": on time";
        }
        return name + " returned " + item.getCode() + ": " + late + " days late, fine Tk "
                + fineFor(item, late);
    }
}

class Student extends Member {
    Student(String name) {
        super(name);
    }

    @Override
    int maxItems() {
        return 3;
    }

    @Override
    int loanDaysFor(LibraryItem item) {
        return item.loanDays();
    }

    @Override
    int fineFor(LibraryItem item, int daysLate) {
        return item.finePerDay() * daysLate;
    }
}

class Faculty extends Member {
    Faculty(String name) {
        super(name);
    }

    @Override
    int maxItems() {
        return 10;
    }

    @Override
    int loanDaysFor(LibraryItem item) {
        return item.loanDays() * 2;
    }

    @Override
    int fineFor(LibraryItem item, int daysLate) {
        return item.finePerDay() / 2 * daysLate;
    }
}

public class LibraryLoans {
    static Member find(ArrayList<Member> members, String name) {
        for (Member m : members) {
            if (m.getName().equals(name)) {
                return m;
            }
        }
        return null;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int m = in.nextInt();
        ArrayList<Member> members = new ArrayList<>();
        for (int i = 0; i < m; i++) {
            String type = in.next();
            String name = in.next();
            members.add(type.equals("faculty") ? new Faculty(name) : new Student(name));
        }
        int q = in.nextInt();
        for (int i = 0; i < q; i++) {
            String action = in.next();
            Member member = find(members, in.next());
            LibraryItem item = LibraryItem.create(in.next(), in.next());
            if (member == null) {
                System.out.println("Unknown member");
                if (action.equals("RETURN")) {
                    in.nextInt();
                }
            } else if (action.equals("BORROW")) {
                System.out.println(member.borrow(item));
            } else {
                System.out.println(member.giveBack(item, in.nextInt()));
            }
        }
    }
}
```

### Explanation
The result depends on two objects: the member and the item. The member's methods hold
the member-specific rule (double the days, half the fine) and ask the item for the
item-specific base values through overridden methods. So `faculty.loanDaysFor(thesis)`
runs `Faculty.loanDaysFor`, which calls `Thesis.loanDays()`: two dynamic dispatches,
one on each object, and no `instanceof` anywhere. Adding a new item type (say `Map`)
needs only one new subclass; adding a new member type needs only one new subclass. The
shared borrowing rules (the item limit and the late-day calculation) are written once in
`Member`. `LibraryItem.create` is a static factory method: the only place that turns
the type word into a class.

## Problem 11: Expression Tree Calculator
**Level:** Advanced

### Problem Statement
Represent arithmetic expressions as a tree of objects. Write an abstract class `Expr`
with `abstract long eval()` and `abstract String show()`, and subclasses:

- `Num(value)`: evaluates to the value, shows it as written;
- `Add(left, right)`, `Sub(left, right)`, `Mul(left, right)`: show as
  `(<left> <op> <right>)`;
- `Neg(inner)`: evaluates to the negated value, shows as `-<inner>`.

The input gives each expression in **prefix** form on one line, tokens separated by
spaces: an operator `+`, `-`, `*` followed by its two operands, `neg` followed by one
operand, or an integer. Build the tree with a recursive method `Expr parse(Scanner s)`
that reads one token and, for an operator, parses its operands recursively.

Input: `n`, then `n` lines. For each expression print `<show> = <eval>`.

### Sample Input
```text
3
+ 2 * 3 4
* + 1 2 - 10 neg 4
neg - 7 * 2 5
```

### Sample Output
```text
(2 + (3 * 4)) = 14
((1 + 2) * (10 - -4)) = 42
-(7 - (2 * 5)) = 3
```

### Solution
```java
import java.util.Scanner;

abstract class Expr {
    abstract long eval();

    abstract String show();
}

class Num extends Expr {
    private final long value;

    Num(long value) {
        this.value = value;
    }

    @Override
    long eval() {
        return value;
    }

    @Override
    String show() {
        return Long.toString(value);
    }
}

abstract class Binary extends Expr {
    protected final Expr left;
    protected final Expr right;

    Binary(Expr left, Expr right) {
        this.left = left;
        this.right = right;
    }

    abstract String op();

    @Override
    String show() {
        return "(" + left.show() + " " + op() + " " + right.show() + ")";
    }
}

class Add extends Binary {
    Add(Expr left, Expr right) {
        super(left, right);
    }

    @Override
    String op() {
        return "+";
    }

    @Override
    long eval() {
        return left.eval() + right.eval();
    }
}

class Sub extends Binary {
    Sub(Expr left, Expr right) {
        super(left, right);
    }

    @Override
    String op() {
        return "-";
    }

    @Override
    long eval() {
        return left.eval() - right.eval();
    }
}

class Mul extends Binary {
    Mul(Expr left, Expr right) {
        super(left, right);
    }

    @Override
    String op() {
        return "*";
    }

    @Override
    long eval() {
        return left.eval() * right.eval();
    }
}

class Neg extends Expr {
    private final Expr inner;

    Neg(Expr inner) {
        this.inner = inner;
    }

    @Override
    long eval() {
        return -inner.eval();
    }

    @Override
    String show() {
        return "-" + inner.show();
    }
}

public class ExpressionTrees {
    static Expr parse(Scanner s) {
        String token = s.next();
        if (token.equals("+")) {
            return new Add(parse(s), parse(s));
        } else if (token.equals("-")) {
            return new Sub(parse(s), parse(s));
        } else if (token.equals("*")) {
            return new Mul(parse(s), parse(s));
        } else if (token.equals("neg")) {
            return new Neg(parse(s));
        }
        return new Num(Long.parseLong(token));
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.nextLine().trim());
        for (int i = 0; i < n; i++) {
            Expr e = parse(new Scanner(in.nextLine()));
            System.out.println(e.show() + " = " + e.eval());
        }
    }
}
```

### Explanation
Each node object knows how to evaluate and print **itself**, and asks its children to
do the same. `eval()` on the root therefore walks the whole tree through dynamic
dispatch, without a single `if` about node types. The only `if` chain is in `parse`,
which must decide which object to create from a token; once the tree exists, all
behaviour is polymorphic. `Binary` is an abstract class in the middle of the hierarchy:
it holds what all two-operand nodes share (two children and the bracketed display)
while still leaving `eval()` and `op()` abstract. Java evaluates method arguments left
to right, so `new Add(parse(s), parse(s))` reads the left operand first, which is what
prefix order needs.

### Solution
```java
import java.util.Scanner;

abstract class Fighter {
    private final String name;
    private int health;
    protected int turns;

    Fighter(String name, int health) {
        this.name = name;
        this.health = health;
    }

    String getName() {
        return name;
    }

    int getHealth() {
        return health;
    }

    boolean isAlive() {
        return health > 0;
    }

    abstract int attackPower();

    int takeHit(int damage) {
        int taken = Math.min(damage, health);
        health -= taken;
        return taken;
    }

    String attack(Fighter target) {
        turns++;
        int taken = target.takeHit(attackPower());
        return name + " hits " + target.getName() + " for " + taken
                + " (" + target.getHealth() + " left)";
    }
}

class Warrior extends Fighter {
    Warrior(String name) {
        super(name, 120);
    }

    @Override
    int attackPower() {
        return 14;
    }

    @Override
    int takeHit(int damage) {
        return super.takeHit(Math.max(1, damage - 3));
    }
}

class Mage extends Fighter {
    Mage(String name) {
        super(name, 80);
    }

    @Override
    int attackPower() {
        return turns % 3 == 0 ? 30 : 10;
    }
}

class Archer extends Fighter {
    private int hitsTaken;

    Archer(String name) {
        super(name, 90);
    }

    @Override
    int attackPower() {
        return turns % 2 == 0 ? 24 : 12;
    }

    @Override
    int takeHit(int damage) {
        hitsTaken++;
        if (hitsTaken % 4 == 0) {
            return 0;
        }
        return super.takeHit(damage);
    }
}

public class Battle {
    static Fighter create(String type, String name) {
        if (type.equals("warrior")) {
            return new Warrior(name);
        } else if (type.equals("mage")) {
            return new Mage(name);
        }
        return new Archer(name);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Fighter first = create(in.next(), in.next());
        Fighter second = create(in.next(), in.next());

        Fighter attacker = first;
        Fighter defender = second;
        int attacks = 0;
        while (first.isAlive() && second.isAlive()) {
            System.out.println(attacker.attack(defender));
            attacks++;
            Fighter temp = attacker;
            attacker = defender;
            defender = temp;
        }
        Fighter winner = first.isAlive() ? first : second;
        System.out.println(winner.getName() + " wins in " + attacks + " attacks");
    }
}
```

### Explanation
`attack()` is written once in `Fighter`, yet each fight behaves differently because two
calls inside it are dynamically dispatched: `attackPower()` on the attacker and
`takeHit()` on the defender. `attack` increments `turns` **before** asking for the
power, so on a mage's third attack `turns % 3 == 0` and the fireball fires.
`Warrior` and `Archer` override `takeHit` but still call `super.takeHit(...)` so the
health rule (never below 0) stays in one place. The game loop swaps two `Fighter`
references each round and never needs to know which classes are fighting.
