# Scenario-Based Problems

These scenarios practise Chapter 03: breaking a problem into small methods with clear
names, parameters and return values, overloading, and recursion. A good solution here
reads almost like the problem statement: `main` handles input and output and calls
methods that each do one job.

Programs read input without prompts and print exactly the sample output. All fees,
rates and rules in these problems are hypothetical and invented for practice.

## Problem 1: Campus Shuttle Fares
**Level:** Basic

### Scenario
The campus shuttle charges by distance. Students show their ID card and get a
discount; staff and visitors pay the full fare. The transport office wants the fare
logic in methods so that the same code can later be used by the ticket machines.

### Problem Statement
Write two overloaded methods:

- `static int fare(int km)`: `20` Tk for the first 2 km, then `8` Tk for every further
  km;
- `static int fare(int km, boolean student)`: the same fare, but students pay 25% less
  (`fare × 75 / 100`, integer arithmetic). It must call `fare(int)` instead of
  repeating the rule.

Input: `n`, then `n` lines `km type` where type is `S` (student) or `V` (visitor).
For each trip print `<km> km <Student|Visitor>: <fare> Tk`, then `Collected: <total> Tk`.

### Sample Input
```text
4
1 S
2 V
7 S
10 V
```

### Sample Output
```text
1 km Student: 15 Tk
2 km Visitor: 20 Tk
7 km Student: 45 Tk
10 km Visitor: 84 Tk
Collected: 164 Tk
```

### Solution
```java
import java.util.Scanner;

public class ShuttleFares {
    static int fare(int km) {
        if (km <= 2) {
            return 20;
        }
        return 20 + (km - 2) * 8;
    }

    static int fare(int km, boolean student) {
        int full = fare(km);
        if (student) {
            return full * 75 / 100;
        }
        return full;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int total = 0;
        for (int i = 0; i < n; i++) {
            int km = in.nextInt();
            boolean student = in.next().equals("S");
            int paid = fare(km, student);
            total += paid;
            System.out.println(km + " km " + (student ? "Student" : "Visitor") + ": " + paid + " Tk");
        }
        System.out.println("Collected: " + total + " Tk");
    }
}
```

### Explanation
The two `fare` methods share a name but have different parameter lists, so the
compiler chooses the right one from the arguments. The two-parameter version reuses
the one-parameter version for the base fare, so the distance rule exists in exactly
one place; if the per-km charge changes, only one line changes. Returning early from
`fare(int)` for short trips keeps the main formula simple.

### Concepts Practiced
- Method overloading
- One method calling another to avoid repeating a rule
- `boolean` parameters and return values





## Problem 2: Student ID Validator
**Level:** Intermediate

### Scenario
The registration office receives student IDs typed by hand, and many contain mistakes.
A valid ID has 9 digits: a 3-digit program code, a 2-digit admission year, a 1-digit
trimester and a 3-digit serial number. The office wants each ID explained in words, or
the first problem found.

### Problem Statement
Program codes: `011` CSE, `021` EEE, `111` BBA. Trimesters: `1` Spring, `2` Summer,
`3` Fall. The year `yy` means `20yy` and must be between `15` and `25`. The serial must
be between `001` and `999`.

Write at least these methods and use them:

- `static boolean allDigits(String s)`
- `static String programName(String code)` (returns `null` for an unknown code)
- `static String trimesterName(int t)` (returns `null` for an invalid trimester)
- `static String check(String id)`: returns the description or the error text.

Checks, in this order, with these messages:

1. length is not 9 → `<id>: must have 9 characters`
2. not all digits → `<id>: only digits allowed`
3. unknown program → `<id>: unknown program <code>`
4. bad year → `<id>: year 20<yy> out of range`
5. bad trimester → `<id>: invalid trimester <t>`
6. serial `000` → `<id>: serial cannot be 000`

A valid ID prints `<id>: <program>, <trimester> 20<yy>, serial <serial without leading zeros>`.

Input: `n`, then `n` IDs (one per line, no spaces).

### Sample Input
```text
5
011221045
02123301
0112210A5
031221045
111244007
```

### Sample Output
```text
011221045: CSE, Spring 2022, serial 45
02123301: must have 9 characters
0112210A5: only digits allowed
031221045: unknown program 031
111244007: invalid trimester 4
```

### Solution
```java
import java.util.Scanner;

public class StudentIdValidator {
    static boolean allDigits(String s) {
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (c < '0' || c > '9') {
                return false;
            }
        }
        return true;
    }

    static String programName(String code) {
        if (code.equals("011")) {
            return "CSE";
        } else if (code.equals("021")) {
            return "EEE";
        } else if (code.equals("111")) {
            return "BBA";
        }
        return null;
    }

    static String trimesterName(int t) {
        switch (t) {
            case 1:
                return "Spring";
            case 2:
                return "Summer";
            case 3:
                return "Fall";
            default:
                return null;
        }
    }

    static String check(String id) {
        if (id.length() != 9) {
            return id + ": must have 9 characters";
        }
        if (!allDigits(id)) {
            return id + ": only digits allowed";
        }
        String code = id.substring(0, 3);
        String program = programName(code);
        if (program == null) {
            return id + ": unknown program " + code;
        }
        String yy = id.substring(3, 5);
        int year = Integer.parseInt(yy);
        if (year < 15 || year > 25) {
            return id + ": year 20" + yy + " out of range";
        }
        int t = id.charAt(5) - '0';
        String trimester = trimesterName(t);
        if (trimester == null) {
            return id + ": invalid trimester " + t;
        }
        int serial = Integer.parseInt(id.substring(6));
        if (serial == 0) {
            return id + ": serial cannot be 000";
        }
        return id + ": " + program + ", " + trimester + " 20" + yy + ", serial " + serial;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            System.out.println(check(in.next()));
        }
    }
}
```

### Explanation
`check` reads like the rule list: each test is one `if` that returns the message as
soon as a problem is found, so later checks can assume earlier ones passed (for
example, `Integer.parseInt` is only reached after `allDigits` confirmed the text). The
small helper methods each answer one question and are easy to test on their own.
Returning `null` means "no such name" and lets the caller decide what message to show.
`id.charAt(5) - '0'` converts a digit character to its number, because the digit
characters `'0'` to `'9'` have consecutive codes. `Integer.parseInt("045")` gives `45`,
which removes the leading zeros for free.

### Concepts Practiced
- Decomposing validation into small methods
- Early `return` from a method
- Returning `null` for "not found"
- Converting digit characters and digit strings to numbers

## Problem 3: Library Staircase
**Level:** Intermediate

### Scenario
The central library has a long staircase. Fahim, who likes puzzles, wonders in how
many different ways he can climb it if each move goes up 1, 2 or 3 steps. He also
notices that his recursive program becomes slow for tall staircases and wants to see
why.

### Problem Statement
Write a recursive method `static long ways(int n)`: the number of different ways to
climb `n` steps with moves of 1, 2 or 3 steps (order matters). `ways(0)` is `1` (doing
nothing is one way) and `ways` of a negative number is `0`. The method must also
increment a `static long calls` counter every time it is called.

Input: `q`, then `q` values of `n` (0 to 25). For each, reset the counter, compute
the answer and print `<n> steps: <ways> ways, <calls> calls`.

### Sample Input
```text
4
1
3
4
10
```

### Sample Output
```text
1 steps: 1 ways, 4 calls
3 steps: 4 ways, 13 calls
4 steps: 7 ways, 25 calls
10 steps: 274 ways, 979 calls
```

### Solution
```java
import java.util.Scanner;

public class LibraryStairs {
    static long calls = 0;

    static long ways(int n) {
        calls++;
        if (n < 0) {
            return 0;
        }
        if (n == 0) {
            return 1;
        }
        return ways(n - 1) + ways(n - 2) + ways(n - 3);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int q = in.nextInt();
        for (int i = 0; i < q; i++) {
            int n = in.nextInt();
            calls = 0;
            long result = ways(n);
            System.out.println(n + " steps: " + result + " ways, " + calls + " calls");
        }
    }
}
```

### Explanation
Think about the **first** move: it is 1, 2 or 3 steps, and after it the rest of the
climb is a smaller version of the same problem. So `ways(n)` is the sum of
`ways(n - 1)`, `ways(n - 2)` and `ways(n - 3)`. The base cases stop the recursion: an
exact landing on step 0 counts as one way, and overshooting (a negative number) counts
as zero. The `calls` counter shows the cost: each call makes three more calls, and the
same sub-problems are solved again and again, so the number of calls grows
exponentially. Chapter 08 shows how an array can remember results and avoid this
repetition.

### Concepts Practiced
- Recursion with several recursive calls
- Base cases, including an invalid input that returns 0
- A `static` counter shared by all calls
- Measuring the cost of naive recursion


#### Small values

## Problem 4: Days Between Two Dates
**Level:** Advanced

### Scenario
The exam office plans the trimester calendar: how many days from the start of classes
to the final exam, and on which weekday each date falls. Spreadsheets have given them
wrong answers around leap years, so they want a careful program built from small,
tested methods.

### Problem Statement
Write and use these methods:

- `static boolean isLeap(int y)`: divisible by 4, except years divisible by 100
  unless also divisible by 400;
- `static int daysInMonth(int m, int y)`;
- `static boolean isValid(int d, int m, int y)`: year 1900 to 2100, month 1 to 12, day
  1 to the month's length;
- `static int dayOfYear(int d, int m, int y)`: 1 for January 1st;
- `static long daysFrom1900(int d, int m, int y)`: days since 1 January 1900 (which is
  day 0);
- `static String weekday(int d, int m, int y)`: 1 January 1900 was a **Monday**.

Input: `n`, then `n` lines `d1 m1 y1 d2 m2 y2`. For each line:

- if either date is invalid print `Invalid date`;
- otherwise print
  `<d1>/<m1>/<y1> (<weekday>) to <d2>/<m2>/<y2> (<weekday>): <k> days`, where `k` is
  `days(second) − days(first)` (it may be negative if the second date is earlier).

### Sample Input
```text
3
1 1 2024 1 3 2024
14 4 2025 25 12 2025
29 2 2023 1 3 2023
```

### Sample Output
```text
1/1/2024 (Monday) to 1/3/2024 (Friday): 60 days
14/4/2025 (Monday) to 25/12/2025 (Thursday): 255 days
Invalid date
```

### Solution
```java
import java.util.Scanner;

public class DaysBetween {
    static boolean isLeap(int y) {
        return (y % 4 == 0 && y % 100 != 0) || y % 400 == 0;
    }

    static int daysInMonth(int m, int y) {
        switch (m) {
            case 2:
                return isLeap(y) ? 29 : 28;
            case 4:
            case 6:
            case 9:
            case 11:
                return 30;
            default:
                return 31;
        }
    }

    static boolean isValid(int d, int m, int y) {
        if (y < 1900 || y > 2100 || m < 1 || m > 12) {
            return false;
        }
        return d >= 1 && d <= daysInMonth(m, y);
    }

    static int dayOfYear(int d, int m, int y) {
        int total = d;
        for (int month = 1; month < m; month++) {
            total += daysInMonth(month, y);
        }
        return total;
    }

    static long daysFrom1900(int d, int m, int y) {
        long days = 0;
        for (int year = 1900; year < y; year++) {
            days += isLeap(year) ? 366 : 365;
        }
        return days + dayOfYear(d, m, y) - 1;
    }

    static String weekday(int d, int m, int y) {
        switch ((int) (daysFrom1900(d, m, y) % 7)) {
            case 0:
                return "Monday";
            case 1:
                return "Tuesday";
            case 2:
                return "Wednesday";
            case 3:
                return "Thursday";
            case 4:
                return "Friday";
            case 5:
                return "Saturday";
            default:
                return "Sunday";
        }
    }

    static String date(int d, int m, int y) {
        return d + "/" + m + "/" + y + " (" + weekday(d, m, y) + ")";
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            int d1 = in.nextInt();
            int m1 = in.nextInt();
            int y1 = in.nextInt();
            int d2 = in.nextInt();
            int m2 = in.nextInt();
            int y2 = in.nextInt();
            if (!isValid(d1, m1, y1) || !isValid(d2, m2, y2)) {
                System.out.println("Invalid date");
            } else {
                long k = daysFrom1900(d2, m2, y2) - daysFrom1900(d1, m1, y1);
                System.out.println(date(d1, m1, y1) + " to " + date(d2, m2, y2) + ": " + k + " days");
            }
        }
    }
}
```

### Explanation
The hard question "how many days between two dates?" becomes easy once both dates are
converted to one number: days since a fixed starting day. Each method builds on the
previous one: `daysFrom1900` uses `dayOfYear`, which uses `daysInMonth`, which uses
`isLeap`. Because each piece is small, it can be checked separately (for example,
`isLeap(1900)` must be `false` and `isLeap(2000)` must be `true`). The weekday comes
from the same number: whole weeks do not change the weekday, so only `days % 7`
matters. Grouped `case` labels (`case 4: case 6: ...`) share one `return` without any
fall-through problem. The sample's third line shows why validation comes first:
29 February 2023 does not exist.

### Concepts Practiced
- Building methods on top of other methods
- Leap-year logic with `&&`, `||` and `%`
- Grouped `switch` labels
- Validating input before computing
