# Scenario-Based Problems

These scenarios practise Chapter 14: starting threads and waiting for them with
`join()`, protecting shared data with `synchronized` and `AtomicInteger`, and running
tasks on a thread pool with `Callable` and `Future`. Thread scheduling changes from run
to run, so every program is designed to print the **same** output every time: threads
store their results, and printing happens in `main` after the work is finished.

Programs read input without prompts and print exactly the sample output. All rules in
these problems are hypothetical and invented for practice.

## Problem 1: Examiners Marking in Parallel
**Level:** Basic

### Scenario
After the final exam, the answer scripts are split into piles and each examiner adds
up the marks of their own pile at the same time as the others. The exam controller
needs each examiner's total and the grand total.

### Problem Statement
Write a class `Examiner extends Thread` that receives an examiner name and an
`int[]` of marks, adds them in `run()`, and stores the total and the number of scripts
in fields.

Input: `k`, then `k` lines `name c m1 ... mc` (an examiner with `c` scripts). Start
all `k` threads, join them all, then print in input order
`<name>: <c> scripts, total <t>, average <a with 1 decimal>` (average `0.0` for an
empty pile) and finally `Grand total: <sum> from <scripts> scripts`.

### Sample Input
```text
3
Hasan 4 55 62 71 48
Rumana 3 80 77 69
Kabir 2 90 35
```

### Sample Output
```text
Hasan: 4 scripts, total 236, average 59.0
Rumana: 3 scripts, total 226, average 75.3
Kabir: 2 scripts, total 125, average 62.5
Grand total: 587 from 9 scripts
```

### Solution
```java
import java.util.Scanner;

class Examiner extends Thread {
    private final String examinerName;
    private final int[] marks;
    private int total;

    Examiner(String examinerName, int[] marks) {
        this.examinerName = examinerName;
        this.marks = marks;
    }

    @Override
    public void run() {
        for (int m : marks) {
            total += m;
        }
    }

    String getExaminerName() {
        return examinerName;
    }

    int getTotal() {
        return total;
    }

    int getScripts() {
        return marks.length;
    }
}

public class ParallelMarking {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int k = in.nextInt();
        Examiner[] examiners = new Examiner[k];
        for (int i = 0; i < k; i++) {
            String name = in.next();
            int[] marks = new int[in.nextInt()];
            for (int j = 0; j < marks.length; j++) {
                marks[j] = in.nextInt();
            }
            examiners[i] = new Examiner(name, marks);
        }

        for (Examiner e : examiners) {
            e.start();
        }
        for (Examiner e : examiners) {
            e.join();
        }

        int grand = 0;
        int scripts = 0;
        for (Examiner e : examiners) {
            double average = e.getScripts() == 0 ? 0 : (double) e.getTotal() / e.getScripts();
            System.out.printf("%s: %d scripts, total %d, average %.1f%n",
                    e.getExaminerName(), e.getScripts(), e.getTotal(), average);
            grand += e.getTotal();
            scripts += e.getScripts();
        }
        System.out.println("Grand total: " + grand + " from " + scripts + " scripts");
    }
}
```

### Explanation
All threads are started first and joined afterwards; joining each thread right after
starting it would make them run one after another and remove all parallelism. Each
thread writes only its own `total` field, so no data is shared and no locking is
needed. `join()` does two jobs: it waits until the thread has finished, and it
guarantees that `main` sees the values the thread wrote. The output order comes from
the array, not from which thread finished first, so it never changes. (The field is
called `examinerName` because `Thread` already has a `getName()` method.)

### Concepts Practiced
- Extending `Thread` and overriding `run()`
- Starting all threads, then joining all threads
- Results stored per thread and read after `join()`

## Problem 2: Two Booths, One Stock of Tickets
**Level:** Intermediate

### Scenario
Concert tickets are sold at two booths at the same time from one shared stock. Each
sold ticket has a serial number, and no two tickets may ever get the same number or
exceed the stock, however the booths' threads interleave.

### Problem Statement
Write a class `TicketStock` with a `synchronized int sell()` that returns the next
serial number (1, 2, 3, …) or `-1` when the stock is used up. Write a `Booth`
`Runnable` that tries to sell a given number of tickets, keeps the serial numbers it
got in its own `ArrayList<Integer>`, and counts refusals.

Input: the stock size, then the requests of booth A and booth B. Run both booths on
their own threads and join them. Then print:

```text
Sold: <total sold>
Refused: <total refused>
Serials unique and complete: <true|false>
Stock left: <left>
```

"Unique and complete" means: all serial numbers from both booths, put together and
sorted, are exactly `1, 2, …, sold`. (Which booth got which number depends on timing,
so it is not printed.)

### Sample Input
```text
5000
3000 3000
```

### Sample Output
```text
Sold: 5000
Refused: 1000
Serials unique and complete: true
Stock left: 0
```

### Solution
```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Scanner;

class TicketStock {
    private final int size;
    private int sold;

    TicketStock(int size) {
        this.size = size;
    }

    synchronized int sell() {
        if (sold == size) {
            return -1;
        }
        sold++;
        return sold;
    }

    synchronized int left() {
        return size - sold;
    }
}

class Booth implements Runnable {
    private final TicketStock stock;
    private final int requests;
    private final List<Integer> serials = new ArrayList<>();
    private int refused;

    Booth(TicketStock stock, int requests) {
        this.stock = stock;
        this.requests = requests;
    }

    @Override
    public void run() {
        for (int i = 0; i < requests; i++) {
            int serial = stock.sell();
            if (serial < 0) {
                refused++;
            } else {
                serials.add(serial);
            }
        }
    }

    List<Integer> getSerials() {
        return serials;
    }

    int getRefused() {
        return refused;
    }
}

public class TwoBooths {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        TicketStock stock = new TicketStock(in.nextInt());
        Booth a = new Booth(stock, in.nextInt());
        Booth b = new Booth(stock, in.nextInt());
        Thread ta = new Thread(a);
        Thread tb = new Thread(b);
        ta.start();
        tb.start();
        ta.join();
        tb.join();

        List<Integer> all = new ArrayList<>(a.getSerials());
        all.addAll(b.getSerials());
        Collections.sort(all);
        boolean complete = true;
        for (int i = 0; i < all.size(); i++) {
            if (all.get(i) != i + 1) {
                complete = false;
            }
        }

        System.out.println("Sold: " + all.size());
        System.out.println("Refused: " + (a.getRefused() + b.getRefused()));
        System.out.println("Serials unique and complete: " + complete);
        System.out.println("Stock left: " + stock.left());
    }
}
```

### Explanation
`sell()` checks the stock, increases the counter and returns the new number as one
indivisible step, because it is `synchronized`: while one booth's thread is inside it,
the other must wait. Without that, both threads could read the same `sold` value and
hand out the same serial number twice, or both could pass the "stock left" check for
the last ticket. Each booth keeps its own list, so the lists themselves are never
shared between threads and need no locking. The final check is a strong test of
correctness: if any serial were duplicated or skipped, the sorted list would not be
exactly `1..sold`. `all.get(i) != i + 1` compares an `Integer` with an `int`, so Java
unboxes the `Integer` and compares numbers.

### Concepts Practiced
- `synchronized` methods guarding check-then-act
- Verifying a concurrent result after `join()`
- Per-thread data that needs no locking
- Sorting with `Collections.sort`

## Problem 3: Exam Hall Temperature Sensors
**Level:** Intermediate

### Scenario
During summer exams each hall has a temperature sensor that uploads a batch of
readings. A monitoring program processes all sensors at once, counts readings above
the alert limit across the whole building, and finds the hottest reading and where it
happened.

### Problem Statement
Write a class `BuildingMonitor` with:

- an `AtomicInteger alerts` counting readings above the limit;
- a `synchronized void offer(int hall, int reading)` that keeps the highest reading
  and its hall (on a tie, the **smaller hall number** wins, so the result does not
  depend on timing);
- getters.

Write a `SensorTask implements Runnable` for one hall that processes its readings.

Input: the alert limit, then `k`, then `k` lines `hall n r1 ... rn` (readings are whole
degrees). Run one thread per hall, join them all and print:

```text
Readings: <total readings>
Alerts above <limit>: <alerts>
Hottest: <reading> in hall <hall>
```

If there are no readings at all, the last line is `Hottest: none`.

### Sample Input
```text
32
3
301 4 30 33 31 34
302 3 29 30 28
303 5 34 35 31 30 33
```

### Sample Output
```text
Readings: 12
Alerts above 32: 5
Hottest: 35 in hall 303
```

### Solution
```java
import java.util.Scanner;
import java.util.concurrent.atomic.AtomicInteger;

class BuildingMonitor {
    private final int limit;
    private final AtomicInteger alerts = new AtomicInteger();
    private final AtomicInteger readings = new AtomicInteger();
    private int hottest = Integer.MIN_VALUE;
    private int hottestHall = -1;

    BuildingMonitor(int limit) {
        this.limit = limit;
    }

    void record(int hall, int reading) {
        readings.incrementAndGet();
        if (reading > limit) {
            alerts.incrementAndGet();
        }
        offer(hall, reading);
    }

    synchronized void offer(int hall, int reading) {
        if (reading > hottest || (reading == hottest && hall < hottestHall)) {
            hottest = reading;
            hottestHall = hall;
        }
    }

    int getAlerts() {
        return alerts.get();
    }

    int getReadings() {
        return readings.get();
    }

    synchronized String hottestText() {
        return hottestHall < 0 ? "none" : hottest + " in hall " + hottestHall;
    }
}

class SensorTask implements Runnable {
    private final BuildingMonitor monitor;
    private final int hall;
    private final int[] values;

    SensorTask(BuildingMonitor monitor, int hall, int[] values) {
        this.monitor = monitor;
        this.hall = hall;
        this.values = values;
    }

    @Override
    public void run() {
        for (int v : values) {
            monitor.record(hall, v);
        }
    }
}

public class HallSensors {
    public static void main(String[] args) throws InterruptedException {
        Scanner in = new Scanner(System.in);
        int limit = in.nextInt();
        BuildingMonitor monitor = new BuildingMonitor(limit);
        int k = in.nextInt();
        Thread[] threads = new Thread[k];
        for (int i = 0; i < k; i++) {
            int hall = in.nextInt();
            int[] values = new int[in.nextInt()];
            for (int j = 0; j < values.length; j++) {
                values[j] = in.nextInt();
            }
            threads[i] = new Thread(new SensorTask(monitor, hall, values));
        }
        for (Thread t : threads) {
            t.start();
        }
        for (Thread t : threads) {
            t.join();
        }
        System.out.println("Readings: " + monitor.getReadings());
        System.out.println("Alerts above " + limit + ": " + monitor.getAlerts());
        System.out.println("Hottest: " + monitor.hottestText());
    }
}
```

### Explanation
Two different tools protect two different kinds of shared data. The counters only ever
need "add one", which `AtomicInteger.incrementAndGet()` does safely without a lock. The
hottest reading is a **pair** of values (reading and hall) that must change together
and depends on comparing with the current value, so it needs a `synchronized` method;
two atomics could be updated separately and get out of step. The tie rule makes the
answer independent of which thread arrives first: with the rule "first one wins", two
halls with the same peak could give different answers on different runs.

### Concepts Practiced
- `AtomicInteger` for simple shared counters
- `synchronized` for compound state that must change together
- Designing results that do not depend on thread timing

## Problem 4: Parallel Similarity Check
**Level:** Advanced

### Scenario
Before marking a programming assignment, the course teacher compares every pair of
submitted reports to spot suspicious similarity. With many submissions the number of
pairs grows quickly, so the comparisons run on a thread pool. The report must list the
suspicious pairs in a fixed order.

### Problem Statement
Each submission is a name and one line of text. The similarity of two submissions is
the **Jaccard index** of their word sets: (number of distinct words in both) ×
100 / (number of distinct words in either), using integer division, where words are
compared in lower case and punctuation `.,;:!?` is removed.

Write a `Callable<PairResult>` named `CompareTask` for one pair; `PairResult` holds the
two names and the similarity. Submit one task per pair `(i, j)` with `i < j` (in that
order) to a fixed pool of 4 threads, collect the `Future`s in submission order and
read them in that order. Print every pair with similarity at least the threshold as
`<name1> ~ <name2>: <s>%`, sorted by similarity (highest first; ties keep submission
order), then `Pairs checked: <p>, flagged: <f>`.

Input: the threshold, `n`, then `n` lines `name text...`.

### Sample Input
```text
50
4
Rafi Java uses references, not pointers.
Sadia Java uses references and not raw pointers!
Imran Objects live on the heap in Java.
Mitu java USES references, NOT pointers
```

### Sample Output
```text
Rafi ~ Mitu: 100%
Rafi ~ Sadia: 71%
Sadia ~ Mitu: 71%
Pairs checked: 6, flagged: 3
```

### Solution
```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;
import java.util.Set;
import java.util.TreeSet;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

class PairResult {
    final String first;
    final String second;
    final int similarity;

    PairResult(String first, String second, int similarity) {
        this.first = first;
        this.second = second;
        this.similarity = similarity;
    }
}

class CompareTask implements Callable<PairResult> {
    private final String nameA;
    private final String textA;
    private final String nameB;
    private final String textB;

    CompareTask(String nameA, String textA, String nameB, String textB) {
        this.nameA = nameA;
        this.textA = textA;
        this.nameB = nameB;
        this.textB = textB;
    }

    static Set<String> words(String text) {
        Set<String> set = new TreeSet<>();
        String cleaned = text.toLowerCase().replaceAll("[.,;:!?]", " ");
        for (String w : cleaned.trim().split("\\s+")) {
            if (!w.isEmpty()) {
                set.add(w);
            }
        }
        return set;
    }

    @Override
    public PairResult call() {
        Set<String> a = words(textA);
        Set<String> b = words(textB);
        Set<String> both = new TreeSet<>(a);
        both.retainAll(b);
        Set<String> either = new TreeSet<>(a);
        either.addAll(b);
        int similarity = either.isEmpty() ? 0 : both.size() * 100 / either.size();
        return new PairResult(nameA, nameB, similarity);
    }
}

public class SimilarityCheck {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        Scanner in = new Scanner(System.in);
        int threshold = in.nextInt();
        int n = in.nextInt();
        List<String> names = new ArrayList<>();
        List<String> texts = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            names.add(in.next());
            texts.add(in.nextLine());
        }

        ExecutorService pool = Executors.newFixedThreadPool(4);
        List<PairResult> flagged = new ArrayList<>();
        int checked = 0;
        try {
            List<Future<PairResult>> futures = new ArrayList<>();
            for (int i = 0; i < n; i++) {
                for (int j = i + 1; j < n; j++) {
                    futures.add(pool.submit(new CompareTask(names.get(i), texts.get(i),
                            names.get(j), texts.get(j))));
                }
            }
            for (Future<PairResult> f : futures) {
                PairResult r = f.get();
                checked++;
                if (r.similarity >= threshold) {
                    flagged.add(r);
                }
            }
        } finally {
            pool.shutdown();
        }

        // Stable insertion sort: highest similarity first, ties keep submission order.
        for (int i = 1; i < flagged.size(); i++) {
            PairResult current = flagged.get(i);
            int j = i - 1;
            while (j >= 0 && flagged.get(j).similarity < current.similarity) {
                flagged.set(j + 1, flagged.get(j));
                j--;
            }
            flagged.set(j + 1, current);
        }
        for (PairResult r : flagged) {
            System.out.println(r.first + " ~ " + r.second + ": " + r.similarity + "%");
        }
        System.out.println("Pairs checked: " + checked + ", flagged: " + flagged.size());
    }
}
```

### Explanation
Each comparison only reads its two texts and builds its own sets, so tasks share
nothing and need no locks; this "embarrassingly parallel" shape is ideal for a thread
pool. The futures are stored in the order the pairs were submitted and read in that
order, so results arrive in a fixed order even though the tasks finish in any order.
`retainAll` keeps only the words present in both sets (the intersection) and `addAll`
gives the union. The final insertion sort only moves an element past elements with a
**smaller** similarity, so pairs with equal similarity keep their submission order: a
stable sort is what makes the output reproducible. `shutdown()` in `finally` stops the
pool's threads even if a task throws.

### Concepts Practiced
- `ExecutorService` with many `Callable` tasks
- Reading `Future` results in submission order
- Independent tasks that share no mutable data
- A stable sort for reproducible output
