# Scenario-Based Problems

These scenarios practise Chapter 05: private fields, methods that protect an object's
rules (its invariants), getters without setters where a value must not be changed from
outside, immutable classes, and abstraction (a small public interface that hides how
the work is done). Exceptions are not used yet: invalid operations are refused and
reported.

Programs read input without prompts and print exactly the sample output. All fees,
rates and rules in these problems are hypothetical and invented for practice.

## Problem 1: Medicine Fridge Monitor
**Level:** Basic

### Scenario
The campus medical centre stores vaccines in a fridge that must stay between 2 °C and
8 °C. A sensor reports readings, and staff sometimes type a target temperature. The
software must never accept a target outside the safe range and must count how many
readings were unsafe.

### Problem Statement
Write a class `Fridge` with private fields `target`, `unsafeReadings` and
`totalReadings`. The target starts at `5`. Methods:

- `boolean setTarget(int t)`: accepted only if `2 <= t <= 8`;
- `void record(int reading)`: counts the reading, and counts it as unsafe if it is
  below 2 or above 8;
- getters `getTarget()`, `getUnsafeReadings()`, `getTotalReadings()`; there is **no**
  setter for the counters.

Input: `n`, then `n` commands `TARGET t` or `READ r`. For `TARGET` print
`Target set to <t>` or `Target <t> rejected, still <current>`. For `READ` print
`<r> ok` or `<r> UNSAFE`. Finally print
`Unsafe readings: <u> of <total>` and `Target: <t>`.

### Sample Input
```text
6
READ 4
TARGET 10
TARGET 3
READ 9
READ 1
READ 8
```

### Sample Output
```text
4 ok
Target 10 rejected, still 5
Target set to 3
9 UNSAFE
1 UNSAFE
8 ok
Unsafe readings: 2 of 4
Target: 3
```

### Solution
```java
import java.util.Scanner;

class Fridge {
    private static final int MIN_SAFE = 2;
    private static final int MAX_SAFE = 8;

    private int target = 5;
    private int unsafeReadings;
    private int totalReadings;

    public boolean setTarget(int t) {
        if (t < MIN_SAFE || t > MAX_SAFE) {
            return false;
        }
        target = t;
        return true;
    }

    public boolean isSafe(int reading) {
        return reading >= MIN_SAFE && reading <= MAX_SAFE;
    }

    public void record(int reading) {
        totalReadings++;
        if (!isSafe(reading)) {
            unsafeReadings++;
        }
    }

    public int getTarget() {
        return target;
    }

    public int getUnsafeReadings() {
        return unsafeReadings;
    }

    public int getTotalReadings() {
        return totalReadings;
    }
}

public class FridgeMonitor {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Fridge fridge = new Fridge();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            int value = in.nextInt();
            if (command.equals("TARGET")) {
                if (fridge.setTarget(value)) {
                    System.out.println("Target set to " + value);
                } else {
                    System.out.println("Target " + value + " rejected, still " + fridge.getTarget());
                }
            } else {
                fridge.record(value);
                System.out.println(value + (fridge.isSafe(value) ? " ok" : " UNSAFE"));
            }
        }
        System.out.println("Unsafe readings: " + fridge.getUnsafeReadings() + " of "
                + fridge.getTotalReadings());
        System.out.println("Target: " + fridge.getTarget());
    }
}
```

### Explanation
The rule "the target is always between 2 and 8" can never be broken, because `target`
is private and the only way to change it is `setTarget`, which checks the range. The
counters have getters but no setters: other code may read them, but only `record` can
change them, and always correctly. The safe range is written once, as two constants,
and both `setTarget` and `isSafe` use them. Returning `boolean` from `setTarget` lets
`main` decide how to report a refusal.

### Concepts Practiced
- `private` fields with validated setters
- Getters without setters for derived data
- Keeping an invariant inside the class

## Problem 2: Immutable Money in a Wallet
**Level:** Intermediate

### Scenario
A mobile-wallet team keeps losing paisa because of `double` rounding. They decide to
store every amount as a whole number of paisa (100 paisa = 1 Tk) in an immutable
`Money` class, so that an amount can never be changed by accident once created.

### Problem Statement
Write an immutable class `Money`:

- `private final long paisa`; a constructor `Money(long paisa)`;
- `Money plus(Money other)` and `Money minus(Money other)` return **new** objects;
- `boolean isLessThan(Money other)`;
- `toString()` returns `Tk <taka>.<paisa with 2 digits>`, e.g. `Tk 12.05`
  (amounts are never negative in this program);
- a static method `Money parse(String text)` that accepts `"12"`, `"12.5"` or
  `"12.05"` (at most 2 digits after the point).

Write a class `Wallet` with a `private Money balance` (starting at zero) and methods
`void deposit(Money m)` and `boolean pay(Money m)` (refused if the balance is less
than `m`).

Input: `n`, then `n` commands `DEPOSIT amount` or `PAY amount`. Print
`Deposited <m>, balance <b>`, `Paid <m>, balance <b>` or
`Refused <m>, balance <b>`. Finally print `Final: <b>`.

### Sample Input
```text
5
DEPOSIT 100
PAY 37.5
PAY 62.51
DEPOSIT 0.05
PAY 62.55
```

### Sample Output
```text
Deposited Tk 100.00, balance Tk 100.00
Paid Tk 37.50, balance Tk 62.50
Refused Tk 62.51, balance Tk 62.50
Deposited Tk 0.05, balance Tk 62.55
Paid Tk 62.55, balance Tk 0.00
Final: Tk 0.00
```

### Solution
```java
import java.util.Scanner;

final class Money {
    private final long paisa;

    Money(long paisa) {
        this.paisa = paisa;
    }

    static Money parse(String text) {
        int dot = text.indexOf('.');
        if (dot < 0) {
            return new Money(Long.parseLong(text) * 100);
        }
        long taka = Long.parseLong(text.substring(0, dot));
        String fraction = text.substring(dot + 1);
        if (fraction.length() == 1) {
            fraction = fraction + "0";
        }
        return new Money(taka * 100 + Long.parseLong(fraction));
    }

    Money plus(Money other) {
        return new Money(paisa + other.paisa);
    }

    Money minus(Money other) {
        return new Money(paisa - other.paisa);
    }

    boolean isLessThan(Money other) {
        return paisa < other.paisa;
    }

    @Override
    public String toString() {
        return String.format("Tk %d.%02d", paisa / 100, paisa % 100);
    }
}

class Wallet {
    private Money balance = new Money(0);

    void deposit(Money m) {
        balance = balance.plus(m);
    }

    boolean pay(Money m) {
        if (balance.isLessThan(m)) {
            return false;
        }
        balance = balance.minus(m);
        return true;
    }

    Money getBalance() {
        return balance;
    }
}

public class MoneyWallet {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Wallet wallet = new Wallet();
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            Money amount = Money.parse(in.next());
            if (command.equals("DEPOSIT")) {
                wallet.deposit(amount);
                System.out.println("Deposited " + amount + ", balance " + wallet.getBalance());
            } else if (wallet.pay(amount)) {
                System.out.println("Paid " + amount + ", balance " + wallet.getBalance());
            } else {
                System.out.println("Refused " + amount + ", balance " + wallet.getBalance());
            }
        }
        System.out.println("Final: " + wallet.getBalance());
    }
}
```

### Explanation
`Money` is immutable: its only field is `private final`, there are no setters, and the
class itself is `final` so nobody can create a mutable subclass. `plus` and `minus`
never change `this`; they return a new `Money`, just like `String` methods return new
strings. The `Wallet` still changes over time, but it does so by replacing its `balance`
reference with a new object. That is why `getBalance()` can safely return the internal
object: nobody can modify it through that reference. Storing whole paisa in a `long`
makes every addition exact, unlike `double`. `parse` turns `"37.5"` into 37 Tk and
`"5"` + `"0"` = 50 paisa, so one-digit fractions are read correctly.

### Concepts Practiced
- Immutable classes (`final` class, `private final` fields)
- Methods that return new objects instead of changing state
- Encapsulating a representation (paisa) behind a clear interface
- Static factory method `parse`

## Problem 3: PIN-Protected Grade Book
**Level:** Intermediate

### Scenario
A course teacher keeps marks for one lab group in a small program. Teaching assistants
can view marks, but only someone with the PIN may change them. After three wrong PINs
in a row the grade book locks itself, and only the course coordinator's master code
can unlock it.

### Problem Statement
Write a class `GradeBook` for a group of three students (`marksA`, `marksB`, `marksC`,
all starting at 0) with a private PIN given in the constructor and a fixed private
master code `"COORD-77"`. There is **no getter for the PIN**.

Methods (each returns the line to print):

- `update(String pin, char student, int marks)`:
  - locked → `LOCKED`;
  - wrong PIN → `Wrong PIN (<k> of 3)`; the third wrong PIN in a row also locks the book
    and prints `Wrong PIN (3 of 3), book locked`;
  - correct PIN resets the wrong-PIN counter; marks outside 0–100 → `Marks must be 0 to 100`;
    unknown student → `No student <s>`; otherwise `<s> = <marks>`.
- `view()`: `A=<a> B=<b> C=<c>` (allowed even when locked);
- `unlock(String code)`: `Unlocked` (and resets the counter) if the code equals the
  master code, otherwise `Unlock refused`.

Input: the PIN on the first line, then `n`, then `n` commands
`UPDATE pin student marks`, `VIEW` or `UNLOCK code`.

### Sample Input
```text
4821
7
UPDATE 4821 A 78
UPDATE 1111 B 90
UPDATE 4821 B 120
UPDATE 0000 B 90
UPDATE 9999 B 90
UPDATE 1234 B 90
VIEW
```

### Sample Output
```text
A = 78
Wrong PIN (1 of 3)
Marks must be 0 to 100
Wrong PIN (1 of 3)
Wrong PIN (2 of 3)
Wrong PIN (3 of 3), book locked
A=78 B=0 C=0
```

### Solution
```java
import java.util.Scanner;

class GradeBook {
    private static final String MASTER_CODE = "COORD-77";
    private static final int MAX_WRONG = 3;

    private final String pin;
    private int marksA;
    private int marksB;
    private int marksC;
    private int wrongInARow;
    private boolean locked;

    GradeBook(String pin) {
        this.pin = pin;
    }

    public String update(String givenPin, char student, int marks) {
        if (locked) {
            return "LOCKED";
        }
        if (!pin.equals(givenPin)) {
            wrongInARow++;
            if (wrongInARow == MAX_WRONG) {
                locked = true;
                return "Wrong PIN (" + wrongInARow + " of " + MAX_WRONG + "), book locked";
            }
            return "Wrong PIN (" + wrongInARow + " of " + MAX_WRONG + ")";
        }
        wrongInARow = 0;
        if (marks < 0 || marks > 100) {
            return "Marks must be 0 to 100";
        }
        if (student == 'A') {
            marksA = marks;
        } else if (student == 'B') {
            marksB = marks;
        } else if (student == 'C') {
            marksC = marks;
        } else {
            return "No student " + student;
        }
        return student + " = " + marks;
    }

    public String view() {
        return "A=" + marksA + " B=" + marksB + " C=" + marksC;
    }

    public String unlock(String code) {
        if (!MASTER_CODE.equals(code)) {
            return "Unlock refused";
        }
        locked = false;
        wrongInARow = 0;
        return "Unlocked";
    }
}

public class GradeBookDemo {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        GradeBook book = new GradeBook(in.next());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("UPDATE")) {
                String pin = in.next();
                char student = in.next().charAt(0);
                int marks = in.nextInt();
                System.out.println(book.update(pin, student, marks));
            } else if (command.equals("VIEW")) {
                System.out.println(book.view());
            } else {
                System.out.println(book.unlock(in.next()));
            }
        }
    }
}
```

### Explanation
The PIN is written once (in the constructor) and only ever **compared** inside the
class; no method returns it. That is data hiding: other code can use the PIN check
without being able to read the PIN. The lock is part of the object's state, and every
method that changes marks checks it first, so it cannot be bypassed. The wrong-PIN
counter counts wrong attempts **in a row**: a correct PIN resets it, as the sample
shows, where the third wrong PIN overall does not lock the book because a correct PIN
came in between. Comparing strings uses `equals`, never `==`.

### Concepts Practiced
- Hiding secret data (no getter)
- An object that guards its own state (a lock)
- Counting consecutive events
- Comparing strings with `equals`

## Problem 4: Fuel Pump with a Shift Report
**Level:** Advanced

### Scenario
A fuel station near the campus wants honest accounting for each shift. Sales are typed
in taka, the pump converts them to fuel, the tank has a fixed capacity, and at any time
the manager can ask for a report. The report must be a snapshot: changing it must never
change the pump.

### Problem Statement
Work only in whole numbers: millilitres (mL) and paisa.

- `FuelPrice` (immutable): fuel name and price in paisa **per litre**.
- `ShiftReport` (immutable): litres sold (mL), sales (paisa), number of sales and the
  tank level (mL); `toString()` returns
  `Sold <L> L in <k> sales, Tk <taka>, tank <L> L` with litres printed with 3 decimals
  (from mL) and taka with 2 decimals (from paisa).
- `Pump`: a private `FuelPrice`, the tank capacity and level (mL) and the running
  totals. Methods:
  - `String sell(long takaAmount)`: the fuel is `takaAmount × 100 × 1000 / pricePerLitre`
    mL (integer division); refused with `Not enough fuel (<needed> mL needed, <level> mL left)`
    if the tank has less; refused with `Invalid amount` if `takaAmount <= 0`; otherwise
    returns `Sold <mL> mL of <fuel> for Tk <taka>`.
  - `String refill(long litres)`: adds `litres × 1000` mL; refused with
    `Invalid amount` if `litres <= 0`, or with `Tank capacity exceeded` if it would
    overflow; otherwise `Tank at <mL> mL`.
  - `ShiftReport report()`: a **new** snapshot each time.

Input: fuel name, price in paisa per litre, tank capacity in litres and initial level
in litres (one line); then `n` and `n` commands `SELL taka`, `REFILL litres` or
`REPORT`. Print what each method returns (`REPORT` prints the report).

### Sample Input
```text
Octane 13500 50 20
5
SELL 1000
SELL 2000
REFILL 40
REFILL 30
REPORT
```

### Sample Output
```text
Sold 7407 mL of Octane for Tk 1000
Not enough fuel (14814 mL needed, 12593 mL left)
Tank capacity exceeded
Tank at 42593 mL
Sold 7.407 L in 1 sales, Tk 1000.00, tank 42.593 L
```

### Solution
```java
import java.util.Scanner;

final class FuelPrice {
    private final String fuel;
    private final long paisaPerLitre;

    FuelPrice(String fuel, long paisaPerLitre) {
        this.fuel = fuel;
        this.paisaPerLitre = paisaPerLitre;
    }

    String getFuel() {
        return fuel;
    }

    long getPaisaPerLitre() {
        return paisaPerLitre;
    }
}

final class ShiftReport {
    private final long soldMl;
    private final long salesPaisa;
    private final int salesCount;
    private final long tankMl;

    ShiftReport(long soldMl, long salesPaisa, int salesCount, long tankMl) {
        this.soldMl = soldMl;
        this.salesPaisa = salesPaisa;
        this.salesCount = salesCount;
        this.tankMl = tankMl;
    }

    private static String litres(long ml) {
        return String.format("%d.%03d", ml / 1000, ml % 1000);
    }

    @Override
    public String toString() {
        return "Sold " + litres(soldMl) + " L in " + salesCount + " sales, Tk "
                + String.format("%d.%02d", salesPaisa / 100, salesPaisa % 100)
                + ", tank " + litres(tankMl) + " L";
    }
}

class Pump {
    private final FuelPrice price;
    private final long capacityMl;
    private long levelMl;
    private long soldMl;
    private long salesPaisa;
    private int salesCount;

    Pump(FuelPrice price, long capacityLitres, long levelLitres) {
        this.price = price;
        this.capacityMl = capacityLitres * 1000;
        this.levelMl = levelLitres * 1000;
    }

    String sell(long takaAmount) {
        if (takaAmount <= 0) {
            return "Invalid amount";
        }
        long ml = takaAmount * 100 * 1000 / price.getPaisaPerLitre();
        if (ml > levelMl) {
            return "Not enough fuel (" + ml + " mL needed, " + levelMl + " mL left)";
        }
        levelMl -= ml;
        soldMl += ml;
        salesPaisa += takaAmount * 100;
        salesCount++;
        return "Sold " + ml + " mL of " + price.getFuel() + " for Tk " + takaAmount;
    }

    String refill(long litres) {
        if (litres <= 0) {
            return "Invalid amount";
        }
        long added = litres * 1000;
        if (levelMl + added > capacityMl) {
            return "Tank capacity exceeded";
        }
        levelMl += added;
        return "Tank at " + levelMl + " mL";
    }

    ShiftReport report() {
        return new ShiftReport(soldMl, salesPaisa, salesCount, levelMl);
    }
}

public class FuelPumpShift {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        FuelPrice price = new FuelPrice(in.next(), in.nextLong());
        Pump pump = new Pump(price, in.nextLong(), in.nextLong());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("SELL")) {
                System.out.println(pump.sell(in.nextLong()));
            } else if (command.equals("REFILL")) {
                System.out.println(pump.refill(in.nextLong()));
            } else {
                System.out.println(pump.report());
            }
        }
    }
}
```

### Explanation
Three classes, three responsibilities. `FuelPrice` and `ShiftReport` are immutable
value objects: once made, they cannot change. `Pump` is the only object with changing
state, and every change goes through `sell` or `refill`, which protect the invariants
(the level never goes below 0 or above capacity, and the totals always match the
sales). `report()` returns a new `ShiftReport` built from copies of the numbers, not a
reference to the pump's own fields, so whoever receives a report cannot affect the
pump. This is a common encapsulation technique: give out snapshots, keep the live
state private. Working in mL and paisa keeps every calculation exact; conversion to
litres and taka happens only when printing. For the sample, Tk 1000 at Tk 135.00 per
litre buys `1000 × 100 × 1000 / 13500 = 7407` mL.

### Concepts Practiced
- Several cooperating classes with clear responsibilities
- Immutable value objects
- Returning snapshots instead of internal state
- Exact integer units (mL, paisa)
