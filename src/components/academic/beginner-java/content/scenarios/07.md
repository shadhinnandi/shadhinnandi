# Scenario-Based Problems

These scenarios practise Chapter 07: deciding what belongs to each object (instance
members) and what belongs to the class as a whole (`static` members). Typical static
uses are counters and ID generators, shared settings, constants, utility methods and
factory methods. A static member is shared by every object, so changing it affects
them all.

Programs read input without prompts and print exactly the sample output. All fees,
rates and rules in these problems are hypothetical and invented for practice.

## Problem 1: Maintenance Complaint Tickets
**Level:** Basic

### Scenario
Students report broken fans, lights and projectors through a help desk. Every
complaint gets a ticket number, starting at 1001, and the desk wants to know how many
tickets exist and how many are urgent, without searching through them.

### Problem Statement
Write a class `Ticket` with:

- a `private static int nextNumber` starting at `1001`, and `private static int urgentCount`;
- instance fields `number`, `room`, `problem` and `urgent`, set in the constructor; the
  constructor takes the next number and updates the urgent count;
- `static int issued()` returning how many tickets were created;
- `static int urgent()` returning the urgent count;
- `toString()` returning `#<number> room <room>: <problem>` plus ` [URGENT]` for urgent
  tickets.

Input: `n`, then `n` lines `room U|N problem words...` (`U` urgent, `N` normal). Print
each ticket as it is created, then `Issued: <k>, urgent: <u>, next number: <next>`.

### Sample Input
```text
4
702 N Projector remote missing
315 U Fan sparking
1101 N Light flickering
315 U Water leak near socket
```

### Sample Output
```text
#1001 room 702: Projector remote missing
#1002 room 315: Fan sparking [URGENT]
#1003 room 1101: Light flickering
#1004 room 315: Water leak near socket [URGENT]
Issued: 4, urgent: 2, next number: 1005
```

### Solution
```java
import java.util.Scanner;

class Ticket {
    private static final int FIRST_NUMBER = 1001;
    private static int nextNumber = FIRST_NUMBER;
    private static int urgentCount = 0;

    private final int number;
    private final String room;
    private final String problem;
    private final boolean urgent;

    Ticket(String room, boolean urgent, String problem) {
        this.number = nextNumber;
        nextNumber++;
        this.room = room;
        this.problem = problem;
        this.urgent = urgent;
        if (urgent) {
            urgentCount++;
        }
    }

    static int issued() {
        return nextNumber - FIRST_NUMBER;
    }

    static int urgent() {
        return urgentCount;
    }

    static int peekNext() {
        return nextNumber;
    }

    @Override
    public String toString() {
        return "#" + number + " room " + room + ": " + problem + (urgent ? " [URGENT]" : "");
    }
}

public class HelpDesk {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String room = in.next();
            boolean urgent = in.next().equals("U");
            String problem = in.nextLine().trim();
            System.out.println(new Ticket(room, urgent, problem));
        }
        System.out.println("Issued: " + Ticket.issued() + ", urgent: " + Ticket.urgent()
                + ", next number: " + Ticket.peekNext());
    }
}
```

### Explanation
`nextNumber` and `urgentCount` are `static`, so there is exactly one copy of each,
shared by all tickets; every new ticket sees the values left by the previous one. The
ticket's own `number` is an instance field: each ticket keeps the number it received
when it was created. The static methods are called on the class (`Ticket.issued()`),
because the questions they answer are about all tickets, not one ticket. `issued()`
computes the count from the counter instead of keeping a third variable that could get
out of step.

### Concepts Practiced
- `static` counters shared by all objects
- Assigning IDs in the constructor
- `static` methods called through the class name
- Instance fields versus static fields

## Problem 2: Shared VAT in the Campus Store
**Level:** Intermediate

### Scenario
The campus store lists three products. The government VAT rate applies to every
product equally, and when it changes, every price tag must change at once. The store
manager wants to see the effect of different VAT rates.

### Problem Statement
Write a class `Product` with instance fields `name` and `basePrice` (whole Tk) and a
`private static int vatPercent` starting at `15`. Provide:

- `static boolean setVat(int percent)`: accepted only for 0 to 25;
- `static int getVat()`;
- `int priceWithVat()`: `basePrice + basePrice × vatPercent / 100` (integer).

Input: three lines `name basePrice`, then `n` commands: `VAT p` or `LIST`. For `VAT`
print `VAT now <p>%` or `VAT <p>% rejected, still <current>%`. For `LIST` print
`At <vat>% VAT:` and each product as `  <name>: <base> + VAT = <price> Tk`.

### Sample Input
```text
Notebook 120
Pen 20
Calculator 1450
4
LIST
VAT 5
LIST
VAT 30
```

### Sample Output
```text
At 15% VAT:
  Notebook: 120 + VAT = 138 Tk
  Pen: 20 + VAT = 23 Tk
  Calculator: 1450 + VAT = 1667 Tk
VAT now 5%
At 5% VAT:
  Notebook: 120 + VAT = 126 Tk
  Pen: 20 + VAT = 21 Tk
  Calculator: 1450 + VAT = 1522 Tk
VAT 30% rejected, still 5%
```

### Solution
```java
import java.util.Scanner;

class Product {
    private static final int MAX_VAT = 25;
    private static int vatPercent = 15;

    private final String name;
    private final int basePrice;

    Product(String name, int basePrice) {
        this.name = name;
        this.basePrice = basePrice;
    }

    static boolean setVat(int percent) {
        if (percent < 0 || percent > MAX_VAT) {
            return false;
        }
        vatPercent = percent;
        return true;
    }

    static int getVat() {
        return vatPercent;
    }

    int priceWithVat() {
        return basePrice + basePrice * vatPercent / 100;
    }

    String line() {
        return "  " + name + ": " + basePrice + " + VAT = " + priceWithVat() + " Tk";
    }
}

public class CampusStoreVat {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Product p1 = new Product(in.next(), in.nextInt());
        Product p2 = new Product(in.next(), in.nextInt());
        Product p3 = new Product(in.next(), in.nextInt());
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("VAT")) {
                int percent = in.nextInt();
                if (Product.setVat(percent)) {
                    System.out.println("VAT now " + percent + "%");
                } else {
                    System.out.println("VAT " + percent + "% rejected, still " + Product.getVat() + "%");
                }
            } else {
                System.out.println("At " + Product.getVat() + "% VAT:");
                System.out.println(p1.line());
                System.out.println(p2.line());
                System.out.println(p3.line());
            }
        }
    }
}
```

### Explanation
The VAT rate is a property of the whole store, not of one product, so it is `static`.
When `Product.setVat(5)` runs, all three products see the new rate the next time they
compute a price, without any loop over the products. The static setter still validates
its input, exactly like an instance setter would. An instance method such as
`priceWithVat()` may read static fields; the reverse is not true: a static method has
no current object, so it could not read `basePrice`.

### Concepts Practiced
- A shared setting stored in a `static` field
- Validating a static setter
- Instance methods reading static data

## Problem 3: Unit Conversion Utility
**Level:** Intermediate

### Scenario
The physics lab keeps writing the same conversion formulas in every program. The lab
coordinator asks for one utility class that every program can use without creating an
object, with the conversion factors stored as named constants.

### Problem Statement
Write a `final` class `Units` with a **private** constructor (so no objects can be
created), `public static final double` constants `KM_PER_MILE = 1.609344`,
`FEET_PER_METRE = 3.28084` and `KG_PER_POUND = 0.45359237`, and static methods:

- `static double convert(double value, String from, String to)` supporting
  `km`↔`mi`, `m`↔`ft`, `kg`↔`lb`, and `C`↔`F` (`F = C × 9 / 5 + 32`);
- `static boolean supported(String from, String to)`.

Input: `n`, then `n` lines `value from to`. Print `<value> <from> = <result> <to>` with
both numbers printed with 3 decimals, or `Cannot convert <from> to <to>` for an
unsupported pair (including converting a unit to itself).

### Sample Input
```text
5
10 km mi
26.2 mi km
100 C F
70 kg lb
5 m kg
```

### Sample Output
```text
10.000 km = 6.214 mi
26.200 mi = 42.165 km
100.000 C = 212.000 F
70.000 kg = 154.324 lb
Cannot convert m to kg
```

### Solution
```java
import java.util.Scanner;

final class Units {
    public static final double KM_PER_MILE = 1.609344;
    public static final double FEET_PER_METRE = 3.28084;
    public static final double KG_PER_POUND = 0.45359237;

    private Units() {
    }

    static boolean supported(String from, String to) {
        String pair = from + ">" + to;
        switch (pair) {
            case "km>mi":
            case "mi>km":
            case "m>ft":
            case "ft>m":
            case "kg>lb":
            case "lb>kg":
            case "C>F":
            case "F>C":
                return true;
            default:
                return false;
        }
    }

    static double convert(double value, String from, String to) {
        switch (from + ">" + to) {
            case "km>mi":
                return value / KM_PER_MILE;
            case "mi>km":
                return value * KM_PER_MILE;
            case "m>ft":
                return value * FEET_PER_METRE;
            case "ft>m":
                return value / FEET_PER_METRE;
            case "kg>lb":
                return value / KG_PER_POUND;
            case "lb>kg":
                return value * KG_PER_POUND;
            case "C>F":
                return value * 9 / 5 + 32;
            default:
                return (value - 32) * 5 / 9;
        }
    }
}

public class LabConversions {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            double value = in.nextDouble();
            String from = in.next();
            String to = in.next();
            if (Units.supported(from, to)) {
                double result = Units.convert(value, from, to);
                System.out.printf("%.3f %s = %.3f %s%n", value, from, result, to);
            } else {
                System.out.println("Cannot convert " + from + " to " + to);
            }
        }
    }
}
```

### Explanation
A utility class holds behaviour that needs no object state, like `Math`. The private
constructor makes `new Units()` a compile error, which documents that the class is not
meant to be instantiated, and `final` stops anyone from subclassing it. The factors are
`public static final`: shared, visible and impossible to change. Joining `from` and
`to` into one key such as `"km>mi"` lets a single `switch` on a `String` handle every
pair. `convert` is only called after `supported` returned `true`, so its `default`
branch can safely handle the last remaining case (`F>C`).

### Concepts Practiced
- Utility classes with a private constructor
- `public static final` constants
- `switch` on strings with grouped labels
- Separating validation from computation

## Problem 4: Office Token Desks
**Level:** Advanced

### Scenario
The administration building has three desks: Admission (`A`), Registration (`R`) and
Accounts (`C`). Visitors take a numbered token for one desk, and each desk calls its
tokens in order. The office manager wants a daily summary across all desks, and the
code must make it impossible to create a fourth desk by accident.

### Problem Statement
Write a class `Desk` with:

- three `public static final Desk` constants `ADMISSION`, `REGISTRATION`, `ACCOUNTS`
  created with a **private** constructor `Desk(char code, String name)`;
- instance counters `issued` and `called` (each desk numbers its tokens from 1);
- `private static int totalIssued` and `private static int totalServed` shared by all
  desks;
- `static Desk forCode(char c)` returning the matching constant or `null`;
- `String issue()`: `Token <code>-<3-digit number> issued (<w> waiting)`;
- `String callNext()`: `Now serving <code>-<number>` or `No one waiting at <name>`;
- `String report()`: `<name>: issued <i>, served <s>, waiting <w>`;
- `static String summary()`: `Total issued <t>, served <s>`.

Input: `n`, then `n` commands `ISSUE c`, `CALL c` or `REPORT` (`c` is a desk code). An
unknown code prints `Unknown desk <c>`. `REPORT` prints the three desk reports in the
order A, R, C followed by the summary.

### Sample Input
```text
8
ISSUE A
ISSUE A
ISSUE R
CALL A
CALL C
ISSUE X
CALL R
REPORT
```

### Sample Output
```text
Token A-001 issued (1 waiting)
Token A-002 issued (2 waiting)
Token R-001 issued (1 waiting)
Now serving A-001
No one waiting at Accounts
Unknown desk X
Now serving R-001
Admission: issued 2, served 1, waiting 1
Registration: issued 1, served 1, waiting 0
Accounts: issued 0, served 0, waiting 0
Total issued 3, served 2
```

### Solution
```java
import java.util.Scanner;

class Desk {
    public static final Desk ADMISSION = new Desk('A', "Admission");
    public static final Desk REGISTRATION = new Desk('R', "Registration");
    public static final Desk ACCOUNTS = new Desk('C', "Accounts");

    private static int totalIssued = 0;
    private static int totalServed = 0;

    private final char code;
    private final String name;
    private int issued;
    private int called;

    private Desk(char code, String name) {
        this.code = code;
        this.name = name;
    }

    static Desk forCode(char c) {
        if (c == 'A') {
            return ADMISSION;
        } else if (c == 'R') {
            return REGISTRATION;
        } else if (c == 'C') {
            return ACCOUNTS;
        }
        return null;
    }

    private int waiting() {
        return issued - called;
    }

    String issue() {
        issued++;
        totalIssued++;
        return String.format("Token %c-%03d issued (%d waiting)", code, issued, waiting());
    }

    String callNext() {
        if (waiting() == 0) {
            return "No one waiting at " + name;
        }
        called++;
        totalServed++;
        return String.format("Now serving %c-%03d", code, called);
    }

    String report() {
        return name + ": issued " + issued + ", served " + called + ", waiting " + waiting();
    }

    static String summary() {
        return "Total issued " + totalIssued + ", served " + totalServed;
    }
}

public class TokenDesks {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String command = in.next();
            if (command.equals("REPORT")) {
                System.out.println(Desk.ADMISSION.report());
                System.out.println(Desk.REGISTRATION.report());
                System.out.println(Desk.ACCOUNTS.report());
                System.out.println(Desk.summary());
                continue;
            }
            char c = in.next().charAt(0);
            Desk desk = Desk.forCode(c);
            if (desk == null) {
                System.out.println("Unknown desk " + c);
            } else if (command.equals("ISSUE")) {
                System.out.println(desk.issue());
            } else {
                System.out.println(desk.callNext());
            }
        }
    }
}
```

### Explanation
The class decides exactly which objects exist: the constructor is private, so the only
`Desk` objects are the three `public static final` constants created when the class is
loaded. `forCode` is a static factory-style lookup that returns one of them. Each desk
has its own `issued` and `called` counters (instance data: Admission's numbers are
separate from Registration's), while `totalIssued` and `totalServed` are static because
they describe all desks together. Both kinds of counter are updated in the same
methods, so they always agree. `%03d` pads the token number to three digits. (An
`enum` is Java's built-in way to declare such a fixed set of constants; this problem
shows the idea underneath it.)

### Concepts Practiced
- `static final` instances and a private constructor
- Instance counters versus static totals
- Static lookup (factory) methods
- Formatting with `%03d`
