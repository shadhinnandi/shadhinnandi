# Chapter 07: Static and Instance Members

Until now, every field you wrote belonged to one object: each `Student` had its own
name and its own CGPA. Some data does not belong to any single object, though. The
number of students created so far, the VAT rate that every product uses, or the value
of pi are facts about the whole class, not about one object. This chapter shows how
Java marks such members with the keyword `static`, and how to decide when a member
should be static and when it should not.

**In this chapter you will learn:**

- the difference between instance variables (one copy per object) and static
  variables (one copy per class)
- the difference between instance methods and static methods, and how to call each
- how to build object counters and auto-generated IDs
- how to declare constants with `static final` and run setup code in static
  initializer blocks
- how to write utility classes and factory methods
- what a static nested class is
- why `this` does not exist in a static context, and why `main` is static
- when `static` is the right choice and when it is a design mistake
- how to use an `enum` for a fixed set of named values

## 1. Concept Explanation

### Two kinds of members

The **members** of a class are its fields and its methods. Every member is one of two
kinds:

- An **instance member** belongs to each object. Every object gets its own copy of an
  instance field, and an instance method always runs on one particular object.
- A **static member** (also called a **class member**) belongs to the class itself.
  There is exactly one copy of a static field, no matter how many objects exist, and a
  static method runs without any object.

You mark a member as static with the keyword `static`. Without that keyword, a member
is an instance member. Everything you wrote in Chapters 04 to 06 (except `main` and
the helper methods of Chapter 03) was an instance member.

| | Instance member | Static member |
|---|---|---|
| Belongs to | one object | the class |
| Number of copies (fields) | one per object | exactly one |
| Exists from | `new` creates the object | the class is first used |
| Usual access | `reference.name` | `ClassName.name` |
| Has a current object (`this`) | yes | no |

### Instance variables: one copy per object

An instance variable (instance field) describes the state of one object. Two students
have different names, so `name` must be an instance field.

```java
class Student {
    String name;   // instance field: every Student has its own
    double cgpa;   // instance field
}
```

```java
Student s1 = new Student();
Student s2 = new Student();
s1.name = "Nusrat";
s2.name = "Tanvir";   // does not touch s1.name
```

Each `new Student()` creates a fresh object on the heap with its own `name` and `cgpa`.
Changing one object's field never changes another object's field.

### Static variables: one copy per class

A static variable (static field, class variable) is declared with `static`. Java keeps
it with the class, not inside any object. There is one copy, and every object of the
class (and every static method) sees that same copy.

```java
class Student {
    static int count;   // static field: ONE copy, shared
    String name;        // instance field: one copy per object
}
```

Here is the picture after three `Student` objects have been created:

```text
                 class Student (one copy of static data)
               +----------------------------------+
               | static int count = 3             |
               +----------------------------------+
                  ^              ^              ^
                  | shared       | shared       | shared
   +--------------+--+  +--------+--------+  +--+--------------+
   | name = "Rahim"  |  | name = "Nusrat" |  | name = "Karim"  |
   +-----------------+  +-----------------+  +-----------------+
       object 1             object 2             object 3
   (each object has its own name, but there is only one count)
```

An analogy: in a classroom, every student writes in their own notebook (instance
data), but there is one whiteboard at the front that everyone reads (static data).
If one student writes on the whiteboard, everyone sees the change.

In Java terms: a static field is created once, when the class is first used. It gets
the same default values as other fields (`0`, `false`, `null`). It exists even when no
object of the class has been created yet.

### Instance methods vs static methods

An **instance method** is called on an object: `account.deposit(500)`. Inside it,
there is a current object (`this`), so the method can read and change that object's
instance fields. It can also use static fields and static methods.

A **static method** is called on the class: `Math.sqrt(16.0)`. Inside it, there is no
current object. It can use static fields and other static methods directly. It can use
instance members only through an object reference that it receives as a parameter or
creates itself.

| Code inside ... | can use instance members directly? | can use static members? |
|---|---|---|
| an instance method | yes (of `this` object) | yes |
| a static method | no, only via a reference | yes |

You already know static methods. In Chapter 03 you wrote helper methods like
`static int square(int x)` in the class that holds `main`. `Math.max`, `Math.sqrt` and
`Integer.parseInt` are static methods of Java's own classes.

### Calling static members through the class name

Outside its class, you reach a static member through the **class name**:

```java
double root = Math.sqrt(49.0);    // static method of class Math
int total = Student.count;        // static field of class Student
int big = Integer.MAX_VALUE;      // static constant of class Integer
```

Inside the same class you can simply write the name (`count`), because the compiler
knows which class you mean.

Java also *allows* `s1.count` (a static field reached through an object reference),
but it is misleading: it looks like `s1` has its own `count`, which is false. The
compiler warns about it when warnings are enabled. Always use the class name.

### Object counters and auto-generated IDs

A classic use of a static field is counting how many objects were created. The
constructor runs once per object, so it is the right place to increase the counter:

```java
class Student {
    private static int count = 0;

    Student() {
        count++;   // one more Student has been created
    }
}
```

The same idea gives every object a unique, automatic ID. A static field remembers the
**next** number to hand out. Each constructor copies it into the object's own `final`
`id` field and then increases it:

```java
class Student {
    private static int nextId = 1;   // shared: the next number to use
    private final int id;            // own: this student's number

    Student() {
        id = nextId;   // take the current number
        nextId++;      // prepare the number for the next object
    }
}
```

The first student gets 1, the second gets 2, and so on. Nobody can forget to set the
ID or set the same ID twice, because only the constructor touches `nextId`.

### Constants with `static final`

A **constant** is a value that never changes, like pi or the passing mark of an exam.
You declare it with both keywords:

```java
static final int PASS_MARK = 40;
static final double VAT_RATE = 0.15;
```

- `final` means the value cannot change after it is set.
- `static` means there is only one copy. A constant is the same for every object, so
  storing it again inside each object would only waste memory.

Constant names use `UPPER_SNAKE_CASE`. Java's own examples are `Math.PI` and
`Integer.MAX_VALUE`.

Do not confuse this with a `final` **instance** field (Chapters 05 and 06). A `final`
instance field such as a student's `id` is fixed after the constructor runs, but it is
different for every object. A `static final` field is one value for the whole class.

| Declaration | Copies | Can change? | Example |
|---|---|---|---|
| `int marks;` | one per object | yes | a student's marks |
| `final int id;` | one per object | no (set in constructor) | a student's ID |
| `static int count;` | one per class | yes | number of students |
| `static final int MAX = 100;` | one per class | no | highest possible mark |

### Static initializer blocks

Sometimes a static field needs more than a single expression to set up, for example a
loop or an `if`. For that, Java has a **static initializer block**: a block of code
written as `static { ... }` directly inside the class.

A static initializer block runs **once**, when the class is initialized. That happens
just before the class is first really used: the first object is created, a static
method is called, or a static field is read (constants like `static final int X = 5;`
are an exception: the compiler copies their value directly). Static field initializers
and static blocks run from top to bottom in the order they are written.

```text
  first use of class Shop
          |
          v
  static fields and static { } blocks run   (ONCE per program run)
          |
          v
  new Shop()  -->  instance fields  -->  constructor body
  new Shop()  -->  instance fields  -->  constructor body
  new Shop()  -->  instance fields  -->  constructor body
```

Compare this with the instance initialization order from Chapter 06: instance
initialization happens again for **every** object; static initialization happens only
once for the class.

### Utility classes

A **utility class** is a class that only groups related static methods (and maybe
constants). It has no state of its own, so you never need an object of it. `Math` is
the best-known example: you write `Math.sqrt(2.0)`, never `new Math()`.

When you write your own utility class:

- make every method `static`
- give the class a `private` constructor, so that nobody can create a useless object
  of it (`new GradeUtil()` then becomes a compile error)
- optionally mark the class `final`, so nobody can extend it (Chapter 09)

A method is a good candidate for a utility class when its result depends **only on
its parameters**, like converting Celsius to Fahrenheit or turning marks into a grade.

### Factory methods

A **factory method** is a static method that creates and returns an object. Instead
of `new Ticket("Rahim", "Student", 20)`, the caller writes `Ticket.forStudent("Rahim")`.

Why bother?

- The method name says what kind of object you get (`forStudent`, `forVisitor`).
- The method can check the input and return `null` when it cannot build a valid object
  (exceptions, a better tool for this, come in Chapter 11).
- If the constructor is `private`, the factory methods become the only way to create
  objects, so the class keeps full control over counting and validation.

You have seen factory methods before: `String.valueOf(42)` and `Integer.valueOf("7")`
are static methods that return objects.

### Static nested classes

A class can be declared **inside** another class. If the inner declaration is marked
`static`, it is a **static nested class**. It works like a normal class, but its full
name includes the outer class: `Order.Item`. It does not need an object of the outer
class.

Use a static nested class for a small helper type that only makes sense together with
its outer class, such as an `Item` that belongs to an `Order`, or a `Builder` that
helps create a `Pizza`. Grouping them shows the reader that they belong together.

Java also has non-static nested classes (called **inner classes**), whose objects are
tied to one object of the outer class. You will meet them in the Swing lab. In this
chapter, nested classes are always `static`.

### No `this` in a static context

Inside an instance method, `this` means "the object this method was called on".
A static method is called on the **class**, not on an object, so there is no current
object and `this` does not exist. For the same reason, a static method cannot use an
instance field such as `name` on its own: the compiler would have to ask "the `name`
of **which** object?"

```text
  account.deposit(500)        Bank.interestOn(1000)
          |                             |
          v                             v
  instance method:              static method:
  this = account                no current object
  can use balance               cannot use balance
```

The compiler reports this as an error:

```text
error: non-static variable name cannot be referenced from a static context
```

A "static context" means any code inside a static method, a static initializer block,
or the initializer of a static field.

### Why `main` is static

When you run `java ShuttleTrips`, the JVM must call some method to start your program.
At that moment no object of your class exists yet. If `main` were an instance method,
the JVM would first have to create an object, which means choosing a constructor and
its arguments. Making `main` static avoids the problem: the JVM simply calls
`ShuttleTrips.main(args)` on the class.

The consequence for you: `main` is a static context. To call an instance method from
`main`, first create an object, then call the method on it:

```java
BankAccount acc = new BankAccount("Rahim", 1000);
acc.deposit(500);   // instance method called through a reference
```

### When static is right, and when it is wrong

`static` is a design decision, not a tool for silencing the compiler. Use it when the
member truly belongs to the class:

| Good use of static | Example |
|---|---|
| Data shared by all objects | object counter, shared VAT rate |
| Constants | `static final int PASS_MARK = 40;` |
| Pure helpers (result depends only on parameters) | `Math.max`, `GradeUtil.letter(85)` |
| Factory methods | `Ticket.forStudent("Mitu")` |
| The program's entry point | `main` |

Avoid it in these cases:

- **Per-object data.** A student's name is not shared. Making `name` static means all
  students share one name, so the last assignment wins for everyone.
- **Global mutable state.** A `public static` variable that any code anywhere can
  change is hard to follow: when its value is wrong, every line of the program is a
  suspect. Keep static fields `private`, change them only through methods that
  validate, and keep their number small.
- **"Making everything static to fix the compiler error".** When `main` cannot call an
  instance method, the fix is to create an object, not to make the method and all its
  fields static. That turns your objects back into C-style global data.

When you are unsure, ask the same questions you ask about classes and fields:

```text
  Does the value differ from object to object?        -> instance field
  Is it one fact about the whole class?                -> static field
  Is it fixed forever?                                 -> static final constant
  Does the method use or change one object's fields?   -> instance method
  Does it need only its parameters (and static data)?  -> static method
```

> **Coming from C?** A `static` field plays a role similar to a global variable in C,
> but it lives inside a class and can be `private`. Note that `static` in Java does not
> mean "this function is private to the file" or "this local variable keeps its value",
> as it can in C. Java has no static local variables.

### Enums: a fixed set of named constants

Many things can only be in one of a few states: an order is placed, cooking, ready or
delivered; a traffic light is red, yellow or green. Beginners often store such states
as numbers (`0`, `1`, `2`) or strings (`"READY"`). Both are fragile: nothing stops you
from writing `status = 7` or `"REDY"`.

An **enum** (enumeration) is a special kind of class with a fixed list of named values:

```java
enum OrderStatus {
    PLACED, COOKING, READY, DELIVERED
}
```

`OrderStatus` is now a type, and `OrderStatus.READY` is one of its four values. A
variable of type `OrderStatus` can hold only one of those values (or `null`), so a
typo is a compile error instead of a hidden bug.

Each enum constant is a single object that Java creates once, when the enum is
initialized. You can think of each one as a `public static final` field whose type is
the enum itself. Because there is exactly one object per constant, comparing with `==`
is correct for enums.

Useful things every enum has:

- `OrderStatus.values()` gives all constants in declaration order (used with a for-each
  loop below; arrays and that loop are covered in Chapter 08)
- `status.name()` returns the constant's name as a `String`, and printing an enum value
  prints its name
- `status.ordinal()` returns its position, starting at 0
- a `switch` can test an enum value directly

## 2. Syntax

In a real project each public class lives in its own file. Here we keep each program
in one file so you can compile it with one command.

### Static fields

```java
class Product {
    private static double vatRate = 0.15;   // one copy for all products
    private static int productCount;        // default value 0
    private String name;                    // one copy per product
}
```

- `static` goes before the type. Access modifiers (`private`, `public`) can be
  combined with it; the usual order is `private static`.
- Keep static fields `private` and offer static methods to read or change them, just
  as you do for instance fields (Chapter 05).

### Static methods

```java
class Product {
    private static double vatRate = 0.15;

    static double getVatRate() {
        return vatRate;
    }

    static boolean setVatRate(double newRate) {
        if (newRate < 0 || newRate > 0.5) {
            return false;   // keep the old rate
        }
        vatRate = newRate;
        return true;
    }
}
```

- A static method may use static fields and call other static methods directly.
- It may not use `this` or instance fields without a reference.

### Accessing static members

```java
Product.setVatRate(0.10);            // from another class: ClassName.member
double r = Product.getVatRate();
System.out.println(Math.PI);         // Java's own constant
```

Inside `Product` itself, `vatRate` and `getVatRate()` can be used without the class
name.

### Constants with `static final`

```java
class Exam {
    static final int PASS_MARK = 40;
    static final int MAX_MARK = 100;
    static final String GRADE_SCALE = "A B C D F";
}
```

A `static final` field must be given a value either in its declaration or in a static
initializer block. Once set, any attempt to assign it again is a compile error.

### Static initializer block

```java
class Shuttle {
    static final int TRIPS_PER_DAY;
    private static String timetable = "";

    static {
        int trips = 0;
        for (int hour = 7; hour <= 19; hour += 2) {
            timetable = timetable + hour + ":00 ";
            trips++;
        }
        TRIPS_PER_DAY = trips;   // a static final field may be set here, once
    }
}
```

- `static { ... }` is written directly in the class body, outside every method.
- It has no name, no parameters and no return value. You never call it; Java runs it
  once when the class is initialized.

### Utility class with a private constructor

```java
final class TempUtil {
    private TempUtil() {
        // no objects: every member is static
    }

    static double toFahrenheit(double celsius) {
        return celsius * 9 / 5 + 32;
    }

    static double toCelsius(double fahrenheit) {
        return (fahrenheit - 32) * 5 / 9;
    }
}
```

Usage: `double f = TempUtil.toFahrenheit(36.6);`. Writing `new TempUtil()` outside the
class is a compile error, because the constructor is private.

### Factory method

```java
class Ticket {
    private final String passenger;
    private final int fare;

    private Ticket(String passenger, int fare) {   // only the class may call it
        this.passenger = passenger;
        this.fare = fare;
    }

    static Ticket forStudent(String name) {
        return new Ticket(name, 20);
    }

    static Ticket forVisitor(String name) {
        return new Ticket(name, 50);
    }
}
```

Usage: `Ticket t = Ticket.forStudent("Sadia");`.

### Static nested class

The following complete program declares a `Builder` class inside `Pizza`. The builder
collects choices step by step; `build()` creates the final `Pizza`.

```java
class Pizza {
    private final String size;
    private final boolean extraCheese;
    private final int toppings;

    private Pizza(String size, boolean extraCheese, int toppings) {
        this.size = size;
        this.extraCheese = extraCheese;
        this.toppings = toppings;
    }

    String describe() {
        String cheese = extraCheese ? ", extra cheese" : "";
        return size + " pizza, " + toppings + " topping(s)" + cheese;
    }

    static class Builder {
        private String size = "Medium";
        private boolean extraCheese = false;
        private int toppings = 0;

        Builder size(String size) {
            this.size = size;
            return this;   // returning the builder lets calls be chained
        }

        Builder extraCheese() {
            extraCheese = true;
            return this;
        }

        Builder addTopping() {
            toppings++;
            return this;
        }

        Pizza build() {
            return new Pizza(size, extraCheese, toppings);
        }
    }
}

public class PizzaShop {
    public static void main(String[] args) {
        Pizza plain = new Pizza.Builder().build();
        Pizza special = new Pizza.Builder()
                .size("Large")
                .addTopping()
                .addTopping()
                .extraCheese()
                .build();
        System.out.println(plain.describe());
        System.out.println(special.describe());
    }
}
```

**Output:**

```text
Medium pizza, 0 topping(s)
Large pizza, 2 topping(s), extra cheese
```

- `new Pizza.Builder()` creates a builder without any `Pizza` object, because the
  nested class is `static`.
- The nested class can call `Pizza`'s private constructor: members of nested classes
  can access the private members of the outer class and the other way round.
- Inside `Builder`, `this` refers to the builder object. The builder methods are
  instance methods of `Builder`; only the class declaration itself is static.

### Enum declaration, `switch` and `values()`

```java
enum Light {
    RED, YELLOW, GREEN
}
```

```java
Light now = Light.RED;
if (now == Light.RED) {
    System.out.println("Stop");
}
```

```java
Light next = switch (now) {   // switch expression on an enum
    case RED -> Light.GREEN;
    case GREEN -> Light.YELLOW;
    case YELLOW -> Light.RED;
};
```

- Inside `case` labels, you write the constant name alone (`RED`, not `Light.RED`).
- A switch expression on an enum must cover every constant (or have a `default`).

```java
for (Light light : Light.values()) {
    System.out.println(light.ordinal() + " " + light.name());
}
```

This prints `0 RED`, `1 YELLOW`, `2 GREEN`, one per line.

An enum can also have fields, a constructor and methods. A short example:

```java
enum Coin {
    ONE(1), TWO(2), FIVE(5);

    private final int taka;

    Coin(int taka) {          // enum constructors are always private
        this.taka = taka;
    }

    int getTaka() {
        return taka;
    }
}
```

`Coin.FIVE.getTaka()` returns `5`. You cannot create new constants with `new Coin(10)`;
the list in the declaration is fixed.

## 3. Worked Examples

### Example 1: Shuttle Trips (Instance vs Static Counter)

**Problem:** The campus has several shuttle buses. Each bus must remember how many
trips it made today, and the transport office also wants the total number of trips of
all buses together.

Design:

- `trips` differs from bus to bus, so it is an **instance** field.
- `totalTrips` is one number for all buses, so it is a **static** field.
- `completeTrip()` changes both: the bus's own count and the shared total.

```java
class Shuttle {
    private static int totalTrips = 0;   // shared by all buses

    private final String route;          // own data of each bus
    private int trips;

    Shuttle(String route) {
        this.route = route;
    }

    void completeTrip() {
        trips++;        // this bus only
        totalTrips++;   // all buses together
    }

    void report() {
        System.out.println(route + ": " + trips + " trip(s)");
    }

    static int getTotalTrips() {
        return totalTrips;
    }
}

public class ShuttleTrips {
    public static void main(String[] args) {
        System.out.println("Total before any bus exists: " + Shuttle.getTotalTrips());

        Shuttle badda = new Shuttle("Campus - Badda");
        Shuttle mirpur = new Shuttle("Campus - Mirpur");

        badda.completeTrip();
        badda.completeTrip();
        mirpur.completeTrip();
        badda.completeTrip();

        badda.report();
        mirpur.report();
        System.out.println("Total trips: " + Shuttle.getTotalTrips());
    }
}
```

**Output:**

```text
Total before any bus exists: 0
Campus - Badda: 3 trip(s)
Campus - Mirpur: 1 trip(s)
Total trips: 4
```

**Why it works:** Each `Shuttle` object has its own `trips`, so Badda's three trips
do not affect Mirpur's count. There is only one `totalTrips`, and every call of
`completeTrip()` on any bus increases that same variable. The first line shows that a
static field exists even before any object is created: `getTotalTrips()` is called on
the class, and the value is the default starting value `0`.

### Example 2: Auto-Generated Student IDs

**Problem:** The registration office enters new students one by one. Every student
must get a unique ID in the form `STU-001`, `STU-002`, ... automatically. Read the
number of students and their full names, print each new ID, and finally print how many
students were created.

Design:

- `nextNumber` is a private static field: the number the next student will get.
- `id` is a `private final` instance field: set once in the constructor, never
  changed, and there is no setter.
- `getCreatedCount()` is static because the answer is about the class, not about one
  student.

```java
import java.util.Scanner;

class Student {
    private static int nextNumber = 1;

    private final String id;
    private final String name;

    Student(String name) {
        this.name = name;
        this.id = String.format("STU-%03d", nextNumber);
        nextNumber++;
    }

    String getId() {
        return id;
    }

    String getName() {
        return name;
    }

    static int getCreatedCount() {
        return nextNumber - 1;
    }
}

public class StudentIds {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        in.nextLine(); // consume the rest of the first line
        for (int i = 0; i < n; i++) {
            Student s = new Student(in.nextLine());
            System.out.println(s.getId() + "  " + s.getName());
        }
        System.out.println("Students created: " + Student.getCreatedCount());
    }
}
```

**Input:**

```text
4
Nusrat Jahan
Tanvir Ahmed
Ayesha Siddiqua
Rafi Islam
```

**Output:**

```text
STU-001  Nusrat Jahan
STU-002  Tanvir Ahmed
STU-003  Ayesha Siddiqua
STU-004  Rafi Islam
Students created: 4
```

**Why it works:** The constructor runs once for every `new Student(...)`. It copies
the shared `nextNumber` into the object's own `id` and then increases `nextNumber`, so
the next object gets the next number. `%03d` pads the number with zeros to three
digits. The loop variable `s` refers to a new object in every round, yet the count is
not lost, because it is stored in the class, not in any object.

### Example 3: A VAT Rate Shared by All Products

**Problem:** A campus shop sells products with a base price. The shop adds VAT to every
price, and the VAT rate (15% at first, a hypothetical value) is the same for all
products. When the rate changes, every product's final price must change at once. The
rate must stay between 0 and 50%.

Design:

- The rate belongs to the whole class, so `vatRate` is a `private static` field.
- `setVatRate` is a static method that validates the new value and keeps the old one
  if it is invalid.
- `priceWithVat()` is an instance method: it uses the object's own `basePrice`
  together with the shared rate.

```java
class Product {
    static final double MAX_VAT_RATE = 0.5;
    private static double vatRate = 0.15;

    private final String name;
    private final double basePrice;

    Product(String name, double basePrice) {
        this.name = name;
        this.basePrice = basePrice;
    }

    static double getVatRate() {
        return vatRate;
    }

    static boolean setVatRate(double newRate) {
        if (newRate < 0 || newRate > MAX_VAT_RATE) {
            return false;
        }
        vatRate = newRate;
        return true;
    }

    double priceWithVat() {
        return basePrice * (1 + vatRate);
    }

    void print() {
        System.out.printf("  %-12s %8.2f Tk%n", name, priceWithVat());
    }
}

public class ShopVat {
    static void printPrices(Product a, Product b, Product c) {
        System.out.printf("VAT rate: %.1f%%%n", Product.getVatRate() * 100);
        a.print();
        b.print();
        c.print();
    }

    public static void main(String[] args) {
        Product pen = new Product("Pen", 20);
        Product notebook = new Product("Notebook", 120);
        Product bag = new Product("School bag", 1500);

        printPrices(pen, notebook, bag);

        if (Product.setVatRate(0.075)) {
            System.out.println("Rate changed.");
        }
        printPrices(pen, notebook, bag);

        if (!Product.setVatRate(0.8)) {
            System.out.println("Rejected: 80% is above the limit.");
        }
        printPrices(pen, notebook, bag);
    }
}
```

**Output:**

```text
VAT rate: 15.0%
  Pen             23.00 Tk
  Notebook       138.00 Tk
  School bag    1725.00 Tk
Rate changed.
VAT rate: 7.5%
  Pen             21.50 Tk
  Notebook       129.00 Tk
  School bag    1612.50 Tk
Rejected: 80% is above the limit.
VAT rate: 7.5%
  Pen             21.50 Tk
  Notebook       129.00 Tk
  School bag    1612.50 Tk
```

**Why it works:** None of the three product objects stores a rate. Each call of
`priceWithVat()` reads the single static `vatRate`, so one call of
`Product.setVatRate(0.075)` changes the price of every product. The invalid rate is
rejected by the static setter, so the shared value stays correct. In `printf`, `%%`
prints a literal percent sign. Notice that `main` calls `printPrices` without an
object: it is a static helper method in the main class, as in Chapter 03.

### Example 4: A Grade Utility Class

**Problem:** A teacher wants to convert exam marks (0 to 100) into letter grades and
grade points using a fixed, hypothetical scale. Read the number of students, then a
name and a mark on each line. Print the grade and grade point of each valid mark, a
message for an invalid mark, and the average grade point of the valid entries.

| Marks | Grade | Point |
|---|---|---|
| 80 to 100 | A | 4.00 |
| 65 to 79 | B | 3.00 |
| 50 to 64 | C | 2.00 |
| 40 to 49 | D | 1.00 |
| below 40 | F | 0.00 |

Design: converting a mark needs nothing except the mark itself, so the conversions
are static methods in a utility class `GradeUtil` with a private constructor.

```java
import java.util.Scanner;

final class GradeUtil {
    static final int MIN_MARK = 0;
    static final int MAX_MARK = 100;

    private GradeUtil() {
        // utility class: no objects
    }

    static boolean isValid(int marks) {
        return marks >= MIN_MARK && marks <= MAX_MARK;
    }

    static String letter(int marks) {
        if (marks >= 80) {
            return "A";
        } else if (marks >= 65) {
            return "B";
        } else if (marks >= 50) {
            return "C";
        } else if (marks >= 40) {
            return "D";
        }
        return "F";
    }

    static double point(int marks) {
        String grade = letter(marks);   // static method calling a static method
        switch (grade) {
            case "A":
                return 4.0;
            case "B":
                return 3.0;
            case "C":
                return 2.0;
            case "D":
                return 1.0;
            default:
                return 0.0;
        }
    }
}

public class GradeReport {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        double totalPoints = 0;
        int validCount = 0;
        for (int i = 0; i < n; i++) {
            String name = in.next();
            int marks = in.nextInt();
            if (!GradeUtil.isValid(marks)) {
                System.out.println(name + ": invalid mark " + marks);
                continue;
            }
            double gp = GradeUtil.point(marks);
            System.out.printf("%-8s %3d  %s  %.2f%n", name, marks,
                    GradeUtil.letter(marks), gp);
            totalPoints += gp;
            validCount++;
        }
        if (validCount > 0) {
            System.out.printf("Average grade point: %.2f%n", totalPoints / validCount);
        }
    }
}
```

**Input:**

```text
5
Rahim 85
Karim 47
Mitu 105
Sadia 66
Imran 39
```

**Output:**

```text
Rahim     85  A  4.00
Karim     47  D  1.00
Mitu: invalid mark 105
Sadia     66  B  3.00
Imran     39  F  0.00
Average grade point: 2.00
```

**Why it works:** `GradeUtil` has no fields that change, so there is nothing that an
object could hold. Every method's result depends only on its parameter, which is
exactly when static methods fit. The private constructor makes `new GradeUtil()`
impossible outside the class, and the class name in every call
(`GradeUtil.letter(marks)`) tells the reader where the logic lives. Each `return`
inside the classic `switch` leaves the method, so no case falls through.

### Example 5: When Static Initialization Runs

**Problem:** Show the exact moment when static initializer blocks run, compared with
constructors. A `Library` class prepares its catalog size with a loop in a static
block. The main class also has a static block.

```java
class Library {
    private static int catalogSize;

    static {
        System.out.println("[Library static block] preparing the catalog");
        int total = 0;
        for (int shelf = 1; shelf <= 4; shelf++) {
            total += shelf * 25;   // shelf 1 holds 25 books, shelf 2 holds 50, ...
        }
        catalogSize = total;
    }

    private final String branch;

    Library(String branch) {
        this.branch = branch;
        System.out.println("[Library constructor] " + branch + " branch opened");
    }

    String getBranch() {
        return branch;
    }

    static int getCatalogSize() {
        return catalogSize;
    }
}

public class InitOrder {
    static {
        System.out.println("[InitOrder static block] runs before main");
    }

    public static void main(String[] args) {
        System.out.println("main starts");
        System.out.println("Library has not been used yet");
        Library central = new Library("Central");
        Library hostel = new Library("Hostel");
        System.out.println("Branches: " + central.getBranch() + ", "
                + hostel.getBranch());
        System.out.println("Catalog size: " + Library.getCatalogSize());
    }
}
```

**Output:**

```text
[InitOrder static block] runs before main
main starts
Library has not been used yet
[Library static block] preparing the catalog
[Library constructor] Central branch opened
[Library constructor] Hostel branch opened
Branches: Central, Hostel
Catalog size: 250
```

**Why it works:** The JVM must initialize `InitOrder` before it can call its static
`main`, so that static block prints first. `Library` is not initialized when the
program starts; Java waits until its first real use, the first `new Library(...)`.
Then its static block runs once (25 + 50 + 75 + 100 = 250), and only after that the
constructor runs. Creating the second branch runs the constructor again, but not the
static block.

### Example 6: Shuttle Tickets with Factory Methods

**Problem:** The campus shuttle sells three kinds of tickets with fixed, hypothetical
fares: student 20 Tk, staff 30 Tk, visitor 50 Tk. Every ticket gets a serial number.
Read the number of sales, then on each line a type code (`S`, `T` for staff, `V`) and
the passenger's name. Print each ticket, report unknown codes, and finally print the
number of tickets and the total fare collected.

Design:

- The fares are `static final` constants.
- The constructor is `private`. Tickets are created only through the factory methods
  `forStudent`, `forStaff`, `forVisitor`, and `fromCode`, which returns `null` for an
  unknown code.
- `issued` and `collected` are static: they describe all tickets together.

```java
import java.util.Scanner;

class Ticket {
    static final int STUDENT_FARE = 20;
    static final int STAFF_FARE = 30;
    static final int VISITOR_FARE = 50;

    private static int issued = 0;
    private static int collected = 0;

    private final int serial;
    private final String passenger;
    private final String type;
    private final int fare;

    private Ticket(String passenger, String type, int fare) {
        issued++;
        collected += fare;
        this.serial = issued;
        this.passenger = passenger;
        this.type = type;
        this.fare = fare;
    }

    static Ticket forStudent(String name) {
        return new Ticket(name, "Student", STUDENT_FARE);
    }

    static Ticket forStaff(String name) {
        return new Ticket(name, "Staff", STAFF_FARE);
    }

    static Ticket forVisitor(String name) {
        return new Ticket(name, "Visitor", VISITOR_FARE);
    }

    static Ticket fromCode(String code, String name) {
        if (code.equals("S")) {
            return forStudent(name);
        } else if (code.equals("T")) {
            return forStaff(name);
        } else if (code.equals("V")) {
            return forVisitor(name);
        }
        return null;   // unknown code: no ticket is created
    }

    String describe() {
        return String.format("#%d %-8s %-7s %2d Tk", serial, passenger, type, fare);
    }

    static int getIssued() {
        return issued;
    }

    static int getCollected() {
        return collected;
    }
}

public class ShuttleTickets {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        for (int i = 0; i < n; i++) {
            String code = in.next();
            String name = in.next();
            Ticket t = Ticket.fromCode(code, name);
            if (t == null) {
                System.out.println("Unknown ticket type " + code + " for " + name);
            } else {
                System.out.println(t.describe());
            }
        }
        System.out.println("Tickets issued: " + Ticket.getIssued());
        System.out.println("Fare collected: " + Ticket.getCollected() + " Tk");
    }
}
```

**Input:**

```text
5
S Rahim
V Farhana
T Imran
X Sadia
S Mitu
```

**Output:**

```text
#1 Rahim    Student 20 Tk
#2 Farhana  Visitor 50 Tk
#3 Imran    Staff   30 Tk
Unknown ticket type X for Sadia
#4 Mitu     Student 20 Tk
Tickets issued: 4
Fare collected: 120 Tk
```

**Why it works:** Because the constructor is private, `main` cannot write
`new Ticket(...)`; it must go through a factory method. That guarantees every ticket
has a correct fare and is counted. For the unknown code `X`, `fromCode` returns `null`
before any constructor runs, so the serial numbers stay without gaps (Mitu gets `#4`).
The factory methods are static because they are called before any `Ticket` exists.

### Example 7: Canteen Orders with an Enum

**Problem:** The canteen tracks each order through the states placed, cooking, ready
and delivered; an order can also be cancelled, but only while it is placed or cooking.
Order numbers start at 101. Read two orders: for each, the item name on one line and a
line of commands, where `A` advances the order to the next state and `C` cancels it.
Print what happens.

```java
import java.util.Scanner;

enum OrderStatus {
    PLACED, COOKING, READY, DELIVERED, CANCELLED
}

class CanteenOrder {
    private static int nextNumber = 101;

    private final int number;
    private final String item;
    private OrderStatus status;

    CanteenOrder(String item) {
        this.number = nextNumber;
        nextNumber++;
        this.item = item;
        this.status = OrderStatus.PLACED;
    }

    boolean advance() {
        OrderStatus next = switch (status) {
            case PLACED -> OrderStatus.COOKING;
            case COOKING -> OrderStatus.READY;
            case READY -> OrderStatus.DELIVERED;
            case DELIVERED, CANCELLED -> status;   // final states: no next state
        };
        if (next == status) {
            return false;
        }
        status = next;
        return true;
    }

    boolean cancel() {
        if (status == OrderStatus.PLACED || status == OrderStatus.COOKING) {
            status = OrderStatus.CANCELLED;
            return true;
        }
        return false;
    }

    String describe() {
        return "Order " + number + " (" + item + "): " + status;
    }
}

public class CanteenOrders {
    public static void main(String[] args) {
        System.out.print("States:");
        for (OrderStatus s : OrderStatus.values()) {
            System.out.print(" " + s.ordinal() + "=" + s);
        }
        System.out.println();

        Scanner in = new Scanner(System.in);
        for (int k = 0; k < 2; k++) {
            CanteenOrder order = new CanteenOrder(in.nextLine());
            String commands = in.nextLine();
            System.out.println(order.describe());
            for (int i = 0; i < commands.length(); i++) {
                char c = commands.charAt(i);
                boolean ok;
                if (c == 'A') {
                    ok = order.advance();
                } else {
                    ok = order.cancel();
                }
                String result = ok ? "" : " (refused)";
                System.out.println("  " + c + " -> " + order.describe() + result);
            }
        }
    }
}
```

**Input:**

```text
Chicken Khichuri
AAAA
Singara
ACA
```

**Output:**

```text
States: 0=PLACED 1=COOKING 2=READY 3=DELIVERED 4=CANCELLED
Order 101 (Chicken Khichuri): PLACED
  A -> Order 101 (Chicken Khichuri): COOKING
  A -> Order 101 (Chicken Khichuri): READY
  A -> Order 101 (Chicken Khichuri): DELIVERED
  A -> Order 101 (Chicken Khichuri): DELIVERED (refused)
Order 102 (Singara): PLACED
  A -> Order 102 (Singara): COOKING
  C -> Order 102 (Singara): CANCELLED
  A -> Order 102 (Singara): CANCELLED (refused)
```

**Why it works:** The variable `status` can only hold one of the five `OrderStatus`
values, so an impossible state such as `"COOKD"` cannot exist. The switch expression
lists every constant, so the compiler checks that no state is forgotten; adding a new
constant later without updating the switch becomes a compile error. Comparing with
`==` is correct because each enum constant is a single object. The order numbers
come from the static `nextNumber`, exactly like the IDs in Example 2.

## Common Mistakes

### Calling an instance method directly from `main`

```java nocompile
public class Greeter {
    void greet() {
        System.out.println("Hello");
    }

    public static void main(String[] args) {
        greet();   // error: non-static method greet() cannot be referenced
                   //        from a static context
    }
}
```

`main` is static, so there is no current object to call `greet()` on. Create one:

```java
public class Greeter {
    void greet() {
        System.out.println("Hello");
    }

    public static void main(String[] args) {
        Greeter g = new Greeter();
        g.greet();
    }
}
```

**Output:**

```text
Hello
```

(If `greet()` really uses no object data, making it `static` is also fine. The point
is to decide on purpose.)

### Using an instance field inside a static method

```java nocompile
class Account {
    private double balance;

    static void printBalance() {
        System.out.println(balance);   // error: non-static variable balance
                                       //        cannot be referenced from a
                                       //        static context
    }
}
```

Which account's balance? A static method has no `this`. Either make the method an
instance method, or pass the object as a parameter: `static void print(Account a)`.

### Making everything static to silence the compiler

The compiler error above tempts beginners to add `static` everywhere. It compiles, but
it silently breaks the program:

```java
class Student {
    static String name;   // WRONG: one name shared by all students

    Student(String name) {
        Student.name = name;
    }

    String getName() {
        return name;   // an instance method may read a static field
    }
}

public class StaticBug {
    public static void main(String[] args) {
        Student first = new Student("Ayesha");
        Student second = new Student("Fahim");
        System.out.println("First student's name: " + first.getName());
        System.out.println("Second student's name: " + second.getName());
    }
}
```

**Output:**

```text
First student's name: Fahim
Second student's name: Fahim
```

There are two objects, but only one `name`, so the second constructor overwrote the
first student's name. Per-object data must be instance fields.

### Other mistakes to watch for

- **Using `this` in a static method.** The compiler says
  `non-static variable this cannot be referenced from a static context`.
- **Accessing static members through an object** (`badda.getTotalTrips()`). It
  compiles (an IDE or `javac -Xlint` warns) but suggests that the value belongs to `badda`. Write
  `Shuttle.getTotalTrips()`.
- **Increasing a counter outside the constructor.** If `count++` sits in a method that
  may or may not be called, the counter no longer matches the number of objects. Put
  it in the constructor (or in the one constructor that all others chain to with
  `this(...)`).
- **Thinking a counter tracks living objects.** A static counter counts how many
  objects were *created*. When an object becomes unreachable and is garbage-collected,
  the counter does not go down.
- **A public, changeable static field.** `public static double vatRate;` lets any code
  set it to `-5`. Make it `private` and change it through a validating static method.
- **Comparing an enum with a string.** `status.equals("READY")` is always `false`,
  because a `String` is never an `OrderStatus`. Compare with
  `status == OrderStatus.READY`.

## Summary

- An **instance** field has one copy per object; a **static** field has exactly one
  copy, stored with the class and shared by all objects.
- An instance method runs on an object and can use `this`; a static method runs on the
  class, has no current object, and reaches instance members only through a reference.
- Call static members through the class name: `Math.sqrt(x)`, `Product.setVatRate(r)`.
- A static counter increased in the constructor gives object counts and unique
  auto-generated IDs; store the ID in a `private final` instance field.
- `static final` declares a constant (`UPPER_SNAKE_CASE`); a `static { }` block runs
  once, when the class is first used.
- Utility classes hold only static methods and have a private constructor; factory
  methods are static methods that create objects and may validate the input.
- A static nested class (such as `Pizza.Builder`) is a helper class grouped inside its
  outer class; it needs no outer object.
- `main` is static because the JVM must call it before any object exists; from `main`,
  create objects to call instance methods.
- Use static for shared data, constants, pure helpers and factory methods; never for
  per-object data, and never just to make a compiler error go away.
- An `enum` defines a fixed set of named constants; compare them with `==`, list them
  with `values()`, and test them with `switch`.
