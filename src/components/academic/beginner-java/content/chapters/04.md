# Chapter 04: Classes and Objects

Until now every program lived inside one class that only held `main` and a few `static`
methods. The data was a loose collection of variables. In this chapter you create your
own types: a `Student`, a `BankAccount`, a `Book`. Each one keeps its data and the code
that works on that data together. This is where object-oriented programming really
starts.

**In this chapter you will learn:**

- Why programs need classes, and what a class really is: a new type
- How `new` creates an object on the heap and gives you a reference to it
- Fields (state) and instance methods (behaviour), and why each object has its own fields
- Default field values (`0`, `false`, `null`) and how they differ from local variables
- How to reach members with `.`, and how `this` refers to the current object
- How to design a class from a plain-English description ("should this be a class?")
- How objects work together by calling each other's methods
- How to write a friendly `toString()` method, and a first look at constructors

## 1. Concept Explanation

### Why we need classes

Suppose you store two students with what you know from Chapters 01 to 03:

```java
String name1 = "Rahim";
int id1 = 1001;
double cgpa1 = 3.45;

String name2 = "Nusrat";
int id2 = 1002;
double cgpa2 = 3.90;
```

This works for two students, but it does not grow well:

- Values that belong together are separate variables. Nothing says that `cgpa1` belongs
  to `name1`.
- A method that prints a student needs three parameters. A method that changes a CGPA
  cannot return two values.
- It is easy to mix things up: `printStudent(name1, id2, cgpa1)` compiles fine.
- The rules (for example, "a CGPA is between 0.00 and 4.00") live far away from the data.

A **class** fixes this. It lets you describe *one student* as a single unit that holds
its name, ID and CGPA, together with the methods that use them. This is the main idea of
OOP from Chapter 00: keep the data and the code that changes it in the same place.

### A class defines a new type

You may have heard: "a class is a blueprint, an object is a house built from it." That
analogy is a good start. One blueprint, many houses; every house has its own rooms and
its own paint colour.

Now the real programming model. When you write `class Student { ... }`, you add a **new
type** to Java, just like `String` and `Scanner` are types. You can then:

- declare variables of type `Student`
- create values (objects) of type `Student`
- pass a `Student` to a method and return one from a method

| Type | Kind | Who wrote it | Example value |
|---|---|---|---|
| `int` | primitive | built into Java | `42` |
| `String` | class | Java library | `"Rahim"` |
| `Scanner` | class | Java library | `new Scanner(System.in)` |
| `Student` | class | you | `new Student()` |

A class describes two things about its objects:

- **Fields**: the data each object stores (its **state**). Fields are also called
  **instance variables**.
- **Instance methods**: what each object can do (its **behaviour**).

### Creating an object: `new` and references

```java
Student s = new Student();
```

This one line does three separate things:

1. `Student s` declares a **reference variable**. It can refer to a `Student` object, but
   it is not the object itself.
2. `new Student()` asks the Java Virtual Machine (JVM) to create a new object in the
   **heap**, the memory area where all objects live. Every field gets a default value.
3. `new` gives back a **reference** to the new object, and `=` stores that reference in
   `s`.

```text
   STACK (local variables)        HEAP (objects)
  +--------------+           +------------------------+
  | s      o-----+---------->| Student object         |
  +--------------+           |   name = null          |
                             |   id   = 0             |
                             |   cgpa = 0.0           |
                             +------------------------+
```

A **reference** is the value that lets your program reach an object. You saw this
picture in Chapter 03 with `StringBuilder`; now you create objects of your own classes.
Java uses references instead of exposing raw memory pointers like C and C++. You cannot
see an object's address, do arithmetic on a reference, or free an object yourself.
Chapter 08 explores references in depth.

> **Coming from C?** A class with only fields looks like a `struct`. The differences
> matter: a Java object is always created on the heap with `new`; your variable holds a
> reference to it, not the object itself; there is no `malloc`/`free`, because the
> garbage collector reclaims objects that nothing refers to any more (Chapter 06); and a
> class also contains methods that work on its fields.

### Each object has its own fields

Every call to `new` creates a separate object with its own copy of every field.

```java
Student a = new Student();
Student b = new Student();
a.name = "Rahim";
b.name = "Nusrat";
a.cgpa = 3.45;
```

```text
  STACK                  HEAP
 +-------+        +------------------+
 | a  o--+------->| name = "Rahim"   |
 +-------+        | id   = 0         |
                  | cgpa = 3.45      |
                  +------------------+
 +-------+        +------------------+
 | b  o--+------->| name = "Nusrat"  |
 +-------+        | id   = 0         |
                  | cgpa = 0.0       |
                  +------------------+
```

Changing `a.cgpa` does not touch `b.cgpa`. Two objects of the same class share the same
*kind* of data, but not the data itself.

### Methods are shared and act on the object you call them on

The code of a method is stored once, with the class. It is not copied into every object.
When you call `a.printInfo()`, the method runs with `a`'s object as the **current
object**. When you call `b.printInfo()`, the same code runs with `b`'s object.

```text
          class Student (method code, stored once)
         +---------------------------------------+
         | void printInfo() {                    |
         |     System.out.println(name + ...);   |
         | }                                     |
         +---------------------------------------+
               ^                         ^
        a.printInfo()              b.printInfo()
        current object:            current object:
        Rahim's object             Nusrat's object
```

Inside `printInfo`, the word `name` means "the `name` field of the current object". So
the same method prints `Rahim` for one call and `Nusrat` for the other. In Chapter 00
language: calling a method is **sending a message** to an object, and each object
answers using its own state.

### State and behaviour

The **state** of an object is the set of values in its fields at one moment. Its
**behaviour** is what its methods do. Behaviour usually reads the state, and often
changes it: `withdraw` depends on the balance and then lowers it.

| Class | State (fields) | Behaviour (methods) |
|---|---|---|
| `Student` | name, id, cgpa | `printInfo()`, `isOnProbation()` |
| `BankAccount` | owner, balance | `deposit(amount)`, `withdraw(amount)` |
| `Book` | title, author, copies | `borrow()`, `giveBack()` |
| `Course` | code, credits, seats | `enroll(student)`, `isFull()` |
| `Employee` | name, salary | `giveRaise(percent)`, `monthlyPay()` |
| `Rectangle` | width, height | `area()`, `perimeter()`, `isSquare()` |

### Default field values

When `new` creates an object, every field starts with a **default value** before any of
your code runs:

| Field type | Default value |
|---|---|
| `byte`, `short`, `int`, `long` | `0` |
| `float`, `double` | `0.0` |
| `char` | `'\u0000'` (the character with code 0) |
| `boolean` | `false` |
| any reference type (`String`, `Student`, ...) | `null` |

`null` means "refers to no object". A `String` field that you never set is `null`, not
the empty string `""`.

This is different from **local variables** (variables declared inside a method). A local
variable gets no default value: the compiler refuses to let you read it before you
assign it.

| | Field | Local variable |
|---|---|---|
| Declared | inside the class, outside methods | inside a method |
| Lives | as long as its object | until the method returns |
| Default value | yes (`0`, `false`, `null`) | no, must be assigned before use |

> **Coming from C?** In C an uninitialized variable holds a garbage value. Java never
> does that: fields get defaults, and local variables must be assigned first.

### Two references, one object

Assigning one reference variable to another copies the **reference**, not the object.

```java
Student a = new Student();
a.name = "Rahim";
Student b = a;          // b now refers to the SAME object
b.name = "Karim";
System.out.println(a.name);   // prints Karim
```

```text
 +-------+
 | a  o--+------+       +------------------+
 +-------+      +------>| name = "Karim"   |
 +-------+      |       | ...              |
 | b  o--+------+       +------------------+
 +-------+
```

There is only one object, so a change through `b` is visible through `a`. To get a
second student you must call `new` again. A reference variable can also hold `null`.
Using `.` on a `null` reference stops the program with a `NullPointerException`.
Chapter 08 covers aliasing and `null` in detail.

### The current object: `this`

Inside an instance method, the keyword `this` is a reference to the current object: the
object the method was called on. In `a.printInfo()`, `this` refers to the same object as
`a`.

You need `this` in two common situations.

**1. A parameter has the same name as a field.** The parameter *shadows* (hides) the
field, so a plain `name` means the parameter. `this.name` means the field.

```java
void rename(String name) {
    this.name = name;   // field of the current object = parameter
}
```

**2. You want to talk about the current object as a whole**, for example to compare it
with another object of the same class:

```java
boolean hasHigherCgpaThan(Student other) {
    return this.cgpa > other.cgpa;
}
```

When there is no name clash, `cgpa` and `this.cgpa` mean the same thing. Many
programmers still write `this.` to make "this is a field" obvious.

### Should this be a class?

Designing classes is a skill you will use in every chapter from now on. A simple method
to start with:

1. Write a short description of the problem in plain English.
2. Underline the **nouns**. Important nouns become candidate **classes**; nouns that
   just describe something become **fields**.
3. Underline the **verbs**. They become **methods** of the class that owns the data the
   verb changes.

Example description:

> The campus library lends books to students. Each book has a title, an author and a
> number of copies. A student may borrow a book if a copy is available and return it
> later. The librarian wants to print a short line about each book.

| Word | Kind | Decision |
|---|---|---|
| book | noun with its own data and rules | class `Book` |
| title, author, number of copies | nouns describing a book | fields of `Book` |
| student | noun with its own data | class `Student` (if we need its data) |
| borrow, return | verbs that change a book's copies | methods `borrow()`, `giveBack()` |
| print a line | verb | method `toString()` |
| library | noun holding many books | a class later, once you have lists (Chapter 08) |

Ask these questions for each candidate:

- **Does it hold several pieces of data that belong together?** Then it is probably a
  class.
- **Does it have rules or actions of its own?** A class.
- **Will the program have several of them?** A class (one class, many objects).
- **Is it a single value that describes something else** (a name, a price, a date of
  birth)? A field.
- **Is it an action?** A method, not a class. `class Withdraw` is a warning sign;
  `withdraw()` inside `BankAccount` is right.

Put each method in the class whose fields it uses. `withdraw` changes the balance, so it
belongs in `BankAccount`, not in `main`.

### Objects working together

Real programs have several classes whose objects send messages to each other. A method
can take another object as a parameter:

```java
boolean transferTo(BankAccount other, int amount) {
    if (!this.withdraw(amount)) {
        return false;
    }
    other.deposit(amount);
    return true;
}
```

`rahim.transferTo(karim, 500)` asks Rahim's account to move money; Rahim's account in
turn asks Karim's account to accept a deposit.

```text
   main                 rahim's account          karim's account
    |  transferTo(karim,500)   |                        |
    |------------------------->|                        |
    |                          | withdraw(500) on this  |
    |                          |---+                    |
    |                          |<--+                    |
    |                          |  deposit(500)          |
    |                          |----------------------->|
    |          true            |                        |
    |<-------------------------|                        |
```

Remember from Chapter 03: Java is always pass-by-value. Here the value passed is a copy
of the *reference* to Karim's account. Both references lead to the same object, so the
method can change that object. It cannot make the caller's variable refer to a different
object.

### Printing an object: `toString()`

If you print an object of a class that has no `toString()` method, Java prints the class
name, an `@` sign and a number in hexadecimal (derived from the object's hash code), for
example:

```text
Student@1b6d3586
```

The number differs from run to run, and it means nothing to a user. You can give your
class a friendly text form by writing a method with exactly this header:

```java
public String toString() {
    return name + " (" + id + "), CGPA " + cgpa;
}
```

Java calls it for you in two places: `System.out.println(s)` and string concatenation
such as `"Top student: " + s`. You can also call `s.toString()` yourself.

`toString()` *returns* the text; it does not print it. The caller decides where the text
goes. The word `public` is required here: every class already has a basic `toString()`
from Java's `Object` class, and you are replacing it. Replacing an inherited method is
called **overriding**, explained in Chapter 09.

### A first look at constructors

Creating an object and then setting its fields one by one is slow to write and easy to
get wrong: forget one line and a field silently stays `null` or `0`. A **constructor**
sets up a new object at the moment it is created.

```java
class Student {
    String name;
    int id;

    Student(String name, int id) {   // a constructor: no return type
        this.name = name;
        this.id = id;
    }
}
```

```java
Student s = new Student("Rahim", 1001);   // created and set up in one step
```

A constructor has the same name as the class and no return type (not even `void`). The
arguments after `new Student` are passed to it. One warning: once you write a
constructor with parameters, `new Student()` with no arguments no longer compiles,
unless you also write a constructor without parameters. Chapter 06 covers constructors
fully; in this chapter most examples set fields directly so you can see every step.

## 2. Syntax

### Declaring a class with fields and methods

```java
class Student {
    // fields (state): one copy per object
    String name;
    int id;
    double cgpa;

    // instance methods (behaviour): no "static"
    void printInfo() {
        System.out.println(id + " " + name + " " + cgpa);
    }

    boolean isOnProbation() {
        return cgpa < 2.0;
    }
}
```

- `class Student` starts the class. Class names use `PascalCase`.
- Fields are declared inside the class but outside every method.
- Instance methods have **no** `static` keyword. They can use the fields directly.
- The fields here have no access modifier, so code in the same file can read and change
  them. That is fine for learning in this chapter. In Chapter 05 you will make fields
  `private` and protect them.

The other classes in a file are not `public`; only the class with `main` is. In a real
project each public class lives in its own file; here we keep each program in one file
so you can compile it with one command.

### Fields with a starting value

```java
class Book {
    String title;          // default: null
    int copies = 1;        // every new Book starts with 1 copy
    boolean reference;     // default: false
}
```

A field may have an initializer (`= 1`). It runs for every new object.

### Instance methods

```java
class Rectangle {
    double width;
    double height;

    double area() {                    // returns a value computed from fields
        return width * height;
    }

    void scale(double factor) {        // changes the state of the current object
        width = width * factor;
        height = height * factor;
    }
}
```

The form is the same as the `static` methods of Chapter 03 (return type, name,
parameters, body) without the word `static`.

### Creating objects with `new`

```java
Rectangle r = new Rectangle();   // declare and create in one line

Rectangle q;                     // declare only: no object yet
q = new Rectangle();             // create later
```

### Accessing members with `.`

```java
r.width = 4.0;                   // write a field
r.height = 2.5;
double a = r.area();             // call a method that returns a value
r.scale(2);                      // call a method that changes the object
System.out.println(r.width);     // read a field
```

| Expression | Meaning |
|---|---|
| `r.width` | the `width` field of the object `r` refers to |
| `r.area()` | send the message `area()` to that object |
| `r.scale(2)` | send `scale(2)`; the object changes itself |

### `this`

```java
class Employee {
    String name;
    int salary;

    void setSalary(int salary) {
        this.salary = salary;          // field = parameter
    }

    boolean earnsMoreThan(Employee other) {
        return this.salary > other.salary;
    }
}
```

### `toString()`

```java
class Book {
    String title;
    String author;

    public String toString() {
        return title + " by " + author;
    }
}
```

```java
Book b = new Book();
b.title = "Data Structures";
b.author = "N. Akter";
System.out.println(b);                    // Data Structures by N. Akter
String line = "Book: " + b;               // "Book: Data Structures by N. Akter"
```

### A constructor (first look)

```java
class Course {
    String code;
    int credits;

    Course(String code, int credits) {
        this.code = code;
        this.credits = credits;
    }
}
```

```java
Course oop = new Course("CSE 1115", 3);
```

### Instance methods need an object

`main` is `static`, so it has no current object. It cannot call an instance method or
read a field by its bare name; it must go through a reference.

```java nocompile
class Student {
    String name;

    void printInfo() {
        System.out.println(name);
    }
}

public class Wrong {
    public static void main(String[] args) {
        printInfo();   // error: non-static method printInfo() cannot be referenced
                       //        from a static context
    }
}
```

The fix is to create an object and call the method on it: `Student s = new Student();`
then `s.printInfo();`. Chapter 07 explains `static` in full.

## 3. Worked Examples

### Example 1: Students as Separate Objects

**Problem:** Create two `Student` objects. Print one right after `new` to see the
default values, then fill in both and print them. Finally, make a second reference to
Rahim's object, change the CGPA through it, and show that Rahim's data changed.

The class has four fields and one method, `printInfo()`, that prints the state of the
current object. `printf` with `%.2f` keeps the CGPA format fixed.

```java
class Student {
    String name;
    int id;
    double cgpa;
    boolean scholarship;

    void printInfo() {
        System.out.printf("%d | %s | CGPA %.2f | scholarship: %b%n",
                id, name, cgpa, scholarship);
    }
}

public class StudentObjects {
    public static void main(String[] args) {
        Student rahim = new Student();
        System.out.println("A brand-new object:");
        rahim.printInfo();

        rahim.name = "Rahim";
        rahim.id = 1001;
        rahim.cgpa = 3.45;

        Student nusrat = new Student();
        nusrat.name = "Nusrat";
        nusrat.id = 1002;
        nusrat.cgpa = 3.90;
        nusrat.scholarship = true;

        System.out.println("After setting the fields:");
        rahim.printInfo();
        nusrat.printInfo();

        Student sameStudent = rahim;    // copies the reference, not the object
        sameStudent.cgpa = 3.60;
        System.out.println("After changing the CGPA through sameStudent:");
        rahim.printInfo();
        nusrat.printInfo();
    }
}
```

**Output:**

```text
A brand-new object:
0 | null | CGPA 0.00 | scholarship: false
After setting the fields:
1001 | Rahim | CGPA 3.45 | scholarship: false
1002 | Nusrat | CGPA 3.90 | scholarship: true
After changing the CGPA through sameStudent:
1001 | Rahim | CGPA 3.60 | scholarship: false
1002 | Nusrat | CGPA 3.90 | scholarship: true
```

**Why it works:** The first line of output shows the default values: `0`, `null`,
`0.0` and `false`. `rahim` and `nusrat` refer to two different objects, so each keeps
its own fields. `sameStudent = rahim` creates no new student; both variables now refer
to Rahim's object, so the change made through `sameStudent` appears when `rahim` prints.
Nusrat's object is untouched. The single `printInfo()` method serves both objects: each
call prints the fields of the object it was called on.

### Example 2: Rectangles with Behaviour

**Problem:** Read the width and height of two rectangles, then a scale factor. Print a
report for each rectangle, scale the first one, print both again, and say whether the
first is now larger than the second.

Design: a `Rectangle` knows its own size, so it is the right place for `area()`,
`perimeter()`, `isSquare()` and `scale()`. Comparing two rectangles is a method that
takes another `Rectangle`. Printing the report is a `static` helper in the main class
that receives a rectangle as a parameter.

```java
import java.util.Scanner;

class Rectangle {
    double width;
    double height;

    double area() {
        return width * height;
    }

    double perimeter() {
        return 2 * (width + height);
    }

    boolean isSquare() {
        return width == height;
    }

    void scale(double factor) {
        width = width * factor;
        height = height * factor;
    }

    boolean isLargerThan(Rectangle other) {
        return this.area() > other.area();
    }
}

public class RectangleReport {
    static void printReport(String label, Rectangle r) {
        System.out.printf("%s: %.1f x %.1f, area %.2f, perimeter %.2f%n",
                label, r.width, r.height, r.area(), r.perimeter());
        if (r.isSquare()) {
            System.out.println(label + " is a square");
        }
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Rectangle first = new Rectangle();
        first.width = in.nextDouble();
        first.height = in.nextDouble();
        Rectangle second = new Rectangle();
        second.width = in.nextDouble();
        second.height = in.nextDouble();
        double factor = in.nextDouble();

        printReport("A", first);
        printReport("B", second);
        System.out.println("A is larger than B: " + first.isLargerThan(second));

        first.scale(factor);
        System.out.println("After scaling A by " + factor + ":");
        printReport("A", first);
        printReport("B", second);
        System.out.println("A is larger than B: " + first.isLargerThan(second));
    }
}
```

**Input:**

```text
4 6
5 5
1.5
```

**Output:**

```text
A: 4.0 x 6.0, area 24.00, perimeter 20.00
B: 5.0 x 5.0, area 25.00, perimeter 20.00
B is a square
A is larger than B: false
After scaling A by 1.5:
A: 6.0 x 9.0, area 54.00, perimeter 30.00
B: 5.0 x 5.0, area 25.00, perimeter 20.00
B is a square
A is larger than B: true
```

**Why it works:** `first.scale(factor)` changes only the object `first` refers to; `B`
prints the same numbers before and after. In `first.isLargerThan(second)`, `this` is the
first rectangle and `other` is the second, so `this.area()` and `other.area()` call the
same method on two different objects. `printReport` reads fields and calls methods
through the reference it receives, without knowing or caring which rectangle it is.

### Example 3: Bank Accounts that Talk to Each Other

**Problem:** Model bank accounts that accept deposits, refuse invalid withdrawals and
can transfer money to another account. Use `this` to set the owner's name, and show
which operations succeed.

Design: amounts are whole Taka, so `int` is enough. Each operation returns `boolean`:
`true` when it succeeded. The class does not decide what to print; `main` does.

```java
class BankAccount {
    String accountNumber;
    String owner;
    int balance;          // in Tk; starts at 0, the default value

    void setOwner(String owner) {
        this.owner = owner;       // the field gets the parameter's value
    }

    boolean deposit(int amount) {
        if (amount <= 0) {
            return false;
        }
        balance = balance + amount;
        return true;
    }

    boolean withdraw(int amount) {
        if (amount <= 0 || amount > balance) {
            return false;
        }
        balance = balance - amount;
        return true;
    }

    boolean transferTo(BankAccount other, int amount) {
        if (!this.withdraw(amount)) {
            return false;
        }
        other.deposit(amount);
        return true;
    }

    void printStatement() {
        System.out.println(accountNumber + " (" + owner + "): " + balance + " Tk");
    }
}

public class BankAccountDemo {
    public static void main(String[] args) {
        BankAccount rahim = new BankAccount();
        rahim.accountNumber = "AC-101";
        rahim.setOwner("Rahim");

        BankAccount karim = new BankAccount();
        karim.accountNumber = "AC-102";
        karim.setOwner("Karim");

        System.out.println("Rahim deposits 5000: " + rahim.deposit(5000));
        System.out.println("Karim deposits -20: " + karim.deposit(-20));
        System.out.println("Karim withdraws 100: " + karim.withdraw(100));
        System.out.println("Rahim sends 1500 to Karim: " + rahim.transferTo(karim, 1500));
        System.out.println("Karim sends 9000 to Rahim: " + karim.transferTo(rahim, 9000));
        rahim.printStatement();
        karim.printStatement();
    }
}
```

**Output:**

```text
Rahim deposits 5000: true
Karim deposits -20: false
Karim withdraws 100: false
Rahim sends 1500 to Karim: true
Karim sends 9000 to Rahim: false
AC-101 (Rahim): 3500 Tk
AC-102 (Karim): 1500 Tk
```

**Why it works:** In `setOwner`, the parameter `owner` hides the field `owner`, so
`this.owner = owner` is needed to reach the field. `transferTo` reuses `withdraw` on the
current object, so the "not more than the balance" rule is written only once. If the
withdrawal fails, nothing is deposited and both balances stay the same, which is why
Karim's attempt to send 9000 Tk changes nothing. The two accounts cooperate by calling
each other's methods; `main` never touches `balance` directly.

### Example 4: Library Books with `toString()`

**Problem:** A library owns several copies of each book. Write a `Book` class that
tracks how many copies are on loan, refuses to lend more copies than it has, and prints
itself in a friendly way.

Design: the state is `copies` (owned) and `onLoan` (borrowed now). The number of
available copies is not stored; `available()` computes it, so it can never be out of
date. `toString()` builds the text once and is used three different ways.

```java
class Book {
    String title;
    String author;
    int copies;
    int onLoan;

    boolean borrow() {
        if (onLoan == copies) {
            return false;
        }
        onLoan++;
        return true;
    }

    boolean giveBack() {
        if (onLoan == 0) {
            return false;
        }
        onLoan--;
        return true;
    }

    int available() {
        return copies - onLoan;
    }

    public String toString() {
        return title + " by " + author + " (" + available() + " of " + copies
                + " available)";
    }
}

public class LibraryShelf {
    public static void main(String[] args) {
        Book dataStructures = new Book();
        dataStructures.title = "Data Structures";
        dataStructures.author = "N. Akter";
        dataStructures.copies = 2;

        Book novel = new Book();
        novel.title = "The River Town";
        novel.author = "S. Rahman";
        novel.copies = 1;

        System.out.println(dataStructures);            // println calls toString()
        dataStructures.borrow();
        dataStructures.borrow();
        System.out.println("Third copy lent? " + dataStructures.borrow());
        String line = "Most wanted: " + dataStructures; // + calls toString()
        System.out.println(line);

        System.out.println("Return unborrowed novel? " + novel.giveBack());
        System.out.println(novel.toString());          // explicit call
    }
}
```

**Output:**

```text
Data Structures by N. Akter (2 of 2 available)
Third copy lent? false
Most wanted: Data Structures by N. Akter (0 of 2 available)
Return unborrowed novel? false
The River Town by S. Rahman (1 of 1 available)
```

**Why it works:** `System.out.println(dataStructures)` and
`"Most wanted: " + dataStructures` both call `toString()` automatically, so the output
shows the title instead of something like `Book@1b6d3586`. Each `Book` object keeps its
own `onLoan` count, so lending copies of one book never affects the other. The rules ("not more than you own",
"cannot return what was not lent") sit inside the class, next to the fields they
protect.

### Example 5: Designing an Employee Class from a Description

**Problem:** The university canteen pays its staff monthly. *Each employee has a name,
an ID, a basic salary in Tk and a number of overtime hours this month. Overtime is paid
at 200 Tk per hour. The manager wants to record overtime, give an employee a raise by a
percentage, compute the month's pay, and print a pay slip.* Read one employee's data,
an overtime entry and a raise percentage, then print the pay slip before and after.

Start with nouns and verbs:

| Word | Decision |
|---|---|
| employee | class `Employee` (several pieces of data, rules, many employees) |
| name, ID, basic salary, overtime hours | fields |
| overtime rate (200 Tk per hour) | field with a starting value |
| record overtime | method `addOvertime(int hours)` |
| give a raise | method `giveRaise(int percent)` |
| compute the month's pay | method `monthlyPay()` (computed, not stored) |
| print a pay slip | method `toString()` |
| manager | only uses the program; no data to store, so not a class |

```java
import java.util.Scanner;

class Employee {
    String name;
    String id;
    int basicSalary;           // Tk per month
    int overtimeHours;
    int overtimeRate = 200;    // Tk per hour, same start value for every employee

    void addOvertime(int hours) {
        if (hours > 0) {
            overtimeHours = overtimeHours + hours;
        }
    }

    void giveRaise(int percent) {
        if (percent > 0) {
            basicSalary = basicSalary + basicSalary * percent / 100;
        }
    }

    int monthlyPay() {
        return basicSalary + overtimeHours * overtimeRate;
    }

    public String toString() {
        return id + " " + name + ": basic " + basicSalary + ", overtime "
                + overtimeHours + " h, pay " + monthlyPay() + " Tk";
    }
}

public class CanteenPayroll {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        Employee e = new Employee();
        e.name = in.nextLine();
        e.id = in.nextLine();
        e.basicSalary = in.nextInt();
        int hours = in.nextInt();
        int raise = in.nextInt();

        System.out.println("Start:    " + e);
        e.addOvertime(hours);
        System.out.println("Overtime: " + e);
        e.giveRaise(raise);
        System.out.println("Raised:   " + e);
    }
}
```

**Input:**

```text
Sadia Islam
E-17
25000
12
10
```

**Output:**

```text
Start:    E-17 Sadia Islam: basic 25000, overtime 0 h, pay 25000 Tk
Overtime: E-17 Sadia Islam: basic 25000, overtime 12 h, pay 27400 Tk
Raised:   E-17 Sadia Islam: basic 27500, overtime 12 h, pay 29900 Tk
```

**Why it works:** Every verb in the description became a method, and every method sits
in the class whose fields it changes. `monthlyPay()` is computed from the current state
each time, so after the raise the pay is right without any extra update. The manager is
not a class: a noun becomes a class only when the program must store data or rules for
it. The ID is a `String` because "E-17" is a label, not a number to calculate with.

### Example 6: Students Registering for Courses

**Problem:** During course registration, a student may take at most 15 credits in a
trimester, and a course section has a limited number of seats. Write `Student` and
`Course` classes, give them constructors, and let a course enroll students while
checking both rules.

Design:

- `Student` knows its own credits and limit, so it answers `canTake(credits)` and
  updates itself in `addCredits(credits)`.
- `Course` knows its seats, so it checks `isFull()`. Its `enroll(Student s)` method
  asks the student before it changes anything: two objects cooperate.
- Constructors set up each object in one line, as a first taste of Chapter 06.

```java
class Student {
    String name;
    int credits;
    int creditLimit = 15;

    Student(String name, int credits) {
        this.name = name;
        this.credits = credits;
    }

    boolean canTake(int courseCredits) {
        return credits + courseCredits <= creditLimit;
    }

    void addCredits(int courseCredits) {
        credits = credits + courseCredits;
    }

    public String toString() {
        return name + " (" + credits + " credits)";
    }
}

class Course {
    String code;
    int credits;
    int seats;
    int enrolled;

    Course(String code, int credits, int seats) {
        this.code = code;
        this.credits = credits;
        this.seats = seats;
    }

    boolean isFull() {
        return enrolled == seats;
    }

    boolean enroll(Student s) {
        if (isFull()) {
            System.out.println(s.name + " cannot join " + code + ": section full");
            return false;
        }
        if (!s.canTake(credits)) {
            System.out.println(s.name + " cannot join " + code + ": credit limit");
            return false;
        }
        enrolled++;
        s.addCredits(credits);
        System.out.println(s.name + " joined " + code);
        return true;
    }

    public String toString() {
        return code + " (" + credits + " cr): " + enrolled + "/" + seats + " seats taken";
    }
}

public class CourseRegistration {
    public static void main(String[] args) {
        Course oop = new Course("CSE 1115", 3, 2);
        Course math = new Course("MAT 2109", 3, 40);

        Student rahim = new Student("Rahim", 9);
        Student ayesha = new Student("Ayesha", 13);
        Student fahim = new Student("Fahim", 6);
        Student mitu = new Student("Mitu", 3);

        oop.enroll(rahim);
        oop.enroll(ayesha);
        oop.enroll(fahim);
        oop.enroll(mitu);
        math.enroll(mitu);

        System.out.println(oop);
        System.out.println(math);
        System.out.println(rahim);
        System.out.println(ayesha);
        System.out.println(mitu);
    }
}
```

**Output:**

```text
Rahim joined CSE 1115
Ayesha cannot join CSE 1115: credit limit
Fahim joined CSE 1115
Mitu cannot join CSE 1115: section full
Mitu joined MAT 2109
CSE 1115 (3 cr): 2/2 seats taken
MAT 2109 (3 cr): 1/40 seats taken
Rahim (12 credits)
Ayesha (13 credits)
Mitu (6 credits)
```

**Why it works:** `oop.enroll(rahim)` runs with `this` = the OOP course and `s` = Rahim.
The course checks its own seats, asks the student about the credit limit, and only then
changes *both* objects: `enrolled++` on itself and `s.addCredits(credits)` on the
student. Ayesha already has 13 credits, so 3 more would exceed 15 and nothing changes.
The constructors replace four or five assignment lines per object with one `new`
expression, and `creditLimit = 15` shows that a field initializer and a constructor can
work together.

## Common Mistakes

- **Using a reference before creating the object.** `Student s;` followed by
  `s.name = "Rahim";` does not compile ("variable s might not have been initialized").
  `Student s = null;` compiles, but `s.name = "Rahim";` then stops the program with a
  `NullPointerException`. Create the object first: `Student s = new Student();`.
- **Forgetting `this` when names clash.** In `void setOwner(String owner) { owner =
  owner; }` the parameter is assigned to itself and the field stays `null`. Write
  `this.owner = owner;`.
- **Calling an instance method from `main` without an object.** `printInfo();` inside
  `main` fails with "non-static method ... cannot be referenced from a static context".
  Call it on an object: `s.printInfo();`.
- **Adding `static` to fields to "fix" that error.** A `static` field is shared by all
  objects, so every student would have the same name. Fields that describe one object
  must not be `static` (Chapter 07).
- **Expecting `b = a` to copy an object.** It copies the reference; both variables then
  refer to one object. Use `new` to create a second object.
- **Printing inside `toString()`.** `toString()` must `return` a `String`. If it calls
  `System.out.println` and returns nothing useful, `println(s)` shows the wrong text.
- **Writing a return type on a constructor.** `void Student(String name) { ... }` is an
  ordinary method that happens to share the class name, not a constructor. Constructors
  have no return type.
- **Putting the logic in `main`.** If `main` does `acc.balance = acc.balance - 500;`,
  the "no overdraft" rule is skipped. Ask the object: `acc.withdraw(500)`.

## Summary

- A class defines a new type. Its objects have **state** (fields) and **behaviour**
  (instance methods).
- `new ClassName()` creates an object on the heap and gives back a **reference**; a
  variable of a class type stores that reference, not the object itself.
- Each object has its own copy of every field. Method code is stored once in the class
  and runs on the object it is called on.
- Fields start with default values (`0`, `0.0`, `false`, `null`); local variables must
  be assigned before use.
- Use `.` to reach members: `obj.field`, `obj.method(args)`. Assigning one reference to
  another makes two names for the same object.
- `this` refers to the current object. Use it to reach a field hidden by a parameter of
  the same name and to compare the current object with another.
- Design classes from descriptions: nouns become classes or fields, verbs become
  methods placed in the class whose data they change. Always ask "should this be a
  class?"
- Objects cooperate by passing references to each other's methods.
- `public String toString()` returns a friendly text form; `println(obj)` and
  `"text" + obj` call it automatically.
- A constructor sets up a new object when it is created; Chapter 06 covers constructors
  fully. In this chapter fields are not `private`; Chapter 05 adds encapsulation.
