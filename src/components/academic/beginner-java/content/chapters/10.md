# Chapter 10: Polymorphism, Abstract Classes and Interfaces

In Chapter 09 you built class hierarchies with `extends` and overrode methods. This
chapter shows what that buys you: one piece of code can work with many kinds of
objects, and each object responds in its own way. This idea is called polymorphism.
You will also learn the two tools that make polymorphic designs clean: abstract
classes and interfaces.

**In this chapter you will learn:**

- what polymorphism means and why it makes programs easier to extend
- compile-time polymorphism: method overloading and constructor overloading
- runtime polymorphism: overriding, superclass references and dynamic method dispatch
- upcasting, downcasting, `ClassCastException` and `instanceof` (including the
  pattern form)
- what is *not* polymorphic: static methods, fields, `private` and `final` methods
- how Java's dynamic dispatch relates to what C++ calls "virtual functions"
- abstract classes and abstract methods
- interfaces, multiple interfaces, `default` methods and `static` interface methods
- when to choose an abstract class and when to choose an interface
- how to replace long `if`/`else` type checks with polymorphism

## 1. Concept Explanation

### What polymorphism means

The word comes from Greek: *poly* means "many" and *morph* means "form". In
programming it means **one interface, many forms**: the same method call can do
different things, depending on the object that receives it.

An analogy first. At the campus canteen counter the cashier says "Pay, please".
Rahim pays cash, Nusrat taps a card and Tanvir uses a mobile wallet. The cashier sends
one message ("pay"), and each customer carries it out in a different way. The cashier
does not need a separate rule for every payment type.

Now the real programming model:

```java
Payment p = new CardPayment();   // p could also refer to a CashPayment
p.pay(250);                      // the object decides what "pay" means
```

The variable `p` has the type `Payment`, but the object it refers to is a
`CardPayment`. When the program runs, Java calls the `pay` method of the actual
object.

Why this matters:

- Code that works with `Payment` does not change when you add a new payment type.
- Each class keeps its own behaviour next to its own data (encapsulation again).
- You avoid long `if (type == ...)` chains spread across the program.

### Two kinds of polymorphism

Java has two mechanisms that both let one name stand for several behaviours.

| | Compile-time polymorphism | Runtime polymorphism |
|---|---|---|
| Java feature | Overloading | Overriding + superclass references |
| Who picks the method | The compiler (`javac`) | The JVM, while the program runs |
| Based on | Number and types of arguments | Actual class of the object |
| Other names | Static binding, early binding | Dynamic binding, dynamic dispatch |

When people say "polymorphism" without more detail, they usually mean the runtime
kind. Both kinds are covered here.

### Compile-time polymorphism: overloading

**Overloading** means several methods in the same class share one name but have
different parameter lists (a different number, types or order of parameters). You met
it in Chapter 03 (methods) and Chapter 06 (constructors).

```java
static int max(int a, int b) { ... }
static double max(double a, double b) { ... }
static int max(int a, int b, int c) { ... }
```

The compiler chooses the version by looking at the arguments written in the call.
This happens before the program runs, which is why it is called *compile-time*
polymorphism.

```java
static void show(int x)    { System.out.println("int: " + x); }
static void show(double x) { System.out.println("double: " + x); }
static void show(String x) { System.out.println("String: " + x); }

show(7);      // int: 7
show(7.5);    // double: 7.5
show("7");    // String: 7
show('A');    // int: 65   (no show(char), so char is widened to int)
```

Rules to remember:

- The return type alone does not make an overload. `int total()` and
  `double total()` in the same class is a compile error.
- With no exact match, the compiler may widen a value (`char` → `int` → `long` →
  `double`) and picks the most specific method that fits.
- The choice uses the *declared* type of each argument, never the actual object.
  Example 4 shows why that matters.

**Constructor overloading** is the same idea for constructors: several ways to create
an object. With `this(...)` (Chapter 06) the short versions pass default values to
the full one, so the setup code is written once.

```java
class Ticket {
    private final String route;
    private final int seats;

    Ticket() {
        this("Campus Loop", 1);
    }

    Ticket(String route) {
        this(route, 1);
    }

    Ticket(String route, int seats) {
        this.route = route;
        this.seats = seats;
    }
}
```

`new Ticket()`, `new Ticket("Mirpur")` and `new Ticket("Uttara", 2)` all compile; the
compiler picks the constructor whose parameters match the arguments.

### Runtime polymorphism: overriding and superclass references

Runtime polymorphism needs two ingredients from Chapter 09:

1. A subclass **overrides** a method: same name, same parameter list, compatible
   return type.
2. A variable of a **superclass type** can refer to an object of **any subclass**,
   because every `Cat` *is an* `Animal`.

```java
class Animal {
    String sound() {
        return "...";
    }
}

class Cat extends Animal {
    @Override
    String sound() {
        return "Meow";
    }
}

class Cow extends Animal {
    @Override
    String sound() {
        return "Moo";
    }
}
```

```java
Animal a = new Cat();            // superclass reference, subclass object
System.out.println(a.sound());   // Meow
a = new Cow();
System.out.println(a.sound());   // Moo
```

The same line `a.sound()` produced two different results. To understand why, keep
two types apart:

| | Meaning | For `Animal a = new Cat();` |
|---|---|---|
| Declared (static) type | Type of the variable, fixed at compile time | `Animal` |
| Actual (runtime) type | Class of the object, known at run time | `Cat` |

- The **declared type** decides *which methods you may call*. The compiler checks it.
- The **actual type** decides *which version of an overridden method runs*. The JVM
  chooses it.

```java
Animal a = new Cat();
a.sound();       // OK: Animal has sound(); Cat's version runs
a.climbTree();   // compile error if only Cat has climbTree()
```

### Dynamic method dispatch

**Dynamic method dispatch** is the mechanism behind runtime polymorphism. When an
overridden method is called through a reference, the JVM looks at the object the
reference points to and runs the version from that object's class. If that class
does not override the method, the JVM moves up to the superclass, and so on.

```text
  Animal a = new Cat();
  a.sound();

  COMPILE TIME (javac)              RUN TIME (JVM)
  +-------------------------+       +---------------------------+
  | a is declared Animal    |       | a refers to a Cat object  |
  | Animal has sound()? yes |       | look for sound() in Cat   |
  | --> call is allowed     |       | --> run Cat's sound()     |
  +-------------------------+       +---------------------------+

  stack                    heap
  +--------------+         +--------------+
  | a  (Animal)  |-------->| Cat object   |
  +--------------+         +--------------+
                                  |
                 JVM: "what is the object's real class?"  Cat
                                  |
                                  v
  search starts at the object's class and moves up:

  +----------+  not found?  +----------+  not found?  +----------+
  |   Cat    |------------->|  Animal  |------------->|  Object  |
  +----------+              +----------+              +----------+
  sound() is found in Cat, so Cat's version runs.
```

This is what makes a loop over mixed objects so short:

```java
Animal[] farm = { new Cat(), new Cow(), new Cat() };
for (Animal x : farm) {
    System.out.println(x.sound());   // one line, three behaviours
}
```

### Java and "virtual functions"

If you read C++ material, you will meet the term **virtual function**: a member
function whose call is resolved at run time from the actual object. Java has the same
idea, but no `virtual` keyword.

In Java, **every instance method that is not `static`, not `private` and not `final`
is dynamically dispatched by default**. Conceptually, that is what C++ calls a virtual
function. The difference is the default:

| Question | C++ (in words) | Java |
|---|---|---|
| Keyword needed for dynamic dispatch | Yes, `virtual` | No keyword: it is the default |
| Ordinary instance method | Not dispatched dynamically | Dispatched dynamically |
| How you change the default | Opt in with `virtual` | Opt out with `final` (or `static`, `private`) |
| Method with no body, to be supplied | "Pure virtual function" | `abstract` method |
| Class that has such methods | Abstract class | `abstract` class or interface |

So instead of saying "Java has virtual functions", say: "In Java, overridable instance
methods are dynamically dispatched by default; C++ needs the `virtual` keyword for
that."

### Upcasting and downcasting

**Upcasting** converts a subclass reference to a superclass type. It is always safe
(every `Cat` is an `Animal`), so Java does it implicitly.

**Downcasting** converts a superclass reference to a subclass type. You must write the
cast, for example `(Cat) a`. The compiler accepts it because it *might* be correct;
the JVM checks it at run time. If the object is not really a `Cat`, the JVM throws a
`ClassCastException` and the program stops.

```text
                +------------+
                |   Animal   |
                +------------+
                  ^        |
     upcasting    |        |    downcasting
     implicit     |        |    explicit: (Cat) a
     always safe  |        |    checked at run time,
                  |        |    may throw ClassCastException
                  |        v
                +------------+
                |    Cat     |
                +------------+
```

```java
Cat tom = new Cat();
Animal a = tom;          // upcast: implicit, no cast written
Cat back = (Cat) a;      // downcast: fine, a really refers to a Cat

Animal b = new Cow();
Cat wrong = (Cat) b;     // compiles, but fails at run time
```

The last line stops the program with a message like this (shortened):

```text
Exception in thread "main" java.lang.ClassCastException:
    class Cow cannot be cast to class Cat
```

Two more facts:

- A cast never changes the object. It only changes the type of the reference, and so
  which methods the compiler lets you call.
- A cast between unrelated classes, such as `(String) a`, is a compile error,
  because no object can be both.

You will learn how to catch exceptions in Chapter 11. Here you will learn to avoid
this one with `instanceof`.

### `instanceof` and its pattern form

`x instanceof Cat` is `true` when `x` refers to a `Cat` (or an object of a subclass
of `Cat`), and `false` otherwise. It is always `false` when `x` is `null`.

The classic form tests first and casts afterwards:

```java
if (a instanceof Cat) {
    Cat c = (Cat) a;
    c.climbTree();
}
```

Java 16 added the **pattern form**, which tests and declares the variable in one step:

```java
if (a instanceof Cat c) {
    c.climbTree();          // c is already a Cat here
}
```

The variable `c` exists only where the test is known to be true. You may use it later
in the same condition: `if (a instanceof Cat c && c.isHungry())`.

A warning: if your code is full of `instanceof` checks, the design usually needs an
overridden method instead. Use `instanceof` for behaviour that only *some* classes
have, not for behaviour that *every* class has in its own way.

### What is not polymorphic

Dynamic dispatch applies to overridable instance methods only. Everything else is
decided at compile time.

| Member | Overridden? | What decides which one is used |
|---|---|---|
| Ordinary instance method | Yes | Actual class of the object (run time) |
| `static` method | No, it is *hidden* | Declared type or class name (compile time) |
| Field | No, it is *hidden* | Declared type of the reference (compile time) |
| `private` method | No, not inherited | The class where the call is written |
| `final` method | Cannot be overridden | There is only one version |
| Constructor | Not inherited | The class named after `new` |
| Choice among overloads | Not overriding | Declared argument types (compile time) |

- **Static methods are hidden, not overridden.** If `Child` declares a static method
  with the same signature as a static method in `Parent`, `Parent.category()` and
  `Child.category()` are simply two different methods. Writing `@Override` on a
  static method is a compile error.
- **Fields are hidden, not overridden.** If both classes declare a field `label`,
  the declared type of the reference picks the field. Avoid this: keep fields
  `private` and use methods, which *are* polymorphic.
- **Private methods are invisible to subclasses.** A method with the same name in a
  subclass is a brand-new method, and calls written inside the superclass still go to
  the superclass's private method.
- **Final methods** cannot be overridden, so every object uses the same version.

Example 4 demonstrates every row of this table.

### Abstract classes

Look again at `Animal.sound()` returning `"..."`. That body is meaningless: there is no
plain "animal" in a zoo, only lions, cows and cats. Java lets you say "every animal
has a sound, but I cannot write it here":

```java
abstract class Shape {
    private final String name;

    Shape(String name) {          // abstract classes can have constructors
        this.name = name;
    }

    abstract double area();       // no body: every subclass must supply it

    String describe() {           // a concrete method that uses the abstract one
        return String.format("%s with area %.2f", name, area());
    }
}
```

An **abstract class** is a class marked `abstract`. It can have fields, constructors,
ordinary (concrete) methods and **abstract methods**, which have a signature but no
body.

- You cannot create an object of it: `new Shape("x")` is a compile error.
- A concrete (non-abstract) subclass must override every abstract method. If it does
  not, it must be declared `abstract` too.
- An abstract method can only appear in an abstract class (or an interface).
- `abstract` cannot be combined with `private`, `static` or `final`: each of those
  prevents overriding, and an abstract method exists only to be overridden.
- References of the abstract type work normally: `Shape s = new Circle(1.5);`

```text
               +------------------------+
               | <<abstract>> Shape     |
               | - name                 |
               | + area()   (abstract)  |
               | + describe()           |
               +------------------------+
                   ^        ^        ^
                   |        |        |
           +----------+ +--------+ +-----------+
           | Circle   | | Square | | Triangle  |
           | area()   | | area() | | area()    |
           +----------+ +--------+ +-----------+
```

Use an abstract class when related classes share fields and code, but one step must
be done differently by each subclass. In the example above, `describe()` is written
once and calls `area()`, which each subclass fills in. This "fixed outline, variable
step" design is often called the *template method* pattern.

### Interfaces

An **interface** is a contract: a list of methods that a class promises to provide.
It says *what* an object can do, not *what kind of thing* it is or *how* it does it.

```java
interface Payable {
    int amountDue();              // implicitly public and abstract
}

class Invoice implements Payable {
    private final int quantity;
    private final int unitPrice;

    Invoice(int quantity, int unitPrice) {
        this.quantity = quantity;
        this.unitPrice = unitPrice;
    }

    @Override
    public int amountDue() {      // must be public
        return quantity * unitPrice;
    }
}
```

Key facts:

- Interface methods without a body are implicitly `public` and `abstract`. The
  implementing method must therefore be `public`.
- Fields in an interface are implicitly `public static final` constants. An interface
  has no instance fields and no constructors, and you cannot instantiate it.
- A class that `implements` an interface must implement all its abstract methods, or
  be declared `abstract`.
- A class can extend one class but **implement many interfaces**:
  `class Employee extends Person implements Payable, Taxable`. This is Java's form of
  multiple inheritance of *type* (Chapter 09).
- An interface can extend other interfaces: `interface Refundable extends Payable`.
- An interface is a type. `Payable p = new Invoice(10, 450);` is interface-based
  polymorphism.

The last point is the important one. Classes that have nothing else in common can be
handled by the same code:

```text
              +-------------------+
              | <<interface>>     |
              | Payable           |
              | + amountDue()     |
              +-------------------+
                 ^             ^
      implements |             | implements
         +--------------+  +--------------+
         | Employee     |  | Invoice      |
         | (a person)   |  | (a document) |
         +--------------+  +--------------+
```

You already use an interface from Java's library: `List<E>` is an interface and
`ArrayList<E>` is a class that implements it. So `List<Shape> shapes = new
ArrayList<>();` declares the variable by the contract (`List`) and picks the
implementation (`ArrayList`) in one place only. This habit is called "programming to
an interface".

### `default` and `static` methods in interfaces

Since Java 8 an interface may also contain methods with a body:

```java
interface Payable {
    int amountDue();

    default String paymentLine() {           // inherited; may be overridden
        return "Pay " + formatTk(amountDue());
    }

    static String formatTk(int amount) {     // called as Payable.formatTk(...)
        return amount + " Tk";
    }
}
```

- A **default method** is inherited by every implementing class, which may override
  it. Default methods let a library add a method to an interface without breaking
  every class that already implements it.
- A **static interface method** is a helper that belongs to the interface itself. Call
  it with the interface name: `Payable.formatTk(500)`. It is not inherited by
  implementing classes.
- If a class implements two interfaces that both provide the same default method, the
  class must override that method to settle the conflict.

### Abstract class vs interface

| | Abstract class | Interface |
|---|---|---|
| A class uses it with | `extends` | `implements` |
| How many per class | One | Many |
| Instance fields (state) | Yes | No (only constants) |
| Constructors | Yes | No |
| Kinds of methods | Abstract and concrete | Abstract, `default`, `static` |
| Method access | Any (`private` ... `public`) | `public` (plus private helpers) |
| Relationship | "is a kind of" | "can do" |
| Example | A `Circle` is a `Shape` | An `Invoice` can be paid |
| Use when | Related classes share data and code | Unrelated classes share a role |

A good default: describe a *role* with an interface, and add an abstract class when
several implementations share real code. The two combine well:
`abstract class Employee implements Payable`.

### Designing with polymorphism

Here is a design smell (a sign that something is wrong):

```java
double area;
if (type.equals("circle")) {
    area = Math.PI * r * r;
} else if (type.equals("square")) {
    area = side * side;
} else if (type.equals("triangle")) {
    area = 0.5 * base * height;
} else {
    area = 0;
}
```

The problems:

- Every new shape means editing this chain, and every other chain like it (perimeter,
  drawing, saving ...). It is easy to forget one.
- The data of a shape and the rules about it live in different places.

The polymorphic fix: each shape becomes a class that overrides `area()`, and the
caller writes just `s.area()`. Adding a hexagon means adding one new class; existing,
tested code does not change. This is called the **open/closed principle**: open for
extension, closed for modification.

Back to the course question, **"Should this be a class?"**: if a method keeps asking
"what type are you?", each answer is probably a class of its own (or an
implementation of an interface).

## 2. Syntax

### Overloading (compile-time)

```java
class Printer {
    void print(int value) { ... }                // print(int)
    void print(String text) { ... }              // print(String)
    void print(String text, int copies) { ... }  // print(String, int)
}
```

Same name, different parameter lists. Return type and parameter *names* do not count.

### Overriding (runtime)

```java
class Cat extends Animal {
    @Override
    String sound() {
        return "Meow";
    }
}
```

- Same name and same parameter types as the superclass method.
- Return type: the same, or a subclass of it (a *covariant* return type).
- Access: the same or wider (`protected` may become `public`, never `private`).
- `@Override` asks the compiler to check that you really override something. A typing
  mistake such as `Sound()` then becomes a compile error instead of a silent new method.

### Superclass and interface references

```java
Animal a = new Cat();                 // class type
Payable p = new Invoice(3, 120);      // interface type
List<Shape> shapes = new ArrayList<>();
shapes.add(new Circle(1.0));          // upcast happens automatically
```

### Casting and `instanceof`

```java
Cat c1 = (Cat) a;                     // downcast; may throw ClassCastException

if (a instanceof Cat) {               // classic form
    Cat c2 = (Cat) a;
}

if (a instanceof Cat c3) {            // pattern form (Java 16+)
    c3.climbTree();
}
```

### Abstract class and abstract method

```java
abstract class Shape {
    abstract double area();           // no body, ends with ;
    String describe() { ... }         // concrete method
}

class Circle extends Shape {
    private final double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}
```

### Interface and `implements`

```java
interface Taxable {
    int TAX_PERCENT = 5;              // public static final constant
    int taxableIncome();              // public abstract
}

class Employee implements Payable, Taxable {
    @Override
    public int amountDue() { ... }

    @Override
    public int taxableIncome() { ... }
}
```

### `default` and `static` interface methods

```java
interface Payable {
    int amountDue();

    default String paymentLine() {    // body allowed; inherited
        return "Pay " + amountDue();
    }

    static String formatTk(int amount) {
        return amount + " Tk";        // call as Payable.formatTk(...)
    }
}
```

### Stopping overriding with `final`

```java
class Account {
    final int accountNumber() { ... } // no subclass can override this
}

final class Receipt { ... }           // no class can extend this
```

## 3. Worked Examples

In a real project each public class lives in its own file; here we keep each program
in one file so you can compile it with one command.

### Example 1: Overloading in a Canteen Bill

**Problem:** A canteen bill should accept items in different ways: one item at a
price, several of the same item, or another person's whole bill (when a friend pays
for both). The bill can be created with a customer name or without one.

Design: one class `CanteenBill` with two overloaded constructors and three overloaded
`add` methods. The short versions call the full versions, so each rule is written
once.

```java
class CanteenBill {
    private final String customer;
    private int total;
    private int itemCount;

    CanteenBill() {
        this("Walk-in");
    }

    CanteenBill(String customer) {
        this.customer = customer;
    }

    void add(String item, int price) {
        add(item, price, 1);
    }

    void add(String item, int price, int quantity) {
        total += price * quantity;
        itemCount += quantity;
        System.out.printf("%-8s %-8s %d x %d Tk%n", customer, item, quantity, price);
    }

    void add(CanteenBill other) {
        total += other.total;
        itemCount += other.itemCount;
        System.out.println(customer + " pays the bill of " + other.customer);
    }

    void print() {
        System.out.println(customer + ": " + itemCount + " items, " + total + " Tk");
    }
}

public class CanteenOverloading {
    public static void main(String[] args) {
        CanteenBill rahim = new CanteenBill("Rahim");
        CanteenBill guest = new CanteenBill();

        rahim.add("Singara", 10);
        rahim.add("Tea", 15, 2);
        guest.add("Samosa", 12, 3);
        rahim.add(guest);
        rahim.print();
    }
}
```

**Output:**

```text
Rahim    Singara  1 x 10 Tk
Rahim    Tea      2 x 15 Tk
Walk-in  Samosa   3 x 12 Tk
Rahim pays the bill of Walk-in
Rahim: 6 items, 76 Tk
```

**Why it works:** For each call the compiler looks at the arguments: `("Singara", 10)`
matches `add(String, int)`, `("Tea", 15, 2)` matches `add(String, int, int)` and
`(guest)` matches `add(CanteenBill)`. The choice is fixed when the program is
compiled. In the same way, `new CanteenBill()` picks the constructor with no
parameters, which forwards to the other one with `this("Walk-in")`.

### Example 2: Campus Transport Fares

**Problem:** A student wants to compare the fare of several kinds of transport for the
same distance. Read the distance in km and print the fare of each option, then the
cheapest option.

Design: a superclass `Vehicle` with a standard `fare(km)` and a `describe(km)` method.
Each subclass overrides only `fare`. The program keeps all options in one
`Vehicle[]` array.

```java
import java.util.Scanner;

class Vehicle {
    private final String name;

    Vehicle(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    int fare(int km) {
        return 10 * km;                      // standard bus rate
    }

    String describe(int km) {
        return getName() + " for " + km + " km: " + fare(km) + " Tk";
    }
}

class Rickshaw extends Vehicle {
    Rickshaw() {
        super("Rickshaw");
    }

    @Override
    int fare(int km) {
        return 20 + 15 * km;
    }
}

class Cng extends Vehicle {
    Cng() {
        super("CNG");
    }

    @Override
    int fare(int km) {
        return 40 + 25 * km;
    }
}

class Shuttle extends Vehicle {
    Shuttle() {
        super("Campus shuttle");
    }

    @Override
    int fare(int km) {
        return 15;                           // flat fare for any distance
    }
}

public class TransportFares {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int km = in.nextInt();

        Vehicle[] options = {
            new Vehicle("Bus"), new Rickshaw(), new Cng(), new Shuttle()
        };

        Vehicle cheapest = options[0];
        for (Vehicle v : options) {
            System.out.println(v.describe(km));
            if (v.fare(km) < cheapest.fare(km)) {
                cheapest = v;
            }
        }
        System.out.println("Cheapest: " + cheapest.getName());
    }
}
```

**Input:**

```text
4
```

**Output:**

```text
Bus for 4 km: 40 Tk
Rickshaw for 4 km: 80 Tk
CNG for 4 km: 140 Tk
Campus shuttle for 4 km: 15 Tk
Cheapest: Campus shuttle
```

**Why it works:** The array has the declared element type `Vehicle`, so storing a
`Rickshaw` in it is an implicit upcast. `describe` is written only in `Vehicle`, yet
inside it the call `fare(km)` is dynamically dispatched: for the `Cng` object it runs
`Cng.fare`. The loop and `describe` never ask which kind of vehicle they have.

### Example 3: Zoo Animals and Safe Downcasting

**Problem:** A zoo keeper walks past a row of animals. Every animal makes its sound,
but some animals also have a special trick: dogs fetch a ball, parrots repeat a word.
Print each animal's sound and, where possible, its trick.

Design: `sound()` is common to all animals, so it is overridden. The tricks exist only
in `Dog` and `Parrot`, so the program uses `instanceof` before calling them. The dog
uses the pattern form; the parrot uses the classic form for comparison.

```java
class Animal {
    private final String name;

    Animal(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    String sound() {
        return "(silence)";
    }
}

class Dog extends Animal {
    Dog(String name) {
        super(name);
    }

    @Override
    String sound() {
        return "Woof";
    }

    String fetch() {
        return getName() + " fetches the ball";
    }
}

class Parrot extends Animal {
    private final String word;

    Parrot(String name, String word) {
        super(name);
        this.word = word;
    }

    @Override
    String sound() {
        return "Squawk";
    }

    String talk() {
        return getName() + " says \"" + word + "\"";
    }
}

class Fish extends Animal {
    Fish(String name) {
        super(name);
    }
}

public class ZooTricks {
    public static void main(String[] args) {
        Animal[] row = {
            new Dog("Tommy"), new Parrot("Mithu", "Hello"),
            new Fish("Goldie"), new Dog("Lalu")
        };

        int dogs = 0;
        for (Animal a : row) {
            System.out.println(a.getName() + ": " + a.sound());
            if (a instanceof Dog d) {
                System.out.println("  " + d.fetch());
                dogs++;
            } else if (a instanceof Parrot) {
                Parrot p = (Parrot) a;
                System.out.println("  " + p.talk());
            }
        }
        System.out.println("Dogs in the row: " + dogs);

        Animal third = row[2];
        if (!(third instanceof Dog)) {
            System.out.println(third.getName() + " is not a Dog: no (Dog) cast");
        }
    }
}
```

**Output:**

```text
Tommy: Woof
  Tommy fetches the ball
Mithu: Squawk
  Mithu says "Hello"
Goldie: (silence)
Lalu: Woof
  Lalu fetches the ball
Dogs in the row: 2
Goldie is not a Dog: no (Dog) cast
```

**Why it works:** `a.sound()` needs no test, because every `Animal` has `sound()` and
dynamic dispatch picks the right one (the fish inherits the default). `fetch()` and
`talk()` are not in `Animal`, so the compiler refuses `a.fetch()`; the program first
proves the type with `instanceof` and then works with a `Dog` or `Parrot` reference.
Casting `row[2]` to `Dog` without the test would compile, but it would throw a
`ClassCastException` at run time.

### Example 4: What Dynamic Dispatch Does Not Cover

**Problem:** Show, in one program, which members follow the actual object and which
follow the declared type: an overridden method, a static method, a field, a private
method, a final method and an overloaded method.

Design: `Parent` and `Child` declare members with the same names. `Parent.report()`
calls each of them, and the program calls `report()` on a `Child` object through a
`Parent` reference.

```java
class Parent {
    String label = "Parent field";

    static String category() {
        return "Parent static";
    }

    String who() {
        return "Parent method";
    }

    private String secret() {
        return "Parent private";
    }

    final String rule() {
        return "Parent final";
    }

    void report() {
        System.out.println("who():      " + who());
        System.out.println("category(): " + category());
        System.out.println("secret():   " + secret());
        System.out.println("rule():     " + rule());
    }
}

class Child extends Parent {
    String label = "Child field";        // hides Parent.label

    static String category() {           // hides Parent.category()
        return "Child static";
    }

    @Override
    String who() {                       // overrides Parent.who()
        return "Child method";
    }

    String secret() {                    // a NEW method, not an override
        return "Child secret";
    }
}

public class NotPolymorphic {
    static void greet(Parent x) {
        System.out.println("greet(Parent) chosen");
    }

    static void greet(Child x) {
        System.out.println("greet(Child) chosen");
    }

    public static void main(String[] args) {
        Parent p = new Child();
        p.report();

        System.out.println("p.label:    " + p.label);
        Child c = (Child) p;
        System.out.println("c.label:    " + c.label);
        System.out.println("Parent.category(): " + Parent.category());
        System.out.println("Child.category():  " + Child.category());

        greet(p);
        greet(c);
    }
}
```

**Output:**

```text
who():      Child method
category(): Parent static
secret():   Parent private
rule():     Parent final
p.label:    Parent field
c.label:    Child field
Parent.category(): Parent static
Child.category():  Child static
greet(Parent) chosen
greet(Child) chosen
```

**Why it works:** Only `who()` follows the object, because it is the only overridable
instance method. Inside `Parent`, the call `category()` means `Parent.category()`;
static methods are bound at compile time. `secret()` in `Parent` is private, so the
call inside `Parent` can only mean `Parent`'s own method. `rule()` is final, so there
is only one version. The fields follow the declared type of the reference: `p` and `c`
point to the *same* object but read different fields. Finally, `greet(p)` and
`greet(c)` pass the same object, yet the compiler chooses the overload from the
declared types `Parent` and `Child`.

### Example 5: Abstract Shapes in a List

**Problem:** Read a list of shapes (circle with radius, rectangle with width and
height, triangle with base and height). Print each shape with its area, the total
area and the name of the largest shape.

Design: an abstract class `Shape` holds the name and the shared `describe()` method;
`area()` is abstract. The shapes are stored in a `List<Shape>`, which is an interface
type implemented by `ArrayList`.

```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

abstract class Shape {
    private final String name;

    Shape(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    abstract double area();

    String describe() {
        return String.format("%-9s area = %6.2f", name, area());
    }
}

class Circle extends Shape {
    private final double radius;

    Circle(double radius) {
        super("Circle");
        this.radius = radius;
    }

    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}

class Rectangle extends Shape {
    private final double width;
    private final double height;

    Rectangle(double width, double height) {
        super("Rectangle");
        this.width = width;
        this.height = height;
    }

    @Override
    double area() {
        return width * height;
    }
}

class Triangle extends Shape {
    private final double base;
    private final double height;

    Triangle(double base, double height) {
        super("Triangle");
        this.base = base;
        this.height = height;
    }

    @Override
    double area() {
        return 0.5 * base * height;
    }
}

public class ShapeList {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        List<Shape> shapes = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            String kind = in.next();
            if (kind.equals("C")) {
                shapes.add(new Circle(in.nextDouble()));
            } else if (kind.equals("R")) {
                shapes.add(new Rectangle(in.nextDouble(), in.nextDouble()));
            } else {
                shapes.add(new Triangle(in.nextDouble(), in.nextDouble()));
            }
        }

        double total = 0;
        Shape largest = shapes.get(0);
        for (Shape s : shapes) {
            System.out.println(s.describe());
            total += s.area();
            if (s.area() > largest.area()) {
                largest = s;
            }
        }
        System.out.printf("Total area: %.2f%n", total);
        System.out.println("Largest: " + largest.getName());
    }
}
```

**Input:**

```text
3
C 1.5
R 3 4
T 6 2.5
```

**Output:**

```text
Circle    area =   7.07
Rectangle area =  12.00
Triangle  area =   7.50
Total area: 26.57
Largest: Rectangle
```

**Why it works:** `Shape` cannot be instantiated, but `Shape` references can hold any
subclass object. `describe()` is written once in the abstract class and calls the
abstract `area()`; at run time each object supplies its own formula. Note that the
input-reading code still checks the kind letter: text has to become objects
somewhere. That is fine, because it happens in one place only, and the rest of the
program works with `Shape` and never asks "what kind are you?" again.

### Example 6: Payable Employees and Invoices

**Problem:** The accounts office of a university pays two very different things:
employees (a monthly salary minus 5% tax) and supplier invoices (quantity times unit
price, no tax). Print one payment line for each, the total to pay and the total tax
withheld.

Design: an `Employee` and an `Invoice` are not related by "is-a", so they share an
interface `Payable` instead of a superclass. Only employees pay tax, so a second
interface `Taxable` is implemented by `Employee` alone. One object can be in both
lists, because it has both types.

```java
import java.util.ArrayList;

interface Payable {
    int amountDue();

    String payee();

    default String paymentLine() {
        return String.format("%-22s %s", payee(), formatTk(amountDue()));
    }

    static String formatTk(int amount) {
        return amount + " Tk";
    }
}

interface Taxable {
    int TAX_PERCENT = 5;

    int taxableIncome();

    default int tax() {
        return taxableIncome() * TAX_PERCENT / 100;
    }
}

class Employee implements Payable, Taxable {
    private final String name;
    private final int monthlySalary;

    Employee(String name, int monthlySalary) {
        this.name = name;
        this.monthlySalary = monthlySalary;
    }

    @Override
    public int taxableIncome() {
        return monthlySalary;
    }

    @Override
    public int amountDue() {
        return monthlySalary - tax();
    }

    @Override
    public String payee() {
        return "Employee " + name;
    }
}

class Invoice implements Payable {
    private final String supplier;
    private final String item;
    private final int quantity;
    private final int unitPrice;

    Invoice(String supplier, String item, int quantity, int unitPrice) {
        this.supplier = supplier;
        this.item = item;
        this.quantity = quantity;
        this.unitPrice = unitPrice;
    }

    @Override
    public int amountDue() {
        return quantity * unitPrice;
    }

    @Override
    public String payee() {
        return "Invoice " + supplier;
    }

    @Override
    public String paymentLine() {
        return String.format("%-22s %s for %d x %s", payee(),
                Payable.formatTk(amountDue()), quantity, item);
    }
}

public class AccountsOffice {
    public static void main(String[] args) {
        Employee ayesha = new Employee("Ayesha", 40000);
        Employee karim = new Employee("Karim", 32000);
        Invoice paper = new Invoice("Print House", "paper ream", 20, 450);

        ArrayList<Payable> payables = new ArrayList<>();
        payables.add(ayesha);
        payables.add(paper);
        payables.add(karim);

        ArrayList<Taxable> taxables = new ArrayList<>();
        taxables.add(ayesha);
        taxables.add(karim);

        int totalDue = 0;
        for (Payable p : payables) {
            System.out.println(p.paymentLine());
            totalDue += p.amountDue();
        }
        int totalTax = 0;
        for (Taxable t : taxables) {
            totalTax += t.tax();
        }
        System.out.println("Total to pay: " + Payable.formatTk(totalDue));
        System.out.println("Tax withheld: " + Payable.formatTk(totalTax));
    }
}
```

**Output:**

```text
Employee Ayesha        38000 Tk
Invoice Print House    9000 Tk for 20 x paper ream
Employee Karim         30400 Tk
Total to pay: 77400 Tk
Tax withheld: 3600 Tk
```

**Why it works:** The first loop sees only `Payable` references. For the employees
the inherited default `paymentLine()` runs; for the invoice its own override runs.
`Employee.amountDue()` calls `tax()`, a default method it got from `Taxable`, which
uses the interface constant `TAX_PERCENT`. `Payable.formatTk` is a static interface
method, so it is called with the interface name. The object `ayesha` sits in both
lists at once: it is a `Payable` *and* a `Taxable`.

### Example 7: Replacing a Type Check Chain

**Problem:** The library charges late fines that depend on the member type. Students
pay 5 Tk per day after 2 free days, faculty pay 2 Tk per day after 7 free days and
guests pay 10 Tk per day from the first day. Read the members and the days late,
print each fine and the total.

A first attempt often looks like this fragment:

```java
int fine;
if (type.equals("S")) {
    fine = Math.max(0, daysLate - 2) * 5;
} else if (type.equals("F")) {
    fine = Math.max(0, daysLate - 7) * 2;
} else {
    fine = daysLate * 10;
}
```

It works, but the rules of each member type are scattered, and a chain like this
tends to be copied wherever the type matters (borrowing limits, loan periods ...).

Design: an abstract class `Member` keeps the one shared rule (`fine`), and each
subclass supplies its own numbers by overriding `finePerDay()` and `graceDays()`.
Later the library added alumni members (3 Tk per day after 3 free days): that took
one new class and one line in the factory method `create`.

```java
import java.util.Scanner;

abstract class Member {
    private final String name;

    Member(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    abstract String kind();

    abstract int finePerDay();

    abstract int graceDays();

    int fine(int daysLate) {
        int charged = daysLate - graceDays();
        if (charged <= 0) {
            return 0;
        }
        return charged * finePerDay();
    }

    static Member create(String code, String name) {
        switch (code) {
            case "S":
                return new StudentMember(name);
            case "F":
                return new FacultyMember(name);
            case "A":
                return new AlumniMember(name);
            default:
                return new GuestMember(name);
        }
    }
}

class StudentMember extends Member {
    StudentMember(String name) {
        super(name);
    }

    @Override
    String kind() {
        return "Student";
    }

    @Override
    int finePerDay() {
        return 5;
    }

    @Override
    int graceDays() {
        return 2;
    }
}

class FacultyMember extends Member {
    FacultyMember(String name) {
        super(name);
    }

    @Override
    String kind() {
        return "Faculty";
    }

    @Override
    int finePerDay() {
        return 2;
    }

    @Override
    int graceDays() {
        return 7;
    }
}

class GuestMember extends Member {
    GuestMember(String name) {
        super(name);
    }

    @Override
    String kind() {
        return "Guest";
    }

    @Override
    int finePerDay() {
        return 10;
    }

    @Override
    int graceDays() {
        return 0;
    }
}

class AlumniMember extends Member {
    AlumniMember(String name) {
        super(name);
    }

    @Override
    String kind() {
        return "Alumni";
    }

    @Override
    int finePerDay() {
        return 3;
    }

    @Override
    int graceDays() {
        return 3;
    }
}

public class LibraryFines {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int total = 0;
        for (int i = 0; i < n; i++) {
            String code = in.next();
            String name = in.next();
            int days = in.nextInt();
            Member m = Member.create(code, name);
            int fine = m.fine(days);
            System.out.printf("%-8s %-8s %2d days late -> %3d Tk%n",
                    m.kind(), m.getName(), days, fine);
            total += fine;
        }
        System.out.println("Total fines: " + total + " Tk");
    }
}
```

**Input:**

```text
4
S Nusrat 5
F Arif 10
G Imran 3
A Farhana 6
```

**Output:**

```text
Student  Nusrat    5 days late ->  15 Tk
Faculty  Arif     10 days late ->   6 Tk
Guest    Imran     3 days late ->  30 Tk
Alumni   Farhana   6 days late ->   9 Tk
Total fines: 60 Tk
```

**Why it works:** The shared formula lives once, in `Member.fine()`, and asks the
object for its own numbers through dynamic dispatch. The only place that looks at the
type code is the factory method `create`, which turns input text into objects.
Everything after that works with a `Member` reference and would keep working
unchanged if a fifth member type were added.

## Common Mistakes

- **Forgetting `public` when implementing an interface method.** Interface methods are
  public, so `int amountDue() { ... }` in the class is a compile error ("attempting to
  assign weaker access privileges"). Write `public int amountDue()`.
- **Overloading when you meant to override.** `boolean equals(Student other)` does not
  override `equals(Object)`; it adds an overload that dynamic dispatch never uses.
  Always write `@Override` so the compiler catches this.
- **Calling a subclass-only method through a superclass reference.** `Animal a = new
  Dog("Tommy"); a.fetch();` does not compile. Test with `instanceof` first, or move the
  method into the superclass if every subclass needs it.
- **Downcasting without checking.** `(Dog) a` compiles even when `a` refers to a
  `Fish`, and then throws `ClassCastException` at run time.
- **Trying to instantiate an abstract class or an interface.** `new Shape("x")` and
  `new Payable()` are compile errors. Create an object of a concrete subclass or an
  implementing class.
- **Expecting static methods or fields to be polymorphic.** They are chosen by the
  declared type at compile time. Make the method an instance method if it should
  depend on the object.
- **Using `instanceof` chains instead of overriding.** If every branch does "the same
  job in a different way", that job belongs in an overridden method.
- **Forgetting to implement every abstract method.** The compiler reports "is not
  abstract and does not override abstract method ...". Implement it, or declare the
  class `abstract`.

## Summary

- Polymorphism means one interface, many forms: the same call does different things
  for different objects.
- Overloading (methods and constructors) is compile-time polymorphism; the compiler
  chooses by the declared types of the arguments.
- Overriding plus superclass (or interface) references give runtime polymorphism; the
  JVM chooses by the actual class of the object (dynamic method dispatch).
- Java has no `virtual` keyword: non-static, non-private, non-final instance methods
  are dynamically dispatched by default. C++ opts in with `virtual`; Java opts out
  with `final`.
- Upcasting is implicit and safe; downcasting is explicit and can throw
  `ClassCastException`, so check with `instanceof` (or its pattern form) first.
- Static methods and fields are hidden, not overridden; private and final methods
  cannot be overridden.
- An abstract class cannot be instantiated; it shares fields and code and leaves
  abstract methods for subclasses to fill in.
- An interface is a contract; a class can implement many interfaces, and unrelated
  classes can be handled through one interface type. Interfaces may have `default`
  and `static` methods.
- Use an abstract class for "is a kind of" with shared code, an interface for a
  "can do" role.
- Replace `if (type == ...)` chains with overridden methods, so new types mean new
  classes instead of edits to tested code.
