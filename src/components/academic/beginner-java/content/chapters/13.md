# Chapter 13: Generic Programming

Since Chapter 08 you have written `ArrayList<Student>` and been told the `<Student>`
part would be explained later. This chapter explains it. Generic programming lets you
write one class or one method that works with many types, while the compiler still
checks that every value has the right type. The result is code that is reusable,
needs no casts and fails at compile time instead of in front of your users.

**In this chapter you will learn:**

- why containers built on `Object` are unsafe, and how generics fix that
- how to write generic classes (`Box<T>`, `Pair<K, V>`) and generic methods
- type parameter naming conventions and multiple type parameters
- bounded type parameters (`<T extends Comparable<T>>`, `<T extends Number>`)
- wildcards at an introductory level: `?`, `? extends`, `? super`
- the generic collections: `List`, `ArrayList`, `Set`, `Map`, `HashMap`, `TreeMap`
- autoboxing: why you write `List<Integer>` and not `List<int>`
- ordering objects with `Comparable<T>` and `Comparator<T>`
- type erasure, and how Java generics differ from C++ templates

## 1. Concept Explanation

### The problem: one container for every type

Suppose you want a small class that holds one item. You want it for names, for marks,
for `Student` objects, for anything. Before generics (Java 1.4 and earlier),
programmers wrote such a class with the type `Object`, because every class in Java
extends `Object`:

```java
class ObjectBox {
    private Object item;

    void put(Object item) {
        this.item = item;
    }

    Object get() {
        return item;
    }
}
```

It works for every type, but it has two problems:

1. **Casts everywhere.** `get()` returns `Object`, so you must write
   `String name = (String) box.get();` each time.
2. **No type checking.** The compiler lets you `put(42)` into a box that you meant
   for names. The mistake is discovered only when the program runs and the cast fails
   with a `ClassCastException`.

```text
  ObjectBox box                         what the compiler knows
  +----------------+
  | item: Object   |  <-- put("Rahim")   "it is some Object"
  |                |  <-- put(42)       "still some Object, fine"
  +----------------+
          |
          v  (String) box.get()          checked only at RUN time
     ClassCastException if it holds 42
```

A bug found by the compiler costs you a minute. A bug found at runtime may cost you
a crashed program during a demo. Generics move this check to compile time.

### What generics are

A **generic class** has a **type parameter**: a placeholder name for a type, written
in angle brackets after the class name. When you use the class, you supply a
**type argument**, the actual type.

```java
class Box<T> {          // T is the type parameter
    private T item;

    void put(T item) {
        this.item = item;
    }

    T get() {
        return item;
    }
}

Box<String> names = new Box<String>();   // String is the type argument
```

You already know this idea from methods. A method parameter is a placeholder for a
*value* that the caller supplies. A type parameter is a placeholder for a *type* that
the user of the class supplies.

```text
                    Box<T>   (one class, written once)
                      |
        +-------------+--------------+
        |             |              |
        v             v              v
   Box<String>   Box<Integer>   Box<Student>
   put(String)   put(Integer)   put(Student)
   String get()  Integer get()  Student get()
```

For `Box<String>`, the compiler treats every `T` as `String`. Now `names.put(42)` is
a compile error, and `String s = names.get();` needs no cast. That is **type safety**:
the compiler guarantees that a `Box<String>` only ever contains strings.

### Type parameter naming conventions

Type parameters are usually single capital letters, so you can tell them apart from
real class names at a glance.

| Name | Usual meaning | Example |
|---|---|---|
| `T` | Type (any type) | `Box<T>` |
| `E` | Element of a collection | `List<E>`, `Stack<E>` |
| `K` | Key of a map | `Map<K, V>` |
| `V` | Value of a map | `Map<K, V>` |
| `N` | Number | `<N extends Number>` |
| `R` | Result type | `Converter<T, R>` |
| `S`, `U` | Second, third types | `Pair<T, U>` |

These are conventions, not rules. `Box<Thing>` compiles, but readers would think
`Thing` is a real class, so do not do that.

### Generic classes and generic methods

There are two places where you can declare type parameters:

- **On a class** (`class Box<T>`): the type parameter is available in every instance
  field and instance method of the class. Each object has its type fixed when it is
  created (`new Box<String>()`).
- **On a method** (`static <T> void printAll(List<T> items)`): the type parameter is
  available only inside that method. It is fixed separately for each call, usually
  by the compiler looking at the arguments (this is called **type inference**).

A class can also have several type parameters, separated by commas:
`class Pair<K, V>` holds a key of one type and a value of another type.

### Generic collections

The collection classes in `java.util` are all generic. You have used `ArrayList<E>`.
Here are the most useful ones, as interfaces (what they promise) and classes (how they
store the data):

| Interface | Meaning | Common classes | Order when you loop |
|---|---|---|---|
| `List<E>` | ordered sequence, duplicates allowed, index access | `ArrayList<E>` | insertion order |
| `Set<E>` | no duplicates | `HashSet<E>` | no fixed order |
| | | `LinkedHashSet<E>` | insertion order |
| | | `TreeSet<E>` | sorted order |
| `Map<K, V>` | key to value lookup, keys unique | `HashMap<K, V>` | no fixed order |
| | | `LinkedHashMap<K, V>` | insertion order |
| | | `TreeMap<K, V>` | sorted by key |

Good practice is to declare variables with the interface type and create objects of
a concrete class:

```java
List<String> names = new ArrayList<>();
Map<String, Integer> stock = new TreeMap<>();
Set<String> courses = new TreeSet<>();
```

Code that uses `names` only knows it is a `List`. If you later switch to another
`List` class, only one line changes. This is the "program to an interface" idea from
Chapter 10.

`HashMap` and `HashSet` are the fastest for lookups, but their loop order depends on
hash codes and can look random. When you print a map or a set, use `TreeMap`/`TreeSet`
(sorted) or `LinkedHashMap`/`LinkedHashSet` (insertion order) so the output is
predictable.

### Autoboxing: `int` vs `Integer`

Type arguments must be **reference types** (class or interface types). Primitive types
like `int` and `double` are not allowed: `List<int>` does not compile. For each
primitive type, Java has a **wrapper class** whose objects hold one primitive value.

| Primitive | Wrapper | Primitive | Wrapper |
|---|---|---|---|
| `int` | `Integer` | `double` | `Double` |
| `long` | `Long` | `float` | `Float` |
| `char` | `Character` | `boolean` | `Boolean` |
| `byte` | `Byte` | `short` | `Short` |

The compiler converts between them automatically:

- **Autoboxing**: `int` to `Integer` when an object is needed (`marks.add(85);`).
- **Unboxing**: `Integer` to `int` when a primitive is needed (`int m = marks.get(0);`).

```java
List<Integer> marks = new ArrayList<>();
marks.add(85);              // autoboxing: 85 becomes an Integer object
int first = marks.get(0);   // unboxing: Integer back to int
int total = first + marks.get(0);   // unboxing inside arithmetic
```

Three traps come with wrappers:

- `==` on two `Integer` objects compares **references**, not values. It may seem to
  work for small numbers (Java caches the `Integer` objects from -128 to 127) and then
  fail for larger ones. Use `a.equals(b)` or unbox first.
- Unboxing `null` throws `NullPointerException`. `int n = map.get("x");` crashes when
  the key is missing, because `get` returns `null`.
- `List<Integer>` has two `remove` methods: `remove(int index)` and
  `remove(Object value)`. `list.remove(3)` removes the element **at index 3**. To
  remove the value 3, write `list.remove(Integer.valueOf(3))`.

### Bounded type parameters

Inside `class Box<T>`, Java knows nothing about `T` except that it is some object.
You can call only `Object` methods (`toString`, `equals`, `hashCode`) on a `T`.

Sometimes you need more. To find the largest element, you must compare elements. A
**bound** restricts which types are allowed, and in return lets you use the methods of
the bound:

```java
<T extends Comparable<T>>   // T must be comparable to other T values
<T extends Number>          // T must be Integer, Double, Long, ...
```

In a bound, `extends` means "is a subtype of", both for classes and for interfaces.
With `<T extends Number>` you may call `doubleValue()` on a `T`. With
`<T extends Comparable<T>>` you may call `compareTo`. Trying to use the method with a
type that does not satisfy the bound is a compile error.

### Wildcards: `?`, `? extends`, `? super`

First, a surprising fact. `Integer` is a subtype of `Number`, but
`List<Integer>` is **not** a subtype of `List<Number>`:

```text
   Number          List<Number>
     ^                  X       not related!
     |
   Integer         List<Integer>
```

If it were allowed, this would happen:

```java
List<Integer> ints = new ArrayList<>();
List<Number> nums = ints;   // compile error (imagine it compiled...)
nums.add(2.5);              // ...a Double inside a list of Integers!
```

So a method `double total(List<Number> values)` cannot accept a `List<Integer>`.
A **wildcard** `?` means "some type that I do not name". It makes methods more
flexible:

| Wildcard | Read as | Accepts | You can safely |
|---|---|---|---|
| `List<?>` | list of some unknown type | any `List` | read elements as `Object` |
| `List<? extends Number>` | list of `Number` or a subtype | `List<Integer>`, `List<Double>`, `List<Number>` | read elements as `Number` |
| `List<? super Integer>` | list of `Integer` or a supertype | `List<Integer>`, `List<Number>`, `List<Object>` | add `Integer` values |

A short rule to remember, called **PECS**: *Producer Extends, Consumer Super*. If a
list produces values for you to read, use `? extends`; if it consumes values you
write into it, use `? super`.

You will mostly *use* wildcards in method parameters. You do not need them for
variables or for creating objects.

### Ordering objects: `Comparable<T>` and `Comparator<T>`

To sort a `List<Student>`, Java must know how to compare two students. There are two
ways:

| | `Comparable<T>` | `Comparator<T>` |
|---|---|---|
| Package | `java.lang` | `java.util` |
| Method | `int compareTo(T other)` | `int compare(T a, T b)` |
| Who implements it | the class itself (`Student`) | a separate class |
| How many orders | one, the **natural order** | as many as you like |
| Used by | `Collections.sort(list)`, `TreeSet`, `TreeMap` | `list.sort(cmp)`, `new TreeSet<>(cmp)` |

Both methods return a negative number if the first object comes first, zero if they
are equal in this order, and a positive number if the first comes after. `String`,
`Integer` and `Double` already implement `Comparable`, so you can compare names with
`a.compareTo(b)` and numbers with `Integer.compare(x, y)` or `Double.compare(x, y)`.

Do not compare by subtraction (`return a.marks - b.marks;`). For very large or very
negative values the subtraction overflows and gives the wrong sign.

### Type erasure

Generics exist for the compiler. When you compile, `javac` checks every type argument,
inserts the needed casts for you, and then **erases** the type arguments. In the
bytecode, `Box<String>` and `Box<Integer>` are the same class `Box`, and `T` has become
`Object` (or its bound, for example `Comparable`).

```text
  Your source              After compiling (simplified)
  ---------------------    ------------------------------
  Box<String> b = ...;     Box b = ...;
  String s = b.get();      String s = (String) b.get();
                           (the cast is inserted by javac
                            and is always safe)
```

Because the type argument is gone at runtime, a few things are impossible:

- `new T()` (the JVM would not know which class to create)
- `new T[10]` (an array must know its element type at runtime); use an
  `ArrayList<T>` instead
- `obj instanceof Box<String>` when `obj` is an `Object` (test `obj instanceof Box<?>`
  instead)
- primitive type arguments like `Box<int>`

**Raw types**: writing a generic class name without any type argument is a leftover
from code written before Java 5. It switches off the type checks and makes the compiler
print warnings. Never write it. Always give a type argument, or use the diamond `<>`.

### C++ templates vs Java generics

C++ has a feature for the same goal, called **templates**. The idea is similar, but
the mechanism is very different.

| | C++ templates | Java generics |
|---|---|---|
| How it works | the compiler generates separate code for each type used | one compiled class for all types; type arguments are checked, then erased |
| Primitive types | allowed as type arguments | not allowed; use wrappers (`Integer`) |
| At runtime | each instantiation is a different type | `List<String>` and `List<Integer>` share one runtime class |
| Requirements on the type | checked when the template is used with a type | declared up front with bounds (`extends`) |
| Creating a `T` | possible | `new T()` is not allowed |
| Values as parameters | allowed (sizes, constants) | only types can be parameters |

> **Coming from C++?** Do not call Java generics "templates". There is no code
> generation per type in Java: one `ArrayList` class serves every element type.

## 2. Syntax

### Declaring a generic class

```java
class Box<T> {
    private T item;

    void put(T item) {
        this.item = item;
    }

    T get() {
        return item;
    }

    boolean isEmpty() {
        return item == null;
    }
}
```

- `<T>` after the class name declares the type parameter.
- Inside the class, `T` is used like any type: field type, parameter type, return type.
- The constructor is written without `<T>`: `Box() { ... }`, not `Box<T>() { ... }`.

### Creating objects and the diamond `<>`

```java
Box<String> nameBox = new Box<String>();   // full form
Box<String> cityBox = new Box<>();         // diamond: compiler infers String
```

The empty angle brackets `<>` are called the **diamond**. The compiler copies the type
argument from the left side. Do not leave out the brackets completely: that would be a
raw type.

### Multiple type parameters

```java
class Pair<K, V> {
    private final K key;
    private final V value;

    Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    K getKey() {
        return key;
    }

    V getValue() {
        return value;
    }
}

Pair<String, Integer> credits = new Pair<>("CSE 1115", 3);
String course = credits.getKey();
int c = credits.getValue();          // unboxing
```

### Generic methods

```java
static <T> void printAll(List<T> items) {
    for (T item : items) {
        System.out.println(item);
    }
}

printAll(names);                     // T inferred as String
printAll(marks);                     // T inferred as Integer
Main.<String>printAll(names);        // explicit type argument (rarely needed)
```

The `<T>` goes **before the return type**. It declares a type parameter that belongs
to this one method. A generic method can live in a normal (non-generic) class, and it
can be `static` or an instance method.

### Bounded type parameters

```java
static <T extends Comparable<T>> T maxOf(List<T> items) {
    T best = items.get(0);
    for (T item : items) {
        if (item.compareTo(best) > 0) {   // allowed because of the bound
            best = item;
        }
    }
    return best;
}

class Stats<N extends Number> {
    private final List<N> values = new ArrayList<>();

    void add(N value) {
        values.add(value);
    }

    double average() {
        double sum = 0;
        for (N v : values) {
            sum += v.doubleValue();       // a Number method
        }
        return sum / values.size();
    }
}
```

`Stats<Integer>` and `Stats<Double>` are fine. `Stats<String>` is a compile error,
because `String` is not a `Number`.

### Wildcards

```java
static double total(List<? extends Number> values) {   // read as Number
    double sum = 0;
    for (Number n : values) {
        sum += n.doubleValue();
    }
    return sum;
}

static void addRollNumbers(List<? super Integer> target) {   // write Integers
    for (int i = 1; i <= 3; i++) {
        target.add(i);
    }
}

static int countItems(List<?> items) {   // any list; only size/Object use
    return items.size();
}
```

Inside `total` you cannot `add` to `values` (the compiler does not know whether it is
a list of `Integer` or of `Double`). Inside `addRollNumbers`, reading gives you only
`Object`. That is exactly the PECS rule.

### Implementing `Comparable<T>`

```java
class Student implements Comparable<Student> {
    private final int id;
    // other fields, constructor, getters ...

    @Override
    public int compareTo(Student other) {
        return Integer.compare(this.id, other.id);   // natural order: by id
    }
}

Collections.sort(students);   // uses compareTo
```

Note the type argument: `Comparable<Student>`, so the parameter is a `Student` and no
cast is needed.

### Writing a `Comparator<T>`

```java
class ByName implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        return a.getName().compareTo(b.getName());
    }
}

students.sort(new ByName());
```

`Comparator` has only one abstract method, `compare`. An interface with exactly one
abstract method is called a **functional interface**. For such interfaces Java 8 added
a shorter form called a **lambda expression**:

```java
students.sort((a, b) -> a.getName().compareTo(b.getName()));
```

Read it as: "a function that takes `a` and `b` and returns
`a.getName().compareTo(b.getName())`". The compiler sees that `sort` expects a
`Comparator<Student>`, so it knows `a` and `b` are `Student` objects, and it creates
the comparator object for you. A named class is clearer when the comparison is long or
reused; a lambda is handy for a one-line comparison.

### Common map operations

```java
Map<String, Integer> count = new TreeMap<>();
count.put("apple", 1);                          // add or replace
int n = count.getOrDefault("mango", 0);         // 0 if the key is missing
count.put("apple", count.get("apple") + 1);     // update an existing value
boolean has = count.containsKey("apple");

for (Map.Entry<String, Integer> e : count.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}
```

`Map.Entry<K, V>` is a key-value pair from the map. Looping over `entrySet()` visits
every pair; with a `TreeMap` the keys come in sorted order.

### What you cannot write

```java nocompile
class Factory<T> {
    T make() {
        return new T();            // error: T is erased at runtime
    }

    T[] makeArray() {
        return new T[10];          // error: generic array creation
    }
}

List<int> numbers = new ArrayList<>();   // error: primitive type argument
```

> In a real project each public class lives in its own file; here we keep each

### Example 1: From an Object Box to a Generic Box

**Problem:** Show the problem with an `Object`-based container, then solve it with a
generic `Box<T>`. Store a name and some marks, and show that the generic version needs
no casts and that both `Box<String>` and `Box<Integer>` are the same class at runtime.

The `ObjectBox` accepts anything, so a wrong `put` is only caught when the cast fails.
The program catches the `ClassCastException` (Chapter 11) so it can finish normally.
The generic `Box<T>` makes the compiler do the checking.

```java
class ObjectBox {
    private Object item;

    void put(Object item) {
        this.item = item;
    }

    Object get() {
        return item;
    }
}

class Box<T> {
    private T item;

    void put(T item) {
        this.item = item;
    }

    T get() {
        return item;
    }

    boolean isEmpty() {
        return item == null;
    }
}

public class BoxComparison {
    public static void main(String[] args) {
        ObjectBox oldBox = new ObjectBox();
        oldBox.put("Rahim");
        String name = (String) oldBox.get();      // cast needed
        System.out.println("Object box gave: " + name);

        oldBox.put(42);                            // compiler accepts anything
        try {
            String wrong = (String) oldBox.get();  // fails only at runtime
            System.out.println("Never printed: " + wrong);
        } catch (ClassCastException e) {
            System.out.println("Object box: ClassCastException at runtime");
        }

        Box<String> nameBox = new Box<>();
        System.out.println("Name box empty? " + nameBox.isEmpty());
        nameBox.put("Nusrat");
        String safeName = nameBox.get();           // no cast
        System.out.println("Generic box gave: " + safeName);
        // nameBox.put(42);   would be a COMPILE error: int is not a String

        Box<Integer> marksBox = new Box<>();
        marksBox.put(87);                          // autoboxing
        int marks = marksBox.get();                // unboxing
        System.out.println("Marks plus bonus: " + (marks + 5));

        boolean sameClass = nameBox.getClass() == marksBox.getClass();
        System.out.println("Same runtime class? " + sameClass);
        System.out.println("Runtime class name: " + marksBox.getClass().getName());
    }
}
```

**Output:**

```text
Object box gave: Rahim
Object box: ClassCastException at runtime
Name box empty? true
Generic box gave: Nusrat
Marks plus bonus: 92
Same runtime class? true
Runtime class name: Box
```

**Why it works:** `Box<String>` makes the compiler replace `T` with `String`
everywhere, so `get()` returns a `String` and a wrong `put` cannot compile. The last
two lines show type erasure: at runtime both boxes are plain `Box` objects, because the
type arguments were checked and then erased by the compiler.

### Example 2: A Pair Class and Generic Methods

**Problem:** Write a generic `Pair<K, V>` with a `swap()` method, and three generic
methods: `join` (turns any list into one line of text), `maxOf` (largest element,
for any comparable type) and `countMatches` (how often a value appears). Use them with
a list of student names and a list of marks.

- `Pair<K, V>` has two type parameters; `swap()` returns a `Pair<V, K>`, with the
  types in the other order.
- `maxOf` needs `compareTo`, so its type parameter is bounded by `Comparable<T>`.
- `countMatches` only needs `equals`, which every object has, so `<T>` is enough.

```java
import java.util.ArrayList;
import java.util.List;

class Pair<K, V> {
    private final K key;
    private final V value;

    Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    K getKey() {
        return key;
    }

    V getValue() {
        return value;
    }

    Pair<V, K> swap() {
        return new Pair<>(value, key);
    }

    @Override
    public String toString() {
        return "(" + key + ", " + value + ")";
    }
}

public class GenericMethodsDemo {
    static <T> String join(List<T> items) {
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < items.size(); i++) {
            if (i > 0) {
                sb.append(", ");
            }
            sb.append(items.get(i));
        }
        return sb.toString();
    }

    static <T extends Comparable<T>> T maxOf(List<T> items) {
        T best = items.get(0);
        for (T item : items) {
            if (item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }

    static <T> int countMatches(List<T> items, T target) {
        int count = 0;
        for (T item : items) {
            if (item.equals(target)) {
                count++;
            }
        }
        return count;
    }

    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("Rafi");
        names.add("Ayesha");
        names.add("Tanvir");
        names.add("Mitu");

        List<Integer> marks = new ArrayList<>();
        marks.add(72);
        marks.add(91);
        marks.add(65);
        marks.add(91);

        System.out.println("Names: " + join(names));
        System.out.println("Marks: " + join(marks));
        System.out.println("Last name alphabetically: " + maxOf(names));
        System.out.println("Highest mark: " + maxOf(marks));
        System.out.println("How many got 91: " + countMatches(marks, 91));

        Pair<String, Integer> course = new Pair<>("CSE 1115", 3);
        Pair<Integer, String> swapped = course.swap();
        System.out.println("Pair: " + course + ", swapped: " + swapped);
        int credits = course.getValue();
        System.out.println(course.getKey() + " has " + credits + " credits");
    }
}
```

**Output:**

```text
Names: Rafi, Ayesha, Tanvir, Mitu
Marks: 72, 91, 65, 91
Last name alphabetically: Tanvir
Highest mark: 91
How many got 91: 2
Pair: (CSE 1115, 3), swapped: (3, CSE 1115)
CSE 1115 has 3 credits
```

**Why it works:** For `maxOf(names)` the compiler infers `T = String`, checks that
`String` implements `Comparable<String>`, and allows `compareTo`. For `maxOf(marks)` it
infers `T = Integer`. In `countMatches(marks, 91)` the `91` is autoboxed to an
`Integer` so it matches `T`. One method body serves both lists, and the compiler still
checks the types at every call.

### Example 3: A Generic Stack for Undo and Reversal

**Problem:** Build a generic `Stack<E>` (last in, first out) with `push`, `pop`,
`peek`, `isEmpty` and `size`. Use one `Stack<String>` as the undo history of a small
text editor and one `Stack<Integer>` to print shuttle stop numbers in reverse order.

Arrays of `E` cannot be created (`new E[10]` is not allowed because of erasure), so the
stack stores its elements in an `ArrayList<E>`. The top of the stack is the end of the
list, so `push` and `pop` are fast. Popping an empty stack is a programming error, so
it throws an `IllegalStateException` (Chapter 11); the caller checks `isEmpty()` first.

```java
import java.util.ArrayList;
import java.util.List;

class Stack<E> {
    private final List<E> items = new ArrayList<>();

    void push(E item) {
        items.add(item);
    }

    E pop() {
        if (items.isEmpty()) {
            throw new IllegalStateException("pop on an empty stack");
        }
        return items.remove(items.size() - 1);
    }

    E peek() {
        if (items.isEmpty()) {
            throw new IllegalStateException("peek on an empty stack");
        }
        return items.get(items.size() - 1);
    }

    boolean isEmpty() {
        return items.isEmpty();
    }

    int size() {
        return items.size();
    }
}

public class StackDemo {
    public static void main(String[] args) {
        Stack<String> history = new Stack<>();
        history.push("type 'Hello'");
        history.push("make bold");
        history.push("delete word");
        System.out.println("Actions done: " + history.size());
        System.out.println("Last action: " + history.peek());

        System.out.println("Undo: " + history.pop());
        System.out.println("Undo: " + history.pop());
        System.out.println("Actions left: " + history.size());

        Stack<Integer> stops = new Stack<>();
        for (int stop = 1; stop <= 5; stop++) {
            stops.push(stop * 10);                 // autoboxing
        }
        StringBuilder back = new StringBuilder("Return trip:");
        while (!stops.isEmpty()) {
            int stop = stops.pop();                // unboxing
            back.append(" ").append(stop);
        }
        System.out.println(back);
    }
}
```

**Output:**

```text
Actions done: 3
Last action: delete word
Undo: delete word
Undo: make bold
Actions left: 1
Return trip: 50 40 30 20 10
```

**Why it works:** The `Stack<E>` code is written once. `Stack<String>` and
`Stack<Integer>` each get full type checking: `history.pop()` returns a `String`, and
`stops.pop()` returns an `Integer` that is unboxed to `int`. Using `ArrayList<E>`
inside avoids the generic array problem completely. (Java also has a class
`java.util.Stack`; we wrote our own to see how a generic class is built.)

### Example 4: Counting Words with Maps and Sets

**Problem:** Read one line of text. Print how many times each word appears, in
alphabetical order, ignoring case and punctuation. Then print the distinct words in the
order they first appeared.

- A `Map<String, Integer>` maps each word to its count. A `TreeMap` keeps keys sorted,
  so the report is alphabetical.
- `getOrDefault(word, 0)` returns the current count, or 0 for a new word.
- A `LinkedHashSet<String>` ignores duplicates and remembers insertion order.

```java
import java.util.LinkedHashSet;
import java.util.Map;
import java.util.Scanner;
import java.util.Set;
import java.util.TreeMap;

public class WordCount {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        String line = in.nextLine();

        Map<String, Integer> counts = new TreeMap<>();
        Set<String> firstSeen = new LinkedHashSet<>();

        String[] parts = line.toLowerCase().split(" ");
        for (String part : parts) {
            String word = part.replaceAll("[^a-z]", "");   // keep letters only
            if (word.isEmpty()) {
                continue;
            }
            counts.put(word, counts.getOrDefault(word, 0) + 1);
            firstSeen.add(word);
        }

        System.out.println("Word counts:");
        for (Map.Entry<String, Integer> entry : counts.entrySet()) {
            System.out.printf("%-6s %d%n", entry.getKey(), entry.getValue());
        }
        System.out.println("Distinct words: " + counts.size());
        System.out.println("In order of first use: " + firstSeen);
    }
}
```

**Input:**

```text
The bus is late. The canteen is open, and the bus is full!
```

**Output:**

```text
Word counts:
and    1
bus    2
canteen 1
full   1
is     3
late   1
open   1
the    3
Distinct words: 8
In order of first use: [the, bus, is, late, canteen, open, and, full]
```

**Why it works:** `counts.getOrDefault(word, 0) + 1` unboxes the stored `Integer`,
adds one, and `put` autoboxes the result back. Because `counts` is a `TreeMap`, the
loop over `entrySet()` visits keys in sorted order. With a `HashMap` the counts would be
the same but the printing order would not be predictable. `firstSeen.add` does nothing
for a word that is already in the set, and printing a `LinkedHashSet` shows its
elements in insertion order.

### Example 5: Sorting Students with Comparable and Comparator

**Problem:** Store a few students (ID, name, CGPA) in a list. Print them sorted by ID
(the natural order), then by CGPA from highest to lowest (ties by name), then by name.

- `Student implements Comparable<Student>`: the natural order is by ID, so
  `Collections.sort(list)` needs no extra argument.
- `ByCgpaDescending implements Comparator<Student>`: a second order, written as a
  named class because it has a tie-break rule.
- The name order is a one-line comparison, so it is passed as a lambda.

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.List;

class Student implements Comparable<Student> {
    private final int id;
    private final String name;
    private final double cgpa;

    Student(int id, String name, double cgpa) {
        this.id = id;
        this.name = name;
        this.cgpa = cgpa;
    }

    int getId() {
        return id;
    }

    String getName() {
        return name;
    }

    double getCgpa() {
        return cgpa;
    }

    @Override
    public int compareTo(Student other) {
        return Integer.compare(id, other.id);
    }

    @Override
    public String toString() {
        return String.format("%d %-7s %.2f", id, name, cgpa);
    }
}

class ByCgpaDescending implements Comparator<Student> {
    @Override
    public int compare(Student a, Student b) {
        int byCgpa = Double.compare(b.getCgpa(), a.getCgpa());   // b first: descending
        if (byCgpa != 0) {
            return byCgpa;
        }
        return a.getName().compareTo(b.getName());
    }
}

public class StudentSorting {
    static void printAll(String title, List<Student> list) {
        System.out.println(title);
        for (Student s : list) {
            System.out.println("  " + s);
        }
    }

    public static void main(String[] args) {
        List<Student> students = new ArrayList<>();
        students.add(new Student(1103, "Sadia", 3.75));
        students.add(new Student(1101, "Karim", 3.40));
        students.add(new Student(1104, "Arif", 3.75));
        students.add(new Student(1102, "Farhana", 3.92));

        Collections.sort(students);
        printAll("By ID:", students);

        students.sort(new ByCgpaDescending());
        printAll("By CGPA (high to low):", students);

        students.sort((a, b) -> a.getName().compareTo(b.getName()));
        printAll("By name:", students);
    }
}
```

**Output:**

```text
By ID:
  1101 Karim   3.40
  1102 Farhana 3.92
  1103 Sadia   3.75
  1104 Arif    3.75
By CGPA (high to low):
  1102 Farhana 3.92
  1104 Arif    3.75
  1103 Sadia   3.75
  1101 Karim   3.40
By name:
  1104 Arif    3.75
  1102 Farhana 3.92
  1101 Karim   3.40
  1103 Sadia   3.75
```

**Why it works:** `Collections.sort` requires a list whose element type implements
`Comparable`; the bound in its declaration guarantees this at compile time. `list.sort`
takes any `Comparator<Student>`, whether a named class object or a lambda. Swapping
`a` and `b` in `Double.compare(b.getCgpa(), a.getCgpa())` reverses the order, and the
tie-break on name makes the result fully predictable when two CGPAs are equal.

### Example 6: Wildcards and Bounded Statistics

**Problem:** Write methods that work with lists of different number types: `total`
reads from any list of numbers, `addRollNumbers` writes `Integer` values into a list
that can hold them, and `describe` reports the size of any list. Also write a bounded
generic class `Stats<N extends Number>` that computes an average and a maximum.

```java
import java.util.ArrayList;
import java.util.List;

class Stats<N extends Number> {
    private final List<N> values = new ArrayList<>();

    void add(N value) {
        values.add(value);
    }

    double average() {
        double sum = 0;
        for (N v : values) {
            sum += v.doubleValue();
        }
        return sum / values.size();
    }

    N largest() {
        N best = values.get(0);
        for (N v : values) {
            if (v.doubleValue() > best.doubleValue()) {
                best = v;
            }
        }
        return best;
    }
}

public class WildcardDemo {
    // Producer: we only READ numbers from the list -> ? extends
    static double total(List<? extends Number> values) {
        double sum = 0;
        for (Number n : values) {
            sum += n.doubleValue();
        }
        return sum;
    }

    // Consumer: we only WRITE Integers into the list -> ? super
    static void addRollNumbers(List<? super Integer> target, int count) {
        for (int i = 1; i <= count; i++) {
            target.add(i);
        }
    }

    // Any list at all: we only use methods that do not depend on the type
    static String describe(List<?> items) {
        return items.size() + " item(s): " + items;
    }

    public static void main(String[] args) {
        List<Integer> credits = new ArrayList<>();
        credits.add(3);
        credits.add(3);
        credits.add(1);

        List<Double> fees = new ArrayList<>();
        fees.add(1500.50);
        fees.add(820.25);

        System.out.printf("Total credits: %.1f%n", total(credits));
        System.out.printf("Total fees: %.2f Tk%n", total(fees));

        List<Number> numbers = new ArrayList<>();
        List<Object> things = new ArrayList<>();
        things.add("seat");
        addRollNumbers(numbers, 3);
        addRollNumbers(things, 2);
        System.out.println(describe(numbers));
        System.out.println(describe(things));

        Stats<Integer> quiz = new Stats<>();
        quiz.add(8);
        quiz.add(10);
        quiz.add(7);
        System.out.printf("Quiz average: %.2f, best: %d%n", quiz.average(), quiz.largest());

        Stats<Double> temps = new Stats<>();
        temps.add(31.5);
        temps.add(29.0);
        System.out.printf("Temp average: %.2f, highest: %.1f%n",
                temps.average(), temps.largest());
    }
}
```

**Output:**

```text
Total credits: 7.0
Total fees: 2320.75 Tk
3 item(s): [1, 2, 3]
3 item(s): [seat, 1, 2]
Quiz average: 8.33, best: 10
Temp average: 30.25, highest: 31.5
```

**Why it works:** `total` accepts both `List<Integer>` and `List<Double>` because of
`? extends Number`, and it reads each element as a `Number`. `addRollNumbers` accepts
`List<Number>` and `List<Object>` because both can hold an `Integer`. `Stats<N extends
Number>` can call `doubleValue()` on its elements because of the bound, and
`largest()` returns an `N`, so `quiz.largest()` is an `Integer` (printed with `%d`) and
`temps.largest()` is a `Double` (printed with `%.1f`).

## Common Mistakes

- **Using a primitive as a type argument.** `List<int>` does not compile. Write
  `List<Integer>` and let autoboxing convert values.
- **Leaving out the type argument.** A generic class name with no `<...>` is a raw
  type: it turns off type checking and causes warnings. Use `new ArrayList<>()`.
- **Comparing wrappers with `==`.** `Integer a = 1000, b = 1000; a == b` is `false`.
  Use `a.equals(b)`, or compare `int` values.
- **Unboxing a missing map value.** `int n = map.get(key);` throws
  `NullPointerException` when the key is absent. Use `getOrDefault(key, 0)` or check
  `containsKey` first.
- **Calling `remove(3)` on a `List<Integer>` to remove the value 3.** It removes the
  element at index 3. Use `remove(Integer.valueOf(3))`.
- **Expecting `List<Integer>` to be a `List<Number>`.** It is not. Use
  `List<? extends Number>` in the method parameter.
- **Trying `new T()` or `new T[n]`.** Not allowed because of type erasure. Store
  elements in an `ArrayList<T>`, or ask the caller to pass in the object.
- **Comparator by subtraction.** `return a.getMarks() - b.getMarks();` can overflow.
  Use `Integer.compare` and `Double.compare`.
- **Printing a `HashMap` or `HashSet` and expecting an order.** Use `TreeMap`,
  `TreeSet`, `LinkedHashMap` or `LinkedHashSet` when order matters.
- **Implementing `Comparable` without the type argument.** Write
  `implements Comparable<Student>`, so `compareTo` takes a `Student` and needs no cast.

## Summary

- Generics let one class or method work with many types while the compiler checks
  every use. They replace unsafe `Object` containers and remove casts.
- A type parameter (`T`, `E`, `K`, `V`) is declared in angle brackets after a class
  name (`class Box<T>`) or before a method's return type (`static <T> void m(...)`).
- A class may have several type parameters (`Pair<K, V>`); `new Pair<>(...)` uses the
  diamond to infer them.
- Bounds such as `<T extends Comparable<T>>` and `<N extends Number>` limit the
  allowed types and let you call the bound's methods.
- Wildcards make methods flexible: `? extends T` to read (producer), `? super T` to
  write (consumer), `?` when the type does not matter.
- The generic collections `List`, `Set` and `Map` with `ArrayList`, `HashSet`,
  `TreeSet`, `HashMap`, `TreeMap` and the `Linked...` versions cover most needs.
  Use the sorted or linked ones when printing order matters.
- Type arguments must be reference types; autoboxing converts between `int` and
  `Integer`. Compare wrappers with `equals`, and beware of unboxing `null`.
- `Comparable<T>` gives a class its natural order; `Comparator<T>` objects (named
  classes or lambdas) give any number of extra orders.
- Type erasure: generic types are checked at compile time and erased at runtime, so
  `new T()`, `new T[]` and `obj instanceof List<String>` (for an `Object obj`) are not
  possible. Never use raw
  types.
- C++ templates generate code per type; Java generics compile to one class and erase
  the type arguments.
