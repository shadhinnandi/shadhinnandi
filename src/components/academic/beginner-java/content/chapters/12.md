# Chapter 12: Object-Oriented I/O

Until now every program forgot everything when it ended: the students you added, the
balances you updated and the marks you typed were gone. Real programs keep data in
**files** so the next run can continue where the last one stopped. In this chapter you
learn how Java reads and writes files, and why its I/O library is a classic example of
object-oriented design: small objects that you wrap around each other.

**In this chapter you will learn:**

- the stream idea: data flows from a source, through your program, to a destination
- byte streams (`InputStream`, `OutputStream`) vs character streams (`Reader`, `Writer`)
- why buffering matters (`BufferedReader`, `BufferedWriter`)
- how to write text with `FileWriter`, `BufferedWriter` and `PrintWriter`
- how to read text with `BufferedReader` and with `Scanner`
- the `File` class (and a short look at the modern `java.nio.file` API)
- the decorator design: wrapping one stream object inside another
- closing files safely with try-with-resources and handling `IOException`
- parsing CSV lines with `split`
- serialization: saving whole objects with `ObjectOutputStream` and `ObjectInputStream`,
  `Serializable`, `transient` and `serialVersionUID`
- when to choose text files, binary files or object files

## 1. Concept Explanation

### Why programs need files

Variables and objects live in RAM. RAM is fast, but it is cleared when the program
ends. A file lives on the disk (or SSD) and survives after the program ends and even
after the computer is switched off. This property is called **persistence**.

Typical reasons to use files:

- **Save and load data:** a student list, a shop's inventory, a game save.
- **Process data made by someone else:** a CSV export of marks from a spreadsheet.
- **Produce reports:** a result sheet that can be printed or emailed.
- **Keep a log:** a record of every login or transaction, added line by line.

> **Coming from C?** In C you used `FILE *`, `fopen`, `fprintf`, `fgets` and `fclose`.
> Java uses objects instead: you create a reader or writer object, send it messages
> such as `readLine()` or `println()`, and close it. The ideas are the same; the
> packaging is object-oriented.

### The stream idea

Java models input and output as a **stream**: an ordered flow of data that you read
from one end or write to one end, one piece after another. You do not jump around;
you read the next piece, then the next.

```text
   INPUT STREAM                         OUTPUT STREAM

 +-----------+   data   +---------+   data   +-------------+
 |  source   | -------> | program | -------> | destination |
 | file,     |          |         |          | file,       |
 | keyboard, |          |         |          | screen,     |
 | network   |          |         |          | network     |
 +-----------+          +---------+          +-------------+
```

You have used streams since Chapter 00: `System.in` is an input stream connected to
the keyboard and `System.out` is an output stream connected to the screen. A file is
just another source or destination. Your program talks to a stream object, and the
stream object deals with the operating system.

### Byte streams and character streams

Everything in a file is stored as **bytes** (8-bit values). Java offers two families
of stream classes:

| | Byte streams | Character streams |
|---|---|---|
| Unit of data | `byte` (8 bits) | `char` (16-bit UTF-16 unit) |
| Abstract base classes | `InputStream`, `OutputStream` | `Reader`, `Writer` |
| File classes | `FileInputStream`, `FileOutputStream` | `FileReader`, `FileWriter` |
| Use for | images, audio, any binary data, exact copies | text: `.txt`, `.csv`, logs |

A character stream is a byte stream plus a translator. When you read text, the bytes
in the file are **decoded** into characters using a **character encoding** (a rule
such as UTF-8 that maps characters to bytes). When you write text, characters are
encoded back into bytes. For text, use character streams so Java does this for you.
For anything that is not text, use byte streams so no translation changes your data.

```text
             InputStream (abstract)            Reader (abstract)
              /         \                     /        |        \
 FileInputStream  ObjectInputStream   FileReader  BufferedReader ...
     ...

             OutputStream (abstract)           Writer (abstract)
              /         \                     /        |        \
 FileOutputStream ObjectOutputStream  FileWriter  BufferedWriter  PrintWriter
```

Notice the OOP design: `InputStream`, `OutputStream`, `Reader` and `Writer` are
**abstract classes** (Chapter 10). Code written against `Reader` works with any
concrete reader. That is polymorphism applied to I/O.

### Buffering and why it matters

Asking the operating system for data is slow compared with work done in memory. A
`FileReader` on its own may go to the operating system for small amounts of data
again and again. A **buffer** is a block of memory (8192 characters by default) that is
filled in one large read; your program then takes characters from memory.

```text
 without buffer:  program --read 1 char--> OS --> disk   (many slow trips)

 with buffer:     program --read--> [ buffer: 8192 chars ] --refill--> OS
                            fast, from memory        rare, large reads
```

Writing works the same way in reverse: a `BufferedWriter` collects characters and
sends them to the file in large blocks. Buffering also gives you useful methods:
`BufferedReader.readLine()` reads a whole line, and `BufferedWriter.newLine()` writes
the correct line separator for the operating system.

Because a buffered writer keeps data in memory, the data reaches the file only when
the buffer is **flushed**. Closing a writer flushes it. Forgetting to close a writer is
the classic reason for an empty output file.

### The decorator idea: wrapping streams

Look at this common line:

```java
BufferedReader reader = new BufferedReader(new FileReader("students.txt"));
```

There are two objects here. The `FileReader` knows how to read characters from a file.
The `BufferedReader` knows nothing about files: it takes *any* `Reader` and adds a
buffer and `readLine()`. This design is called the **decorator** (or wrapper) pattern.

```text
     your code
         |
         v   readLine()
 +------------------------------+
 | BufferedReader               |   adds: buffer, readLine()
 |   +------------------------+ |
 |   | FileReader             | |   adds: bytes -> chars from a file
 |   |   +------------------+ | |
 |   |   | the file on disk | | |
 |   |   +------------------+ | |
 |   +------------------------+ |
 +------------------------------+
```

Why is this good object-oriented design?

- **Each class has one job.** File access, buffering, formatting and object conversion
  are separate classes.
- **Mix and match.** Any feature can be combined with any source. A `BufferedReader`
  can wrap a `FileReader`, an `InputStreamReader` around `System.in`, or a reader of a
  network connection.
- **Is-a and has-a together.** `BufferedReader` *is a* `Reader` (it extends `Reader`)
  and *has a* `Reader` (the one it wraps). So a wrapped stream can be wrapped again,
  and code that expects a `Reader` accepts any of them.

Without decorators, Java would need a separate class for every combination:
`BufferedFileReader`, `BufferedNetworkReader`, `PrintingBufferedFileWriter`, and so on.
Wrapping avoids that explosion of classes.

When you close the outermost wrapper, it closes the object it wraps, which closes the
next one, down to the file. So you only close the outer object.

### Closing files: try-with-resources

An open file is a **resource** owned by the operating system. A program can only keep a
limited number of files open, and written data may stay in a buffer until the file is
closed. Memory is reclaimed by the garbage collector, but the garbage collector does
not close files at a predictable time (Chapter 06). You must close them yourself.

The safe way is **try-with-resources** (Chapters 06 and 11): every object declared in
the parentheses after `try` is closed automatically when the block ends, whether it
ends normally or because of an exception. All stream classes implement
`AutoCloseable`, so they work with it.

```java
try (BufferedReader reader = new BufferedReader(new FileReader("notes.txt"))) {
    System.out.println(reader.readLine());
}   // reader.close() runs here automatically
```

### Exceptions in I/O

Files are outside your program's control. A file may be missing, read-protected, or
the disk may be full. Java reports these problems with **checked exceptions**
(Chapter 11), so the compiler forces you to handle or declare them.

```text
              Exception
                  |
             IOException             (checked: general I/O failure)
          /       |         \
 FileNotFoundException  EOFException  ObjectStreamException ...
 (file cannot be      (end of data   (serialization problems,
  opened)              reached early) e.g. InvalidClassException)
```

- `FileNotFoundException` is thrown when a file cannot be opened: it does not exist
  (for reading) or cannot be created (for writing).
- `IOException` covers every other I/O failure. Because `FileNotFoundException` is a
  subclass, a single `catch (IOException e)` handles both. If you want a special
  message for a missing file, catch `FileNotFoundException` first (specific first).

### The `File` class

`java.io.File` represents a **path name**, not the contents of a file. Creating a
`File` object does not create or open anything on the disk. It answers questions and
performs simple operations:

| Method | Meaning |
|---|---|
| `exists()` | is there a file or folder with this name? |
| `isFile()` / `isDirectory()` | which kind is it? |
| `getName()` | the last part of the path, e.g. `marks.csv` |
| `length()` | size in bytes (0 if it does not exist) |
| `delete()` | deletes it; returns `true` on success |

A relative name such as `"students.txt"` is looked up in the program's **current
working directory**: the folder you were in when you typed `java`. All programs in
this chapter use relative names.

> **Note:** Since Java 7 there is a newer API in `java.nio.file`: `Path`, `Paths` and
> the helper class `Files` (`Files.readAllLines`, `Files.exists`, `Files.size`,
> `Files.copy`). Modern code often uses it. This chapter uses the classic `java.io`
> classes because they show the stream and decorator design clearly, and everything
> you learn here carries over.

### Text, binary and object files: which one?

| Format | How you write it | Pros | Cons |
|---|---|---|---|
| Text (`.txt`, `.csv`) | `PrintWriter`, `BufferedWriter` | readable in any editor; other programs and spreadsheets can use it | you must design the format and parse it back |
| Binary (raw bytes) | `FileOutputStream` | exact, compact; needed for images and audio | not human-readable |
| Object (serialized) | `ObjectOutputStream` | saves whole objects with one call | Java-only; breaks when classes change; never load untrusted files |

A good rule for this course: use **text** (often CSV) for data that people or other
programs read, **byte streams** for copying or processing non-text files, and
**serialization** for quickly saving and restoring your own program's objects.

### CSV files

**CSV** means *comma-separated values*. Each line is one record and commas separate
the fields. The first line is often a header with the field names.

```text
id,name,cgpa
1001,Nusrat Jahan,3.85
1002,Karim Uddin,3.10
```

To read a CSV line, split it at the commas with `line.split(",")` and convert each
piece with `Integer.parseInt` or `Double.parseDouble`. Real data contains mistakes
(missing fields, letters where numbers belong), so a careful program checks the
number of fields and catches `NumberFormatException`. Simple `split` cannot handle a
comma *inside* a field (like `"Dhaka, Bangladesh"`); real CSV libraries handle quoted
fields. In this chapter the data never contains commas inside fields.

### Serialization: saving objects

**Serialization** turns an object (and every object it refers to) into a sequence of
bytes. **Deserialization** builds an equal object from those bytes later, maybe in a
different run of the program.

```text
 +----------------------+  writeObject   +------------------+
 | Roster object        | -------------> | roster.ser       |
 |  list -> [Student,   |                | AC ED 00 05 ...  |
 |           Student]   | <------------- | (binary bytes)   |
 +----------------------+   readObject   +------------------+
```

The rules:

- A class must implement `java.io.Serializable` to be serialized. `Serializable` has
  no methods: it is a **marker interface** that says "objects of this class may be
  saved". Otherwise `writeObject` throws `NotSerializableException`.
- Every object reachable through non-`transient` fields is saved too, so those
  objects must also be serializable. `String`, wrapper classes and `ArrayList` already
  are.
- A field marked **`transient`** is skipped. After loading it has its default value
  (`0`, `false`, `null`). Use it for passwords, caches and values that can be
  recomputed.
- `static` fields belong to the class, not the object, so they are not saved.
- During deserialization the constructor of a `Serializable` class does **not** run;
  the fields are filled directly from the saved bytes.
- **`serialVersionUID`** is a version number for the class. When reading, Java
  compares the number stored in the file with the number in the current class. If
  they differ, it throws `InvalidClassException` instead of loading wrong data. If
  you do not declare it, Java computes one from the class details, and almost any edit
  changes it. Declare it yourself in every serializable class:
  `private static final long serialVersionUID = 1L;`

> **Security note:** deserializing a file means letting the file decide which objects
> are created. Only load serialized files that your own program wrote.

### Should this be a class?

Once a program saves data, ask: *who knows the file format?* If `main` contains the
`split` calls, the `PrintWriter` and the parsing rules all mixed together, every change
to the format touches everything. A better design gives that job to one class:

- the **model class** (`Student`) knows how to turn itself into a line
  (`toCsvLine()`) and how to be built from one (`fromCsvLine(...)`);
- a **store class** (`StudentFile`) knows the file name and has `save(list)` and
  `load()` methods;
- `main` only asks: "load the students", "save the students".

The rest of the program does not care whether the data is stored as CSV, as
serialized objects or in a database. That is abstraction (Chapter 05) applied to I/O.

## 2. Syntax

All I/O classes in this chapter live in the package `java.io`. Import the ones you use,
for example `import java.io.BufferedReader;`, or all of them with `import java.io.*;`.
The programs in this chapter import each class by name so you can see where it comes
from.

### Writing text: `FileWriter` and `BufferedWriter`

```java
try (BufferedWriter writer = new BufferedWriter(new FileWriter("menu.txt"))) {
    writer.write("Khichuri 60");
    writer.newLine();                 // line separator for this OS
    writer.write("Singara 10");
    writer.newLine();
} catch (IOException e) {
    System.out.println("Could not write menu.txt: " + e.getMessage());
}
```

- `new FileWriter("menu.txt")` creates the file, or **erases** it if it exists.
- `new FileWriter("menu.txt", true)` opens it in **append mode**: new text goes at
  the end and the old content is kept.
- `write(String)` writes characters only; it does not add a line break.

### Writing text: `PrintWriter`

```java
try (PrintWriter out = new PrintWriter(new FileWriter("bill.txt"))) {
    out.println("Canteen bill");
    out.printf("%-10s %5d%n", "Tea", 15);
    out.printf("Total: %d Tk%n", 75);
}
```

`PrintWriter` gives files the same `print`, `println` and `printf` you know from
`System.out`. You can also write `new PrintWriter("bill.txt")`, which builds the
`FileWriter` (and a buffer) for you. Unlike other writers, `PrintWriter`'s print
methods do not throw `IOException`; they set an error flag that you can test with
`checkError()`. Creating it can still throw `FileNotFoundException`.

### Reading lines: `BufferedReader`

```java
try (BufferedReader reader = new BufferedReader(new FileReader("menu.txt"))) {
    String line = reader.readLine();
    while (line != null) {            // null means end of file
        System.out.println(line);
        line = reader.readLine();
    }
} catch (FileNotFoundException e) {
    System.out.println("menu.txt not found");
} catch (IOException e) {
    System.out.println("Read error: " + e.getMessage());
}
```

`readLine()` returns the next line **without** its line separator, or `null` at the
end of the file. An empty line is returned as `""`, not `null`. You will often see the
loop written in the shorter form `while ((line = reader.readLine()) != null)`, which
assigns and tests in one condition.

### Reading tokens: `Scanner` on a file

```java
try (Scanner in = new Scanner(new File("numbers.txt"))) {
    int sum = 0;
    while (in.hasNextInt()) {
        sum += in.nextInt();
    }
    System.out.println("Sum = " + sum);
} catch (FileNotFoundException e) {
    System.out.println("numbers.txt not found");
}
```

A `Scanner` built from a `File` works exactly like the keyboard `Scanner`:
`nextInt()`, `next()`, `nextLine()`, plus `hasNextInt()`, `hasNext()` and
`hasNextLine()` to check before reading. Note the argument: `new Scanner(new File(...))`
reads the file, but `new Scanner("numbers.txt")` would scan the *text*
`numbers.txt` itself. `Scanner` is convenient for numbers and words; `BufferedReader`
is faster for large files read line by line.

### Byte streams: `FileInputStream` and `FileOutputStream`

```java
try (FileInputStream in = new FileInputStream("photo.jpg");
     FileOutputStream out = new FileOutputStream("photo-copy.jpg")) {
    byte[] buffer = new byte[4096];
    int count = in.read(buffer);      // bytes read, or -1 at the end
    while (count != -1) {
        out.write(buffer, 0, count);  // write only the bytes we got
        count = in.read(buffer);
    }
}
```

- `read()` with no argument returns one byte as an `int` from 0 to 255, or `-1` at
  the end. It returns `int`, not `byte`, so that `-1` can mean "no more data".
- `read(buffer)` fills an array and returns how many bytes it read. The last read is
  usually shorter than the array, so always write `count` bytes, not `buffer.length`.
- `BufferedInputStream` and `BufferedOutputStream` add a buffer to byte streams, just
  as `BufferedReader` does for characters.
- Two resources in one `try`, separated by `;`, are closed in reverse order.

### Parsing a CSV line

```java
String line = "1001,Nusrat Jahan,3.85";
String[] parts = line.split(",");     // ["1001", "Nusrat Jahan", "3.85"]
if (parts.length == 3) {
    int id = Integer.parseInt(parts[0].trim());
    String name = parts[1].trim();
    double cgpa = Double.parseDouble(parts[2].trim());
}
```

`trim()` removes spaces around a field, so `1001, Nusrat Jahan` also works. Writing a
CSV line is the reverse: join the fields with commas, for example
`out.println(id + "," + name + "," + cgpa);`.

### Serialization: a serializable class

```java
class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    private final int id;
    private final String name;
    private transient String loginPin;     // not saved

    Student(int id, String name, String loginPin) { ... }
}
```

### Serialization: writing and reading objects

```java
// write
try (ObjectOutputStream out =
         new ObjectOutputStream(new FileOutputStream("student.ser"))) {
    out.writeObject(student);
}

// read
try (ObjectInputStream in =
         new ObjectInputStream(new FileInputStream("student.ser"))) {
    Student loaded = (Student) in.readObject();
} catch (IOException | ClassNotFoundException e) {
    System.out.println("Could not load: " + e.getMessage());
}
```

- `ObjectOutputStream` decorates a byte stream: it turns objects into bytes and passes
  them to the `FileOutputStream`.
- `readObject()` returns an `Object`, so you downcast it (Chapter 10) to the type you
  wrote. It throws `ClassNotFoundException` if the class of the saved object is not
  available, plus the usual `IOException`.
- Read objects back in the same order you wrote them. `writeInt`, `writeDouble` and
  `writeUTF` (and the matching `readInt`, `readDouble`, `readUTF`) save simple values
  in the same stream.
- To save a list, either wrap it in your own serializable class (`Roster` with an
  `ArrayList<Student>` field) or write the count with `writeInt` followed by each
  object. Casting `readObject()` directly to `ArrayList<Student>` compiles only with an
  "unchecked" warning, because generic type information is not available at run time
  (Chapter 13 explains why).

## 3. Worked Examples

In a real project each public class lives in its own file; here we keep each program in
one file so you can compile it with one command. Each program reads and writes files in
the folder you run it from.

### Example 1: Word Count of a Text File

**Problem:** Count the lines, blank lines, words and characters (not counting line
separators) in `story.txt`, and show the longest line. If the file is missing, print a
friendly message instead of crashing.

Reading and counting are two different jobs, so they go into two places. The
`TextStats` class only counts: it receives one line at a time through `addLine` and
does not know that a file exists. `main` opens the file and feeds the lines to the
object. The same `TextStats` could count text typed on the keyboard.

```java
import java.io.BufferedReader;
import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.IOException;

class TextStats {
    private int lines;
    private int blankLines;
    private int words;
    private int characters;
    private String longestLine = "";

    void addLine(String line) {
        lines++;
        characters += line.length();
        String trimmed = line.trim();
        if (trimmed.isEmpty()) {
            blankLines++;
            return;
        }
        words += trimmed.split("\\s+").length;
        if (line.length() > longestLine.length()) {
            longestLine = line;
        }
    }

    void print() {
        System.out.println("Lines:       " + lines);
        System.out.println("Blank lines: " + blankLines);
        System.out.println("Words:       " + words);
        System.out.println("Characters:  " + characters);
        System.out.println("Longest:     " + longestLine);
    }
}

public class WordCount {
    public static void main(String[] args) {
        String fileName = "story.txt";
        TextStats stats = new TextStats();
        try (BufferedReader reader = new BufferedReader(new FileReader(fileName))) {
            String line;
            while ((line = reader.readLine()) != null) {
                stats.addLine(line);
            }
            stats.print();
        } catch (FileNotFoundException e) {
            System.out.println("Cannot open " + fileName);
        } catch (IOException e) {
            System.out.println("Error while reading: " + e.getMessage());
        }
    }
}
```

**Input file `story.txt`:**

```text
The campus shuttle leaves at eight.
Rahim missed it again today.

He walked to the library instead
and found a seat near the window.
```

**Output:**

```text
Lines:       5
Blank lines: 1
Words:       24
Characters:  128
Longest:     The campus shuttle leaves at eight.
```

**Why it works:** `split("\\s+")` splits a line at every run of whitespace (the
regular expression `\s+` means "one or more spaces or tabs"), so the number of pieces
is the number of words. Blank lines are skipped before splitting, because
`"".split("\\s+")` would give one empty piece. If `story.txt` did not exist, the
`FileReader` constructor would throw `FileNotFoundException`, the first `catch` would
print `Cannot open story.txt`, and the program would still end normally.

### Example 2: Copying a File with Byte Streams

**Problem:** Make a backup copy of `syllabus.txt` called `syllabus.bak`, byte by byte,
so the copy is identical whatever the file contains. Check first that the source
exists, then report how many bytes were copied and compare the two sizes.

Byte streams copy any file (text, image, PDF) without changing it, because they never
decode or encode characters. The `File` class answers the questions about existence
and size. The copying is a reusable static method that returns the number of bytes.

```java
import java.io.BufferedInputStream;
import java.io.BufferedOutputStream;
import java.io.File;
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class FileCopy {
    static long copy(String source, String target) throws IOException {
        long total = 0;
        try (BufferedInputStream in =
                 new BufferedInputStream(new FileInputStream(source));
             BufferedOutputStream out =
                 new BufferedOutputStream(new FileOutputStream(target))) {
            byte[] buffer = new byte[1024];
            int count = in.read(buffer);
            while (count != -1) {
                out.write(buffer, 0, count);
                total += count;
                count = in.read(buffer);
            }
        }
        return total;
    }

    public static void main(String[] args) {
        File source = new File("syllabus.txt");
        File target = new File("syllabus.bak");
        if (!source.exists()) {
            System.out.println(source.getName() + " does not exist");
            return;
        }
        try {
            long copied = copy(source.getName(), target.getName());
            System.out.println("Copied " + copied + " bytes");
            System.out.println(source.getName() + ": " + source.length() + " bytes");
            System.out.println(target.getName() + ": " + target.length() + " bytes");
            System.out.println("Same size: " + (source.length() == target.length()));
        } catch (IOException e) {
            System.out.println("Copy failed: " + e.getMessage());
        }
    }
}
```

**Input file `syllabus.txt`:**

```text
CSE 1115 Object Oriented Programming
Week 1: Classes and objects
Week 2: Encapsulation
```

**Output:**

```text
Copied 87 bytes
syllabus.txt: 87 bytes
syllabus.bak: 87 bytes
Same size: true
```

**Output file `syllabus.bak`:**

```text
CSE 1115 Object Oriented Programming
Week 1: Classes and objects
Week 2: Encapsulation
```

**Why it works:** The file has 84 visible characters and three line separators (`\n`,
one byte each), so 87 bytes. Each `read(buffer)` returns how many bytes it actually
got; writing exactly `count` bytes means the last, partly filled buffer does not add
garbage at the end. The two `Buffered...` wrappers are decorators: the copy loop would
work without them, but they reduce the number of trips to the operating system. Both
streams are closed (output first) when the try block ends, which also flushes the
output buffer to disk.

### Example 3: CSV Marks Report with Bad Lines

**Problem:** A teacher exported `marks.csv` (`id,name,marks` with a header line). Read
it, skip and report broken lines, and write a formatted `report.txt` with each
student's grade (A: 80+, B: 70+, C: 60+, D: 50+, else F) and the class average.

Design decisions:

- `Student` is a small model class. Its static method `fromCsv` turns one line into a
  `Student`, or throws a custom checked exception `BadRecordException` with a clear
  message. All parsing rules live in one place.
- `main` reads lines, collects good students in an `ArrayList`, prints a message for
  each bad line (with its line number) and then writes the report with `PrintWriter`.

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;
import java.io.PrintWriter;
import java.util.ArrayList;

class BadRecordException extends Exception {
    BadRecordException(String message) {
        super(message);
    }
}

class Student {
    private final int id;
    private final String name;
    private final int marks;

    Student(int id, String name, int marks) {
        this.id = id;
        this.name = name;
        this.marks = marks;
    }

    static Student fromCsv(String line) throws BadRecordException {
        String[] parts = line.split(",");
        if (parts.length != 3) {
            throw new BadRecordException("expected 3 fields, found " + parts.length);
        }
        try {
            int id = Integer.parseInt(parts[0].trim());
            int marks = Integer.parseInt(parts[2].trim());
            return new Student(id, parts[1].trim(), marks);
        } catch (NumberFormatException e) {
            throw new BadRecordException("id and marks must be whole numbers");
        }
    }

    int getMarks() {
        return marks;
    }

    char grade() {
        if (marks >= 80) {
            return 'A';
        } else if (marks >= 70) {
            return 'B';
        } else if (marks >= 60) {
            return 'C';
        } else if (marks >= 50) {
            return 'D';
        }
        return 'F';
    }

    String toReportLine() {
        return String.format("%-6d %-18s %5d  %c", id, name, marks, grade());
    }
}

public class MarksReport {
    public static void main(String[] args) {
        ArrayList<Student> students = new ArrayList<Student>();
        try (BufferedReader reader = new BufferedReader(new FileReader("marks.csv"))) {
            String line = reader.readLine();      // skip the header
            int lineNumber = 1;
            while ((line = reader.readLine()) != null) {
                lineNumber++;
                try {
                    students.add(Student.fromCsv(line));
                } catch (BadRecordException e) {
                    System.out.println("Line " + lineNumber + " skipped: "
                            + e.getMessage());
                }
            }
        } catch (IOException e) {
            System.out.println("Cannot read marks.csv: " + e.getMessage());
            return;
        }

        try (PrintWriter out = new PrintWriter("report.txt")) {
            out.println("ID     Name               Marks  Grade");
            int total = 0;
            for (Student s : students) {
                out.println(s.toReportLine());
                total += s.getMarks();
            }
            if (!students.isEmpty()) {
                out.printf("Average: %.2f%n", (double) total / students.size());
            }
        } catch (IOException e) {
            System.out.println("Cannot write report.txt: " + e.getMessage());
            return;
        }
        System.out.println("report.txt written with " + students.size() + " students");
    }
}
```

**Input file `marks.csv`:**

```text
id,name,marks
1001,Nusrat Jahan,88
1002,Karim Uddin,73
1003,Ayesha Siddiqua,abc
1004,Fahim Ahmed
1005,Sadia Islam,95
1006,Imran Hossain,58
```

**Output:**

```text
Line 4 skipped: id and marks must be whole numbers
Line 5 skipped: expected 3 fields, found 2
report.txt written with 4 students
```

**Output file `report.txt`:**

```text
ID     Name               Marks  Grade
1001   Nusrat Jahan          88  A
1002   Karim Uddin           73  B
1005   Sadia Islam           95  A
1006   Imran Hossain         58  D
Average: 78.50
```

**Why it works:** One broken line does not stop the whole report: the inner
`try`/`catch` handles a `BadRecordException` for that line only, and the loop goes on.
The outer `catch (IOException e)` handles problems with the file itself (for example,
a missing `marks.csv`). `fromCsv` converts the low-level `NumberFormatException` into
a message that makes sense to the teacher. Note that the first `readLine()` reads and
ignores the header.

### Example 4: An Append-Only Activity Log

**Problem:** The library's self-service kiosk keeps a log file, `activity.log`. Each
event must be **added** to the end of the file without erasing earlier events, even
across program runs. Write an `ActivityLog` class with a `record(user, action)` method
and show that old entries survive.

An append-only log is a common real-world file: nothing is ever rewritten, so a crash
can at most lose the line being written. The `ActivityLog` object hides the file name
and format; callers only call `record`. Each call opens the file in append mode
(`new FileWriter(name, true)`), writes one line and closes it, so every entry is on
disk as soon as `record` returns.

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.io.PrintWriter;

class ActivityLog {
    private final String fileName;
    private int entriesThisSession;

    ActivityLog(String fileName) {
        this.fileName = fileName;
    }

    void record(String user, String action) {
        try (PrintWriter out = new PrintWriter(new FileWriter(fileName, true))) {
            entriesThisSession++;
            out.printf("%-8s %s%n", user, action);
        } catch (IOException e) {
            System.out.println("Log failed: " + e.getMessage());
        }
    }

    int countAllEntries() throws IOException {
        int count = 0;
        try (BufferedReader reader = new BufferedReader(new FileReader(fileName))) {
            while (reader.readLine() != null) {
                count++;
            }
        }
        return count;
    }

    int getEntriesThisSession() {
        return entriesThisSession;
    }
}

public class KioskLog {
    public static void main(String[] args) {
        ActivityLog log = new ActivityLog("activity.log");
        log.record("Mitu", "borrowed 'Java Basics'");
        log.record("Arif", "returned 'Data Structures'");
        log.record("Mitu", "renewed 'Java Basics'");
        try {
            System.out.println("Added this session: " + log.getEntriesThisSession());
            System.out.println("Total entries in file: " + log.countAllEntries());
        } catch (IOException e) {
            System.out.println("Cannot read log: " + e.getMessage());
        }
    }
}
```

**Input file `activity.log`:**

```text
Farhana  borrowed 'Clean Code'
```

**Output:**

```text
Added this session: 3
Total entries in file: 4
```

**Output file `activity.log`:**

```text
Farhana  borrowed 'Clean Code'
Mitu     borrowed 'Java Basics'
Arif     returned 'Data Structures'
Mitu     renewed 'Java Basics'
```

**Why it works:** The second argument `true` of `FileWriter` selects append mode, so
the entry from an earlier run (Farhana's) stays at the top. If `activity.log` did not
exist yet, append mode would simply create it. Remove `true` and the file would hold
only the last line, because each `record` call would erase the file first. Opening and
closing the file for every entry is slower than keeping it open, but for a log that
receives a few lines it is the safest choice.

### Example 5: Saving Objects with Serialization

**Problem:** Save a roster of students (ID, name, CGPA) to `roster.ser` with
serialization and load it back into new objects. Each student also has a temporary
login PIN that must **not** be stored in the file.

Design:

- `Student` implements `Serializable` and declares `serialVersionUID`. The PIN is
  `transient`, so it is not written.
- `Roster` wraps the `ArrayList<Student>` and is itself serializable, so one
  `writeObject(roster)` saves the roster and every student in it, and one cast
  `(Roster) in.readObject()` brings them back without any unchecked warning.
- `RosterStore` knows the file name and the stream classes; `main` only calls
  `save` and `load`.

```java
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;
import java.util.ArrayList;

class Student implements Serializable {
    private static final long serialVersionUID = 1L;

    private final int id;
    private final String name;
    private final double cgpa;
    private transient String loginPin;

    Student(int id, String name, double cgpa, String loginPin) {
        this.id = id;
        this.name = name;
        this.cgpa = cgpa;
        this.loginPin = loginPin;
    }

    @Override
    public String toString() {
        return String.format("%d %-14s CGPA %.2f  PIN %s", id, name, cgpa, loginPin);
    }
}

class Roster implements Serializable {
    private static final long serialVersionUID = 1L;

    private final String section;
    private final ArrayList<Student> students = new ArrayList<Student>();

    Roster(String section) {
        this.section = section;
    }

    void add(Student s) {
        students.add(s);
    }

    void print() {
        System.out.println("Section " + section + " (" + students.size() + " students)");
        for (Student s : students) {
            System.out.println("  " + s);
        }
    }
}

class RosterStore {
    private final String fileName;

    RosterStore(String fileName) {
        this.fileName = fileName;
    }

    void save(Roster roster) throws IOException {
        try (ObjectOutputStream out =
                 new ObjectOutputStream(new FileOutputStream(fileName))) {
            out.writeObject(roster);
        }
    }

    Roster load() throws IOException, ClassNotFoundException {
        try (ObjectInputStream in =
                 new ObjectInputStream(new FileInputStream(fileName))) {
            return (Roster) in.readObject();
        }
    }
}

public class RosterSerialization {
    public static void main(String[] args) {
        Roster roster = new Roster("CSE-B");
        roster.add(new Student(1001, "Nusrat Jahan", 3.85, "4821"));
        roster.add(new Student(1002, "Tanvir Hasan", 3.42, "1937"));
        roster.add(new Student(1003, "Sadia Islam", 3.97, "7754"));
        System.out.println("Before saving:");
        roster.print();

        RosterStore store = new RosterStore("roster.ser");
        try {
            store.save(roster);
            Roster loaded = store.load();
            System.out.println("After loading:");
            loaded.print();
            System.out.println("Same object? " + (loaded == roster));
        } catch (IOException | ClassNotFoundException e) {
            System.out.println("Serialization failed: " + e.getMessage());
        }
    }
}
```

**Output:**

```text
Before saving:
Section CSE-B (3 students)
  1001 Nusrat Jahan   CGPA 3.85  PIN 4821
  1002 Tanvir Hasan   CGPA 3.42  PIN 1937
  1003 Sadia Islam    CGPA 3.97  PIN 7754
After loading:
Section CSE-B (3 students)
  1001 Nusrat Jahan   CGPA 3.85  PIN null
  1002 Tanvir Hasan   CGPA 3.42  PIN null
  1003 Sadia Islam    CGPA 3.97  PIN null
Same object? false
```

**Why it works:** `writeObject(roster)` follows every reference: the `Roster` refers to
an `ArrayList`, which refers to three `Student` objects, which refer to `String`
objects. All of them are serializable, so the whole graph is written. The transient
`loginPin` is skipped, and because no constructor runs during deserialization, it
comes back as the default value `null`. `loaded == roster` is `false`: reading creates
brand-new objects with equal contents. The `.ser` file is binary, so you cannot read it
in a text editor; to check it, the program loads it and prints the objects.

### Example 6: Writing Your Own Decorator

**Problem:** The help desk saves call notes to `calls.txt`. Phone numbers and PINs in
the notes must not be stored, so every digit must be replaced by `*` when it is
written. Build this as a **decorator**: a writer class that wraps another writer, so it
can be combined with `PrintWriter` and `FileWriter` like Java's own classes.

Java provides `FilterWriter`, an abstract class made for writing decorators: it
`is-a` `Writer`, stores the wrapped writer in a protected field `out`, and passes every
call to it. `MaskingWriter` extends it and overrides the three `write` methods so that
every character passes through `mask` first. It also counts how many digits it hid.

```java
import java.io.FileWriter;
import java.io.FilterWriter;
import java.io.IOException;
import java.io.PrintWriter;
import java.io.Writer;

class MaskingWriter extends FilterWriter {
    private int maskedCount;

    MaskingWriter(Writer target) {
        super(target);
    }

    private int mask(int c) {
        if (c >= '0' && c <= '9') {
            maskedCount++;
            return '*';
        }
        return c;
    }

    @Override
    public void write(int c) throws IOException {
        out.write(mask(c));
    }

    @Override
    public void write(char[] chars, int offset, int length) throws IOException {
        for (int i = offset; i < offset + length; i++) {
            write(chars[i]);
        }
    }

    @Override
    public void write(String text, int offset, int length) throws IOException {
        for (int i = offset; i < offset + length; i++) {
            write(text.charAt(i));
        }
    }

    int getMaskedCount() {
        return maskedCount;
    }
}

public class HelpDeskNotes {
    public static void main(String[] args) {
        try (MaskingWriter masker = new MaskingWriter(new FileWriter("calls.txt"));
             PrintWriter out = new PrintWriter(masker)) {
            out.println("Call 1: Rahim, phone 01711-223344, wallet PIN 5520");
            out.println("Call 2: Ayesha asked about room 402");
            out.printf("Total calls today: %d%n", 2);
            out.flush();
            System.out.println("Digits masked: " + masker.getMaskedCount());
        } catch (IOException e) {
            System.out.println("Cannot write calls.txt: " + e.getMessage());
        }
    }
}
```

**Output:**

```text
Digits masked: 21
```

**Output file `calls.txt`:**

```text
Call *: Rahim, phone *****-******, wallet PIN ****
Call *: Ayesha asked about room ***
Total calls today: *
```

**Why it works:** The chain is `PrintWriter` -> `MaskingWriter` -> `FileWriter` ->
file. `PrintWriter` formats the text and passes characters down; `MaskingWriter`
changes digits; `FileWriter` encodes characters into bytes. None of the three classes
knows about the others' jobs, and `MaskingWriter` can wrap *any* `Writer`. Because it
extends `Writer` (through `FilterWriter`), `PrintWriter` accepts it as an ordinary
writer: that is polymorphism. Both objects are declared as resources so that `main`
can keep a reference to `masker` and ask for its count. `flush()` pushes everything
`PrintWriter` holds down the chain before the count is read. At the end of the block
`out` is closed first, which closes the whole chain; closing `masker` again afterwards
does no harm.

## Common Mistakes

- **Forgetting to close a writer.** Data waits in the buffer and the file stays empty
  or incomplete. Use try-with-resources for every stream.
- **Erasing a file by accident.** `new FileWriter("log.txt")` and
  `new PrintWriter("log.txt")` truncate the file. Use `new FileWriter("log.txt", true)`
  to append.
- **Testing the end of file wrongly.** `readLine()` returns `null` at the end, not
  `""`; `read()` returns `-1`. Comparing a line with `""` stops at the first blank
  line.
- **Calling `readLine()` twice in one loop step**, for example once in the condition
  and again in the body. Every call consumes a line, so half the lines are skipped.
- **`new Scanner("data.txt")` instead of `new Scanner(new File("data.txt"))`.** The
  first one scans the file name as text and never opens the file.
- **Writing the whole buffer** with `out.write(buffer)` after `read(buffer)`. The last
  read usually fills only part of the array; write `count` bytes.
- **Using character streams for binary files.** Copying an image with
  `FileReader`/`FileWriter` decodes and re-encodes the bytes and can damage the file.
- **Catching `IOException` and doing nothing.** An empty `catch` hides the reason a
  file was not saved. At least print a clear message.
- **Expecting the wrong working directory.** A relative name like `"data.txt"` is
  looked up in the folder where `java` was started, not where the `.java` file is.
- **Serializing a class with a non-serializable field.** `writeObject` fails with
  `NotSerializableException`. Make that class `Serializable` too, or mark the field
  `transient`.
- **Omitting `serialVersionUID`.** A small change to the class then makes all old save
  files unreadable (`InvalidClassException`).

## Summary

- A stream is an ordered flow of data from a source or to a destination. Byte streams
  (`InputStream`/`OutputStream`) carry raw bytes; character streams (`Reader`/`Writer`)
  carry text and handle the encoding for you.
- Buffering (`BufferedReader`, `BufferedWriter`, `BufferedInputStream`) makes I/O fast
  by reading and writing in large blocks; `readLine()` and `newLine()` work with lines.
- `PrintWriter` brings `println` and `printf` to files; `Scanner` reads numbers and
  words from a `File`; `FileWriter(name, true)` appends instead of erasing.
- Java's I/O classes follow the decorator design: each class adds one feature and
  wraps another stream (`new BufferedReader(new FileReader(...))`). A wrapper is-a
  stream and has-a stream.
- Always close streams, preferably with try-with-resources, and handle the checked
  `IOException` (and its subclass `FileNotFoundException`) with clear messages.
- `File` describes a path: `exists()`, `length()`, `getName()`, `delete()`.
  `java.nio.file` (`Path`, `Files`) is the newer API.
- CSV lines are parsed with `split(",")`, `trim()` and `parseInt`/`parseDouble`;
  validate the number of fields and catch `NumberFormatException`.
- Serialization saves whole object graphs with `ObjectOutputStream.writeObject` and
  restores them with `ObjectInputStream.readObject` plus a cast. Classes must
  implement `Serializable`; `transient` fields are skipped; declare
  `private static final long serialVersionUID = 1L;`.
- Choose text files for data people or other programs read, byte streams for
  non-text data and exact copies, and serialization for your own program's objects.
- Good design keeps the file format in one class (a store or the model's
  `toCsvLine`/`fromCsvLine` methods), so the rest of the program does not depend on it.
