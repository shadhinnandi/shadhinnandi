# Chapter 03: Methods and Problem Solving

Up to now every program you wrote lived inside one long `main` method. That works for
ten lines, but a real program quickly becomes hard to read, hard to test and full of
repeated code. Methods let you split a program into small named pieces that each do
one job. This chapter also teaches a step-by-step way to solve problems and to find
bugs, and it answers a question that confuses many students: what exactly happens to
a variable when you pass it to a method?

**In this chapter you will learn:**

- why methods exist: decomposition, reuse and good names
- how to define `static` methods and call them from `main`
- parameters vs arguments, return values and `void` methods
- method overloading: one name, several parameter lists
- scope: where a variable can be used and how long it lives
- the call stack: what Java does when one method calls another
- recursion: base case, recursive case, tracing, and the cost of naive Fibonacci
- primitive values vs reference values (stack and heap)
- why Java is **always pass-by-value**, even when you pass an object
- a problem-solving method: understand, plan, dry run, code, test
- practical debugging: compiler errors, printing values, rubber-duck debugging

## 1. Concept Explanation

### Why methods?

Look at this part of a `main` method. It prints a report for two students:

```java
// inside main (fragment)
double avg1 = (78 + 85 + 62) / 3.0;
System.out.println("--------------------");
System.out.printf("Rahim: %.2f%n", avg1);
System.out.println("--------------------");
double avg2 = (91 + 88 + 95) / 3.0;
System.out.println("--------------------");
System.out.printf("Nusrat: %.2f%n", avg2);
System.out.println("--------------------");
```

The same steps appear twice. If you want 30 dashes instead of 20, you must change four
lines. If you have 60 students, the program becomes a wall of copied code.

A **method** is a named block of code inside a class. It can receive input values,
do some work and send back a result. Methods give you three things:

| Benefit | Meaning |
|---|---|
| Decomposition | Split a big problem into small problems, one method each. |
| Reuse | Write the code once, call it as many times as you need. |
| Naming | `average(a, b, c)` says *what* happens; the reader can skip *how*. |

A kitchen analogy helps. The canteen has a recipe called "make tea". The manager does
not explain every step each time; she just says "make tea for table 4". The recipe is
written once and used all day.

In Java the "recipe" is the method definition, and "make tea for table 4" is a
**method call**. The call jumps into the method, runs its statements, and comes back to
the exact place where it was called.

> **Coming from C?** A Java method is like a C function, but it must be written inside
> a class. Java needs no prototypes: a method can be called from code written above it.

### Anatomy of a method

```text
  static   double   average  (int a, int b, int c)   {  ...body...  }
 +------+ +------+ +-------+ +--------------------+  +--------------+
 modifier  return    name      parameter list         body: the
           type                (type + name each)     statements
```

- `static` means the method belongs to the class itself, so `main` (also `static`) can
  call it directly without creating an object. Chapter 07 explains `static` fully.
  You will often see `public static`; `public` is about access control (Chapter 05).
- The **return type** is the type of the value the method sends back. `void` means
  "sends nothing back".
- The **name** follows `camelCase` and is usually a verb or a question:
  `printLine`, `average`, `isLeapYear`.
- The **parameter list** declares the inputs. Each parameter has a type and a name.
- The method name plus the parameter types form the **signature**:
  `average(int, int, int)`. The compiler uses the signature to find the right method.

### Parameters and arguments

These two words are often mixed up, but they mean different things.

| Term | Where it appears | Example |
|---|---|---|
| Parameter | In the method header; a local variable of the method | `int a` in `average(int a, ...)` |
| Argument | In the call; the actual value given | `78` in `average(78, 85, 62)` |

When you call `average(78, 85, 62)`, Java first evaluates each argument, then copies
the values into the parameters in order: `a = 78`, `b = 85`, `c = 62`. The number of
arguments and their types must fit the parameter list. A narrower type is widened
automatically (an `int` argument fits a `double` parameter), but not the other way.

### Return values and `void`

A method with a non-`void` return type must end every path with `return <value>;`.
The `return` statement stops the method at once and hands the value to the caller.

```java
static double average(int a, int b, int c) {
    return (a + b + c) / 3.0;
}
```

The caller can store the result, print it, or use it inside a bigger expression:

```java
double avg = average(78, 85, 62);
System.out.printf("%.2f%n", average(91, 88, 95));
if (average(35, 42, 30) < 40) {
    System.out.println("Needs help");
}
```

A `void` method does its work (usually printing) and returns nothing. It may use a
plain `return;` to stop early. A `void` call is a statement on its own; it cannot be
used as a value.

Here is the report from the start of this section, rewritten with two methods:

```java
public class ReportWithMethods {
    static void printLine(int width) {
        for (int i = 0; i < width; i++) {
            System.out.print("-");
        }
        System.out.println();
    }

    static double average(int a, int b, int c) {
        return (a + b + c) / 3.0;
    }

    public static void main(String[] args) {
        printLine(20);
        System.out.printf("Rahim: %.2f%n", average(78, 85, 62));
        printLine(20);
        System.out.printf("Nusrat: %.2f%n", average(91, 88, 95));
        printLine(20);
    }
}
```

**Output:**

```text
--------------------
Rahim: 75.00
--------------------
Nusrat: 91.33
--------------------
```

Changing the width or the formula now means editing one place only.

### Method overloading

Java allows several methods with the **same name** in one class, as long as their
**parameter lists differ** (in the number of parameters, their types, or their order).
This is called **method overloading**. You have used it already: `System.out.println`
has versions for `int`, `double`, `String`, `char` and more.

```java
static int max(int a, int b) { ... }
static int max(int a, int b, int c) { ... }
static double max(double a, double b) { ... }
```

The compiler chooses the version at **compile time** by looking at the argument types:

| Call | Version chosen | Why |
|---|---|---|
| `max(3, 7)` | `max(int, int)` | exact match |
| `max(3, 7, 5)` | `max(int, int, int)` | three arguments |
| `max(2.5, 1.0)` | `max(double, double)` | exact match |
| `max(4, 2.5)` | `max(double, double)` | `4` is widened to `4.0` |

The return type alone is **not** enough. Two methods `int area(int side)` and
`double area(int side)` have the same signature, so the compiler rejects the second
one with "method area(int) is already defined".

### Scope and local variables

The **scope** of a variable is the part of the code where its name can be used.

- A variable declared inside a method is a **local variable**. It exists from its
  declaration to the closing `}` of the block that contains it.
- Parameters are local variables of their method. They are filled by the call.
- A variable declared in a loop header or loop body disappears when the loop ends.
- Two different methods can use the same name (`total`, `i`) without any conflict:
  each method has its own variables.

```java
static int sumTo(int n) {
    int total = 0;                 // scope: rest of sumTo
    for (int i = 1; i <= n; i++) { // i: only inside the loop
        total += i;
    }
    // i does not exist here
    return total;
}

// in main:
int total = sumTo(4);              // a different 'total', owned by main
// n and i of sumTo are not visible here
```

Two rules that differ from C:

- Local variables have no default value. Using one before assigning it is a compile
  error ("variable might not have been initialized").
- Inside one method you may not declare a local variable with the same name as another
  local variable that is still in scope, even in an inner block. Java reports
  "variable count is already defined".

### The call stack

How does Java remember where to come back after a method finishes? It uses the
**call stack**. Each time a method is called, Java pushes a new **stack frame** on top
of the stack. The frame holds that call's parameters, its local variables and the
place to return to. When the method returns, its frame is popped and the caller
continues.

Consider this program:

```java
public class CallStackDemo {
    static int discount(int amount) {
        return amount / 10;
    }

    static int finalPrice(int price, int qty) {
        int total = price * qty;
        int off = discount(total);
        return total - off;
    }

    public static void main(String[] args) {
        int bill = finalPrice(120, 3);
        System.out.println(bill);
    }
}
```

**Output:**

```text
324
```

At the moment `discount` is running, the stack looks like this (the top is the method
that is running right now):

```text
              +-----------------------------+
   top  --->  | discount                    |
              |   amount = 360              |
              +-----------------------------+
              | finalPrice                  |
              |   price = 120, qty = 3      |
              |   total = 360, off = ?      |
              +-----------------------------+
              | main                        |
              |   bill = ?                  |
              +-----------------------------+
```

Then the stack unwinds:

```text
 1. discount returns 36    -> its frame is removed
 2. finalPrice: off = 36, returns 324 -> its frame is removed
 3. main: bill = 324, prints 324
```

Each frame has its *own* variables. That is why two methods can both have a variable
called `total`, and why the same method can be running several times at once, which
is exactly what recursion needs.

### Recursion

A method is **recursive** when it calls itself. It solves a problem by solving a
smaller copy of the same problem. Every recursive method needs two parts:

- a **base case**: a small input answered directly, without another call;
- a **recursive case**: a call on a smaller input that moves toward the base case.

Factorial is the classic first example: `n! = n * (n - 1)!` and `0! = 1`.

```java
static long factorial(int n) {
    if (n == 0) {
        return 1;                    // base case
    }
    return n * factorial(n - 1);     // recursive case
}
```

**Tracing** `factorial(4)`: the calls go down until the base case, then the results
come back up.

```text
factorial(4)                       calls go DOWN
  = 4 * factorial(3)
          = 3 * factorial(2)
                  = 2 * factorial(1)
                          = 1 * factorial(0)
                                  = 1          <- base case
                          = 1 * 1 = 1          results come back UP
                  = 2 * 1 = 2
          = 3 * 2 = 6
  = 4 * 6 = 24
```

The same trace as stack frames, at the deepest point:

```text
   +----------------+
   | factorial n=0  |  <- base case, returns 1
   +----------------+
   | factorial n=1  |  waiting for factorial(0)
   +----------------+
   | factorial n=2  |  waiting for factorial(1)
   +----------------+
   | factorial n=3  |  waiting for factorial(2)
   +----------------+
   | factorial n=4  |  waiting for factorial(3)
   +----------------+
   | main           |
   +----------------+
```

More recursive definitions you will meet in the examples:

| Problem | Base case | Recursive case |
|---|---|---|
| `power(b, e)` = b to the e | `e == 0` gives 1 | `b * power(b, e - 1)` |
| `digitSum(n)` | `n < 10` gives `n` | `n % 10 + digitSum(n / 10)` |
| `gcd(a, b)` (Euclid) | `b == 0` gives `a` | `gcd(b, a % b)` |
| `fib(n)` | `n <= 1` gives `n` | `fib(n - 1) + fib(n - 2)` |

**The cost of naive Fibonacci.** `fib(n)` calls itself *twice*, and the two calls
repeat the same work. The call tree for `fib(5)` already has 15 calls:

```text
                         fib(5)
                /                    \
            fib(4)                  fib(3)
           /      \                /      \
       fib(3)    fib(2)        fib(2)    fib(1)
       /    \     /   \        /   \
   fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
   /   \
fib(1) fib(0)
```

`fib(3)` is computed twice and `fib(2)` three times. The number of calls grows about
1.6 times for every step of `n`: `fib(30)` makes 2,692,537 calls and `fib(40)` makes
more than 331 million. A simple loop computes the same numbers in `n - 1` steps.
Recursion is the right tool when the problem is naturally recursive (GCD, digit
processing, Tower of Hanoi, nested structures); it is the wrong tool when it repeats
the same work again and again.

**Missing base case.** If the recursion never reaches a base case, frames pile up
until the stack is full and the program crashes with `StackOverflowError`:

```java
static int countDown(int n) {
    System.out.println(n);
    return countDown(n - 1);   // no base case: never stops
}
```

### Primitive values and reference values

Before we can talk about passing values to methods, you need a clear picture of what a
variable holds. Java has two kinds of types:

- **Primitive types** (`int`, `double`, `char`, `boolean`, `long`, ...): the variable
  holds the value itself.
- **Reference types** (`String`, `StringBuilder`, `Scanner`, and every class): the
  variable holds a **reference**, a value that lets Java reach an object. The object
  itself lives in a memory area called the **heap**.

Local variables live in the stack frame of their method. So a useful picture is:

```java
int count = 42;
String name = "Nusrat";
StringBuilder note = new StringBuilder("Tk");
```

```text
   STACK (main's frame)                 HEAP
  +---------+---------+
  | count   |   42    |
  +---------+---------+          +-------------------+
  | name    |    o----+--------> | String "Nusrat"   |
  +---------+---------+          +-------------------+
  | note    |    o----+--------> | StringBuilder     |
  +---------+---------+          |   "Tk"            |
                                 +-------------------+
```

Assignment copies whatever is inside the variable's box:

- `int copy = count;` copies the number 42. Changing `copy` later does not touch
  `count`.
- `StringBuilder other = note;` copies the **reference**. Now two variables refer to
  the *same* object; a change made through `other` is visible through `note`.
  (Chapter 08 calls this *aliasing* and studies it in depth.)

A reference is not a raw memory address: Java has no address-of operator and no
pointer arithmetic. You can only use a reference to reach the object with `.`.

### Java is always pass-by-value

This is the single most important rule of this chapter:

> **Java is always pass-by-value.** When you call a method, each parameter receives a
> **copy** of the argument's value. For a primitive, the copy is the number (or
> `char`, or `boolean`). For an object, the copy is the **reference**. The object
> itself is never copied, and the caller's variable is never handed to the method.

Let us look at the three situations one by one.

**Case 1: a primitive argument.** The method gets its own copy of the number.

```java
static void addBonus(int marks) {
    marks = marks + 5;     // changes the copy only
}
// in main:
int marks = 70;
addBonus(marks);           // marks is still 70
```

```text
   main frame              addBonus frame
  +-------+------+        +-------+-------------+
  | marks |  70  |  copy  | marks |  70 -> 75   |
  +-------+------+  ---->  +-------+-------------+
   unchanged                 discarded on return
```

If you want the new value, **return** it: `marks = withBonus(marks);`.

**Case 2: a reference argument, and the method changes the object.**
`StringBuilder` is a mutable text object: `append` changes the object it is called on.

```java
static void addCourse(StringBuilder list, String code) {
    list.append(code);      // follows the copied reference to the SAME object
}
// in main:
StringBuilder courses = new StringBuilder("CSE 1111");
addCourse(courses, ", MATH 1151");   // courses is now "CSE 1111, MATH 1151"
```

```text
   main frame                          HEAP
  +---------+------+
  | courses |  o---+-----+
  +---------+------+     |      +------------------------------+
                         +----> | StringBuilder                |
   addCourse frame       |      | "CSE 1111" -> "CSE 1111,     |
  +---------+------+     |      |               MATH 1151"     |
  | list    |  o---+-----+      +------------------------------+
  +---------+------+
   two copies of one reference, one object
```

The caller sees the change, not because the variable was passed "by reference", but
because both copies of the reference lead to the same object.

**Case 3: a reference argument, and the method reassigns its parameter.**

```java
static void replaceList(StringBuilder list) {
    list = new StringBuilder("EEE 1001");   // the copy now points elsewhere
    list.append(", PHY 1101");              // changes the NEW object only
}
// in main:
replaceList(courses);    // courses still "CSE 1111, MATH 1151"
```

```text
   main frame                          HEAP
  +---------+------+            +------------------------------+
  | courses |  o---+----------> | "CSE 1111, MATH 1151"        |
  +---------+------+            +------------------------------+

   replaceList frame
  +---------+------+            +------------------------------+
  | list    |  o---+----------> | "EEE 1001, PHY 1101"  (new)  |
  +---------+------+            +------------------------------+
```

Reassigning `list` only changes the method's own copy of the reference. The caller's
variable `courses` still refers to the original object. This is the proof that Java
does not pass variables by reference: a method can never make the caller's variable
refer to a different object.

**And `String`?** A `String` object is **immutable**: no method can change its
characters. Methods like `toUpperCase()` or `concat()` build and return a *new*
`String`.

```java
static void shout(String text) {
    text = text.toUpperCase();   // new String object, assigned to the local copy
}
// in main:
String greeting = "hello";
shout(greeting);                 // greeting is still "hello"
```

So a method that receives a `String` cannot change the caller's text in any way: it
cannot change the object (immutable) and it cannot change the caller's variable (pass
by value). The correct design is to **return** the new string:
`greeting = shouted(greeting);`.

**Quick test: a swap method.** If Java had pass-by-reference, this would swap the
caller's variables. It does not, for any type:

```java
static void swap(int x, int y) {
    int temp = x;
    x = y;
    y = temp;        // only the copies x and y are swapped
}
```

What a method can and cannot do to its caller:

| Can a method ... | Primitive | `StringBuilder` | `String` |
|---|---|---|---|
| change the caller's variable? | No | No | No |
| change the object the caller refers to? | (no object) | Yes | No (immutable) |
| give a new value back? | Yes, with `return` | Yes, with `return` | Yes, with `return` |

Never say "Java passes objects by reference". Say: "Java passes a copy of the
reference, so the method can use the same object but cannot change the caller's
variable."

### A problem-solving method

Most beginner programs fail not because of Java syntax but because the programmer
started typing before understanding the problem. Use these five steps:

```text
  1. Understand  ->  2. Plan        ->  3. Dry run
     input, output,    pseudocode,       by hand, with
     hand examples     methods           a table
                                              |
                                              v
                    5. Test edges    <-  4. Code
                       0, 1, big,           one method
                       negative ...         at a time
```

We apply it to a small task: *a hostel room number is "mirror" if it reads the same
backwards (like 1221 or 7). Write a method that checks it.*

**1. Understand.** Input: one non-negative `int`. Output: `true` or `false`.
Examples by hand: 1221 is true, 7 is true, 1230 is false (backwards it is 0321, that
is 321). Questions to settle: is 0 a mirror number? Yes, it has one digit.

**2. Plan.** Split the work into methods and write pseudocode:

```text
reverse(n):
    rev = 0
    while n > 0:
        digit = n % 10        (last digit)
        rev = rev * 10 + digit
        n = n / 10            (drop last digit)
    return rev

isMirror(n):
    return reverse(n) == n
```

**3. Dry run.** Execute the plan on paper with a **dry-run table**: one column per
variable, one row per loop pass. For `reverse(1230)`:

| Pass | `n` before | `digit` | `rev` after | `n` after |
|---|---|---|---|---|
| 1 | 1230 | 0 | 0 | 123 |
| 2 | 123 | 3 | 3 | 12 |
| 3 | 12 | 2 | 32 | 1 |
| 4 | 1 | 1 | 321 | 0 |

The loop stops because `n` is 0; `reverse(1230)` is 321, so `isMirror(1230)` is false,
as expected. A dry run catches wrong formulas before you write any Java.

**4. Code.** Translate one method at a time and test each method alone.

```java
static int reverse(int n) {
    int rev = 0;
    while (n > 0) {
        int digit = n % 10;
        rev = rev * 10 + digit;
        n = n / 10;
    }
    return rev;
}

static boolean isMirror(int n) {
    return reverse(n) == n;
}
```

**5. Test with edge cases.** Choose inputs where bugs like to hide:

| Input | Why test it | Expected |
|---|---|---|
| 0 | the loop body never runs | `true` |
| 7 | single digit | `true` |
| 1221 | normal "yes" | `true` |
| 1230 | trailing zero | `false` |
| 10 | smallest two-digit "no" | `false` |

Notice how methods help: you can dry-run and test `reverse` on its own before you
build `isMirror` on top of it.

### Debugging

A **bug** is a mistake that makes a program fail to compile or give wrong results.
Three practical techniques:

**Read compiler errors from the top.** A `javac` message has the form
`File.java:line: error: message`, followed by the line and a `^` under the problem.
Fix the first error first; later errors are often caused by the first one.

```text
Grades.java:8: error: missing return statement
    }
    ^
1 error
```

| Message | Usual cause |
|---|---|
| `missing return statement` | some path of a non-`void` method has no `return` |
| `cannot find symbol` ... `variable mark` | name used outside its scope, or a typo |
| `incompatible types: possible lossy conversion from double to int` | storing a `double` result in an `int` |
| `method letter in class Grades cannot be applied to given types` | wrong number or types of arguments; the message lists `required:` and `found:` |
| `incompatible types: void cannot be converted to String` | using a `void` method's call as a value |
| `variable count is already defined in method main(String[])` | same local name declared twice in one scope |

**Print intermediate values.** When the output is wrong, print the variables inside
the suspicious method and compare them with your dry-run table:

```java
static int digitSum(int n) {
    int sum = 0;
    while (n > 0) {
        sum = sum + n / 10;      // bug: should be n % 10
        System.out.println("DEBUG n=" + n + " sum=" + sum);
        n = n / 10;
    }
    return sum;
}
```

For `digitSum(123)` the debug lines show `sum=12` after the first pass, while the table
says 3. The wrong line is found in seconds. Remove the `DEBUG` lines after fixing.

**Rubber-duck debugging.** Explain your code, line by line, out loud, to a friend or
even to a rubber duck on your desk. While you say "this line adds the last digit", you
often notice that the line does something else. It works because explaining forces
you to read what you *wrote*, not what you *meant*.

## 2. Syntax

### Defining and calling a static method

```java
static <ReturnType> <methodName>(<Type1> <param1>, <Type2> <param2>) {
    <statements>
    return <value>;     // required when ReturnType is not void
}
```

```java
static int square(int x) {
    return x * x;
}

// calls (from main or from another static method of the same class)
int s = square(9);                    // 81
int t = square(2) + square(3);        // 4 + 9 = 13
int u = square(square(2));            // square(4) = 16
```

- Methods are written inside the class, but **outside** other methods. Java has no
  methods inside methods.
- The order of methods in the class does not matter.
- An argument can be any expression of a fitting type, including another call.

### Returning a value

```java
static boolean isLeapYear(int year) {
    if (year % 400 == 0) {
        return true;
    }
    if (year % 100 == 0) {
        return false;
    }
    return year % 4 == 0;
}
```

- The value after `return` must match the return type (or be widened to it).
- A method returning `boolean` reads well in an `if`: `if (isLeapYear(2028)) { ... }`.
- A method returns exactly one value. To give back several results, call several
  methods, or (from Chapter 04) return an object.

### `void` methods and early `return`

```java
static void printReceiptLine(String item, int taka) {
    if (taka <= 0) {
        return;                       // nothing to print, stop here
    }
    System.out.printf("%-12s Tk %5d%n", item, taka);
}
```

- `return;` without a value is allowed only in a `void` method.
- Call a `void` method as a statement: `printReceiptLine("Tea", 15);`

### Overloaded methods

```java
static int area(int side) {                 // square
    return side * side;
}

static int area(int length, int width) {    // rectangle
    return length * width;
}

static double area(double radius) {         // circle
    return Math.PI * radius * radius;
}
```

- Same name, different parameter lists. A different return type alone is not allowed.
- `area(5)` calls the `int` version; `area(5.0)` calls the `double` version.

### Recursive methods

```java
static int digitSum(int n) {
    if (n < 10) {                       // base case first
        return n;
    }
    return n % 10 + digitSum(n / 10);   // smaller problem
}
```

- Write the base case first, then make sure every recursive call gets closer to it.
- Use `long` when results grow fast (factorial, power).

### `StringBuilder` essentials

`StringBuilder` is a Java class for text that can change. It lives in `java.lang`, so
it needs no import. We use it in this chapter to show what happens when a method
receives a reference to a mutable object.

```java
StringBuilder sb = new StringBuilder("CSE");  // create with initial text
sb.append(" 1111");                           // add at the end: "CSE 1111"
sb.append(3).append('!');                     // append returns sb, so calls chain
int len = sb.length();                        // number of characters
sb.reverse();                                 // reverses the text in place
sb.setLength(0);                              // makes it empty again
String s = sb.toString();                     // a String copy of the current text
```

`System.out.println(sb)` prints the current text. Compare `StringBuilder` contents by
first converting with `toString()`.

## 3. Worked Examples

### Example 1: Student Result Card

**Problem:** Read the number of students `n`, then `n` lines, each with a name and
three marks (out of 100). Print a table with each student's average (two decimals) and
letter grade, and finally how many students passed. Grades: 80 and above `A+`, 70 and
above `A`, 60 and above `B`, 50 and above `C`, 40 and above `D`, otherwise `F`.

The program is decomposed into small methods, each with one job:

- `average` computes, `letterGrade` decides, `printRow` and `printLine` print.
- `main` only reads input and coordinates the methods.

```java
import java.util.Scanner;

public class ResultCard {
    static double average(int a, int b, int c) {
        return (a + b + c) / 3.0;
    }

    static String letterGrade(double avg) {
        if (avg >= 80) {
            return "A+";
        } else if (avg >= 70) {
            return "A";
        } else if (avg >= 60) {
            return "B";
        } else if (avg >= 50) {
            return "C";
        } else if (avg >= 40) {
            return "D";
        }
        return "F";
    }

    static void printLine(int width) {
        for (int i = 0; i < width; i++) {
            System.out.print("-");
        }
        System.out.println();
    }

    static void printRow(String name, double avg, String grade) {
        System.out.printf("%-8s %7.2f  %s%n", name, avg, grade);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        System.out.printf("%-8s %7s  %s%n", "Name", "Average", "Grade");
        printLine(24);
        int passed = 0;
        for (int i = 0; i < n; i++) {
            String name = in.next();
            int m1 = in.nextInt();
            int m2 = in.nextInt();
            int m3 = in.nextInt();
            double avg = average(m1, m2, m3);
            String grade = letterGrade(avg);
            printRow(name, avg, grade);
            if (!grade.equals("F")) {
                passed++;
            }
        }
        printLine(24);
        System.out.println("Passed: " + passed + " of " + n);
    }
}
```

**Input:**

```text
4
Rahim 78 85 62
Nusrat 91 88 95
Karim 35 42 30
Ayesha 70 65 74
```

**Output:**

```text
Name     Average  Grade
------------------------
Rahim      75.00  A
Nusrat     91.33  A+
Karim      35.67  F
Ayesha     69.67  B
------------------------
Passed: 3 of 4
```

**Why it works:** Each method has one clear job and a name that says what it does, so
`main` reads almost like the problem statement. `letterGrade` returns as soon as a
condition matches, so the last `return "F";` covers every remaining case and the
compiler is satisfied that every path returns. To change the grading policy you edit
one method, and nothing else in the program needs to change.

### Example 2: Canteen Bill with Overloaded Methods

**Problem:** The campus canteen sells items by count (tea, singara), by count with a
percentage discount (bulk orders), and by weight (sweets). Write three overloaded
`price` methods and print a small bill.

- `price(int unitPrice, int quantity)` returns an `int` in Tk.
- `price(int unitPrice, int quantity, int discountPercent)` reuses the first version.
- `price(double weightKg, int pricePerKg)` returns a `double`.

```java
public class CanteenBill {
    static int price(int unitPrice, int quantity) {
        return unitPrice * quantity;
    }

    static int price(int unitPrice, int quantity, int discountPercent) {
        int full = price(unitPrice, quantity);
        return full - full * discountPercent / 100;
    }

    static double price(double weightKg, int pricePerKg) {
        return weightKg * pricePerKg;
    }

    public static void main(String[] args) {
        int tea = price(15, 4);
        int singara = price(10, 12, 10);
        double sweets = price(0.75, 480);
        int water = price(2, 20);

        System.out.printf("%-22s Tk %7d%n", "Tea x 4", tea);
        System.out.printf("%-22s Tk %7d%n", "Singara x 12 (10% off)", singara);
        System.out.printf("%-22s Tk %7.2f%n", "Sweets 0.75 kg", sweets);
        System.out.printf("%-22s Tk %7d%n", "Water x 2", water);
        double total = tea + singara + sweets + water;
        System.out.printf("%-22s Tk %7.2f%n", "Total", total);
    }
}
```

**Output:**

```text
Tea x 4                Tk      60
Singara x 12 (10% off) Tk     108
Sweets 0.75 kg         Tk  360.00
Water x 2              Tk      40
Total                  Tk  568.00
```

**Why it works:** The compiler picks a `price` method by the argument types at compile
time: `price(15, 4)` matches `(int, int)` exactly, `price(10, 12, 10)` has three
arguments, and `price(0.75, 480)` needs a `double` first. Watch `price(2, 20)`: both
`(int, int)` and `(double, int)` could accept it (2 can widen to 2.0), but Java
prefers the exact match, so the result is the `int` 40. The discount version calls the
basic version instead of repeating the multiplication.

### Example 3: Recursion Toolkit with a Trace

**Problem:** Read two numbers `a b`, then `n`, then `base exp`, then a number `d`.
Print a trace of Euclid's recursive GCD of `a` and `b` (indent each deeper call by two
spaces and show each returned value), then print `gcd(a, b)`, `n!`, `base^exp` and the
digit sum of `d`, all computed recursively.

The trace uses an extra `depth` parameter. Each call passes `depth + 1` to the next
call, so the method knows how far to indent. A helper `indent` builds the spaces.

```java
import java.util.Scanner;

public class RecursionToolkit {
    static String indent(int depth) {
        String spaces = "";
        for (int i = 0; i < depth; i++) {
            spaces = spaces + "  ";
        }
        return spaces;
    }

    static int gcdTrace(int a, int b, int depth) {
        System.out.println(indent(depth) + "gcd(" + a + ", " + b + ")");
        if (b == 0) {
            System.out.println(indent(depth) + "-> " + a);
            return a;
        }
        int result = gcdTrace(b, a % b, depth + 1);
        System.out.println(indent(depth) + "-> " + result);
        return result;
    }

    static long factorial(int n) {
        if (n == 0) {
            return 1;
        }
        return n * factorial(n - 1);
    }

    static long power(long base, int exp) {
        if (exp == 0) {
            return 1;
        }
        return base * power(base, exp - 1);
    }

    static int digitSum(int n) {
        if (n < 10) {
            return n;
        }
        return n % 10 + digitSum(n / 10);
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int a = in.nextInt();
        int b = in.nextInt();
        int n = in.nextInt();
        long base = in.nextLong();
        int exp = in.nextInt();
        int d = in.nextInt();

        int g = gcdTrace(a, b, 0);
        System.out.println("gcd(" + a + ", " + b + ") = " + g);
        System.out.println(n + "! = " + factorial(n));
        System.out.println(base + "^" + exp + " = " + power(base, exp));
        System.out.println("digit sum of " + d + " = " + digitSum(d));
    }
}
```

**Input:**

```text
84 36
6
3 5
90817
```

**Output:**

```text
gcd(84, 36)
  gcd(36, 12)
    gcd(12, 0)
    -> 12
  -> 12
-> 12
gcd(84, 36) = 12
6! = 720
3^5 = 243
digit sum of 90817 = 25
```

**Why it works:** Every recursive method has a base case (`b == 0`, `n == 0`,
`exp == 0`, `n < 10`) and a recursive case that makes the problem smaller (`a % b` is
less than `b`; `n - 1`; `exp - 1`; `n / 10` has one digit less). The trace shows the
call stack directly: the lines go deeper while calls are pushed, and the `->` lines
come back out in reverse order as frames are popped. Each frame has its own `a`, `b`
and `depth`, which is why the indentation is correct on the way back.

### Example 4: The Cost of Naive Fibonacci

**Problem:** Compare a recursive Fibonacci method with a loop. For `n` = 5, 10, 15,
20, 25, 30 print `fib(n)` from both versions and the number of calls the recursive
version makes.

To count calls without any extra variables, write a second recursive method with the
*same shape* as `fib`: one call costs 1, plus the calls of the two sub-problems.

```java
public class FibonacciCost {
    static long fibRecursive(int n) {
        if (n <= 1) {
            return n;
        }
        return fibRecursive(n - 1) + fibRecursive(n - 2);
    }

    static long countCalls(int n) {
        if (n <= 1) {
            return 1;
        }
        return 1 + countCalls(n - 1) + countCalls(n - 2);
    }

    static long fibLoop(int n) {
        long previous = 0;
        long current = 1;
        if (n == 0) {
            return 0;
        }
        for (int i = 2; i <= n; i++) {
            long next = previous + current;
            previous = current;
            current = next;
        }
        return current;
    }

    public static void main(String[] args) {
        System.out.printf("%3s %8s %8s %10s%n", "n", "loop", "recur", "calls");
        for (int n = 5; n <= 30; n += 5) {
            System.out.printf("%3d %8d %8d %10d%n",
                    n, fibLoop(n), fibRecursive(n), countCalls(n));
        }
    }
}
```

**Output:**

```text
  n     loop    recur      calls
  5        5        5         15
 10       55       55        177
 15      610      610       1973
 20     6765     6765      21891
 25    75025    75025     242785
 30   832040   832040    2692537
```

**Why it works:** Both versions give the same numbers, but the costs are very
different. `countCalls` mirrors the structure of `fibRecursive`, so it counts exactly
the calls that `fibRecursive` makes; the count grows by a factor of about 1.6 for
each step of `n` because the same sub-problems are solved again and again. `fibLoop`
keeps only the last two values and does `n - 1` additions. The recursive version is a
perfect copy of the mathematical definition, and that is exactly its weakness here.

### Example 5: Pass-by-Value Lab

**Problem:** Write a program that proves, with printed output, the rules of parameter
passing: a primitive, a `StringBuilder` that is modified, a `StringBuilder` parameter
that is reassigned, and a `String`. For the primitive and the `String`, also show the
correct design (return the new value).

```java
public class PassByValueLab {
    static void addBonus(int marks) {
        marks = marks + 5;
        System.out.println("  inside addBonus: marks = " + marks);
    }

    static int withBonus(int marks) {
        return marks + 5;
    }

    static void addCourse(StringBuilder list, String code) {
        if (list.length() > 0) {
            list.append(", ");
        }
        list.append(code);
    }

    static void replaceList(StringBuilder list) {
        list = new StringBuilder("EEE 1001");
        list.append(", PHY 1101");
        System.out.println("  inside replaceList: " + list);
    }

    static void shout(String text) {
        text = text.toUpperCase();
        System.out.println("  inside shout: " + text);
    }

    static String shouted(String text) {
        return text.toUpperCase();
    }

    public static void main(String[] args) {
        System.out.println("1) int argument");
        int marks = 70;
        addBonus(marks);
        System.out.println("  after addBonus: marks = " + marks);
        marks = withBonus(marks);
        System.out.println("  after marks = withBonus(marks): marks = " + marks);

        System.out.println("2) StringBuilder argument, object modified");
        StringBuilder courses = new StringBuilder();
        addCourse(courses, "CSE 1111");
        addCourse(courses, "MATH 1151");
        System.out.println("  after addCourse twice: " + courses);

        System.out.println("3) StringBuilder parameter reassigned");
        replaceList(courses);
        System.out.println("  after replaceList: " + courses);

        System.out.println("4) String argument");
        String greeting = "hello";
        shout(greeting);
        System.out.println("  after shout: " + greeting);
        greeting = shouted(greeting);
        System.out.println("  after greeting = shouted(greeting): " + greeting);
    }
}
```

**Output:**

```text
1) int argument
  inside addBonus: marks = 75
  after addBonus: marks = 70
  after marks = withBonus(marks): marks = 75
2) StringBuilder argument, object modified
  after addCourse twice: CSE 1111, MATH 1151
3) StringBuilder parameter reassigned
  inside replaceList: EEE 1001, PHY 1101
  after replaceList: CSE 1111, MATH 1151
4) String argument
  inside shout: HELLO
  after shout: hello
  after greeting = shouted(greeting): HELLO
```

**Why it works:** Every parameter is a new local variable that starts with a copy of
the argument's value. In part 1 the copy is the number 70, so `main` is unaffected.
In part 2 the copy is a reference to `main`'s `StringBuilder`, and `append` follows it
to the same object, so `main` sees the change. In part 3 the method makes its copy
refer to a brand-new object; `main`'s variable still refers to the old one. In part 4
`toUpperCase` creates a new `String` (strings are immutable) and only the local copy
is reassigned. In both "fixed" versions the method *returns* the result and the caller
decides to store it.

### Example 6: Lucky Shuttle Tickets (Problem-Solving Method)

**Problem:** Campus shuttle tickets have 6-digit numbers (100000 to 999999). A ticket
is *lucky* when the digit sum of its first three digits equals the digit sum of its
last three digits (for example 123402: 1+2+3 = 6 and 4+0+2 = 6). Read `q` queries,
each a range `from to`. For each query print how many lucky tickets the range has and
the first lucky ticket, or `Invalid range` if `from > to`, or `none` as the first
ticket if there are no lucky tickets.

**1. Understand.** Inputs are two `int`s per query; ranges are inclusive. Hand
examples: 123402 is lucky; 100000 is not (1 vs 0); 100001 is lucky (1 vs 1).

**2. Plan** (methods and pseudocode):

```text
digitSum(n):       add n % 10 and drop the digit until n is 0
isLucky(t):        digitSum(t / 1000) == digitSum(t % 1000)
countLucky(a, b):  count t in a..b with isLucky(t)
firstLucky(a, b):  first t in a..b with isLucky(t), or -1 if none
main:              for each query: check range, print count and first
```

**3. Dry run** of `isLucky(123006)`: `t / 1000` is 123 and `t % 1000` is 6.

| `digitSum(123)` pass | `n` | `n % 10` | `sum` |
|---|---|---|---|
| 1 | 123 | 3 | 3 |
| 2 | 12 | 2 | 5 |
| 3 | 1 | 1 | 6 |

`digitSum(6)` is 6, so 123006 is lucky.

**4. Code** (below) and **5. Test** with a normal range, a one-ticket range, a range
with no lucky tickets, and an invalid range.

```java
import java.util.Scanner;

public class LuckyTickets {
    static int digitSum(int n) {
        int sum = 0;
        while (n > 0) {
            sum += n % 10;
            n /= 10;
        }
        return sum;
    }

    static boolean isLucky(int ticket) {
        return digitSum(ticket / 1000) == digitSum(ticket % 1000);
    }

    static int countLucky(int from, int to) {
        int count = 0;
        for (int t = from; t <= to; t++) {
            if (isLucky(t)) {
                count++;
            }
        }
        return count;
    }

    static int firstLucky(int from, int to) {
        for (int t = from; t <= to; t++) {
            if (isLucky(t)) {
                return t;
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int q = in.nextInt();
        for (int i = 0; i < q; i++) {
            int from = in.nextInt();
            int to = in.nextInt();
            if (from > to) {
                System.out.println(from + "-" + to + ": Invalid range");
                continue;
            }
            int first = firstLucky(from, to);
            String firstText = (first == -1) ? "none" : String.valueOf(first);
            System.out.println(from + "-" + to + ": " + countLucky(from, to)
                    + " lucky, first " + firstText);
        }
    }
}
```

**Input:**

```text
4
123000 123999
123402 123402
100002 100009
500000 400000
```

**Output:**

```text
123000-123999: 28 lucky, first 123006
123402-123402: 1 lucky, first 123402
100002-100009: 0 lucky, first none
500000-400000: Invalid range
```

**Why it works:** The plan's methods became Java methods one to one, so every piece
could be dry-run and tested on its own. `isLucky` splits the ticket with `/ 1000` and
`% 1000` and reuses `digitSum` twice. `firstLucky` returns as soon as it finds a
ticket and uses `-1` to mean "not found", which `main` turns into `none`. The test
inputs were chosen as edge cases: a single-ticket range (`from == to`), a range with
no lucky ticket, and an invalid range.

## Common Mistakes

- **Forgetting to use the return value.** `withBonus(marks);` computes 75 and throws
  it away. Write `marks = withBonus(marks);`.
- **Expecting a method to change the caller's primitive or `String`.** It receives a
  copy. Return the new value instead.
- **Saying "objects are passed by reference".** Java passes a copy of the reference.
  The method can change a mutable object, but cannot make the caller's variable refer
  to another object.
- **Missing `return` on some path.** Every path of a non-`void` method must return a
  value; the compiler reports `missing return statement`.
- **Using a variable outside its scope.** A variable declared in a loop or in another
  method does not exist here (`cannot find symbol`).
- **Overloading by return type only.** `int f(int x)` and `double f(int x)` cannot both
  exist; the parameter lists must differ.
- **Recursion without a reachable base case** (or a recursive call that does not get
  smaller): the program ends with `StackOverflowError`.
- **Using naive recursion for Fibonacci-like problems** with large `n`: the same work
  is repeated millions of times. Use a loop.
- **Printing inside a method that should return.** A method like `average` should
  return the number and let the caller decide how to print it.
- **Writing everything before testing anything.** Build and test one method at a
  time; it is much easier to find a bug in ten lines than in a hundred.

## Summary

- A method is a named block of code inside a class; methods give decomposition, reuse
  and readable names.
- Parameters are declared in the method header; arguments are the values given in the
  call and are copied into the parameters.
- A non-`void` method must `return` a value on every path; a `void` method returns
  nothing and may use `return;` to stop early.
- Overloaded methods share a name but differ in their parameter lists; the compiler
  chooses one at compile time from the argument types.
- Local variables and parameters live only in their method (or block) and get a fresh
  copy in every call, stored in that call's stack frame.
- Recursion needs a base case and a recursive case that gets smaller; naive Fibonacci
  shows that recursion can be very expensive.
- Primitive variables hold values; reference variables hold references to objects on
  the heap.
- Java is always pass-by-value: a method gets a copy of a primitive or a copy of a
  reference. It can change a mutable object through the copy, but never the caller's
  variable. `String` is immutable, so return a new `String` instead.
- Solve problems in five steps: understand, plan in pseudocode, dry run with a table,
  code method by method, test edge cases.
- Debug by reading the first compiler error, printing intermediate values, and
  explaining the code line by line.
