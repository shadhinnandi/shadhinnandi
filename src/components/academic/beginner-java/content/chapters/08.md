# Chapter 08: Arrays, Object References and Collections

So far every program has worked with a few separate variables or a few objects. Real
programs handle many values at once: the marks of 40 students, the seats of a bus, the
books of a library. This chapter shows how Java stores many values in **arrays** and
**ArrayLists**, and it explains what a variable of a class type really holds: a
**reference** to an object, not the object itself. Once you understand references,
aliasing, `null` and `NullPointerException` stop being mysteries.

**In this chapter you will learn:**

- How to create, fill, loop over and print arrays of primitive values
- How two-dimensional arrays work (an array of arrays)
- Why `new Student[3]` creates three `null` references and no students
- What reference variables, `null`, reference assignment and aliasing mean
- The difference between object identity (`==`) and equality (`equals`)
- What happens when you pass objects and arrays to methods and return them
- What causes a `NullPointerException` and how to avoid it
- How Java references differ from C/C++ pointers, and why Java hides raw memory
- How to use `ArrayList` to store a growing collection of objects
- How to search, filter and sort a collection of objects by a field

## 1. Concept Explanation

### Why arrays?

Suppose you must store the quiz marks of 40 students. Forty variables (`mark1`,
`mark2`, ..., `mark40`) would be impossible to loop over. An **array** is one object
that holds a fixed number of values of the same type, stored one after another. Each
value is an **element**, and you reach it by its **index** (position).

```text
int[] marks = {78, 92, 65, 88};

index:     0      1      2      3
        +------+------+------+------+
        |  78  |  92  |  65  |  88  |
        +------+------+------+------+
marks.length == 4      (valid indexes: 0 .. 3)
```

Important facts about arrays in Java:

- Indexes start at 0. The last index is `length - 1`.
- The size is fixed when the array is created. It cannot grow or shrink later.
- Every element has the same type (`int`, `double`, `String`, `Student`, ...).
- Java checks every index at run time. Using index `-1` or `length` throws an
  `ArrayIndexOutOfBoundsException` and stops the program. Java never reads or writes
  memory outside the array.

### An array is an object

In Java an array is an object that lives on the **heap** (the memory area where objects
are created). The variable `marks` does not contain the four numbers. It contains a
**reference**: a value that tells the program how to reach the array object.

```text
   stack (main)                 heap
  +-------------+        +----+----+----+----+
  | marks  o----+------> | 78 | 92 | 65 | 88 |   int[] object
  +-------------+        +----+----+----+----+   length = 4
```

You met this picture in Chapter 03 (stack variables pointing to heap objects) and in
Chapter 04 (`new` gives back a reference). Arrays follow exactly the same rule.

### Default values of elements

When you create an array with `new`, Java fills every element with a default value,
just like the fields of a new object (Chapter 04):

| Element type | Default value |
|---|---|
| `int`, `long`, `short`, `byte` | `0` |
| `double`, `float` | `0.0` |
| `char` | `'\u0000'` (the zero character) |
| `boolean` | `false` |
| any class type (`String`, `Student`, ...) | `null` |

There are never "garbage values" as in C.

### Two-dimensional arrays

A **two-dimensional (2D) array** stores a table: rows and columns. In Java it is really
an **array of arrays**: the outer array holds references to the row arrays.

```text
int[][] seats = new int[3][4];

 seats        outer array        row arrays
+-----+      +-----+
|  o--+----> |  o--+--------->  [ 0 | 0 | 0 | 0 ]   seats[0]
+-----+      +-----+
             |  o--+--------->  [ 0 | 0 | 0 | 0 ]   seats[1]
             +-----+
             |  o--+--------->  [ 0 | 0 | 0 | 0 ]   seats[2]
             +-----+
seats.length == 3 (rows), seats[0].length == 4 (columns)
```

`seats[1][2]` means "row 1, then column 2 inside that row". Because each row is its
own array, rows may even have different lengths (a **jagged** array), but most tables
you write will be rectangular.

### Arrays of objects hold references

This is the most important picture in the chapter. Look at this line:

```java
Student[] list = new Student[3];
```

It creates **one** array object with three slots. Each slot can hold a reference to a
`Student`. Because the default value of a class type is `null`, all three slots are
`null`. **No `Student` object has been created yet.**

```text
Student[] list = new Student[3];

 list            Student[] object
+-----+      +--------+--------+--------+
|  o--+----> |  null  |  null  |  null  |
+-----+      +--------+--------+--------+
                [0]      [1]      [2]
```

You create each student separately with `new` and store its reference in a slot:

```text
list[0] = new Student("Rahim", 3.75);
list[2] = new Student("Sadia", 3.90);

 list            Student[] object
+-----+      +--------+--------+--------+
|  o--+----> |   o    |  null  |   o    |
+-----+      +---+----+--------+---+----+
                 |                 |
                 v                 v
          +-------------+   +-------------+
          | name "Rahim"|   | name "Sadia"|
          | cgpa 3.75   |   | cgpa 3.90   |
          +-------------+   +-------------+
```

Slot `[1]` is still `null`. Calling a method through it (`list[1].getName()`) is the
classic cause of a `NullPointerException`, explained below.

### Reference variables and `null`

A variable of a class type (or array type) is a **reference variable**. It holds one of
two things:

- a reference to an object, or
- `null`, which means "refers to no object".

`null` is not an object, not zero and not an empty string. You can test for it with
`== null` and `!= null`. A local reference variable has no default value: you must
assign it (even if only `null`) before you use it. Fields and array elements of a class
type start as `null`.

### Reference assignment and aliasing

Assignment with `=` copies the **value in the variable**. For a primitive, that value
is the number itself. For a reference variable, that value is the reference, so after
`b = a` both variables refer to the **same** object. Two names for one object are
called **aliases**.

```text
BankAccount a = new BankAccount("Karim", 5000);
BankAccount b = a;          // copies the reference, not the object

  a  +-----+
     |  o--+-----+
     +-----+     |      +-----------------+
                 +----> | owner  "Karim"  |
  b  +-----+     |      | balance 5000    |
     |  o--+-----+      +-----------------+
     +-----+
```

Now `b.deposit(1000)` changes the one shared object, so `a.getBalance()` also returns
6000. Aliasing is not a bug in itself. It is how objects share data (a `Book` can refer
to the `Member` who borrowed it). It becomes a bug when you *think* you made a copy but
you only copied the reference. To get a real copy, create a new object (for example
with a copy constructor, Chapter 06).

If you then write `b = new BankAccount("Nusrat", 200);`, only `b` changes: it now
refers to a different object, and `a` still refers to Karim's account.

### Identity (`==`) vs equality (`equals`)

There are two different questions you can ask about two references:

| Question | How to ask | Meaning |
|---|---|---|
| Identity: are they the same object? | `x == y` | both references reach one object |
| Equality: do they hold equal values? | `x.equals(y)` | the class decides what "equal" means |

`String` is the standard example. `String` defines `equals` to compare the characters:

```java
String s1 = "Dhaka";
String s2 = new String("Dhaka");   // forces a second, separate object
System.out.println(s1 == s2);      // false: two different objects
System.out.println(s1.equals(s2)); // true: same characters
```

This is why Chapter 01 told you to compare strings with `equals`. For your own classes,
`equals` (inherited from Java's `Object` class) behaves like `==` until you write your
own version. Writing a custom `equals` is explained in Chapters 09 and 10. Until then,
compare objects by their fields, for example `s.getId() == id` or
`s.getName().equals(name)`.

### Passing objects to methods

Chapter 03 said: **Java is always pass-by-value.** For an object argument, the value
copied into the parameter is the reference. So the method's parameter and the caller's
variable are aliases for the same object:

- The method **can change the object** (call `deposit`, set a field), and the caller
  sees the change, because there is only one object.
- The method **cannot change the caller's variable**. If the method assigns a new object
  to its parameter, only the parameter changes; the caller's variable still refers to
  the old object.

```text
caller:   acc  o-----+
                     +---->  [ BankAccount object ]
method:   p    o-----+

p.deposit(500);       --> changes the shared object (caller sees it)
p = otherAccount;     --> only p points elsewhere (acc is unchanged)
```

Arrays behave the same way: a method that receives an `int[]` can change its elements,
and the caller sees the changes.

### Returning objects and arrays

A method can return a reference. The caller receives a reference to the object or
array that the method created or found. Typical uses:

- a method that **finds** an object, for example `findById(list, 205)`, returning the
  reference or `null` when nothing matches;
- a method that **builds** a new array, for example `copyOf(marks)`, returning a
  reference to the new array.

Nothing is copied when you return a reference; the caller simply gets another alias.

### `NullPointerException`

A `NullPointerException` (NPE) is thrown when the program uses a `null` reference as
if it referred to an object:

- calling a method: `s.getName()` when `s` is `null`;
- reading or writing a field through `null`;
- using `length` or an index on an array variable that is `null`;
- unboxing a `null` (you will meet this with collections of numbers in Chapter 13).

Common causes in student programs:

1. An array of objects was created but some slots were never filled.
2. A search method returned `null` ("not found") and the caller used the result
   without checking.
3. A field of a class type was never assigned, so it still holds its default `null`.

How to avoid it: fill arrays fully or loop only over the filled part (keep a `count`);
check `if (x != null)` before using a result that may be `null`; set reference fields in
the constructor. Handling exceptions with `try`/`catch` comes in Chapter 11. In this
chapter the goal is to write code that never causes an NPE in the first place.

Since Java 15 the error message (by default) names the expression that was `null`:

```text
Exception in thread "main" java.lang.NullPointerException: Cannot invoke
"Student.getName()" because "<local1>[1]" is null
    at NpeDemo.main(NpeDemo.java:11)
```

Here `<local1>` is local-variable slot 1 of `main` (slot 0 is `args`), here the array
`list`; the compiler
does not keep local variable names unless you compile with `javac -g`. Line 11 is where
to look.

### References are not raw pointers

Many courses call references "object pointers". The idea is similar: a reference lets
your program reach an object that lives somewhere else in memory. But Java uses object
references **instead of exposing raw memory pointers** like C and C++ do:

| C / C++ pointer | Java reference |
|---|---|
| `&x` gives the address of any variable | no address-of operator |
| `p + 1` moves to the next address | no pointer arithmetic |
| `*p` or `p->field` dereferences | dereferencing is automatic with `.` |
| may point to freed or random memory | refers to a real object or is `null` |
| you call `free` / `delete` yourself | the garbage collector frees memory |
| can be cast to an integer address | the address is never visible |

When you write `acc.deposit(500)`, the `.` follows the reference to the object and
calls the method there. That is implicit **dereferencing**.

Why does Java hide raw memory addresses?

- **Safety:** a program cannot read or overwrite memory it does not own, and an index
  outside an array is caught at run time. A whole family of C bugs (buffer overflows,
  dangling pointers, double `free`) cannot happen.
- **Garbage collection:** the garbage collector (Chapter 06) may move objects around
  in memory to compact it. Because no program knows the real addresses, the JVM is free
  to do this and update the references.
- **Portability:** the same bytecode runs on every JVM, whatever memory layout it uses.

> **Coming from C/C++?** In C, an array name decays to a pointer to its first element,
> and `arr[i]` is `*(arr + i)`. In Java an array is an object with a `length` field, and
> `arr[i]` is a checked access, not address arithmetic. There is no `int *p`, no `&`,
> no `->`, no `malloc`/`free`, and no `sizeof`. You can do only four things with a
> Java reference: assign it, compare it (`==`, `!=`), set it to `null`, and follow it
> with `.` (or `[]` for arrays). It can never be moved with arithmetic or turned into a
> number.

### Why collections? `ArrayList`

An array's size is fixed. A library does not know in advance how many books it will
have, and books are added and removed all the time. Java's standard library offers
**collections**: objects that store a group of other objects and grow or shrink as
needed. The most common one is `ArrayList`.

- An `ArrayList<Book>` keeps references to `Book` objects in order, with indexes from 0.
- `add` appends at the end and grows the list automatically.
- `remove` takes an element out and shifts the later ones left.
- `size()` tells how many elements it holds right now.

Inside, an `ArrayList` uses an ordinary array and replaces it with a bigger one when it
fills up. You get that work done for you.

| Need | Use |
|---|---|
| fixed number of values, known up front (12 months, 5 days) | array |
| numbers in a table (seats, a grid) | 2D array |
| a group that grows and shrinks (members, orders, books) | `ArrayList` |

> **Should this be a class?** When you find yourself keeping three parallel arrays
> (`names[]`, `ids[]`, `cgpas[]`) where index `i` in each describes the same student,
> that is a sign you need a `Student` class and one `Student[]` or
> `ArrayList<Student>`. One object per student keeps its data together.

## 2. Syntax

### Declaring and creating arrays

```java
int[] marks;                 // declare a reference variable (no array yet)
marks = new int[5];          // create an array of 5 ints, all 0

double[] prices = new double[3];      // declare and create: 0.0, 0.0, 0.0
String[] days = {"Sun", "Mon", "Tue"}; // array initializer: size is 3
int[] primes = new int[] {2, 3, 5, 7}; // same idea, usable in any expression
```

- `int[] marks` is the preferred style. `int marks[]` also compiles (C style), but
  keep the brackets with the type.
- The initializer form `{...}` is allowed only in a declaration. Elsewhere use
  `new int[] {...}`.
- The size can come from a variable: `new int[n]` where `n` was read from input.

### Accessing elements and `length`

```java
marks[0] = 78;                     // write element 0
int first = marks[0];              // read element 0
int last = marks[marks.length - 1]; // read the last element
marks[2] += 5;                     // elements work like normal variables
```

`length` is a field of the array (no parentheses), while `String` has a method
`length()` (with parentheses). Mixing them up is a common compile error.

### Looping over an array

```java
// classic for: you have the index, so you can read, write, or compare neighbours
for (int i = 0; i < marks.length; i++) {
    marks[i] = marks[i] + 2;
}

// enhanced for ("for-each"): read every element in order, no index
int total = 0;
for (int m : marks) {
    total += m;
}
```

Read the enhanced `for` as "for each `int m` in `marks`". The variable `m` is a copy
of the element, so assigning to `m` does not change the array. Use the classic `for`
when you need the index or want to change elements.

### The `Arrays` helper class

`java.util.Arrays` is a utility class (Chapter 07) with static methods for arrays:

```java
import java.util.Arrays;

int[] data = {42, 7, 19, 3};
System.out.println(Arrays.toString(data)); // [42, 7, 19, 3]
Arrays.sort(data);                         // sorts in place, ascending
System.out.println(Arrays.toString(data)); // [3, 7, 19, 42]
int[] copy = Arrays.copyOf(data, data.length); // a new array with the same values
```

`System.out.println(data)` would print something like `[I@1b6d3586` (a type code and a
hash), not the elements. Use `Arrays.toString`.

### Two-dimensional arrays

```java
int[][] sales = new int[3][5];          // 3 rows, 5 columns, all 0
sales[0][4] = 1200;                     // row 0, column 4

int[][] grid = {
    {1, 2, 3},
    {4, 5, 6}
};                                      // 2 rows, 3 columns

for (int r = 0; r < grid.length; r++) {          // rows
    for (int c = 0; c < grid[r].length; c++) {   // columns of row r
        System.out.print(grid[r][c] + " ");
    }
    System.out.println();
}
```

Use `grid.length` for the number of rows and `grid[r].length` for the columns of row
`r`.

### Arrays of objects

```java
Student[] list = new Student[3];        // 3 null references
list[0] = new Student("Rahim", 3.75);   // now slot 0 refers to a Student
System.out.println(list[0].getName());  // dereference with .

int count = 0;                          // how many slots are filled
for (int i = 0; i < list.length; i++) {
    if (list[i] != null) {              // skip empty slots
        count++;
    }
}
```

A common design is a partly filled array plus a counter: `list[count] = s; count++;`
adds a student, and loops run `for (int i = 0; i < count; i++)` so they never touch
the `null` slots.

### Comparing references and strings

```java
if (a == b) { ... }                    // same object?
if (a != null) { ... }                 // refers to an object?
if (name.equals("Rahim")) { ... }      // same characters?
if ("Rahim".equals(name)) { ... }      // same, and safe even when name is null
int order = name1.compareTo(name2);    // alphabetical order (see below)
```

To sort objects by a `String` field you need to know which string comes first.
`a.compareTo(b)` returns a negative number if `a` comes before `b`, `0` if they are
equal, and a positive number if `a` comes after `b`. It compares character codes, so
uppercase letters come before lowercase (`"Zara"` before `"arif"`).

### Methods that take and return arrays and objects

```java
static double average(int[] values) {            // array parameter
    int sum = 0;
    for (int v : values) {
        sum += v;
    }
    return (double) sum / values.length;
}

static int[] doubled(int[] values) {             // returns a new array
    int[] result = new int[values.length];
    for (int i = 0; i < values.length; i++) {
        result[i] = values[i] * 2;
    }
    return result;
}

static Student findByName(Student[] list, int count, String name) {
    for (int i = 0; i < count; i++) {
        if (list[i].getName().equals(name)) {
            return list[i];                       // the reference that was found
        }
    }
    return null;                                  // "not found": caller must check
}
```

### `ArrayList` basics

```java
import java.util.ArrayList;

ArrayList<String> names = new ArrayList<>();  // empty list of String references
names.add("Mitu");               // [Mitu]
names.add("Rafi");               // [Mitu, Rafi]
names.add(0, "Arif");            // insert at index 0: [Arif, Mitu, Rafi]
String s = names.get(1);         // "Mitu"
names.set(1, "Farhana");         // replace: [Arif, Farhana, Rafi]
names.remove(0);                 // remove by index: [Farhana, Rafi]
names.remove("Rafi");            // remove by value (uses equals): [Farhana]
int n = names.size();            // 1
boolean has = names.contains("Farhana"); // true (uses equals)
boolean empty = names.isEmpty();  // false
System.out.println(names);       // [Farhana]
```

- The `<String>` part says what type of reference the list stores. Write it every
  time; the `<>` on the right lets Java repeat it for you. The `<Student>` syntax
  (generics) is explained in Chapter 13.
- A list holds references to objects only. For numbers use `ArrayList<Integer>` or
  `ArrayList<Double>` (wrapper classes, Chapter 13), not `ArrayList<int>`.
- `get(i)` with `i < 0` or `i >= size()` throws `IndexOutOfBoundsException`.
- `contains` and `remove(Object)` use `equals`. For your own classes without a custom
  `equals`, that means "the same object", so search by a field with a loop instead.
- `println(list)` prints each element's `toString()` inside brackets. That is readable
  for `String`; for your own class, print the fields yourself or write `toString()`.

### Iterating over an `ArrayList`

```java
ArrayList<Student> students = new ArrayList<>();
students.add(new Student("Imran", 3.10));
students.add(new Student("Fahim", 3.55));

for (int i = 0; i < students.size(); i++) {      // with an index
    System.out.println(i + ": " + students.get(i).getName());
}

for (Student s : students) {                      // for-each: read only
    System.out.println(s.getName());
}
```

Do not call `add` or `remove` on a list inside a for-each loop over that same list:
Java usually stops the loop with a `ConcurrentModificationException` (and otherwise
may silently skip elements). To remove while looping,
use an index loop and step back after each removal (or loop from the end):

```java
for (int i = students.size() - 1; i >= 0; i--) {
    if (students.get(i).getCgpa() < 2.0) {
        students.remove(i);              // safe: later indexes are already done
    }
}
```

> In a real project each public class lives in its own file; here we keep each program
> in one file so you can compile it with one command.

## 3. Worked Examples

### Example 1: Quiz Marks Report

**Problem:** A teacher enters the number of students and their quiz marks. Print the
marks, the highest and lowest mark, the average (2 decimal places), how many students
scored above the average, and the marks in ascending order. The original order must be
kept for later use, so sort a copy, not the original array.

The program reads the marks into an `int[]`. Helper methods take the array as a
parameter. `copyOf` creates and returns a new array, so sorting the copy leaves the
original untouched.

```java
import java.util.Arrays;
import java.util.Scanner;

public class QuizReport {
    static int highest(int[] values) {
        int best = values[0];
        for (int v : values) {
            if (v > best) {
                best = v;
            }
        }
        return best;
    }

    static int lowest(int[] values) {
        int worst = values[0];
        for (int v : values) {
            if (v < worst) {
                worst = v;
            }
        }
        return worst;
    }

    static double average(int[] values) {
        int sum = 0;
        for (int v : values) {
            sum += v;
        }
        return (double) sum / values.length;
    }

    static int[] copyOf(int[] values) {
        int[] result = new int[values.length];
        for (int i = 0; i < values.length; i++) {
            result[i] = values[i];
        }
        return result;
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt();
        int[] marks = new int[n];
        for (int i = 0; i < n; i++) {
            marks[i] = in.nextInt();
        }

        double avg = average(marks);
        int above = 0;
        for (int m : marks) {
            if (m > avg) {
                above++;
            }
        }

        int[] sorted = copyOf(marks);
        Arrays.sort(sorted);

        System.out.println("Marks        : " + Arrays.toString(marks));
        System.out.println("Highest      : " + highest(marks));
        System.out.println("Lowest       : " + lowest(marks));
        System.out.printf("Average      : %.2f%n", avg);
        System.out.println("Above average: " + above);
        System.out.println("Sorted copy  : " + Arrays.toString(sorted));
        System.out.println("Original     : " + Arrays.toString(marks));
    }
}
```

**Input:**

```text
6
78 92 65 88 92 54
```

**Output:**

```text
Marks        : [78, 92, 65, 88, 92, 54]
Highest      : 92
Lowest       : 54
Average      : 78.17
Above average: 3
Sorted copy  : [54, 65, 78, 88, 92, 92]
Original     : [78, 92, 65, 88, 92, 54]
```

**Why it works:** The size of the array comes from the input (`new int[n]`). Each
helper receives a copy of the reference to the same array, so it reads the real marks
without copying them. `copyOf` returns a reference to a brand-new array; had we written
`int[] sorted = marks;` instead, `Arrays.sort(sorted)` would have sorted the original
too, because both variables would be aliases of one array.

### Example 2: Exam Hall Seat Plan

**Problem:** An exam hall has `rows` rows of `cols` seats. Students with roll numbers
starting from 101 are seated row by row. Read `rows`, `cols` and the number of
students, then print the seat plan (`---` for an empty seat) and the number of empty
seats. If there are more students than seats, seat as many as fit and print how many
could not be seated.

A 2D `int` array models the hall: `0` (the default value) means "empty". Nested loops
walk the seats row by row.

```java
import java.util.Scanner;

public class SeatPlan {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int rows = in.nextInt();
        int cols = in.nextInt();
        int students = in.nextInt();

        int[][] hall = new int[rows][cols];   // every seat starts at 0 (empty)
        int nextRoll = 101;
        int seated = 0;
        for (int r = 0; r < hall.length; r++) {
            for (int c = 0; c < hall[r].length; c++) {
                if (seated < students) {
                    hall[r][c] = nextRoll;
                    nextRoll++;
                    seated++;
                }
            }
        }

        int empty = 0;
        for (int r = 0; r < hall.length; r++) {
            System.out.print("Row " + (r + 1) + ":");
            for (int c = 0; c < hall[r].length; c++) {
                if (hall[r][c] == 0) {
                    System.out.print(" ---");
                    empty++;
                } else {
                    System.out.print(" " + hall[r][c]);
                }
            }
            System.out.println();
        }
        System.out.println("Empty seats: " + empty);
        if (seated < students) {
            System.out.println("Not seated: " + (students - seated));
        }
    }
}
```

**Input:**

```text
3 4 10
```

**Output:**

```text
Row 1: 101 102 103 104
Row 2: 105 106 107 108
Row 3: 109 110 --- ---
Empty seats: 2
```

**Why it works:** `new int[rows][cols]` builds an outer array of `rows` references,
each pointing to a row array of `cols` zeros. `hall.length` is the number of rows and
`hall[r].length` the number of seats in row `r`, so the loops never leave the array.
The default value `0` doubles as the "empty" marker, which works because roll numbers
start at 101.

### Example 3: Student Register With Empty Slots

**Problem:** A tutorial group register has a fixed number of slots. Read the capacity,
then the number of students and each student's name and CGPA. Store them in a
`Student[]`, print every slot (an unused slot prints `empty`), and print the student
with the highest CGPA. The program must not crash on the empty slots.

`Student` is an encapsulated class (Chapter 05). The register is a `Student[]` whose
unused slots stay `null`. Every loop that touches all slots checks for `null` first.

```java
import java.util.Scanner;

class Student {
    private final String name;
    private final double cgpa;

    Student(String name, double cgpa) {
        this.name = name;
        this.cgpa = cgpa;
    }

    String getName() {
        return name;
    }

    double getCgpa() {
        return cgpa;
    }
}

public class TutorialRegister {
    static Student topper(Student[] slots) {
        Student best = null;                 // no student seen yet
        for (Student s : slots) {
            if (s != null && (best == null || s.getCgpa() > best.getCgpa())) {
                best = s;
            }
        }
        return best;                         // may be null if all slots are empty
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int capacity = in.nextInt();
        Student[] slots = new Student[capacity];   // capacity null references
        int n = in.nextInt();
        for (int i = 0; i < n && i < capacity; i++) {
            String name = in.next();
            double cgpa = in.nextDouble();
            slots[i] = new Student(name, cgpa);    // now slot i refers to a Student
        }

        for (int i = 0; i < slots.length; i++) {
            if (slots[i] == null) {
                System.out.println("Slot " + i + ": empty");
            } else {
                System.out.printf("Slot %d: %s (%.2f)%n",
                        i, slots[i].getName(), slots[i].getCgpa());
            }
        }

        Student best = topper(slots);
        if (best == null) {
            System.out.println("No students registered.");
        } else {
            System.out.printf("Topper: %s with CGPA %.2f%n",
                    best.getName(), best.getCgpa());
        }
    }
}
```

**Input:**

```text
5
3
Nusrat 3.85
Tanvir 3.40
Ayesha 3.92
```

**Output:**

```text
Slot 0: Nusrat (3.85)
Slot 1: Tanvir (3.40)
Slot 2: Ayesha (3.92)
Slot 3: empty
Slot 4: empty
Topper: Ayesha with CGPA 3.92
```

**Why it works:** `new Student[capacity]` creates only references, all `null`. Three
`new Student(...)` calls create the three objects. The condition
`s != null && (...)` uses short-circuit `&&`: when `s` is `null`, Java does not
evaluate the right side, so `s.getCgpa()` is never called on `null`. `topper` returns
a reference to the object it found (no copy) or `null`, and `main` checks for `null`
before using it.

### Example 4: Aliases, Identity and Method Calls

**Problem:** Demonstrate, with a bank account, what reference assignment does, the
difference between `==` and `equals`, and what a method can and cannot change when it
receives an object.

Each step prints a short line, so you can predict the output before you read it.

```java
class BankAccount {
    private final String owner;
    private int balance;   // whole Tk

    BankAccount(String owner, int balance) {
        this.owner = owner;
        this.balance = balance;
    }

    String getOwner() {
        return owner;
    }

    int getBalance() {
        return balance;
    }

    void deposit(int amount) {
        balance += amount;
    }
}

public class ReferenceDemo {
    static void addBonus(BankAccount acc, int bonus) {
        acc.deposit(bonus);                       // changes the shared object
    }

    static void replace(BankAccount acc) {
        acc = new BankAccount("Nobody", 0);       // changes only the parameter
        acc.deposit(100);
    }

    static BankAccount richer(BankAccount x, BankAccount y) {
        if (x.getBalance() >= y.getBalance()) {
            return x;
        }
        return y;
    }

    public static void main(String[] args) {
        BankAccount a = new BankAccount("Karim", 5000);
        BankAccount b = a;                        // alias: same object
        b.deposit(1000);
        System.out.println("1. a balance: " + a.getBalance());

        BankAccount c = new BankAccount("Karim", 6000);   // separate object
        System.out.println("2. a == b: " + (a == b));
        System.out.println("3. a == c: " + (a == c));
        System.out.println("4. same owner: " + a.getOwner().equals(c.getOwner()));

        String s1 = "Karim";
        String s2 = new String("Karim");
        System.out.println("5. s1 == s2: " + (s1 == s2));
        System.out.println("6. s1.equals(s2): " + s1.equals(s2));

        addBonus(a, 500);
        System.out.println("7. after addBonus: " + a.getBalance());
        replace(a);
        System.out.println("8. after replace: " + a.getOwner() + " " + a.getBalance());

        BankAccount top = richer(a, c);
        System.out.println("9. richer is a: " + (top == a));

        b = null;                                 // b refers to nothing now
        System.out.println("10. b is null: " + (b == null) + ", a still "
                + a.getBalance());
    }
}
```

**Output:**

```text
1. a balance: 6000
2. a == b: true
3. a == c: false
4. same owner: true
5. s1 == s2: false
6. s1.equals(s2): true
7. after addBonus: 6500
8. after replace: Karim 6500
9. richer is a: true
10. b is null: true, a still 6500
```

**Why it works:**

- Line 1: `b = a` copied the reference, so `b.deposit` changed Karim's only account.
- Lines 2-4: `a` and `c` hold equal data but are two objects, so `==` is `false`;
  comparing a field with `equals` answers the "same data?" question.
- Lines 5-6: `new String` makes a separate object with the same characters.
- Line 7: `addBonus` received a copy of the reference and changed the object.
- Line 8: `replace` pointed its own parameter at a new object; the caller's `a` is
  untouched (pass-by-value, as in Chapter 03).
- Line 9: `richer` returned one of its arguments, so the result is an alias of `a`.
- Line 10: setting `b` to `null` removes one reference; the object is still reachable
  through `a`, so it stays alive.

### Example 5: Library Catalogue With ArrayList

**Problem:** A small department library keeps its books in an `ArrayList<Book>`. Add
five books, list them, find a book by title, list the books by one author (filtering),
remove every book published before 2010, and finally print the remaining books sorted
by year (oldest first).

`Book` is a small immutable class. Searching, filtering and sorting are written with
simple loops so you can see every step. The sort is a selection sort that swaps
references inside the list with `get` and `set`.

```java
import java.util.ArrayList;

class Book {
    private final String title;
    private final String author;
    private final int year;

    Book(String title, String author, int year) {
        this.title = title;
        this.author = author;
        this.year = year;
    }

    String getTitle() {
        return title;
    }

    String getAuthor() {
        return author;
    }

    int getYear() {
        return year;
    }

    public String toString() {
        return title + " (" + author + ", " + year + ")";
    }
}

public class LibraryCatalogue {
    static Book findByTitle(ArrayList<Book> books, String title) {
        for (Book b : books) {
            if (b.getTitle().equalsIgnoreCase(title)) {
                return b;
            }
        }
        return null;
    }

    static ArrayList<Book> byAuthor(ArrayList<Book> books, String author) {
        ArrayList<Book> result = new ArrayList<>();
        for (Book b : books) {
            if (b.getAuthor().equals(author)) {
                result.add(b);                 // same object, second list
            }
        }
        return result;
    }

    static void sortByYear(ArrayList<Book> books) {
        for (int i = 0; i < books.size() - 1; i++) {
            int min = i;
            for (int j = i + 1; j < books.size(); j++) {
                if (books.get(j).getYear() < books.get(min).getYear()) {
                    min = j;
                }
            }
            Book temp = books.get(i);          // swap two references
            books.set(i, books.get(min));
            books.set(min, temp);
        }
    }

    static void printAll(String heading, ArrayList<Book> books) {
        System.out.println(heading + " (" + books.size() + "):");
        for (Book b : books) {
            System.out.println("  " + b);
        }
    }

    public static void main(String[] args) {
        ArrayList<Book> books = new ArrayList<>();
        books.add(new Book("Java Basics", "Rahman", 2015));
        books.add(new Book("Data Structures", "Hossain", 2008));
        books.add(new Book("OOP Design", "Rahman", 2019));
        books.add(new Book("Discrete Maths", "Akter", 2005));
        books.add(new Book("Algorithms", "Hossain", 2012));
        printAll("All books", books);

        Book found = findByTitle(books, "oop design");
        if (found != null) {
            System.out.println("Found: " + found);
        }
        Book missing = findByTitle(books, "Compilers");
        System.out.println("Compilers found? " + (missing != null));

        printAll("By Rahman", byAuthor(books, "Rahman"));

        for (int i = books.size() - 1; i >= 0; i--) {
            if (books.get(i).getYear() < 2010) {
                books.remove(i);
            }
        }
        sortByYear(books);
        printAll("Since 2010, oldest first", books);
    }
}
```

**Output:**

```text
All books (5):
  Java Basics (Rahman, 2015)
  Data Structures (Hossain, 2008)
  OOP Design (Rahman, 2019)
  Discrete Maths (Akter, 2005)
  Algorithms (Hossain, 2012)
Found: OOP Design (Rahman, 2019)
Compilers found? false
By Rahman (2):
  Java Basics (Rahman, 2015)
  OOP Design (Rahman, 2019)
Since 2010, oldest first (3):
  Algorithms (Hossain, 2012)
  Java Basics (Rahman, 2015)
  OOP Design (Rahman, 2019)
```

**Why it works:**

- The list grows with every `add`; no size was chosen in advance.
- `findByTitle` returns a reference into the list or `null`, and `main` checks it
  before printing.
- `byAuthor` builds a new list that refers to the **same** `Book` objects. Nothing is
  copied: the filtered list only stores references.
- The removal loop runs from the end, so removing index `i` never skips an element.
- `sortByYear` moves references, not books. The `Book` objects stay where they are on
  the heap; only the order of references in the list changes.
- `println("  " + b)` calls `toString()` automatically (Chapter 04). Why `toString()`
  is written with `public` here is explained with overriding in Chapter 09.

## Common Mistakes

- **Index off by one.** `for (int i = 0; i <= a.length; i++)` reads `a[a.length]` and
  throws `ArrayIndexOutOfBoundsException`. Use `i < a.length`.
- **Thinking `new Student[3]` creates students.** It creates three `null` references.
  Create each object with `new Student(...)` before using its slot.
- **Using a search result without checking for `null`.** A "find" method that can fail
  returns `null`; always test `if (result != null)` first.
- **Copying the reference when you wanted a copy.** `int[] backup = marks;` makes an
  alias. Use `Arrays.copyOf(marks, marks.length)` or a loop, or for objects create a new
  object.
- **Comparing strings or objects with `==`.** `==` checks identity. Use `equals` for
  `String`, and compare fields for your own classes (until Chapter 09).
- **Printing an array directly.** `System.out.println(marks)` prints `[I@...`. Use
  `Arrays.toString(marks)`.
- **`length` vs `length()` vs `size()`.** Arrays: `a.length`. Strings: `s.length()`.
  ArrayLists: `list.size()`.
- **Removing from an ArrayList inside a for-each loop.** It usually throws
  `ConcurrentModificationException` (or silently skips elements). Use an index loop running backwards.
- **Writing `ArrayList<int>`.** Collections store references; use `ArrayList<Integer>`.

## Summary

- An array is a fixed-size object holding elements of one type; indexes run from 0 to
  `length - 1`, and Java checks every index at run time.
- New arrays are filled with default values: `0`, `0.0`, `false`, or `null` for class
  types. A 2D array is an array of arrays.
- `new Student[3]` creates an array of three `null` references; each `Student` must be
  created separately with `new`.
- A reference variable holds a reference to an object or `null`. Assignment copies the
  reference, so `b = a` makes two aliases of one object.
- `==` tests identity (same object); `equals` tests equality as defined by the class.
  Compare `String` contents with `equals`.
- Java is pass-by-value: a method receives a copy of the reference, so it can change
  the object but not the caller's variable. Methods can return objects and arrays.
- A `NullPointerException` comes from using a `null` reference; avoid it by filling
  slots, tracking a count, and checking results for `null`.
- Java uses references instead of raw pointers: no address-of, no pointer arithmetic,
  no manual `free`, automatic dereferencing with `.`, and garbage collection.
- `ArrayList<T>` is a growable list with `add`, `get`, `set`, `remove`, `size` and
  `contains`; use it when the number of elements changes.
- Searching, filtering and sorting a collection of objects by a field are loops over
  references: compare a field, collect references, or swap references.
