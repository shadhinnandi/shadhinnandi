This chapter answers two questions before you write serious code: what Java is, and
why object-oriented programming (OOP) exists at all. You will see how a Java program
travels from a `.java` file to running instructions, and you will write and run your
first programs. Most importantly, you will meet the ideas that the rest of the course
builds on: objects, messages, and the four OOP principles.

## 1. Concept Explanation

### What Java is

Java is a general-purpose programming language. It was first released in 1995 and is
now developed in the open as the OpenJDK project, with a new version every six months.

Three facts describe Java well:

- **It is object-oriented.** Every method you write lives inside a class. Programs are
  built from objects that hold data and offer behaviour.
- **It is compiled to bytecode, not to machine code.** The compiler produces
  instructions for a virtual machine (the JVM), not for your specific processor.
- **It manages memory for you.** You create objects with `new`, but you never free them
  yourself. A garbage collector reclaims objects your program can no longer reach.

### Why Java

Why do universities and companies keep choosing Java?

- **Portability.** The same compiled program runs on Windows, Linux and macOS.
- **Safety.** Array indexes are checked, there is no pointer arithmetic, and local
  variables cannot be used before they are given a value. Many C bugs simply cannot
  happen.
- **A large standard library.** Lists, maps, files, networking, threads and GUI
  windows are included. You do not have to write them from scratch.
- **It is used in real systems.** Server back-ends, Android apps, banking software,
  desktop tools and build tools are written in Java.
- **It is a good OOP teaching language.** Classes are not optional in Java, so you
  practise object-oriented thinking from the first day.

### Java vs C

Most of you come from a C course. The syntax will look familiar (`int`, `if`, `for`,
`while`, braces, semicolons), but the model underneath is different.

| Aspect | C | Java |
|---|---|---|
| Main style | Procedural (functions + data) | Object-oriented (classes + objects) |
| Compiled to | Native machine code for one platform | Bytecode, run by the JVM |
| Memory | `malloc` / `free` by hand | `new`; garbage collector frees |
| Pointers | Raw pointers, pointer arithmetic | References; no pointer arithmetic |
| Array index out of range | Undefined behaviour | Checked; throws an exception |
| Strings | `char` arrays ending in `'\0'` | `String` objects (immutable) |
| True / false | Integers (0 and non-zero) | `boolean`; not a number |
| Size of `int` | Depends on the platform | Always 32 bits |
| Unassigned local variable | Garbage value | Compile error if used |
| Entry point | `int main(void)` | `public static void main(String[] args)` |
| Libraries | `#include` header files | `import` classes; no preprocessor |

> **Coming from C?** Your knowledge of expressions, `if`, loops and functions transfers
> almost directly. What changes is *where* code lives (inside classes) and *how* data
> is organised (inside objects).

### Java vs C++

C++ is also object-oriented, so the differences are about design choices. You do not
need to know C++ for this course; this table is only for orientation.

| Aspect | C++ | Java |
|---|---|---|
| Classes | Optional; global functions allowed | Every method is inside a class |
| Runs as | Native machine code | Bytecode on the JVM |
| Freeing memory | `delete`, destructors, smart pointers | Garbage collector; no destructors |
| Multiple inheritance of classes | Allowed | A class extends one class only |
| Pointers | Pointers and references | References only |
| Operator overloading | Allowed for user types | Not allowed (`+` on `String` is built in) |
| Generic code | Templates | Generics |
| Dynamic dispatch | Only for `virtual` methods | Default (non-final, non-private instance methods) |

### How a Java program runs: JDK, JRE, JVM and bytecode

Four terms appear everywhere. Learn them once:

- **Source code**: the text you write, saved in a file ending in `.java`.
- **Bytecode**: compact instructions for the Java Virtual Machine, stored in `.class`
  files. Bytecode is not tied to any processor or operating system.
- **JVM (Java Virtual Machine)**: the program that loads `.class` files, checks them
  (verification) and executes them. It interprets bytecode and also compiles
  frequently used parts to native machine code while running (JIT, just-in-time
  compilation), which is why Java programs run fast.
- **JRE (Java Runtime Environment)**: the JVM plus the standard class library. It is
  everything needed to *run* Java programs.
- **JDK (Java Development Kit)**: the JRE plus development tools such as `javac`
  (the compiler), `java` (the launcher), `jar` and `javadoc`. It is what you install
  to *write* Java programs. Since Java 11 you normally just install a JDK.

```text
+------------------------------------------------+
| JDK  (for developers)                          |
|   javac, jar, javadoc, ...                     |
|  +------------------------------------------+  |
|  | JRE  (for running programs)              |  |
|  |   standard library: String, Math,        |  |
|  |   Scanner, ArrayList, ...                |  |
|  |  +------------------------------------+  |  |
|  |  | JVM  loads, verifies and runs      |  |  |
|  |  |      bytecode (.class files)       |  |  |
|  |  +------------------------------------+  |  |
|  +------------------------------------------+  |
+------------------------------------------------+
```

The compile-run cycle has two separate steps:

```text
  you write          step 1: compile          step 2: run
+------------+     +--------------+     +-------------+     +--------+
| Hello.java | --> | javac        | --> | Hello.class | --> | java   |
| source     |     | (compiler)   |     | bytecode    |     | Hello  |
+------------+     +--------------+     +-------------+     +--------+
                          |                                     |
                          v                                     v
                   compile errors                     the JVM runs main;
                   (syntax, types)                    output appears
```

- `javac` checks your code. Syntax mistakes and type mistakes are reported here, and
  no `.class` file is produced until they are fixed.
- `java` starts a JVM, loads the class and calls its `main` method. Mistakes that only
  appear while running (dividing by zero, a bad index) are reported here.

> **Coming from C?** `gcc` turns `hello.c` into a native executable that you run
> directly. Java adds a middle layer: the `.class` file is run *by* the JVM.

### Write once, run anywhere

Because bytecode targets the JVM rather than a real processor, the same `.class` file
can run on every system that has a JVM. Only the JVM itself is platform-specific.

```text
                     Hello.class  (one bytecode file)
                 /          |               \
                v           v                v
        +-----------+  +-----------+  +-----------+
        | JVM for   |  | JVM for   |  | JVM for   |
        | Windows   |  | Linux     |  | macOS     |
        +-----------+  +-----------+  +-----------+
              |              |              |
         same output    same output    same output
```

A C program must be recompiled for each platform. A Java program is compiled once;
each platform supplies its own JVM.

### Why OOP exists

Small programs are easy in any style. The trouble starts when programs grow. A campus
system might begin with a student's canteen balance, then add library fines, shuttle
passes, hostel fees and course registration. Soon there are thousands of lines and
dozens of functions.

In that growing program, three problems appear:

1. **Anyone can change any data.** If the balance is an ordinary variable, any function
   can set it to `-500`. When it goes wrong, you must search the whole program for the
   culprit.
2. **Data and the code that changes it drift apart.** The rules for the balance ("never
   below zero", "record every payment") are scattered across many functions.
3. **The code does not look like the problem.** The real world has students, wallets,
   books and buses. The program has a pile of variables and functions.

OOP answers all three with one idea: **keep each piece of data together with the code
that is allowed to change it, and model the program on the things in the problem
domain.** Such a bundle is called an **object**.

### Procedural vs object-oriented: the same problem twice

The problem: a student pays at the canteen with a campus card. The card has a balance.
The student can recharge it and pay with it, and a payment must be refused if the
balance is too low.

**Procedural (structured) style.** The data lives in plain variables. Separate functions
receive the data and change it.

```text
  data (anyone can touch it)          functions
+---------------------------+    +---------------------+
| balance = 120             | <--| recharge(balance, x)|
| owner   = "Rahim"         | <--| pay(balance, x)     |
+---------------------------+ <--| printReport(...)    |
            ^                    +---------------------+
            |
   any other function in the program can also write
   balance = -500  and nothing stops it
```

The design is a list of steps: "read the balance, subtract, store it back". It works,
but nothing protects the balance, and the rule "refuse if too low" must be repeated
wherever someone pays.

**Object-oriented style.** We ask: *what things exist in this problem?* There is a card.
The card *knows* its owner and balance, and *can* recharge and pay. Only the card
changes its own balance.

```text
               CampusCard object
        +-------------------------------+
        |  owner   = "Rahim"            |  <- data (hidden inside)
        |  balance = 120                |
        |-------------------------------|
  ----> |  recharge(amount)             |  <- the only ways in
  ----> |  pay(amount): refuses if low  |
  ----> |  getBalance()                 |
        +-------------------------------+
```

The rest of the program never writes to `balance`. It *asks* the card to pay, and the
card applies its own rule. If a bug corrupts the balance, there is only one place to
look.

| Question | Procedural | Object-oriented |
|---|---|---|
| How is the program organised? | Around steps (functions) | Around things (objects) |
| Where is the data? | Separate variables, passed around | Inside objects |
| Who may change data? | Any function | Only the object's own methods |
| Where are the rules? | Repeated in many functions | In one class |
| Adding a new kind of thing | Edit many functions | Add a new class |

OOP does not throw away procedural thinking. Inside each method you still write
step-by-step code with variables, `if` and loops. OOP decides *how those methods and
data are grouped*.

### Objects and messages

**The analogy.** At the canteen you say "one cup of tea, please". You do not walk into
the kitchen and boil the water yourself. The staff member receives your request,
does the work their own way, and gives you a reply (the tea).

**The programming model.** An object has:

- **state**: the data it holds (fields), for example a card's balance;
- **behaviour**: the things it can do (methods), for example `pay`;
- **identity**: it is one particular object, different from another object with the
  same data.

Calling a method on an object is **sending it a message**. The object that receives
the message decides how to respond, may change its own state, and may send back a
reply (a return value).

You already used this idea without noticing. In `System.out.println("Hi")`, the
object `System.out` (the standard output stream) receives the message `println` with
the argument `"Hi"`. Here is another message, sent to a `String` object:

```text
     main method                         String object
   +-------------+   toUpperCase()     +----------------+
   |             | ------------------> | text: "Rahim"  |
   |             |                     |                |
   |             | <------------------ |                |
   +-------------+   reply: "RAHIM"    +----------------+
```

The code is `name.toUpperCase()`: the receiver is `name`, the message is
`toUpperCase`, and the reply is a new string `"RAHIM"`. You do not know how
`toUpperCase` works inside, and you do not need to. That is the point.

### The four ideas of OOP

Each OOP idea exists because it solves a problem that programmers kept running into.
Learn the problem first; the definition then makes sense.

#### Encapsulation

**The problem:** data that any code can change ends up in invalid states (a negative
balance, a CGPA of 7.5), and the bug could be anywhere.

**The idea:** bundle the data and the methods that work on it into one unit (a class),
and hide the data so that it can only be changed through those methods. The methods
enforce the rules.

```text
   +--------- CampusCard ---------+
   |  [ balance ]  hidden         |
   |                              |
   |  pay()  recharge()  <- doors |
   +------------------------------+
   outside code uses the doors, never the balance directly
```

Covered in Chapter 05.

#### Abstraction

**The problem:** a large program has more detail than anyone can keep in their head.
If you had to understand how `Scanner` parses digits before reading one number, you
would never finish anything.

**The idea:** show *what* an object does and hide *how* it does it. You use an object
through a small set of clear methods.

```text
   what you see                  what is hidden
   +------------------+          +---------------------------+
   | in.nextInt()     |  ---->   | buffering, skipping       |
   | in.nextLine()    |          | spaces, parsing digits,   |
   +------------------+          | handling the keyboard ... |
                                 +---------------------------+
```

Every time you use `Scanner`, `String` or `Math` in this chapter, you are using
abstraction. Covered in Chapters 05 and 10.

#### Inheritance

**The problem:** similar kinds of things share a lot. A `Student` and a `Teacher` both
have a name, an ID and an email. Copying that code into both classes means fixing
every bug twice.

**The idea:** put the common part in a general class and let specific classes *extend*
it, adding only what is different. The relationship reads "a Student **is a** Person".

```text
                 +------------------+
                 | Person           |
                 | name, id, email  |
                 +------------------+
                   ^              ^
                   |   extends    |
         +------------------+  +------------------+
         | Student          |  | Teacher          |
         | cgpa, credits    |  | salary, courses  |
         +------------------+  +------------------+
```

Covered in Chapter 09.

#### Polymorphism

**The problem:** code fills up with checks like "if it is a circle, compute this; if it
is a rectangle, compute that". Adding a new shape means editing every such check.

**The idea:** send the *same message* to different objects and let each one respond in
its own way. The caller just says `area()`; each shape knows its own formula. A new
shape only needs a new class.

```text
                      area()
   caller  ---------------------------+------------------+
                     |                |                  |
                     v                v                  v
              +------------+   +-------------+   +-------------+
              | Circle     |   | Rectangle   |   | Triangle    |
              | pi * r * r |   | w * h       |   | b * h / 2   |
              +------------+   +-------------+   +-------------+
```

Covered in Chapter 10.

## 2. Syntax

### The structure of a Java program

Every Java program has at least one class, and execution starts in a method called
`main`.

```java
// File: Hello.java  (the file name must match the public class name)
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

| Part | Meaning |
|---|---|
| `public class Hello` | Declares a class named `Hello`. A `public` class must be saved in `Hello.java`. |
| `{ ... }` after the class | The class body. Everything in the program lives inside it. |
| `public static void main(String[] args)` | The entry point. The JVM calls this method first. |
| `public` | The JVM (outside code) is allowed to call it. |
| `static` | It can run without creating a `Hello` object first (Chapter 07). |
| `void` | It returns no value. |
| `String[] args` | Command-line arguments, as an array of strings (arrays: Chapter 08). |
| `System.out.println(...);` | A statement. Every statement ends with a semicolon. |

Rules that catch beginners:

- Java is **case-sensitive**: `System` is not `system`, and `main` is not `Main`.
- Braces `{ }` group code. Every `{` needs a matching `}`.
- Statements end with `;`. A class or method header does not.

> In a real project each public class lives in its own file; in this course we keep
> each program in one file so you can compile it with one command.

### Compiling and running

```text
$ javac Hello.java        compiles; creates Hello.class
$ java Hello              runs the class (no ".class" at the end)
Hello, Java!
```

Since Java 11 you can also run a single-file program directly with
`java Hello.java`; the launcher compiles it in memory first. It is convenient for quick
tests, but you should understand the two separate steps.

### Printing: `println` and `print`

```java
System.out.println("Line one");   // prints, then moves to a new line
System.out.print("Same ");        // prints, stays on the same line
System.out.print("line");
System.out.println();             // just ends the current line
```

`System.out` is an object that represents the screen (standard output). `println` and
`print` are messages you send to it.

### String literals and concatenation

A **string literal** is text in double quotes: `"Dhaka"`. The `+` operator joins
(concatenates) strings. If one side of `+` is a string, the other side is converted
to text first.

```java
System.out.println("CGPA: " + 3.75);        // CGPA: 3.75
System.out.println("Total: " + 40 + 25);    // Total: 4025  (text first!)
System.out.println("Total: " + (40 + 25));  // Total: 65
System.out.println(40 + 25 + " Tk");        // 65 Tk        (numbers first)
```

Java evaluates `+` from left to right. In the second line, `"Total: " + 40` is already
a string, so `25` is appended as text. Use parentheses when you want arithmetic.

### Comments

```java
// A single-line comment: ignored by the compiler.

/* A multi-line comment
   can span several lines. */

/** A documentation comment: the javadoc tool turns these into web pages. */
```

Write comments that explain *why*, not comments that repeat the code.

### Variables you will use in this chapter

Chapter 01 covers types in detail. For now three kinds are enough:

```java
int credits = 3;              // whole numbers
double cgpa = 3.75;           // numbers with a fractional part
String name = "Nusrat";       // text (a String is an object)
int fee = credits * 5500;     // arithmetic: + - * /
```

### Sending messages to objects

The general form of a method call is:

```java
receiver.methodName(arguments)
```

```java
String name = "Ayesha";
int letters = name.length();          // 6
String loud = name.toUpperCase();     // "AYESHA"
String part = name.substring(0, 3);   // "Aye"  (from index 0 up to, not including, 3)
int big = Math.max(17, 42);           // 42
double root = Math.sqrt(49);          // 7.0
```

- `name.length()` sends the message `length` to the `String` object `name`.
- `Math.max(17, 42)` is a little different: `Math` is a class that offers helper
  methods, and you call them with the class name. Chapter 07 explains these `static`
  methods.
- Parentheses are required even when there are no arguments: `name.length()`.

### Reading input with `Scanner`

`Scanner` is a ready-made object that reads input. You do not need to know how it works
inside. You create one, then send it messages.

```java
import java.util.Scanner;              // first line of the file, before the class

Scanner in = new Scanner(System.in);   // create a Scanner object reading the keyboard
int credits = in.nextInt();            // read a whole number
double cgpa = in.nextDouble();         // read a decimal number
String word = in.next();               // read one word (up to a space)
String line = in.nextLine();           // read the rest of the current line
```

`new Scanner(System.in)` creates a new object. Every `in.nextInt()` is a message to that
object. Chapter 01 explains `Scanner` properly, including one common trap with
`nextLine()`.

## 3. Worked Examples

### Example 1: Your First Program

**Problem:** Print a short welcome message for a new OOP course. Use both `println` and
`print`, and print one empty line between the parts.

Each `print` continues on the same line, so three `print` calls followed by a
`println` build a single line from pieces. `println()` with no argument prints just a
line break.

```java
public class Welcome {
    public static void main(String[] args) {
        // println ends the line; print does not
        System.out.println("Welcome to Object Oriented Programming!");
        System.out.print("Write once, ");
        System.out.print("run ");
        System.out.println("anywhere.");
        System.out.println();
        System.out.println("Trimester: Fall");
        System.out.println("Language: Java");
    }
}
```

**Output:**

```text
Welcome to Object Oriented Programming!
Write once, run anywhere.

Trimester: Fall
Language: Java
```

**Why it works:** The JVM calls `main`, which runs its statements from top to bottom.
Every statement is a message to the `System.out` object: `print` adds text, `println`
adds text and then a line break.

### Example 2: Shuttle Fare Calculator

**Problem:** The campus shuttle charges 25 Tk per trip. Fahim takes 2 trips a day for 5
days. Print the number of trips and the weekly cost, and show what goes wrong when the
`+` operator is used carelessly.

Store each value in a named variable, compute with `*`, and use parentheses whenever
arithmetic must happen inside a concatenation.

```java
public class ShuttleFare {
    public static void main(String[] args) {
        String rider = "Fahim";
        int farePerTrip = 25;
        int tripsPerDay = 2;
        int days = 5;

        int trips = tripsPerDay * days;
        int weeklyCost = trips * farePerTrip;

        System.out.println("Rider: " + rider);
        System.out.println("Trips this week: " + trips);
        System.out.println("Weekly cost: " + weeklyCost + " Tk");

        // Two weeks: compare with and without parentheses
        System.out.println("Careless: " + weeklyCost + weeklyCost + " Tk");
        System.out.println("Correct: " + (weeklyCost + weeklyCost) + " Tk");
    }
}
```

**Output:**

```text
Rider: Fahim
Trips this week: 10
Weekly cost: 250 Tk
Careless: 250250 Tk
Correct: 500 Tk
```

**Why it works:** `tripsPerDay * days` is pure arithmetic, so `trips` is `10`. In the
"Careless" line, `"Careless: " + weeklyCost` is already a string, so the second
`weeklyCost` is glued on as text. The parentheses in the last line force the addition
to happen first.

### Example 3: Sending Messages to a String

**Problem:** Given a student's full name, print it in upper case, count its characters,
print the first name, and build a short display name such as `N. Jahan`.

A `String` is an object, so we process it by sending messages: `length`,
`toUpperCase`, `indexOf` (where is the space?) and `substring` (cut a piece out).

```java
public class NameMessages {
    public static void main(String[] args) {
        String fullName = "Nusrat Jahan";

        int space = fullName.indexOf(" ");             // position of the space: 6
        String firstName = fullName.substring(0, space);
        String lastName = fullName.substring(space + 1);
        String initial = fullName.substring(0, 1);

        System.out.println("Full name: " + fullName);
        System.out.println("Upper case: " + fullName.toUpperCase());
        System.out.println("Characters: " + fullName.length());
        System.out.println("First name: " + firstName);
        System.out.println("Display name: " + initial + ". " + lastName);
        System.out.println("Unchanged: " + fullName);
    }
}
```

**Output:**

```text
Full name: Nusrat Jahan
Upper case: NUSRAT JAHAN
Characters: 12
First name: Nusrat
Display name: N. Jahan
Unchanged: Nusrat Jahan
```

**Why it works:** Positions (indexes) in a string start at 0, so the space in
`"Nusrat Jahan"` is at index 6. `substring(0, space)` takes indexes 0 to 5, and
`substring(space + 1)` takes everything after the space. The last line shows that the
messages never changed `fullName`: each method returned a *new* string. Java strings
are immutable (they cannot be changed after creation).

### Example 4: Course Fee With Scanner

**Problem:** Read a student's name, the number of credits taken this trimester and the
fee per credit. Print a short fee statement.

The `Scanner` object does the reading. We read the name with `nextLine()` first (a name
may contain spaces), then the two numbers with `nextInt()`.

```java
import java.util.Scanner;

public class CourseFee {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);

        System.out.println("Student name:");
        String name = in.nextLine();
        System.out.println("Credits this trimester:");
        int credits = in.nextInt();
        System.out.println("Fee per credit (Tk):");
        int feePerCredit = in.nextInt();

        int tuition = credits * feePerCredit;

        System.out.println("--- Fee statement ---");
        System.out.println("Student: " + name);
        System.out.println("Credits: " + credits);
        System.out.println("Tuition: " + tuition + " Tk");
    }
}
```

**Input:**

```text
Tanvir Ahmed
12
5500
```

**Output:**

```text
Student name:
Credits this trimester:
Fee per credit (Tk):
--- Fee statement ---
Student: Tanvir Ahmed
Credits: 12
Tuition: 66000 Tk
```

**Why it works:** `new Scanner(System.in)` creates an object connected to the keyboard.
Each `nextLine()` or `nextInt()` is a message asking it for the next piece of input.
We never see how it reads characters or converts `"5500"` into the number `5500`; that
hidden detail is abstraction at work. (The Output block shows only what the program
prints; the lines you type are not part of it.)

### Example 5: Distance Across the Campus

**Problem:** On a campus map, the library is at point (100, 200) and the hostel is at
point (400, 600), in metres. Print the straight-line distance, the walking distance
along the grid of paths, and the larger of the two coordinate gaps.

The straight-line distance comes from Pythagoras:
`sqrt(dx * dx + dy * dy)`. Walking along paths that run only east-west and
north-south covers `dx + dy`. The `Math` class provides `sqrt`, `abs` and `max`.

```java
public class CampusDistance {
    public static void main(String[] args) {
        int libraryX = 100;
        int libraryY = 200;
        int hostelX = 400;
        int hostelY = 600;

        // Math.abs makes the gaps positive, whichever point comes first
        int dx = Math.abs(hostelX - libraryX);
        int dy = Math.abs(hostelY - libraryY);

        double straight = Math.sqrt(dx * dx + dy * dy);
        int walking = dx + dy;

        System.out.println("East-west gap: " + dx + " m");
        System.out.println("North-south gap: " + dy + " m");
        System.out.println("Straight line: " + straight + " m");
        System.out.println("Walking on paths: " + walking + " m");
        System.out.println("Larger gap: " + Math.max(dx, dy) + " m");
    }
}
```

**Output:**

```text
East-west gap: 300 m
North-south gap: 400 m
Straight line: 500.0 m
Walking on paths: 700 m
Larger gap: 400 m
```

**Why it works:** `Math.sqrt` returns a `double`, so the result prints as `500.0`.
`Math.abs` and `Math.max` work with `int` values and return `int` results. We use
these methods without knowing how square roots are computed inside, exactly as we
use any other object's methods.

## Common Mistakes

- **File name does not match the public class.** `public class Hello` must be saved in
  `Hello.java`, or `javac` reports an error.
- **Wrong capital letters.** `system.out.println` does not compile, because the class
  is called `System`. A method named `Main` compiles, but the JVM cannot start the
  program: it looks for a method named exactly `main`.
- **Missing semicolon.** `System.out.println("Hi")` without `;` is a compile error.
- **Running the `.class` file name.** Use `java Hello`, not `java Hello.class`.
- **Concatenation instead of addition.** `"Sum: " + a + b` joins the digits. Write
  `"Sum: " + (a + b)`.
- **Forgetting the parentheses of a method call.** `name.length` is an error for a
  `String`; you must send the message: `name.length()`.
- **Single quotes for text.** `'Hello'` is not a string. Strings use double quotes;
  single quotes are for one character (Chapter 01).
- **Thinking a method changed a string.** `name.toUpperCase();` alone does nothing
  useful: it returns a new string, and `name` is unchanged. Store or print the result.

## Summary

- Java is an object-oriented language whose source code is compiled by `javac` into
  bytecode (`.class` files) that the JVM runs with `java`.
- JVM runs bytecode; JRE = JVM + standard library; JDK = JRE + development tools.
- "Write once, run anywhere": one `.class` file runs on any platform that has a JVM.
- Compared with C, Java adds classes, automatic memory management, references instead
  of raw pointers, checked array indexes and a real `boolean` type.
- A program is a class containing `public static void main(String[] args)`; statements
  end with `;` and blocks are grouped by braces.
- `+` adds numbers but joins text; it is evaluated left to right, so use parentheses
  for arithmetic inside a message.
- OOP exists to manage growing programs: it keeps data together with the code allowed
  to change it, and models the program on the things in the problem.
- An object has state, behaviour and identity; calling a method is sending a message
  to an object, which decides how to respond.
- Encapsulation protects data, abstraction hides detail, inheritance shares common
  code, and polymorphism lets different objects answer the same message in their own
  way.
- `String`, `Math` and `Scanner` are ready-made: you use them through their methods
  without knowing how they work inside.
