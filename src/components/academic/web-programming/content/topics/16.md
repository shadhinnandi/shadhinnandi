# SQL Aggregation, Grouping and Joins

Same **`uiu_demo`** data as topic 15. Every output was produced on MariaDB 10.4.

## Aggregate functions

An aggregate function turns many rows into **one value**.

| Function | Gives |
|---|---|
| `COUNT(*)` | Number of rows |
| `COUNT(column)` | Number of rows where the column is not NULL |
| `SUM(column)` | Total |
| `AVG(column)` | Average |
| `MAX(column)` / `MIN(column)` | Largest / smallest |

```sql
SELECT AVG(cgpa) AS avg_cgpa, MAX(cgpa) AS highest,
       MIN(cgpa) AS lowest, SUM(credits) AS total_credits
FROM students;
```

```text
+----------+---------+--------+---------------+
| avg_cgpa | highest | lowest | total_credits |
+----------+---------+--------+---------------+
| 3.291667 |    3.85 |   2.70 |           400 |
+----------+---------+--------+---------------+
```

`ROUND(AVG(cgpa), 2)` gives `3.29`.

## GROUP BY: one result row per group

```sql
SELECT dept_code, COUNT(*) AS students, ROUND(AVG(cgpa), 2) AS avg_cgpa,
       SUM(credits) AS credits
FROM students
GROUP BY dept_code
ORDER BY students DESC;
```

```text
+-----------+----------+----------+---------+
| dept_code | students | avg_cgpa | credits |
+-----------+----------+----------+---------+
| CSE       |        3 |     3.27 |     195 |
| EEE       |        2 |     3.05 |     105 |
| BBA       |        1 |     3.85 |     100 |
+-----------+----------+----------+---------+
```

Rule: every column in `SELECT` is either **in the GROUP BY** or **inside an aggregate**.

Typical exam wording and the query shape:

| The question says | SQL |
|---|---|
| "count the number of X **for each** Y" | `SELECT Y, COUNT(*) FROM t GROUP BY Y` |
| "total revenue **per** category" | `SELECT category, SUM(revenue) ... GROUP BY category` |
| "average **of each** product" | `SELECT product, AVG(qty) ... GROUP BY product` |
| "... in descending order of the count" | add `ORDER BY COUNT(*) DESC` |

## HAVING: filter groups

`WHERE` filters **rows before** grouping. `HAVING` filters **groups after** grouping, so it can use `COUNT`, `SUM`, `AVG`.

```sql
SELECT city, COUNT(*) AS students
FROM students
GROUP BY city
HAVING COUNT(*) > 1;
```

```text
+-------+----------+
| city  | students |
+-------+----------+
| Dhaka |        3 |
+-------+----------+
```

Both together:

```sql
SELECT dept_code, ROUND(AVG(cgpa), 2) AS avg_cgpa
FROM students
WHERE credits >= 45              -- 1. drop rows (Tanvir, 30 credits)
GROUP BY dept_code               -- 2. make groups
HAVING AVG(cgpa) > 3.0           -- 3. drop groups
ORDER BY avg_cgpa DESC;          -- 4. sort what is left
```

```text
+-----------+----------+
| dept_code | avg_cgpa |
+-----------+----------+
| BBA       |     3.85 |
| EEE       |     3.40 |
| CSE       |     3.27 |
+-----------+----------+
```

## Full clause order

```sql
SELECT ... FROM ... JOIN ... ON ...
WHERE ...
GROUP BY ...
HAVING ...
ORDER BY ...
LIMIT ...;
```

## CASE: if / else inside SQL

```sql
SELECT name, cgpa,
       CASE
           WHEN cgpa >= 3.5 THEN 'Excellent'
           WHEN cgpa >= 3.0 THEN 'Good'
           ELSE 'Needs work'
       END AS standing
FROM students;
```

```text
+----------------+------+------------+
| name           | cgpa | standing   |
+----------------+------+------------+
| Karim Uddin    | 3.75 | Excellent  |
| Rahima Akter   | 3.40 | Good       |
| Jashim Hossain | 2.95 | Needs work |
| Faria Karim    | 3.85 | Excellent  |
| Nadia Islam    | 3.10 | Good       |
| Tanvir Ahmed   | 2.70 | Needs work |
+----------------+------+------------+
```

**CASE in an UPDATE** changes different rows in different ways in **one** statement, so no row is changed twice:

```sql
UPDATE students
SET credits = CASE
    WHEN cgpa >= 3.5 THEN credits + 10
    ELSE credits + 5
END;
```

Running two separate UPDATEs (first `+10 WHERE cgpa >= 3.5`, then `+5 WHERE ...`) is fine here, but when the first update changes the column the second one tests (e.g. "decrease salaries over 10000 by 10%, increase the rest by 10%"), a row can be caught twice. One CASE avoids that.

## Counting groups that may be empty

`GROUP BY` only shows groups that **have** rows. To also show zero counts, either count each value with a condition:

```sql
SELECT SUM(cgpa >= 3.5) AS excellent,
       SUM(cgpa >= 3.0 AND cgpa < 3.5) AS good,
       SUM(cgpa < 3.0) AS needs_work
FROM students;
```

```text
+-----------+------+------------+
| excellent | good | needs_work |
+-----------+------+------------+
|         2 |    2 |          2 |
+-----------+------+------------+
```

(In MySQL a condition is 1 when true and 0 when false, so `SUM(condition)` counts matches.)

or LEFT JOIN from the full list (next section).

## JOIN: combine tables

```sql
SELECT s.name, d.dept_name
FROM students s
INNER JOIN departments d ON s.dept_code = d.dept_code;
```

```text
+----------------+---------------------------------------+
| name           | dept_name                             |
+----------------+---------------------------------------+
| Karim Uddin    | Computer Science and Engineering      |
| Rahima Akter   | Electrical and Electronic Engineering |
| Jashim Hossain | Computer Science and Engineering      |
| Faria Karim    | Business Administration               |
| Nadia Islam    | Computer Science and Engineering      |
| Tanvir Ahmed   | Electrical and Electronic Engineering |
+----------------+---------------------------------------+
```

`s` and `d` are **table aliases** (short names). `ON` says which columns match.

| Join | Keeps |
|---|---|
| `INNER JOIN` | Only rows that match in both tables |
| `LEFT JOIN` | Every row of the left table; NULL where the right has no match |
| `RIGHT JOIN` | Every row of the right table |

**LEFT JOIN to include zero counts:**

```sql
SELECT d.dept_name, COUNT(s.id) AS students
FROM departments d
LEFT JOIN students s ON s.dept_code = d.dept_code
GROUP BY d.dept_code, d.dept_name
ORDER BY students DESC;
```

```text
+---------------------------------------+----------+
| dept_name                             | students |
+---------------------------------------+----------+
| Computer Science and Engineering      |        3 |
| Electrical and Electronic Engineering |        2 |
| Business Administration               |        1 |
| Civil Engineering                     |        0 |
+---------------------------------------+----------+
```

Count `COUNT(s.id)`, not `COUNT(*)`: `COUNT(*)` would count Civil Engineering's empty joined row as 1.

## Subqueries

A query inside another query.

```sql
-- students above the overall average (3.29)
SELECT name, cgpa FROM students
WHERE cgpa > (SELECT AVG(cgpa) FROM students);
```

```text
+--------------+------+
| name         | cgpa |
+--------------+------+
| Karim Uddin  | 3.75 |
| Rahima Akter | 3.40 |
| Faria Karim  | 3.85 |
+--------------+------+
```

A **correlated subquery** uses the outer row, so it runs once per row: "above the average **of their own** department".

```sql
SELECT s.name, s.dept_code, s.cgpa
FROM students s
WHERE s.cgpa > (SELECT AVG(s2.cgpa) FROM students s2
                WHERE s2.dept_code = s.dept_code);
```

```text
+--------------+-----------+------+
| name         | dept_code | cgpa |
+--------------+-----------+------+
| Karim Uddin  | CSE       | 3.75 |
| Rahima Akter | EEE       | 3.40 |
+--------------+-----------+------+
```

(CSE average 3.27, EEE average 3.05; Faria is alone in BBA, so she equals her average and is not "above" it.)

## UPDATE with ORDER BY and LIMIT

"Give the **most recently hired** employee a raise" changes exactly one row:

```sql
UPDATE employee SET SALARY = SALARY * 1.175 ORDER BY HIRE_DATE DESC LIMIT 1;
```

MySQL and MariaDB allow `ORDER BY` + `LIMIT` in a single-table UPDATE.

## Query cookbook

| Need | Query |
|---|---|
| All rows | `SELECT * FROM t;` |
| Rows matching two conditions | `SELECT * FROM t WHERE a > 5 AND b = 'X';` |
| Text contains a word | `WHERE name LIKE '%Beach%'` |
| Range, both ends included | `WHERE n BETWEEN 4.0 AND 4.5` |
| Top 3 by a column | `ORDER BY col DESC LIMIT 3` |
| Single highest row | `ORDER BY col DESC LIMIT 1` |
| Count all rows | `SELECT COUNT(*) FROM t;` |
| Count per group | `SELECT g, COUNT(*) FROM t GROUP BY g;` |
| Count per group, largest first | `... GROUP BY g ORDER BY COUNT(*) DESC;` |
| Groups with more than one row | `... GROUP BY g HAVING COUNT(*) > 1;` |
| Total per group | `SELECT g, SUM(x) FROM t GROUP BY g;` |
| Total of a product of columns | `SELECT SUM(price * stock) FROM t;` |
| Average per group, 2 decimals | `SELECT g, ROUND(AVG(x), 2) FROM t GROUP BY g;` |
| Dates in a month | `WHERE d BETWEEN '2024-01-01' AND '2024-01-31'` |
| Percentage of the total | `SELECT x, ROUND(x * 100 / (SELECT SUM(x) FROM t), 2) AS pct FROM t;` |
| Label rows | `CASE WHEN ... THEN ... ELSE ... END AS label` |
| Above own group's average | correlated subquery (above) |
| Raise by 10% | `UPDATE t SET x = x * 1.10 WHERE ...;` |
| Raise only if it stays under a cap | `UPDATE t SET x = x + 5 WHERE x > 80 AND x + 5 <= 90;` |
| Two different changes at once | `UPDATE t SET x = CASE WHEN ... THEN ... ELSE ... END;` |
| One row by rank | `UPDATE t SET ... ORDER BY d DESC LIMIT 1;` |

## Common mistakes

- `WHERE COUNT(*) > 1`: aggregates belong in `HAVING`.
- Selecting a column that is neither grouped nor aggregated.
- Forgetting groups with zero rows when the question says "count for **each** grade".
- `COUNT(*)` after a LEFT JOIN (counts the empty match as 1).
- Doing two dependent UPDATEs when one CASE was needed.
