# PHP Forms with POST

## The rule for this course

**Every form sends its data with POST**, and PHP reads it from **`$_POST`**. POST sends the values inside the request body, so they do not appear in the address bar, they are not saved in browser history, and there is no small size limit. Every example and every exam answer on this site uses POST.

## How a form reaches PHP

1. The form tag says **where** to send (`action`) and **how** (`method="POST"`).
2. Each input has a **`name`**. That name becomes the key in `$_POST`.
3. The user clicks the submit button. The browser sends `name=value` pairs.
4. PHP reads `$_POST["name"]`, calculates and echoes the result.

## id vs name

| | `id` | `name` |
|---|---|---|
| Used by | JavaScript and CSS | The form submission (PHP) |
| Read with | `document.getElementById("hours")` | `$_POST["hours"]` |
| Must be unique? | Yes, on the page | No (radio buttons in a group share one name) |
| Sent to the server? | No | Yes |

An input **without a `name` is not sent**. It is common to give both the same value: `<input type="number" id="hours" name="hours">`.

## A complete single-file form

The form posts to the **same file**. Leaving `action` empty (or setting `action=""`) means "this page".

```php
<!DOCTYPE html>
<html>
<head>
    <title>Add Two Numbers</title>
</head>
<body>
    <form method="POST" action="">
        <label>First number:</label>
        <input type="number" name="a" required><br><br>
        <label>Second number:</label>
        <input type="number" name="b" required><br><br>
        <input type="submit" name="submit" value="Add">
    </form>

    <?php
    if (isset($_POST["submit"])) {
        $a = (int) $_POST["a"];
        $b = (int) $_POST["b"];
        echo "<p>$a + $b = " . ($a + $b) . "</p>";
    }
    ?>
</body>
</html>
```

- `isset($_POST["submit"])` is **false** on the first visit (nothing submitted), so no result shows until the button is clicked.
- `(int)` / `(float)` convert the text to numbers.

Another common check is the request method:

```php
<?php
if ($_SERVER["REQUEST_METHOD"] === "POST") {
    // the form was submitted
}
```

## Two files: form + processor

Some questions ask for `index.html` and `result.php` separately (241 Q3):

```html
<!-- index.html -->
<form method="POST" action="result.php">
    <input type="text" name="city">
    <input type="submit" value="Send">
</form>
```

```php
<?php
// result.php
$city = $_POST["city"] ?? "";
echo "You chose " . htmlspecialchars($city);
```

`$_POST["city"] ?? ""` means "the value, or an empty string if it is missing" (no warning).

## Reading every input type

```php
<form method="POST" action="">
    <input type="text" name="name">
    <input type="number" name="units" step="any">
    <input type="password" name="password">

    <select name="location">
        <option value="">-- Select --</option>
        <option value="Dhaka">Dhaka</option>
        <option value="Chittagong">Chittagong</option>
    </select>

    <input type="radio" name="area" value="Urban"> Urban
    <input type="radio" name="area" value="Rural"> Rural

    <input type="checkbox" name="topics[]" value="PHP"> PHP
    <input type="checkbox" name="topics[]" value="SQL"> SQL

    <textarea name="note"></textarea>
    <button type="submit" name="submit">Submit</button>
</form>
```

```php
<?php
if (isset($_POST["submit"])) {
    $name = trim($_POST["name"] ?? "");
    $units = (float) ($_POST["units"] ?? 0);
    $location = $_POST["location"] ?? "";
    $area = $_POST["area"] ?? "";            // missing if no radio chosen
    $topics = $_POST["topics"] ?? [];        // an array because of []
    $note = $_POST["note"] ?? "";
}
```

## Validation

```php
<?php
$errors = [];
if ($name === "") $errors[] = "Name is required.";
if ($units <= 0) $errors[] = "Units must be positive.";
if (!in_array($location, ["Dhaka", "Chittagong"])) $errors[] = "Choose a location.";

if ($errors) {
    foreach ($errors as $e) echo "<p>$e</p>";
} else {
    // calculate and show the result
}
```

Browser checks like `required` and `min="1"` help the user, but **always check again in PHP**: anyone can send a request without your form.

## htmlspecialchars: output safely

When you echo something the user typed, wrap it in **`htmlspecialchars()`**. It turns `<` into `&lt;` and `>` into `&gt;`, so typed HTML or script is shown as text instead of running.

```php
<?php
$name = $_POST["name"] ?? "";
echo "Hello, " . htmlspecialchars($name);
// typing <b>Karim</b> shows the tags as text, not bold
```

Numbers you cast with `(int)` / `(float)` are already safe.

## Keeping the typed value after submit

```php
<input type="number" name="hours" value="<?= htmlspecialchars($_POST["hours"] ?? "") ?>">
```

## Showing results in a table

```php
<?php
echo "<table border='1' cellpadding='8'>";
echo "<tr><th>Item</th><th>Value</th></tr>";
echo "<tr><td>Pizzas needed</td><td>$pizzas</td></tr>";
echo "<tr><td>Leftover slices</td><td>$leftover</td></tr>";
echo "</table>";
```

## Common mistakes

- No `name` on an input: it never reaches `$_POST`.
- `$_POST["Name"]` vs `name="name"`: keys are case-sensitive.
- Reading `$_POST` values before checking the form was submitted (warnings on first load).
- Forgetting `method="POST"` on the form tag. Without it the browser uses its default, and `$_POST` stays empty.
- Echoing user input without `htmlspecialchars()`.
