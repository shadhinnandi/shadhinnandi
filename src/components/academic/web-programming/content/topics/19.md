# Database Exam Practice

Question 3 (Question 4 in Summer 2024) is the database question, and it has the same shape in every paper since Fall 2023.

## The shape of the question

1. **Create** a database and one table, and fill it with the rows printed in the paper.
2. Do **3 to 5 tasks** on it, usually a mix of:
   - a **report** (count, total or average per group),
   - a **conditional update** ("if ... change ... to ..."),
   - a **capped update** ("add 5, but only if the result is at most 90"),
   - a **sorted / filtered list** ("most popular first", "only groups with more than 1").
3. "Write full PHP–MySQL code": the answer must be a **PHP page that runs the SQL and shows the results**, not only the queries.

## What to submit

| File | Contains |
|---|---|
| `setup.sql` (or an Export from phpMyAdmin) | `CREATE DATABASE`, `CREATE TABLE`, `INSERT` |
| `index.php` | Connection, the tasks, the results as HTML tables |

## The answer template

Every database answer on this site follows this template. Learn it once and only the SQL changes.

```php
<?php
mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);
$conn = new mysqli("localhost", "root", "", "your_database");
$conn->set_charset("utf8mb4");

// Prints any SELECT result as an HTML table
function showTable($result) {
    if ($result->num_rows === 0) {
        echo "<p>No rows found.</p>";
        return;
    }
    echo "<table border='1' cellpadding='6'><tr>";
    foreach ($result->fetch_fields() as $field) {
        echo "<th>" . htmlspecialchars($field->name) . "</th>";
    }
    echo "</tr>";
    while ($row = $result->fetch_assoc()) {
        echo "<tr>";
        foreach ($row as $value) {
            echo "<td>" . htmlspecialchars((string) $value) . "</td>";
        }
        echo "</tr>";
    }
    echo "</table>";
}

$message = "";
$task = $_POST["task"] ?? "";

// Updates run only when their button is pressed
if ($task === "2") {
    $limit = 75;
    $stmt = $conn->prepare("UPDATE your_table SET LetterGrade = 'C' WHERE Grade < ? AND LetterGrade <> 'D'");
    $stmt->bind_param("i", $limit);
    $stmt->execute();
    $message = "Task 2: " . $stmt->affected_rows . " row(s) changed.";
}
?>
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Final Exam: Question 3</title>
</head>
<body>
    <form method="POST" action="">
        <button type="submit" name="task" value="2">Run task 2</button>
    </form>
    <p><?= htmlspecialchars($message) ?></p>

    <h2>All rows</h2>
    <?php showTable($conn->query("SELECT * FROM your_table")); ?>

    <h2>1) Report</h2>
    <?php showTable($conn->query("SELECT LetterGrade, COUNT(*) AS Total FROM your_table GROUP BY LetterGrade")); ?>
</body>
</html>
<?php
$conn->close();
```

**Why the updates are behind POST buttons:** a page that runs `UPDATE` every time it loads changes the data again on every refresh (a 5% raise becomes 10%, then 15%...). With a button, opening the page only **reads**, and data changes only when you choose.

**Why prepared statements here:** the thresholds (75, 40000, 1.10...) are bound with `bind_param`, the same way you must bind anything a user types (topic 17). In the exam, writing the numbers directly into `$conn->query()` is also accepted, because none of these values comes from a user.

## Order matters

The tasks are numbered, and later tasks see the data **after** earlier updates:

- **233:** the paper's 27.65% for SKING is from the **original** salaries; after task 2 it is 31.46%.
- **253:** before task 2, task 1 shows Overdue 3 and Returned 2; after it, Grace Period 2 and Returned 2.
- **261 Set A:** before task 2, Heritage averages exactly 4.40 and is excluded from task 3; after it, Heritage averages 4.50 and appears.

When a printed example disagrees with your output, check whether the example used the data before or after an update, and say so in your answer.

## Exam-day checklist

1. Start **Apache** and **MySQL** in XAMPP.
2. phpMyAdmin → **SQL** tab → paste `CREATE DATABASE`, `CREATE TABLE`, `INSERT`. Check with `SELECT *`.
3. Use exact names from the paper (`uiuweb_final`, `student_final`, `LetterGrade`...).
4. Pick column types: whole numbers `INT`, money and ratings `DECIMAL`, text `VARCHAR`, dates `DATE`.
5. Text with an apostrophe: `'Cox''s Bazar Beach'`.
6. **Test each query in phpMyAdmin first**, then copy it into PHP.
7. Copy the template, change the database name, add one block per task.
8. Show the full table on the page so the effect of updates is visible.
9. Open http://localhost/your-folder/ and press each update button **once**.
10. Export the database if the paper asks for a .sql file.

## Mistakes that cost marks

- `WHERE COUNT(*) > 1` instead of `HAVING`.
- Missing a group with zero rows when the question lists the values (A, B, C, **D**).
- Two separate UPDATEs where one CASE was needed (rows changed twice).
- `Grade > 80` written as `>= 80` ("greater than" excludes 80).
- Updates that run on every page load.
- Forgetting the cap condition (`AND x + 5 <= 90`).
- `FLOAT` for ratings, so `AVG()` and `BETWEEN` give unexpected results.
