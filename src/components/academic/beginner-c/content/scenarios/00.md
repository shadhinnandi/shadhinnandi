## Problem 1: Daily Commute Cost
**Level:** Moderate

### Scenario
Nadia lives in Mirpur and attends classes five days a week. Every class day she takes a rickshaw from home to the bus stop, then a bus to campus, and makes the same trip back in the evening. She wants to know how much she spends on travel each day and each week.

### Problem Statement
Design an algorithm, and then a program, that reads two whole numbers: the one-way rickshaw fare and the one-way bus fare (in taka). It must print:

- the daily travel cost (both trips, rickshaw and bus each way), and
- the weekly travel cost for 5 class days.

Use only a sequence of steps: input → calculate → output. No decisions are needed.

Print exactly:
```text
Daily cost: <daily> Tk
Weekly cost: <weekly> Tk
```

### Sample Input
```text
30 40
```

### Sample Output
```text
Daily cost: 140 Tk
Weekly cost: 700 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int rickshaw, bus;
    scanf("%d %d", &rickshaw, &bus);

    int daily = 2 * (rickshaw + bus);   /* there and back */
    int weekly = daily * 5;             /* 5 class days */

    printf("Daily cost: %d Tk\n", daily);
    printf("Weekly cost: %d Tk\n", weekly);
    return 0;
}
```

### Explanation
**Algorithm**

1. Start.
2. Read the rickshaw fare and the bus fare.
3. One trip costs `rickshaw + bus`. A day has two trips, so `daily = 2 × (rickshaw + bus)`.
4. `weekly = daily × 5`.
5. Print both values. End.

**Flowchart**
```text
[START] -> [Read rickshaw, bus] -> [daily = 2 x (rickshaw + bus)]
        -> [weekly = daily x 5] -> [Print daily, weekly] -> [END]
```

**Dry run** with `30 40`: one trip = 70, daily = 140, weekly = 700. The common mistake is forgetting the return trip and getting 70 and 350.

### Concepts Practiced
- Algorithm design: sequence of steps
- Flowchart
- Dry run
- Variables and arithmetic (preview)



#### Walks to the bus stop (rickshaw fare 0)
**Input**
```text

```
**Expected Output**
```text

```

## Problem 2: Tea Stall Change
**Level:** Moderate

### Scenario
Between classes, friends crowd around a tea stall near the campus gate. A cup of tea costs 15 Tk and a singara costs 10 Tk. The stall owner wants a quick way to work out the bill and the change, and to notice when a customer has not paid enough.

### Problem Statement
Read three whole numbers: the number of cups of tea, the number of singaras, and the amount the customer hands over. Calculate the bill. Then make one decision:

- If the amount paid is at least the bill, print the change.
- Otherwise, print how much more money is needed.

Print exactly:
```text
Total bill: <bill> Tk
Change: <change> Tk
```
or, when the payment is short:
```text
Total bill: <bill> Tk
Not enough money. Short by <shortfall> Tk
```

### Sample Input
```text
3 4 100
```

### Sample Output
```text
Total bill: 85 Tk
Change: 15 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int tea, singara, paid;
    scanf("%d %d %d", &tea, &singara, &paid);

    int bill = tea * 15 + singara * 10;
    printf("Total bill: %d Tk\n", bill);

    if (paid >= bill) {
        printf("Change: %d Tk\n", paid - bill);
    } else {
        printf("Not enough money. Short by %d Tk\n", bill - paid);
    }
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `tea`, `singara` and `paid`.
2. `bill = tea × 15 + singara × 10`.
3. Print the bill.
4. Decision: is `paid ≥ bill`?
   - Yes: print `paid − bill` as the change.
   - No: print `bill − paid` as the shortfall.

**Flowchart**
```text
[Read tea, singara, paid] -> [bill = tea x 15 + singara x 10] -> [Print bill]
                                       |
                              <paid >= bill ?>
                         YES /                \ NO
           [Print change = paid - bill]   [Print short = bill - paid]
```

Note the decision uses `>=`, not `>`: paying the exact amount is fine and gives 0 change.

### Concepts Practiced
- Algorithm design: sequence and one decision
- Flowchart with a decision diamond
- Choosing the correct comparison (`>=` vs `>`)
- if-else (preview)

### Test Cases
#### Exact payment
**Input**
```text
2 0 30
```
**Expected Output**
```text

Change: 0 Tk
```

#### Customer pays too little
**Input**
```text
5 5 100
```
**Expected Output**
```text

Not enough money. Short by 25 Tk
```

## Problem 3: Best Two of Three Quizzes
**Level:** Intermediate

### Scenario
In a first-trimester programming course, students sit three class quizzes (each out of 20). Only the best two count: the lowest quiz is dropped and the other two are averaged. Students often get this calculation wrong when checking their own marks.

### Problem Statement
Read three whole-number quiz marks. Find the lowest mark, then the average of the remaining two. Your algorithm must work whichever quiz is the lowest, including when two or three marks are equal.

Print exactly:
```text
Lowest quiz dropped: <lowest>
Best-two average: <average with 2 decimals>
```

Hint for the algorithm: you do not need to know *which* two marks are the best. Think about the total.

### Sample Input
```text
18 12 17
```

### Sample Output
```text
Lowest quiz dropped: 12
Best-two average: 17.50
```

### Solution
```c
#include <stdio.h>

int main() {
    int q1, q2, q3;
    scanf("%d %d %d", &q1, &q2, &q3);

    int lowest = q1;
    if (q2 < lowest) lowest = q2;
    if (q3 < lowest) lowest = q3;

    int bestTwoTotal = q1 + q2 + q3 - lowest;
    double average = bestTwoTotal / 2.0;

    printf("Lowest quiz dropped: %d\n", lowest);
    printf("Best-two average: %.2f\n", average);
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `q1`, `q2`, `q3`.
2. Assume `lowest = q1`.
3. If `q2 < lowest`, set `lowest = q2`. If `q3 < lowest`, set `lowest = q3`.
4. The best two add up to `(q1 + q2 + q3) − lowest`.
5. Divide by 2 (as a decimal division) and print.

**Dry run** with `18 12 17`: lowest starts at 18, becomes 12 (12 < 18), stays 12 (17 is not < 12). Best-two total = 47 − 12 = 35, average = 17.50.

Dividing by `2.0` instead of `2` keeps the half mark: `35 / 2` in whole numbers would give 17, which is wrong.

### Concepts Practiced
- Algorithm design: finding a minimum step by step
- Dry run
- Total-minus-lowest trick
- Decimal vs whole-number division (preview)

### Test Cases

**Expected Output**
```text

```

#### Lowest is the first quiz (missed quiz = 0)
**Input**
```text

```
**Expected Output**
```text

```

## Problem 4: Library Late Fine
**Level:** Intermediate

### Scenario
The university library lends books for 14 days. A book kept longer is late. The fine is 5 Tk for each of the first 7 late days, and 10 Tk for every late day after that. The front-desk assistant calculates fines by hand and wants a reliable step-by-step method.

### Problem Statement
Read the number of days a student kept the book (a whole number, 0 or more). Work out the number of late days (never negative) and the fine under the rule above.

Print exactly:
```text
Days late: <late days>
Fine: <fine> Tk
```

### Sample Input
```text
25
```

### Sample Output
```text
Days late: 11
Fine: 75 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int daysKept;
    scanf("%d", &daysKept);

    int late = daysKept - 14;
    if (late < 0) late = 0;            /* returned on time */

    int fine;
    if (late <= 7) {
        fine = late * 5;
    } else {
        fine = 7 * 5 + (late - 7) * 10;
    }

    printf("Days late: %d\n", late);
    printf("Fine: %d Tk\n", fine);
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `daysKept`.
2. `late = daysKept − 14`. If `late` is negative, the book came back early, so set `late = 0`.
3. Decision: is `late ≤ 7`?
   - Yes: `fine = late × 5`.
   - No: the first 7 days cost `7 × 5 = 35`, the rest cost `(late − 7) × 10`.
4. Print both values.

**Dry run** with 25: late = 11. Since 11 > 7, fine = 35 + 4 × 10 = 75.

Notice the boundary: on day 7 of lateness the fine is 35, and on day 8 it is 45. Checking `late ≤ 7` rather than `late < 7` puts day 7 in the cheaper band, as the rule says.

### Concepts Practiced
- Algorithm design with decisions
- Tiered (slab) calculation
- Boundary values
- if-else (preview)

**Expected Output**
```text

```

**Input**
```text

```


## Problem 5: Exam Seat Finder
**Level:** Intermediate

### Scenario
For the mid-term exam, students are seated by roll number. Each exam room holds 30 students. Rolls 1–30 sit in room 101, rolls 31–60 in room 102, and so on. Inside a room, seats are numbered 1 to 30 in roll order. Students keep asking the invigilators where to sit.

### Problem Statement
Read a roll number. If it is less than 1, print `Invalid roll number`. Otherwise print the room and seat number using arithmetic only (no list of rooms).

Print exactly:
```text
Room: <room>
Seat: <seat>
```

Think carefully about rolls 30 and 31: they must land in different rooms.

### Sample Input
```text
75
```

### Sample Output
```text
Room: 103
Seat: 15
```

### Solution
```c
#include <stdio.h>

int main() {
    int roll;
    scanf("%d", &roll);

    if (roll < 1) {
        printf("Invalid roll number\n");
        return 0;
    }

    int position = roll - 1;            /* count from 0 */
    int room = 101 + position / 30;     /* whole-number division */
    int seat = position % 30 + 1;       /* remainder */

    printf("Room: %d\n", room);
    printf("Seat: %d\n", seat);
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `roll`. If it is below 1, report an invalid roll and stop.
2. Shift to counting from zero: `position = roll − 1`. Now rolls 1–30 become positions 0–29.
3. `room = 101 + position ÷ 30` (whole-number division, dropping the remainder).
4. `seat = (position mod 30) + 1`.
5. Print room and seat.

**Dry run** with 75: position 74, 74 ÷ 30 = 2 → room 103; 74 mod 30 = 14 → seat 15.

Without the `− 1` shift, roll 30 would give 30 ÷ 30 = 1 → room 102, which is wrong. Shifting to zero-based counting is a standard trick you will use again with arrays.

### Concepts Practiced
- Algorithm design with arithmetic
- Zero-based counting
- Quotient and remainder (preview of `/` and `%`)
- Input validation

## Problem 6: Savings Goal
**Level:** Challenging

### Scenario
Rafi wants a second-hand laptop for his programming lab. He sets aside the same amount at the end of every month from his tuition income. He wants to know how many months it will take to reach his goal and how much extra he will have in the final month.

### Problem Statement
Read two whole numbers: the monthly saving and the goal (both in taka). Use **repetition**: start with 0 saved and 0 months, and keep adding one month's saving until the total reaches or passes the goal.

- If the monthly saving is 0 or less, print `Saving amount must be positive` and stop (otherwise the repetition would never end).
- A goal of 0 is already reached after 0 months.

Print exactly:
```text
Months needed: <months>
Total saved: <total> Tk
Extra beyond goal: <extra> Tk
```

### Sample Input
```text
1500 10000
```

### Sample Output
```text
Months needed: 7
Total saved: 10500 Tk
Extra beyond goal: 500 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int monthly, goal;
    scanf("%d %d", &monthly, &goal);

    if (monthly <= 0) {
        printf("Saving amount must be positive\n");
        return 0;
    }

    int saved = 0, months = 0;
    while (saved < goal) {
        saved = saved + monthly;
        months = months + 1;
    }

    printf("Months needed: %d\n", months);
    printf("Total saved: %d Tk\n", saved);
    printf("Extra beyond goal: %d Tk\n", saved - goal);
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `monthly` and `goal`. If `monthly ≤ 0`, report it and stop.
2. Set `saved = 0`, `months = 0`.
3. Repeat while `saved < goal`: add `monthly` to `saved`, add 1 to `months`.
4. Print `months`, `saved`, and `saved − goal`.

**Dry run** with `1500 10000`:

| Month | Saved | Still below goal? |
|---|---|---|
| 1 | 1500 | yes |
| 2 | 3000 | yes |
| … | … | … |
| 6 | 9000 | yes |
| 7 | 10500 | no → stop |

The check for a non-positive saving matters: with `monthly = 0`, `saved` would stay 0 forever and the loop would never stop. Always ask "is this repetition guaranteed to end?"

### Concepts Practiced
- Algorithm design with repetition
- Loop termination
- Dry-run table
- while loop (preview)


```text
Extra beyond goal: 0 Tk
```

#### Goal of zero

**Expected Output**
```text

Extra beyond goal: 0 Tk
```

## Problem 7: Electricity Meter Check
**Level:** Challenging

### Scenario
A student hostel records each room's electricity meter at the start and end of the month. The hostel office charges a flat (hypothetical) rate of 8.50 Tk per unit, with a minimum bill of 150 Tk. Sometimes a reading is typed wrongly and the new reading is smaller than the old one.

### Problem Statement
Read the previous and current meter readings (whole numbers).

1. If the current reading is smaller than the previous one, print `Invalid reading` and stop.
2. Otherwise, units used = current − previous, and the bill = units × 8.50.
3. If that bill is below 150 Tk, the room pays 150 Tk instead.

Print exactly:
```text
Units used: <units>
Bill: <bill with 2 decimals> Tk
```
When the minimum applies, the second line is:
```text
Bill: 150.00 Tk (minimum charge applied)
```

### Sample Input
```text
12450 12610
```

### Sample Output
```text
Units used: 160
Bill: 1360.00 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int previous, current;
    scanf("%d %d", &previous, &current);

    if (current < previous) {
        printf("Invalid reading\n");
        return 0;
    }

    int units = current - previous;
    double bill = units * 8.50;

    printf("Units used: %d\n", units);
    if (bill < 150) {
        printf("Bill: 150.00 Tk (minimum charge applied)\n");
    } else {
        printf("Bill: %.2f Tk\n", bill);
    }
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `previous` and `current`.
2. Decision 1 (validation): if `current < previous`, the data is wrong; report it and stop.
3. `units = current − previous`; `bill = units × 8.50`.
4. Decision 2 (business rule): if `bill < 150`, charge the minimum.
5. Print units and the bill.

**Dry run** with `12450 12610`: units = 160, bill = 160 × 8.50 = 1360.00, which is above the minimum.

Two different kinds of decision appear here: one protects the program from bad data, the other applies a business rule. Keep them separate in your algorithm; it makes both easier to check.

### Concepts Practiced
- Algorithm design with two decisions
- Input validation before calculation
- Minimum-charge rule
- Decimal calculation (preview)

## Problem 8: Cashier's End-of-Day Summary
**Level:** Challenging

### Scenario
The campus cafeteria cashier writes every sale on a paper slip. At closing time the manager wants three numbers: the total taken, the biggest single sale, and the average sale. Doing this by hand for a long list is slow and error-prone.

### Problem Statement
Read a whole number `N` (the number of sales), then `N` sale amounts (whole taka). Using repetition, compute the total, the highest sale, and the average sale.

- If `N` is 0 or less, print `No sales recorded` and stop (an average of zero sales is undefined).

Print exactly:
```text
Total sales: <total> Tk
Highest sale: <highest> Tk
Average sale: <average with 2 decimals> Tk
```

### Sample Input
```text
5
120 450 80 300 250
```

### Sample Output
```text
Total sales: 1200 Tk
Highest sale: 450 Tk
Average sale: 240.00 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);

    if (n <= 0) {
        printf("No sales recorded\n");
        return 0;
    }

    int total = 0, highest = 0, sale;
    for (int i = 1; i <= n; i++) {
        scanf("%d", &sale);
        total = total + sale;
        if (i == 1 || sale > highest) {
            highest = sale;
        }
    }

    printf("Total sales: %d Tk\n", total);
    printf("Highest sale: %d Tk\n", highest);
    printf("Average sale: %.2f Tk\n", (double) total / n);
    return 0;
}
```

### Explanation
**Algorithm**

1. Read `N`. If `N ≤ 0`, report no sales and stop.
2. Set `total = 0`.
3. Repeat `N` times: read a sale, add it to `total`; if it is the first sale or bigger than `highest`, it becomes the new `highest`.
4. `average = total ÷ N` as a decimal.
5. Print the three results.

**Dry run** with the sample: total grows 120, 570, 650, 950, 1200; highest goes 120 → 450 and stays there. Average = 1200 ÷ 5 = 240.00.

Taking the *first* sale as the starting `highest` (instead of 0) is the safe habit: it works even if every value could be negative, such as refunds.

### Concepts Practiced
- Algorithm design with repetition and a decision inside it
- Running total and running maximum
- Guarding against division by zero
- for loop (preview)
