# Scenario-Based Problems

This chapter is about **how** to solve problems, so these exercises practise the habits it describes: understand the problem, plan the algorithm, dry-run it, write the code, and hunt for bugs and edge cases. Each problem names the habit it trains. You may use everything from Chapters 01–12.

Before opening a solution, write down (1) the inputs and outputs, (2) your plan in steps, and (3) at least two edge cases you expect to be tricky. Then compare them with the explanation and the test cases.

Programs read input without prompts and print exactly the sample output. Rules and rates are hypothetical.

## Problem 1: Fix the Quiz Average Program
**Level:** Moderate

### Scenario
A classmate wrote a program to average quiz marks, but it gives wrong answers and sometimes crashes. He asks you to debug it. Here is his code:

```c
#include <stdio.h>
int main() {
    int n, mark, sum;
    scanf("%d", &n);
    for (int i = 0; i <= n; i++) {
        scanf("%d", &mark);
        sum = sum + mark;
    }
    printf("Average: %d\n", sum / n);
    return 0;
}
```

### Problem Statement
Find every bug in the program above (there are four), then write a correct version. It reads `N` and then `N` whole-number marks and prints `Average: <average with 2 decimals>`. If `N` is 0 or less it prints `No marks entered`.

**Debugging habit:** for each bug, describe the *symptom* (what goes wrong when you run it) before fixing it.

### Sample Input
```text
4
15 18 12 20
```

### Sample Output
```text
Average: 16.25
```

### Solution
```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);

    if (n <= 0) {                       /* bug 4: division by zero */
        printf("No marks entered\n");
        return 0;
    }

    int sum = 0;                        /* bug 1: sum was never initialised */
    for (int i = 0; i < n; i++) {       /* bug 2: i <= n read one value too many */
        int mark;
        scanf("%d", &mark);
        sum += mark;
    }

    printf("Average: %.2f\n", (double) sum / n);   /* bug 3: integer division */
    return 0;
}
```

### Explanation
The four bugs and their symptoms:

1. **Uninitialised variable**: `sum` starts with whatever garbage is in memory, so the total (and average) can be any number. Fix: `int sum = 0;`.
2. **Off-by-one loop**: `i <= n` runs `n + 1` times, so the program waits for an extra mark (or reads a leftover number). Fix: `i < n`.
3. **Integer division**: `sum / n` with two `int`s gives 16 instead of 16.25, and `%d` cannot show decimals. Fix: `(double) sum / n` with `%.2f`.
4. **Division by zero**: with `N = 0` the program divides by zero and may crash. Fix: check `n <= 0` first.

Notice how different the symptoms are: one gives random results, one makes the program "hang" waiting for input, one is slightly wrong, and one crashes only on a special input. Testing with several kinds of input (normal, single value, zero) is how you find all of them.

### Concepts Practiced
- Debugging from symptoms
- Initialising accumulators
- Loop bounds (off-by-one)
- Integer vs decimal division
- Guarding against division by zero

## Problem 2: Make the Program Show Its Dry Run
**Level:** Moderate

### Scenario
Your lab teacher says: "If you cannot dry-run your loop, make the computer do it for you." For the classic reverse-a-number loop, she wants a version that prints a trace line for every iteration, exactly like the dry-run table you would draw on paper.

### Problem Statement
Read a whole number `n` (0 or more) and reverse its digits with the loop "take the last digit, append it to `reversed`, remove it from `n`". Before removing the digit, print a trace line for each iteration:
```text
Step <k>: n = <n>, digit = <d>, reversed = <reversed so far>
```
Finally print `Reversed: <reversed>`.

**Habit:** run the sample by hand first and write your own table; then compare it with the program's trace.

### Sample Input
```text
1230
```

### Sample Output
```text
Step 1: n = 1230, digit = 0, reversed = 0
Step 2: n = 123, digit = 3, reversed = 3
Step 3: n = 12, digit = 2, reversed = 32
Step 4: n = 1, digit = 1, reversed = 321
Reversed: 321
```

### Solution
```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);

    int reversed = 0, step = 0;
    while (n > 0) {
        int digit = n % 10;
        reversed = reversed * 10 + digit;
        step++;
        printf("Step %d: n = %d, digit = %d, reversed = %d\n", step, n, digit, reversed);
        n = n / 10;
    }
    printf("Reversed: %d\n", reversed);
    return 0;
}
```

### Explanation
Printing the important variables at each step turns an invisible process into a table you can check line by line. This is the simplest and most useful debugging technique: when a loop misbehaves, print its state.

The trace also reveals two edge cases you might not think of:

- **Trailing zeros disappear**: 1230 reversed is 0321, which as a number is 321. Step 1 shows `reversed = 0` because 0 × 10 + 0 is still 0.
- **Zero input**: for `n = 0` the loop body never runs, so there is no trace and the result is 0. A `do-while` loop would run once and print a step for 0; which one is "right" depends on what the trace should show.

### Concepts Practiced
- Dry-running a loop
- Trace (debug) output
- Digit manipulation
- Recognising edge cases from a trace

## Problem 3: Trimester CGPA Update
**Level:** Intermediate

### Scenario
At the end of each trimester, students want to know their new CGPA before the official result appears. They know their previous CGPA, how many credits it was calculated over, and this trimester's courses with credits and grade points.

### Problem Statement
Read the previous CGPA and previous credits (decimals), then `N` and `N` lines of `credits gradePoint`. If `N` is less than 1, or any credit is 0 or less, or a grade point is outside 0–4, print `Invalid input`. Otherwise print:
```text
Trimester GPA: <gpa>
New CGPA: <cgpa>
Credits completed: <total credits, 1 decimal>
```
(two decimals for GPA and CGPA).

**Decomposition habit:** before coding, write the formula for each output in terms of smaller quantities, for example "quality points = Σ credits × grade point".

### Sample Input
```text
3.45 60
3
3 4.00
3 3.33
1.5 3.67
```

### Sample Output
```text
Trimester GPA: 3.67
New CGPA: 3.47
Credits completed: 67.5
```

### Solution
```c
#include <stdio.h>

int main() {
    double prevCgpa, prevCredits;
    int n;
    scanf("%lf %lf %d", &prevCgpa, &prevCredits, &n);
    if (n < 1) {
        printf("Invalid input\n");
        return 0;
    }

    double termCredits = 0, termPoints = 0;
    for (int i = 0; i < n; i++) {
        double credits, gp;
        scanf("%lf %lf", &credits, &gp);
        if (credits <= 0 || gp < 0 || gp > 4) {
            printf("Invalid input\n");
            return 0;
        }
        termCredits += credits;
        termPoints += credits * gp;
    }

    double gpa = termPoints / termCredits;
    double previousPoints = prevCgpa * prevCredits;
    double totalCredits = prevCredits + termCredits;
    double cgpa = (previousPoints + termPoints) / totalCredits;

    printf("Trimester GPA: %.2f\n", gpa);
    printf("New CGPA: %.2f\n", cgpa);
    printf("Credits completed: %.1f\n", totalCredits);
    return 0;
}
```

### Explanation
The decomposition:

- term quality points = 3 × 4.00 + 3 × 3.33 + 1.5 × 3.67 = 12 + 9.99 + 5.505 = 27.495
- term credits = 7.5, so GPA = 27.495 ÷ 7.5 = 3.666 → 3.67
- previous quality points = CGPA × credits = 3.45 × 60 = 207
- new CGPA = (207 + 27.495) ÷ (60 + 7.5) = 234.495 ÷ 67.5 = 3.474 → 3.47

A common wrong approach is averaging the old CGPA and the new GPA: (3.45 + 3.67) ÷ 2 = 3.56. That ignores the fact that 60 old credits weigh far more than 7.5 new ones. Writing the formula in terms of quality points first prevents that mistake.

For a first-trimester student (previous credits 0), the formula correctly gives CGPA = GPA without any special case.

### Concepts Practiced
- Decomposing a formula into intermediate quantities
- Weighted averages
- Input validation inside a loop
- Thinking about a special case (first trimester)

## Problem 4: Fair Bill Splitter
**Level:** Intermediate

### Scenario
After a club dinner, friends split the bill plus a tip. Nobody wants to deal with paisa, so each person pays the same **whole** number of taka, rounded **up** so the restaurant is never short. The organiser wants to know how much extra will be collected. Floating-point rounding has caused arguments before, so this time the calculation must be exact.

### Problem Statement
Read the bill (decimal, up to 2 decimal places), the number of people and the tip percentage (whole numbers). Check edge cases first:

- people 0 or less → `Number of people must be positive`
- negative bill → `Invalid bill amount`
- negative tip → `Invalid tip`

Then calculate the total with tip, convert it to **whole paisa** (round to the nearest paisa), and compute each person's share in whole taka rounded up, using only integer arithmetic for the rounding. Print:
```text
Total with tip: <total, 2 decimals> Tk
Each person pays: <whole taka> Tk
Extra collected: <extra, 2 decimals> Tk
```

**Edge-case habit:** list every input that could break the program before you write it.

### Sample Input
```text
1234.50 4 10
```

### Sample Output
```text
Total with tip: 1357.95 Tk
Each person pays: 340 Tk
Extra collected: 2.05 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    double bill;
    int people, tip;
    scanf("%lf %d %d", &bill, &people, &tip);

    if (people <= 0) {
        printf("Number of people must be positive\n");
        return 0;
    }
    if (bill < 0) {
        printf("Invalid bill amount\n");
        return 0;
    }
    if (tip < 0) {
        printf("Invalid tip\n");
        return 0;
    }

    double total = bill * (100 + tip) / 100;
    long long totalPaisa = (long long) (total * 100 + 0.5);    /* nearest paisa */

    long long perPersonPaisa = (long long) people * 100;          /* 1 taka per person */
    long long share = (totalPaisa + perPersonPaisa - 1) / perPersonPaisa;   /* round up */
    long long extraPaisa = share * people * 100 - totalPaisa;

    printf("Total with tip: %.2f Tk\n", totalPaisa / 100.0);
    printf("Each person pays: %lld Tk\n", share);
    printf("Extra collected: %lld.%02lld Tk\n", extraPaisa / 100, extraPaisa % 100);
    return 0;
}
```

### Explanation
Money in `double` is approximate: 1234.50 × 1.10 is stored as something like 1357.9500000000003. Converting once to whole paisa (rounding to the nearest) and doing all further work with integers removes those tiny errors.

Rounding **up** an integer division `a / b` uses the formula `(a + b − 1) / b`. Here `a` is the total in paisa (135795) and `b` is "one taka for each person" in paisa (4 × 100 = 400): (135795 + 399) / 400 = 340. So each pays 340 Tk, 4 × 340 = 1360 Tk is collected, and 1360.00 − 1357.95 = 2.05 Tk is extra.

The extra amount is printed from paisa as `taka.paisa` with `%02lld`, so 5 paisa prints as `0.05`, not `0.5`. The edge cases (zero people, negative values) are checked **before** any division.

### Concepts Practiced
- Listing edge cases before coding
- Avoiding floating-point errors with integer paisa
- Rounding up with integer division
- long long and `%02lld`

## Problem 5: Campus Parking Fee
**Level:** Intermediate

### Scenario
The university's (fictional) parking rules were written in a long paragraph that nobody reads. You are asked to turn them into a program, and the IT office insists that each rule lives in its own function so the rules are easy to update:

- Vehicle types: `C` car (40 Tk per hour, daily maximum 300 Tk), `M` motorcycle (20 Tk per hour, maximum 150 Tk), `B` bicycle (5 Tk per hour, maximum 30 Tk).
- The first 15 minutes are free: a stay of 15 minutes or less costs nothing.
- Otherwise every started hour is charged (61 minutes = 2 hours).
- Leaving after 22:00 adds a night surcharge **after** the daily maximum: 50 Tk for cars, 20 Tk for motorcycles, 0 for bicycles.

### Problem Statement
Read the vehicle type, entry time `HH MM` and exit time `HH MM` (same day, 24-hour clock). Print `Unknown vehicle type` or `Invalid times` (exit before entry) when appropriate. Otherwise print:
```text
Duration: <h> h <m> min
Billed hours: <hours>
Fee: <fee> Tk
```
Write at least these functions: `int billedHours(int minutes)`, `int hourlyRate(char type)`, `int dailyMax(char type)`, `int nightSurcharge(char type, int exitMinutes)`.

**Habit:** translate one sentence of the rules into one function, and test each function on the boundary values from the rules (15, 16, 60, 61 minutes; exactly 22:00).

### Sample Input
```text
C 09 40 13 05
```

### Sample Output
```text
Duration: 3 h 25 min
Billed hours: 4
Fee: 160 Tk
```

### Solution
```c
#include <stdio.h>

int billedHours(int minutes) {
    if (minutes <= 15) return 0;          /* free period */
    return (minutes + 59) / 60;           /* every started hour */
}

int hourlyRate(char type) {
    switch (type) {
        case 'C': return 40;
        case 'M': return 20;
        case 'B': return 5;
        default: return -1;
    }
}

int dailyMax(char type) {
    switch (type) {
        case 'C': return 300;
        case 'M': return 150;
        default: return 30;
    }
}

int nightSurcharge(char type, int exitMinutes) {
    if (exitMinutes <= 22 * 60) return 0;   /* leaving at 22:00 exactly is not night */
    switch (type) {
        case 'C': return 50;
        case 'M': return 20;
        default: return 0;
    }
}

int main() {
    char type;
    int h1, m1, h2, m2;
    scanf(" %c %d %d %d %d", &type, &h1, &m1, &h2, &m2);

    if (hourlyRate(type) < 0) {
        printf("Unknown vehicle type\n");
        return 0;
    }

    int entry = h1 * 60 + m1, exitTime = h2 * 60 + m2;
    if (exitTime < entry) {
        printf("Invalid times\n");
        return 0;
    }

    int minutes = exitTime - entry;
    int hours = billedHours(minutes);
    int fee = hours * hourlyRate(type);
    if (fee > dailyMax(type)) {
        fee = dailyMax(type);
    }
    fee += nightSurcharge(type, exitTime);

    printf("Duration: %d h %d min\n", minutes / 60, minutes % 60);
    printf("Billed hours: %d\n", hours);
    printf("Fee: %d Tk\n", fee);
    return 0;
}
```

### Explanation
Each sentence of the rules became one function, and `main` reads like a summary of the policy: convert times, bill hours, apply the cap, add the surcharge. When the university changes a rate, only one `case` changes.

`(minutes + 59) / 60` is the integer "round up" trick: 205 minutes → 264 / 60 = 4 hours, while 180 minutes → 239 / 60 = 3 hours.

The order of the last steps matters: the cap is applied **before** the night surcharge, as the rules say. A car parked from 08:00 to 22:30 would cost 15 × 40 = 600, capped to 300, plus 50 for leaving after 22:00 = 350.

### Concepts Practiced
- One function per rule
- Rounding up minutes to hours
- Caps and surcharges in the right order
- Boundary testing of each rule

## Problem 6: Gift Within Budget
**Level:** Challenging

### Scenario
For a friend's birthday, a group wants to buy exactly two **different** items from a gift shop so that the total is exactly their budget. With a long price list, checking every pair is slow. The club's senior suggests a faster idea: sort the prices, then move two pointers inward from both ends.

### Problem Statement
Read `N` (2–100), `N` prices (whole taka) and the budget. If `N` is out of range, print `Invalid number of items`. Sort the prices in increasing order (bubble sort is fine) and apply the **two-pointer** method:

- start with `i` at the cheapest item and `j` at the most expensive;
- while `i < j`: compare `price[i] + price[j]` with the budget (count one check); if equal, stop; if smaller, move `i` right; if larger, move `j` left.

Print `Pair: <a> + <b> = <budget>` for the pair found, or `No pair matches the budget`. Then print how many checks the two-pointer method made and how many a brute-force check of all pairs would make (`N(N − 1)/2`):
```text
Checks (two-pointer): <k>
Checks (all pairs): <total>
```

**Habit:** think about the algorithm's cost before writing it.

### Sample Input
```text
8
450 120 750 300 250 600 90 880
1000
```

### Sample Output
```text
Pair: 120 + 880 = 1000
Checks (two-pointer): 2
Checks (all pairs): 28
```

### Solution
```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);
    if (n < 2 || n > 100) {
        printf("Invalid number of items\n");
        return 0;
    }

    int price[100];
    for (int k = 0; k < n; k++) scanf("%d", &price[k]);
    int budget;
    scanf("%d", &budget);

    for (int pass = 0; pass < n - 1; pass++) {
        for (int k = 0; k < n - 1 - pass; k++) {
            if (price[k] > price[k + 1]) {
                int t = price[k];
                price[k] = price[k + 1];
                price[k + 1] = t;
            }
        }
    }

    int i = 0, j = n - 1, checks = 0, found = 0;
    while (i < j) {
        checks++;
        int sum = price[i] + price[j];
        if (sum == budget) {
            found = 1;
            break;
        } else if (sum < budget) {
            i++;            /* need a bigger sum: try a dearer cheap item */
        } else {
            j--;            /* need a smaller sum: try a cheaper dear item */
        }
    }

    if (found) {
        printf("Pair: %d + %d = %d\n", price[i], price[j], budget);
    } else {
        printf("No pair matches the budget\n");
    }
    printf("Checks (two-pointer): %d\n", checks);
    printf("Checks (all pairs): %d\n", n * (n - 1) / 2);
    return 0;
}
```

### Explanation
After sorting, the prices are 90 120 250 300 450 600 750 880. The pointers start at 90 and 880 (sum 970, too small, so `i` moves right), then 120 and 880 (sum 1000), found after 2 checks. Checking every pair could take up to 8 × 7 ÷ 2 = 28 checks.

Why moving a pointer is safe: if `price[i] + price[j]` is too small, then `price[i]` plus any item to the **left** of `j` is even smaller, so `price[i]` can never be part of the answer and can be discarded. The same argument works for `j` when the sum is too large. Each check discards one item, so the method makes at most `N − 1` checks.

There can be several valid pairs (250 + 750 also works); this method reports the first one it meets, as the problem specifies. Using `i < j` (not `i <= j`) ensures two **different** items, while two items with the same price are still allowed.

### Concepts Practiced
- Choosing an efficient algorithm
- Sorting before searching
- Two-pointer technique
- Counting operations to compare algorithms

## Problem 7: Bank Counter Queue
**Level:** Challenging

### Scenario
The campus bank booth has one counter. During fee-payment week, the queue gets long and students complain about waiting. The bank wants to simulate a morning: given when each student arrives and how long their service takes, when does each one start and leave, how long do they wait, and how long is the counter idle?

### Problem Statement
Read `N` and then `N` lines `arrival service` (minutes after opening, whole numbers; arrivals never decrease). If `N` is less than 1, print `No customers`. If an arrival is earlier than the previous one, print `Arrival times must not decrease` and stop (lines already printed stay). Students are served in arrival order. For each student print:
```text
Customer <k>: arrives <a>, starts <s>, waits <w>, leaves <l>
```
then:
```text
Average wait: <average, 2 decimals> min
Counter idle: <minutes> min
```
The counter opens at time 0; idle time includes any time before the first arrival.

**Habit:** simulate the first three customers by hand in a table before writing the loop.

### Sample Input
```text
5
0 5
2 3
4 6
15 2
16 4
```

### Sample Output
```text
Customer 1: arrives 0, starts 0, waits 0, leaves 5
Customer 2: arrives 2, starts 5, waits 3, leaves 8
Customer 3: arrives 4, starts 8, waits 4, leaves 14
Customer 4: arrives 15, starts 15, waits 0, leaves 17
Customer 5: arrives 16, starts 17, waits 1, leaves 21
Average wait: 1.60 min
Counter idle: 1 min
```

### Solution
```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);
    if (n < 1) {
        printf("No customers\n");
        return 0;
    }

    int counterFreeAt = 0;        /* when the counter finishes the current student */
    int totalWait = 0, idle = 0, previousArrival = 0;

    for (int k = 1; k <= n; k++) {
        int arrival, service;
        scanf("%d %d", &arrival, &service);
        if (arrival < previousArrival) {
            printf("Arrival times must not decrease\n");
            return 0;
        }
        previousArrival = arrival;

        int start;
        if (arrival >= counterFreeAt) {
            idle += arrival - counterFreeAt;   /* counter waited for this student */
            start = arrival;
        } else {
            start = counterFreeAt;             /* student waits for the counter */
        }
        int wait = start - arrival;
        counterFreeAt = start + service;
        totalWait += wait;

        printf("Customer %d: arrives %d, starts %d, waits %d, leaves %d\n",
               k, arrival, start, wait, counterFreeAt);
    }

    printf("Average wait: %.2f min\n", (double) totalWait / n);
    printf("Counter idle: %d min\n", idle);
    return 0;
}
```

### Explanation
The whole simulation needs just one piece of state: the time when the counter becomes free. For each student there are only two cases:

- the counter is already free when they arrive: they start at once, and the counter was idle for the gap;
- the counter is busy: they start when it becomes free and wait for the difference.

Customer 3 arrives at 4 but the counter is busy until 8, so they wait 4 minutes. Customer 4 arrives at 15 after the counter became free at 14, so the counter was idle for 1 minute and customer 4 waits 0.

Recognising that a complicated-sounding problem (a queue) needs only one variable of state is exactly the kind of insight a hand simulation gives you.

### Concepts Practiced
- Simulation with a single state variable
- Two-case reasoning in a loop
- Validating input order
- Averages and totals

## Problem 8: Boro Bhai's Loyalty Card
**Level:** Challenging

### Scenario
The elakar boro bhai's tea stall has gone "digital". Every regular customer gets a loyalty card, and **every 10th cup on a card is free**: cups 10, 20, 30, … in a card's history cost nothing. A cup costs 12 Tk. Boro bhai types each sale as the card number and the number of cups, and wants his nephew's program to show what each customer pays and, at the end of the day, the revenue, the free cups given, and his most loyal customer.

### Problem Statement
Read `N` sales, each `card cups`. Keep each card's running total of cups (at most 20 different cards; use arrays). For each sale:

- cups 0 or less → print `Invalid sale`;
- otherwise free cups in this sale = (total after this sale ÷ 10) − (total before ÷ 10), using whole-number division, and print `Card <c>: cups <n>, free <f>, pays <amount> Tk`.

Finally print:
```text
Revenue: <total paid> Tk
Free cups given: <count>
Top customer: card <c> (<cups> cups)
```
The top customer has the most cups in total (first card seen on a tie); with no valid sales print `Top customer: none`.

**Habit:** check the formula on paper with a card that crosses 10 and 20 in one sale.

### Sample Input
```text
6
7 4
12 3
7 8
12 7
7 1
30 10
```

### Sample Output
```text
Card 7: cups 4, free 0, pays 48 Tk
Card 12: cups 3, free 0, pays 36 Tk
Card 7: cups 8, free 1, pays 84 Tk
Card 12: cups 7, free 1, pays 72 Tk
Card 7: cups 1, free 0, pays 12 Tk
Card 30: cups 10, free 1, pays 108 Tk
Revenue: 360 Tk
Free cups given: 3
Top customer: card 7 (13 cups)
```

### Solution
```c
#include <stdio.h>

int cardNo[20], cupsSoFar[20];
int cardsUsed = 0;

/* index of the card in the arrays, adding it if new; -1 if the list is full */
int findCard(int card) {
    for (int i = 0; i < cardsUsed; i++) {
        if (cardNo[i] == card) return i;
    }
    if (cardsUsed == 20) return -1;
    cardNo[cardsUsed] = card;
    cupsSoFar[cardsUsed] = 0;
    return cardsUsed++;
}

int main() {
    int n, revenue = 0, freeTotal = 0;
    scanf("%d", &n);

    for (int s = 0; s < n; s++) {
        int card, cups;
        scanf("%d %d", &card, &cups);
        if (cups <= 0) {
            printf("Invalid sale\n");
            continue;
        }
        int i = findCard(card);
        if (i < 0) {
            printf("Card list full\n");
            continue;
        }

        int before = cupsSoFar[i];
        int after = before + cups;
        int freeCups = after / 10 - before / 10;
        int pay = (cups - freeCups) * 12;

        cupsSoFar[i] = after;
        revenue += pay;
        freeTotal += freeCups;
        printf("Card %d: cups %d, free %d, pays %d Tk\n", card, cups, freeCups, pay);
    }

    printf("Revenue: %d Tk\n", revenue);
    printf("Free cups given: %d\n", freeTotal);
    if (cardsUsed == 0) {
        printf("Top customer: none\n");
    } else {
        int best = 0;
        for (int i = 1; i < cardsUsed; i++) {
            if (cupsSoFar[i] > cupsSoFar[best]) best = i;
        }
        printf("Top customer: card %d (%d cups)\n", cardNo[best], cupsSoFar[best]);
    }
    return 0;
}
```

### Explanation
`after / 10 − before / 10` counts how many multiples of 10 were passed in this sale, which is exactly the number of free cups. Card 7 goes from 4 to 12 cups: 12/10 − 4/10 = 1 − 0 = 1 free cup. A single sale from 5 to 25 cups crosses both 10 and 20: 2 − 0 = 2 free cups. Checking this on paper first (the habit) catches the wrong idea of "one free cup if the sale includes 10 cups".

Card numbers are not small indexes (7, 12, 30), so the program keeps a small table: `cardNo[i]` and `cupsSoFar[i]`. `findCard` searches the table and adds a new card at the end, returning its index. This "look up or insert" pattern appears everywhere, from contact lists to databases.

### Concepts Practiced
- Formula checked by hand before coding
- Look-up-or-insert in parallel arrays
- Function returning an index or −1
- Running totals per key
- Integer division to count multiples
