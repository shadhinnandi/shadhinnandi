# Scenario-Based Problems

These problems are solved with operators only: arithmetic (including `/` and `%` on integers), relational and logical operators, assignment and compound assignment, and `++`/`--`. There are no `if` statements yet. Where a yes/no answer is needed, print the value of the condition itself: in C a true condition is `1` and a false one is `0`.

Programs read input without printing prompts and print exactly the sample output. You can assume the input is valid.

## Problem 1: Lab Session Duration
**Level:** Moderate

### Scenario
The lab computers log how long each student was logged in as a single number of seconds. The lab in-charge wants that number shown as hours, minutes and seconds in the weekly usage report.

### Problem Statement
Read a whole number of seconds (0 or more). Convert it to hours, minutes and remaining seconds using only `/` and `%`.

Print exactly:
```text
Hours: <h>
Minutes: <m>
Seconds: <s>
```

### Sample Input
```text
7509
```

### Sample Output
```text
Hours: 2
Minutes: 5
Seconds: 9
```

### Solution
```c
#include <stdio.h>

int main() {
    int totalSeconds;
    scanf("%d", &totalSeconds);

    int hours = totalSeconds / 3600;
    int minutes = totalSeconds % 3600 / 60;
    int seconds = totalSeconds % 60;

    printf("Hours: %d\n", hours);
    printf("Minutes: %d\n", minutes);
    printf("Seconds: %d\n", seconds);
    return 0;
}
```

### Explanation
Integer division gives "how many whole units fit", and `%` gives "what is left over":

- Hours: 7509 / 3600 = 2 (7200 seconds used)
- What is left after whole hours: 7509 % 3600 = 309; whole minutes in it: 309 / 60 = 5
- Seconds: 7509 % 60 = 9

`%` and `/` have the same precedence and are evaluated left to right, so `totalSeconds % 3600 / 60` means `(totalSeconds % 3600) / 60`, which is what we want.

### Concepts Practiced
- Integer division `/`
- Modulus `%`
- Operator precedence and associativity

## Problem 2: Cash Counter Note Breakdown
**Level:** Moderate

### Scenario
At the end of the day, the university cash counter must hand over an amount using as few notes and coins as possible. Bangladesh uses notes and coins of 1000, 500, 100, 50, 20, 10, 5, 2 and 1 taka.

### Problem Statement
Read a whole amount of taka (0 or more). Find how many of each denomination to use, always taking as many of the largest denomination as possible first. Use `/` to count and `%=` to keep only what is left.

Print exactly nine lines, from 1000 down to 1:
```text
1000 x <count>
500 x <count>
...
1 x <count>
```

### Sample Input
```text
3786
```

### Sample Output
```text
1000 x 3
500 x 1
100 x 2
50 x 1
20 x 1
10 x 1
5 x 1
2 x 0
1 x 1
```

### Solution
```c
#include <stdio.h>

int main() {
    int amount;
    scanf("%d", &amount);

    printf("1000 x %d\n", amount / 1000);
    amount %= 1000;
    printf("500 x %d\n", amount / 500);
    amount %= 500;
    printf("100 x %d\n", amount / 100);
    amount %= 100;
    printf("50 x %d\n", amount / 50);
    amount %= 50;
    printf("20 x %d\n", amount / 20);
    amount %= 20;
    printf("10 x %d\n", amount / 10);
    amount %= 10;
    printf("5 x %d\n", amount / 5);
    amount %= 5;
    printf("2 x %d\n", amount / 2);
    amount %= 2;
    printf("1 x %d\n", amount);
    return 0;
}
```

### Explanation
For each denomination, `amount / note` is how many notes fit, and `amount %= note` (short for `amount = amount % note`) keeps only the part that still has to be paid.

With 3786: three 1000s leave 786; one 500 leaves 286; two 100s leave 86; one 50 leaves 36; one 20 leaves 16; one 10 leaves 6; one 5 leaves 1; no 2; one 1.

This "largest first" method gives the fewest notes for Bangladeshi denominations. (It is called a greedy algorithm; for some unusual sets of coin values it does not give the minimum, which you will study in algorithms courses.)

### Concepts Practiced
- Integer division `/`
- Compound assignment `%=`
- Greedy calculation step by step

## Problem 3: Exam Building Seat Locator
**Level:** Intermediate

### Scenario
For the trimester final, all first-year students sit in one exam building. Each room has 40 seats and each floor has 6 rooms. Room numbers combine the floor and the room on that floor: the 1st room on floor 3 is room 301. Students are seated in roll order starting from room 101, seat 1.

### Problem Statement
Read a roll number (1 or more). Using only arithmetic operators, find the floor, the room number and the seat number.

Print exactly:
```text
Floor: <floor>
Room: <room number>
Seat: <seat>
```

### Sample Input
```text
517
```

### Sample Output
```text
Floor: 3
Room: 301
Seat: 37
```

### Solution
```c
#include <stdio.h>

int main() {
    int roll;
    scanf("%d", &roll);

    int position = roll - 1;            /* 0-based position in the queue */
    int roomIndex = position / 40;      /* 0-based room counted across floors */
    int seat = position % 40 + 1;
    int floor = roomIndex / 6 + 1;
    int roomOnFloor = roomIndex % 6 + 1;
    int roomNumber = floor * 100 + roomOnFloor;

    printf("Floor: %d\n", floor);
    printf("Room: %d\n", roomNumber);
    printf("Seat: %d\n", seat);
    return 0;
}
```

### Explanation
The trick is to apply the same divide-and-remainder idea twice:

1. Counting from 0, roll 517 is at position 516.
2. Rooms: 516 / 40 = 12 full rooms come before it, so it is in room index 12; the seat is 516 % 40 + 1 = 37.
3. Floors: room index 12 / 6 = 2 full floors before it, so floor 3; the room on that floor is 12 % 6 + 1 = 1.
4. Room number = 3 × 100 + 1 = 301.

Working with 0-based positions and adding 1 only at the end avoids the off-by-one errors at the edges (roll 40, roll 240).

### Concepts Practiced
- Integer division and modulus
- Zero-based counting
- Combining quotients into a code (floor × 100 + room)

## Problem 4: Scholarship Status Flags
**Level:** Intermediate

### Scenario
The student affairs office (rules are hypothetical) wants a quick status sheet showing which programmes a student qualifies for. Each status is a yes/no flag:

- **Merit scholarship:** CGPA at least 3.75, at least 30 credits completed, and no disciplinary cases.
- **Dean's list:** CGPA at least 3.90 and at least 12 credits completed.
- **Probation:** CGPA below 2.00.
- **Needs advising:** CGPA below 2.50, or at least one disciplinary case.

### Problem Statement
Read the CGPA (decimal), the number of completed credits and the number of disciplinary cases (whole numbers). Without using `if`, print each flag as `1` (yes) or `0` (no) by printing the value of a relational/logical expression.

Print exactly:
```text
Merit scholarship: <0 or 1>
Dean's list: <0 or 1>
Probation: <0 or 1>
Needs advising: <0 or 1>
```

### Sample Input
```text
3.82 45 0
```

### Sample Output
```text
Merit scholarship: 1
Dean's list: 0
Probation: 0
Needs advising: 0
```

### Solution
```c
#include <stdio.h>

int main() {
    double cgpa;
    int credits, cases;
    scanf("%lf %d %d", &cgpa, &credits, &cases);

    int merit = cgpa >= 3.75 && credits >= 30 && cases == 0;
    int deansList = cgpa >= 3.90 && credits >= 12;
    int probation = cgpa < 2.00;
    int advising = cgpa < 2.50 || cases > 0;

    printf("Merit scholarship: %d\n", merit);
    printf("Dean's list: %d\n", deansList);
    printf("Probation: %d\n", probation);
    printf("Needs advising: %d\n", advising);
    return 0;
}
```

### Explanation
A relational expression such as `cgpa >= 3.75` has the value `1` when it is true and `0` when it is false, so it can be stored in an `int` and printed.

- `&&` (AND) is true only if every part is true: all three merit conditions must hold.
- `||` (OR) is true if at least one part is true: either a low CGPA or a case triggers advising.
- Relational operators bind more tightly than `&&` and `||`, so no brackets are needed.

"At least" means `>=` and "below" means `<`. Reading the rule wording carefully is half the job: the boundary test cases below check exactly these edges.

### Concepts Practiced
- Relational operators
- Logical operators `&&` and `||`
- Truth values 1 and 0
- Translating written rules into expressions

## Problem 5: Locker PIN Analyzer
**Level:** Intermediate

### Scenario
The library's new lockers use 4-digit PINs. Before a PIN is accepted, the system shows some facts about it, because PINs that are palindromes (like 1221) or have predictable patterns are easier to guess.

### Problem Statement
Read a 4-digit PIN (1000–9999). Using `/` and `%`, extract its four digits. Then print:

- the four digits separated by spaces,
- their sum,
- the PIN with its digits reversed, as a number,
- whether the PIN reads the same backwards (1/0),
- whether it is even (1/0), and
- whether its digit sum is divisible by 3 (1/0).

Print exactly:
```text
Digits: <d1> <d2> <d3> <d4>
Digit sum: <sum>
Reversed: <reversed>
Palindrome: <0 or 1>
Even: <0 or 1>
Divisible by 3: <0 or 1>
```

### Sample Input
```text
4821
```

### Sample Output
```text
Digits: 4 8 2 1
Digit sum: 15
Reversed: 1284
Palindrome: 0
Even: 0
Divisible by 3: 1
```

### Solution
```c
#include <stdio.h>

int main() {
    int pin;
    scanf("%d", &pin);

    int d1 = pin / 1000;
    int d2 = pin / 100 % 10;
    int d3 = pin / 10 % 10;
    int d4 = pin % 10;

    int sum = d1 + d2 + d3 + d4;
    int reversed = d4 * 1000 + d3 * 100 + d2 * 10 + d1;

    printf("Digits: %d %d %d %d\n", d1, d2, d3, d4);
    printf("Digit sum: %d\n", sum);
    printf("Reversed: %d\n", reversed);
    printf("Palindrome: %d\n", reversed == pin);
    printf("Even: %d\n", pin % 2 == 0);
    printf("Divisible by 3: %d\n", sum % 3 == 0);
    return 0;
}
```

### Explanation
To get a digit, first shift it into the last position with `/`, then cut it out with `% 10`:

- 4821 / 1000 = 4
- 4821 / 100 = 48, and 48 % 10 = 8
- 4821 / 10 = 482, and 482 % 10 = 2
- 4821 % 10 = 1

Rebuilding the digits in the opposite order with place values (`d4 × 1000 + …`) gives the reversed number. A PIN is a palindrome exactly when it equals its reverse, so `reversed == pin` prints 1 or 0 directly.

Watch the special case 9000: its reverse is 0009, which as a number is just 9.

### Concepts Practiced
- Digit extraction with `/` and `%`
- Place-value arithmetic
- Relational operators as 1/0 values
- Divisibility tests with `%`

## Problem 6: Daily Wallet Tracker
**Level:** Challenging

### Scenario
Mim tracks her spending on a typical class day. She starts with some cash, pays for breakfast, takes a rickshaw to campus and back (same fare both ways), pays for lunch, and in the evening receives payment from her home tuition. She wants to see her balance after each step, how many transactions she made, and how much she spent.

### Problem Statement
Read five decimal values: starting balance, breakfast cost, one-way rickshaw fare, lunch cost, and tuition payment received. Process them in this order using compound assignment (`-=`, `+=`) on a single `balance` variable, add each spending to a `spent` variable with `+=`, and count each transaction with `++`.

Print exactly (two decimals for money):
```text
After breakfast: <balance>
After rickshaw (both ways): <balance>
After lunch: <balance>
After tuition payment: <balance>
Transactions: <count>
Spent today: <spent>
```
The balance may become negative; there are no checks yet.

### Sample Input
```text
500 60 40 120 1000
```

### Sample Output
```text
After breakfast: 440.00
After rickshaw (both ways): 360.00
After lunch: 240.00
After tuition payment: 1240.00
Transactions: 4
Spent today: 260.00
```

### Solution
```c
#include <stdio.h>

int main() {
    double balance, breakfast, rickshaw, lunch, tuition;
    scanf("%lf %lf %lf %lf %lf", &balance, &breakfast, &rickshaw, &lunch, &tuition);

    double spent = 0;
    int transactions = 0;

    balance -= breakfast;
    spent += breakfast;
    transactions++;
    printf("After breakfast: %.2f\n", balance);

    balance -= rickshaw * 2;
    spent += rickshaw * 2;
    transactions++;
    printf("After rickshaw (both ways): %.2f\n", balance);

    balance -= lunch;
    spent += lunch;
    transactions++;
    printf("After lunch: %.2f\n", balance);

    balance += tuition;
    transactions++;
    printf("After tuition payment: %.2f\n", balance);

    printf("Transactions: %d\n", transactions);
    printf("Spent today: %.2f\n", spent);
    return 0;
}
```

### Explanation
`balance -= x` is shorthand for `balance = balance - x`, and `transactions++` adds one. Using one running `balance` variable mirrors what really happens to a wallet and makes each printed line easy to check:

- 500 − 60 = 440
- 440 − 2 × 40 = 360
- 360 − 120 = 240
- 240 + 1000 = 1240

The tuition payment changes the balance but is not spending, so it is not added to `spent` (60 + 80 + 120 = 260). Keeping two separate running totals is a pattern you will use in many accounting problems.

### Concepts Practiced
- Compound assignment `+=` and `-=`
- Increment operator `++`
- Running totals
- Multiplication inside an expression

## Problem 7: Class End Time
**Level:** Challenging

### Scenario
The university runs some long evening workshops and online sessions that can cross midnight. The scheduling system stores a start time (24-hour clock) and a duration in minutes, and must show when the session ends and how many days later that is.

### Problem Statement
Read the start hour (0–23), start minute (0–59) and the duration in minutes (0 or more). Calculate the end time on a 24-hour clock and how many midnights are passed. Use `%02d` to print hours and minutes with two digits (for example `01:05`).

Print exactly:
```text
Ends at: <HH>:<MM>
Days later: <days>
```

### Sample Input
```text
14 40 95
```

### Sample Output
```text
Ends at: 16:15
Days later: 0
```

### Solution
```c
#include <stdio.h>

int main() {
    int hour, minute, duration;
    scanf("%d %d %d", &hour, &minute, &duration);

    int total = hour * 60 + minute + duration;   /* minutes since start of day */
    int daysLater = total / 1440;                /* 1440 minutes in a day */
    int minuteOfDay = total % 1440;

    printf("Ends at: %02d:%02d\n", minuteOfDay / 60, minuteOfDay % 60);
    printf("Days later: %d\n", daysLater);
    return 0;
}
```

### Explanation
Converting everything to one unit (minutes since midnight) turns clock arithmetic into ordinary arithmetic:

- 14:40 is 14 × 60 + 40 = 880 minutes; adding 95 gives 975.
- 975 / 1440 = 0 whole days have passed; 975 % 1440 = 975 minutes into the day.
- 975 / 60 = 16 hours and 975 % 60 = 15 minutes → 16:15.

`%` "wraps around" at 1440, just as a clock wraps at midnight. In `%02d`, the `2` sets a minimum width of two characters and the `0` pads with zeros, so 1 prints as `01`.

### Concepts Practiced
- Converting to a common unit
- Modulus for wrap-around
- Integer division
- printf width and zero padding `%02d`

## Problem 8: Fee in Three Installments
**Level:** Challenging

### Scenario
The accounts office lets students pay the trimester fee in three installments. To keep receipts simple, the first two installments are equal and are a multiple of 100 Tk: one third of the fee, rounded **down** to the nearest hundred. The third installment pays whatever is left, so the three always add up to the exact fee.

### Problem Statement
Read the total fee (a whole number of taka). Using integer arithmetic only, calculate the three installments and print a check line with their sum.

Print exactly:
```text
Installment 1: <amount> Tk
Installment 2: <amount> Tk
Installment 3: <amount> Tk
Check (sum): <sum> Tk
```

### Sample Input
```text
85250
```

### Sample Output
```text
Installment 1: 28400 Tk
Installment 2: 28400 Tk
Installment 3: 28450 Tk
Check (sum): 85250 Tk
```

### Solution
```c
#include <stdio.h>

int main() {
    int fee;
    scanf("%d", &fee);

    int installment = fee / 3 / 100 * 100;   /* one third, rounded down to 100 */
    int last = fee - 2 * installment;

    printf("Installment 1: %d Tk\n", installment);
    printf("Installment 2: %d Tk\n", installment);
    printf("Installment 3: %d Tk\n", last);
    printf("Check (sum): %d Tk\n", installment + installment + last);
    return 0;
}
```

### Explanation
`fee / 3 / 100 * 100` is evaluated left to right with integer division:

- 85250 / 3 = 28416 (the fraction is dropped)
- 28416 / 100 = 284 (drops the last two digits)
- 284 × 100 = 28400

Dividing by 100 and then multiplying by 100 is the standard integer trick for rounding **down** to a multiple of 100. In real-number maths `x / 100 × 100` would just be `x`; in integer arithmetic it is not, which is exactly why it works.

The last installment absorbs the rounding: 85250 − 2 × 28400 = 28450. Printing the sum is a self-check that no taka was lost.

### Concepts Practiced
- Integer division for rounding down
- Left-to-right evaluation of `/` and `*`
- Remainder handled by subtraction
- Self-checking output
