# Chapter 00: Introduction to Programming

Welcome to the very beginning of your programming journey! Before we write a single line of C code, it's crucial to understand what programming is, how it works, and how to think logically.

## 1. Concept Explanation

### What is Programming?

**Simple Explanation:**
Imagine you have a very obedient but very dumb robot. This robot can do anything you say, but it only understands very specific, simple instructions. Programming is the act of writing a list of these instructions for the robot (a computer) to follow.

**Technical Explanation:**
Programming is the process of designing and building an executable computer program to accomplish a specific computing result. It involves tasks such as analysis, generating algorithms, profiling algorithms' accuracy and resource consumption, and the implementation of algorithms in a chosen programming language.

### What is an Algorithm?

**Simple Explanation:**
An algorithm is like a recipe. If you want to bake a cake, you follow a series of steps in order: mix flour and sugar, add eggs, etc. An algorithm is just a step-by-step plan to solve a problem or complete a task.

**Technical Explanation:**
An algorithm is a finite sequence of well-defined, computer-implementable instructions, typically to solve a class of problems or to perform a computation.

### What is a Flowchart?

**Simple Explanation:**
A flowchart is a drawing that shows the steps of a recipe (our algorithm). It uses different shapes to represent different types of actions (like starting, doing something, making a decision, and ending). It helps us see the "flow" of our plan.

**Technical Explanation:**
A flowchart is a type of diagram that represents a workflow or process. It uses a set of standard symbols to depict various operations and the flow of control. It's a visual representation of an algorithm.

**Flowchart Example: Making Tea**

Here’s a text-based description of a flowchart for making a cup of tea.

```
[START]
   |
   v
[Boil Water]
   |
   v
[Put Tea Bag in Cup]
   |
   v
[Pour Boiled Water into Cup]
   |
   v
<Is Sugar Needed?>
   |
   +---- [YES] ----> [Add Sugar]
   |                  |
   v                  v
[NO] ------------> [Stir Tea]
   |                  |
   v                  v
[END] <---------------+
```

## 2. Why is This Important?

*   **Logic is Everything:** Programming is 90% logic and 10% syntax. If you can create a clear plan (algorithm), writing the code is the easy part.
*   **Visualize Before You Code:** Flowcharts help you catch logical errors in your plan before you've written a single line of code, saving you a lot of time.
*   **Universal Skill:** The ability to create algorithms and flowcharts is a skill that applies to *every* programming language, not just C.

## 3. How to Think Before Coding

This is the most critical skill you will develop. Always follow these steps before writing code:

1.  **Understand the Problem:** Read the problem statement carefully. What is the input? What should be the output?
2.  **Make a Plan (Algorithm):** Write down the steps to solve the problem in plain English. Don't think about code yet.
3.  **Draw a Flowchart (Optional but Recommended):** Visualize your plan. This helps you see the flow and any decision points.
4.  **Dry Run Your Logic:** Pretend you are the computer. Take a sample input and walk through your steps. Does it produce the correct output?
5.  **Write the Code:** Now, and only now, translate your steps into C code.

### Example: Adding Two Numbers

**Problem:** Write a program to add two numbers given by a user.

1.  **Understand:**
    *   Input: Two numbers (e.g., 5 and 10).
    *   Output: The sum of those two numbers (e.g., 15).

2.  **Plan (Algorithm):**
    *   Start.
    *   Ask the user for the first number.
    *   Store it.
    *   Ask the user for the second number.
    *   Store it.
    *   Add the two stored numbers together.
    *   Store the result.
    *   Show the result to the user.
    *   End.

3.  **Flowchart:**
    ```
    [START]
       |
       v
    [Get number1]
       |
       v
    [Get number2]
       |
       v
    [result = number1 + number2]
       |
       v
    [Display result]
       |
       v
    [END]
    ```
    *(Placeholder: `/assets/flowchart_add.png`)*

4.  **Dry Run:**
    *   User gives `number1 = 5`.
    *   User gives `number2 = 10`.
    *   `result = 5 + 10`, so `result` is `15`.
    *   Display `15`.
    *   The logic works!

5.  **Write Code:** We will learn how to do this in the next chapter!

## 4. Practice Problems (Thought Questions)

To solidify your understanding of these core concepts, think through the following questions. You don't need to code anything yet; just think about the logic.

### 🟢 Easy

1.  **Algorithm:** Write down the step-by-step algorithm for making your favorite sandwich.
2.  **Algorithm:** Write the algorithm for finding a specific contact in your phone.
3.  **Flowchart:** Draw a simple flowchart for deciding what to wear based on the weather (is it raining or sunny?).
4.  **Logic:** A user wants a program that tells them if a number is positive or negative. What is the key decision you need to make in your algorithm?
5.  **Debugging:** Your algorithm for making a sandwich says "Put bread on plate. Put cheese on bread. Put another bread on plate." What is the logical error here?
6.  **Algorithm:** Write the steps for calculating the total price of three items at a store.
7.  **Flowchart:** Draw a flowchart for a light switch. It has two states: on and off.
8.  **Logic:** What information do you need to calculate the area of a rectangle? (What are the inputs?)
9.  **Algorithm:** Write the algorithm for logging into your email account.
10. **Debugging:** Your algorithm for a calculator is: "Get first number. Get second number. Show the first number." What's missing?

### 🟡 Medium

11. **Algorithm:** Write an algorithm to find the largest of three numbers (A, B, and C).
12. **Flowchart:** Draw a flowchart for a simple ATM withdrawal. It should check if the requested amount is less than or equal to the account balance.
13. **Logic:** You need to write a program that sorts a list of 5 numbers from smallest to largest. Describe in plain English how you might approach this.
14. **Algorithm:** Write the algorithm for a simple guessing game. The computer thinks of a number (e.g., 7), and the user has three tries to guess it. The program should say "too high", "too low", or "you got it!".
15. **Debugging:** A program to calculate the average of 3 numbers has this logic: "Get num1, num2, num3. Average = num1 + num2 + num3 / 3." What is the logical error here? (Hint: think about operator precedence).
16. **Flowchart:** Draw a flowchart for a coffee machine. It should ask the user if they want coffee, then if they want milk, then if they want sugar.
17. **Algorithm:** Write an algorithm to determine if a year is a leap year. (A leap year is divisible by 4, except for years divisible by 100 but not by 400).

### 🔴 Hard

18. **Algorithm:** Write a detailed algorithm to find the second-largest number in a list of 10 numbers. How would you do it in a single pass?
19. **Flowchart:** Draw a flowchart for a traffic light system at a four-way intersection. How do you ensure that traffic flows from one direction at a time?
20. **Logic:** You need to write a program to find a path out of a maze. What are the basic rules or steps your "person" inside the maze would need to follow? (This is a classic computer science problem!)

This foundational chapter is all about building the right mindset. In the next chapter, we'll dive into the C language and write our very first program.
